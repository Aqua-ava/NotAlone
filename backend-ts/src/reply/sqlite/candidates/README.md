# SQLite 候选回复与依据

产品合同以[候选生成与来源资格](../../../../../architecture/current/reply-generation.md)、[联系人上下文](../../../../../architecture/current/domain-data.md)为准；本页只保留本模块的接口、装配和故障处理。

生成期间的来源核验只沿本次输入及运行副本实际接触的依赖查找，不再计算整个用户的历史失证影响。聊天来源按实际联系人批量核验；旧讨论、显式选稿及本人资料引用的其他联系人来源仍须覆盖。完整候选输入在冻结、每次物理发送和最终保存时核验，发送核验与原有出站账本授权处于同一事务；Skill 与 Agent 中间步骤只核任务、取消和运行范围。真正删除资料时仍执行原删除依赖闭包，不新增权威资料版本；检索派生迁移见[检索模块](../../../retrieval/README.md)。

候选的 `status?request_key=…` 是无正文的轻量状态接口，区分整理、排队、模型处理中、保存、完成及失败；已发出但未收到结果的调用在本机确认不再在途后自动放弃，呈现为失败，保留“已发送”事实，并以 `abandoned`（历史视图为 `generationAbandoned`）标明已放弃；已收到响应的失败同样已发送，但不标记已放弃（[ADR-183](../../../../../architecture/adr/183-auto-abandon-unknown-reply-model-calls.md)，实现状态见该 ADR）。页面只展示本轮阶段；失败保留安全错误码和是否已发送的状态。后端确认可以重试的终态失败（含自动放弃）允许用户新建请求；原请求不重发，其迟到结果不采用。

普通生成从本机已有的合法资料冻结输入；不为首轮生成恢复来源、补历史或等待未完成的后台任务。实际已选依赖失效时拒绝沿用，不能把失效材料当作无资料继续；具体降级和重试语义见现行回复生成合同。

初始只提供最近五十条、本次独立输入和合法 L3/L2 资料，不自动召回 L1。官方 DSH scoped Tools `search_relationship_memory`／`search_relationship_history` 由模型按信息缺口调用；`reply.beginSearch` 先持久占用尝试，语义评分在事务外进行，`reply.finishSearch` 重新核验并追加真实材料。历史搜索使用 v2 接纳边界与共享 BM25／向量／RRF 索引覆盖当前联系人全部获准历史，不列举五百条身份或截断历史范围；五秒计算预算超时返回未完成，不追加部分结果。L1 与旧历史准备池不当作已读依据，删除时定向剪除锚点；每次后续真实模型请求继续核验实际结果，Skill 降级重放已读材料且不重置预算。

`../retrieval-policy.ts` 是不依赖框架和存储的检索合同：集中四类触发、已有直接依据的例外、工具元数据及共享预算。`turns.ts` 使用同一完整提示生成配置摘要并出站；`search-tool.ts` 只负责官方工具注册、参数校验与执行，存储模块仍负责授权、来源和预算。触发指引参考腾讯固定提交 `42d4cde50c5a83182fced8c584f9ddb32a620615` 的 `tdai-profile-memory-injector.ts:179–209`，并保留本项目的数据／指令区分及未命中不证明不存在的约束；DSH 接线沿既有 `0.2.1-rc.2` 官方 `systemPrompt.section`、`defineTool` 和 scoped `tools.register`，不改 Agent loop。

`replyCandidateMigration(version)` 仅追加新版本。候选稳定身份不保存正文，模型原稿从 v1 起；手工编辑追加同候选父版本，多条消息分别按 `part_no` 保存。选稿是固定版本的追加事件，不证明复制或发送。

`SqliteReplyCandidateService` 提供 begin/view/version/edit/select；`SqliteReplyTurns` 复用讨论域的真实DSH运行、共享provider/arbiter及共享调用账本。`reply.begin`复用讨论域请求键、身份与unknown保护，保存真实触发发言和历史覆盖依据。联系人资格通过后可立即生成，历史未开始、同步中或不完整均不阻塞，也不要求额外确认；覆盖事实和当前可用资料限制进入冻结输入与输出依据，不将部分覆盖标成完整。旧 `accept_incomplete` 字段仅兼容已有调用，不授予读取或改变生成资格。原请求重试使用受理时的覆盖快照，不随后台历史进度改写或重复调用。任何重开、选稿、编辑和回看均不发送模型请求。

`ReplyKnowledgeReader.read/requireCurrent` 在当前 SQLite 短事务运行，HTTP 不能传正文、版本资格、SQL 或 adapter。`ReplyKnowledgeItem` 固定真实版本、本人／联系人范围、publication 成员和精确 `capture_record.id` 来源；写者复验所选版本，候选域复验范围、来源与解释修订。生产 Worker 安装 `replyLocalKnowledgeReader` 组合正式记忆与文档；未确认参考默认关闭，不把提取原稿视为已采纳记忆。一次性工作区要求不读取或保存长期表达偏好。

候选存储动作的统一入口负责建立同步完整验证作用域：同一动作内按读者、用户、联系人、助手会话及请求／上下文身份，或资料的完整冻结快照，复用已成功的验证。正文、投影、发布集合、来源及修订不同不能借用成功；失败不缓存。任何写入或派生状态结清都会使既有验证失效，退出动作即清除，下一动作／事务重新核验。新增列表或逐条读取入口必须沿用该入口，并运行候选数与历史请求数增长回归；候选版本和正文完整性仍逐条检查。未建立作用域的其他领域调用保留完整核验。

回复挑选记忆走按需核验：读者可选提供 `list`（低成本头部：当前版本正文、范围与资格类型，不核验来源，是 `read` 同类条目的超集且同序）、`open`（核验并物化单个头部，失效或版本已变返回 null）与 `readDocuments`。`selectReplyKnowledge` 消费检索模块给出的 ID／版本顺序和各自预算，不重新计算 L1 相关性，入选前才对排在前面的条目调用 `open`，失效条目被跳过且不占条数或字符预算，结果与逐条核验后再排序完全一致；每次回复的核验次数只随入选条数增长，不随记忆池线性增长。原先 `freezeInput` 与 `memoryPool` 各自整池逐条核验来源（每条数十次查询），池大时单个存储动作会超过 15 秒执行上限而终止 Worker。未提供 `list/open` 的读者退化为整体 `read`。

`reply_candidate_context` 留存冻结时本人／联系人的 memory/document 修订作为快照信息；资格复验以本次实际选择的版本、publication 成员及完整来源为准，未改变这些依赖的其他记忆新增、主题或概览发布不使本轮失效。`reply_candidate_input` 在原 context 类型之外保存真实候选输入，不重写已发布表。`reply_execution_input` 将快照绑定真实 `model_request` 事件，`event_source_planned` 保存这一类型化来源分支。展示依据仅引用本次 call 的实际输入，不能替代删除依赖闭包。

候选执行每次重建独立受管DSH副本，以避免未选择的旧候选通过SDK历史进入下一请求。只有同讨论的真实selection可以显式携入；携入固定正文版本及原始输入来源。Skill仍由 Skill 域的官方 provider读取，assertCurrent/recordSelection/recordInput及写事务requireSkillRun沿讨论域真实合同，不以selected冒充loaded，不改变原目录。

分组复验只约束在途使用；候选输入按数据库中的请求状态区分在途与已完成记录。已完成候选的回看、版本、编辑、选稿、参考资料及明确携入不要求历史分组仍是当前分组，但包修订、来源与删除保护继续复验；新请求独立冻结当前分组。

`replyCandidateDeletionDomain` 必须列入requiredDomains，并在discussion_calls前释放候选FK；其余原有域顺序保持。来源闭包由讨论域收集，增量纳入知识/选稿完整来源及后续显式携入请求。fence立即撤下候选正文与依据、不可逆清除版本资格；统一删除排空持有者后清实际输入、选择、版本、调用追踪及讨论域完整受管文件。候选域自身没有文件目标，不能声称只删本域即完成删除。

正常前台将确认的联系人上下文同时用于主进程门禁和页面禁用／撤快照；不能只信任 renderer 的 `confirmed_contact`。当前上下文取得规则见领域合同。页面 Skill 名称仅来自真实 `skill_input`，策略只作用本次；选择、复制或编辑均不证明外部消息已发送。

页面在失效事件、操作明确拒绝或权威重读发现旧请求失效时，清除候选、草稿、编辑、携入和Skill快照；短暂网络失败只保留原请求键、草稿及无正文的来源标识，后续权威确认失效时仍能撤下旧草稿。

正常表达工作区通过可选 `workspace` 固定字段提交 express／suggest、统一主输入，并固定空补充背景及自动关系背景；语气和一次性要求直接写在主输入中，不再接收独立 `tone`／`instruction` 字段；空 suggest 保持未确认立场。工作区不提供最近聊天查看／刷新、补充输入或背景开关，不产生消息级排除字段；候选 GET 不再额外读取或返回近期聊天和顶层覆盖投影。生成仍自动纳入最近最多 50 条有效消息与合法关系资料。后台补充输入和背景选择字段继续服务实际输入装配、原请求指纹、旧输入恢复及历史回看，不因界面退役重写原请求。可读动作与主输入作为本次讨论输入，设置指纹（`version: 3`）与覆盖事实用 `reply_candidate_request_v1` 版本格式保存在既有 JSON 元数据中，旧 plain coverage 与已保存的独立写作要求材料保持只读兼容；只有真实覆盖和获准资料进入模型材料，内部指纹不进入用户历史或候选依据。同请求更改设置返回冲突，不重复物理调用。
