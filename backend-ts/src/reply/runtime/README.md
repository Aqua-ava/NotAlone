# 助手运行副本

`AssistantRuntime` 只管理候选回复的本机 DSH 副本。可见讨论、候选、版本及来源继续由 PostgreSQL 裁定。

- `history` 通过官方 JSONL 只读句柄取回已提交事件；真实事件作为零 HTTP 预检的 seed，正式生成使用官方 `agents.resume`。
- `acquire` 在模型调用前标记 `dirty`，同一讨论只允许一个写者；`commit` 在官方句柄释放后执行持久化屏障并核对业务提交、事件数及完整事件摘要，再允许下次恢复。
- `AssistantRuntimeProjection.read` 默认只检查新鲜资格，不需要新建生成锚点。输入和候选版本的正文在 PostgreSQL 内计算摘要，只返回身份、状态、依赖和摘要；作者、记忆、来源、偏好、分层资料与已加载 Skill 资源继续由原守卫逐项复验，必要的旧快照和明确引用正文仍实际读取。完整材料清单还覆盖未被候选直接引用的背景、工具材料和 Skill 目录。修正、失效和范围收窄排除旧输入及其派生候选。
- `materialize` 在同一产品讨论内建立或替换底层运行实例；正常合法追加保留 SDK 历史，变化回执不含正文。新旧计划在发布事务再次比较，建档和文件释放在事务外执行。会话级占用与 operation 参加来源删除排空，宿主关闭也等待该操作；未知写者或删除屏障不能借重建解除。
- `hasHistory` 只选择运行引用表示；原来源、不可变版本、绑定、Skill 和提交守卫继续复验。正常续用不构造完整讨论 items 或参考 payload，也不复制进当前提示；只有首次建档或确认必须替换时，运行管理器以 `readPlan(client,true)` 请求正文构建。出站与保存各自重新检查资格，不跨阶段沿用成功结果。原准备快照的不可变性校验仍有正文读取和逐记录指纹成本；这不等于重新装配整段业务引用，也不能据此声称历史查询全部消失。预检与正式恢复还比较同一运行身份、资格和事件内容，实际恢复历史与伴随引用均计入完整序列化请求预算。
- `run` 先核对持久未完成的 deletion operation，再将准备、恢复读取、模型执行、提交和真实句柄释放纳入同一范围取消与完成边界；删除等待读写结束后才清盘，不持 owner 事务锁等写者。SDK 无法确认关闭时保留占用并让删除失败，不能把插件卸载当作清盘完成。
- `quarantine` 禁止恢复不合格文件；`erase` 只清除经过归属标记核验的整段应用目录，覆盖所有运行世代、分叉、索引、缓存及临时文件，并复核目录消失。

迁移 122 仅以 owner、contact、会话 ID 的既有输入／轮次存在性标记 `legacy_runtime_pending`，不复制正文，旧空壳与未来新段为 false。旧段无运行档案时，准备／生成在写入 turn 和输入之前要求明确继续；仅构建出 ready 资格与落盘摘要后清除此标记。配置未就绪或没有建档回调时不盲清。当前旧段也有明确继续按钮，失败后可重试；新段的方向输入跨重启进入首次生成不依赖内存或时间猜测。

既有数据库讨论仍只读，首次明确继续才建立存档，不批量迁移、重新提取或生成候选。`origin=business_bootstrap/business_rebuild` 以有效业务投影落盘为凭据，允许真实的 `committed_request_id=NULL`；`origin=generated` 必须对应真实完成的数据库请求，不混淆两类凭据。迁移 121 增加资格和完整事件摘要，117—120 保持不变。

零模型建档使用官方 `SessionStore.create`、`sessionPersistence.create(header)`、写句柄 `flush/close` 建立合法空档，业务引用保存在同一受管运行目录的 `business-reference.json`。首次明确生成时，在当前用户轮携入这一份低权重业务引用；随后只复用真实 SDK 消息。资格 v2 的记录摘要与伴随文件的 `payload_sha256` 分开：后者仅在真实构建时保存，恢复引用时与文件逐字核对，正常 native 运行不虚构这一正文凭据。旧资格格式按相同业务身份安全重建，不把旧正文摘要当作新鲜资格。保留输入、候选、编辑版本及来源身份，旧要求不成为长期偏好、当前事实或已发送证据。

直接先追加业务 `user/message` 的探针只能证明 resume：首次真实 followup 后，锁定 SDK 的[格式校验](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/session/session-format-v3-to-v4/src/relationships.ts#L124)要求系统消息位于受保护的首节点，会拒绝这种先用户后系统的档案。本实现用空档和自有伴随文件避开该不合法顺序，不手造 SDK 执行轮，不使用 experimental plugin record，也不修改 SDK。只有真实 Host 跨重启、首次生成及再次续用测试才作为该接线可用的依据。

`materialize(scope, session, configuration, readPlan, signal, options)` 是共用的零模型构建接缝，返回原业务身份、新运行身份、origin、状态、事件数、业务提交身份、资格摘要和无正文变化回执。`AssistantRuntimePlanReader(client,build?:true)` 必须将第二参数透传给 `AssistantRuntimeProjection.read` 的末参数：默认只返回资格，显式 true 才返回经过同一守卫的完整 payload；未返回 payload 时构建失败关闭。资格 scope 仅包含 owner/contact，binding 单独严格核验，避免不同入口的额外已验证字段引起重复重建。无需新迁移，117—122 均保持不变。

恢复先验证受管目录和所有文件，再以官方写句柄核验锁与日志。缺档、已知损坏、事件数／摘要分歧及 dirty 副本在一次明确操作内至多重建一次，正文只来自当前有效业务投影；未来格式、身份不符、链接、权限、活写锁及未知关闭失败拒绝恢复，保留可读业务历史。日志缺失但目录仍在时，官方 create/flush 先在原路径取得真实锁，不能因没有 JSONL 就绕过持有者。未知关闭失败保留进程内会话占用，重启前不能假定安全。删除 pending／blocked 不能被修复解除；读盘期间新发现的可修分歧只标 dirty，下一次明确动作才重建。

宿主取得唯一启动责任后、公开接口就绪前，按原任务身份裁定中断，不以旧业务租约阻止已死宿主的恢复。正常退出等待在途任务取消和释放，取消结算为中断；已可靠提交的 DB 候选始终先赢，文件发布失败不把它降成普通失败。SDK 未完成轮的关闭不是半步续跑，读取、重建及启动均不发模型。明确重试沿原输入与新 retry 请求键保持幂等，普通 completed 同键重放仍只读。公开 `generation-receipt` 只按原 owner/contact、请求键及受理会话别名找回回执，不提交正文或触发准备；Main 仅在明确收尾重试时采用，并验证原连接与 previous_session_id，迟到结果不迁入新视图。

Host 组合根在模型装配前创建唯一运行管理器，供启动删除恢复及模型端共用。合成宿主可在可信启动配置中显式提供同 businessHome 的 `persistentAssistantHome`；当前正常配置仍保持临时运行，完整恢复及桌面验收另行完成。

空闲分段的准备回执可能全部丢失。实际新段任务仍 running 时，原请求段暂不允许删除，避免删除外键把唯一受理别名置空；公开协调器在创建删除操作前检查，实际删除的 owner 事务内再次复验，覆盖预检后的并发受理。拒绝不默认取消独立新段；Main 保留未知作业并允许用户明确核对、停止后重试删除，其他来源／生成门禁保持。已创建操作在复验失败时保留可重试状态，停止新段不依赖旧段删除完成；分段中断回执的可选 previous_session_id 仍经原身份解析器核验。

删除操作提交后就建立早期屏障，先在事务外取消并排空相关轮次，再执行任何可能失败的备份核验、闭包擦除或文件清理。来源的 owner memory／携入依赖可跨联系人，因此未完成的来源清理保守暂停同一本人的恢复和生成，历史只读及无关档案保留；清理成功后才解除，失败显示“资料清理未完成，暂时不能生成”并保留明确重试。联系人／账户按自身范围协调，包括没有助手 turn 的兼容临时轮；讨论删除只匹配自身会话或已核验闭包。

公开来源、联系人和助手会话删除沿真实业务闭包，在级联或正文擦除之前将目标及阻断持久绑定到原 deletion operation（迁移 118）。文件清理失败后，即使业务会话已不存在，目标仍可跨重启核验、阻断恢复并明确重试；受管更新恢复副本沿原归属校验清除。成功后只保留去身份凭证。未完成讨论删除允许同 owner、contact 范围只读查找最小 UUID，桌面重启据此恢复失败占位，不能把 404 当作清盘成功。

合成回归通过真实产品 Host、官方 JSONL、环回供应商与文件读取屏障验证跨重启清理、迟到结果、故障重试及无关讨论保留。它们不证明真实模型效果或原生 App 验收。

所有 DSH 能力固定为 `0.2.1-rc.2`，Cordis 为 `4.0.5`。运行世界仍挂在正式 profile 的同一根 context，使用官方 Session、Agent、Projection、SystemPrompt、Tools、JSONL 和 AgentLoop 插件；不修改 SDK，也不另建启动根。为适配该版本隔离子作用域的依赖继承，薄插件沿用[官方 Loader 的 `internal/plugin` 与 `Inject.resolve` 接缝](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/vendor/loader/src/index.ts#L129)，仅补本轮 Loop 直接子 fiber 的明确依赖，随运行世界关闭撤销。
