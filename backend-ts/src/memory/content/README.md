# 记忆内容插件

文字与图片通过同一个 `MemoryContentPlugin` 接口进入正常记忆任务。任务冻结、联系人授权、模型许可、追踪、候选采纳和删除由现有流程负责；插件不自行发模型请求或写记忆。

- `snapshot` 在建轮事务内为单条规范消息选择有效内容，冻结插件版本与来源身份。图片记录确切文件、摘要、媒体代次、格式和大小；没有实际副本时返回未就绪，不能拿占位文案代替图片。
- 可选的 `availableMany` 只判断同一联系人候选内容当前是否可用，用于轻量调度与页面统计；每批最多 500 条，仅返回消息 ID，不冻结正文、不生成内容摘要或调用模型。内置文字和图片提供批量实现；旧自定义插件通过同范围完整消息回退原 `snapshot`。真正建轮和执行仍调用 `snapshot/prepare` 重新核验，不把统计结果作为授权。
- `modelInputCost` 声明组批所需的图片数量和原始字节数。执行器优先选择目标，再在剩余额度内加入上下文；正式模型发送仍独立计量最终请求。
- `prepare` 只读取冻结内容，返回模型消息及实际附件。读取前后复验当前任务；图片通过受管媒体读取接口取得字节，不读取微信或任意路径。

`builtins.ts` 是默认可信插件清单。宿主以官方 `ctx.plugin(memoryContentPlugin, {registry, plugins})` 注册，Worker 使用 `createMemoryContentStorageRegistry(base, plugins)` 装配同一批插件模块。自定义清单须在两侧一致；仅注入宿主 registry 不能让另一个 Worker 自动加载代码。插件版本不一致时停止处理，不猜测兼容。

新增类型可以在独立模块实现这个接口，并在可信装配点注册，无需给任务筛选、冻结、组批或执行器增加类型分支。`test/fixtures/memory-content/` 用合成文件插件验证正常建轮和处理接线，不表示产品已经支持真实文件、语音或视频解析。新类型仍须提供可靠内容读取、对应的类型化证据及资源删除依赖，不能把解析摘要当作原文。

本轮图片证据使用 `multimodal-claim-v1`：实际图片与文字共同进入提取和来源核验，图片引用绑定文件版本，观察描述明确区分于文字引句。已核验的新记忆可沿原规则自动采纳；与旧资料比较涉及图片、旧关系核验不足时保留待确认，不自动合并或替换。记忆正文与检索表示继续为文字。

插件为构建时受信任的业务模块，不提供界面上传代码、任意脚本执行或外部聊天发送能力。
