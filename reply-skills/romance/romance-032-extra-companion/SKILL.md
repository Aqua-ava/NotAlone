# 约会临时增加朋友或同行者

来源候选：D26、G12。

**适用：**原本约好两人见面后，对方提出带朋友、朋友临时加入，或到了现场才发现多一位同行者。目标是让用户表达自己对这次安排的真实意愿。

**边界：**同行者是安全风险或用户决定离场时，转入安全退出；若两人改天再约，才进入再次邀约场景。本 Skill 不要求用户为了显得大度而接受变化。

**信息不全时：**优先使用用户本轮表达的目的、已提供的原话和当前可用的背景。缺少会改变候选的关键事实时，只问一个必要问题；否则写条件清楚的候选，不补造经历、情绪、约定或对方动机。

## 处理步骤

1. 先确认变化发生在事前还是现场，以及同行者是谁；用户还没弄清时，只问清人数和安排，不先揣测对方动机。

2. 分开两件事：用户是否愿意见同行者，以及是否仍想和原对象单独相处；不要把其中一个答案替用户作出。

3. 选择一个实际可行的方案：接受多人、改约两人、缩短此次见面或结束当次安排；说明具体安排，不用惩罚式措辞。

4. 如果已到现场且不舒服，先处理交通、位置和离开方式，再拟礼貌但清楚的一句话；不要假装开心维持场面。

## 按实际反馈选择下一步

- 用户愿意多人见面：确认同行者和地点，按新安排赴约，不把接受解释成关系承诺。
- 用户想单独见或需要考虑：提出另约时间，或先问这次安排；等待对方实际回应。
- 用户不接受且不想继续：简短说明并离开，后续是否再约由用户决定。

## 完成条件

候选说清用户对同行安排的选择，并落到一个当下动作；不借“测试”对方来制造压力。候选保持可编辑，由用户选择、改写后自行决定是否使用。

**案例指针：**只有在需要比较本场景的常见与困难情形、或用户明确要求演练时，才读取 `references/cases.md`；普通单次回复依本文件步骤处理。
