# 对方主要在需要帮助时才联系

来源候选：C12、G15。

**适用：**对方频繁因办事、借用物品、介绍资源等联系，而日常相处较少。用户希望继续关系但不想只有服务角色。

**边界：**单纯一次紧急求助按具体请求处理；长期情绪倾诉且没有双向交流转入陪聊失衡。不要用账本或试探来惩罚对方。

**信息不全时：**优先使用用户本轮表达的目的、已提供的原话和当前可用的背景。缺少会改变候选的关键事实时，只问一个必要问题；否则写条件清楚的候选，不补造经历、情绪、约定或对方动机。

## 处理步骤

1. 核对用户愿意提供哪一项具体帮助及实际成本，必要时先回答能否帮，而非以拒绝换取关注。

2. 观察并只陈述可见模式，例如最近联系多是请求帮忙；不把它诊断为利用或不喜欢。

3. 表达一项真实界限，再提出用户愿意尝试的双向相处方式，例如一起吃饭或互相分享近况。

4. 听对方回应后按实际行动决定下一步；不因为对方说“以后一定补偿”就默认关系改变。

## 按实际反馈选择下一步

- 对方理解并开始主动安排普通相处：回应具体计划，慢慢观察互惠。
- 对方只继续请求：按能力接受、拒绝或限缩帮助，别承诺超出能力的支持。
- 对方生气或施压：重复边界并停止解释，不用争论谁亏欠谁。

## 完成条件

候选既说明当前愿意帮到哪，也让用户关系期待可被听见；帮助不自动交换感情。候选保持可编辑，由用户选择、改写后自行决定是否使用。

**案例指针：**只有在需要比较本场景的常见与困难情形、或用户明确要求演练时，才读取 `references/cases.md`；普通单次回复依本文件步骤处理。
