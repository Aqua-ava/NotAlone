# 承接上次体验提出再次见面

来源候选：D16、E22。

**适用：**一次见面或共同活动结束后，用户明确想再见，且可依据真实共享细节提出新活动。场景重点是把想法落成一次可商量的安排。

**边界：**若用户只想发约后第一条感谢，不加入邀约；如果用户尚未决定是否再见，先写当下感受而不替他推进。

**信息不全时：**优先使用用户本轮表达的目的、已提供的原话和当前可用的背景。缺少会改变候选的关键事实时，只问一个必要问题；否则写条件清楚的候选，不补造经历、情绪、约定或对方动机。

## 处理步骤

1. 先确认用户确实想再见，并找到上次互动中双方都参与的具体线索。

2. 把共同线索变成活动提议，给一个大致时间窗口和地点方向，避免含糊的“下次有空”。

3. 消息只放一个邀请，语气留出真实拒绝或另提时间的空间；不要用“欠我一次”制造债务。

4. 收到反馈后分别处理：确定就补齐细节；暂时不便就看对方是否给出替代时间；没有替代信息则不连环追。

## 按实际反馈选择下一步

- 对方接受：确认时间地点和必要安排，不把答应一次升级成关系承诺。
- 对方忙但提出另一个时间：沿对方给的窗口具体化。
- 对方只说“以后再说”或不回应：轻轻收住，不继续要求对方证明兴趣。

## 完成条件

邀请有共同经历、具体但可调整；用户没有把一次约会描述成对方已经同意的关系。候选保持可编辑，由用户选择、改写后自行决定是否使用。

**案例指针：**只有在需要比较本场景的常见与困难情形、或用户明确要求演练时，才读取 `references/cases.md`；普通单次回复依本文件步骤处理。
