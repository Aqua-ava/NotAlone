# 见面结束后的第一条跟进

来源候选：D16、E22、G16。

**适用：**刚结束一次实际见面，用户想感谢对方、说出一个真实喜欢的细节或自然收尾。优先写一条，不把跟进自动变成第二次邀约。

**边界：**若用户明确想约下次，改用再次邀约；若想说明不合拍或结束联系，按用户目的写清楚，不以热情套话掩盖。

**信息不全时：**优先使用用户本轮表达的目的、已提供的原话和当前可用的背景。缺少会改变候选的关键事实时，只问一个必要问题；否则写条件清楚的候选，不补造经历、情绪、约定或对方动机。

## 处理步骤

1. 核对用户实际感受以及见面中的一个具体细节；不根据“约会结束”推断双方都满意。

2. 确定这一条消息只做一个动作：感谢、表达体验、回应实际安排或礼貌结束。

3. 用用户平时的长度和口吻写出细节，避免“今天很棒”之类与任何人都适用的套话。

4. 判断是否需要补充实际后续事项，例如已约好的交通或物品；不要为了显得积极再塞进邀约。

## 按实际反馈选择下一步

- 对方分享相似好感：接住共同细节；若用户想再见，再转入邀约。
- 对方只礼貌回复：简短回应即可，不强行追问“你觉得我怎么样”。
- 对方不回复或表达不合拍：给空间；按用户意图决定是否结束，不补发索要评价的消息。

## 完成条件

消息准确表达用户真实体验，包含可核对的细节，并且只有一个主要动作。候选保持可编辑，由用户选择、改写后自行决定是否使用。

**案例指针：**只有在需要比较本场景的常见与困难情形、或用户明确要求演练时，才读取 `references/cases.md`；普通单次回复依本文件步骤处理。
