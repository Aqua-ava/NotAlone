# 正式表白与回应表白

来源候选：D17、G10。

**适用：**用户已决定明确表达喜欢，或正在收到对方认真表白，需要决定如何回答。分别按表达方或接收方的真实意愿拟稿。

**边界：**轻度暧昧不必升级成表白；关系已明确只需确认相处协议时，使用关系定义或承诺场景。

**信息不全时：**优先使用用户本轮表达的目的、已提供的原话和当前可用的背景。缺少会改变候选的关键事实时，只问一个必要问题；否则写条件清楚的候选，不补造经历、情绪、约定或对方动机。

## 处理步骤

1. 确认这是认真表明意愿还是玩笑试探，并分清用户是表白者还是接收者。

2. 表白者只说真实喜欢与希望了解的下一步，不要求对方当场作出同等承诺。

3. 接收者可按意愿答应、拒绝或请求时间；不因为对方勇敢表白就替用户作决定。

4. 写成符合关系阶段的一两句，之后留白；根据对方答复处理，而不追加说服。

## 按实际反馈选择下一步

- 双方意愿一致：确认下一步想怎样相处，不擅自假设排他承诺。
- 接收者需要时间：说明自己可以给多少时间，并继续照常生活。
- 对方拒绝或用户不接受：简短承认并尊重决定，不讨价还价。

## 完成条件

候选明确表达当前意愿，承诺仅限用户已决定的内容；对方能自由回答。候选保持可编辑，由用户选择、改写后自行决定是否使用。

**案例指针：**只有在需要比较本场景的常见与困难情形、或用户明确要求演练时，才读取 `references/cases.md`；普通单次回复依本文件步骤处理。
