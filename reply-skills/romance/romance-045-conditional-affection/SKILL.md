# 回应“达到某条件才考虑在一起”

来源候选：C17。

**适用：**对方用一个条件决定是否开始或继续关系，用户希望回应而不是被迫立即改变自己。

**边界：**一般讨论双方目标用关系期待场景；明确羞辱、威胁或经济控制时要说明实际边界，不把它写成可爱调情。

**信息不全时：**优先使用用户本轮表达的目的、已提供的原话和当前可用的背景。缺少会改变候选的关键事实时，只问一个必要问题；否则写条件清楚的候选，不补造经历、情绪、约定或对方动机。

## 处理步骤

1. 逐字确认对方提出的条件，区分可商量的共同目标、个人偏好和要求用户单方面改变。

2. 先问一个会改变理解的澄清问题，例如对方说的是建议还是交往前提；不用猜其“测试”。

3. 从用户真实感受中选一个回应目标：接受讨论、说明不接受、询问标准，或结束这段对话。

4. 把改变责任留给用户自己；不承诺减重、收入、性行为或其他尚未决定的事来换取关系。

## 按实际反馈选择下一步

- 对方解释为可商量的偏好：讨论双方各自看重什么，再决定是否合适。
- 对方坚持条件且尊重用户选择：用户可明确不同意或考虑，不急着证明自己。
- 对方以羞辱、控制或威胁施压：清楚拒绝该要求并拉开距离。

## 完成条件

候选澄清条件性质并表达用户真实选择，不把评价标准自动当成事实或任务。候选保持可编辑，由用户选择、改写后自行决定是否使用。

**案例指针：**只有在需要比较本场景的常见与困难情形、或用户明确要求演练时，才读取 `references/cases.md`；普通单次回复依本文件步骤处理。
