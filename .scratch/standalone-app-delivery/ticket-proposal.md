# 独立 App 交付：任务粒度与依赖提案

状态：待用户确认，尚未发布逐张任务。

规格：[独立本机 App 的首启与兼容更新](spec.md)。每张任务须交付可独立验证的完整用户行为；以下为提案序号，不是已发布任务。

## 1. 独立安装包完成本机首次设置

Blocked by: 无。

提供受管后台、数据运行环境和首启向导。无开发环境的新安装从实际包启动，完成环境准备、本人及模型设置并进入可用的联系人空目录；不要求 Python／项目路径、终端或测试进程预先准备数据库。覆盖可重定位、重复打开、准备失败后的动作与正常退出。随包依赖的来源、许可、完整性和签名一起验证。

## 2. 通过受控授权完成微信首次接入

Blocked by: 1。

用户在向导了解影响后，亲自确认退出／重新打开微信和必要的一次性系统授权，完成工具初始化并看到真实可用或失败结果。保留原微信，不保存管理员密码，特权仅限本次固定初始化；取消和失败不继续。此任务须解决可取得组件源码／构建来源及 LLDB／系统 Python 等隐含开发依赖，在无开发环境验证；若路线不可行，记录事实并回到设计，不擅自扩大权限或把准备完成写成接入通过。

## 3. 新用户确认联系人后同步并生成候选

Blocked by: 2。

首次会话默认不选，用户确认联系人与会话并开启同步后，只读取授权范围；实际增量去重、关闭停读与前台定位分别核对。用户通过公开界面生成、编辑候选并亲自发送。正式 App、微信、模型和签名组件的结果按同版记录，不用合成回执代替实机；失败有对应恢复动作。

## 4. 已有用户备份并完成兼容更新

Blocked by: 1。

App 识别既有受控本机资料，用户一次确认“备份并完成更新”，完成仅本机可读备份、恢复能力校验、版本更新与重连，保留身份、联系人、聊天、记忆、来源、绑定及开关。覆盖外置旧安装的保留资料接续，禁止静默新建空库或升级错目标。失败／中断可安全续接，原目标与备份保留，未知基线和漂移有真实恢复入口。

## 5. 独立分发的完整两路验收与交付检查

Blocked by: 3、4。

冻结同一实际安装产物，完成无开发环境的新装／微信确认／生成，以及旧版资料在 App 内备份更新后继续使用两条用户路径；补齐移动 App、重复启动、权限拒绝、更新失败和退出收尾的组合检查。核对全部组件来源、许可、签名与适用的平台范围，完成两轴审查、用户可用的安装说明及分项实机证据。公开分发所需签名／公证在可审查产物准备好后另按授权完成；未满足项明确阻止“独立可交付”结论。

## 依赖关系

```text
1 ──→ 2 ──→ 3 ──→ 5
└────→ 4 ────────→ 5
```

任务 4 可以在任务 1 完成后与微信接入路径并行推进；其余顺序由实际交付依赖决定。用户确认粒度和依赖后，按仓库 Local Markdown 规则发布每张任务，再进入逐项实现与验证。
