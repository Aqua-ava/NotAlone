# 独立 App 手动输入首版

Triage: ready-for-agent

状态：用户于2026-10-16明确接受此首版范围，持续实现中；不表示安装包已可正式分发。完整长期目标仍见[原规格](spec.md)。

## Problem Statement

普通使用者需要拿到 App 后直接开始使用。本机后台与资料更新正在完成，微信自动首次接入尚无可交付路径，不能继续把它作为首版的前提，也不能让空联系人目录阻止用户手动使用回复助手。

## Solution

首版提供双击开始的本机设置、明确建联系人与选择联系人、手动粘贴当前聊天文字或导入单联系人文件，以及生成、查看依据和编辑候选的完整路径。微信自动接入保留为未完成能力。已有资料仍通过“备份并完成更新”接续。

## User Stories

1. 作为新用户，我希望双击 App 完成本机准备，不必安装开发工具或填写运行路径。
2. 作为新用户，我希望明确确认本人身份，并亲自输入模型密钥，了解文字的接收方与用途。
3. 作为新用户，我希望没有微信或已有资料时也能在 App 内创建一位联系人。
4. 作为用户，我希望每次输入和生成前能清楚看见并确认本次联系人，避免混用资料。
5. 作为用户，我希望粘贴当前聊天文字后直接使用回复助手，不必先绑定桌面会话。
6. 作为用户，我希望导入已有单联系人资料时先预览、确认归属，遇到混杂或损坏资料时得到明确提示。
7. 作为用户，我希望生成前明确操作，并沿用表达方向与上下文确认流程。
8. 作为用户，我希望生成结果带可查看的依据，能够编辑并自己决定最终发送内容。
9. 作为用户，我希望切换联系人后，输入和候选按各自范围保存或失效，不串到其他联系人。
10. 作为用户，我希望手动输入当前消息不会未经确认变成长期关系记忆。
11. 作为用户，我希望断开模型、缺少设置或资料不可用时，看到对应的实际恢复动作。
12. 作为用户，我希望界面如实说明微信自动接入尚未提供，不反复要求准备无法完成的工具或权限。
13. 作为已有用户，我希望本机备份更新后保留资料、来源、绑定、同步开关和暂停状态。
14. 作为用户，我希望重新打开或搬动 App 后继续使用，退出后本次后台确实停止。

## Implementation Decisions

- 采用已实现的受管本机后台、PostgreSQL、本人及模型设置，不另建账号或改变模型供应商。
- 联系人创建只需用户明确提供展示信息，生成独立联系人标识；不伪造微信身份或桌面会话绑定。手动输入必须显式选择联系人，不根据昵称、正文或模型猜测归属。
- 复用现有具名桥接、联系人范围和候选运行时；普通手动输入路径不能被缺少 CLI／原生定位条件永久阻止，也不放宽自动识别和后台同步的门槛。
- 当前手动输入与明确历史导入继续分层。导入沿用已支持格式、预览与确认、单联系人隔离、来源与删除语义；不要求用户从微信执行未提供的导出操作，不新增自动读取渠道。
- 用户明确生成后才进行既有最小模型出站，密钥不进入渲染状态、日志或仓库。最终消息由用户亲自发送。
- 首版不启用或携带未完成的微信特权初始化入口。普通公共组件的研发代码和已获得的证据不代表该能力已交付。
- 原有资料更新与失败恢复范围保持，正式签名、公证、外部发布及用户实际资料更新仍按具体产物与授权执行。

## Testing Decisions

- 最高接缝继续采用实际安装包公开 App 操作：空用户目录首启、本人与模型设置、显式创建／选择联系人、手动输入或单联系人导入、生成、依据查看与编辑、退出与重开。
- 沿用现有实际 App、真实认证 HTTP、正式迁移及隔离 PostgreSQL 夹具。先取得公开行为 red，再推进 green；不靠内部控制器预填联系人或绕过生成条件补签首用路径。
- 可用本机合成模型验证确定性接线、故障和数据隔离，必须与用户自有凭据的真实模型验收分记；真正无开发环境目标机器同样独立记录。
- 最少覆盖空目录、新联系人明确确认、未选择联系人禁止生成、手动输入不依赖微信、切换隔离、混杂／损坏导入、缺模型或模型失败、候选编辑与依据、重复点击、搬动重开及退出停服。
- 不读取用户私人聊天、不发送外部消息、不请求新增微信／管理员权限。仍未具备的验收资源如实留项。

## Out of Scope

- 微信自动初始化、自动会话识别及同步渠道的首次交付；原任务02／03保留后续范围。
- 自动发送消息、根据正文猜测联系人、自动扩大读取授权或静默采纳长期记忆。
- 云端资料、集中模型计费或代管用户密钥。
