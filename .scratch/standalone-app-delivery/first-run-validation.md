## 崩溃恢复与停服失败回归

两轴审查发现 Main 崩溃会遗留受管服务。旧 v3 公开用例明确得到 red：Main 被 SIGKILL 后实际后台15秒仍在运行。断言失败后按本例精确记录的后台、PG和 App 归属收尾；另两次测试脚本问题（握手格式误读、退出后再次取 Playwright 已销毁对象）保留为测试故障，不计通过。

新包加入本次后台的父进程/管道寿命门和 PostgreSQL 窄监督器：前者先完成停止，后者取得本轮私有寿命锁再 fast shutdown 自己的子进程。公开崩溃→同 userData 重开1/1通过（1.4分钟），原后台与PG退场、握手和数据库锁消失，本人身份及空联系人保留，重开后正常菜单退出。App 自建服务不按未知PID接管或查杀；快速重开先等待旧监督器自然停止。此证据使用 EDB PostgreSQL16.15-5 的开发态 ad-hoc 包；后续替换源码构建 PG 必须重新验证，不能自动移用。

无后端认证目标的资料服务停止返回 false/抛错均先得到 red（停在 stopping/异常逸出），统一发布 shutdown-failed 和可执行退出重试后2/2通过，含受管设置未就绪的可见入口。构建/载入清单边界的共同合成用例先 red 后4/4通过，来源数量及备份恢复工具不再有分歧。后端认证停读、握手与同步宿主36/36通过。完整安全回归85项中84通过，唯一未通过是其他聊天当时持有无头页面租约，与该测试假设全局租约 absent 冲突；未改动或清除其他聊天的租约。

本片没有读取用户原业务资料、改变默认 userData、微信安装、联系人授权或系统权限，没有模型出站。Computer Use 及最终无开发环境/旧资料更新仍分项待验，任务01保持 claimed。
