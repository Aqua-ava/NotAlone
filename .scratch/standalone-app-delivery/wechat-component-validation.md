## 实际构建

使用任务02工作树当时的 `desktop/wechat-sources.lock.json`、只读 CLI 补丁与标准构建脚本。准备独立来源缓存，仅提供固定公开归档、固定 Git 对象及已核验的 Go 模块缓存；**不提供**脚本支持的 WCDB 成品库缓存或调试器成品目录缓存。因此本次实际进入 WCDB 与 debugserver 的源码编译分支。

```sh
node desktop/scripts/prepare-wechat.mjs \
  --source-cache "$SOURCE_CACHE" \
  --output-directory "$COMPONENT_OUTPUT"
node desktop/scripts/prepare-wechat.mjs --check-directory "$COMPONENT_OUTPUT"
```

两条命令均 exit 0。构建日志、来源缓存与产物保存在端侧临时目录，不提交二进制或本机路径。不是空缓存联网构建；开发机上的 Xcode、CMake 是构建工具，不作为用户运行时依赖随包。

本轮固定来源为微信 CLI `795071fa0591da5fc2c6ab94a70f22ccd93ef06c`、WCDB 2.1.16 官方归档、LLVM debugserver `ca7933e47d3a3451d81e72ac174dcb5aa28b59d1`、CodeLLDB 的固定 LLDB 归档及 PBS 3.12.14。具体 URL、完整归档摘要和构建参数保留在来源锁文件。

## 后续门槛

此次来源锁摘要为 `f6ab4defff9535e18d92a289ae65143cd597f337a15174c7844fbbd1dcabb41a`。后续修改 CLI 裁剪或来源锁必须产生新产物并重新核验，不能沿用此记录补签新组件。

审阅发现本版上游 `sessions.go` 的会话列表会查询最近消息 `summary`，关键词也会匹配该列。产品首次列表不应借此读取未确认联系人的正文片段；任务02正在将会话列表和全局会话事件裁剪为元数据专用，并追加对应合成数据库回归。本次构建成功不代表该裁剪已经完成。

根 Agent 另用本次真实 CLI／WCDB 和三个自建合成加密库，直接调用当前生产 `LocalWechatCli`：版本、两个会话、名称解析、单会话文字与实时来源、重复水位空结果、全局会话事件、单会话新增文字流均通过。关闭流后两个本次子进程均退出；未生成额外支持文件，临时数据库随夹具结束删除。去掉合成会话表的 `summary` 列后列表失败，且原始列表含两个正文摘要，复现上述范围问题。首轮夹具尝试 `DROP COLUMN` 被 WCDB 内 SQLite 拒绝，改用重命名与显式投影重建夹具后重跑；该夹具兼容性失败不算产品缺陷。修复后的普通 CLI 回归另行记录，不沿用此基线补签。

微信特权首次初始化的实现子任务随后被工具安全审查中止，返回原因是“可能涉及网络安全风险”。相关实现已停止并保留现场，未完成的原生 worker 不纳入可交付构建；没有通过重试或改写请求继续该路线。普通 CLI 的元数据裁剪、资料更新和不依赖特权初始化的验证继续进行。该中止不能解释成仅缺用户授权，也不能将组件构建成功标记为微信接入完成。

没有操作真实微信、读取真实聊天、请求系统授权、访问 Keychain、迁移用户资料或调用模型。本轮也没有完成真实渠道协议验收、无开发环境机器验收、全部传递依赖许可复核、Developer ID 签名或公证。产物仍标记 `pending-transitive-review`，实际系统授权及真实微信字段继续为 `false`。
