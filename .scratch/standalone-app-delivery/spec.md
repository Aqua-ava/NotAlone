# 独立本机 App：首次使用与兼容更新

Triage: ready-for-agent

状态：用户体验、数据位置、安全边界和公开 App 验收路径已确认；用户已批准五项任务并要求持续实现，见[实现索引](planning.md)。产品尚未完成。

## Problem Statement

使用者拿到现有 App，能够看到管理后台，却因没有启动路径或数据库结构较旧而无法使用。“重试连接”重复相同检查，无法完成缺失的准备。现有自动测试预填开发环境并由测试进程提前升级数据库，没有证明普通人拿到安装包能完成首次使用。

## Solution

交付提供受管本机后台与数据环境的独立 App。首次启动通过向导准备环境、完成本人和模型设置、接入微信并确认联系人，全程不用终端或填写开发路径。已有使用者更新 App 时，在界面点一次“备份并完成更新”，保留资料并完成兼容更新，成功后继续使用；失败有真实原因和恢复动作。

## User Stories

1. 作为新用户，我希望下载 App 后双击开始设置，不必安装 Python、PostgreSQL 或开发工具。
2. 作为新用户，我希望 App 处理运行环境与数据位置，不必填写解释器、仓库或配置文件路径。
3. 作为新用户，我希望向导说明当前步骤、进度和需要我的操作，以便知道是否准备完成。
4. 作为新用户，我希望本人身份由我明确确认，避免自动选择其他人的身份。
5. 作为新用户，我希望在 App 内配置自己的模型密钥，并知道文字会发送给谁及用于什么。
6. 作为新用户，我希望通过向导准备微信读取工具，不必查找 CLI 命令或配置路径。
7. 作为用户，我希望在微信将被退出、重新打开或需要系统授权前看到影响，并亲自确认。
8. 作为用户，我希望管理员认证由系统处理，App 不保存我的管理员密码。
9. 作为用户，我希望原微信安装包保留，未授权时不发生额外初始化操作。
10. 作为用户，我希望拒绝授权或取消设置后仍能回到明确状态，随后继续、重试或使用已具备条件的功能。
11. 作为用户，我希望首次列表不预选联系人，由我确认读取对象与范围。
12. 作为用户，我希望只有确认范围内的会话能同步，关闭同步后停止新增读取。
13. 作为用户，我希望确认联系人后能够生成、编辑候选，并亲自发送最终消息。
14. 作为用户，我希望关闭或退出 App 的行为清楚，不留下重复后台或未确认停读的实例。
15. 作为已有用户，我希望更新 App 后保留联系人、聊天、关系资料和原有绑定。
16. 作为已有用户，我希望 App 自动发现存储格式需要更新，用清楚的按钮完成处理。
17. 作为已有用户，我希望更新前有仅保存在本机的可恢复备份，并知道备份的实际结果。
18. 作为已有用户，我希望更新保留原同步开关与暂停状态，不额外授权联系人或重新生成关系资料。
19. 作为已有用户，我希望更新失败时保留资料和备份，不出现覆盖资料的自动恢复。
20. 作为用户，我希望每种失败都有对应动作，持续点重试不会掩盖需要设置、授权或更新的问题。
21. 作为用户，我希望重新打开 App 后复用已完成的准备，不重复创建环境、身份或读取进程。
22. 作为使用者，我希望包内组件来自可核验来源，App 不携带开发者配置、凭据或私人资料。
23. 作为交付者，我希望以真正无开发环境的新装和已有资料更新两条完整用户路径决定能否交付。

## Implementation Decisions

- 独立交付与本机数据位置按新架构决定执行，修订旧的外置开发环境分发边界；保留 PostgreSQL 领域存储及现有 Python 应用层，不在本轮改换数据库或业务架构。
- App 提供并管理实际需要的运行环境，安装产物可重定位，不依赖开发者仓库、Conda、Homebrew、开发工具或系统 Python。具体运行时构建选择须以独立运行证据确定，不能仅依据包名或理论可行性。
- 受管运行环境与用户资料分开；升级程序文件不覆盖资料。只有本机认证接口可访问后台，继续保留最小具名桥接、单实例、受控子进程和认证停读约束。
- 首启控制统一呈现准备、等待用户操作、更新、可用和失败状态。未具备运行条件时展示对应设置或恢复动作；只有实际暂态连接故障才提供相应重试。内部版本号和开发路径不作为普通用户完成流程的必填项。
- 本人和模型设置复用既有明确初始化与凭据提交语义；不自动恢复其他身份，不扩大模型出站范围。
- 微信接入的组件选择须固定可取得的源码／构建来源、版本、摘要与完整依赖许可。旧黑盒二进制和当前公开源码不能互相替代证据；新版本须重验实际兼容性。
- 用户先看到退出／重开微信与系统授权的影响，再明确执行一次性初始化。管理员认证留在系统界面，App 和第三方子进程不保存管理员密码，原微信安装包保留；不以关闭系统安全保护作为完成步骤。
- 特权初始化为用户当前明确动作绑定的窄入口，只允许核验后的固定操作和受控产物，不接受任意 Shell／命令／可执行路径，不把权限交给后台同步或候选回复能力。取消、失败或任务结束后不得继续使用本次授权触发新的特权动作。
- LLDB、系统 Python 及微信不同版本的初始化依赖都属于独立交付核验范围；没有证明脱离开发环境可用前，不开放对应“已完成”状态。
- 微信读取范围继续由用户逐次确认绑定，名称不作为稳定身份；OCR、文字同步、来源保存与删除沿用既有产品边界。
- 新空数据环境可以在用户开始首次设置后初始化。已有资料则先只读核验受控目标、基线、迁移历史和兼容性，用户一次确认后再备份、校验恢复能力并逐版本更新。
- 已有安装使用外置本机数据库时，须识别其既有受控配置并提供可理解的保留资料接续方式；不得静默指向新空库、只升级固定默认库，或让用户重新安装来绕过原有资料。具体接续实现必须保留可恢复原目标及身份、来源、绑定和开关。
- 更新前确保目标没有仍在写入或未确认停读的本次运行时。使用真实版本账本和单版本原子执行，支持安全续接；未知基线、历史漂移或不受支持版本进入专门恢复状态，不伪造通过。
- 备份仅保存在端侧受限目录，完成后可查看位置和结果。失败保留真实检查点与备份，不自动以旧备份覆盖原库，不将部分更新显示为完成。
- 新旧 App 版本不兼容时，旧程序不得写入无法理解的结构；App 目录搬动、重复启动与更新中断均需维持唯一受控运行时。
- 对外安装包需要逐项核验实际运行时、组件清单及签名。正式公证、使用私人开发者凭据或外部发布遵循现有授权，开发态 ad-hoc 包只能认证其实际覆盖范围。

## Testing Decisions

- 用户已确认最高接缝为实际安装包的公开 App 操作：新装完成首次使用，以及保留资料的兼容更新。测试应观察用户可见状态、实际结果和正确停止，不通过调用内部控制器制造“已完成”。
- 新装路径从独立空用户目录及没有开发环境的机器开始；不预填解释器／项目路径，不提前迁移目标库，不借用开发机上可执行文件。依赖包可重定位，所有实际执行组件均来自受控安装产物或已说明的系统接口。
- 更新路径使用正式旧版结构和合成资料，保留同范围联系人、消息、关系资料、来源依赖、绑定、开关及暂停状态；用户在 App 内确认备份更新后，从公开界面继续使用并核对结果。
- 覆盖取消与拒绝授权、组件缺失或被替换、初始化失败、数据库启动失败、版本不兼容、磁盘不足、备份失败、迁移失败／中断／重开、账本漂移、重复点击、重复 App 和退出停读。
- 特权协议需验证调用方、操作范围、任务有效期、取消与终止行为，验证不存在管理员密码持久化或后台新提权。模拟系统边界的测试不能代替真实系统授权和微信初始化验收。
- 微信集成必须以确认测试联系人验证初始默认不选、授权后同步、增量去重、关闭停读和候选生成；未经确认的联系人不可读，候选不发送。使用者亲自输入管理员凭据和模型密钥，验收日志不含这些内容。
- 复用现有 App 夹具、真实本机认证 HTTP、正式迁移与独立合成数据库；按一个公开行为的 red → green 垂直切片推进。旧夹具提前准备的结果只能用于相应后端或恢复回归，不能认证新首启路径。
- 自动化、Computer Use、模型／微信实机和真正无开发环境的验收分别记证。只有包、平台、组件版本和数据条件相同的证据才可组合；没有测试资源时如实保留缺项。
- 完成时按仓库要求执行相关类型、测试、打包与签名检查，做 Standards／Spec 独立审查并创建仅含本任务的本地提交。

## Out of Scope

- 云端资料存储、多用户账号、集中模型计费或平台代管密钥。
- 自动发送外部消息、扩大联系人授权、降低 OCR 身份门槛或改变记忆采纳规则。
- 保存管理员密码、静默修改原微信安装包、关闭系统保护、赋予通用命令／Agent 特权能力。
- 自动接管未知旧库、伪造迁移历史、删除既有资料或无确认覆盖恢复。
- 本规格批准本身不授权操作用户当前业务库、改变系统权限、推送代码或对外发布。
