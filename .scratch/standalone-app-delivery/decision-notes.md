# 独立 App 交付：首启与升级决策记录

日期：2026-10-16

当前阶段：产品决策与[任务粒度和依赖](ticket-proposal.md)均已确认；用户要求持续实现。按[任务索引](planning.md)推进，产品尚未完成。

## 已确认目标

- 用户要求修复首次启动与版本升级的产品流程，让其他人拿到 App 后也能使用。
- 用户已明确选择：下载 App 后双击完成首次设置，不需要自行安装 Python／PostgreSQL、填写运行路径或执行终端命令。
- 后台与资料都在本机，由 App 自带并管理运行环境。
- 微信同步的工具准备、联系人确认和必要权限设置纳入首启向导，全程不用终端。
- 用户已同意按两条完整用户路径验收：无开发环境的新机器完成安装、首启、确认微信联系人和生成候选；已有旧版资料的机器在 App 内完成备份与兼容更新，资料、绑定和同步开关保留。模型沿用用户自有密钥，最终消息仍由用户亲自发送。
- 更新体验已通过通俗解释再次确认：保留已有联系人、聊天和关系资料，用户点一次“备份并完成更新”，App 在本机完成备份、兼容更新与重连。失败时保留资料与备份，提供恢复入口。
- 微信首次接入允许向导先说明影响，由用户亲自确认退出／重开微信和必要的一次性系统管理员授权；App 不保存管理员密码，并保留原微信安装包。此为产品设计确认，不代表授权 Agent 现在执行本机权限操作。
- 本轮按 `ask-matt` 路由继续梳理设计，再形成规格和可独立验收的任务；不会用当前机器的单次连接恢复代替独立交付验收。

## 已核实的缺口

1. 当前包只包含 Electron、前端与可选自研探针；没有 Python、后端源码或 PostgreSQL。见[打包入口](../../desktop/scripts/package.mjs)。
2. 桌面启动依赖用户目录内的启动路径配置，没有配置时无法发现或准备可用运行环境。见[启动配置](../../desktop/src/main/backend/config.ts)及[诊断](../../desktop/src/main/startup/diagnostics.ts)。
3. 本次现场先因没有启动路径而被阻止；保存路径后，只读检查确认现有库为 055、仓库要求到 059，返回 `migration_pending`。业务库尚未升级。
4. 通用连接提示仍要求重试；详细诊断只说明外部修正要求，App 内没有完成环境准备或数据库升级的用户路径。见[连接状态](../../desktop/src/renderer/backend-status.tsx)和[机器环境设置](../../desktop/src/renderer/StartupSettings.tsx)。
5. 现有首启测试由测试进程先迁移数据库、再点击 App 重试，验证的是外部修正后的恢复；没有证明干净机器只拿 App 能完成首次使用。见[启动回归](../../desktop/tests/startup-diagnostics.spec.ts)和[夹具](../../desktop/tests/startup-fixture.ts)。
6. 安装脚本固定准备默认开发库，保留已有 `.env`，但没有把桌面启动配置接好；当已有配置指向其他库时，安装目标与 App 实际目标可能不一致。见[安装入口](../../scripts/install.sh)。

## 当前阶段边界

- 产品体验、公开 App 测试路径、任务粒度与依赖已明确，不再重复询问已经确认的选择。
- 微信组件、特权适配及无开发环境的真实可用性须按任务验证，不能把已确认目标写成已实现能力。

## 微信接入的只读核验

- 既有固定材料与公开代码须区分：历史验收对应 CLI v1.6.25，但其精确源码／WCDB 构建来源仍有缺口，不能用当前公开 RC 源码替旧二进制补证或直接恢复第三方随包。
- [wxkey v1.4.8 的固定源码](https://github.com/r266-tech/wxkey/blob/9b70eecdde47a7172b19465c3f977c86b6050e8a/cmd/wxkey/main.go#L546)显示普通用户 bootstrap 会先处理并保存 sudo 凭据；没有现成的普通用户一次性授权／不保存密码参数。euid 为 0 的入口会跳过凭据处理，但通过系统授权接入该受限入口需要独立实现和验证。
- [同版复制与启动链](https://github.com/r266-tech/wxkey/blob/9b70eecdde47a7172b19465c3f977c86b6050e8a/cmd/wxkey/main.go#L1163)默认准备独立微信副本，但会停止微信并启动副本；不能将其包装成无影响的普通下载步骤。
- PBKDF fallback 仍涉及 LLDB 与系统 Python，尚未证明在没有开发环境的新 Mac 上可用；内嵌 NotAlone 后端 Python 不自动解决此依赖。
- [Apple Service Management 文档](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos)说明系统级 helper 需要用户认证，并提供授权状态与管理接口。这只说明接口约定，不能证明上述微信接入已经可行或完成。
- 核验只读取仓库历史材料及公开官方源码／文档；没有运行第三方工具、停止微信、获取密钥、读写凭据或变更系统权限。

## 后续必须解决的设计与验收

以下为待完善的设计清单，不代表对应方案已经确定或功能已经实现：

- 新安装时准备运行环境与空数据库；用户只处理必要的本人、模型及权限设置。
- 已有资料升级时提供可理解的备份、升级和恢复入口；反复重试不能代替升级操作，失败不能伪装为可用。
- 区分缺环境、空库、受管旧库、未受管旧库、历史漂移及真正的连接故障，并给出对应动作。
- 通过 App 公开操作验证全新安装与旧版本升级；独立运行包的验收不得依赖本机 Conda、开发仓库、已迁移测试夹具或预填启动路径。
- 保留联系人授权、模型出站范围、单实例、认证停读和用户亲自发送等既有产品边界。
- 核对第三方运行环境、微信读取工具和 WCDB 的来源、许可与实际分发能力；现有探针打包通过不证明这些能力已交付。
