# 回复准备的异步等待

Triage: ready-for-agent
State: resolved

继续上一轮生成失败优化。用户接受取消准备阶段固定八秒失败机制的方向；已有重复读取优化保留。

## 行为与边界

- 仅初次回复、替换与退出后重试的 prepare 改用可选 `Prefer: respond-async`；旧同步调用兼容，继续调整和历史方向探索保持既有协议。
- 首个 POST 立即返回 202 与无正文 `preparation_id`、`state: preparing`。同路径 GET `.../prepare/status/<preparation_id>` 只查询，不触发准备或模型；处理中仍202，终态返回原 HTTP 状态与受限响应。
- 每个认证后端实例的任务按 owner、contact、session、action、manual scope 和 request_key 隔离。同键同输入复用在途任务，不同输入冲突；已结束任务由新显式 POST 重新走原权威准备，不缓存旧回执绕过复验。
- 默认准备预算120秒，采用协作式取消与期限检查；不把网络断开当作业务已停止。DELETE 同一 status 地址标记取消，实际失败仍须原持久状态结算；退出继续使用已有回执恢复与 interrupt。
- 任务数和并发有界，忙时明确失败；停止或重载不自动重启任务。内存任务不持久化正文，终态仅短期保存原具名接口的无正文回执或安全错误；新 POST、状态读取和取消均不启动模型。
- 最终 prepared writer 与原来源、删除、联系人及输入守卫共用事务；协作取消或期限到达后拒绝迟到材料写入。保留同请求显式重试。
- 桌面在现有等待状态内以短请求查询，每个网络请求仍有超时。取消等待及时清理定时器与请求，并向原任务发送取消意图。准备完成后仍按原唯一执行入口生成，生成请求25秒限制暂不变。

## 实现与测试决策

沿用已确认的生产 HTTP 与桌面生成入口作为公开测试边界，不以私有函数断言替代行为。

- 合成慢准备超过8秒能收到回执；任务查询不触发二次准备和模型。
- 同键并发去重、输入冲突、错路径/身份/手动范围、认证、失败回执与 no_generation 证明。
- 取消、期限、重启后的未知任务及退出/重载结算；来源删除和迟到保存继续阻止生成。
- 最小用例→相关模块→类型检查及现有HTTP回归；最后复用 `npm run dev` 实际 App 验收，不打包、不外部发送。

## 排除项

不修改模型、记忆Worker、同步授权、检索来源范围、人工发送边界或通用八秒网络超时，不宣称消除所有生成延迟。
