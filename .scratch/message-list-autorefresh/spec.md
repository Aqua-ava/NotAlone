# 新消息列表自动更新与同步延迟验证

## 用户要求

新消息入库后自动更新当前联系人的消息列表，不再依赖手动刷新；实际核验微信消息的同步延迟。

## 行为边界

- 复用认证事件与当前联系人消息页的归属核验，通过后自动合并列表。
- 保留已选消息、表达方向、候选编辑和原生成依据，不自动选择新消息或创建候选任务。
- 保留已加载的历史页；按时间和消息 ID 排序、去重，分页不跳过中间缺口。
- 断流仍明确提示；用户重连后自动读取最新一页，不再额外要求点击刷新。
- 联系人、助手会话、来源或连接代际失效后，迟到响应不能恢复旧内容。
- 不扩大微信读取授权，不改 CLI 轮询策略，不增加媒体读取或发送能力。

## 已确认的验证入口

- 用户要求的可见行为：真实认证 HTTP/SSE 夹具连接生产输入小窗，验证自动出现及选择、编辑、依据保护。
- 本机真实消息：区分消息时间、后端写入时间与界面可见时间；现有记录只能证明已测样本，不推断固定时延。
- 如需新发外部测试消息，必须先明确测试会话和精确内容；仅用开发 Agent 的桌面操作发送。
- 仅复用 `npm run dev`；不打包、不启动打包版，不提交真实正文、身份、凭据或截图。

## 验收

1. 正常消息入库后无需刷新即可见；本人消息同样适用。
2. 断流恢复后自动对齐最新列表，保留原选择、编辑与生成依据。
3. 连续消息、分页和迟到响应仍保持范围隔离与正确顺序。
4. 报告实际命令、真实测量样本、测量边界与剩余风险。
