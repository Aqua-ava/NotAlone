## 为什么当前会 UNKNOWN

[source_proof.py](../../backend/src/notalone/memory_extraction/source_proof.py)第 418–446、748–773 行在提案结构与位置合法的前提下，依次区分三类问题：

1. **语义处理范围**：完整窗口须恰一消息、恰一目标，候选来源精确为该消息；多消息、额外上下文、多目标等先返回 `scope_not_supported`。不能只摘出有利片段再称满足原窗口合同。
2. **受控来源前提**：实际文字须与提供的受控来源集一致；`message_type/text_representation` 必须为 `text`，来源快照须能生成活动状态摘要且来源 UUID 合法。缺失时返回 `untrusted_source`。这是当前来源链与保存状态条件，不认证外部文件、微信实物或现实事件真伪。
3. **全文有限语法与提案**：上述条件成立后仍须独立解析来源全文和候选全文，再核图、语用和位置；包装不在当前候选语法中会是 `unsupported_grammar`。通过这些检查仍缺 proof，则为 `missing_proof`；不能由 compiler 补签。

公开用例的 [build_window](../../backend/src/notalone/memory_extraction/evaluation.py)第 81–98 行只建立合成消息身份、sender、正文与时间；[MessageRef](../../backend/src/notalone/memory_extraction/models.py)第 137–148 行的快照默认空、媒体类型与文字表示默认 `unknown`。因此这些公开窗口不能天然满足可信来源前提；多消息窗口还会先被范围检查排除。**本稿不提议给原公开窗口补造 trusted 元数据、缩窗或改 Gold 来获取正例**。后续有来源链的协议控制应由独立的合成来源／loader／隔离保存路径真实形成，不计原公开窗的质量收益。

## 三种选择

| 选择 | 核验对象与收益 | 代价与限制 |
| --- | --- | --- |
| A．暂保持 UNKNOWN | 维持现有有限语法与 grounded 包装之间的不兼容；继续如实展示来源与未知原因 | 不增加 grounded 包装的有效事件依据；原03第一条 AC 的广泛缺口继续保留 |
| **B．原事件的有限包装兼容（推荐）** | 明确包装是系统保留原事件内容与语用归属的一种受控表示；先仅核已知作者刚到家的完整事件，不增加事件种类 | 用户只决定是否接受该范围扩展；表示编号、规则版本、能力核验和必要形状由工程落实并评审；仅此一规则，不签通用指代／转述 |
| C．通用 sender 发言主张 | 新建“当前受控来源记录中，该 sender 的完整正文是某原文”这一较弱主张，可保留字面归属而不解释内部事件 | 现有 AST 无此类型；须另定主张、证据、存储、检索／展示和维度相关性合同。不能把它替代原事件去通过原事件的相关维度门；本稿不推荐作为原03的捷径 |

三种选择都不认证来源叙述在现实中为真。B 核的是有限事件内容在来源与候选表示之间是否得到完整保留；C 只核来源记录中的发言归属。C 中已知 sender 不是引文内任意“我／他／她”的身份结论。即使未来选择 C，原事件若仍作为独立候选存在，其未知依据和原门槛也必须保留。

## B 的建议范围：须用户决定后才成为合同

### 核验对象与最小 Seam

建议将第一切片限定为：显式离线 grounded-v3 输入、**可信单消息／单 target／唯一候选来源**，完整来源匹配现有 `AUTHOR_ARRIVAL_H1`，完整候选仅为程序定义的 `用户原话：“<完整来源>”` 或 `联系人原话：“<完整来源>”`。内文精确保留来源；首尾空白和一个句末 `。` 仅能按显式规则处理，不做模糊归一化。该切片不修改生产默认 grounded-v2 的表示或行为。

保留 `source_proof.verify_proposal` 与 `reverify_basis` 这一小 Interface。新增表示识别和位置映射可以置于其内部 Seam；I/O 继续由 loader／仓储负责，不公开新 AST，不增加可写 Tool、外部读取或模型调用。提案仍来自同次 V；parser 独立核实际来源与完整候选，不相信模型提供的作者、完整性、scope 或依据有效布尔。

用户需要决定的范围是：包装在本切片中承载**原事件内容及其语用归属**，不是只证明“存在一段引用”。接受该范围后，工程须逐项复核候选外层作者、内文事件作者、当前受控 sender、`fact.subject` 一致；事件谓词、completed 阶段、`刚／刚刚` 限定、`assertion/asserted/literal` 及空 H 日期一致。`刚` 不能变成实际日期，原文 quoted “我”也不能脱离这条完整第一人称到达语法绑定作者。

### 表示、版本与依据能力

建议为该表示分配显式表示编号和规则集版本，并让保存复核按原版本分发。具体编号、DTO 形状及是否需要新增前向数据库约束在后继 spec 中落实；本稿不把尚未评审的字段名写成已批准 schema。不可仅替换全局 `rule_set_sha256`，然后让旧 basis 被新规则重新解释；旧 NULL／v1／既有 v2 basis 保持原版本语义，不回填、不重采纳。若当前固定形状不能表达新表示和能力，就显式扩展版本；不能向旧 JSONB 偷塞未知键。

[dimensions.py](../../backend/src/notalone/memory_extraction/dimensions.py)第 208–215 行目前对有效 v2 `semantic_basis` 直接加入 `paraphrase/reference/subject/reported`，有 time qualifier 再加 time。**新表示不能直接沿用这条全维度映射**。建议后继合同逐规则明确以下能力，任何一项都必须由实际完整图与当前绑定复核支持：

| 到达规则可能增加的依据 | 必须核的内容 | 仍不覆盖 |
| --- | --- | --- |
| 作者主体与局部自指 | 来源第一人称、受控 actual sender、包装作者、候选 subject 一致 | 第三人身份、跨消息代词、引用内人物的通用消歧 |
| 有限事件保真 | `arrive_home/completed`、作者与 recency 在完整来源和完整包装中对应，外部无新主张 | 任意引句、其他动作、部分片段覆盖或一般非字面改写 |
| 仅 direct 框架的归属一致性 | 本规则的直接自述及候选语用一致；“原话”作为表示标记不自行改成 report | 嵌套转述、请托收到／接受／执行的区别、第三方 reported 关系 |
| 本规则的 recency 限定 | `刚／刚刚 → just` 仍附到达事件，保存复核不丢失 | 具体发生日期、观察时点与事件时刻互换、H 检索期限 |

这些是建议核验的能力范围，不是已经生成的有效维度集合。后继 spec 必须将能力与维度的对应写明，并用“仅作者／引用对齐不足以签完整 reference／reported”的负控约束它。`truth_intent`、媒体以及其他相关项不因出现引号而补签或消失。仍采用现有相关维度保守超集；一项无依据就保持 pending。

### 严格拒绝边界

- 来源范围或可信条件不成立，仍按现有原因 UNKNOWN；不降低来源要求，不读取额外上下文补全。
- 包装必须整体匹配：日期前缀、相关原文括号、同一原消息续句、多引句、任意尾句、额外断言、嵌套引号及任意自由包装都先 UNKNOWN；不从任意正文中找第一对引号，也不靠部分覆盖签整句。
- 来源不在完整到达语法内，包括第三人、否定、条件、计划、引用或额外上下文，均不因引用逐字而获得此规则的正例资格。
- 包装作者、subject、语用、阶段或限定存在可由完整受控语法确定的差异时，只降级；超出可穷尽语法的内容保持 UNKNOWN，不笼统宣称现实矛盾。不能删改标签、正文或限定恢复通过。
- 位置继续使用实际字符串的 Unicode 码点半开区间，拒 bool／float、越界、错消息及错范围。新合同须同时规定完整包装覆盖和内文／作者／限定的坐标映射；不能把去包装后的临时字符串位置冒充 `fact.text` 坐标。
- proof 缺失／null 或缺必要链接时，不生成新依据。E labels、V supported、编译器输出、旧 basis 或相等 hash 都不能自行补提案或跳过当前全文重验；非法 proof 继续原严格失败路径，原 V 只降不升。

## 选择 B 后的最小验证范围（全部待实施、待运行）

1. **同一 Interface 的真红→绿**：旧直接候选回归；可信 self/contact 的完整固定包装正例与参数组合；null proof、错误作者／subject／语用／阶段／日期、额外尾句、嵌套引用、否定／条件、部分引句、复杂来源、scope／来源状态缺口负控。测试应核完整关系与失败原因，不只核返回 true。
2. **坐标与版本控制**：非 ASCII 位置、空白／句末标点、完整包装覆盖、内外坐标错位、重复片段、错消息／越界／bool／float、错误版本或摘要；旧 basis 用原规则复核，新 basis 不可借旧版本或单改 hash 通过。保存后修改原文、包装、作者／语用或来源状态均使依据失效。
3. **实际 producer 与维度合取**：经 V 严格解析→`verify_proposal`→`build_dimension_evidence`→绑定器，不手工注入 `source_bound=true` 或非空 basis。用弱引用对齐／只作者信息的负控证明不会沿旧 v2 映射签全部维度；相关项缺一仍 pending，report 与风险等原门不被抬升。默认空表和生产 v2 的回归必须保持。
4. **隔离保存／读取／导出／删除**：复用现有 [v2 隔离持久测试 Seam](../../backend/tests/integration/persistence/test_dimension_evidence_v2.py)。独立合成来源经受控 loader 和实际 producer 生成依据，事务保存与确认前重解析；回读和 API 导出核版本、能力、当前来源状态与无正文的定位，跨 `owner_id + contact_id` 读取拒绝。覆盖候选删除／拒绝、来源删除及窗口来源失效清除依据和残留复查。若形状变化，新增前向约束只在隔离库验证，不改历史迁移或业务库。

这组测试只能证明新有限表示与来源链的实现合同，不能证明真实模型会提供有效 proof，也不能补签旧公开窗。当前没有新增实现、测试通过数、真实质量成绩或预算安排；既有测试文件仅指出可复用 Seam。

## 决定之后仍保留的工作

无论选 A、B 或 C，[原03](../memory-accuracy-next/issues/03-per-dimension-rollout.md)第一条 AC 都不能凭本稿勾选。B 只增加一种到达事件表示的潜在依据，不覆盖跨消息指代、省略、多第三人、产权／受益人未知、复杂转述、媒体来源、通用保真、完整核心命题与留出集。受限合成控制、公开主集质量、实际运行时依据与真实 App／渠道验收分别举证，不拼接旧通过样本凑至少15例。

若选择 B，后续先按决定显式补充 ADR-047 的表示／版本／能力合同，并核对 ADR-051 的“编译器不签依据”约束仍保持，再形成精确 spec 与实施文件范围。若选择 C，需先记录新的弱主张领域合同及其独立相关维度，不能用它重解释现有原事件候选。本文不改 ADR、原票 AC／状态、Gold、审核或任何冻结原件。

默认放行表为空、生产 grounded-v2、原语用／0.7／风险三门、V 只降不升和所有相关维度有效依据＋逐类批准的合取门继续保持。有效字段、有限规则正例、质量达标与用户逐类放行是不同证据，不互相代替。
