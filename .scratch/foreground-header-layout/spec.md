# 含顶部提示条的名称区域定位

用户在群聊切换验收中遇到“布局定位·未能确定顶部名称区域”，要求定位并修复。用户主动提供的截图已通过生产 `observeHeader` 的离线内存输入复现相同失败码，OCR 调用为0；原图、标题和裁剪内容均不进入仓库。

## 范围与约束

- 修复受支持微信布局下顶部名称区域的定位，涵盖群聊顶部额外提示条；群聊仍按ADR-055暂停匹配和新生成。
- 沿用已确认的正式 `AutomaticSessionCapture.observeHeader(context:capture:recognize:)` 输入接缝，覆盖真实布局计算、输出协议及OCR收到的局部图像。系统采集及OCR本身用合成边界输入，不运行App、不截屏、不调用Vision。
- 单帧、前台/窗口/几何门禁、顶部局部OCR及质量/唯一私聊/已确认绑定保持。无法证明唯一布局时继续失败关闭；不按固定屏幕坐标直接猜测名称位置。
- 对提供截图仅做端侧内存几何复核，不识别正文、不保存裁剪图、不上传。持久回归仅包含合成色块与几何结构。
- 包含可重复失败回路、最小修复、正反回归、双轴评审和本地提交；真实App复验仍需新的有限场次。

## 已有现场边界

两次用户要求的候选包测试均在已认可时段内正常退出，第二次认证停读、进程退出和随机库删除均确认，租约absent。现场截图表明群聊暂停保护保留，但后续布局失败；不能将测试生命周期通过等同于群聊定位及私聊恢复全部通过。

## 已验证的实现决定

旧检测只搜索窗口顶部45–85pt的横向边界。提供截图在三组相邻内存裁剪中，唯一强边界均位于约95–97pt，均返回原错误；这与带单行顶部提示条的合成96pt布局一致。将搜索上限扩展到110pt，继续在整个范围内要求唯一强边界，不选取多个候选中的任意一条。

名称裁剪的原点、高度及宽度上限保持原实现，最多36pt高、400pt宽；扩展边界检测范围不扩展OCR范围。亮暗主题、1/2/3倍像素、普通62pt和提示条96pt边界、窗口尺寸及非零屏幕位置由合成公开观察回归约束；缺失、多重或范围外边界仍在layout阶段拒绝。
