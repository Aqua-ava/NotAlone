# 07 — 检索评测与向量补充

**What to build:** 用户和维护者能够用合成或匿名化数据评估当前 SQL/全文检索的命中、引用、延迟和 Token 表现；只有评测证明全文不足时，才启用可回退的向量候选路径，并保持相同的联系人隔离和删除语义。

**Blocked by:** 06 — 完整候选回复链路和安全追踪必须先可验证。

**Status:** ready-for-agent
**State:** open
**Triage:** ready-for-agent

- [ ] 建立覆盖同义表达、确切短语、时间条件、无结果、冲突和跨联系人的合成评测集。
- [ ] 记录空结果率、降级率、Top-K 命中、引用纠错率、候选拒绝率、延迟、Token 和 Tool 次数。
- [ ] 先评估 PostgreSQL SQL/全文路径；评测结果能明确说明是否需要向量补充。
- [ ] 如果评测不证明需要向量，任务可以以评测报告和保留现有路径结束，不强行增加向量服务。
- [ ] 如果评测证明需要，向量只作为全文结果的补充候选，由程序合并、去重和排序。
- [ ] 向量不可用时回退到 SQL/全文；Embedding 生成、删除和索引重建不改变原始 L0/Message。
- [ ] 向量数据遵守与文字相同的 Owner/联系人隔离、供应商审查、留存和级联删除规则。
- [ ] 向量能力通过 feature flag 控制，未完成隐私与数据处理评审前不得进入生产。
