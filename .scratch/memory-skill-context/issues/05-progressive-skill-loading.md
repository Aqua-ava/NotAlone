# 05 — Skill 目录与按需加载

**What to build:** 用户生成候选回复时，系统先提供可用 Skill 的轻量目录；用户或模型可以选择一个策略，系统再按需加载对应的不可变版本和受控辅助资源。没有匹配或加载失败时，回复仍使用默认策略。

**Blocked by:** 03 — Skill 必须嵌入已验证的 ReplyContext 和候选回复入口。

**Status:** ready-for-agent
**State:** open
**Triage:** ready-for-agent

- [ ] 目录只包含名称、描述、适用场景、状态和版本等轻量元数据，可以作为会话级稳定内容缓存。
- [ ] 用户明确选择优先；自动选择最多使用一个 Skill，也可以不使用。
- [ ] 选中的 Skill 只加载一个经过校验的不可变版本，记录版本和选择原因。
- [ ] references/assets 只能按当前版本的受控相对路径按需读取；脚本、任意文件、网络、Tool/MCP 和外部发送能力均被拒绝。
- [ ] Skill 只能影响本次回复策略，不能写 Memory、修改权限、读取其他联系人或改变发送边界。
- [ ] 目录、版本或联系人范围变化后，相关缓存和旧运行状态失效。
- [ ] 没有匹配、目录失败、版本不一致或 Resource 读取失败时，系统回退到无 Skill 策略。
- [ ] 候选结果可追踪实际使用的 Skill 和版本，且使用现有 Skill Library 的管理和读取契约。
