# 03 — 基础 ReplyContext 与每轮 Prompt

**What to build:** 用户针对已确认联系人生成候选回复时，系统通过一次新的上下文快照提供当前消息、最近完整对话和少量相关 L1/L2；无关历史不会混入，下一次请求不会沿用上一轮的隐藏上下文。

**Blocked by:** 01 — 关系记忆采纳规则；02 — L2 目录及其 revision/失效语义。

**Status:** ready-for-agent
**State:** open
**Triage:** ready-for-agent

- [ ] 候选回复使用当前 Message、有限的最近完整对话和当前联系人相关的有效 `confirmed_memory`。
- [ ] L2 只作为当前场景的导航或少量提示，不把全量 L2 或历史 L0 注入初始 Prompt。
- [ ] 历史 L0 默认不进入初始 Prompt；初始上下文只包含当前任务需要的资料。
- [ ] 每次候选回复都重新校验联系人、来源和 revision，并生成独立的 `ReplyContext` 快照。
- [ ] 每项进入上下文的资料带来源 ID、状态、有效期和入选原因，且所有资料属于当前联系人。
- [ ] 空检索或基础检索失败时，系统只使用当前消息和最近对话继续，不能编造历史事实。
- [ ] 通过候选回复生成入口验证从请求到可展示候选的外部行为，不依赖具体 Prompt 字符串或数据库查询实现。
