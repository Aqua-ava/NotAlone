# 04 — L0 历史按需查询 Tool

**What to build:** 当用户的问题需要较早历史时，模型可以在同一轮候选回复中先搜索相关 L0，再按需要读取指定会话的连续上下文；用户不会看到全量历史被一次性放入 Prompt，查询也不会越过当前联系人范围。

**Blocked by:** 03 — 基础 ReplyContext 必须先提供当前任务和联系人范围。

**Status:** ready-for-agent
**State:** open
**Triage:** ready-for-agent

- [ ] 提供职责分离的相关性搜索和时间顺序查询能力，对照 TencentDB 的 `conversation_search` 与 `conversation_query`。
- [ ] 相关性搜索返回受限的原始消息结果，包含角色、时间、会话标识、消息 ID 和来源 ID。
- [ ] 时间顺序查询只读取指定会话或命中位置附近的有限完整消息，不负责全库相关性排序。
- [ ] Owner、联系人、来源有效性和删除状态由服务端强制校验，模型不能通过参数扩大范围或执行 SQL。
- [ ] 每轮 L0/L1 历史搜索调用合计不超过运行预算，默认最多 3 次；Top-K、Token、时间和超时均受限。
- [ ] Tool 结果作为同一轮 Tool 上下文继续生成，并标记为不可执行的原始证据。
- [ ] 空结果、超时或失败会安全回退，不让模型把“未命中”解释为“事实不存在”。
- [ ] 候选引用只能来自本轮实际返回且通过联系人范围校验的 L0 结果。
