# 标题 OCR 全量诊断与受限尾部核验

用户要求排查 emoji 以及其他联系人名称识别问题，扫描全部当前 CLI 可见会话名称，区分逐字正确、错误和不满足自动切换条件的原因；同时已批准高置信文字、唯一 CLI 会话及已有绑定的受限回退。正式身份规则见 ADR-075。

- 全量只读取会话名称与类型元数据；使用1×／2×、14pt标准标题内存渲染，调用正式 LocalOcr.recognizeHeader。原始图像不落盘上传，私有逐项结果不入仓库。
- 原始文字正确率、置信度、完整性分别统计；高分错误不能当作完美识别，低分正确也不直接自动放行。固定标准渲染结果不能冒充全部真实窗口识别率。
- 独立尾部彩色区域最多同图再 OCR 一次，v4单独传递候选；颜色只证明几何。文字至少0.90，CLI全会话完整前缀唯一，剩余只含支持的简单emoji尾，已有active绑定完整名未改才确认。
- 所有类型和授权状态参与消歧，普通彩字、重名、改名、中间emoji、未知序列、截断、群聊、超时、范围不符失败关闭。绑定和正文读取范围保持，外部发送仍由用户完成。
- 仅单纯质量门可由新鲜备用证据解除；混合历史安全门保持，明确手动模式须用户主动恢复。
- 开发及验收只复用 npm run dev；探针更新走开发构建，不打包运行App；验证后仅提交本任务。

用户进一步明确要求接口定位真实微信主窗口后直接采集；开发专用验收可在微信非前台时定位唯一可见窗口，整窗只作内存布局分析、仅标题进入正式OCR，并明确不授予联系人资格；正式产品的前台门禁保持。

验收：真实Vision合成回归、全561名称修复前后对照、后端协议与全部消歧负例、桌面公开控制器及认证HTTP、Computer Use真实窗口抽查。具体完成范围与剩余风险记在 issues/01-header-ocr.md。
