Type: task

## Answer

根因：ADR-076 原实现仅在原始分数至少0.90时给完整同名优先级；低分完整正确文字被重新放入编辑近邻集合，与差一个字的其他私聊及企业会话并列，产生错误人工拦截。纯 matcher 和 locator 两层合成重现先稳定失败，修复后通过。不是对某个真实姓名加特例。

按 ADR-077，无tail且存在完整规范化名称命中时，只在完整同名集合内消歧，不加入需修改文字的近邻；没有完整命中才纠错。低分仍须至少0.30及两个真实文字锚点。跨类型同名、重复和规范化碰撞仍阻断，完整命中未绑定或改名不退回已绑定近邻。tail并集、范围/稳定标识、人工历史门与原始分数不变；数字括号例外仍额外要求0.90，避免新的exact方法绕过原门禁。

本机只读实时核验：用户指出的完整标题在全部561项CLI元数据中唯一，原始分数0.50保留，候选由4项变为1项；当前owner下对应唯一active绑定且完整名未变。该核验输入来自用户报告，不伪称新的前台采集或实际自动切换已验收。没有读取新正文、创建绑定或授权。

完整1122条既有OCR回放：唯一正确501→514，错误唯一仍0，13条恢复（11歧义、2群候选否决）。有效私聊293名，两倍率均正确239→249、仅一种23→16、均不能31→28；群聊96名的92/3/1不变。新未通过清单为29项两次均未通过、19项仅一次通过、1项空白名，旧报告已私有备份；逐项数据不入仓库。仍逐字相同却未通过的私聊共22次观察/14条记录：同名冲突16次/8条、低分单字2次/2条、完整性拒绝4次/4条，无其他未解释项。新增同名策略无法证明普遍零误识别，回放不等于逐个真实窗口验收。
