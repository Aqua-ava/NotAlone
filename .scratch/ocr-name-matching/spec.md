# 标题 OCR 与完整会话名单的通用匹配

用户要求 OCR 多字、漏字、错字均结合会话名单核验；唯一且已有有效绑定的私聊自动切换，不确定时人工选择。延续已完成的标题 OCR 诊断，采用 ADR-076；不扩大读取授权。

- 正式输入仍是一帧、已验证布局、完整单行标题；不 OCR 正文或联系人列表，不保存图像。
- 原始分数如实保留。完整高分全名保留精确路径；其他文字以 Unicode 规范化和有界编辑距离查找完整 CLI 名单，至少两个文字锚点，不按绑定状态提前过滤。
- 竞争者包括未绑定、群聊、未知类型及规范化碰撞；多个合理候选不按分数挑选。唯一私聊还须同一账号、稳定标识唯一、active 绑定完整名未变。
- 独立尾部文字与原始 OCR 的候选合并消歧，不能覆盖冲突。布局、完整性、超时、取消和人工安全门保持。
- 阈值是保守启发式，不宣称概率或完美识别；全量标准渲染回放与真实窗口抽查分开报告。
- 仅复用 npm run dev；公共测试均用合成名称；私人逐项报告只在本机私有目录。验证后仅本地提交，不推送。

验收包括纯算法正反例、绑定/范围/类型/截断/取消的 locator 集成、桌面质量门及认证 HTTP、1122 条既有 OCR 的完整名单回放和真实 App 抽查。
