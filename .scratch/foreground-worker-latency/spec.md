# 前台原生进程复用与联系人切换时延

用户于2026-10-19明确要求将已验证的同进程复用方案接入正式流程，排查变化通知和两秒兜底轮询，并以真实微信切换联系人验收。采用ADR-078，局部替代ADR-052的短生命周期进程要求。

- 一个宿主探针实例按请求串行复用一个原生进程，只保留系统模型加载状态。每次请求取得新帧并重新验证当前前台、唯一窗口、几何、标题完整性、完整名单及有效绑定；不得复用帧、文字或身份结果。
- 使用有界、带版本和请求标识的JSONL协议。就绪握手不采集；请求错误、错配、超长、超时和取消均失败关闭，不在同轮重试截图。退出、关闭及权限熔断回收自有进程；空闲最多60秒。
- 变化事件取消正常两秒空等；在途变化合并为完成后的立即复查，拒绝过时身份。技术错误的四／八秒退避、单轮在途和人工确认门不因性能优化放宽。
- 增加显式启用、固定枚举及数值字段的端侧有界计时；名称、联系人标识、正文、坐标和图像不进入普通日志或公开夹具。
- 仅复用`npm run dev`，更新开发原生资源，不打包、不发送消息、不增加联系人绑定或读取授权，不推送。

验证：协议合成正反例、同PID复用、超时/EOF/关闭恢复、生产控制器变化与轮询、相关认证HTTP；真实微信至少覆盖两个可见会话来回切换、已绑定自动选择及群聊安全暂停，分别报告事件触发、原生处理、联系人发布和可见界面核验。实窗条件不成立时如实记录缺口，不把原型计时当端到端延迟。
