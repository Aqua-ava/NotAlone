# 记忆来源语义核验与逐命题评测

> Triage: ready-for-agent
> 来源：用户要求继续完整工作流，解决记忆语义准确性。
> 固定起点：97a4649。上游：ADR-024、ADR-026、ADR-027、ADR-029。

## Problem Statement

合法消息编号与模型自报的确定标签不能证明候选正文忠于原话。公开链路已复现：
否定原文配上相反的肯定候选仍可自动写入。现有评测也会让一条正确候选遮蔽额外错误
候选，并把自动采纳的否定反转只计一般错误，因而可能错误地宣布某维度达标。
用户希望系统自己核验主体与事实含义，而不靠用户逐条发现误记。

## Solution

在记忆采纳前，以独立、有限的来源语义核验将候选逐条与原消息及必要上下文比对。
核验明确支持才继续原有门槛；证据不足留待确认，明确无支持拒绝。核验不改写候选、
不猜人物或日期，不证明现实真伪。评分逐命题检查所有候选、主体、限定及额外输出，
并区分去向测试和有语义标注的测量。真实聊天只在本机最小范围检查，模型实测只用合成资料。

## User Stories

1. 作为用户，我希望“我不喝酒”不会被记为“经常喝酒”。
2. 作为用户，我希望第三人的事情不被写成我或联系人的事情。
3. 作为用户，我希望“可能、准备、如果、偶尔、只有”以及数量、期间被保留。
4. 作为用户，我希望当前事实与未来安排分别判断，不把整个复合句升级为已发生。
5. 作为用户，我希望一条正确候选不能掩盖另一条错误候选。
6. 作为用户，我希望原话支持不充分时安静留待确认，明确矛盾的候选不成为记忆。
7. 作为用户，我希望未执行核验时不能凭高置信度自动入库。
8. 作为用户，我希望核验证据是原文实际片段，不能由模型编造或跨联系人引用。
9. 作为用户，我希望核验失败可重试，不能推进进度并丢掉待处理消息。
10. 作为用户，我希望正确的普通事实继续通过原有安全门，不通过扩大风险白名单增加覆盖率。
11. 作为用户，我希望看到模型置信度的含义，不把它误读成实测准确率。
12. 作为用户，我希望旧记忆、原消息、绑定与暂停范围保持不变，并明确旧数据未经本轮自动重核验。

## Implementation Decisions

1. 在现有公开 ExtractionFlow 与 run_extraction seam 增加显式注入的来源语义核验。
   字段与来源编号先按原规则解析；同一有限窗口中所有可保留候选用一次核验调用批量处理，
   不扩大窗口，不查询其他资料。单批最多核验 60 条候选，超限安全停止，不静默截断。
2. 核验运行时接收窗口及不可变候选，按零起始候选序号返回 supported / uncertain /
   unsupported、受控问题类别与原文证据片段。不得返回修改后正文、改归属、新增来源或确认动作。
   结果必须一一覆盖待核验候选，重复、遗漏、越界或非法结果整批失败。
3. supported 必须提供非空的逐字原文片段，片段引用只属于该候选原来源，且包含 target
   证据。每段必须是对应原消息的实际非空子串。完整支持继续原有门槛；uncertain 追加
   semantic 风险留在 pending；unsupported 拒绝。没有核验器时以未核验风险降级，不自动入库。
4. 核验覆盖正文含义、人物归属、否定、程度、数量、条件、时间、语用和跨话题拼接；
   支持当前有界输入能够提供的文本引用，不声称恢复生产加载器尚未传入的原生引用元数据。
   不使用关键词特判生产主张，不用子串匹配替代语义判断；子串仅核实证据未被编造。
5. 生产 CLI 与 Worker 都默认装配核验运行时，继续使用既有供应商和模型，不新增供应商、
   工具循环、依赖、数据库迁移或配置开关。每次额外调用记录无正文台账；提取与核验的
   成功／失败分别记账。网络失败不推进水位，非法结构输出沿用 ADR-029 的可见恢复策略。
6. 证据片段与结构化核验只在本次运行内使用；已有来源 ID、风险与时间沿当前端口保存。
   本轮不创建永久“已核验正确”标签；模型 supported 不是现实事实证明，也不倒填旧记录。
7. 评测增加允许命题的显式语义标注：逐条完整匹配一条允许命题，每条期望命题检查召回，
   不合并多条候选文字满足一条命题，不让正确候选遮蔽未匹配额外候选。允许已声明的同义
   表述，不要求逐字答案相等。自动采纳的相反或无支持命题计安全错误，记错人独立计数。
8. 保留既有 120 条去向用例与历史记录，标明语义标注覆盖；未标注用例不能作为语义达标
   证据。旧去向评测可在仅处理合成资料的显式 baseline 模式中测原门槛的潜在去向，不能
   作为生产绕过核验的入口。生产默认与有核验评测都走同一 guard。
9. 使用现有模型对合成提取和受控错误候选作配对对照，保留逐条输出与严格复算结果。
   预置错误输出用来验证核验能力，不宣称是模型自然生成的错误或真实聊天准确率。
   保留否定、主体、条件、数量、时间及跨话题的未见变体；不以放宽标注获得通过。
10. 保留 0.7、CONFIRMABLE 和风险白名单；不接入按维放行表。界面改为“模型置信度”，
    明示分数不等于实际准确率。实际数据只读验收，App 重建、双轴评审与中文本地提交收尾。

## Testing Decisions

沿用用户已授权的公开 seam：ExtractionFlow.run → MemoryAdoption.adopt → MemoryPort，
run_extraction 的水位与台账，LangChain adapter 的实际模型输入，evaluate_case / summarize
的逐命题对分。没有用户操作才能验证的步骤时，由 Agent 自主完成。

- 先 red：错误附加主张被正确候选遮蔽、自动否定反转只计一般错误，以及合法 ID 的错误
  正文自动入库；每个行为一个纵切，修复后用公开端口确认可检索集合与待确认风险。
- 核验覆盖支持、未知、无支持、虚构片段、非来源片段、上下文冒充主证据、序号越界／
  重复／遗漏、无核验器、供应商失败、非法结构及原有风险门槛，采用合成窗口和 fake model。
- API／Worker／命令回归确认默认装配、无正文台账与水位失败恢复；不测试提示词字面内容。
- 真实模型只接收合成输入；先保存基线，再对同批候选核验，分别报告安全错误、召回损失、
  结构化失败和语义标注覆盖。至少 15 个独立语义场景，正向和错误候选配对；不将重复对照
  当作维度达标，不宣称全部 120 条或真实分布已充分语义标注。
- 最终相关类型检查、完整迁移的随机隔离 `_test` 库全量测试、Swift 与正式 App 构建、
  双轴评审、当前资料行哈希不变与本机界面验证；不 push。

## Out of Scope

全量重新提取或重核验真实聊天、上传真实原文、旧记忆自动重写、永久核验审计 schema、
原生引用元数据摄入、无日期消息与水位协议变更、固定 TTL、按维放行、待确认参与回复、
生产供应商切换、云端、聊天发送与远端提交。
