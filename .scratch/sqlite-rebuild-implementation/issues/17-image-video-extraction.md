## 交付行为

用户明确选择已确认且勾选联系人下的一条图片或视频消息，得到应用保存并核验的可查看／可播放副本，以及原图、缩略图、质量未知或失败的准确状态；需要原图时由用户明确补提。图片和视频各有可操作页面、正常接口与删除接入，不把可用入口推迟到19。

本票在16的独立副本、尝试身份、受控发布和统一清理上接入类型适配器，保持[媒体规格](../../wechat-media-extraction/spec.md)Q1–Q11及[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)的角色、质量和文件关系。当前真实资源未认证时先用明确合成资源贯通，19按类型核验真实归属。

## 验收条件

- [ ] 正常接口和页面支持单条图片、单条视频及图片原图补提，展示提取、质量、可用性和错误状态；不按选择联系人、页面打开或同步占位自动下载，不支持多选或整联系人批量。
- [ ] 每次新读取复验App运行、已核验账号／绑定／来源、当前联系人勾选和读取总开关，持续遵守16的资料／选择／媒体代次与租约；未认证的消息到资源映射不能执行真实读取，不根据文件名、时间邻近或含糊回退取首条。
- [ ] 图片和视频成功结果是应用保存的独立受管副本；原微信路径仅作必要来源定位，不直接作为保存成功证明，不跨消息共享文件，不修改微信或用户已有文件。
- [ ] `.dat`只按已核验的V3 XOR、V4 V1／V2纯字节合同处理；严格核验版本头、长度和整数边界、AES分段及padding，再将输出交给内容识别和实际图片解码，不能凭猜出的文件头宣布成功。
- [ ] V2只使用当前已授权账号范围内既有且经核验的受控密钥，密钥仅在受控内存中使用、不入库／日志／命令参数；缺失或不匹配明确返回 `needs_image_key`，不自动运行wxkey、扫描进程、刷新密钥或搜索无归属兄弟文件。
- [ ] WXGF及未核验封装明确返回 `unsupported`；不改扩展名、不把未知容器交给下游冒充支持，也不因明确失败擅自取消已确认的图片功能目标。
- [ ] 图片按内容核验格式、尺寸、总像素和实际解码；动画还核验支持的帧范围及资源上限。可打开、尺寸大或扩展名正确都不能证明原图或资源复制完整。
- [ ] 原图质量只接受可靠资源质量证据；明确缩略图可作为有限结果并标“原图未取得”，无证据标未知；质量证据与可查看性分别记录，后续原图需新明确请求，失败不降低已有合法原图。
- [ ] 视频副本分别核验完整资源读取／复制证明、实际容器和受支持媒体轨道／播放能力；仅文件存在、路径可访问或扩展名正确不算可播放，未知codec或截断明确失败或标明受限结果，不假报完整成功。
- [ ] 类型处理遵循先登记、写入校验、短事务发布当前组合和旧清理意图；只留当前所需文件及尝试记录，新结果失败保留仍合法旧成果，有限／未知新结果不得降级旧完整结果。
- [ ] 清单条媒体保留消息占位；来源／联系人失效经统一删除闭包清除自有副本、派生图片、定位／XML证明、暂存和活动引用，晚到处理不能复活旧结果，微信及用户外部原件保持不动。
- [ ] 空间不足不驱逐已有媒体；取消、关闭读取、清除、退出和崩溃按16停止或中断，新明确操作才新执行，同请求键重送不重执行、不自动重新读微信。
- [ ] 同票通过正式接口、页面和真实受管文件验证图片解密成功／失败、缺密钥、坏padding、超长声明、未知格式、缩略图／未知质量、视频截断／不支持codec、原图补提失败及删除晚到场景；图像和视频真实支持矩阵分别记账。

## 验证与证据

依据[媒体运行时研究](../../../research/sqlite-ready-media-runtime.md)复用固定源码和7项`.dat`合成字节合同，不把该结果写成真实`.dat`或所有格式已经可用。以隔离SQLite、独立目录、已登记的合成图片／视频和正常类型适配器执行最小相关检查；复制、容器、可查看／播放和质量证据分别报告。

真实验证按19限定到用户明确指定、授权仍有效的一条消息，当前范围或唯一关联无法核验则不读。提供实际命令、页面反馈、类型矩阵、明示替身、未验范围及自有资源清理记录；既有12／14组合成机制不能代替图片或视频的真实资源归属认证。
