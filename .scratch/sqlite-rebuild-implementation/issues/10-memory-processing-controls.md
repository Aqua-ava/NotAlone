## 交付行为

用户通过统一状态和明确的暂停／继续动作控制已手动启动的固定记忆任务。普通暂停允许当前合法小批收尾，取消联系人或删除来源立即撤销提交资格；退出后保持暂停。失败保留真实进度，手动继续沿用成功步骤和合法回执，不盲目重发未知调用。

## 验收条件

- [ ] 正常记忆界面与状态接口统一呈现固定轮次、实际阶段、待处理、处理中、暂停、受阻和完成；历史失败不冒充当前状态，不把消息、记忆和步骤数量加成虚假百分比。
- [ ] 用户请求普通暂停后不再启动新小批；正在执行且范围／来源仍合法的小批可完成并提交，然后显示已暂停，暂停期间的取消／删除仍立即失效。
- [ ] 取消勾选某联系人立即撤销其提取、整理及本人贡献的提交资格，其他有效联系人可继续；本人混合结果不靠删一个标签继续提交。
- [ ] 清空聊天或删除来源通过05先撤销旧写入资格，再按真实闭包清理；旧模型结果、文档发布和重试即使晚到也不能恢复内容或解除删除排除。
- [ ] 总开关关闭只停止微信新读取，不暂停合法已启动记忆过程；关闭时仍能手动处理已勾选联系人的有效保存文字，独立暂停与取消选择分别生效，不以处理请求触发CLI补读。
- [ ] 单联系人资料／处理失败只让该人受阻，其他人继续；共用模型配置等通用故障暂停相关整轮并显示固定原因，失败不自动重试模型请求。
- [ ] App正常退出或异常中断后不启动后续模型调用，重开保持暂停／受阻及真实已完成结果；读取恢复与记忆恢复分别控制，不把宿主重启当手动继续。
- [ ] 手动继续沿同一合法固定任务、输入与成功步骤推进，新增执行记录，不重做已成功目标／阶段；新消息留到下一次明确启动，不能靠换轮次绕过旧成功或未知状态。
- [ ] 模型准备、发送、已知返回、失败、未知回执和业务提交分别核验；超时、退出或租约失效不证明未发送，继续按钮不能清掉unknown或无条件重发，安全恢复必须有可验证的既有回执或幂等依据。
- [ ] 任务领取、暂停／继续和提交按租约、控制修订、范围／资料代次CAS互斥；过期执行不能用新授权刷新旧资格，旧领取者和迟到回调不得覆盖新状态。
- [ ] 主题／长期概览遵守09的后置冻结和完整集合发布；当前仍有适用阶段未结束或未知回执未解时，不因已有记忆／旧文档可用而显示整轮完成。
- [ ] 控制状态读取失败只展示状态暂不可用与刷新，清除旧范围动作资格；恢复查询不自行改变业务状态、增加预算或发送模型请求。
- [ ] 与04同步控制组合验证关闭读取、重选、退出和重开，不混淆读取资格与已保存资料处理资格；真实模型凭据沿已有配置，不增加新设置或用途授权。
- [ ] 隔离正常入口与真实页面覆盖暂停小批收尾、单人失败／共用故障、退出重开、成功步骤复用、unknown、租约接替和删除晚到，核对界面、账本与可检索内容一致。

## 验证与证据

沿正式认证控制接口、真实存储／Worker、具名桌面桥及正常记忆页面运行隔离合成资料；仅在供应商和精确时序边界使用替身。先单个暂停／删除／unknown反例，再相关控制、同步、完整记忆管线及页面回归，最后在热更新开发App复验实际交互。

以父规格的暂停、失败、退出、总开关和固定目标合同及统一设计的租约／调用回执／CAS为准。分别记录请求是否发出、业务是否提交、阶段是否成功、界面是否反馈，以及实际命令和资源收尾；合成回执不替代真实供应商质量或当前微信验收。

## 范围与执行门禁

- 本轮仅发布任务，不启动实现。`ready-for-agent`表示任务信息可供后续处理，执行仍须用户另行明确下达实现指令；本任务不授权读取私人资料、调用模型或切换／清理真实业务库。
- 适用[实施索引公共约定](../planning.md)和两份父规格；数据库实体、键、状态及事务以[唯一统一设计](../../sqlite-database-rebuild/greenfield-design.md)为准，不采用早期讨论稿的并行结构。新增敏感资料及本人跨联系人依赖均接入[05来源删除与清理](05-source-deletion-and-cleanup.md)，不能只靠隐藏或移除单条引用声称已删除。
- 后续开发只用 `pnpm run dev`，先执行 `dev:status`核验并复用实例；不得擅自打包、运行旧包、修改发布门禁、推送或创建远端分支／PR。
- App首次使用继续搁置；组件安装、新模型设置、干净机器和发布、微信迁移／恢复实验均不属于本任务。不新增模型或凭据入口，沿现有配置核验用途与最小文本出站授权。
- 合成结果与真实模型、真实微信、产品集成分别记账。当前未核验的真实账号／联系人读取范围不可读取；不发送外部消息，不把开发验证能力加入产品工具。
