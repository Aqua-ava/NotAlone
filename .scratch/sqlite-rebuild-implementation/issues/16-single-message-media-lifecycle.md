## 交付行为

用户明确选定已确认联系人下的一条图片、视频或语音消息后，通过正常业务接口和页面保存、查看提取状态或单独清除媒体；文件归应用独立管理，清除媒体保留聊天占位。此票交付真实文件登记、写入、发布和删除协调，不只建表；实际图片／视频适配器由17承接，语音适配器由18承接，未接线类型明确不可用。

数据与事务遵循[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)的 `message_media`、`media_extraction_attempt`、`media_file` 及统一删除账本；读取和代次遵循[同步与记忆规则](../../sync-memory-behavior/spec.md)。通过明确的合成消息和类型适配器可独立验证本票，不要求真实微信先通过。

### 实现与数据影响

- 三实体按用户、联系人及消息限定归属，验证来源、读取/选择/资料/媒体代次及租约；请求回执固定原尝试，互斥、重启中断和旧请求墓碑均不引起自动重取。仅媒体清除推进媒体代次，不推进联系人资料代次。
- 文件先登记随机定位，再排他创建和登记文件/父目录身份；事务外分段写入、同步、独立完整性及类型复核，短事务发布当前组合。失败保留合法旧件，质量降级及无原始父件的播放件不得发布。启动/查看发现实际文件缺失或损坏会撤下成功声明，不自动新读。
- 暂存、退役、原始/派生件和关联证明加入05同一删除计划及同一活动引用集合。实际DOM、播放器src及blob先撤下再ACK；未确认、文件身份改变或未知身份均不能冒称完成。适配器漏await及晚到save不会提前释放在途句柄。
- 正式宿主使用当前联系人生命周期与同一删除协调器，不增加元数据缓存。读取总开关关闭只停止微信读取分支；取消联系人停止全部分支。退出等待领域排空，媒体关闭失败仍结算历史/联系人后关闭存储并保留失败。
- 生产CSP仅为图片和媒体增加blob来源，脚本和网络策略保持原约束。App单文件保存及可撤销预览统一上限32MiB；超限在读取字节前拒绝，不自动驱逐其他成功媒体。媒体正文不入消息文本、记忆、OCR/ASR或模型。
