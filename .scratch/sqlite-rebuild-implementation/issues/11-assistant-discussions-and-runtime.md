## 交付行为

用户可以在已确认联系人下查看、继续已有助手讨论。业务发言与 DSH 运行副本分别持久化，分段、重开、释放及来源删除具有可核验状态；运行副本不能成为独立绕过来源删除的内容副本。

## 验收条件

- [ ] 讨论、发言、请求和运行副本具有真实的用户及联系人关系约束；不能更换讨论的联系人归属，也不能由同一用户身份推导跨联系人可读。
- [ ] 沿用已确认的讨论分段规则；新分段与明确继续旧讨论可区分，重开不隐式继续旧讨论或发起新的模型请求，不预建旧发言编辑／分支平台。
- [ ] 实际用户／助手发言的顺序和来源可回查；模型发言关联本次真实请求及调用，不复制可编辑候选正文来伪造讨论发言。
- [ ] DSH 通过官方 profile、公开插件与生命周期接入，业务数据库保存可见历史主记录；不得修改核心、另造 Harness 或臆造会话删除 API。
- [ ] 副本创建前持久保存独立副本身份、官方 SessionId、固定联系人范围、写入代次及受管保留定位；preparing 时目录尚未建立可无预期身份，允许写入前必须登记真实目录身份。陌生目录或会话身份冲突不得接管。
- [ ] 业务提交、副本 flush／close 与 ready 状态分开记录；只有实际事件边界、配置摘要、来源资格和业务提交均核验后才将副本置 ready，不能把进程内 symbol／revision 当跨重启证明。
- [ ] 运行副本记录真正纳入的每份上下文及其来源，包括展示依据之外的实际输入；来源删除能反查所有当前、退役和重建副本，而非只查当前路径。
- [ ] 重开先检查当前实例、维护／删除状态和副本资格；dirty／preparing 副本不能直接恢复。无法核验时明确受阻，只能从仍合法业务资料在后续明确请求中重建，不为核验调用模型。
- [ ] 来源或讨论清理先持久封禁旧写入，等待 Agent 和读写所有者释放，再在事务外按已登记身份清理完整受管副本，最后复核数据库及活动引用；close 的末尾写入须纳入排空，释放错误或超时不能记清理完成。
- [ ] 在创建目录前后、真实身份落库前、业务提交后、flush／close 期间及删除前后注入失败；重开只沿原清理操作续清，不扩大路径、不误删同定位的新身份，也不将物理文件操作放入长数据库事务。
- [ ] 请求重送及迟到回调保持原请求、租约和写入代次校验；被取消或来源失效的回调不能新建讨论内容或重新登记已删除副本。
- [ ] 现有讨论界面与正常业务入口能展示分段、继续、加载失败和恢复受阻状态；日志不包含聊天正文、密钥、原始路径或可复用私密材料。

## 验证与证据

通过正常讨论服务、正式 profile 和既有桌面入口，用两个联系人及多段合成讨论验证保存、重开、明确继续和范围隔离。使用真实受管临时目录检查释放末写、身份冲突、活动引用与同操作恢复；外部模型仅在已核验授权和配置下有界执行，模拟结果与真实质量分开报告。先运行最小生命周期用例，再覆盖相关副本／删除模块；本轮发布不执行这些验收。
