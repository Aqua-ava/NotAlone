## 交付行为

通过既有开发入口在隔离目录使用受控SQLite：创建可信初始实例、显示真实就绪或故障状态，并在重开和升级后保留同一实例。提供业务逐票加入结构和具名短事务的底座；本票不切换默认业务库，也不把开库成功当作完整产品可用。

## 验收条件

- [ ] 首次创建、普通打开与明确重置分别判断；新库生成独立实例身份和SQLite版本账本，不复制旧PG业务、授权、排除或迁移账本。
- [ ] 业务路径来自受控配置根并核验文件/目录身份、权限、符号链接与预期database_id；目录0700、文件0600；不从工作目录猜业务库。
- [ ] 采用已核验的node:sqlite与专用存储Worker，具名短事务串行执行；所有连接启用外键，WAL、同步和清理策略按统一设计设置，不伪造pg兼容池或开放任意SQL工具。
- [ ] 结构变化与迁移记录同事务提交，重复打开不重放已成功版本；中断可核验后继续，迁移漂移、未知高版本、损坏或实例不符时保留现场并停止业务写入，不另造空库。
- [ ] 精确整数、空值分支、唯一性和复合外键分别验证；integrity_check与foreign_key_check分别通过，不能以其中一项代替另一项。
- [ ] 短写事务不等待CLI、模型或文件I/O；有界busy处置只重试可幂等数据库动作，不重发外部请求；Worker失败和旧租约迟到写入明确拒绝。
- [ ] 通过正常启动/诊断边界和可见状态验收创建、重开、升级中断及拒绝损坏库；使用独立临时根和合成资料，不触碰用户业务库。
- [ ] 为后续业务票提供同一实例的增量结构与事务接入合同，尚未完成的业务能力保持不可用；全部目标结构和消费者完整性由20切换前复核，不在本票冒称77表产品验收完成。
- [ ] 实施时明确修订ADR-101/102中本票涉及的PG底座条款并更新相关入口，保留DSH官方机制、用户模型凭据、原Skill目录和外部原文件。

## 验证与证据

先验证临时库单一开库/事务失败用例，再扩大到升级、Worker和两连接WAL等相关检查；观察实际热更新入口的就绪与故障状态。已有SQLite合成探针可作为机制先例，不能代替本票实际代码和DDL验证。

依据[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)和父规格实施；历史研究票、骨架或已知合成探针不能标为本票已完成。真实门槛见[定稿验证记录](../../../research/wechat-spec-finalization-validation.md)。
