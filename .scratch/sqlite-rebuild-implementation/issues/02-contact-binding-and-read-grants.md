## 交付行为

在现有联系人和同步界面中核验当前账号与真实渠道身份，逐人保存选择及读取授权；取消、重选或会话改名时保持可解释的身份和资格，不扩大范围。

## 验收条件

- [ ] 联系人只由可验证渠道来源建立并关联稳定内部身份；owner、contact、账号、会话和绑定分层，所有联系人数据信息按owner_id+contact_id隔离，昵称/备注仅展示。
- [ ] 复用现有界面和已有可用微信组件；必要列表访问须取得同意，仅处理所需元数据并丢弃夹带摘要，不提前读取正文、媒体或保存全部私聊授权。
- [ ] 新空SQLite重新核验身份和逐人授权，列表不预选，新私聊不自动纳入；旧PG授权及全部私聊范围不迁入；schema有all_private字段不表示启用该范围。
- [ ] 同一已核验私聊取消后重选沿用原binding身份，创建新的授权记录和选择代次；旧请求不因重新勾选自动恢复提交资格，旧清空排除也不解除。
- [ ] 取消某人立即撤销该人的新读取、记忆处理及本地媒体转换资格，但不因取消本身删除合法保存资料；提交时再验账号、联系人、绑定、授权与当前代次。
- [ ] 重名、改名、账号切换、低置信度、稳定身份冲突或来源不连续时明确要求确认或拒绝，不凭名字、内容相似度或旧缓存猜测合并。
- [ ] 前台定位/本次回复确认与后台读取授权分别保存；manual_confirmation不创建联系人、不验证外部会话，也不授予新微信读取。
- [ ] 重复确认与并发勾选幂等，冲突有明确可重读状态；界面、持久记录和后台资格一致，重开不扩大已确认范围。
- [ ] 隔离合成验证同名不同身份、跨owner/contact、取消/重选和旧结果迟到；真实账号或联系人证据未核验时不得读取对应正文。
- [ ] 实施时明确处理ADR-089/095与本轮逐人选择目标的适用范围，保留真实来源、账号隔离和删除排除，不把首用流程搁置理解为取消同步授权。

## 验证与证据

通过联系人选择/授权的业务服务、认证接口和现有页面操作验证，不只断言表行；在合成渠道边界替换元数据，记录与真实渠道差异。必要真实身份检查只在既有有效授权范围进行。

依据[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)和父规格实施；历史研究票、骨架或已知合成探针不能标为本票已完成。真实门槛见[定稿验证记录](../../../research/wechat-spec-finalization-validation.md)。

## 范围与执行门禁

仅承接同步本身的身份和授权；不新增首次使用引导、组件安装或新模型设置。当前无法核验的真实账号/范围保持不可用，不能因测试需要默认授权。
