## 交付行为

用户在已确认联系人下生成候选回复、查看依据、编辑并选择具体版本。每次真实请求、调用、输入快照、候选版本和选择都有准确来历，最终消息由用户亲自发送。

## 验收条件

- [ ] 每次请求关联当前讨论、联系人及真实触发发言，绑定验证或手动定位确认必须符合已确认身份规则；改名、重名、低置信度或匹配失败要求明确选择，手动定位确认不建立联系人或授予微信读取权限。
- [ ] 首次历史尚未完成时阻止生成；已明确覆盖不完整时，仅在用户确认使用已有部分后允许，警告同时进入页面、后端门禁与请求依据，不能由测试替身跳过。
- [ ] 沿用已有模型配置，核验凭据可用、调用用途和必要文本出站授权；未就绪时给出可识别状态，不新增模型设置流程或扩大外部工具权限。
- [ ] 请求、运行尝试、逻辑模型操作及物理调用准确关联；同一请求键重送不产生第二次无意调用，未知调用不能通过新请求／新尝试身份绕过保护后重发。
- [ ] 冻结实际输入与准确版本，原聊天和讨论按当前联系人隔离，本人材料有独立范围核验；只使用仍具生成资格的记忆及发布文档，未确认候选若按既有规则引用须明确标注，不伪作已确认事实。
- [ ] 候选身份与正文分离，模型原稿和手工编辑稿统一从 v1 进入版本结构；模型版关联真实调用及输出位置，手改版关联同候选父版本，不能保留独立 v0 正文或覆写历史版本。
- [ ] 一个版本中的多条短消息保留自己的内容与顺序；缺失或已擦除正文的版本不得选用、携入后续请求或恢复为可读。
- [ ] 选择和改选记录真实事件并固定到具体候选版本；携入后续讨论必须有显式选择和相同讨论范围，不把复制、展示或编辑推断为已经发送。
- [ ] 展示依据指向实际输入快照；模型版依据可追到产生调用的真实输入链。手改稿继承依据时标记尚未重新核验，不能冒称模型已验证修改后的正文。
- [ ] 人工编辑、选稿和迟到生成结果按当前版本、来源资格和控制代次复验；过期结果不能覆盖用户编辑，失效版本不能因重试或重开重新成为当前可用稿。
- [ ] 来源删除接入05及11：清理实际输入窗口、候选及版本、展示依据、选择引用、调用追踪与受管副本；不能仅删除展示依据子集，不能把旧输入的来源替换成另一条记录保住旧证明。
- [ ] 已有候选界面和正常业务接口可完成生成、编辑、选稿与依据回看，并区分失败、未知、覆盖不足和来源失效；产品 Tool、后台和桌面接口均没有外部聊天发送能力。
- [ ] 使用合成已存记忆和文档即可验证检索及版本读取合同，不硬等待记忆／文档写者任务完成；必须在20切换前的隔离产品集成验证实际记忆／文档写者输出的兼容性，21再扩大组合场景；不将夹具读取通过当完整集成。
