## 交付行为

在首次历史接入基础上持续同步合法新消息，响应总开关、退出、取消和重选，并可见地报告缺口及失败；微信读取控制与已保存资料处理分开。

## 验收条件

- [ ] 历史和增量交接无无声缺口，重复读取幂等；可靠游标包含完整作用域和稳定续读顺序，不用单一local_id或排序水位漏掉更新。
- [ ] 仅App运行、总开关开启、联系人已选且账号/绑定/授权有效时发起微信读取；关闭或退出停止后续查询并取消在途读取，旧读取代次结果不能提交。
- [ ] 关闭总开关不删除合法已保存资料，也不撤销其手动记忆处理或合法SILK本地重转资格；本票不因此发起任何模型或媒体请求。
- [ ] 取消某人停止该人新读并撤销相关提交资格，其他合法联系人继续；重选只在新资格下补齐本机仍可读缺口，不复活旧执行或解除清空排除。
- [ ] 账号变化、来源实例/分片不连续、游标失效或覆盖不明确时停止相应范围并可见报错；不能清零旧排除以恢复普通读取。
- [ ] 新消息、发送状态补齐、已存在行的可认证更新分别处理；不重复建消息，未知状态不猜完成；必要更新发现能力按真实支持档验证。
- [ ] 捕获写入、处理关联与检查点原子提交；每页接受前复验当前读取资格、代次及删除状态，取消/关闭后迟到页不能推进新水位。
- [ ] 重开仅恢复仍有效且允许的读取；不得自动调用记忆、恢复未知模型请求或自动提取媒体。
- [ ] 通过现有界面核验开启、关闭、退出、取消/重选、断线与覆盖不足，并验证微信不在前台仍可在有效授权下CLI同步，不把OCR当后台门禁。
- [ ] 03/06尚未认证的真实身份、状态或清空能力继续拒绝放行；合成正向路径须证明合法新消息能够进入，不把全部拒绝当成功。
