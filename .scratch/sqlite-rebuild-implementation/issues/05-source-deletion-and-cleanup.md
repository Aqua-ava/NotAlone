## 交付行为

通过现有来源删除操作立即阻止已失效资料被检索或写回，再按同一删除操作清理并复核数据库、追踪和受管文件。后续记忆、助手和媒体票各自把真实依赖接入这套流程。

## 验收条件

- [ ] 共用统一删除操作、明确类型的目标及分面复核，不另造删除平台；请求幂等并持久保存控制代次、计划修订和重试进度。
- [ ] 先推进范围代次、撤销旧写入和派生使用资格；在途模型、CLI页或文件即使迟到也不得凭旧资格写回；删除本身不隐式调用模型或读取新微信。
- [ ] 来源闭包覆盖实际参与上下文、追踪输入输出、候选/版本/文档/回复依据及本人跨联系人贡献，不只沿展示citation清理。
- [ ] 同一消息或事实另有合法来源时可按规则复验保留，但不能把旧执行的真实来源换指其他记录以保住旧证明、追踪或媒体副本；需模型核验者先撤下资格并等待用户手动处理。
- [ ] DSH等受管副本先封禁和排空持有者，等待公开dispose/close及末次写入结束，再精确清自有文件和活动引用；未确认释放不伪报完成。
- [ ] 清理包括当前、退役、暂存、在途文件与敏感定位/证明；只处理可核验归属的应用副本，保留微信原件、用户外部原文件、模型密钥和受保护Skill目录。
- [ ] 真实含正文追踪随实际参与来源清理；无正文回执与请求墓碑按具体删除范围保留或清除，不把无正文call记录冒充完整过程。
- [ ] 删除行后继续复核SQLite空闲页、WAL/SHM、临时文件及活动读取引用；维护有界排空并核验，失败保持未完成，不承诺SSD或外部备份法证擦除。
- [ ] 发现新目标先更新计划修订并重新复核；全部本次必需存储面通过且无未处置迟到写入才完成，不将DB行已删当跨存储原子成功。
- [ ] 本票通过合成来源、受管文件和可控持有者验证正常/部分失败/重启重试/错误归属；后续每个写者在自己的票内完成删除接入与页面不可读验证。
- [ ] 实施时核对来源、联系人和账号删除的台账保留差异及ADR-031/094等相关约束；不因统一删除而合并不同范围授权。

## 验证与证据

使用临时SQLite、受管目录和确定性活动持有者，先验证单来源清理及幂等，再验证跨联系人贡献、文件失败与晚到写入。通过业务删除入口和公开状态确认结果，不只检查文件或表行是否存在。

依据[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)和父规格实施；历史研究票、骨架或已知合成探针不能标为本票已完成。真实门槛见[定稿验证记录](../../../research/wechat-spec-finalization-validation.md)。

## 范围与执行门禁

可按已定模型与合成来源独立验证，不以等待真实微信作为本地清理前置。它只提供已确认共用合同；各新领域写者必须随票注册清理闭包，20切换前再验完整清单，不能到21才补基础保护。
