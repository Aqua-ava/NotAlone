## 交付行为

用户手动启动的记忆过程在前置提取核验与正式记忆阶段完成后，继续整理主题资料和长期概览，以同范围、同一完整发布集合展示一致结果。场景文档与长期画像共用文档／版本模型，保留各自条目、推断、矛盾及来源，不把局部产出或旧概览当作本轮完成。

## 验收条件

- [ ] 通过正常记忆处理入口消费本轮合法记忆及固定贡献，场景文档与长期画像按 `kind`区分而共用身份／版本模型；本人和联系人范围分别核验，不混用联系人资料。
- [ ] 同一任务的前置记忆阶段成功后、首个文档步骤冻结输入时才捕获记忆修订、文档修订和当前发布集合基线；不能在任务创建时过早冻结，也不能在事后刷新基线掩盖并发变化。
- [ ] 即使本轮选中零条记忆或某阶段明确不适用，也保存适当的基线／原因；零输入、缺记录和失败不能被当作已完成或绕过CAS。
- [ ] 步骤输入冻结到精确记忆版本、文档版本、反馈和真实来源；运行后不追加消息、材料或重新指向当前版本，不通过摘要或裸ID替代来源及版本关系。
- [ ] 主题资料和长期概览的段落、条目、推断与矛盾保存真实形成版本与依据；仅有模型输出但解析、核验或保存未完成时不得用于生成。
- [ ] 发布前复验同范围的记忆／文档修订、当前发布集合、人工保护和实际来源；完整成员集合与指针及文档修订在同一短事务CAS发布，不混合不同轮次的新旧成员。
- [ ] 冻结后出现不兼容并发修订时使本任务文档结果失效，不覆盖另一轮发布；需要新固定输入时由明确后续处理建立新轮次，不自动刷新原任务基线或调用模型重算。
- [ ] 文档发布和读取均验证本人／联系人范围；本人混合资料逐一复验贡献联系人资格，取消某人后不能删标签并沿用混合结果，不影响其他仍合法联系人独立结果。
- [ ] 来源删除经05立即撤销受影响资料及发布资格，清理含正文版本、条目、实际输入追踪及本人跨联系人派生闭包；需语义重新核验时进入用户手动处理范围，待核验内容不可用于生成。
- [ ] 部分阶段失败时保留合法已有资料并明确本轮未完成；只有本轮全部适用阶段结束才显示整轮完成，无须执行的阶段有明确不适用结果，不能以文档条数或模型返回推断完成。
- [ ] 正常页面和检索／回复消费同一个合法完整发布集合；界面可区分当前可用旧集合、本轮处理中、冲突和待核验，来源失效后旧集合不得继续成为有效依据。
- [ ] 隔离正常入口覆盖前置阶段新增记忆、零成员基线、并发发布、完整集合原子切换、本人混合贡献撤销及来源删除后的晚到发布，证明不自我失效、不串范围、不半新半旧、不复活已删正文。

## 验证与证据

通过正式记忆处理服务、真实存储／Worker及正常状态与资料页面，衔接08产生的合成记忆，观察主题／概览阶段、集合发布和检索结果。仅外部模型和确定性并发边界使用替身；故障注入分别覆盖冻结前后、CAS及05删除，不靠直接写发布指针冒充流程。

验收依据为父规格的完整记忆流程、固定范围及删除规则，以及统一设计中的文档、版本、依据、发布集合和后置文档基线合同。先最小冻结／发布反例，再相关整理、检索、页面和删除回归；记录实际命令、结果、资源清理及语义质量边界。

## 范围与执行门禁

- 本轮仅发布任务，不启动实现。`ready-for-agent`表示任务信息可供后续处理，执行仍须用户另行明确下达实现指令；本任务不授权读取私人资料、调用模型或切换／清理真实业务库。
- 适用[实施索引公共约定](../planning.md)和两份父规格；数据库实体、键、状态及事务以[唯一统一设计](../../sqlite-database-rebuild/greenfield-design.md)为准，不采用早期讨论稿的并行结构。新增敏感资料及本人跨联系人依赖均接入[05来源删除与清理](05-source-deletion-and-cleanup.md)，不能只靠隐藏或移除单条引用声称已删除。
- 后续开发只用 `pnpm run dev`，先执行 `dev:status`核验并复用实例；不得擅自打包、运行旧包、修改发布门禁、推送或创建远端分支／PR。
- App首次使用继续搁置；组件安装、新模型设置、干净机器和发布、微信迁移／恢复实验均不属于本任务。不新增模型或凭据入口，沿现有配置核验用途与最小文本出站授权。
- 合成结果与真实模型、真实微信、产品集成分别记账。当前未核验的真实账号／联系人读取范围不可读取；不发送外部消息，不把开发验证能力加入产品工具。
