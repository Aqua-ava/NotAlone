## 交付行为

原有用户维护的 Skill 目录继续受保护，通过官方 DSH 加载并保存最小业务身份与版本锚点。用户可区分已知启用、已知停用及待核验状态，空业务库不会被当作删除 Skill 的理由。

## 验收条件

- [ ] 只接回官方 DSH Skill 加载与必要的包／修订关联，核验当前锁定及安装版本的公开接口；不修改 DSH 核心、不引入任意插件安装入口或另一套加载 Harness。
- [ ] 用户维护的原目录保持，目录身份核验后建立最小关联；新空库缺少引用、缺少审核记录或旧 PG 行不存在均不能触发孤儿清理、目录删除或覆盖原文件。
- [ ] enabled、disabled、unknown 与核验状态分别表达，保留可证明的既有启停状态，不默认全部停用或全部启用；不能仅凭文件存在、文件名或旧快照位置洗成用户授权／审核证明。
- [ ] 包身份与不可变修订锚点分开，保存真实目录身份及内容／清单摘要；读取时重新核验，当前摘要匹配只证明当前字节一致，不证明历史内容仍可读取。
- [ ] 被选择的 Skill 与本次实际载入的内容分别记录；实际调用能回查准确包修订和真实输入，不以 selected 状态代替 loaded 证据。
- [ ] 文件被修改、丢失或身份不匹配时，旧修订不可继续冒充可用；新版本核验与当前指针更新须复验业务修订，不让迟到登记覆盖更晚的用户启停或核验结果。
- [ ] 官方加载的文件访问与业务权限分别核验；Skill 内容不能授予微信读取、跨联系人检索、外部发送或扩大模型资料出站范围。
- [ ] 按已定删除／运行副本合同登记实际Skill输入、修订及资格保护，保留原目录；05或11/12尚未就绪时用明确的合同替身验证注册和失效拒绝，不宣称真实链路已通过。后续写者接入实际窗口后在20切换前复核敏感追踪及副本清理；来源影响包资格时明确待核验，不复制文件制造虚假独立来源。
- [ ] 现有管理或业务查询入口能显示已知启停、待核验、缺失和版本冲突；未核验的未知状态不冒称当前已加载成功。
- [ ] 本轮不新增经验学习、审核发布、方法级停用的业务平台或表；相关旧入口的必要收敛与20切换任务协调，不能因该范围暂不接回而清理用户原目录。
- [ ] 使用官方 profile 的隔离回归验证已启用、已停用、未知、空库、内容变更、目录身份冲突和迟到结果；正常加载可追溯，禁止路径和权限扩展被拒绝，原目录字节保持。

## 验证与证据

用专门创建的合成 Skill 目录和隔离 SQLite 验证官方加载、状态分离、修订锚点及原目录保护，不扫描或重写用户真实目录作为夹具。只有本票直接验证的加载／管理行为可记通过；在12及最终组合验收中核对回复实际输入和来源删除，不能把已安装依赖、类型检查或目录存在当业务加载成功。
