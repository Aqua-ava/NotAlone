## 交付行为

用户明确选定已确认且勾选联系人下的一条语音，保存独立SILK原始件并生成可播放WAV；SILK完整保存而WAV失败时明确显示“语音已保存，暂不可播放”。对仍合法的已存SILK，用户可在读取总开关关闭时手动重转，整个过程不补读微信、不转成文字、不调用模型。

遵循[媒体规格](../../wechat-media-extraction/spec.md)Q1–Q11、[同步与记忆规则](../../sync-memory-behavior/spec.md)和[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)。16提供实际文件和统一删除流程，本票负责语音类型、转换、有限组合及其接口／页面／删除测试；真实语音资源唯一关联由19另验。

## 验收条件

- [ ] 正常接口和页面提供单条语音提取、播放／不可播放状态、手动本地重转与单独清除；不批量取语音，不因选人、打开页面或同步占位自动提取，不调用ASR／OCR／模型。
- [ ] 新语音读取同时核验App运行、当前账号／绑定／来源、联系人勾选和读取总开关，持续复验读取／选择／资料／媒体代次与租约；不能以时间或含糊OR／取首条匹配BLOB，未认证唯一关联时真实提取保持不可用。
- [ ] 只有证据表明该次稳定资源读取完整、实际字节数与预期相符时，才声称原始SILK完整保存；单独摘要、文件存在、头部正确或解码成功均不能补造复制完整性证明。
- [ ] 严格检查受支持腾讯SILK头、逐帧长度与边界、终止规则、最少解码前置包和输入／预计输出限额；未知前缀、无效长度、半帧截断明确拒绝，不盲目增删前缀迁就解码器。
- [ ] 正好整帧截短不能仅靠容器检查判定完整；结合读取证明及可核验时长分别说明证据强度，没有期望长度／完整读取证明时不得标“完整原始语音已保存”。
- [ ] 本地解码产生正确PCM与WAV容器，独立核对采样格式、声道、采样率、字节长度及可播放性；支持输入与codec边界有明确矩阵，宽松解码器返回成功不代替外层检查。
- [ ] `silk-wasm`3.7.1仅作为已有合成验证路线；实施前核对项目实际版本及接口，WASM资产可离线加载并落实资源限额、取消和第三方完整告知，不在运行时从CDN补资产，不将研究制品当成已集成依赖。
- [ ] 原始SILK与播放WAV分别登记文件角色和派生关系，在同一消息下可构成当前所需组合；不跨消息共享，不保留每次旧字节，原件仍被当前播放件或转换依赖时不能误清理。
- [ ] 完整且合法SILK已保存而WAV失败时允许有限结果，明确不可播放及失败原因；若原始件自身完整性无证据则不能套用该成功分支，失败或有限新结果不降低已有合法可播放组合。
- [ ] 读取总开关关闭时允许用户手动本地重转，仅用同消息当前、仍存在且已核验的受管SILK；仍需联系人勾选、来源／文件合法、选择／资料／媒体代次及租约复验，本地分支不要求新微信读取资格，也绝不重新定位或读取微信。
- [ ] 取消联系人、来源／文件失效、单清媒体或清空聊天后不允许继续转换或发布；每次明确重转有新尝试，同请求键重送不重执行，退出／崩溃后不自动重读或重转。
- [ ] SILK、WAV均遵循16的登记、排他创建、写入校验和短事务发布／旧清理计划；空间不足停止新增写入，不驱逐其他成果，新WAV发布失败保留仍合法旧组合。
- [ ] 删除闭包覆盖原始件、WAV、父输入关系、定位／XML证明、暂存、退役、在途转换和活动播放引用，经05的共同账本复核后完成；微信及用户外部原件不改动，迟到转换不能复活已清内容。
- [ ] 同票通过正常业务入口、页面、真实受管文件和独立播放检查验证正常转换、缺证明、截断／坏容器、WAV失败有限结果、关闭读取后本地重转、空间不足、取消和清除并发，不把入口或基础清理推到19。
- [ ] 转换错误、任务和日志不输出语音内容、完整XML、密钥或可恢复私密定位；合成／真实、复制／容器／播放证明及正常配置差异分别登记。

## 验证与证据

复用[媒体运行时研究](../../../research/sqlite-ready-media-runtime.md)的合成解码、宽松截断反例和三层完整性合同；这些结果不等于项目已经支持真实语音。使用隔离SQLite、独立受管目录、明确长度和来源的合成SILK，通过正式操作及实际文件校验先跑单场景，再跑相关模块，记录替身、WASM资源加载和清理结果。

只有19取得当前真实范围与单条语音唯一归属证明后，才验收真实提取。已有原生12项和生命周期14项只覆盖各自机制，不认证语音BLOB关联、当前状态码或本票接线。结果报告明确哪些可播放、哪些只保存SILK、哪些因证明不足而失败。

## 范围与执行门禁

- 本轮只发布任务，不启动实现、产品、微信或模型；后续用户明确要求实现后才执行。
- 后续桌面开发仅使用后台 `pnpm run dev`，先 `pnpm run dev:status` 复用实例；禁止自行打包、运行安装包、解除发布门禁或执行push／PR等远端操作。
- App首次使用整条线继续搁置，不做首用向导、组件准备、新模型设置、干净机器验收／发布；不做微信迁移／恢复实验。
- 未核验现有真实范围时不得读取微信，不能为验证语音擅自开启同步、扫描账号或扩大联系人范围。
- 不做转写、媒体入记忆、模型调用、云上传、批量提取或自动重提；保留用户亲自发送外部消息的边界。
