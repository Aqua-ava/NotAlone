## 交付行为

用户清空某个联系人的全部聊天时，同时终止此前未读旧历史的自动补入，并在有效授权下继续同步新消息；用户以后明确要求重新同步历史时，只为该联系人建立新的合法读取操作。

## 验收条件

- [ ] 清空覆盖该联系人全部已存文字/占位/来源及派生资料，保留联系人与同步选择；通过05推进单调代次，封禁旧历史目标、处理和文件结果，不能以普通暂停的小批收尾规则放行旧写入。
- [ ] 在已授权且允许读取时，持有完整相关分片的只读原生连接，仅枚举该联系人必要身份元数据S(B)，包含本机已有而应用从未读过的旧页；不读旧正文/媒体、不整库备份。
- [ ] 每分片使用独立observer/reader：所有observer先pre采样，所有reader真正读取固定快照，各原observer再post采样；短获取窗口分别相等并核验实例/完整命名空间连续性，随后reader枚举期间允许源正常提交。
- [ ] 获取窗口变化仅在接受前有界重试；不能给微信加写锁、暂停微信或改源日志模式制造静止。分片变化、实例替换、取消或无法证明连续性时候选失效。
- [ ] 完整manifest和精确成员持久化后原子接受B；分段候选不提前生效，不覆盖/撤销旧有效排除；不能只存最大号、时间或摘要。
- [ ] B是所证明的源快照切面，接受后的重试、重启和慢清理不得后移；B后合法新消息必须能在新资格下进入，不把旧writer拒绝当丢弃新消息的理由。
- [ ] 读取前、分段和接受前复验账号、联系人、开关、授权和代次；开关关闭或撤销后不为边界偷读元数据，缺边界明确boundary_pending，不能显示清空成功。
- [ ] 清理按照05覆盖实际来源闭包，包括本人资料、记忆、助手副本、完整追踪及媒体当前/旧/暂存件；合法新代次消息不得被旧清理误删，完成须分面复核。
- [ ] 只有用户明确选择该联系人重新同步全部本机可读历史，重新核验账号/身份后创建独立操作和新授权；普通重启、重选、后台重试不解除历史抑制，不把全部排除记录清零。
- [ ] 显式重读创建新来源并幂等处理重叠消息，不恢复旧记忆、助手会话、媒体、旧证明或旧执行，不自动触发记忆/媒体处理，微信与外部原件不变。
- [ ] 验证首次历史未完、从未读入旧页、同秒/乱序、清空中来新消息、候选中断、已接受B后崩溃与关停；正常写入下能完成边界并继续新消息，全部拒绝不能算通过。
- [ ] 真实支持档与最终读取制品须认证；复用12项研究库机制并不认证当前微信。迁移／恢复实验不在本轮；未知回填类别不得猜新消息，旧排除保护仍保持。
