## 交付行为

用户明确保存、修改或删除长期表达偏好，后续回复按当次有效版本和适用范围使用。偏好保留真实确认及来源，历史回复仍能解释当时使用的版本。

## 验收条件

- [ ] 长期偏好须来自真实明确确认，确认键重送保持幂等；一次回复策略、讨论内容或模型推断不能静默写成长久偏好。
- [ ] 偏好身份与版本分开保存，内容、联系人／本人适用范围及回复模式随版本固定；修改形成新版本并原子核验当前指针，不覆写历史版本或按正文相似自动合并偏好身份。
- [ ] 普通设置、讨论表达和前版继承具有可区分的真实来源；讨论来源须是用户表达，继承关系无环，不伪造用户确认、独立手录或已审核来源。
- [ ] 同一偏好扩大适用范围时仍保留形成它的联系人及来源链；改成全局适用不能清掉原联系人来源，也不能将已删内容复制成新的独立来源。
- [ ] 回复构造核验当次偏好范围、当前资格和版本，将准确版本与偏好修订纳入实际输入快照；不同用户与不适用联系人不能误用该偏好。
- [ ] 用户修改偏好后，新的合法请求读取新版本；已有回复的依据快照继续指向原真实版本，不能把历史实际输入改成新内容。
- [ ] 并发编辑和迟到请求使用当前修订检查；过期保存不得覆盖新确认，旧版本的模型回调不能重新启用已撤销的偏好。
- [ ] 删除偏好或实际来源接入05：撤销新生成资格并清理受影响版本、追踪、回复上下文及运行副本；需要模型重核时等待用户明确启动，删除动作不自动发起模型调用。
- [ ] 仍有其他合法来源时按真实继承和依赖规则复核，不能替换旧证明的实际来源。来源不足或待核验期间不进入生成，用户独立重新输入必须有新的真实确认。
- [ ] 现有偏好管理及回复入口可展示当前适用范围、保存／修正／删除结果及冲突原因；错误与日志不泄漏偏好内容、联系人或凭据。

## 验证与证据

通过偏好管理和回复业务入口，在隔离资料中覆盖长期确认、一次性策略、幂等重送、全局／联系人范围、并发修改、真实版本回看，以及来源删除后的生成禁用。使用跨联系人来源扩大全局偏好的用例检查删除闭包，验证同一库内其他合法资料不受影响。测试采用正常输入构造和正式控制流程，不以直接改表代替确认行为。
