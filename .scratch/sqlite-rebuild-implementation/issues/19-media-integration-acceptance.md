## 交付行为

在16–18已贯通正常业务接口、页面、独立文件和基本删除的基础上，分别核验当前微信图片、视频、语音与选定消息的真实唯一关联，并验证跨类型、同步控制、清除和中断的组合行为。用户能知道哪些类型已认证可用，哪些只有合成证据或仍受阻；不把此票变成最后才接UI、删除或实现全部适配器的大票。

消息与授权基础沿用[03](03-private-history-sync.md)及[同步与记忆规格](../../sync-memory-behavior/spec.md)，媒体归属和文件闭包按[媒体规格](../../wechat-media-extraction/spec.md)及[统一数据库设计](../../sqlite-database-rebuild/greenfield-design.md)独立验收。前置票缺失的实现回到原票补齐；本票处理组合核验及发现问题的证据，不扩大产品范围。

## 验收条件

- [ ] 开始前登记当前程序、CLI／WCDB及适配器实际版本、支持档和证据范围；03的消息身份认证不能连带放行图片、视频或语音资源，三个类型分别给出已支持、明确不支持或未验证结论。
- [ ] 真实检查仅限用户明确指定的一条消息和已确认、仍勾选的联系人；核验当前账号／来源、总开关、绑定及操作用途，范围不明、业务库不可连或状态无法复验时不读微信，不把环境故障解释为可跳过授权。
- [ ] 图片、视频、语音分别证明消息到资源的精确映射及读取完整性；同号、同秒、相似文件名、同内容和重名联系人不串读，禁止未认证的OR／LIMIT 1取首条、时间邻近和目录启发式回退。
- [ ] 正常真实路径至少证明授权单条资源可保存为应用独立副本，并按其类型验证可查看／播放或规格允许的有限结果；没有实际成功证据时如实保留未验证，不能把全部拒绝当正常可用。
- [ ] 图片质量的原图、缩略图和未知有独立可靠证据；`.dat`缺密钥、未知封装和WXGF沿17明确失败，不自动刷新密钥或扩展读取；视频格式／轨道与语音三层完整性沿各类型证据分别记录。
- [ ] 正文同步只产生非文字占位，不自动提取媒体、ASR／OCR或调用模型；页面打开、选人、开关开启、普通同步及重开均不触发媒体批量下载或自动重提。
- [ ] 组合覆盖读取关闭／取消勾选与在途提取并发，停止后续源读取并拒绝晚到发布；已有合法副本仍可查看，18的手动本地重转可在总开关关闭时进行但仍需当前勾选／来源／文件／代次合法，不补读微信。
- [ ] 组合覆盖原图补提、SILK成功WAV失败、重转、同请求重送和新明确重提；旧合法完整组合不被有限新结果降级，请求重送不重执行，不因租约到期或中断后重开隐式恢复。
- [ ] 单清媒体保留消息占位，之后旧提取／转换回调及页面重开不能复活文件；来源删除、联系人清空和媒体替换均沿同一删除计划，覆盖定位／XML证明、当前／退役／暂存文件和活动播放引用，保留微信及用户外部原件。
- [ ] 验证清空已接受的B及媒体代次不会因慢清理或真实关联复核后移；清理只命中登记的旧文件，B后合法新消息及其新操作不被旧清理误删，新读取仍需新资格，不撤销旧排除。
- [ ] 使用确定性合成故障验证空间不足、写入／发布／清理中断、晚到与并发窗口；只清本次可清临时件，不驱逐其他成功成果，不用损坏真实微信或恢复实验制造故障。
- [ ] 真实及合成、机制及产品、复制及格式及播放的证据分别归档；核对页面状态与后端／文件复核一致，缺口保持开放并说明影响，敏感原始资料和可识别截图不入库提交，完成自有临时文件与进程收尾。

## 验证与证据

16–18应已提供每类型正常入口和测试；本票复用它们，通过真实开发App及微信的必要桌面操作核对所授权的单消息结果。仅将真实资源定位与读取放在用户明确范围内；故障注入、跨联系人冲突和中断矩阵使用隔离合成资料，禁止借真实验证遍历私人聊天或全部媒体。

复核[当前定稿证据](../../../research/wechat-spec-finalization-validation.md)、[原生WCDB报告](../../../research/wechat-wcdb-native-results-v3.md)、[生命周期报告](../../../research/wechat-lifecycle-validation-v3.md)及[媒体运行时报告](../../../research/sqlite-ready-media-runtime.md)。既有12／14组合成机制、`.dat`字节合同及解码探针可以复用其有效范围，但不得作为本票新增真实验收。

交付按类型列明实际版本、授权范围的脱敏说明、唯一关联证明、操作步骤、实际命令、页面反馈、文件／数据库复核、与正常配置的差异及清理结果。不能取得某类型真实证据时，该类型保持未验证／受阻且真实入口不放行；不把缺口藏在“综合通过”中，也不要求重新运行未变化的有效测试。

## 范围与执行门禁

- 本轮只发布任务，不启动实现、产品、微信或模型；后续用户明确要求实现／验收后才执行。
- 后续先 `pnpm run dev:status` 核验并复用实例，只用后台 `pnpm run dev` 做开发验收；禁止自行打包、运行安装包、解除发布门禁或执行push／PR等远端操作。
- App首次使用整条线继续搁置，不做首用向导、组件准备、新模型设置、干净机器验收或发布；不做迁移／恢复实验。
- 未核验真实scope及账号／联系人／控制状态时不读微信，不自行开启同步或扩大范围；不发送或撤回外部消息，任何此类测试另需用户明确对象和确切内容。
- 不增加批量提取、自动恢复、共享文件平台、ASR／OCR、媒体入记忆或模型能力；19的完成不代替其他领域与整体验收。
