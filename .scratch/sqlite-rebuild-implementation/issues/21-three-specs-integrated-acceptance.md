## 验收条件

- [ ] 19和20及其全部依赖满足各自验收；功能票已有业务入口、页面反馈、相应测试和删除接入，本票不能靠最后补UI/基础保护冒充前置完成。
- [ ] 按三份正式规格覆盖联系人身份与授权、历史/增量、手动记忆全阶段、修正/撤销、主题画像、讨论/候选版本、偏好、官方Skill、纠错诊断及单条媒体，保持owner/contact隔离。
- [ ] 验证关闭读取时CLI/新媒体停读，仍合法的已启动记忆继续，也可手动处理已存文字及本地SILK；取消单人、独立暂停和来源删除各按不同语义生效。
- [ ] 组合历史未完清空、B后新消息、旧页迟到、显式重新同步历史；重试/重开/重选不解除旧排除，不恢复旧派生内容或自动启动模型/媒体。
- [ ] 组合固定轮次、有限前文、本人跨联系人贡献、文档基线发布、普通暂停小批收尾、单人/共用故障及unknown；验证成功目标不重复、无产出不当失败、未知不盲发。
- [ ] 组合来源清空与模型/DSH末写/文件发布/播放/替换/新代次写入并发；删除闭包、计划修订、SQLite页/WAL、活动引用和跨存储重启恢复均须实际复核，合法新资料不得误删。
- [ ] 组合图片/视频/语音正常与有限结果、空间不足、中断和显式重提；不同消息独立副本、旧合法组合不降级、不跨联系人串读，原微信及外部文件保持。
- [ ] 在日常热更新App中通过实际界面与必要微信操作核验可见状态，先核验并复用开发实例；只用授权测试范围，不以构建或代码审阅代替交互效果。
- [ ] 合成测试、实际开发App、真实模型和真实微信分别列出实际命令、输入差异、版本、通过/失败/未测及清理结果；原生12项/生命周期14项等旧机制证据不代替新产品接线。
- [ ] 完整真实渠道所需的当前schema/身份、状态、只读制品、精确屏障及各类媒体唯一关联逐项认证；无真实证据保持未验证，不把全部拒绝或部分覆盖当完整正向验收。
- [ ] 检查生成和恢复路径仅使用仍合法的资料，候选可编辑且有依据，最终消息人工发送；产品Tool、后台或测试替身不得引入外部发送能力。
- [ ] 输出三份规格验收矩阵、遗留问题与实际数据影响；所有必需验收未通过时本票保持open或报告受阻，不以已发布任务/已提交代码关闭规格。
