# 授权私聊首次完整历史同步

Triage: ready-for-agent
State: open

> 设计状态：2026-10-23 用户已确认完整行为；决策见 [ADR-100](../../architecture/adr/100-authorized-private-history-sync.md)。
> 实现状态：未开始。当前代码仍是 baseline 后的增量同步，本规格不能作为已完成能力引用。

## 问题

用户授权全部微信私聊后，当前系统只会为现有及新增私聊建立联系人，并从授权时刻的 baseline 读取后续新消息。已有聊天历史不会自动进入消息层，新用户打开任意旧联系人时没有语境，无法立即得到符合当前产品的候选回复。已有用户也看到相同结果，且旧授权明确不含历史读取。

本功能要让“授权私聊同步”符合用户的直接预期：只要一个私聊进入有效授权范围，就同步该会话本机当前可读的全部既有文字，再持续同步新消息。聊天历史属于消息层；关系记忆是独立派生层，不因本次导入自动扩张为无界模型处理。

## 用户行为

1. 新用户在首次连接中明确授权全部私聊后，现有私聊自动建立联系人，并开始各自的历史同步；无须逐个导入文件。
2. 使用“仅所选会话”模式逐项授权的私聊，也执行相同的首次完整历史同步。
3. “全部私聊”模式以后发现的新会话，首次纳入时同样读取它现有的可读历史，然后转为增量。
4. 用户看到的是一套持续同步状态；历史追平与实时增量只是内部阶段。
5. 首次同步在后台进行。用户可以继续使用 App，当前选中的联系人优先读取；该联系人历史未追平时不静默生成回复。
6. 单会话历史失败或本机记录不完整时，页面明确标记该联系人覆盖不完整并自动重试；其他会话不受影响。用户可以使用已同步部分，但生成回复前必须看到不完整提示。
7. 老用户的旧授权只覆盖增量消息。升级后需一次明确确认扩展为历史读取；拒绝时原增量同步继续，确认后与新用户完全一致。
8. 总开关关闭、绑定撤销、来源删除或联系人删除后，不继续读取对应范围；恢复时从可靠检查点继续。

## 范围与不变量

- 只处理微信一对一私聊的文字，不新增群聊、其他 App、媒体正文读取、模型用途或外部发送能力。
- 历史消息、实时消息和文件导入都按稳定消息 ID 去重；同一规范消息可以保留多个来源引用。
- 历史与实时消息必须无缝接续。历史追踪期间出现的新消息需要进入同一去重与来源链，不能等到历史结束才建立起点。
- 覆盖状态仍按 `owner_id + contact_id + binding_id` 隔离；昵称、备注和展示名不能充当身份或存储范围。
- 只有本机当前可读的消息能被同步。本机已删除、无记录或读取失败的区间保持未知或不完整，不能推断或生成缺失正文。
- 历史同步完成只表示消息覆盖已追到约定水位，不表示关系记忆已经提取、整理或审核。
- 历史正文沿用现有来源、消息、关系资料、删除和隐私边界；新增能力不得把完整历史无界发送给模型。

## 实现决定

### 授权与迁移

- 引入明确的“历史同步授权版本”状态，替代只靠现有同步范围推断历史读取资格。
- 新用户的首次连接确认同时授予全部私聊范围、开启后台同步和首次历史同步资格。
- 旧授权若版本不包含历史同步，下一次进入相关设置或启动时展示一次明确确认；拒绝不改变已保存的总开关和既有绑定，旧增量路径继续，但不创建历史同步任务。
- 完成一次历史授权升级后，它与新用户使用同一行为，不再出现老新用户分支。
- 重复确认、响应丢失、后端重启和并发刷新不能重复创建历史任务、重置检查点或恢复撤销排除的会话。

### 会话历史覆盖

- 每个绑定拥有独立、持久、可恢复的历史覆盖状态，至少区分：尚未开始、同步中、完整、不完整。
- 逐页读取本机当前可读的既有文字，单页成功写入消息和来源后才推进检查点；分页失败不推进可靠位置。
- 开始历史同步时固定活动水位并持续消费期间的新事件；历史追到该水位且无更早页面后，才能进入完整状态。
- 已有 cursor、baseline、文件导入消息和此前成功观察不能阻止历史读取；使用稳定消息 ID 合并并去重。
- 历史读取不占用单一全局无界事务。总开关关闭、授权撤销和退出必须让对应读取停止或可取消，并保留已提交检查点。
- 当前查看联系人的历史任务优先调度，但不得饿死其它绑定。单会话失败按现有自动恢复思路退避重试。
- 本机历史为空、删除、缺消息表或 CLI 无法解析时标记不完整或对应不可读原因，不能用空结果完成。

### 自定义微信号兼容

- `sessions --type-filter private` 返回的 `username` 是稳定会话标识，即使它不是 `wxid_` 前缀也必须能被后续读取当作原始定位标识。
- 修复当前 CLI 把自定义 `username` 当显示名解析并错误要求缓存刷新的行为；只读产品不能要求执行会写入缓存的 `cache refresh`。
- 该修复必须覆盖单个历史读取、实时读取、全局事件触发、查询与会话列表身份一致性，不得改用昵称匹配。

### 回复资格与记忆分层

- 当前联系人历史同步完成后，正常允许生成。
- 历史未完成时默认不允许新生成；读取失败形成明确不完整状态后，可以允许用户基于已同步部分继续，但请求前必须展示历史覆盖不完整，不能静默使用。
- 历史消息入库可以作为关系提取的合法来源，但不得同步等待全部关系提取完成。提取任务独立排队、限流、可恢复，并在来源、撤销和删除变化时失效。
- 页面分别表达“消息历史覆盖”和“关系资料处理”，不能把二者合成一个“记忆已同步”状态。

## 测试决定

- 授权前已有大量合成文字的单个私聊，首次同步后全部可检索，重复运行不重复写入。
- 新用户全部私聊授权、老用户仅所选授权、上线后新发现私聊三条路径都触发首次历史同步。
- 历史读取期间插入新消息，最终历史、实时消息均存在且按稳定 ID 去重，没有断档或重复推进。
- 已有 cursor、文件导入来源和重叠历史不阻断读取，也不产生重复规范消息。
- 首页当前联系人优先于队列；关闭总开关、撤销绑定和退出后停止新增读取，恢复时不丢已提交检查点。
- 单会话超时、空结果、本机历史删除、缺表和异常输出分别形成可恢复的不完整/失败状态，不阻塞其他会话，不虚假标记完整。
- 旧授权拒绝升级后仍可增量同步但不读取历史；接受升级后只创建一次历史任务，与新用户结果一致。
- 历史未完整时默认阻止新生成；明确的不完整状态下用户若继续，界面与请求证据都保留警告，不声称完整语境。
- 历史入库不等待无界记忆提取；任务暂停、失败或积压不改变消息历史覆盖状态。
- 使用合成自定义 `username`（非 `wxid_` 前缀）覆盖会话发现、历史分页和实时增量，验证不再要求缓存刷新。
- 使用真实开发 App 和微信做只读验收；不向外部联系人发送消息。真实全历史规模、重启恢复和 24 个既有失败会话的兼容结果必须单独记录，不能由合成测试替代。

## 数据处理影响

- 读取和留存范围从授权后的增量扩展为每个授权私聊当前可读的全部文字历史，本机 PostgreSQL 存储量、首次读取时间和检索范围都会显著增加。
- 历史正文仍只保存在本机权威库及其既有派生链路，不因本功能自动增加外部模型调用、媒体上传或发送能力。
- 比此前更大的历史快照会进入来源删除、联系人删除、记忆来源失效和导出／备份边界；实现必须验证删除后不可重新检索或恢复。

## 不在本次范围

- 群聊历史、媒体正文读取或转写、跨微信账号合并。
- 自动发送消息。
- 首次历史入库时立即无界提取全部关系记忆。
- 对文件“历史导入”重新定义；单联系人文件导入仍是独立入口。
