# 多绑定历史调度、失败隔离与覆盖状态界面

Triage: ready-for-agent
State: open
Type: task
Blocked by: 03

按 [spec](../spec.md) 与 [ADR-100](../../../architecture/adr/100-authorized-private-history-sync.md)，让多个绑定的历史同步共享现有“每心跳一页”的续读队列：当前查看的联系人优先，但不得饿死其他绑定；单会话失败只影响该绑定并按退避自动恢复。桌面按联系人展示消息覆盖状态，并与关系资料处理分开表达。

## 验收

- [ ] 多个绑定同时历史同步时每心跳只推进一页，当前查看联系人获得优先调度，其他绑定仍持续前进。
- [ ] 单会话超时、空结果或读取失败只影响该绑定的覆盖状态，其他会话继续；失败按现有退避自动重试，不阻塞队列。
- [ ] 桌面按联系人展示尚未开始、同步中、完整、不完整（含原因），当前联系人进度与汇总可见。
- [ ] 连接成功、即时读取成功或计数增长不会被显示成历史已完整；历史不完整与失败可区分。
- [ ] 消息历史覆盖与关系资料处理在界面上是两个状态，不合并成“记忆已同步”。
- [ ] 控制器、视图与页面级测试覆盖；真实 App 的只读检查可回放。
