# 02 — Worker 执行记忆提取

**Triage:** ready-for-human
**State:** resolved

**What to build:** 提供一次只执行一个可领取步骤的 Worker 入口，使导入任务能够在消息入库后异步执行 `extract_memory`。Worker 需要安全领取、更新进度、处理暂时失败，并支持在崩溃或手动重试后从未完成步骤继续。

**Blocked by:** 01 — 导入任务和固定步骤必须先存在。

- [x] Worker 一次只领取一个有效租约步骤，统一联系人范围内不能同时执行两个任务。
- [x] 租约过期后，另一个 Worker 可以接管未完成步骤；正常租约不能被并行接管。
- [x] `extract_memory` 使用已有的结构化提取、证据校验、自动采纳和出站台账边界。
- [x] 首次历史导入按有限批次处理全部来源消息；后续只处理水位之后的新增消息。
- [x] 网络、超时或模型暂时错误最多自动重试 3 次；成功步骤不重做；失败任务可手动复用原任务重试。
- [x] 记忆提取失败不回滚已经成功入库的消息和来源。
- [x] Worker 输出当前步骤、处理数量、尝试次数和不含正文的错误分类。
- [x] fake model 覆盖成功、pending、证据越界、结构错误、重试和租约接管；不调用真实模型。

## Answer

已完成：新增 Worker 租约领取、同联系人串行锁、租约过期接管、固定步骤推进、记忆提取执行、
自动重试和失败任务手动复用。`PostgresMemoryExtractionRunner` 复用现有结构化提取、证据校验、
记忆采纳、台账和联系人水位；任务记录补充 worker、尝试次数、错误分类、模型版本和规则版本。
失败批次会停止本次提取且不推进水位，避免重试跳过失败消息；永久结构错误不会自动重试。

来源删除同时取消该来源未完成的任务步骤，Worker 不再领取已删除来源。此处只处理任务停止，来源
派生记忆和目录的清理仍由第 4 张票负责。

通过。测试只使用合成 PostgreSQL 数据和 fake runtime。
