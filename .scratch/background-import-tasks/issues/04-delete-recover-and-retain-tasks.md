# 04 — 删除、恢复和任务留存

**Triage:** ready-for-human
**State:** resolved

**What to build:** 将来源删除、Worker 恢复和任务留存接入后台任务生命周期，确保删除优先于未完成的提取或索引，Worker 崩溃后可以接管，终态任务只保留有限时间的最小元数据。

**Blocked by:** 01、03 — 需要任务生命周期和可验证的联系人记忆目录。

- [x] 删除来源时，相关未完成任务进入系统取消/停止路径，不能继续生成依赖已删除来源的记忆或目录。
- [x] 删除来源时按现有删除契约清理规范消息、仅由该来源支持的候选/已确认记忆和目录证据。
- [x] 多来源共同支持的记忆只移除被删除来源的证据，所有来源删除后才失效。
- [x] Worker 在步骤中途崩溃后，租约过期可以从未完成步骤恢复，不重复写消息、记忆或索引。
- [x] 同一联系人任务保持串行；不同联系人不共享租约或状态。
- [x] 活动任务持续保留；成功、失败和系统取消的终态任务保留 90 天后清理。
- [x] 任务清理只删除任务元数据，不影响仍然有效的消息、记忆、联系人和删除凭证。
- [x] 合成 PostgreSQL 测试覆盖删除竞态、来源级不可检索、崩溃接管、重复恢复和终态清理。

## Comments

- 用户主动取消入口不属于 v1；来源删除是停止未完成任务的系统触发点。

## Answer

已完成：来源删除现在先获取 owner/contact 锁并取消相关任务/步骤，再清理消息和派生资料，防止在途
Worker 在删除提交后写回。仅由该来源支持的候选和联系人/owner 记忆会失效或删除；多来源记忆只
移除被删除来源的证据。目录保留剩余引用并标记 stale，删除的 memory_id 不再保留在目录投影中。

Worker 原有租约过期接管和同联系人串行逻辑已纳入删除竞态边界；新增 owner 级锁防止 owner 记忆
并发写回。`cleanup_terminal_tasks` 和 `notalone-task-cleanup` 清理超过 90 天的 succeeded、
failed、cancelled 任务及步骤元数据，活动任务和来源/消息/记忆不受影响。

验证：来源删除、共享来源记忆、owner 记忆、Worker 取消和任务留存测试通过；全套测试 266 个通过、
2 个既有权限测试跳过；未使用真实聊天数据或模型。
