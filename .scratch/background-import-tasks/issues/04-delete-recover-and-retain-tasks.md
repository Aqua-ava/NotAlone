# 04 — 删除、恢复和任务留存

**Triage:** ready-for-agent
**State:** open

**What to build:** 将来源删除、Worker 恢复和任务留存接入后台任务生命周期，确保删除优先于未完成的提取或索引，Worker 崩溃后可以接管，终态任务只保留有限时间的最小元数据。

**Blocked by:** 01、03 — 需要任务生命周期和可验证的联系人记忆目录。

- [ ] 删除来源时，相关未完成任务进入系统取消/停止路径，不能继续生成依赖已删除来源的记忆或目录。
- [ ] 删除来源时按现有删除契约清理规范消息、仅由该来源支持的候选/已确认记忆和目录证据。
- [ ] 多来源共同支持的记忆只移除被删除来源的证据，所有来源删除后才失效。
- [ ] Worker 在步骤中途崩溃后，租约过期可以从未完成步骤恢复，不重复写消息、记忆或索引。
- [ ] 同一联系人任务保持串行；不同联系人不共享租约或状态。
- [ ] 活动任务持续保留；成功、失败和系统取消的终态任务保留 90 天后清理。
- [ ] 任务清理只删除任务元数据，不影响仍然有效的消息、记忆、联系人和删除凭证。
- [ ] 合成 PostgreSQL 测试覆盖删除竞态、来源级不可检索、崩溃接管、重复恢复和终态清理。

## Comments

- 用户主动取消入口不属于 v1；来源删除是停止未完成任务的系统触发点。
