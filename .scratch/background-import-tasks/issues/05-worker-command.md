# 05 — Worker 启动命令

**Triage:** ready-for-agent  
**State:** resolved

**What to build:** 提供 `notalone-task-worker` 命令，复用已有模型提取和 `BackgroundTaskWorker`，让用户可以指定一个联系人并串行执行该联系人最早的一个导入后台任务。

**Blocked by:** 02 — Worker 记忆提取；03 — 联系人记忆目录

- [x] 启动前校验数据库、owner、联系人和模型配置。
- [x] PostgreSQL 全局会话锁保证当前 v1 只有一个命令 Worker。
- [x] 一个命令连续执行 `parse -> normalize -> extract_memory -> index -> verify`。
- [x] 暂时失败自动退避重试，永久失败返回非零退出码。
- [x] 长提取步骤通过租约心跳续期，成功步骤不重复执行。
- [x] 输出只包含状态、步骤数量和错误分类。

## 确认记录

以下记录把 grilling 会话中的 9 个问题与最终决定对应起来；规格和 ADR 保存规范化后的规则，
本节保留问题到决定的追踪关系。

1. **Q1 处理范围**：命令只处理指定联系人，不扫描所有任务；范围是配置中的 `owner_id` 加命令传入的 `contact_id`。
2. **Q2 命令生命周期**：一次启动连续执行一个任务的五个固定步骤；中断后再次启动从未完成步骤继续。
3. **Q3 Worker 数量**：当前 v1 全局只允许一个命令 Worker；底层联系人租约保留未来放开并行的能力。
4. **Q4 自动重试**：模型或网络暂时失败最多自动重试 3 次，并使用有限退避；永久失败停止。
5. **Q5 启动前检查**：数据库、owner、联系人或模型配置检查失败时，先退出，不领取任务、不改变任务状态。
6. **Q6 全局限制位置**：全局串行由启动命令的 PostgreSQL 会话锁保证，不改变 `owner_id + contact_id` 的数据隔离和底层租约语义。
7. **Q7 长步骤租约**：模型调用期间使用租约心跳续期，不把租约简单改成无限期长租约。
8. **Q8 一次处理数量**：一次命令只处理该联系人最早的一个任务，不自动继续处理后续排队任务。
9. **Q9 无任务退出**：没有待处理任务返回 `status=idle` 且退出码为 0；成功退出码为 0；永久失败返回非 0。

## Answer

PostgreSQL 会话级全局锁保证 v1 当前只有一个命令 Worker；一次只处理指定联系人最早的一个任务，
连续执行五个固定步骤，暂时失败按 1/2/4 秒退避并复用已有最多三次重试语义。新增步骤租约续期，
模型提取超过默认租约时仍可安全完成；命令输出不含聊天正文、联系人标识或模型完整输入输出。
