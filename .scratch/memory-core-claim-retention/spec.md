# 记忆核心事实保留与历史阶段保真

## Problem Statement

用户要求继续处理未能正确保留的记忆。上一轮同批自然提取的 12 个必需参考机会中，完整契约准确候选只覆盖 6 个。初核显示其余 6 个并非全部漏提：复合报价出现无来源的意向／限定扩写，历史薪资出现主体、转述标签或当前未知状态丢失，另有整项未生成。正确拒绝错误候选不能称为核验误拒，也不能通过放宽门槛补覆盖。

## Solution

先以冻结原话、参考主张和完整公开 I/O 区分未生成、正文失真、标签／引用错误及误拒，再测试最小事实表达与历史阶段保真。前12项现有接缝试探未达标后，按用户新批准范围开展有限候选修订实验。只发布真实复测证明有效的最小修改；保留原安全门及 source verification，展示全部额外输出、遗漏和失败。

## User Stories

1. 作为用户，我希望报价、观点与意向分清楚，报价讨论不被补成已经决定购买。
2. 作为用户，我希望正确的金额、容量或程度不被添加近似、对象和其他未说过的限定。
3. 作为用户，我希望多个独立事实可以分别保留，每条都有完整直接来源。
4. 作为用户，我希望同一事实必需的条件、时间和否定仍保留，不因拆分而失真。
5. 作为用户，我希望第三人的历史薪资不被归到联系人本人或双方共同状态。
6. 作为用户，我希望原话中的第三人称呼和转述标签都能保留。
7. 作为用户，我希望过去经历与当前未知状态分别表达，不把旧数额当成现在。
8. 作为用户，我希望真实计划继续被正确表示，不因为防止意向扩写而一概丢计划。
9. 作为用户，我希望正确的用户本人状态、共同安排和既有正例继续保留。
10. 作为用户，我希望原话确有歧义时保留未知，不让我确认已确定的模型错误。
11. 作为用户，我希望覆盖统计区分 raw、接受与完整契约准确，不把局部内容出现当成全部正确。
12. 作为用户，我希望修复前后测试沿同一联系人和既有模型服务，不上传完整历史。
13. 作为用户，我希望旧五条认可资料、既有记忆和水位不被本轮评测改写。
14. 作为用户，我希望 Agent 自行核实、测试与本地提交，只把真正有歧义的原话交给我。

## Implementation Decisions

- 工程起点为 `920e71a`，上一轮已验证的记忆思考配置保持。用户接受“逐条归因→修复集中原因→同批复测”的下一轮，不重复询问同一公开接缝与普通实现权限。
- 前12项试探使用现有提取 Runtime、ExtractionFlow、来源核验及采纳公开边界，不新增模块接口、持久化字段、模型阶段、网络目的地、依赖或写入工具。
- 2026-10-02用户明确同意[候选修订有限试验提案](../../docs/memory-candidate-revision-proposal-20261002.md)。允许设计CandidateRevisionRuntime／Plan并先作私有原型，在原核验前最多增加一次有界修订调用；成功空初提也可查漏，失败初提不变相补救。原窗口／字段／source／target／预算、语用及采纳门保持；修订替换不得抬高原置信度或删除原风险、语用与时间阻塞，失败不写业务记忆或水位。逐次调用独立记账，不能藏在初提里。此授权不代表方案已有效或已发布。
- 新阶段按提案逐门推进，最多126次公开invoke，任阶段判败不继续；不循环增加调参轮次。只用同一已授权服务及冻结范围，不新增数据目的地、依赖、持久化字段、写入工具或全历史重提。正式路径发布仍须有效复测、最终冻结留出、相关验证与两轴审阅；设计决定写明状态，不把私有原型称为生产实现。
- 修订原型严格检查原14字段输入并记录原索引及拒项，不能宣称覆盖旧解析器所有容错输入。新增／替换逐声明来源提供精确原文片段，原核验引用门不改；更严格的结构失败与合法损失计入结果。与任一原正文逐字相同的addition整体拒绝，包括先删除再新增；同义改写的来源与权限归属仍须独审，不把字面检查当语义证明。计划绑定当前窗口／候选指纹，应用前重验；未改候选不重写，修正原pending标签仍保留原阻塞。
- 2026-10-03用户明确同意[第二版职责调整](../../docs/memory-candidate-revision-contract-proposal-20261003.md)。第一版逐来源quote契约及其首失败保留为历史；第二版R替换／新增直接返回原14字段Fact，引用与语义支持由原V负责，不补造第一版缺失引用。不改其他语义提示、strict seed、来源／目标／窗口／指纹、不升权限或采纳门。增加一次最多2invoke的第二版匿名阶段；连同第一版已花1次，匿名累计上限3、总上限127。后续24／24／36／40逐阶段门不变，累计预算共用第一版目录不重置；第一版失败阶段关闭，只授权这一第二版，不循环调参。已确认的正确可选seed输入损失仍计入，最终能否恢复须实测，不以结构放行当语义收益。
- 先冻结归因账本与可变红反馈；提示原则或现有字段说明按单变量试探。没有复现的分类问题不顺手修改。
- 四个提取提示试探未达标后，允许按官方 ECNU 当前接口证据测试同一已配置 ecnu-max 的 reasoning_effort=max；已有 thinking enabled 保持，沿现有 extra_body 入口，不改变供应商、输出协议、模型阶段或采纳门。先用无私人资料的结构兼容 smoke，再进行冻结同批／合成比较；更高档不能仅凭文档或配置回显宣称有效。
- 提示与最高档位均未改善后，可在同一来源核验适配器内部试探字段检查：工具 wire 分开正文、主体、语用、时间和引用判断，确定性合成为原四键返回。公开 SourceVerificationRuntime／Result／Flow 接口、两阶段调用上限、采纳门与存储均不变。先验证匿名结构与组合规则，再用冻结原候选比较；逐字段输出仍是模型判断，不能宣称语义已获确定性证明。
- 字段检查未达标后，可测试既有 ECNU 网关的另一文本模型 ecnu-plus，使用现有 model_name 配置入口、原始提取和核验协议及 thinking enabled，不新增供应商或连接。先通过匿名具名工具与隐私过滤兼容检查，再按冻结开发组和实际窗口比较；方案达标并冻结后才首次运行留出。不得仅凭模型更换宣称准确，不修改全局回复模型配置。
- 已捕获的来源编号截断导致完整合法候选丢失时，可在适配器内部试探窗口内短来源编号；输出必须精确还原原 UUID，公开 Fact／VerificationResult／Flow、原 scope／target／quote 校验和采纳门不变。未知编号不得猜测、修补或模糊匹配，不共享跨窗绑定。此改变只处理表达来源的可靠性，语义效果仍须独审复测。
- 漏提与独立主张合并仍未改善时，可试探内部按目标消息分组的提取工具 wire：每个 target 返回一组原字段事实，确无值得记忆的内容允许空数组；出口按原目标顺序摊平成既有 ExtractionPayload。重复、缺失、未知或仅上下文的分组编号须失败关闭，不猜测补齐。原来源、语用、时间、核验与采纳校验不变，不强制每条消息产生事实，不增加模型调用。先只改 wire 与协议说明，不叠加来源短编号；完整分组可能增加整批损失，必须单列并实测，不能把列齐目标视为语义完整。
- 不按私聊句子、数额、姓名或评测答案特判。核验不能改写正文、主体、日期或引用；禁止撤去核验或扩大自动采纳。
- 优先修复模型可见定义的直接矛盾：原 subject 字段说明把 self／contact／shared 一概当事件当事人，而系统提示明确第三人事件的 subject 是关系资料范围。可只澄清该字段说明，不增加 actor 字段或确定性改写标签；原系统提示、字段类型／枚举、Runtime、核验与采纳门不变。源码与匿名边界验证只能证明接口一致，语义收益仍须冻结原话实测。
- 保持 source／target 范围、窗口预算、原语用／风险门与只降不升约束。合法转述只保留 pending，不为了覆盖率升级为 auto。
- 新合成开发与留出在联网前独立复核并冻结；留出揭盲后不得用它继续调提示。旧集合只称回归。
- 实际聊天只沿上一轮冻结的同一已确认联系人必要窗口与现有服务复测。排除已知凭据消息与无关身份；公开请求／返回、首失败与逐索引审计只在仓库外 0700／0600 私有材料保存，不保存内部思考。
- 本轮不写业务记忆或水位，不把 Agent Gold 标作用户确认，不修改上一轮尚待判断的原话。

## Testing Decisions

测试沿已认可的公开模型 I/O 与 ExtractionFlow.run，Gold 来自独立原话核对；fake 只用于重放实际捕获返回或边界契约，不能用预设 supported／unsupported 自证语义。

- 秒级捕获重放先确认现有 6/12 严格覆盖及具体损失，保持原结果和 Gold 不变；新公开模型输出再由独立 Agent 全量逐候选审计。
- 同批 6 自然窗口各两次，逐必需／可选主张统计 raw、接受和完整契约核心覆盖；比较正确保留、正文／标签／引用错误、误拒、坏 auto 和运行失败，不只数最终候选数量。
- 新合成 8 场景分 4 开发／4 留出，含独立正例、禁止擅补主张及完备来源。先冻结方案，再首次运行留出；旧固定候选集合为安全回归。
- 有效修改必须增加严格正确保留或减少已复现语义错误，并且不能用拒绝所有候选或增加坏 auto 达标；未改善方案不进入默认路径。
- 运行最小相关 unittest 与类型检查，最终隔离 `_test` 全量、Standards／Spec 两轴审阅、中文任务专属本地提交。报告真实耗时与数据处理影响。
