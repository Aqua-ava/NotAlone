# 记忆核心事实保留与历史阶段保真

## Problem Statement

用户要求继续处理未能正确保留的记忆。上一轮同批自然提取的 12 个必需参考机会中，完整契约准确候选只覆盖 6 个。初核显示其余 6 个并非全部漏提：复合报价出现无来源的意向／限定扩写，历史薪资出现主体、转述标签或当前未知状态丢失，另有整项未生成。正确拒绝错误候选不能称为核验误拒，也不能通过放宽门槛补覆盖。

## Solution

先以冻结原话、参考主张和完整公开 I/O 区分未生成、正文失真、标签／引用错误及误拒，再测试最小事实表达与历史阶段保真。前12项现有接缝试探未达标后，按用户新批准范围开展有限候选修订实验。只发布真实复测证明有效的最小修改；保留原安全门及 source verification，展示全部额外输出、遗漏和失败。

## User Stories

1. 作为用户，我希望报价、观点与意向分清楚，报价讨论不被补成已经决定购买。
2. 作为用户，我希望正确的金额、容量或程度不被添加近似、对象和其他未说过的限定。
3. 作为用户，我希望多个独立事实可以分别保留，每条都有完整直接来源。
4. 作为用户，我希望同一事实必需的条件、时间和否定仍保留，不因拆分而失真。
5. 作为用户，我希望第三人的历史薪资不被归到联系人本人或双方共同状态。
6. 作为用户，我希望原话中的第三人称呼和转述标签都能保留。
7. 作为用户，我希望过去经历与当前未知状态分别表达，不把旧数额当成现在。
8. 作为用户，我希望真实计划继续被正确表示，不因为防止意向扩写而一概丢计划。
9. 作为用户，我希望正确的用户本人状态、共同安排和既有正例继续保留。
10. 作为用户，我希望原话确有歧义时保留未知，不让我确认已确定的模型错误。
11. 作为用户，我希望覆盖统计区分 raw、接受与完整契约准确，不把局部内容出现当成全部正确。
12. 作为用户，我希望修复前后测试沿同一联系人和既有模型服务，不上传完整历史。
13. 作为用户，我希望旧五条认可资料、既有记忆和水位不被本轮评测改写。
14. 作为用户，我希望 Agent 自行核实、测试与本地提交，只把真正有歧义的原话交给我。
