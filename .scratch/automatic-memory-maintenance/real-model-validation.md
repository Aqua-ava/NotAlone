日期：2026-10-18。用户明确授权真实模型验收，并将请求次数调整为不限。只发送合成对话至当前配置的官方 DeepSeek Flash；没有读取或外发私人聊天。

## 结果

- 联系人：乌龙茶偏好 → 明确更正为红茶。真实提取、来源核验、UPDATE 裁决、两轮 L2/L3 均成功。
- 本人保留样例：每周末跑步 → 明确更正为游泳。未根据这个样例调整代码，同样通过。
- 两例更新后均只有一条当前有效记忆，revision=2，supersedes 指向旧项；L2/L3 仅引用新版本，维护完成且覆盖数等于有效记忆数。
- 寒暄没有成为长期记忆。两例分别由独立 Agent 审核实际模型响应及持久化结果，通过；不登记为人工审阅或正式全局质量资格。

每例完整成功链路均为 13 次真实物理请求。全部诊断累计 60 次，含早期失败和验收脚本调试，不重置问题账本。计数从本次任务开始，不代表此前实验总数。原始请求／响应、各轮审阅和累计账本保存在仓库外私有证据目录。

## 发现与修复

1. Direct 生成遗漏无期限习惯的双 null 时间规则，把陈述时间当偏好开始日，被独立核验拒绝。补齐与既有核验一致的时间规则；不改写模型日期、不放松核验。该提示修改已随并行会话的 `34a145e5` 提交保留。
2. 明确更正即使核验支持，也被旧语用门一律要求人工确认。仅在默认逐条核验策略、同次有效来源回执、唯一阻塞为更正时解除该项阻塞；保留原语用标签、风险和人工修正保护。
3. 新旧表达的字符二元组重合度为 0.1702，低于 0.2，旧版本未进入裁决，导致两条同时有效。对上述已核验更正采用同类别／主题的有界召回，交给裁决选择 UPDATE／KEEP；不直接删除或替换。

验收脚本也修正了导入夹具必须包含本人身份、两类任务状态接口的差异、维护结束断言和数据库清理实测。早期“有新记忆和新整理结果”不足以证明更新，现已断言新旧 active ID 互斥，并独立审核版本关系。

## 复现与验证

在 backend 目录，先按 `docs/agents/quality-diagnosis.md` 建立同一问题账本并开始轮次，再显式运行：

```sh
python -m tests.integration.server.real_model_automatic_memory --output "$EVIDENCE_DIR" --ledger "$DIAG_LEDGER" --round "$ROUND" --case contact_tea
python -m tests.integration.server.real_model_automatic_memory --output "$HELDOUT_DIR" --ledger "$DIAG_LEDGER" --round "$HELDOUT_ROUND" --case owner_exercise
```

两个命令间须结案上一轮再开始下一轮；不能复制或重建账本重置额度。该入口不被普通 unittest discover 自动执行；只复用测试库迁移和 HTTP 辅助，不替换模型、核验器或采纳策略。L1 与整理物理发送均先经过同一问题总账，整理另受 PersistentSuiteBudget 约束。

相关离线回归 59 项通过：`test_automatic_memory`、`test_adoption`、`test_pragmatics`、`test_direct_adapter`、`test_all_source_adoption`、`test_merge`。新增测试先复现更正被阻塞、低重合漏裁决，再转绿；覆盖缺回执、未知来源、歧义、显式旧策略及人工修正保护。未重跑全量测试。

范围限制：证明这两个合成场景的真实模型自动提取、明确更正 UPDATE 和整理；没有声称所有记忆类别、MERGE 或私人聊天整体质量通过。没有发送微信消息。所有专用测试库已删除；保留证据，没有创建打包产物、重启用户的开发 App 或推送。
