# NotAlone 官网视觉与页面规格

State: open
Triage: ready-for-agent

## 用户问题

访客需要在一个有辨识度的官网中快速理解 NotAlone 是什么：它帮助用户在具体联系人关系语境中找到更合适的表达，但不替用户发送消息或虚构人格。官网主要用于展示产品体验；懂代码的访客可以在页尾进入源码仓库。

## 目标

建立一个以产品展示为中心的单页官网，先建立品牌记忆，再用概念化的回复工作台证明产品价值。官网可以展示目标产品愿景，但必须明确当前仍在开发中，不得把未实现的 UI 或端到端能力描述为已完成。

## 已确认的设计决策

1. 首屏主标题是巨大产品名 `NotAlone`，下方放产品副句；不使用对话句作为首屏主标题。
2. 核心文案方向是“不是替你回复，是陪你找到自己的表达”，对应领域术语“真实表达”。
3. 首屏及第一个大型展示使用“回复工作台”：联系人、表达方向、候选回复、依据在同一视图中出现。
4. 页面采用整屏产品章节：每一屏聚焦一个能力或边界，而不是普通 SaaS 功能卡片长列表。
5. 视觉参考组合：Claude 的文字宣言与产品展示布局；Teenage Engineering 的大型产品展台与工业目录感；Kimi K3 的工程图、节点、测量线和实验材料；Physical Intelligence 仅参考浅色背景和安静空间。
6. 主色为冷灰 + 黑 + 深蓝。深蓝用于结构与状态，避免高饱和科技渐变。
7. 回复工作台的材质暂不决定；“实体仪器/工业面板”“纸张/手稿”“外部仪器、内部纸张”作为首屏原型的并列探索分支。
8. GitHub 源码链接低调放在页尾，不作为首屏主要行动按钮；不承诺“下载产品”或成熟安装包。

## 页面线框

### 01 / 首屏：产品名

- 极简导航：NotAlone、少量章节锚点、页尾源码入口提示。
- 大面积冷灰背景。
- 巨大 `NotAlone` 标题，配副句：`不是替你回复，是陪你找到自己的表达。`
- 下方或侧方出现大型回复工作台预览，作为产品物件，而不是普通浏览器窗口截图。

### 02 / 联系人：先确认“对谁说”

- 展示联系人确认和会话范围。
- 视觉重点是稳定身份、选择和边界，而不是猜测联系人。
- 文案避免“AI 自动读懂所有聊天”。

### 03 / 关系语境：为什么不是通用润色

- 展示同一联系人下的近期对话、关系记忆和当前表达方向如何形成限定上下文。
- 只展示抽象或合成示例，不放真实私人资料。

### 04 / 表达方向：你想怎么说

- 展示用户给出的草稿、单独说明或确认后的表达方向。
- 一次性改写要求不能被表现为永久人格设定。

### 05 / 候选回复：给你几种说法

- 展示 1–3 条带依据、可编辑的候选回复。
- 依据可查看；候选不自动发送。

### 06 / 由你决定：最后一句由你发送

- 明确用户可以修改、复制并亲自发送。
- 不展示或暗示发送 Tool、后台代聊或自动联系第三方。

### 07 / 页尾：开发状态与源码

- 明确“产品开发中”或当前可验证范围。
- 低调提供 GitHub 源码链接。
- 不写“已完成端到端产品”“全部本地”“端到端加密”等仓库尚未支持的承诺。

## 不在本轮范围

- 不实现完整真实产品 UI 或桌面 App。
- 不连接真实微信、真实联系人资料或外部发送渠道。
- 不确定回复工作台最终材质、最终字体和最终品牌标志；先用首屏原型验证。
- 不新增下载、登录、等待名单或自动化 CTA。

## 测试与验收方向

- 首屏在不滚动时能识别产品名、核心作用和产品仍在开发中。
- 首屏大型展示能同时表达联系人、表达方向、候选回复、依据四个概念。
- 页面所有示例数据均为合成内容，不包含私人资料。
- 页面不出现自动发送、代聊或已完成端到端能力的暗示。
- 页尾存在 GitHub 源码入口，且视觉权重低于产品展示。
