# NotAlone 官网视觉与页面规格

State: resolved
Triage: ready-for-agent

## 用户问题

访客需要在一个有辨识度的官网中快速理解 NotAlone 是什么：它帮助用户在具体联系人关系语境中找到更合适的表达，但不替用户发送消息或虚构人格。官网主要用于展示产品体验；懂代码的访客可以在页尾进入源码仓库。

## 目标

建立一个以产品展示为中心的单页官网，先建立品牌记忆，再用回复工作台展品证明产品价值。功能做到可用才会发布，因此展品以成品感呈现，页面不标注开发状态；页尾只提供 GitHub 来源链接。

## 已确认的设计决策

1. 首屏主标题是巨大产品名 `NotAlone`，占据整屏：约占屏宽 50% × 屏高 30%（以原型风格 1 实测尺寸为准），下方放产品副句；不使用对话句作为首屏主标题。
2. 核心文案方向是“不是替你回复，是陪你找到自己的表达”，对应领域术语“真实表达”。
3. 首屏只放大字 `NotAlone`，不放回复工作台；工作台展品作为滚动后的第二个大型展示。
4. 页面采用沉浸式大场景：往下滚动时镜头拉近工作台展品不同部位，联系人、表达方向、候选回复、依据四个概念在看展品的过程中呈现，不设独立文字章节。
5. 视觉参考组合：Claude 的文字宣言与产品展示布局；Teenage Engineering 的大型产品展台与工业目录感；Kimi K3 的工程图、节点、测量线和实验材料；Physical Intelligence 仅参考浅色背景和安静空间。
6. 主色为浅色背景 + 淡蓝元素。字色用黑/深灰蓝，淡蓝用于光斑、结构线与状态点；避免高饱和科技渐变。背景整体为冷灰/浅蓝空气感，而非深色。
7. 首屏艺术字采用 AI 生成的“水彩花体 × 波普拼贴”方向，以 F5 颜色和 P6 排版为基准拓展 M/X 系列；文字保持可识别，抠图后作为独立视觉资产使用。
8. 页尾只放 GitHub 链接，不展示源码内容；不作为首屏主要行动按钮，不承诺“下载产品”或成熟安装包。

## 页面结构（沉浸式大场景）

### 01 / 首屏：全屏产品名

- 极简导航：NotAlone、少量章节锚点。
- 浅色冷灰背景 + 淡蓝空气光斑。
- 巨大 `NotAlone` 水彩花体拼贴标题，约占屏宽 50% × 屏高 30%，配副句：`不是替你回复，是陪你找到自己的表达。`
- 首屏不放工作台，字是唯一主角。

### 02–05 / 滚动放大：镜头拉近展品部位

访客继续滚动时，镜头拉近展品的不同部位，概念在看展品过程中呈现，不设独立文字章节：

- 联系人部位：稳定身份、选择和边界；避免“AI 自动读懂所有聊天”的暗示。
- 表达方向部位：用户草稿、单独说明或确认后的方向；一次性改写要求不被表现为永久人格设定。
- 候选回复部位：1–3 条带依据、可编辑的候选；依据可查看；候选不自动发送。
- 由你决定部位：可修改、复制并亲自发送；不暗示发送 Tool、后台代聊或自动联系第三方。

所有示例数据均为合成内容，不放真实私人资料。

### 06 / 页尾

- 只放 GitHub 链接，不展示源码内容。
- 不写“已完成端到端产品”“全部本地”“端到端加密”等仓库尚未支持的承诺。

## 不在本轮范围

- 不实现完整真实产品 UI 或桌面 App。
- 不连接真实微信、真实联系人资料或外部发送渠道。
- 回复工作台材质已从三材质分支收敛为“浅色 + 淡蓝 + 纸张感”方向，但工作台具体布局细节待下一轮原型验证。
- 不新增下载、登录、等待名单或自动化 CTA。

## 测试与验收方向

- 首屏在不滚动时能识别产品名 `NotAlone`（水彩花体 × 波普拼贴、约 50% 屏宽）和副句。
- 滚动后工作台展品依次呈现联系人、表达方向、候选回复、依据四个概念。
- 页面所有示例数据均为合成内容，不包含私人资料。
- 页面不出现自动发送、代聊或后台能力的暗示。
- 页尾存在 GitHub 链接，且视觉权重低于产品展示。
