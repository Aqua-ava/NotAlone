## Answer

新增轮次完成后自动接纳后续消息目标。后续轮次只选择未归轮、无完成回执且来源仍有效的任务目标，同一消息跨来源只冻结一次；同一观察任务携带的后续目标会在旧轮完成后复用原任务重新排队，不新建任务或刷新回执。通知重放与并发接纳由范围锁和目标唯一键收敛到一个后续轮次。

受阻轮次不再允许同范围任务继续领取，也不因新通知重置原任务失败、尝试次数或预算。新观察回执保留为等待资料，恢复仍需明确继续；其他联系人继续沿原全局串行 Worker 推进，没有增加并发。旧主题画像入口的显式继续只重开该原任务所在且没有其他失败任务的受阻轮次，保留兼容到 06 收口。

正式认证 HTTP、隔离 PostgreSQL 和真实 Worker 已观察两轮自动完成、受阻联系人保留、另一联系人完成；轮次存储覆盖运行中新目标、同一观察任务跨轮、重叠来源去重、五路并发重放和三次重试耗尽。实际 `pnpm run dev` 观察到暂停 0/1 与后续 1 条等待，继续后自动完成两轮并显示已完成 1/1；受阻联系人保持 0/1、另有 1 条等待且无观察任务风暴，往返切换不串状态。合成资源和进程均已清理；未验证真实供应商质量、真实微信资料、启动恢复或存量接入。
