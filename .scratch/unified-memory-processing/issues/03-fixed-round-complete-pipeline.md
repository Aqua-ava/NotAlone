# 03: 固定一轮资料，完整处理到画像

Triage: ready-for-agent
State: resolved
Blocked by: 02

规格：[统一记忆处理生命周期](../spec.md)。决策依据：[ADR-107](../../../architecture/adr/107-unified-memory-processing-lifecycle.md)。

**What to build:** 在统一继续或已接纳工作的执行路径中形成一轮固定目标，贯穿提取、核验保存、必要索引、主题和画像；使用相同状态入口展示整轮进展及合法完成结果。严格限定一轮，不扩展至新增资料的自动连续调度、启动恢复或存量接入；向 04／05 提供稳定的轮次、后续等待集合、恢复资格和预算合同。

阻塞任务：[02](./02-persistent-pause-and-continue.md)

## 验收条件

- [x] 本轮目标、来源与版本持久固定，新增资料记录为后续等待，不能追加本轮总数；保存合法已完成目标和阶段回执。
- [x] 各阶段在预算与领域守卫内自动衔接，只有全部必要阶段完成或确定性无需执行，才能结束本轮。
- [x] 不合格候选逐条拒绝、零新增及无需画像变更可正常完成，不伪造调用或结果；协议、来源及证据合同异常保持受阻。
- [x] 主题已成功而画像失败时保留主题，恢复只补仍合法的画像阶段；删除、人工修正和版本变化使旧晚结果失效。
- [x] 本人和联系人均沿各自合法输入推进，复用既有去重、来源隔离及模型回执，不改变抽取、关系判定或画像算法。
- [x] 为后续票提供稳定的轮次、待续资料、恢复资格和预算合同；本票只验证一轮闭环，不扩展到自动连续接纳或启动扫描。
- [x] 同一消息多来源不重复计数；全部候选明确不合格时按确定性结果结束，不捏造记忆、调用或画像版本。
- [x] 用正式宿主、隔离库和供应商边界的合成结果驱动一次完整轮次，并经生产桥接页面观察阶段与完成；覆盖无结果、部分成功和受阻等分支。

- 后端通过正式 profile 的已认证记忆处理 HTTP、真实隔离 PostgreSQL 和实际 Worker 验证；只在明确的供应商或确定性时序边界使用合成替身。

- 先在上述公开入口建立能捕获本票问题的最小回归，再按单例、相关模块、类型检查的阶梯推进；完成时按仓库流程做规范与规格审查。

## 实现边界

- 继承父规格、ADR-107 及原来源、联系人隔离、版本、预算、回执、租约、人工修正和删除保护；不改变消息同步、Skill 学习或外部聊天发送边界。
- 日常开发及桌面验收只用 `pnpm run dev`：先核验并复用现有热更新实例。不得自行打包、运行打包版或解除发布门禁。
- 合成夹具不得包含私人聊天或真实凭据；真实资料及外部模型验证须另有明确范围授权。保留原配置、数据库和资料位置，不执行私人资料迁移或删除。
- 涉及 DSH 接口或生命周期时，先核对锁定版本及对应官方源码、类型和本项目接线，不猜 API、不绕过官方扩展机制。
- 只提交本票变更；不得 push、创建远端分支或 PR，除非用户明确同意。完成记录必须区分实际覆盖与剩余限制。

## Answer

新增轮次目标快照与完成回执核验。任务首次接纳时冻结当时可处理消息；同一任务或新任务后来追加的目标不进入当前轮执行，只计入后续等待。提取成功后仅使用本轮回执关联的合法记忆。主题成功、画像核验失败时保留主题，继续只恢复同一成功批次后的画像且保留累计预算。正式宿主已覆盖联系人零候选、部分成功、逐条拒绝、主题到画像和画像受阻；本人经认证入口覆盖独立轮次。实际开发 App 验证暂停继续、1/1 固定计数、完成状态和联系人隔离。
