# 统一记忆处理状态栏

来源：当前会话用户确认的五种状态、整体状态栏和任务详情要求。

## 行为

- 主栏只显示当前读取范围内的整体状态：等待处理、正在处理记忆、记忆处理需要继续、记忆处理已完成、记忆处理已停止。
- 失败、中断、配置/来源不可用、跳过或结果未知优先提示需要继续；正在处理时并列说明仍有未完成部分。
- 没有任务不显示等待或完成；记录截断且没有可核实的未完成任务时，以“状态读取不完整”异常提示保留未知，不冒充需要继续或整体完成。读取中和读取异常不属于五种业务状态。
- 单个任务可显示已核实数量；多个任务可能覆盖同一消息，不相加、不选择其中一个冒充整体进度。
- 主栏“继续处理”顺序恢复可继续的任务，每次写前重读状态；不重启主动停止任务，不越过联系人/连接代际校验。
- 仅停止任务可点击“重新开始”；重复点击受忙碌状态防护，部分提交后失败如实回读。
- 具体来源、进度、原因、任务操作和折叠处理历史全部放进“查看详情”。
- observation 的名称使用“同步聊天资料”，不声称刚发生新聊天。
- 只核查排队任务元数据，不删除真实待处理资料，不自动发起模型重试或外部消息。

## 验证边界

- React 页面经生产桥接/控制器和合成 HTTP 数据：五态、混合优先级、详情、批量继续、查询竞态、空记录和未知结果。
- 后端 observation 公共 API/Worker 隔离 PG 回归：旧批次重放、重复事件、失败后的新批次条件、与导入任务隔离。
- 复用 npm run dev 的实际 App，检查整体栏与详情；不运行打包版。
- 代码审查比较本次限定文件，保留工作区已有的其他修改。

## 不包含

- 重写后台任务协议、自动重试旧资料、变更同步授权、聚合跨任务消息计数或私人数据迁移。
