# 统一记忆处理生命周期

Triage: ready-for-agent
State: claimed

规格状态：已发布，任务拆分提案待用户确认；产品行为及三层验收入口均已由用户确认，尚未实现。

设计依据：[ADR-107](../../architecture/adr/107-unified-memory-processing-lifecycle.md)、[领域词汇](../../CONTEXT.md)及本轮设计讨论。本文修订原“统一记忆处理状态栏”规格的范围，扩展至真实生命周期管理；[旧规格](history/state-bar-spec-20261022.md)与[旧验收记录](history/state-bar-verification-20261022.md)保留为历史，不作为本规格已实现的证据。

## 问题陈述（Problem Statement）

用户查看一位联系人的记忆时，同时看到聊天提取失败、主题与画像完成、旧任务停止等多张记录，无法判断当前资料是否处理完，也不知道应恢复哪一个任务。现有两个进度入口重叠，显示、暂停、恢复和后台执行仍分别管理；刷新可能只更新某一套状态，历史失败持续占据主视图。

仅统一文案无法解决持续暂停、固定轮次、受阻后的新资料排队、跨阶段衔接及重启恢复问题。本人入口还存在把全部联系人提取任务当作本人进度的旧合同，必须修正范围语义。

## 解决方案（Solution）

为每位已确认联系人提供一个记忆处理入口，本人记忆提供独立的同类入口。它管理已保存资料从提取、核验保存、主题整理到长期画像更新的完整过程，统一当前状态和继续／暂停操作。消息同步和 Skill 学习保留各自入口与授权。

主状态固定为五种，仅由当前有效工作和持久控制意图决定：

| 状态 | 条件及主界面说明 |
| --- | --- |
| 等待处理 | 资料等待执行或满足处理条件；从未有可处理资料时说明“暂无待处理资料”。 |
| 处理中 | 当前有效轮次正在推进，显示提取、核验、主题、画像或有限重试阶段。 |
| 已完成 | 已有轮次全部阶段结束，且没有后续待处理资料。 |
| 已暂停 | 用户明确暂停该范围，保留结果和原有阻碍，直到手动继续。 |
| 处理受阻 | 存在不能安全继续的阻碍，保留结果，显示中文原因和可执行动作。 |

聚合优先级为已暂停、处理受阻、处理中、等待处理、已完成。状态读取异常独立于业务五态，显示暂不可用与刷新入口，不展示未经确认的业务状态，不改写后台事实。

当前阶段只展示可靠的实际数量；未知数量保持未知，不混合聊天、记忆和步骤单位，也不拼接整体百分比。旧的完成、停止和失败记录进入默认收起的处理历史；主视图保留一张统一状态卡，技术错误码和任务编号进入详情。

## 用户故事（User Stories）

1. 作为用户，我希望每位联系人只有一个当前记忆处理状态，以便知道这位联系人的资料是否处理完。
2. 作为用户，我希望“我”的记忆独立显示和操作，以便不会误处理某位联系人的聊天。
3. 作为用户，我希望未选择联系人时仍可查看本人的合法记忆处理状态，以便本人入口不依赖当前联系人。
4. 作为用户，我希望切换联系人立即清除旧进度和旧操作资格，以便不会把上一人的结果展示或应用给下一人。
5. 作为用户，我希望连接更换后旧响应失效，以便看到的是当前连接中的真实状态。
6. 作为用户，我希望主界面只有五种整体状态，以便不用理解内部任务类型。
7. 作为用户，我希望提取、核验、主题和画像作为处理阶段展示，以便知道当前进行到哪里。
8. 作为用户，我希望提取失败时整体显示受阻，即使旧画像仍可用，以便不会把局部完成当作全部完成。
9. 作为用户，我希望主界面说明已有资料仍可使用，以便处理受阻时仍能查看和使用合法旧记忆。
10. 作为用户，我希望从未有可处理资料时显示暂无资料，以便不会被误告知已经处理完成。
11. 作为用户，我希望已有轮次全部完成且没有待处理资料时显示已完成，以便知道当前已经处理完。
12. 作为用户，我希望新聊天按原授权保存后自动排队，以便不用逐条启动记忆处理。
13. 作为用户，我希望各阶段自动衔接，以便不用分别恢复提取、主题和画像任务。
14. 作为用户，我希望每轮处理固定的一组资料，以便处理中总数和进度保持稳定。
15. 作为用户，我希望运行中新资料进入下一轮，以便当前轮次能够结束并留下清楚结果。
16. 作为用户，我希望下一轮符合条件时自动继续，以便持续更新记忆。
17. 作为用户，我希望重叠来源中的同一消息按合法回执去重，以便不会重复提取或重复增加进度。
18. 作为用户，我希望只显示实际可靠的计数，以便未知进度不会被伪装成精确结果。
19. 作为用户，我希望聊天、记忆和步骤分别计数，以便不同处理量不会被相加成虚假的进度。
20. 作为用户，我希望一次暂停能停止该范围后续所有记忆处理阶段，以便不用逐任务操作。
21. 作为用户，我希望暂停保留已经完成的结果，以便恢复时不从头重做。
22. 作为用户，我希望暂停在新消息到来和 App 重启后仍然有效，以便系统持续尊重我的选择。
23. 作为用户，我希望暂停不会关闭已经授权的消息同步或影响 Skill 设置，以便不同用途的控制保持清楚。
24. 作为用户，我希望恢复从合法的未完成位置继续，以便成功阶段和已知回执可以复用。
25. 作为用户，我希望重复点击继续不会创建重复轮次或重复模型调用，以便避免重复处理与费用。
26. 作为用户，我希望并发暂停和继续遵循最新已接受的控制意图，以便迟到操作不会覆盖新选择。
27. 作为用户，我希望 App 重启后自动恢复可以安全续跑的工作，以便正常使用不需要反复手动恢复。
28. 作为用户，我希望需要修复或尚不能安全确认的工作在重启后仍受阻，以便系统不会猜测重发。
29. 作为用户，我希望同一联系人受阻后新资料继续保存和排队，以便后续能够补处理。
30. 作为用户，我希望新消息不清除原有阻碍，也不反复创建同类失败任务，以便界面和处理状态保持稳定。
31. 作为用户，我希望其他联系人在各自条件允许时继续推进，以便一个人的故障不会逻辑上暂停所有人。
32. 作为用户，我希望明确不合格的候选逐条拒绝，其余合法候选继续，以便单条正常拒绝不会中断整批。
33. 作为用户，我希望整轮检查结束后即使没有新增记忆也能正确结束，以便系统不会为了“有结果”捏造记忆。
34. 作为用户，我希望协议、来源或证据合同异常被明确显示为受阻，以便错误不会被静默跳过。
35. 作为用户，我希望可安全重试的临时故障有限自动重试，以便减少无须我介入的中断。
36. 作为用户，我希望重试耗尽后显示中文原因和下一步操作，以便知道该处理什么。
37. 作为用户，我希望未知模型调用先核对回执，以便不会因为重启或重复点击而盲目重发。
38. 作为用户，我希望恢复保留累计预算，以便切换界面和重启不会悄悄重开额度。
39. 作为用户，我希望主题已完成而画像失败时保留主题结果，以便恢复时只补合法的未完成阶段。
40. 作为用户，我希望恢复前复验当前来源和版本，以便已删除或已修正的资料不会被旧结果重新写入。
41. 作为用户，我希望主动暂停优先显示，原有阻碍留在说明中，以便清楚自己的选择及恢复前提。
42. 作为用户，我希望只有安全可恢复时才出现继续处理动作，以便不会点到必然失败或不被允许的操作。
43. 作为用户，我希望暂时读不到状态时明确提示并允许刷新，以便连接异常不会冒充处理失败或完成。
44. 作为用户，我希望查看、刷新和展开详情只读取状态，以便查看页面不会自动触发模型。
45. 作为用户，我希望旧任务默认收进处理历史，以便主界面不会同时出现几张相互矛盾的状态卡。
46. 作为用户，我希望历史保留真实结果并可继续查看下一页，以便界面简化不会删除追查依据。
47. 作为用户，我希望旧失败不影响当前有效轮次的状态，以便新的成功结果能正确显示。
48. 作为用户，我希望技术编号、原始错误码和安全诊断只进入详情，以便主界面使用清楚的中文说明。

## 实现决定（Implementation Decisions）

### 一个领域管理入口

- 在普通 TypeScript 业务层建立统一的记忆处理管理模块，向调用方提供按范围读取当前状态、读取历史、暂停和继续的窄接口。调用方不再自行遍历任务并按各自类型依次恢复。
- 联系人范围由已认证 owner 与稳定 contact 身份决定；本人范围具有明确的本人语义。昵称、备注和前台选中名称不能替代范围身份。
- 内部沿用既有任务、步骤、提取计划、消息目标与处理回执、主题和画像批次、版本及模型调用回执。统一管理负责协调与聚合，不另建一套相互冲突的任务执行真相，不引入新 Agent Harness、队列产品或通用 Tool。
- 各领域的来源、版本、预算、租约和删除检查仍由领域模块执行；统一操作不能绕过它们，也不通过对旧内部执行接口的裸调用实现恢复。

### 权威状态与控制合同

- 后端返回范围内的权威聚合状态、当前固定轮次、阶段、可靠计数、后续等待信息、暂停意图、中文阻碍分类、允许动作及动作版本。前端不根据历史首屏或局部任务自行推断整体状态。
- 计数必须附带明确单位和当前阶段／轮次范围；未知值不得替换成零。只有可证明互不重叠的同单位集合才可统计，不能累加不同任务可能重叠的数字。
- 每个范围持久保存手动暂停意图及控制代次，持久保存固定轮次与后续等待资料的归属。新增状态通过正常受控、可重复执行的结构升级落库，不更换业务库，不删除历史资料。
- 暂停／继续使用已读动作版本与幂等操作标识。接纳控制意图与更新领取／提交资格须在受控事务内完成；同一操作重放不重复创建轮次或调度模型，过期请求不覆盖更新的控制意图。
- 动作响应区分控制请求已接纳与业务处理已完成。主状态只能依据持久事实与有效执行信息推进，不能因 HTTP 成功、按钮完成或代理模型宣称成功而宣布完成。
- 请求处理、执行前、模型出站前及业务提交时都复验相应资格。公开状态和历史只返回管理所需元数据，不复制聊天、模型输入输出、凭据或本机绝对路径。

### 固定轮次与跨阶段推进

- 一轮接纳时固定本轮待处理资料及可追溯来源／版本；运行中新到资料登记为后续待处理集合，不追加当前轮次总数。
- 在有效来源和回执保护下复用已完成目标与阶段；提取、核验保存、必要的索引维护、主题和画像更新自动衔接。只有本轮全部必要阶段有合法完成或确定性无需执行的结果，才结束本轮。
- 没有合格候选或没有主题／画像变更时允许按确定性规则结束相应阶段，保留真实处理结果；不伪造物理模型调用、画像版本或新增记忆。
- 主题与画像更新使用本轮应更新的合法记忆与来源版本，后续轮次资料不能使当前轮次范围无限扩大。人工修正、来源删除与版本失效沿现有规则使不安全的晚结果失效。
- 主题成功后仅画像失败时，合法主题结果保持；画像恢复可复用仍然有效的输入和回执，不重复提案成功阶段。
- 历史导入、增量观察中属于同一范围的合法目标可纳入统一管理，仍保留原来源类型、去重及一次历史导入只属于一位联系人的边界。

### 暂停、受阻及重启恢复

- 手动暂停作用于整个记忆处理范围及后续轮次，而非仅当前任务；它不改变消息同步和 Skill 的原有授权或设置。恢复必须来自明确继续动作，并保留已经完成的合法结果。
- 暂停被持久接纳后，禁止该范围继续领取新阶段或提交失去资格的晚结果；本地执行尽力取消并有界排空。在途外部调用可能已经发生，不能因界面显示暂停而声称供应商已停止或费用归零；模型回执仍须合法结算。
- 受阻是范围内的后续记忆更新屏障。新增消息可继续按原授权保存和排队，不因新资料清除阻碍、刷新失败预算或反复创建同类失败任务。
- 其他联系人继续按原调度、公平性、前台优先和预算限制推进；不通过解除现有全局执行排他来制造新的并发保证。
- 明确不合格候选按既有领域规则逐条拒绝。关系待定等已定义结果保留原语义；协议、来源及证据合同异常作为技术受阻，不能转换成普通拒绝以跳过检查。
- 沿既有有界策略重试已确认可安全重试的临时故障；重试期间展示处理阶段，耗尽或需要人工处理后保留受阻。未知／待定物理调用先核对原回执，不能盲目重复发送。
- 启动恢复由应用生命周期中的受控执行方处理，页面读取没有调度能力。只恢复原授权下、未手动暂停、来源与版本有效、预算及回执允许的未完成工作；需要人工修复或不能安全恢复的工作保持受阻。
- 重启、旧通知重放、切换页面、规则版本变化和手动继续都不得清零累计已用预算、丢弃未知调用或解除删除与人工修正保护。规则版本变化导致无法原样续跑时，保留原结果并给出明确资格与处理说明，不能向前端返回成功后静默换来源重做。

### 本人范围和存量兼容

- 本人入口只管理已经合法归属本人范围的资料与处理工作，不宽查全部联系人提取任务后在前端筛选，不利用本人动作定位并恢复联系人任务。
- 联系人提取过程中依法产生本人记忆仍按原归属与来源规则保存；这不把联系人提取任务整体转换为本人任务，也不让本人控制入口反向启动该联系人的提取。
- 新公开合同必须显式区分联系人与本人范围。旧 owner 宽查询语义不可静默沿用为本人语义；如过渡期必须保留兼容能力，应与新的本人合同明确隔离，并在调用方切换后收敛。
- 旧任务的 cancelled、failed、paused 或“已停止”不能被猜测为用户持续暂停；旧停止也不能被自动解释成可运行。保留历史与原始原因，只有可信控制记录能恢复对应的用户意图。
- 无法证明固定轮次归属、来源或回执安全的存量工作不自动执行，不捏造完成数量，不刷新预算；使用中文说明引导合格的恢复动作。
- 已明确停用或撤销的资料处理、来源及同步范围保持原决定；新控制模型不得借结构补齐或启动扫描重新授权。

### 桌面交互和历史

- 真实记忆页只保留一个当前状态与操作入口，移除内部任务面板与提取卡并排充当主入口的重复呈现；详细任务、原始技术原因及历史通过统一详情进入。
- 联系人和本人使用同一管理合同的明确范围。本人页不依赖选中联系人，不把当前联系人提取进度混入本人页。
- 继续和暂停通过具名、受范围约束的桌面桥接转交统一管理模块，不暴露任意 URL、SQL、工具调用或任务枚举执行能力给页面。
- 联系人身份、选择代次及连接代次都必须匹配。范围或连接变化立即撤销读取、清空快照和动作资格，迟到结果不回填；本人范围保持独立。
- 历史独立分页，保留真实来源类型、时间与可靠计数。聚合状态不能由历史首屏、截断列表或“没有看到未完成任务”推断；历史读取失败也不能反向宣布当前工作完成。
- 状态读取失败显示状态暂不可用与刷新入口，先隐藏未经确认的业务状态与动作。当前受阻主卡采用中文原因；错误码、任务编号和安全诊断保留在详情。

## 测试决定（Testing Decisions）

### 验证入口

以下三层验收入口已由用户确认，优先复用已有公开能力，作为后续实现与 TDD 的约定 seam：

1. 后端：经过正式 profile 的已认证记忆处理 HTTP 入口、真实隔离 PostgreSQL 和实际 Worker，观察状态、动作与持久结果；供应商边界使用合成模型结果，其他领域、事务、任务、预算和恢复逻辑保持生产路径。
2. 桌面：真实记忆页面经过生产具名桥接、控制器和认证 HTTP 合同，验证用户可见状态与动作。保留已有 React／普通页面夹具，修正把后台任务入口整体替换为空而漏掉重复呈现的覆盖缺口。
3. 开发 App：复用唯一热更新实例，以隔离合成资料由 Computer Use 验证实际页面、切换范围、暂停／恢复和重开后的状态。默认不点击真实私人历史的继续或发起真实模型调用；实际模型效果与渠道可用性不由合成通过推定。

接口核对状态：用户于 2026-10-27 明确选择采用上述三层验收入口；此确认不代表已编写或运行新实现测试。

### 验证原则及既有先例

- 验证调用方可观察的行为，通过同一公开 seam 证明状态、操作、持久化与副作用；不通过私有方法调用或与实现同构的断言制造通过。
- 沿用现有正式宿主恢复回归、统一任务管理与范围隔离回归、主题／画像真实隔离库回归、生产桥接记忆页夹具及开发模式验收方法。
- 数据库查询可用于独立核对持久结果和没有越权写入，不用它绕过公开操作来制造测试状态迁移。只有合成准备可直接创建必要夹具。
- 人工可控时钟、传输延迟和供应商替身仅用于确定性地制造调度、迟到、取消、重试和重启情形；在记录中写明与正常运行的差异。测试替身不替代领域判断、事务及控制代次。
- 单用例先红后绿，再跑相关模块与类型检查；影响范围需要时才做有时限的全量。实际 App 与真实模型验证分别记录。

### 必须覆盖的验收场景

1. 同范围显示一张主卡，五态与优先级准确，内部提取失败而画像成功时仍受阻。
2. 联系人、本人和另一 owner 相互隔离；本人入口不查询或恢复任一联系人的提取任务。
3. 未选择联系人仍可查看本人范围；切换联系人、连接或选择代次后迟到成功／失败不回填。
4. 一轮固定目标，运行中新消息只改变下一轮等待集合，不改变本轮总数和已完成回执。
5. 合格新资料自动排队，各阶段自动衔接；页面读取、刷新、展开详情不启动模型或 Worker。
6. 所有阶段完成且无后续资料才显示完成；后续等待、从未有资料、没有合格候选和无需画像变更分别正确呈现。
7. 手动暂停在领取前、模型在途和阶段切换时生效；已接受暂停阻止失去资格的晚结果提交。
8. 暂停跨新消息、正常退出及重启持续保留；其他联系人及原消息同步设置不被改写。
9. 同一继续请求、并发点击和旧动作版本不重复建轮次、不重复调用、不覆盖较新的暂停意图。
10. 受阻范围持续累积合法等待资料，新增通知不解除阻碍或创建失败任务风暴；其他范围仍可推进。
11. 单条明确不合格候选正常拒绝，其余合法候选继续；协议及证据合同错误保持受阻且不推进错误水位。
12. 安全临时故障有限重试，耗尽保持受阻；重启和新消息不清零失败预算或物理调用总账。
13. pending／unknown 调用先核对回执；未知结果不能由继续按钮、启动扫描或普通坏候选跳过来重发。
14. 成功 L2 与失败 L3 的恢复只补仍合法的 L3，保留成功 L2、原回执和累计用量。
15. 来源删除、撤销、人工修正和版本变化使不安全晚结果失效，恢复不扩大原授权或恢复被排除项。
16. 启动仅续跑符合资格的未完成工作；手动暂停、明确停用、需要修复、未知或缺乏可信存量归属的工作不自动执行。
17. 当前阶段采用正确单位和可靠计数；未知、重叠、历史截断和下一轮等待不产生虚假的整体百分比或完成状态。
18. 处理历史默认折叠、可分页，旧完成／停止／失败不占主视图，也不覆盖当前有效状态。
19. 状态读取失败和历史读取失败正确隔离；错误编号、技术码和安全诊断不进入主视图或泄漏敏感内容。
20. 通过合成正式宿主和真实生产桥接验证从提取到主题与画像的整轮闭环，再通过实际热更新 App 验收，不用单层通过宣称完整集成已完成。

## 不在范围（Out of Scope）

- 改变微信读取授权、全部私聊范围、历史同步规则、联系人身份核验、OCR／语音／截图边界。
- 新增或改变 Skill 学习控制，以及非记忆处理业务任务的恢复与执行语义。
- 改写记忆抽取、关系判定、来源核验、合并和画像生成算法或提示词来绕过当前失败；现有关系证据合同异常是受阻样例，不能为统一状态而放宽检查。
- 自动发送外部聊天、扩大模型供应商或出站资料范围、自动下载模型、升级 DSH 或新增通用 Tool。
- 私人资料迁移／删除、推送远端、创建 PR、制作发布包或运行打包版。
- 全局所有联系人合并进度、预计完成时间、步骤权重百分比，以及通过历史首屏推测整体完成。
