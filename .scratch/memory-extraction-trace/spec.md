# 记忆提取完整追踪实现规格

Triage: ready-for-agent

## Problem Statement

用户看到一条记忆时，需要知道最初是哪几条聊天、模型实际读取了哪些消息、实际返回了什么、程序做过哪些修改或判断，以及最终为什么保存成这条记忆。现有来源引用、业务记录和最小调用台账无法还原这条链，事后补查也不能替代当时的记录。

## Solution

所有实际执行的记忆提取默认保存完整、可查询、可删除的敏感追踪。从最终记忆或待确认候选反查原始输入、规范化、确切窗口、模型请求与原始返回、逐候选处理、核验、采纳门槛、相似判断、裁决、实际写入和水位。没有落库的候选和失败尝试也可从批次查看。

持续保留到手动删除或来源删除。追踪写入故障停止本批，不继续生成无法溯源的业务结果，不推进水位。已有部分写入如实展示。历史记录不完整时显示真实缺口，不自动重提取私人历史或补造模型理由。

## User Stories

1. 作为用户，我希望查看一条记忆的原始聊天，以便核对主张是否受原话支持。
2. 作为用户，我希望看到全部实际模型输入，而不仅是直接引用消息，以便判断上下文是否造成误解。
3. 作为用户，我希望看到实际目标、前文、后文的数量、顺序和角色，以便知道本批到底处理了多少条。
4. 作为用户，我希望看到原始来源到规范消息的字段转换，以便定位说话人、时间或正文处理错误。
5. 作为用户，我希望查看完整提示词、输出约束与实际模型参数，以便知道模型被要求提取什么。
6. 作为用户，我希望看到模型原始返回，包括不合法内容，以便区分模型输出错误与程序解析错误。
7. 作为用户，我希望知道类别、主题、主体、风险和时间分别由模型还是程序产生，以便判断信息在哪一步改变。
8. 作为用户，我希望看到来源校验和每项拒绝原因，以便理解没有保存的结果。
9. 作为用户，我希望看到来源语义核验的实际请求、返回、片段校验和影响，以便核对第二次判断。
10. 作为用户，我希望看到每道采纳门槛的配置、实测值和结论，以便知道为什么待确认或自动采纳。
11. 作为用户，我希望看到重复与已删除指纹的命中结果，以便理解被跳过的候选。
12. 作为用户，我希望看到相似旧记忆的当时版本和裁决，以便理解新增、更新和 NOOP。
13. 作为用户，我希望看到真实候选、本人/联系人记忆和旧版本标识，以便连接到最终保存结果。
14. 作为用户，我希望失败、部分写入、重试和水位变化可查，以便判断哪些结果真的已保存。
15. 作为用户，我希望零候选和没有落库的结果同样留存，以便完整核对批次。
16. 作为用户，我希望日志失败时提取停止并显示失败，以便避免继续生产无过程依据的记忆。
17. 作为用户，我希望删除来源时清除所有包含其正文的追踪副本，以便避免上下文残留。
18. 作为用户，我希望手动删除追踪而不误删权威记忆，并看到追溯缺失状态，以便管理敏感资料。
19. 作为用户，我希望查询始终限制在自己的已确认联系人范围，以便其他联系人资料不泄露。
20. 作为用户，我希望旧记录缺口和模型返回理由明确标注，以便不把事后解释当成原始记录或内部推理。
21. 作为用户，我希望从 App 的记忆和待确认候选查看全过程，以便无需直接查数据库。
22. 作为用户，我希望历史导入、后台增量和人工触发都使用同一记录机制，以便入口不会遗漏。

## Implementation Decisions

1. 沿用现有 PostgreSQL，在独立追踪存储中保存含正文资料，不扩展最小出站台账，不新增外部存储或模型供应商。来源记录、追踪事件、关联与正文依赖分层保存，受 owner/contact 隔离和删除控制。
2. 在提取执行入口建立追踪上下文，提供小型、可注入的记录与读取 Interface。生产装配默认启用；合成测试使用持久化 Adapter 或故障 Adapter。记录故障采用独立错误，不进入模型非法输出自动跳过恢复。
3. 每个实际批次/尝试有稳定标识、阶段顺序与不可变输入/输出；原始候选在业务入库前取得稳定关联，无业务行的结果也留存。运行标识连接批次和重试，实际代码/规则/提示词/schema 版本和有效门槛一并保存。
4. 记录窗口选择、过滤、渲染、完整提取/核验/裁决请求和原始响应。最终供应商请求捕获覆盖 SDK 添加的 schema 与工具包装，去除鉴权信息；可观察的重试分别记录。缺少捕获不能宣称完整。
5. 原始响应先保存，再解析；所有拒绝、非记忆、重复、已删除、待确认、ADD/UPDATE/NOOP 逐条记录。程序字段变化保存前后值。未执行阶段明确标注，不能补造规则通过结果或候选数量。
6. 保持模型提示词、schema、来源核验、语用、置信度、风险和维度放行语义，不提高预算或增加语义调用。追踪记录实际判断，不改变既有分类或自动采纳默认空放行表。
7. 业务写入的计划标识和实际结果关联，部分提交与未知提交分别记录；完成追踪与水位推进具有一致提交结果，不允许先推进水位再尝试写记录。追踪存储不可写时通过无正文运行状态暴露失败，恢复先核对已提交结果。
8. 原始输入在既有授权、联系人校验通过的范围捕获；历史导入保留所用记录原文、解析与规范化结果，CLI 保留所用文字事件的投影前输入。实际解析/规范化时间、版本、转换、过滤和去重可连接到消息来源；不保存原始视觉帧，不复制整文件或跨会话资料。
9. 来源依赖包含全部窗口消息、所用原始来源和旧记忆正文的来源，不能只用候选直接引用。删除来源保守清除受影响整份追踪正文及关联副本；单条关系资料删除、联系人和账户清除遵循现行派生内容规则。旧来源缺口如实显示。
10. 查询通过受授权的联系人范围提供批次列表、详情、最终记录反查和手动删除。App 展示阶段、实际输入输出、处理与结果；旧记忆显示未记录，手动资料显示不适用，不伪造链路。
11. 新迁移只增加结构与必要约束/索引，旧记录不伪造回填、不自动重提取。只在本任务新建的隔离测试库应用迁移和处理合成资料；现有私人库的迁移或真实数据运行属于后续具体部署步骤。
12. 追踪不进入普通日志、Git 或公开测试；接口错误不回显敏感载荷、SQL 或凭据。长期留存不设置自动过期，也不因容量故障悄悄关闭记录。

## Testing Decisions

用户于 2026-10-07 确认三处公开测试接缝：既有提取执行入口、导入/同步入口、查询/删除入口。测试通过这些 Interface 判断行为，不测试私有实现或复制实现计算作为期望值。

- 提取入口：合成窗口与受控模型响应，检查可查询到准确的全过程与最终记录；包含不足/完整窗口、原始返回、拒绝、非记忆、待确认、自动新增/更新、重复、NOOP、本人归属和零候选。
- 模型系统接缝：按锁定/安装版本核对官方库接口，使用本地合成 HTTP 返回验证实际序列化请求与响应捕获，不调用真实供应商或读取模型凭据。
- 导入/同步入口：合成 JSONL、合成 CLI 事件，验证原记录、解析/规范化、说话人、时区、定位、去重与过滤的可回查关系；覆盖历史缺失与未授权会话拒绝。
- 查询/删除入口：跨 owner/contact 拒绝、从 memory/candidate 反查、手动删除、来源仅出现在上下文仍清除、旧记忆来源清除，以及保留台账无正文。
- 故障注入：在调用前、响应后、业务写入前后和水位提交处触发追踪失败，检查停止后续动作、部分提交、真实失败状态、不推进水位、不累计模型非法输出计数、重试不覆盖旧记录或重复业务写入。
- 使用新建且名称以 `_test` 结尾的独立 PostgreSQL 数据库；全部资料为合成，禁用项目 dotenv 与真实模型调用；任务结束仅清理本任务创建的测试库。
- 参考现有记忆提取、来源删除、导入/同步和 HTTP 业务集成测试的公共调用方式，逐个 red → green 垂直切片。运行相关单文件、类型检查，最终运行全量相关测试及 Swift 构建/测试。
- 按 Standards 与 Spec 两轴独立 review，修复阻断后自动做本任务本地提交；不 push、不创建远端分支或 PR。

## Out of Scope

自动重提取私人历史、补造旧请求、修正现有记忆、修改模型语义提示词或采纳门槛、新模型/外部连接、向量检索、聊天自动发送、云端部署与原始视觉帧保存均不在本规格范围。真实数据库迁移和真实资料运行不作为合成验收的一部分。
