# 01：从提取窗口到最终保存结果的可查询追踪

Triage: ready-for-agent
State: open
Blocked by: None

## What to build

用户能从一个实际提取批次或最终候选/记忆，查到当时窗口、每次模型请求与原始响应、逐候选解析/核验/采纳/裁决及真实保存结果。拒绝、跳过、零候选和失败同样记录，已用来源删除可清除相关正文。来源的旧处理记录缺失如实显示，任务 02 再补齐新输入的最前段。

## Acceptance criteria

- [ ] PostgreSQL 独立追踪保存并按联系人范围查询，无正文资料不挤入最小台账。
- [ ] 实际窗口、完整请求/原始响应、来源校验、时间处理、语用/核验、门槛、重复、相似和裁决逐步可查。
- [ ] 每个原始候选有稳定关联并连接真实候选/本人或联系人记忆/旧版本，无业务行的去向仍可查。
- [ ] SDK 实际供应商请求及可见响应在既有模型调用内捕获，无额外语义调用或真实联网测试。
- [ ] 追踪故障停止本批，不推进水位，不触发非法输出跳过；部分提交和未知结果如实保留，完成记录与水位可靠提交。
- [ ] 全部窗口来源及参与判断的旧记忆来源进入删除依赖；上下文来源删除同样清除正文。
- [ ] 在已确认提取/查询/删除接缝完成 red → green、相关类型与集成验证。
