# 标题单行文字片段顺序

用户在标准渲染报告中发现，较高像素密度仍会漏检短名或使标题片段顺序异常。诊断确认：同一水平行内，不同大小写或字体回退造成的文字框高度差，会触发现有全局纵向排序，颠倒标题左右顺序。

- 只在 `HeaderOcrResult` 组装标题时修复；正文 OCR 顺序不变。
- 所有片段须以有效几何证明属于同一行，再按横坐标组装；多行、重叠或无效框不获得完整性资格。
- 原始 OCR 字符、最低原始分数、裁片边界、省略号、长度和换行检查保持；不凭此还原 emoji 或授予联系人身份。
- 合成回归覆盖大小写框高度不同、输入乱序、真正双行和坏框。
- 名称是否逐字正确、边界检查和最终名单匹配分别呈现；私人报告不入仓库。
- 用户已明确：目标是以足够文字定位完整名单中唯一且已有确认绑定的会话，不要求 OCR 逐字还原。通用名单匹配由独立任务 `.scratch/ocr-name-matching/` 继续，本任务不修改它的文件。

仅复用 `npm run dev`；不打包或运行发布版，不发送微信消息。验证后仅本地提交本任务文件。
