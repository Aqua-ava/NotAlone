# 本机 App 首用与资料生命周期

Triage: ready-for-agent
State: open

> 状态：2026-10-29 规格定稿，实施未启动。保留已确认的完整首用目标及空SQLite、逐人同步和手动记忆处理规则。`ready-for-agent`仅表示规格可供后续拆票，不表示真实渠道、独立交付或产品验收通过，也不授权本轮实现、切库、删除或发布。四方案边界见[一致性约定](../sqlite-database-rebuild/map.md#plan-alignment)。

## Problem Statement

用户希望下载 App 后即可完成本机准备、微信接入与模型配置，不必自行安装数据库服务、Python／Conda、填写运行路径或执行终端命令；资料在重开、更新和重装后应继续可用，异常不应导致资料被换成空库。

## Solution

通过同一首用流程核验运行环境与微信组件，引导用户确认当前账号、逐人选择联系人、了解本机可读历史的覆盖情况并配置自己的模型。新业务资料使用空SQLite；首次创建、本次明确重置、同实例升级与故障恢复分别处理。同步、记忆处理和候选生成各有可观察状态，不以建库成功或工具就绪代替完整交付。

## User Stories

1. 作为用户，我希望下载后通过界面完成本机准备，以便不依赖终端或额外数据库服务开始使用。
2. 作为用户，我希望 App 校验微信组件的来源、版本和许可并解释必要权限，以便知道接入条件及其影响。
3. 作为用户，我希望先核验并确认当前微信账号，以免把其他账号的资料关联到本人。
4. 作为用户，我希望联系人列表不预选、只同步我逐人勾选的联系人，以便控制读取范围且新私聊不会自动加入。
5. 作为用户，我希望首次同步联系人本机可读的既有文字，并看到进度和不完整原因，以便判断可用语境的覆盖程度。
6. 作为用户，我希望历史尚未完成时阻止生成，明确不完整后由我确认是否使用已有部分，以便不会把有限资料当作完整历史。
7. 作为用户，我希望在界面配置自己的模型凭据并主动检查连接，以便自主选择模型及调用时机。
8. 作为用户，我希望未配置模型时仍能授权同步，以便不把模型设置变成消息接入的前提。
9. 作为用户，我希望同步完成、模型配置和 App 重开都不自动提取记忆，以便由我手动启动固定范围的处理。
10. 作为用户，我希望关闭读取总开关只停止微信读取，以便已保存合法文字的手动记忆处理独立受控。
11. 作为用户，我希望取消联系人或删除来源后立即阻止相关在途结果提交，以便旧内容不会重新写回。
12. 作为用户，我希望退出后停读且记忆处理保持暂停，以便重开时由我决定是否继续调用模型。
13. 作为用户，我希望本次从空SQLite重建且不迁入旧PG业务资料，以便重新建立联系人、授权和资料。
14. 作为用户，我希望本次切换保留模型密钥、用户Skill及外部原文件，以免清理旧业务资料时误删需要保留的内容。
15. 作为用户，我希望普通重开、更新和重装沿用同一SQLite实例，以便资料不会被重复初始化或搬动。
16. 作为用户，我希望版本升级中断后核验并继续，损坏或版本不兼容时保留资料并停止写入，以便异常不会被空库或自动降级掩盖。
17. 作为用户，我希望删除程序与彻底删除资料分开，并在后者确认具体范围，以便重装和资料清除符合我的意图。
18. 作为用户，我希望诊断内容脱敏且不自动上传，以便排查故障时不泄露聊天、联系人或凭据。

## 已确认行为

1. 本次切换新建空SQLite，不迁旧PG业务、授权、排除记录或迁移账本，不为本次重置保留旧PG业务备份。切换前依数据库重建方案核验、停止旧writer并清理已确认范围的旧业务及副本，保留模型密钥、用户Skill原目录和外部原文件。切换完成后，普通重开、升级及重装沿用同一SQLite实例；首次创建与这次明确重置必须同异常恢复区分。
2. App 检测环境并准备经验证的微信组件，引导必要授权。不把工具准备等同账号确认、会话可读或读取授权；安全可行接入路径先核实，不重复此前被中止的特权路线。
3. 本轮首用只按用户逐人勾选的联系人同步，列表不预选，新私聊不自动纳入；稳定账号和联系人身份必须核验，授权前不读正文，不凭昵称猜归属。原有显式全部私聊能力保留为既有方案记录，不作为本轮必交付分支或新库授权来源；不据此宣称运行中该能力已退役。
4. 首次历史仅指本机微信可读取的私聊文字，不承诺恢复其他设备缺失消息。非文字沿用占位，不新增媒体正文读取。
5. 授权后进入主界面，按联系人显示进度、覆盖状态和不完整原因；当前联系人优先但不能饿死其他联系人。历史未完成阻止生成，明确不完整后经用户确认可用已有部分，警告保留在界面、后端与请求依据。
6. 消息同步与关系提取分层。模型使用用户自己的API Key，界面配置和用户触发的连接检查；未配置模型可先授权同步，但不能发起模型提取／生成。同步完成、模型配置成功、重开均不自动启动记忆；用户点击后只处理固定已保存文字范围。总开关只停止微信读取，不中断已手动启动的有效处理，关闭时仍可手动处理已勾选人的已保存文字；取消联系人或删除来源立即阻止相关提交。必要文本出站仍须用途与授权，本机存储不等于完全离线。
7. 退出App或关闭总开关停止读取，重开仅在有效授权与开关允许时继续读取；新库产生的撤销／删除排除不恢复，记忆处理退出后保持暂停。空库不继承旧增量或历史授权，按新身份重新确认所选联系人的本机可读历史。未来已有SQLite实例的授权升级须依据真实记录另核，不能借旧PG授权自动扩大范围。
8. 切换后的普通升级在同一SQLite实例应用缺失的可信SQLite迁移，成功版本不重放，不重演PG迁移或伪造旧账本。中断后核验并继续；未就绪时阻止业务同步和生成。
9. 临时失败提供安全重试；漂移、无可信基线、损坏或版本不兼容时保留资料并停止写入，提供脱敏诊断及支持入口，不换空库、不自动降级、不承诺万能修复。
10. 删除程序不等于删除资料；完成本次切换后，重装复用仍在本机的同一SQLite实例。彻底删除须明确范围及二次确认，沿用来源、联系人、账号及历史副本删除规则，不用删目录绕过归属核验。
11. 同机重开、系统重启、更新和重装属于范围。普通启动不强制备份、不搬库；历史副本的清理责任保留。

## Implementation Decisions

- ADR-101记录原首用决定。本次待实施目标局部替代其保留PG和必须交付全部范围的要求；保留ADR-061来源／权限、ADR-066异常不换空库和不强制备份、ADR-100已选联系人本机历史/覆盖/删除边界。与ADR-101/102的PG条款、ADR-089的全部范围及ADR-107的自动记忆存在正式决策衔接，按四方案一致性约定在实施前修订适用范围，不伪称已修改现行ADR或运行时。
- 复用现有受管运行时、启动诊断、首用控制器、微信连接控制器及同步／回复服务的业务边界；PG存储和引擎启动部分须适配为SQLite，不把复用要求理解为继续启动PG或执行Python迁移器。
- 分别表示运行时、数据结构、工具、账号证据、授权、历史覆盖、模型及关系提取状态，不能以一个 ready 替代其他状态。
- 组件获取／校验、只读账号探测、列表枚举、授权提交和正文读取分别设边界。上游列表可能夹带摘要：取得必要列表访问同意后才枚举，摘要丢弃，不保存、不外发；单会话选择不得预存全部正文读取授权。技术上无法满足时记录阻碍，不自行放宽。
- 固定组件来源、版本、摘要、完整许可和无开发环境依赖清单。票01先核实可行路线；新的高风险选择返回决策，不因产品目标获得任意提权、重签或重启微信的权限。
- 诊断导出采用字段白名单，不含正文、联系人身份、密钥、原始截图和可识别路径，不自动上传。

## Testing Decisions

- 测试优先通过首用与运行时的业务服务、正式认证接口、具名桌面桥及真实页面观察结果；只在组件获取、只读渠道和模型供应商等外部边界替换为明确的合成输入。存储初始化、授权提交、历史覆盖和手动记忆处理使用真实协调流程，不用表结构断言代替用户行为。
- 复用已有首次账号连接、原库启动诊断、历史同步与统一记忆处理的隔离测试先例；其旧PG结果只能证明对应旧入口，切换后的SQLite及新的手动触发合同须重新验证。合成与真实微信、开发App与最终交付分别记账。
- 使用独立临时SQLite和合成资料检查首次建库、SQLite资料升级、中断、重复启动、并发、损坏、较新版本拒绝和重装复用，核对业务资料与既有账本不被改写。
- 页面及后端检查逐人选择、未选中和新私聊不纳入、取消、账号变化、授权幂等、权限拒绝、不兼容工具、模型缺失、覆盖警告、二次删除和诊断脱敏。模型连接探测用合成最小输入，不用用户聊天试连。
- 增加手动启动、总开关关闭仍能处理已保存文字、普通暂停、取消联系人、来源删除及unknown不盲重发的完整验收；媒体提取与云端均不是首用前置。
- 真实微信沿用原票08及用户明确范围，不发送外部消息；合成、开发App、真实模型、真实微信分别记录。
- 最终以同一可追溯安装产物在无开发环境的受支持机器验证：新装到生成候选、旧资料升级、中断恢复、停读与重开、重装和旧版本拒绝。开发机隔离目录、构建、签名均不能代替。
- 日常只用 `pnpm run dev`，先 `dev:status` 复用实例。本轮不授权打包、运行安装包、修改发布门禁、公证或发布；最终票等待用户明确发布任务和目标机器。

## Out of Scope

云端资料与账号、多设备同步、换机迁移、模型代付计费、自动降级、通用自动修复、普通启动强制备份、媒体正文及外部自动发送。不承诺新增端侧加密，保留本机库未加密提示。
