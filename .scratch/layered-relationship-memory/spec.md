# L2 场景文档与 L3 长期画像：正式规格

Triage: ready-for-agent
State: claimed
日期：2026-10-17

> 依据已确认的 Q1–Q10 及整体定稿方案。用户已认可11项任务粒度与依赖，正式任务已逐张发布，全部 open、尚未领取；见[任务索引](planning.md)。本规格发布不代表功能、模型质量或真实 App 已验收；本轮只发布文档，不执行业务资料整理、迁移、模型调用或产品实现。

## Problem Statement（用户问题）

NotAlone 已能保存带来源的关系记忆和本人记忆，并在回复中做词法检索。但分散的单条记忆不容易表达一个持续主题的背景，也不能直接给用户或回复模型提供一份简短、可核对的长期背景。现有记忆目录和长期概览是分组与来源导航，尚无自动生成的主题文档或画像正文。

用户希望系统自动整理已经认可的资料，首次覆盖已有记忆，之后持续维护；回复时先了解长期背景，再按需阅读主题细节。整理不能制造事实、改变一次性表达意图、混淆联系人、抹平时间变化，或让删除及纠错后的内容再次出现。

## Solution（解决方案）

### S1：资料入口与两类范围（Q2、Q3、Q4）

- L2 场景文档、L3 长期画像都从同范围合法已采纳记忆整理，包括有明确手动录入来历的资料；仅来历为 `manual_entry` 或 `source_supported` 的实际版本可参与。
- 可读取概览、当前叶存在或后续人工动作，不代表旧来源证明得到补签。`unknown`、待确认、否决、应删及不合法版本不进入两层。
- 联系人范围按 `owner_id + contact_id`，本人范围按 `owner_id` 分别保存、授权、调度与读取。本人只整理合法本人记忆，不自动读取多个联系人的原话或把联系人事实改写成本人事实。
- 不重新提取全部历史，不回填旧证据，不改变现有自动采纳维度放行。待确认候选继续沿原独立轨道标注使用，不通过整理变成长背景。

### S2：持续主题资料（Q1）

- L2 按工作与项目、沟通偏好、重要经历等持续主题组织，由系统产生适合资料内容的中文标题和有界目录提示；不是一次聊天一篇，也不是回复 Skill 的聊天场景。
- 同主题保留稳定身份，新增资料补进相应主题；更名、拆分或合并保留合法引用映射，不让旧文档入口指向另一范围。
- 正文按有依据的段落组织，呈现背景、具体经历与时间变化，每段可追溯到底层记忆版本。合法历史可写为历史，不能由过期、缺少结束时间或反复总结变成确定现状。

### S3：精简长期背景（Q2）

- L3 从当前可用主题资料和对应底层依据中选取稳定事实、明确偏好及重要关系背景，形成受预算限制的概括；每条直接回指底层记忆及真实版本。
- L3 不能只以 L2 或旧画像的文字证明新结论，不能把短暂状态、计划、假设、转述或未经核实的近况变成长期特征或已发生事实。
- 不自动深入判断性格、动机或关系效果，不产生如何回复的策略；回复方法继续由 Skill 管理，长期表达偏好继续走明确保存入口。

### S4：首次整理、增量维护和生效（Q6、Q7）

- 用户选择范围并开启后，有限批次覆盖该范围的已有合格资料，展示实际覆盖数量、剩余量与失败／暂停情况；处理部分不能显示全部完成。
- 后续资料变化按同范围合批，重整受影响 L2 和 L3；提供手动刷新，不逐条聊天触发全量模型调用，不重复产生并行的同范围工作。
- 正常结果通过结构、引用、时间含义、逐次忠实度核验及当前输入复验后原子生效，显示“系统整理”，不要求用户逐篇审核；不采纳或修改底层记忆。
- 不确定、无依据、矛盾、输入失效或超预算结果不生效。临时调用失败有限重试，不能无限改写直到通过；后台模型调用逐次为前台回复让路。
- 用户可撤回某一整理版本；旧版若失效、被纠错或依赖应删资料，不得借撤回重新启用。

### S5：回复中的分层加载（Q5）

- 仅在本次允许关系语境、对应整理范围已开启且质量资格有效时，加载当前联系人与本人的有界 L3 和 L2 目录；缺失或不可用部分正常省略。
- L3 放入系统上下文中明确标注的背景资料区。目录只提供有限主题提示与可读取的版本化入口，L2 正文由独立只读工具按本次冻结版本按需读取。
- L1 词法评分、阈值及联系人 5 条／600 字符、本人 3 条／240 字符、未确认参考 3 条／300 字符的原独立预算保持。L2/L3 新设预算并计入完整请求容量，不成为过滤 L1 的唯一入口。
- 新资料中的命令、引用或策略文字不能改变确定性权限、当前表达意图或 Skill 管理规则；同一事实在两层重复不代表多份独立证据。
- 用户能回看本次实际进入模型的 L3、目录、L2 正文及版本和来源；仅为删除追踪保留的隐藏依赖不冒充实际依据。

### S6：纠错、补充与不可用回退（Q8、Q9）

- 事实有误导向关联底层记忆的修正入口，并撤下受影响派生版本；正确底层资料被总结错时，记录整理反馈并重整，不反向修改正确事实。
- 相同旧依据上的同一错误含义不得换措辞重现；反馈的目标、作用范围、依据与删除路径可核对，不以文本相似度或模型自评代替此保证。
- 补充背景通过合法手动记忆完成，不提供固定人工正文段落或任意画像文件编辑能力。
- 更新中、失败、失效、停用或没有合格内容时不加载受影响 L2/L3；未受影响且合法的主题可继续使用。回复回退合法 L1 与当前聊天，明确显示整理状态，不阻塞用户回复，不用旧缓存补回无效正文。

### S7：入口、范围控制与删除（Q10）

- 现有关系资料页增加“主题资料”和“长期背景”，展示系统整理标记、更新时间、覆盖进度、时间状态、依据及管理操作；不要求用户理解层级编号。
- 首次选择联系人范围及是否包括本人，展示合格资料数量、整理用途、既有模型接收范围和有限调用预算后开启；新联系人不自动加入。
- 停用停止本范围整理及回复加载，仍可查看来源有效的现有文档；真实来源删除照常清理。
- 删除整理结果关闭本范围，并清除生成正文、旧版本、任务输入输出、目录提示、反馈敏感内容、缓存及受影响使用副本；只保留防止迟到恢复的最小无正文世代记录。底层记忆另行管理，用户重新开启才再生成。
- 来源或底层记忆删除继承原删除合同，清理全部实际参与依赖的派生闭包。其他来源仍在不代表旧模型总结可以保留；需要重建时只能使用仍合法资料。

## User Stories（用户故事）

1. 作为用户，我希望选择要整理的联系人，以便控制整理范围。
2. 作为用户，我希望单独决定是否整理本人资料，以便与联系人背景分别管理。
3. 作为用户，我希望看到合格资料数量与整理用途，以便理解开启后的处理。
4. 作为用户，我希望首次整理已有合格记忆，以便立即利用已有积累。
5. 作为用户，我希望看到已覆盖和剩余资料，以便分清完整与部分完成。
6. 作为用户，我希望新资料自动补进持续主题，以免手动维护文档。
7. 作为用户，我希望同主题保持连续，以便看到背景及其变化。
8. 作为用户，我希望主题标题清楚，以便定位要看的资料。
9. 作为用户，我希望主题更名或合并后依据仍可追溯，以免入口失真。
10. 作为用户，我希望每段主题资料能回到底层记忆，以便核对内容。
11. 作为用户，我希望过去和当前状态分别呈现，以免把旧近况当现状。
12. 作为用户，我希望计划与已发生经历分开，以免助手编造共同经历。
13. 作为用户，我希望长期背景只保留有依据的重要内容，以便快速了解这个人及关系。
14. 作为用户，我希望短期情绪不被总结成长期性格，以免误解联系人。
15. 作为用户，我希望系统不自动猜测动机，以免推测被反复当作事实。
16. 作为用户，我希望本人背景不混入他人的事实，以免跨关系泄露。
17. 作为用户，我希望待确认内容保持未确认，以免被整理成确定背景。
18. 作为用户，我希望整理正常完成后自动可用，以免逐篇审核普通更新。
19. 作为用户，我希望失败或有歧义的版本不生效，以免错误影响回复。
20. 作为用户，我希望看到“系统整理”标记，以便区别原记忆与派生表达。
21. 作为用户，我希望可以撤回整理版本，以便停止使用不合适的概括。
22. 作为用户，我希望事实错误能修正到底层，以便后续文档一致更新。
23. 作为用户，我希望总结错误能单独反馈，以免正确记忆被修改。
24. 作为用户，我希望纠正后的错误不换说法回来，以免反复纠错。
25. 作为用户，我希望手动补充背景后参与整理，以便填补已有资料遗漏。
26. 作为用户，我希望可手动刷新，以便主动请求更新。
27. 作为用户，我希望多次变化合并处理，以便控制等待和调用量。
28. 作为用户，我希望前台生成优先，以便后台整理少影响当前使用。
29. 作为用户，我希望回复先获得简短长期背景，以便理解分散事实。
30. 作为用户，我希望助手需要细节时才读主题正文，以免完整历史占满上下文。
31. 作为用户，我希望原有记忆检索继续工作，以免新目录漏掉重要依据。
32. 作为用户，我希望资料里的文字不能变成指令，以免干扰当前表达意图。
33. 作为用户，我希望能查看回复实际使用了哪些整理内容，以便理解候选依据。
34. 作为用户，我希望整理中或失败时仍能回复，以免被后台工作阻塞。
35. 作为用户，我希望空资料、未查到和整理失败分别显示，以免误判资料是否存在。
36. 作为用户，我希望停用后停止整理和加载，以便控制功能使用。
37. 作为用户，我希望停用后仍能查看合法结果，以便回看已有整理。
38. 作为用户，我希望删除整理结果后不会立即重生，以便删除行为真正生效。
39. 作为用户，我希望删除派生结果与删除原记忆分开，以免误删原资料。
40. 作为用户，我希望来源删除后相关摘要与副本被清除，以免敏感内容残留。
41. 作为用户，我希望重试、重启和迟到结果不恢复已删或停用内容，以便控制持续有效。
42. 作为用户，我希望不同联系人始终隔离，以免回复引用另一段关系的资料。
43. 作为用户，我希望知道模型质量尚未验证时功能不会自动加载生成正文，以免误把工程完成当作内容可靠。
44. 作为用户，我希望确认这项功能能改善回复且成本有限，以便决定是否持续使用。

## Implementation Decisions（实现决定）

### I1：模块与测试 Interface

- 整理 Module 以公开管理命令为 Interface，统一处理范围启用／停用、首次整理、刷新、纠错反馈、撤回、删除及状态读取；生成器和忠实度核验器通过可替换 Adapter 注入。
- 回复读取沿已确认的 `LayeredMemoryPort.capture(scope)`、`read_scenario(snapshot, id, range)`、`validate(snapshot)`，集中持有范围、版本、来源、预算和错误模式。回复调用方不用复制这些规则。
- 优先复用已有概览、任务、出站台账、优先级、资料管理、回复准备和来源删除 Module，不建立独立事实库、第二套 Agent 运行时或每层一个运行服务。
- 测试以公开管理／回复 HTTP 加隔离 PostgreSQL 和受控模型 Adapter 为最高主要 Seam，React 沿同一公开行为验证。此方向已在整体方案中确认，不重新拆成纯存储、纯接口或纯 UI 交付。

### I2：数据与一致版本集合

- 单独保存 L2 稳定主题及不可变正文版本、L3 及其版本、整理范围设置与世代、批次状态、反馈与完整依赖。现有无正文概览表不追加生成正文。
- 每个段落／画像条目保留直接支持它的底层记忆版本与时间状态；标题、目录提示和反馈涉及的资料同样登记依赖。
- `organization_generation` 表示同 scope 一致的 L3、L2 目录与可读正文版本集合。待生效结果先保存，校验完成后原子切换；读取不能混合分别取得的“最新”画像与目录。
- 实际版本字段与存储名称在实现时细化，但必须显式识别 schema 修订；旧准备快照不补签新字段，不能静默混用新旧协议。

### I3：完整参与依赖与直接引用

- 解释引用说明一句话由哪些底层资料支持；完整生成依赖覆盖这次模型实际看到的全部内容，未最终引用的输入也在其中。
- L3 递归继承所读 L2 的全部生成依赖。只引用 A 段不意味着读过的 B 段及其来源不再影响原生成结果。
- 直接引用、隐藏删除依赖、模型调用追踪和最小无正文台账分开保存、展示及删除；后台记录和普通日志不复制私密正文。

### I4：有界提案、核验与自动生效

- 一次有限批次最多包含 L2 归组与摘要提案、L2 忠实度核验、L3 提案、L3 忠实度核验四类语义步骤；没有变更可跳过。它是有限语义流程，不开放模型自由规划任务。
- 结构校验检查字段、范围、引用、正文大小和版本；忠实度核验独立检查主体、否定、时间、计划／发生、条件及适用范围。程序校验成功不等于语义正确，也不证明现实真相。
- 真实自动生效同时要求逐次核验、输入及世代复验、对应模型／规则／预算合同的质量资格有效。质量资格不因每条合法新记忆而重复全量评测，但每次生成仍验证自己的输入和结论。
- 整理模型没有采纳记忆、改写底层资料、执行管理命令、发布 Skill、任意读取或外部发送能力。

### I5：本人内容与任务范围

- 本人模型输入只包含合法本人记忆正文、时间状态及必要引用标识；不得直接序列化完整概览条目、lineage、联系人身份表、来源定位或多个联系人的聊天原文。
- 真正来源在后端复验，本人资料原有联系人来源依赖继续保留；不能用 owner 身份豁免删除。
- 新整理类型具有显式联系人／本人 scope。既有联系人任务继续要求其原字段；不创建假联系人、不把全部旧任务的 contact_id 无条件改为可空。
- 本人变化按 owner 唯一排队、去重及目标修订提交；多个联系人的合法本人资料变化合并处理，不能产生争写同一画像的联系人任务。

### I6：任务、并发与失败

- 幂等身份包括 scope、目标资料修订、规则版本及启用／删除世代。相同工作重复提交复用结果与状态；旧工作不能在重新开启后越过新世代。
- 模型调用在事务外进行，保存使用短事务、既有锁序及同连接复验；不得在已持 owner 锁时另开连接反向申请 contact 锁。
- 每次语义调用独立取得并释放后台许可，让前台可在调用间运行。现有 SDK 已发调用不可抢占，有限超时和迟到结果复验仍必需。
- 首次批量覆盖分批持久推进，临时错误按原有限重试规则，预算耗尽显示暂停与剩余量；正常重启恢复未完成工作，清理已提交而回执未存的重复操作。
- 任一输入更正、删除、反馈抑制或范围世代变化，拒绝受影响的迟到结果；L2/L3 不可用不扩大读取或阻塞原回复。

### I7：回复准备、工具和实际依据

- 显式准备固定本次联系人、输入、关系语境开关、整理设置世代与一致版本集合；运行时及最终 writer 复验相同集合和真实依赖。
- L3 与目录置于清楚标识的资料区；关系语境关闭、对应范围停用或质量资格无效时不加入。方向建议等较小输入路径不自动继承候选生成的完整资料或新工具预算。
- 新增独立场景读取工具，只接受本次目录中的稳定 ID、允许段落范围及冻结版本；scope 来自运行时，模型不能自报 owner/contact、任意路径或新版本。
- 工具返回、初始背景与目录均进入完整输入预算；正文累计调用数、返回条目及输入量有硬上限，重复、越界或预算耗尽可解释拒绝，不临时扩大权限。
- 只回看当时实际输入，不从当前文档补回旧回复依据；本人来源中的原联系人不授权跨关系原话补查。原 Skill 读取工具和至多一个版本的限制保持。

### I8：管理、失效和完整删除

- 管理命令幂等并绑定明确 scope／当前世代；UI 随联系人切换、停用、删除及重连及时撤下旧内容，禁止缓存展示另一范围或应删正文。
- 事实纠错与整理纠错有不同命令和目标；整理反馈保存最小必要内容及完整依赖，重复错误判定不确定时阻止再次自动发布受影响结论。
- 来源进入删除流程即阻止相关读取、生成与提交；清理正文、历史、目录、反馈、任务产物、已保存输入、缓存及使用副本，验证无残留后才能宣称删除完成。
- 删除整理结果与底层来源删除分别建模；前者关闭整理且保留原记忆，不能让自动刷新立即重建。停用保留合法查看，但不保留已删除来源的派生副本。
- 外部模型副本沿现行独立删除边界，不把本地删除说成已删外部副本；最小无正文出站台账按原规则保留。

### I9：预算和质量资格

- L2/L3 新预算独立于原 L1，仍受完整模型请求容量及当前输入优先约束；按完整条目／段落选取，不能截断半句话或静默删用户输入。
- 具体长度、目录数量、语义调用批次上限与工具累计预算通过固定合成数据标定。受控开发可使用显式有限测试配置；未标定数值不能被当作生产默认。
- 质量资格分别记录整理与回复读取的实际候选模型、规则／提示词、schema、资料用途政策、对应预算合同及评测版本，配套失败例和人工支持标注；相关身份变化后不能沿用旧资格。只改回复读取预算不自动作废未改变的整理质量结论，改变整理输入／输出／核验合同则须重评相应资格，最终加载要求两部分均有效。
- 工程交付不依赖真实质量预先通过；真实资料自动加载必须同时满足用途及范围确认和质量资格。未通过时保留 L1，不能以评测票关闭、Mock 成功或默认开关代替资格。

## Testing Decisions（测试决定）

### T1：主验收与既有先例

- 测试公开行为与不变量，优先从 HTTP 管理和回复入口穿过真实应用及隔离 PostgreSQL，核对最终用户可见状态、持久恢复与实际模型输入；不测试内部函数排列或字段存在。
- 纯转换与值对象只用有价值的合同测试；模型生成与核验分别可控替换，时钟、延迟、失败和并发可注入。
- 复用已存在的联系人／本人概览生命周期、冻结回复、来源世代、回复 writer 竞态、独立预算、Skill 学习停用重开及模型优先级的高层用例模式。React 控制器、公开页面与真实 App 各自记录实际覆盖。
- 每张实现任务从自己的首个新产物起承担隔离、来源、删除、迟到结果与恢复；最终组合验收不补偿前票遗漏的安全生命周期。

### T2：必须通过的工程不变量

1. 正常整理、无变化、空资料、非法结构、语义不支持、来源未知、重复操作、有限失败、预算暂停和重启均有确定结果。
2. 同主题更新和拆并保留合法身份；首次覆盖数及剩余量真实，部分不冒充全量完成。
3. 待确认、未知来历、已否决和应删资料进入两层为零；跨 owner/contact 内容泄露为零；本人模型输入不含越权原话。
4. 历史／当前未知、否定、计划／已发生、条件与稳定／临时含义保留，逐次核验失败不能生效。
5. L3 直接依据、递归生成依赖与展示引用各自正确，未被引用但实际读入的内容删除时仍使相关结果失效。
6. 同一回复只读取一个一致版本集合；读取、模型前后、保存与最终提交各阶段的更正／删除／停用均不能被迟到结果越过。
7. 停用重开 ABA、任务租约接管、已提交未保存回执、重复刷新和旧请求恢复均不会重复或恢复无效正文。
8. 来源删除、整理结果删除和底层记忆删除分别验证其完整闭包；正文、历史、反馈、任务输入输出、缓存及实际使用副本无应删残留。
9. 前台可在后台语义调用之间获得许可；有限超时、停止和取消后丢弃旧结果，不声称强行中断已发 SDK 调用。
10. L1 既有评测门槛和预算保持；新增背景、目录、工具累计预算及完整请求容量超限为零，失败正常回退且不扩大授权。

### T3：语义质量与回复效果

- 先固定人工标注的合成场景、底层资料及逐条支持关系，再评测实际候选模型。主体、否定、时间、计划、条件、冲突、纠正与长期／临时区分每类至少 15 个独立场景；不把同一例子改几个字当独立覆盖。
- 按生成条目审阅支持关系，保留失败分母；事实主体、时间性质、否定含义和跨关系泄露等关键错误必须为零。ID 存在、模型自报置信度及受控 Adapter 通过均不代表语义质量通过。
- 同一回复输入和相同既有 L1 预算下，对照不加两层与加入两层的结果：检验分散背景利用、无关背景干扰、资料指令污染、虚构或错误承诺、输入量、延迟及调用量。
- 报告包含模型和规则身份、数据集与预算、人工审阅记录、全部失败及未验范围。可以得到未通过结论，产品资格必须如实保持关闭。

### T4：真实交互和阶段签收

- 各票先做最小相关验证及必要回归，最终跨功能演示首次整理、更新、两类纠错、实际回复读取、本人范围、停用／删除及恢复。
- 实现后按工程工作流操作真实 App，验证资料页、来源跳转、范围切换、状态与回复依据；使用合成资料和隔离资源，记录真实操作及清理。HTTP 或普通页面通过不冒充原生 App 通过。
- 本轮文档发布不运行 App 或真实模型。后续真实模型评测按已明确的用途、供应商、数据和调用预算执行；未取得实际证据时保留未验状态，不提前签收。

## Out of Scope（排除项）

- 自动深入性格、动机、依恋或关系成效分析，生成回复方法、改写或自动发布 Skill，以及从一次表达要求形成长期偏好。
- 待确认候选进入 L2/L3，自动放行记忆维度、重跑原始历史提取、给旧证据补签、无范围资料升级。
- 新增原话补查、跨联系人搜索、将本人来源映射变成跨关系聊天读取权限。
- BM25、向量、rerank、LLM 召回计划、DSH 或回复运行时替换；新增自动聊天发送、任意文件读取、Shell、网络或自治常驻 Agent。
- 固定人工正文编辑、独立文档文件系统、每层独立服务、云端资料迁移、多设备同步、OCR／微信同步改造。
- 未授权的真实资料或模型出站、业务库迁移、远端发布、push／PR 和生产部署；任务发布不自动执行这些操作。
