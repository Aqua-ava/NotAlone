本票是可独立演示的窄完整行为，包含所需数据、应用、HTTP、当前界面与验证，不交付孤立存储表或接口。测试及生产调用跨规格约定的同一 Interface。

## Acceptance criteria（验收标准）

- [ ] 沿完整候选路径用同一输入对比原 L1 与新增两层，核对分散背景利用、无关内容误导、资料指令污染、输入量、延迟与调用量，固化读取预算。
- [ ] 最终资格联合整理质量与完整回复对照，开启前检查范围和用途；资格无效或质量未过时界面准确显示并保留 L1，不以最终票关闭冒充可用。
- [ ] 整理预算与回复读取预算各有合同身份；单独标定读取预算只更新对应回复质量资格，不无谓作废10的生成质量结论。若整理实际输入、输出、规则或核验合同变化，则重评相关整理资格。
- [ ] 验证两类范围的选择、普通更新、两类纠错、停用重开、删除不重生、重启、租约接管和实际 App 使用；工程、真实模型、真实 App 的命令与结果分开报告。
- [ ] 只做组合行为、质量与启用的最终交付；前票自己的来源、隔离、删除及恢复必须已通过，不把缺失功能集中留给本票。
- [ ] 新增内容只使用合法范围与已准入实际版本；来源、时间状态、人工决定和原有 L1／Skill 合同保持，真实质量未获资格时不自动开放真实资料使用。
- [ ] 本票新增正文、旧版、反馈、任务输入输出、目录／工具结果及使用副本从产生时就有完整参与依赖；删除、停用、更正与提交的两种顺序、迟到结果、重复和恢复不能复活无效内容。
- [ ] 记录实际命令、结果、数据处理影响和未验范围；工程合成验证、实际模型质量与真实 App 分别报告，不提前勾选或标记完成。

## 验证与交付

以公开管理／回复 HTTP、隔离 PostgreSQL 与当前 React 用户操作为主要验收，注入受控提案及忠实度核验 Adapter、可控时钟和失败事件。测试与业务通过相同 Interface，不仅证明字段、内部调用或脚本输出存在。复用已确认的整理公开命令及 capture/read_scenario/validate；本票只增加完成本票行为必需的合同，后续保持兼容。

实现时按仓库工作流使用 TDD，先运行最小相关验证，再完成相关回归与 Standards／Spec 两轴审查。涉及桌面交互时按工程工作流实际操作 App，以合成资料和自有资源记录验证及清理；普通页面不冒充原生 App 通过。验证完成后据实写入 Answer、更新 State 与任务索引，并创建仅含本票变更的本地提交。

本票的真实模型质量结论必须来自实际候选模型、固定人工标注资料及有限调用证据。受控 Adapter 仅验证流程，不能生成真实质量资格。实际调用的供应商、用途、数据与预算必须明确；未执行则保留未验和门禁关闭状态。模型／规则及对应预算身份变化须按规格复验，不以另一阶段预算变化无谓推翻未变的资格。

## 范围边界

本次发布只建立任务，不开始产品实现、业务资料整理、模型调用或迁移。执行时遵守已确认 scope、来源删除、质量资格和预算；不扩大自动采纳、读取权限、Skill 或外部发送能力。新外发用途、真实资料及远端操作沿仓库授权规则，不因任务发布自动获得授权。

底层记忆及来源保持权威；现有概览继续作为无正文导航投影，生成正文单独版本化。真实 App、模型、渠道及最终可用状态必须有各自证据，不以同一票的局部测试替代。
