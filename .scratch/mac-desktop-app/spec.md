# NotAlone 本机 Mac App：管理后台与输入法式小窗

Type: spec
State: open
Triage: ready-for-agent

## Problem Statement

用户需要一个可以在这台 Mac 上双击启动、日常使用的 NotAlone App：在完整管理后台维护联系人、历史资料、关系记忆和同步范围，在独立、轻巧的输入法式小窗中改写草稿或生成回复。

当前共享前端尚未实现。已审阅的双界面 HTML 原型验证了布局和品牌风格，但只有合成内存状态，未接入真实后端、跨窗口状态或剪贴板。旧 Swift 主界面已经退役，历史 App 的测试和权限记录不能证明新 App 可用。

## Solution

构建 Electron + React/TypeScript 的本机 Mac App，复用现有 Python 3.12 / Conda `NotAlone` 环境、PostgreSQL、后端 HTTP + SSE 和 Mac 原生定位探针。打包前端及桌面宿主，交付可从 Finder 双击启动的 `.app`；本期依赖已经配置的本机 Python 和 PostgreSQL。

App 有两个独立窗口：管理后台负责资料和配置；输入法式小窗负责当次表达。小窗以草稿改写为主要入口，草稿由用户输入或粘贴。用户确认联系人，生成并编辑候选，然后复制，由用户自行粘贴、发送。关闭窗口只隐藏；明确退出 App 时，必须完成本次后端运行时的停读协议。

视觉沿用已经审阅的原型及仓库 logo：淡蓝水彩、米白纸张、少量拼贴和胶带装饰。正文、状态和操作保持清楚。正式界面使用真实数据和操作结果。

## User Stories

1. 作为用户，我希望从 Finder 双击 App 即可打开管理后台，以便日常使用无需先打开终端。
2. 作为用户，我希望 App 找到已经配置的本机 Python 和项目环境，以便不依赖终端中的 Conda 激活状态。
3. 作为用户，我希望环境、数据库或后端不可用时看到明确的启动诊断和重试入口，以便知道如何恢复使用。
4. 作为用户，我希望重复启动回到已经打开的 App，以便不会出现重复窗口、后端或读取进程。
5. 作为用户，我希望第一次使用时完成本人身份和现有模型供应商配置，以便知道生成使用哪个身份和外部服务。
6. 作为用户，我希望已有配置可以直接复用，以便不会每次启动都重复初始化。
7. 作为用户，我希望凭据输入完成后只显示已配置状态，以便密钥不出现在普通页面和日志中。
8. 作为用户，我希望管理后台和输入法式小窗各自独立，以便管理资料与写回复时使用合适的窗口。
9. 作为用户，我希望通过全局快捷键唤起或隐藏小窗，以便在微信旁快速组织表达。
10. 作为用户，我希望快捷键占用时有提示并可修改，以便正常唤起小窗。
11. 作为用户，我希望小窗可以拖动并保持在前，以便放在合适位置使用。
12. 作为用户，我希望关闭任一窗口后仍能从菜单栏或快捷键重新打开，以便保留本次使用进度。
13. 作为用户，我希望有明确的退出入口，以便停止 App 和本次后台读取。
14. 作为用户，我希望退出收尾失败时得到真实结果，以便不会把超时当成已经停读。
15. 作为用户，我希望在管理后台查看联系人及其资料状态，以便选择这次要处理的人。
16. 作为用户，我希望每次生成和候选展示都能看见联系人，以便避免复制错人的回复。
17. 作为用户，我希望只有经过验证的唯一会话绑定自动定位联系人，以便昵称或消息内容不会被当作身份。
18. 作为用户，我希望首次绑定、重名、会话改名、匹配失败或低置信度时自己选择联系人，以便确认归属后再使用。
19. 作为用户，我希望切换联系人清除小窗的旧草稿和候选，以便不把上一位联系人的内容带给下一位。
20. 作为用户，我希望同一联系人在本次运行中保留草稿和编辑状态，以便隐藏再打开时可以继续。
21. 作为用户，我希望未提交草稿和编辑文本不跨重启保存，以便临时输入不会变成额外的长期资料。
22. 作为用户，我希望手动输入或粘贴草稿后进行改写，以便首版不依赖读取微信输入框。
23. 作为用户，我希望选择本次语气或补充要求，以便调整表达而不改变长期偏好。
24. 作为用户，我希望草稿改写默认只处理原句，并能主动开启关系语境，以便控制本次使用的资料。
25. 作为用户，我希望改写保留自己的事实、立场和承诺范围，以便候选仍表达我的真实意图。
26. 作为用户，我希望生成回复前明确给出表达方向并确认待回复消息，以便模型只在我的意图内探索措辞。
27. 作为用户，我希望查看两至三条可编辑候选，以便比较说法；后端只返回一条时，也能查看真实结果。
28. 作为用户，我希望看到生成中、失败、澄清或需要核实的状态，以便理解当前结果而不是反复盲点。
29. 作为用户，我希望重试同一次生成不会重复产生请求或候选，以便短暂断线可以安全恢复。
30. 作为用户，我希望按需展开候选依据和实际使用的上下文，以便判断回复是否合适。
31. 作为用户，我希望新消息只提示上下文更新，由我决定刷新和重新生成，以便不会覆盖正在编辑的文本。
32. 作为用户，我希望旧候选仍对应生成时的依据快照，以便不会把后来发生的内容当作原依据。
33. 作为用户，我希望复制当前编辑后的候选，并可选择复制后隐藏，以便把准备好的文字交给自己发送。
34. 作为用户，我希望复制失败时保留小窗并提示，以便不会误以为文字已经进入剪贴板。
35. 作为用户，我希望一次选择一个单联系人历史文件，并预览本人身份、联系人和资料范围，以便确认后再导入。
36. 作为用户，我希望通过导入新建或选择联系人，以便建立稳定的内部身份和可追溯来源。
37. 作为用户，我希望混合联系人、群聊、损坏或身份冲突文件被拒绝且不部分落库，以便资料不会串到错误联系人。
38. 作为用户，我希望查看导入与关系提取的真实进度、失败原因和重试结果，以便知道资料已经处理到哪一步。
39. 作为用户，我希望查看关系记忆和本人记忆的来源、状态与时间，以便区分自动采纳、待确认和手动录入。
40. 作为用户，我希望手动补充、修正、删除资料或撤销自动采纳，以便控制长期保存的内容。
41. 作为用户，我希望删除导入来源时能看到执行、失败和最终完成状态，以便只有通过不可检索校验才算删除完成。
42. 作为用户，我希望首次同步列表默认没有选择，刷新发现的会话也不自动授权，以便自己决定后台读取范围。
43. 作为用户，我希望确认会话与联系人绑定后再启用总开关，以便正文只从已确认范围内读取。
44. 作为用户，我希望关闭同步后停止新增读取，重新开启后在原确认范围内补齐，以便暂停和恢复不会扩大权限。
45. 作为用户，我希望分别查看后台 CLI 同步与前台会话定位状态，以便前台定位暂停不会被误判为后台正文停止。
46. 作为用户，我希望缺权限、探针不可用或历史补齐不完整时得到明确提示，以便失败不会被包装为成功或无消息。
47. 作为用户，我希望看到本机资料存储和外部模型调用范围的说明，以便理解长期存储、当次生成及外部副本的边界。
48. 作为用户，我希望用合成资料完成完整交付验收，以便先验证 App 再决定自己的真实使用范围。

## Implementation Decisions

### 已确认范围与技术选择

- 桌面宿主使用 Electron，共享界面使用 React/TypeScript。首版交付到本机可用 Mac App，复用现有本机 Python/PostgreSQL 环境。
- 两个独立窗口共享同一个应用会话和已验证后端连接。管理后台包含联系人与绑定、历史导入、关系资料、同步和配置；小窗包含联系人、模式、草稿或待回复消息、表达方向、候选编辑、依据和复制。
- 输入法式小窗采用当前原型默认的 A 横向候选布局作为实现起点；这属于实现默认，不记录为用户对 A/B/C 的逐项选择。装饰只在边缘和标题出现，不压缩正文可读性。
- 保留用户指定 logo 的原图，将所需品牌资产纳入 App 打包。原型只提供设计参考，不将模拟数据、假复制或原型状态代码作为正式运行时。
- 不新增数据库表或重写生成、提取、检索算法。使用现有公共业务接口；遇到阻碍已确认闭环的契约缺口时，先在规格和任务中明确补齐范围，不静默扩大功能。

### 桌面宿主与后端连接

- 主进程集中管理窗口、单实例、全局快捷键、菜单栏、用户主动选择的文件、剪贴板和后端生命周期。渲染层负责展示和交互，不直接管理 Python、数据库或微信读取。
- 主进程保存非秘密的启动配置，使用已经解析、核验的 Python 可执行文件、项目目录和 helper 路径。Finder 启动无需继承交互式终端的 PATH；环境不足时展示诊断和配置入口，允许重试。
- 后端只连接合法的 `127.0.0.1:端口`。主进程验证受控握手、认证和本次运行时，管理普通 HTTP 与 SSE；握手 token 不进入渲染层、诊断日志或源码。复用可验证的既有 NotAlone 后端，避免第二个后端。
- 受限 preload 只提供具名的业务操作及必要桌面能力，验证调用窗口、来源和参数。渲染层使用隔离和沙箱、关闭 Node 集成、限制导航和新窗口、设置 CSP；聊天文本和候选按文本渲染。
- 正式界面从受控的本地 App 资源加载。开发服务与测试入口不得作为交付 App 的运行依赖，也不得让任意网页获得桥接能力。
- 本次连接、联系人和请求都有有效性边界。重启、断线、换连接、换联系人和退出后，旧 HTTP 响应、SSE 事件或子进程回调不得覆盖新状态。
- 关闭管理窗口或小窗只隐藏，保留本次运行状态；打开小窗使微信失去前台时暂停前台定位，已确认范围的 CLI 后台同步按自己的总开关运行。
- 明确退出先阻止新业务操作，在同一已验证连接调用 `POST /api/runtime/shutdown`。以认证成功响应中的真实 `state: stopped` 确认停读；后端在停读并发完该响应后关闭 HTTP 服务，因此不要求成功响应后再有一次可达的 `GET /api/runtime/status`。GET 用于连接验证及关闭未确认时的同连接恢复；响应丢失且连接已关闭时必须显示无法确认，不能凭断线或 PID 判定成功。这也适用于经验证后复用的后端。退出不修改绑定或持久化的同步开关。
- 停读有界且幂等，失败不得报告已停。仅可对本 App 自己创建、仍能确认身份的子进程执行必要的退出清理；不得根据握手 PID 猜测杀掉其他实例。关闭失败保留明确的恢复入口，不静默另启读取进程。
- 默认快捷键采用 `Command+Shift+Space`，检测注册冲突并允许用户修改。小窗可拖动、置顶和快速隐藏，快捷键不读取或操纵微信输入框。

### 首启、联系人与资料管理

- 区分机器环境准备与用户首次配置。机器诊断核对 Python、后端包、数据库可用性和 schema/迁移状态；已有业务库缺基线或迁移时显示阻塞原因，不自动升级、删除或重建业务数据。
- 启动诊断补齐轻量只读入口，复用现有基线与迁移账本校验并检查就绪所需的 schema 元数据，返回受限状态与错误码。它不运行迁移或接管、不创建参考数据库、不读取联系人和消息正文；既有迁移命令会写库，不能拿它作为启动探测。诊断失败、基线缺失、账本漂移和待迁移分别显示真实恢复说明。
- 本人初始化和模型密钥使用已有 setup 接口；现有可配置供应商为 DeepSeek。密钥只经必要的受控提交路径传递，提交后清空输入；页面只查询是否配置，不回显已存密钥。
- 首启就绪以当前后端运行身份为范围。补齐现有 setup/status 的只读 `runtime_owner_configured` 布尔，验证当前实例的受控 owner_id 在同库存在；保留原有全库状态字段语义，不返回身份或密钥，不让渲染层指定 owner。仅有非空 UUID、全库已有其他 owner 或联系人列表为空均不能证明当前本人配置就绪；未就绪时阻塞业务并提示修正受控配置，不静默选择或恢复他人身份。该补齐不新增表或迁移。
- 联系人范围使用稳定的内部 `contact_id`，当前 `owner_id` 来自已验证的后端运行身份。昵称、备注、外部会话标识和 OCR 文本只用于展示或匹配证据。
- 单联系人导入沿用预览、用户确认、原子提交及后台处理流程。用户通过系统文件选择器主动选文件，新建或选择联系人后明确确认。App 不扫描目录或执行第三方导出工具。
- 资料管理沿用已有记忆、版本、候选及来源接口。展示 `auto`/`manual`、待确认状态、来源聊天时间与保存时间、证据引用；修正、手动录入、撤销和删除遵循现有应用层规则。
- 用户已确认在任务 14 补齐本人资料的原子修正：在同一 owner 范围事务内创建新 ID 的 `manual` 版本、保留来源与保存时间、引用旧版本并使旧版退出检索。仅增加现有本人资料表所需的最小版本字段及后端操作，不以非原子的新增加删除代替修正，不新增业务表或重写算法。失败保留原资料有效；其他 owner/联系人与已生成回复的依据快照不被改写。自动迁移验收仅作用隔离测试库，现有业务库升级另行确认。
- 来源删除沿用后台任务和不可检索验证，显示排队、执行、失败及最终结果。来源记录标为 deleted 可以先于最终验证，只在同一来源的原删除任务与 verify_not_retrievable 步骤均成功后显示完成。当前窗口相关数据同步失效，另一联系人不依赖该来源的资料和回复保持自己的状态；同 owner 其他联系人回复若引用了被删来源支持的本人资料，须按现有来源删除契约连带失效。不存在把资料直接迁移给另一联系人的操作。
- 后台任务进度由后端业务状态投影，不能用模型 Todo 或百分比推断完成。导入期间回复仍按现有优先调度执行。

### 小窗生成、编辑与复制

- 首版草稿由用户手动输入或粘贴，默认为 `rewrite_draft`。草稿本身确定基础表达方向，语气或额外要求只作用于本次请求；`include_relationship_context` 默认 `false`，用户可明确打开。
- `reply_to_message` 使用已选联系人范围内的真实规范消息作为目标，并要求用户输入明确表达方向；没有目标或方向时阻止提交。无法取得消息时展示空状态，用户可以使用草稿改写。
- 只有已验证的唯一会话绑定可自动定位联系人；首次、改名、重名、低置信度或失效绑定要求用户确认。小窗始终显示联系人，未经确认不生成。
- 同一联系人在本次 App 运行中保留草稿、候选和编辑文本；切换联系人清空临时表达状态并废弃旧响应。未提交草稿和编辑文本不写入浏览器持久化或跨重启恢复；已经提交的请求与原始候选仍按后端既有审计规则保存。
- 生成请求遵守已有 `idempotency_key` 契约：相同输入的网络重试复用同一请求身份，用户修改输入或明确重新生成时创建新身份。可展示处理中、拒绝、澄清、超时或失败，不能伪造候选。
- 正常展示后端真实返回的候选，目标为两至三条；允许后端有界返回一条或澄清。编辑保持本次窗口文本与原始候选快照分离，复制以当前编辑文本为准。
- 本次候选、目标消息和依据绑定生成时快照。新消息到达后只提示更新，用户明确刷新或重新生成；刷新不会静默覆盖已有候选或正在编辑的文本。
- 依据默认折叠，展开时沿用请求范围内的证据接口，展示实际资料与可核对的来源；来源删除后的状态不得恢复被删除正文。高风险核实提醒沿用后端风险标记，不展示内部推理或模型原始错误。
- 用户触发复制后由主进程写入系统剪贴板。成功后才显示已复制；“复制并隐藏”仅在成功时隐藏。复制不等于已发送、采用或同意沉淀长期偏好。

### 同步、权限与数据处理

- 同步管理读取元数据列表供用户主动选择。首次列表没有预选，刷新和新增会话不自动加入；明确确认会话到联系人绑定后，才进入后台正文授权范围。
- 正文读取遵守运行时、同步总开关和 active 已确认绑定共同门禁。停用后停止新增读取；恢复只在原已确认范围按 ADR-025 补齐，展示失败、暂停和无法确认完整性。
- 前台定位复用现有 Mac 探针，只读取微信前台、会话可见时的最小定位区域；不滚动、切换或控制微信，不读取其他 App。原始帧在端侧内存处理，不持久化或上传。
- 新 Electron 宿主必须重新核验 helper 完整性、签名、运行路径和实际权限归属；不得继承历史 Swift App 的实机结论。权限缺失提供对应功能的安全说明，不扩大为 Full Disk Access、辅助功能或自动化控制权限。
- 当次生成沿用现有外部模型通道和上下文限制，界面明确其供应商及数据范围。本机长期资料按现有存储事实说明；未实现加密时不能宣称已加密，来源删除不等于外部模型副本也已删除。
- 日志只记录必要状态、稳定错误码和非正文标识；不记录聊天正文、候选正文、密钥、握手 token 或 CLI 原始输出。

## Testing Decisions

用户已确认：自动测试实际 App 操作与现有后端 HTTP 接口，使用合成联系人、隔离测试库和可控模型；再在本机检查双击启动、快捷键、剪贴板和退出停读。

### 测试接缝

- 主要接缝为实际 Electron App 的公开用户操作及其可见结果：启动、窗口、输入、联系人切换、生成、复制、导入、资料操作、同步和退出。测试不以 React 私有状态、IPC 频道实现、模块调用顺序或 DOM 结构快照为成功标准。
- 复用后端现有的 HTTP 公共契约作为业务回归接缝。桌面完整闭环连接真实本机 HTTP 服务和 PostgreSQL，只替换外部模型、微信 CLI/探针及必要系统对话框；不以整套假的业务仓库证明真实后端接线。
- 启动、非法握手、认证、断线和关闭失败可使用合成本机服务或合成子进程在同一公开操作接缝核验。系统快捷键、Finder 启动、原生剪贴板和权限另做实机验收。
- 桌面自动化优先使用 Playwright 的 Electron 支持，先在第一张任务中验证锁定版本组合能启动、操作两个真实窗口及正常回收进程。官方将该支持标为 experimental；若实际无法支撑约定接缝，进入决策模式说明证据，再调整测试方案。

### 关键行为

1. App 由 Finder 启动，无预先激活的终端也能找到受控 Python 环境；重复启动只有一个 App/后端，失败有安全诊断，连接更换后的旧结果失效。
2. 两个真实窗口独立打开、隐藏和恢复；同联系人保留本次编辑，换联系人清空旧草稿，延迟响应和事件不会串人。
3. 已确认的两位合成联系人及另一 owner 数据互相隔离；无效或不确定绑定不能生成。
4. 改写默认关系语境关闭，打开后仅取当前范围；回复缺目标或方向不能生成。可控模型捕获允许的输入，输出真实候选、澄清或失败状态。
5. 同输入重试幂等；候选编辑与原快照分离；新消息只提示，依据保留原生成快照；复制取得当前编辑文本，失败不会显示成功或自动隐藏。
6. 空白隔离环境完成首启、单联系人预览确认、原子导入和任务进度；混合、损坏、身份冲突和重复导入都有正确结果。
7. 资料来源、采纳方式和时间展示正确；联系人及本人资料的原子修正、撤销、来源删除到不可检索均经真实接口核验。修正产生带来源的新 manual 版本，旧版退出检索，失败保留旧版有效，历史回复依据仍对应生成时快照；另一 owner/联系人资料保持可用。
8. 首次同步无选择，新增会话不自动授权；仅 active 已确认绑定读取正文。关闭总开关、解绑、退出后停止，恢复只在原范围补齐；不完整或权限错误显示为失败状态。
9. 退出使用已验证运行时的认证停读协议，含复用、超时、失败、重复退出和连接文件改变；成功 POST 的 stopped 响应证明停读，成功后服务关闭不算失败，响应丢失且无法查询则保持未确认。不篡改持久开关，不误杀其他进程，不启动新读取。
10. 渲染层无法取得握手 token、直接读数据库或调用任意系统 API；非 App 页面与非法 IPC 参数被拒绝。候选复制全程不存在微信写入或外部发送动作。

### 既有验证与隔离要求

- 既有核心业务 HTTP 集成覆盖单联系人导入、候选、幂等、跨 owner/contact 拒绝、依据和来源删除；运行时关闭测试覆盖认证、幂等、失败不假报停读及真实 HTTP 收尾。现有首启、导入任务、回复、依据、SSE 与同步接口测试可直接沿用。
- Python 操作按仓库规则激活 Conda `NotAlone`。自动化使用本轮随机新建、完成迁移、名称以 `_test` 结尾的数据库，并隔离握手、dotenv、模型凭据、App 配置和 CLI/探针执行路径。
- 测试不得读业务库、真实默认握手、私人历史或既有联系人正文；测试清理只作用于本轮创建的资源，不修改已有业务环境。
- 每个实现任务先在上述接缝走最小 red -> green，完成相关类型检查与测试，再进行 Standards/Spec 两轴评审和任务范围本地提交。
- 最终编译并验收实际打包的 `.app`，不能只用开发服务器、渲染层测试或历史 App 证明交付。记录打包路径、签名结果和 Finder/快捷键/剪贴板/停读的实际操作结果。
- 可控模型验证请求范围和流程，不能证明真实模型的语义质量。真实模型冒烟优先只使用合成输入；真实微信通道只在用户已确认范围中验收，记录实际通过和未验证部分，不将接口测试包装成微信集成可用。
