# CLI 后台同步缺口补齐

> 状态：已确认，待拆分实现任务
> 基于：`.scratch/cli-background-sync/spec.md`、ADR-003、ADR-023
> 目标：让 CLI 后台同步在恢复运行时自动发现并补齐已确认会话的可检测消息缺口，同时保持联系人隔离、来源可追溯和用户可见的覆盖状态。

## 用户问题

CLI 后台同步目前只保证“开关开启期间”的近实时增量读取。同步关闭、App 重启、CLI 暂时不可用或读取恢复不完整时，消息可能落在已保存游标之后但没有进入 NotAlone。现有实现会跳过手动关闭窗口并推进游标，因此用户看到同步已开启，却看不到关闭期间产生的消息。

## 已确认行为

1. 同步开关开启、App 重启恢复、CLI 从故障恢复以及“立即检查一次”都要触发缺口检测；发现缺口后自动开始后台补齐。
2. 补齐范围覆盖所有已确认的 active 微信一对一会话；当前选中的联系人优先，其他联系人按有界队列继续处理。未确认会话、群聊和新发现联系人不进入补齐范围。
3. 补齐只从最后一条可靠位置开始，不追溯绑定 baseline 之前的历史，不把补齐扩大成全量历史导入。
4. 文字消息进入规范消息流；图片、语音等非文字事件只记录非文字占位或计数，不伪造成文字，也不能阻塞后续文字消息。
5. 实时读取与后台补齐使用不同的来源/状态标记；用户可以看到当前联系人覆盖状态、补齐进度和最终结果。
6. 补齐可以暂停、失败后重试和跨 App 重启继续；暂停或失败时不得显示为已完成。

## 领域与一致性约束

- 补齐只允许写入用户已确认且仍为 active 的 `owner_id + contact_id` 范围；联系人解绑、删除或来源删除过程中不得重新创建或复活消息。
- “最后可靠位置”必须指一批来源记录、规范消息和游标已经在同一成功边界内提交的位置。游标已经前进但消息没有落库时，不能继续信任该游标。
- 补齐任务按稳定的微信消息身份去重；同一消息先实时写入、后补齐，或任务重试时，只保留一条规范消息和可追溯来源。
- 消息发生时间使用 CLI 原始时间；无法确认时间时保留未知或低置信状态，不以读取时间冒充发送时间。
- 补齐记录只保存范围、时间、状态、计数、游标和失败原因等不含聊天正文的审计信息；原始聊天正文仍只进入已有消息来源存储路径。
- 缺口未完成时，回复上下文可以继续使用已有消息，但必须显示“消息覆盖可能不完整”；补齐完成后才可显示覆盖已恢复。

## 实现决策

- 保留一个全局 CLI session 事件流和已有有界安全对账；缺口检测在同步恢复和手动检查路径中复用已确认绑定的 cursor，不为每个联系人创建长 Follow 进程。
- 后台补齐默认按联系人串行或极少量并行执行，当前联系人优先，批次有固定上限；每个批次成功后保存进度，避免单个大缺口阻塞其他联系人。
- 关闭窗口不再作为永久丢弃依据：重新开启后应把可检测的关闭期间消息作为后台补齐候选；这不改变“同步关闭时不读取”的规则。
- 当已知游标超过最后一条已落库消息时，先定位最后可靠观察批次并从该位置重放；不能通过简单覆盖游标掩盖缺口。
- CLI 不能确认来源是否最新时，状态只能标记为“无法确认完整”，不得宣称补齐完成；来源恢复后继续任务。
- App 退出或后端重启不取消补齐任务；持久化任务状态和最后可靠进度，下一次开启同步后继续。

## 测试决策

### 合成与持久化测试

- 关闭窗口后恢复读取，检测缺口并补齐文字消息。
- 游标超前但消息缺失时回退到最后可靠位置并重放。
- 实时读取与后台补齐交错时稳定去重，不重复创建消息或来源。
- 批次中途失败、暂停、App 重启后从最后成功批次继续。
- 多联系人按当前联系人优先且有界公平处理；单个联系人失败不阻塞其他联系人。
- 非文字事件产生占位/计数并前移事件处理进度，文字事件继续写入。
- 解绑、删除、联系人隔离、来源删除和回复上下文覆盖状态保持正确。
- CLI 来源不可用或 freshness 不足时显示不完整，不推进到虚假的完成状态。

### App 与授权联系人验证

- App 状态显示“发现缺口、补齐中、已暂停、补齐失败、补齐完成、无法确认完整”等状态和计数。
- “立即检查一次”同时驱动正常增量和缺口补齐。
- 使用用户已授权的指定联系人做只读验证；只检查消息计数、游标、来源和状态，不发送消息、不操作其他联系人。

## 不在本次范围

- 不补齐首次绑定 baseline 之前的完整历史，不替代用户主动历史导入。
- 不自动绑定新会话、群聊或未确认联系人。
- 不读取微信数据库、密钥或非公开协议；不新增图片 OCR、语音转写或媒体正文解析。
- 不自动切换、滚动、输入或发送微信消息。
- 不把补齐过程做成对外网络服务或独立定时自动化。
