# 合成验收矩阵

所有例子独立合成，不使用真实聊天。预期独立于实现，工程通过不代表模型泛化质量。

| 场景 | 独立预期 | 票 |
| --- | --- | --- |
| 2024年的消息在2026年导入 | 来源仍2024；保存时间独立；不能称刚发生 | 01 |
| 来源日期缺失／仅部分来源有日期 | 未知／不完整，不以导入时间补全 | 01、02 |
| 2030-01-31 23:30 +08说“明天” | 当地2030-02-01，不使用UTC日期或运行日 | 02 |
| 2030-01-01说“昨天” | 当地2029-12-31 | 02 |
| 2030-03-04说“去年换了工作” | 2029年精度，不宣称1月1日发生 | 02 |
| 2030-01-15说“上月出差” | 2029年12月精度 | 02 |
| 多条不同日期消息各说“明天” | 分别用本条锚点，不统一用最后消息 | 02 |
| “最近忙”“过阵子再说” | 原模糊表达，无臆造的7天／30天期限 | 02 |
| “他上周说明天出差”且转述锚点无法确定 | 保留未知，不机械拿本条发送日计算 | 02 |
| 有明确安排日但没有已发生证据 | 日期过去仍为计划，不自动升级完成 | 01、02 |
| “本周不便通话” | 完整来源当地历周适用期，不缩为消息当天 | 02 |
| “出差期间不便通话” | 条件有来源，无臆造截止日 | 03 |
| 后来补充“出差结束” | 条件依据变化，不自动推断现在愿意接电话 | 03、04 |
| 新消息说“去年住在甲地”，已有今年住乙地 | 保留历史，不因消息较新覆盖当前乙地 | 04 |
| 较新资料完成后再导入更早资料 | 新导入确实被处理，旧事实不凭导入顺序替代现状 | 04 |
| 相矛盾来源且不能确认纠错或变化 | 保留矛盾，不自动选较新的写入行 | 04 |
| 人工纠正后再次导入同一旧证据 | 不复活已纠正错误，保护现有用户决定 | 04 |
| 条件／事件来源删除与迟到生成同时发生 | 失去使用资格，缓存／恢复／待写入不复活 | 全部 |
| 旧完成回复快照缺新增字段 | 保持旧时点未知，不以当前资料补证 | 全部 |
| 两联系人同文不同日期／条件 | 严格按owner和contact隔离，不交叉取证 | 全部 |

每条验收记录实际命令与结果；单例red→green、相关回归、真实隔离HTTP/PG、页面与开发App分开记录。
