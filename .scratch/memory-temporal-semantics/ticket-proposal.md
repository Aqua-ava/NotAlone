# 记忆时间语义：纵向任务拆分提案

Triage: ready-for-agent
State: open

> 功能方案已获用户同意。用户已确认本文件任务粒度、依赖及规格测试边界；已按 Local Markdown tracker 发布四票。使用 implement-spec 编排，TDD 实现，最终 code-review 双轴评审。

## 01：时间含义贯穿记忆页面与回复依据

Blocked by: None

交付：旧聊天今天导入后显示来源日期，保存时间独立；已有事件阶段／时段进入联系人、本人、分层资料和回复依据。用户能理解未知原因，不再看到笼统时间核实标签。历史生成快照保持原样。

验收：合成旧资料 → 公开读取 → 卡片／详情 → 回复模型输入 → 保存与恢复快照；覆盖无日期、来源不完整、计划已过日期、来源删除、本人和联系人隔离。沿现有合同贯通字段，本票不虚构新精度或条件状态。

## 02：依据原话解析日期并保留精度

Blocked by: 01

交付：不同消息的昨天／明天分别以各自来源解释；年、月、日和具体时刻如实展示，模糊表达及缺时区保持未知。事件阶段与事实适用期分离，无来源的默认起止日期不再产生。

验收：正式提取／独立核验 → 持久资料 → API／页面 → 分层引用及生成快照；跨时区、去年、上月、多锚点、午夜、未知、计划到期均有合成用例。新事件合同兼容旧版本，时间元数据跟随来源删除。同步旧提示与规格的默认期限口径。

## 03：保留记忆适用条件及其依据

Blocked by: 01

交付：用户能看见资料适用条件、其来源及不确定性；条件在概览、背景、画像和回复中完整保留。出现相反条件证据时，不自动推导原禁忌已撤销。

验收：合成“出差期间不便通话” → 提取／核验 → 页面及回复依据；条件缺失、条件被删、同范围与跨范围来源、旧数据缺条件、手动修正均验证。本票建立条件表达与安全使用；跨版本自动更新由 04 完成。

## 04：按有据时间线更新与处理乱序补导入

Blocked by: 02, 03

交付：裁决同时使用新旧记忆的合法来源、时间、阶段与条件；用户能区分补充、变化、纠错及矛盾。新补导入的旧消息进入正式处理流程，但不能凭较晚导入覆盖较新状态；后发回忆不被误当现状。条件变化与撤销原主张分别判断。

验收：正式导入／处理 → 更新／合并／保留并存 → 版本页面 → 概览／分层资料／回复 → 撤销与来源删除。验证早期补导入的水位、重试幂等、同日期冲突、阶段变化、人工保护、原子失败和删除竞态；最终完成相关回归、开发 App 验收与双轴评审。
