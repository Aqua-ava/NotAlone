## 4. 真实 HTTP 封顶如何成立

表中一轮公开 invoke 数来自“每窗一次 E＋至多一次 V”，不是对当前 runner 的 HTTP 保证。[旧 CountingModel](../memory-accuracy-next/release-eval/run_tier_a.py)只在 `invoke` 外层计数；SDK 的 max_retries=2 在其内部，不能据此把 38 invoke 写成当前真实 HTTP ≤38，也不能在未核安装实现时声称实际会发固定倍数请求。[v2 对照 runner](../memory-core-claim-retention/product-prompt-comparison-v2/run_comparison_v2.py)遇钉扎工具失败会再发默认工具请求；[产品核验器](../../backend/src/notalone/memory_extraction/verification_adapters.py)没有该 fallback，历史 16 个成功返回不是生产路径等价证据。

拟议新评测保留产品原绑定和重试配置；**所有重试共同消耗上述真实 HTTP 硬上限**。≤42 代表最多 42 次请求尝试，遇重试可能提前用完而不能完成 21 窗；这种结果必须标为不完整，不为完成样本追加预算。通用公式：拟议单阶段硬上限 `H=2N`；本机在每次实际 transport 发出前先原子预约一次，达到 H 时硬拒绝下一次发送。失败、超时、空响应、SDK retry 和任何请求 fallback 都计入；本方案禁止工具/供应商 fallback，如意外发生仍计数并立即终止。不得只记录成功请求，未知在途结果也不能退还预约。

[现有追踪 transport](../../backend/src/notalone/memory_trace/transport.py)可在有活动 trace 时观察各次 provider_request，但目前没有评测级持久硬封顶；无 trace 时不计尝试，因此不能直接借它宣称硬门已具备。未来准备门须证明同步/异步发送、SDK 重试、异常捕获和响应落盘故障均不能绕过计数，出站 endpoint allowlist 生效，唯一运行记录不可换目录重置。计数故障须越过 SDK 重试捕获直接停发；串行、无并发在途下一例。硬门没验证就不读凭据、不构造可出站客户端。此处是测试准备约束，尚无实现。

每次运行独立新预算、台账及关闭收据，不复用任何历史余额。公开 ledger 只含运行/样本引用、E/V 用途、请求序号、接收方、状态、耗时、已报告用量和聚合数字。允许的合成原始 I/O 单独私有保存（0700/0600），完整保留失败及额外候选；不给普通日志、Git 或公开汇总复制正文、Authorization 或内部思考。原[追踪留存与删除契约](../../architecture/current/memory-extraction-trace.md)继续有效，本文不接业务 trace store，不写候选、已采纳记忆、水位或迁移。

## 5. 指标、停止和放行分开

| 目标 | 必须分别报告 | 禁止替代的口径 |
| --- | --- | --- |
| 核心事实覆盖 | 每个必需/可选主张的 raw 覆盖、程序接受覆盖、完整契约准确覆盖；漏提、正文/主体/转述/时间/必要来源错误、正确候选损失；确定坏 auto 与歧义 auto 分开；全部额外输出逐条审计 | 候选出现或 V=supported 不等于完整正确；把错候选保留 pending 不算修复；不更新真实 6/12 |
| 指代准确 | 主集 16、补充 3 分开及合计；最终去向、主体、指代对象/不确定保留、语用、正文、时间、来源；假事、记错人、一般错误、运行失败与空结果、严格标注 8/19 | 历史 13/15、当前110个确定性回归或未核验 `--baseline` 不算现行模型成绩；明确对象漏提与含糊对象保守 pending 分开 |
| 维度放行 | 单一完整轮的 `summarize()`、固定计划/已完成/未运行数、假事/记错人/一般错误、严格标注及独立复核、运行时键是否可推导 | 不跨轮拼成“≥15”；未运行不是通过；两轮错误取最好一轮不能放行；评测理想 auto 不等于生产实际写入 |

安全早停：首个 `false_fact` 或 `wrong_subject`，或人工独审发现确定坏 auto，立即关闭本批后续请求；原输出不覆盖、难例不删、不补位。运行失败、非法结构、载荷越界、冻结漂移、HTTP/日志计数或权限故障同样停；合法空 E 按该例期望计漏提或合法 none，占用已发生请求，不重试来补候选。未执行的 V 标为未执行，不伪造空核验；已预约超时标为结果未知。一般错误按完整计划保留，累计超过 1 便已不可能成为本轮放行证据；仅在预注册诊断范围内继续既定一般错误观察，不据此进入下一阶段。

达标签仍为用例数 ≥15、假事 0、记错人 0、一般错误 ≤1，由[当前 summarize](../../backend/src/notalone/memory_extraction/evaluation.py)输出；语义标注覆盖另报，完整原始分母另核。现有 runner 对未捕获异常只写原始失败记录、没有纳入 `results` 的汇总，未来执行须核对计划全量与失败/未运行，不照抄部分 `summarize()` 冒充整场通过。

当前 evaluator 的 auto 是原有三道门的“若该维度放行”理想去向，不叠加生产第 4 道门、不写库。[运行时键](../../backend/src/notalone/memory_extraction/dimensions.py)仅能推导 subject、time、truth_intent；paraphrase、reference、media、reported 缺结构化字段，达标签也不能放行。质量改善和自动采纳是不同执行门，按 [ADR-033](../../architecture/adr/033-source-semantic-verification-before-adoption.md)、[ADR-036](../../architecture/adr/036-per-dimension-adoption-release.md)及[放行台账](../../docs/memory-adoption-dimension-release-ledger.md)保持来源核验、0.7、风险白名单与语用限制；不关闭维度门、不用 `RELEASE_ALL_DIMENSIONS` 改生产。
