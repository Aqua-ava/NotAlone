# NotAlone 未完成工作总清单

更新日期：2026-10-10。本轮已按用户要求推进不需人在场的实现和验证：完成 React 记忆提取追踪接入及删除回归，更新真实 follow 手册，核对指代评测的现行集合与安全门槛。需要现场操作的项目暂放；当前工程优先解除 CLI/WCDB 输入缺口，再安排原生验收。产品讨论仍从持续会话 Q16 接续。

本清单目前汇总 5 份待收束设计、8 张未关闭任务、1 份待实现的媒体规格及 Windows 后续方向，共 15 个工作入口。按下一步主要阶段分为：**待讨论 8 项、待实现 3 项、待验收 4 项**。原第 8 项追踪查看已完成并移至已完成区；为保留引用，其他次序编号不重排。阶段之间存在依赖，这些入口不能解释为 15 个互相独立的功能。

以下优先级和次序是排期建议；原任务的 `State`、`Triage`、验收条件与用户已确认事实仍以链接的来源为准。本清单不发布新任务、不改写现行规格，也不授权新的模型调用、真实微信读取或原生桌面验收。

## 依赖与执行顺序

产品设计先推进第 1 项，再与第 2 项共同核对场景入口、候选版本和新消息处理。两份草图收束后，再形成正式规格与实现任务。第 1 项涉及的持久化、临时要求延续、恢复与删除会影响后续接口，应在实现新交互前明确；当前不加入经验沉淀或自进化。

现有 Mac 验收不以两份新草图落地为前置。先补齐完整、可追溯的 CLI/WCDB 输入及受控打包路径，再安排有限验收时段；首个真实同步切片可采用手动确认的唯一联系人、隔离数据库和禁用模型的路径，详见[真实微信前置核查](../observation-model-smoke/acceptance.md)。**CLI 后台同步不依赖前台 OCR**；任务 18 的自动定位可单独补齐，而最终完整 App 交付仍须完成其原定依赖。

原生复制、测试调度和 follow 的相关检查尽量合并到同一次已认可的有限时段，减少反复启动；每项仍记录自己的实际结果，不能用窗口成功、签名通过或普通页面通过替代原生能力。旧 Swift 冒烟入口和旧“微信必须保持前台才能读正文”的条目已按 ADR-023/025/030 核对，视觉采集与 CLI 正文同步分别验证。

记忆质量工作先区分三件事：核心事实覆盖、指代准确率、按维度放行。自动采纳维持当前空放行表；修复或一次局部评测通过不自动放行，也不重开已关闭实验。App 追踪查看现已完成，可直接核对已保存的实际结果；历史缺口不会因此补造。

## 当前先做什么

**工程上先补齐完整、可追溯的 CLI/WCDB 输入。** 第 3 至 7 项保留 P1 优先级；条件齐备后先验证手动确认联系人的最小同步闭环，再补原生复制、自动定位和最终 App 集成交付。准备材料和普通页面已经通过的部分不重复安排，剩余现场条件暂放；过往预约不自动延续。

不进入现场验收时，产品讨论仍可从第 1 项 Q16 接续，随后收束第 2 项。指代质量需要新的固定对照方案与模型预算；媒体实现需先收束资源接缝。剩余主功能均缺前置或现场条件；目标模式继续从已有规格中寻找可独立验证的准备切片，不重复跑已通过组或把准备当作验收。
