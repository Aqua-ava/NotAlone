## Implementation Decisions

1. 一次性桥只放本轮仓库外0700目录，不新增产品功能、API或服务。Root固定唯一P1 run、21窗顺序、输入／目标／Gold、42真实HTTP尝试封顶、aware期限及实际版本；失败不补位或换UUID重开，不自动P2。准备完成后在启动前写0600冻结清单。
2. 冻结全部提取源码、既有driver要求的memory／trace／ledger／scopes／包配置，以及JSON与中文参考字节；逐文件核实际工作字节与明确本地提交blob。JSON字节摘要、规范JSON摘要和frozen_gold描述摘要分别记录，不能混用。一次性桥本身另有摘要。
3. loader只由持久批次领取后的入口调用，根.env为明确唯一凭据来源。只解析精确指定key，拒重复、空值、插值或不支持结构，不打印值或异常正文，不读取数据库配置、全局环境秘密或旧私人实验资料。不写／复制密钥，不修改或删除根.env。用户此前未用的录入向导不再是前置条件。
4. 两个显式审核回调分别保存仅E的raw视图及持久封存后的full视图，0600且不可覆盖。只打印case／phase／文件名；等待对应review文件和非秘密继续标记，按同一aware期限有限等待。Root逐字段判断，不设默认safe、自动中文oracle或默认全pass；未决／异常／超时停批，raw判断不能在揭full后重写。
5. 沿现有发送前契约、响应允许字段脱敏及已报告型号变化门运行；不打印内部思考、headers或密钥。只上传现有公开合成21窗。Root串行启动一次评测进程，不启动App、微信、OCR、业务PG／Worker或产品CLI。
6. 收口保留全21位置的完成／空／失败／未知／未运行、实际预约与终态、两客户端退场、闭合收据和原matcher／显式审核分层结果。聚合报告不写正文，允许原始I/O只在私有目录。未完成或技术失败不签模型质量、原模型验收或默认维度放行；真实核心6/12保持。

## Testing Decisions
