# 04 — 写入裁决：同事件演变与版本化失效

**What to build:** 借鉴 Mem0 的写入决策：候选入库前在同范围+同受控主题+同主体+同分类内检索相似已有记忆，新候选与相似旧记忆交模型裁决四动作——ADD（新增）/ UPDATE（同事件演变：旧记忆标记失效并保留版本历史，新记忆入库）/ NOOP（重复跳过）/ KEEP（不同事件并存）；失效与写入由确定性代码执行；裁决的外部调用落台账。

**Triage:** ready-for-agent
**State:** open
**Blocked by:** 03（落库层与水位）

- [ ] 相似检索：同 owner（级）范围 + 同主题 + 同主体 + 同分类内的关键词相似匹配
- [ ] 裁决模型调用：新候选 + 相似旧记忆 → 四动作之一，结构化输出沿用强化配方
- [ ] UPDATE 执行：旧记忆标记失效（保留可查历史），新记忆入库；失效记忆不再进入检索
- [ ] NOOP/KEEP/ADD 各自落库行为正确，重复抑制复用 NOOP
- [ ] 裁决调用三态落台账（成功/运行失败/校验拒绝）
- [ ] fake model 单测覆盖四动作；集成测试验证 UPDATE 后检索只返回当前版本
