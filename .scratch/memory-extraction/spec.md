# 记忆提取纵切规格

> Triage: ready-for-agent
> 来源：2026-08-23 会话。依据 ADR-002（提取与分层采纳）、ADR-011（记忆目录，本纵切不做）、ADR-007（后台 Worker，本纵切不做）、CONTEXT.md 关系记忆术语。上游就绪：MemoryPort 生命周期、PostgresMemoryStore（迁移 009）、检索已通、真实模型 ecnu-max 格式已稳定。

## Problem Statement

导入的聊天历史只是流水账，系统对"这个人是谁"没有任何认知：候选回复只能看到当前上下文，不知道"她不吃香菜""他下周出差"。关系记忆的数据模型、采纳生命周期和检索都已就绪，但没有任何生产路径能把消息蒸馏成记忆——`confirmed_memory` 只能手工造数。产品闭环缺"长期关系认知"这半边。

## Solution

新增记忆提取链路：对一个已确认联系人的最近消息窗口，模型以结构化输出提取带来源的事实候选（引用消息 ID、置信度、风险标记、有效期），确定性外壳校验证据契约后经既有 MemoryPort 写入 `memory_candidate` 并按 ADR-002 自动采纳为 `confirmed_memory`（标记 `auto`、可撤销）。v1 以独立命令触发；提取质量不合格时以可见的失败状态保留，不静默放弃。提取产出的记忆立即被既有检索和候选回复消费。

## User Stories

1. 作为用户（Owner），我想在导入聊天记录后运行一次提取，让系统自动蒸馏出"这个人是谁"的关系记忆，而不用手工录入。
2. 作为用户（Owner），我想让每条自动产生的记忆都带来源（能跳回原始消息），以便核对这个判断从哪来。
3. 作为用户（Owner），我想让自动写入的记忆明确标记为"自动采纳"且一键可撤销，以便和"手动录入"区分并随时反悔。
4. 作为用户（Owner），我想让时效性事实（如"他下周出差"）带有效期并在过期后自动失效，不让过期信息污染回复。
5. 作为用户（Owner），我想让提取不读完整历史、只用最近消息窗口，控制成本和无关干扰。
6. 作为用户（Owner），我想让提取严格限制在单一联系人范围内，绝不串库。
7. 作为用户（Owner），我想让高风险话题（转账、健康、借款等）随记忆保存风险标记，生成回复时提醒核实。
8. 作为用户（Owner），我想让提取失败（模型输出不可解析、证据不足）保留可见的失败记录并支持重试，而不是无声消失。
9. 作为用户（Owner），我想让每次外部模型调用都记入出站台账，知道提取花了多少 token。
10. 作为用户（Owner），我想让重复提取同一段消息不产生重复记忆。
11. 作为用户（Owner），我想在提取完成后看到统计（提取了几条、采纳几条、失败几条），不用进数据库查。
12. 作为开发者，我想通过一个新的模型运行时接缝注入 fake model 做全量测试，测试不调真实 API。
13. 作为开发者，我想在显式凭据下运行真实提取冒烟，验证从消息到落库的完整链路。
14. 作为用户（Owner），我想让提取产出的记忆立即改善候选回复质量（检索自动带出），不需要额外接线。
15. 作为用户（Owner），我想让撤销一条自动记忆后它彻底从检索消失，并可级联清除。

## Implementation Decisions

1. **新模块与接缝**：新增记忆提取模块，公开一个深入口（输入已验证联系人范围与消息窗口，返回提取统计与落库结果）。内部含一个模型运行时接缝（输入消息窗口，输出结构化事实候选），风格对齐既有候选回复运行时；模型经既有 DeepSeek 构造入口注入。
2. **结构化输出契约**（对齐 ADR-002 证据契约）：每条候选必须包含事实文本、五类分类之一、支持消息引用列表（窗口内消息 ID）、置信度、风险标记、可选有效期；schema 用与候选回复相同的强化模式（全字段 description、禁字符串数组、低温采样）。
3. **证据契约的确定性校验**：引用的消息 ID 不在窗口内、事实文本为空、分类非法的候选一律拒绝，不写入。整体不可解析时记录一次可见的提取失败，可重试。
4. **自动采纳**：通过校验的候选经既有 MemoryPort 写入 `memory_candidate` 并自动确认，采纳方式标 `auto`；带有效期的事实写入 valid_at/invalid_at。用户可经既有撤销/删除路径处理。
5. **重复抑制**：同联系人间隔文本与既有 active 记忆重复（规范化比较）的候选跳过，计入统计。
6. **触发方式（v1）**：独立命令行入口，参数为已确认联系人（owner/contact 经环境变量与参数提供，对齐导入命令惯例），对最近消息窗口执行一次提取；导入后自动触发与增量同步阈值留待 Worker 纵切。
7. **窗口**：单联系人最近固定条数消息（含媒体占位文本），按时间正序输入模型；不跨联系人、不读完整历史。
8. **台账**：提取的外部模型调用与候选回复共用出站台账三态记录（成功/运行失败/校验拒绝）与用量上报。
9. **隐私边界**：终端输出只含统计数字，不打印消息正文、事实文本或联系人标识；测试只用合成数据。
10. **schema 变更**：无新表——复用迁移 009 的 `memory_candidate`/`confirmed_memory`；`extract_failed` 可见性 v1 以命令行退出状态与统计输出承载，失败状态字段留待 Worker 纵切。

## Testing Decisions

1. 好的测试只断言外部行为：fake model 驱动提取入口，断言落库结果的字段、标记、有效期与统计；不测模型内部。
2. 证据契约校验：引用窗口外消息、空文本、非法分类的候选被拒且不落库。
3. 自动采纳与标记：全部经 MemoryPort，`auto` 采纳可撤销、撤销后检索不到（PostgresMemoryStore 集成测试，合成数据、隔离测试库）。
4. 重复抑制：同文本二次提取不产生重复 active 记忆。
5. 隔离：提取与查询严格按 owner + contact，跨范围不可见（沿用既有集成测试惯例）。
6. 真实冒烟：显式凭据下对合成导入数据跑一次端到端提取，断言落库与台账记录；默认跳过。
7. 先例：候选回复的 fake model 纵切测试、PostgresMemoryStore 集成测试、出站台账测试、真实模型冒烟模式。

## Out of Scope

- 联系人记忆目录的生成与渐进加载（ADR-011，独立纵切）。
- 后台 Worker、任务步骤表与导入后自动触发（ADR-007，独立纵切）。
- 增量同步阈值触发（依赖前台同步纵切）。
- "重复才信"的置信度升级机制（v1 只做文本重复抑制）。
- 产品 UI（记忆页展示属 UI 纵切）。
- 记忆的跨联系人合并或推荐。

## Further Notes

- 提取质量观察点：合成消息窗口下的候选命中数、引用准确率、分类合理率、token 成本；真实冒烟记录首次数据。
- 本纵切完成后，候选回复立即受益：既有检索已读取 active `confirmed_memory`，无需改动回复链路。
