# 记忆提取纵切规格（v2，含 grilling 修订）

> Triage: ready-for-agent
> 来源：2026-08-23 grill-with-docs 会话两轮共十一条决定；依据 ADR-002（全自动采纳与证据契约）、ADR-011（记忆目录，本纵切不做）、ADR-007（后台 Worker，本纵切不做）与 research/ 记忆调研（Mem0 写入决策、Claude Code 双层拼接、ReMe 归并演化、负例设计）。上游就绪：MemoryPort、PostgresMemoryStore（迁移 009）、检索、真实模型 ecnu-max 格式稳定。

## Problem Statement

导入的聊天历史只是流水账，系统对"这个人是谁"没有认知；`confirmed_memory` 只有手工造数的生产替代。同时已识别的深层问题：断章取义的语义错误、新旧矛盾记忆、删除记忆被重提取复活、用户自身资料无归属层级——这些不先定规则，记忆库会在真实使用中劣化。

## Solution

新增记忆提取链路：对已确认联系人的消息（首次导入自动全量分批，之后自动增量，断点可重跑），模型以结构化输出提取带主体标注的事实候选（引用消息 ID、置信度、风险标记、有效期、受控主题），确定性外壳校验证据契约后经写入裁决（新增/更新/跳过/保留）落库：自动采纳标 `auto` 可撤销，同事件演变标记旧版本失效（版本化），用户删除留指纹永不复活。关于用户自身的事实存 owner 级自我记忆，与联系人级关系记忆拼接检索。低置信候选不自动采纳。v1 以命令行触发与纠错；提取产出立即可被检索和候选回复消费。

## User Stories

1. 作为用户（Owner），我想导入后跑一条命令就自动完成首次全量提取，不用分辨全量还是增量。
2. 作为用户（Owner），我想让首次全量按分批滚动执行、断点安全重跑（已提取部分自动跳过），网络中断不丢成果。
3. 作为用户（Owner)，我想让每条自动记忆带来源引用，能跳回原始消息核对。
4. 作为用户（Owner），我想让自动记忆明确标记"自动采纳"且可一键撤销，与手动录入区分。
5. 作为用户（Owner），我想让事实必须标注主体（我 / 联系人 / 共同），"我下周出差"永远不会被记成"他下周出差"。
6. 作为用户（Owner），我想让关于我自己的事实存到我名下（owner 级），对每个联系人都可用且不重复堆积。
7. 作为用户（Owner），我想让同一事件的演变自动接管：新的"开始增肌"让旧的"在减肥"失效，但旧版本保留可追溯。
8. 作为用户（Owner），我想让我删除过的记忆永不因重提取而复活。
9. 作为用户（Owner），我想让低置信度的候选不自动入库，标记待定由我决定。
10. 作为用户（Owner），我想让时效事实带有效期并自动过期。
11. 作为用户（Owner），我想让高风险话题保留风险标记，生成回复时提醒核实。
12. 作为用户（Owner），我想让无关闲聊（"吃了吗"）不产生记忆（负例设计）。
13. 作为用户（Owner），我想让媒体占位只推断发送行为偏好（"不爱发语音"），不推测内容。
14. 作为用户（Owner），我想手动录入记忆（如禁忌"别提他前公司"），标记 manual。
15. 作为用户（Owner），我想用命令列出某联系人或我自己的全部记忆、删除单条——语义错误的纠错路径。
16. 作为用户（Owner），我想让提取的外部调用记入出站台账，成本可见。
17. 作为用户（Owner），我想让单次提取窗口有明确上限常量。
18. 作为开发者，我想用 fake model 全量测试提取、裁决与落库，测试不调真实 API。
19. 作为开发者，我想在显式凭据下跑真实提取冒烟并记录观察点。
20. 作为用户（Owner），我想让提取产出的记忆立即改善候选回复（owner 级与联系人级拼接检索），无需改回复链路。

## Implementation Decisions

1. **模块与接缝**：新增记忆提取模块（提取运行时接缝：消息窗口→结构化候选；确定性外壳：校验、裁决、落库），模型经既有 DeepSeek 构造入口注入；提取是单轮结构化输出调用，不引入 Agent loop。
2. **结构化输出契约**：每条候选含事实文本、主体（self/contact/shared）、五类分类、消息引用列表、置信度、风险标记、受控主题（健康/工作/家庭/出行/财务/学习/情感/其他）、可选有效期；沿用强化配方（全字段 description、禁字符串数组、temperature 0.1、function calling 路径）。prompt 含上下文语气理解要求（注意反讽玩笑）与负例示范（闲聊不产出记忆）。
3. **证据契约确定性校验**：引用消息不在窗口内、文本空、分类/主体/主题非法、缺置信度的候选一律拒绝；整体不可解析返回明确失败可重试。
4. **置信度门槛**：低于阈值（默认 0.7）的合法候选不自动采纳，以 pending 状态保留可查看、可后续确认或丢弃。
5. **写入裁决（借鉴 Mem0）**：候选入库前在同范围（同 owner，联系人级或 owner 级）+ 同受控主题 + 同主体 + 同分类内检索相似已有记忆，将新候选与相似旧记忆交模型裁决四动作——ADD（新增）/ UPDATE（同事件演变：旧记忆标记失效并保留版本历史，新记忆入库）/ NOOP（重复跳过）/ KEEP（不同事件并存）；裁决后的失效与写入由确定性代码执行。主题降级为粗筛范围，不做判定依据。相似检索 v1 用关键词，记忆量级触发漏召回时升级 pgvector（同库插件）。
6. **owner 级自我记忆（借鉴 Claude Code 双层拼接）**：新增 owner 级记忆存储（无联系人归属）；主体为 self 的事实写入 owner 级，contact/shared 写入联系人级；检索时两路合并拼接进上下文，互不覆盖。
7. **删除指纹**：删除为软删除，保留文本指纹；提取与裁决入库前查询删除指纹，命中则不再自动入库（手动录入除外）。
8. **自动采纳与统计**：通过校验与裁决的候选经 MemoryPort 自动确认标 `auto`；返回提取统计（提取/采纳/待定/跳过/拒绝/失效旧版计数）。
9. **触发与命令**：v1 独立命令族——提取命令（自动判断：该联系人从未提取过→全量分批滚动；提取过→只提新增消息，以消息水位记录断点）、手动录入命令（manual）、列出记忆命令、删除记忆命令。数据库连接与 owner 经环境变量，联系人经参数，对齐导入命令惯例。
10. **台账与窗口**：提取与裁决的外部调用共用出站台账三态记录与用量上报；单批消息窗口上限为显式常量。
11. **隐私边界**：终端输出只有统计数字与状态；不打印消息正文、事实文本或联系人标识；测试全合成数据。
12. **schema 变更**：新增 owner 级记忆存储与消息水位记录（新迁移）；记忆版本化失效复用既有状态字段语义（invalidated）；无其他新表。

## Testing Decisions

1. fake model 驱动提取、校验、裁决、落库全链路单测；断言外部行为不测实现。
2. 证据契约：窗口外引用、空文本、非法分类/主体/主题、缺置信度被拒。
3. 置信度门槛：低置信候选 pending 不自动采纳。
4. 裁决：ADD/UPDATE/NOOP/KEEP 四动作各自落库结果正确；UPDATE 后旧记忆失效但仍可查历史、检索不返回失效记忆。
5. 删除指纹：删除后重提取同文本不复活；手动录入同文本可入库。
6. owner 级：self 事实入 owner 级不重复入联系人级；检索拼接两路结果。
7. 隔离与清理：沿用隔离测试库、随机 owner、只清理自己数据的惯例；全部合成数据。
8. 真实冒烟：显式凭据下合成导入→提取→断言落库（auto 标记、来源、主体）、台账、检索可见；默认跳过。

## Out of Scope

- 联系人记忆目录的生成与渐进加载（ADR-011，独立纵切）。
- 后台 Worker、任务步骤表、导入后自动触发（ADR-007，独立纵切）。
- verifier 二次核实（等真实数据评估错误率后再决定）。
- 语义相似检索（pgvector 升级，触发条件：关键词漏召回实测）。
- 媒体内容化（语音转写、图片理解属上游输入适配器纵切）。
- 产品 UI。
- 记忆跨联系人合并、推荐或批量整理。

## Further Notes

- 首次真实提取观察点：候选命中数、引用准确率、主体标注准确率、裁决四动作分布、token 成本、断言负例（闲聊消息不产出）。
- 本规格取代 v1 草案；grilling 十一条决定全部落入实现决策 2-12。
