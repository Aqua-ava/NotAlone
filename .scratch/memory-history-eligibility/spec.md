# 区分纠正错误与历史变化的生成资格

状态：用户已确认方案，代码与隔离验证完成；真实 App 受现有数据库账本漂移阻塞。来源：本会话 2026-10-18 的明确授权。

## 用户问题与范围

旧代码将纠正错误和状态变化都写成 invalidated，历史导航可再次把旧错误传给模型。
用户要求：原来记错的不能再进入生成，后来发生变化的可以作为历史参考，原因不明先禁用。
联系人与本人资料均适用；原始来源、审计回看与生成资格分开。

## 行为与实现决定

- 用户明确选择“纠正错误”或“记录变化”；旧 correct 调用缺省按纠正错误处理。
- 版本链继续保留。旧版记录 retirement_reason：error_correction、state_changed 或 unknown。
- 存量及未明确分类的自动失效默认 unknown；不根据新版存在或修改时间猜测过去成立。
- active 沿用原生成门；invalidated 仅在 state_changed、有合法来源且明确历史导航时可用。
- retired_at 只表示修改记录时间，不冒充事实变化时间；事实有效期不由修改时刻补写。
- 错误/未知旧版只供用户审计；历史检索、概览、L2/L3、缓存、助手讨论、旧候选续写与表达样本均不能旁路带入生成。
- 已生成候选不静默改写；依赖禁止生成的资料时显示依据失效提示，保留只读回看并要求重新生成。
- 生成前、模型返回后及提交时复验，纠错不能被迟到结果绕过；原来源不得反复自动采纳旧错误。
- 真实删除继续覆盖原有派生资料及副本；纠错不等于删除原始聊天或销毁审计历史。

## 验证接口

- 公开 memory correct/versions HTTP：两类操作与未知值拒绝，联系人/本人隔离。
- 存储与检索端口：旧版审计可见、错误/未知召回为空、变化历史有来源与标注。
- 公开助手生成、续写、恢复与表达样本入口：旧错误不能通过已有正文重新进入模型，竞态失败关闭。
- 真实 PostgreSQL 隔离测试库：80→81默认unknown、事务一致、重复迁移与删除。
- 桌面 IPC 与 React 页面测试；复用 npm run dev 进行实际 App 验收，分别记录环境阻碍。
