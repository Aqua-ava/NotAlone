# 真实聊天 App 完整链路验收

用户要求：使用已有真实聊天资料，在实际 App 与微信中完成导入、同步、记忆提取、检索和候选回复的完整验收；发现问题后修复并复验。

## 范围与实施

- 使用当前源码构建的 App、生产后端、真实本机微信 CLI 和根配置中既有的官方 DeepSeek 服务；模型输入限选定联系人的必要文字。
- 使用独立 userData、私有配置和随机隔离 PostgreSQL；原始导出与原业务库保持可恢复。真实正文、身份、凭据与含正文证据只保存在仓库外受控私有目录。
- 主 Agent 独占桌面，通过 Computer Use 完成系统文件选择、预览确认、同步授权、查看任务和资料、生成及编辑候选。
- 先用完整原导出检查兼容性；模型质量使用有界且明确标注范围的真实片段。片段验收不能称为全部历史准确率。
- 不发送外部聊天消息，不改变默认维度放行；Agent 技术核验不标为用户亲自确认。

## 验收边界

1. 真实单联系人文件经系统选择、预览及归属确认正式导入；失败不部分写入，同源重放不重复。
2. 同一联系人的真实 CLI 绑定经界面主动确认，开启同步、关闭停读、重新开启及游标去重可核对；没有新增消息时明确保留正向增量未验证。
3. 原导入任务由生产模型提取并完成或给出具体失败；逐项核对实际候选与来源，明确 pending、拒收和 auto 的差别。
4. 显式启用关系背景或回应路径后，从实际回复依据核验同联系人聊天与资料被检索；不能用默认纯草稿改写代替。
5. 真实模型生成可编辑候选，核对引用、主体、时效和用户意图；确认无外部发送。
6. 修复有据缺陷时先建立生产公开接缝的合成回归，再重建并复验原真实链路，保留失败记录。
7. 正常退出后核对自有后端及读取进程结束；真实私有证据与公开聚合结果分开保留。

## 测试决定

已授权的主要接缝为实际 App 可见控件、认证 HTTP 业务接口和导入规范化公开接口。修复使用最小相关合成测试及类型检查，完成后按仓库规则独立 Standards / Spec 审查和本地提交；不推送远端。
