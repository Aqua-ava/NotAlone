# 显式v4已完成动作的附属数量

Triage: ready-for-agent
State: resolved

## 问题与目标

旧公开A13实际是询问“门票买好了吗？”及回答“买好了，两张。”，并非条件计划。原两条event各自有来源，置信度0.85／0.55，经实际Flow分成auto／pending，冻结整组合同产生bad_auto1。原RAW／FULL、Gold一个必需命题、分母、置信度和闭账保持。

现prefix只适用于前置且不能独立成立的时间／话题分句，不能诚实地把已完整“买好了”伪装成前缀；event＋末尾prefix则是孤立前缀，not_memory丢必需数量。只读禁网络回放已重现原行为，拟议continuation被真实compiler拒绝未知类型。补一个最小v4结构标签，让已完成动作及紧邻后置数量作为完整候选接受既有V和采纳门；最低0.55应使该候选pending，仍不算Gold要求的完整auto通过。

## 实现决定

1. 仅显式离线v4增加 `continuation`，首版只表达**同一目标消息、紧邻已完成普通event的一个附属数量片段**，不是独立新事件、状态、计划、条件、来源或另一人物事实。它是结构角色，不开放任意正文／日期／字段组合，不新增领域类别或采纳政策。
2. 模型必须显式选择；不得按数字、量词、标点、case名或Gold自动合并。标签后再以有限数量语法验证输入范围，超范围整窗拒绝，不能声称程序理解了任意中文附属关系。数量支持独立于案例的半角整数0–9999（不前导零）、规范中文整数0–99及明确计数单位的封闭集合，不将金额、日期、含新谓词或任意尾句纳入；支持范围写在提示与测试中。
3. 主项必须是同一消息前一相邻target且kind=event，不能是context、省略项、prefix／condition、别的类型或另一continuation；不跨完整句末或消息边界，不吞掉独立主张。附属项subject／topic须与主项相容，否则拒绝，不忽略冲突标签。此slice仅一个附属数量；更多组合保持明确失败。
4. 实际原引句按原顺序完整合并；原依赖及source并集、最低confidence、风险／歧义／替代解释均须传播。保留event/assertion/asserted/literal与双null，不改0.7门，不升置信度，不自动提供proof／semantic_basis，不删除问句来源或借合并认证人物。
5. v2／v3提示、schema、编译和生产默认保持；新值旧版拒绝。原event／event标签仍重现旧拆分和错误，不重签历史材料；未来真实验证先修订合同、新freeze及独立台账，本规格不创建预算或启动调用。
