# 修复回复准备阶段延迟

用户报告点击「帮我想想」出现「未收到生成结果，请用同一次请求重试」，要求测出瓶颈并修复，不能仅延长 8 秒超时。

## 范围

- 使用生产上下文组装、来源复验和 HTTP 准备接口建立耗时基线。
- 减少关系概览及候选来源校验中重复的数据库读取与快照处理。
- 保持联系人隔离、原来源世代、删除与修改失效规则；不得跨请求复用来源有效性。
- 保持客户端当前超时值，通过减少实际工作降低耗时。
- 保留同请求重试与用户亲自发送边界，不新增模型调用或后台发送。

## 验证边界

- 来源快照及概览公开读取：同批重复读取预算、精确参数隔离、返回值互不污染。
- 下一次读取及生成前／提交前复验：来源正文、引用或删除变化仍被发现。
- 合成隔离 PostgreSQL 集成测试，以及同输入本地耗时前后对照。
- `npm run dev` 实际 App 的「帮我想想」与候选展示；不运行打包版。

## 数据边界

本地性能诊断仅输出耗时与调用计数；私人正文、身份、凭据不写入仓库。
