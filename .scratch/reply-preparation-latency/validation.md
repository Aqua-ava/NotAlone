# 回复准备延迟修复验收

## 根因与改动

准备接口继承桌面 JSON 客户端的 8000ms 默认超时；超时被归为连接失败，界面显示未收到生成结果。该请求尚未调用模型，后端仍可继续完成准备。

同一准备流程重复读取共享消息窗口、依赖候选的大 JSON 和概览依赖；分层记忆即使没有当前发布集合，也先构建完整底层概览。

现在在单次持锁概览或 REPEATABLE READ 只读候选列表内复用完整查询键的来源快照与依赖，退出立即释放；不同复验阶段重新读取。空分层结果先做精确范围及当前世代的存在性查询；命中仍走原持锁复验。客户端超时未修改。

`npm run dev` 实际 App 选择原问题联系人并点击「帮我想想」，显示生成已完成和 3 条可编辑候选。数据库时间戳显示：准备到创建生成请求7.39s，生成请求处理14.27s，整轮完成23.67s。包含本地复验和保存，不能把生成请求处理全部归为模型网络耗时。未发送外部聊天消息。此次证明原超时场景已走通，不代表任意数据量或机器负载下都能在8s内完成。

## 第二轮逐段排查（2026-10-21）

- 完整请求临时分段计时发现：首轮模型前回调9.697s，其中相同来源复验4.783s+4.910s；次轮8.661s，其中4.400s+4.253s。移除接线层重复复验，保留请求租约检查、每轮真实来源复验、工具新增依据审查及提交事务校验。
- 历史回复依赖读取原来按每条依据返回同一份context_snapshot并重复递归扫描。现按请求聚合依据、只传输/扫描一次快照，继续沿原owner/contact、续写链、实际演化引用取依赖。分析器中该函数累计9.731s降到0.180s；这是独立诊断阶段累计值，不是可直接相减的端到端耗时。
- 讨论冻结回放只读已捕获输入ID；不再SELECT整条含prepared_context的记录。完整首次讨论仍读取完整历史。
- 依据变更SQL直接读取conditions/evolution；候选列表直接投影可选字段，兼容旧schema的缺列NULL。整批163条候选的只读投影对照1.388s→0.035s且返回相等；实际回复仅查询pending子集，不能将此差值算作点击流程收益。
- 冻结窗口校验改用内部只读快照，公开捕获仍返回独立副本；来源活动性仅在现有稳定读scope按精确owner、连接、类型、ID集合去重，下一scope重新核验。
- 同一真实输入、正式服务装配、不带cProfile：改前组装4.843s+复验3.130s+预算0.073s=8.046s；改后3.406s+2.276s+0.073s=5.756s。此对照不含最终持锁保存。分段完整请求中的锁等待小于1ms，不能归因于锁竞争。
- 新增/修改测试：历史依赖聚合3条、讨论投影2条、依据投影2条、模型轮次守卫4条、快照scope6条、来源活动性scope2条、候选投影2条，均已通过。既有约束审查29条、讨论上下文29条、讨论依赖11条通过。独立Spec/Standards及增量缓存/投影审查未发现确认缺陷。

历史依据模块22条和候选范围1条（共23条）隔离 PostgreSQL/HTTP 回归通过，33.127s；覆盖退休、删除、继续调整、重启和最终提交竞态。

## 用户要求先确认根因：当时的诊断与暂停记录

当时按用户要求暂停实现。该轮真实App首轮准备12.1192s仍失败，沿同次请求重试准备4.7500s、生成19.1705s，App最终显示生成已完成；不能宣称首次点击超时已解决。

首轮准备中不重叠的主要开销：6次概览读取6.0389s（构建、完整复验、最终事务各读双方概览），3次顶层讨论读取/复验3.0274s，待确认候选读取2.3670s，其他0.6859s。64次锁操作累计0.2286s、最长0.1849s，此次锁非主因；前文小于1ms属于较早的不同请求。

成功重试的生成19.1705s：调用前本地处理4.6665s，模型前回调2.5368s，回调完成至模型结束约3.4934s，运行时其他约0.1047s，模型后复验3.0256s，保存4.8594s，会话完成0.4820s，其他约0.0021s。模型自身仅占约18%；保存内部还多次递归复验已捕获讨论。

已确认主要原因是校验职责分散在多层同步调用中，同一概览/来源/历史依赖被多次完整读取和展开；历史快照曾按每条依据重复传输、扫描，又进一步放大每次校验成本。不同时间点的来源变化保护仍有必要，不能据此删除全部复验。8秒只是前端默认截止时间，不是这些处理必须耗时8秒。

5.756s只是局部阶段对照，漏掉最终保存，不能与完整12.1192s直接比较；App与独立测试之间剩余运行差异及后台竞争尚未证实。后续HTTP观察计数不与该次12.1192s同时发生，不能作为竞争因果证据。

暂停前另有实验改动未完成最终验收：准备专用校验路径（概览3轮降2轮）4项新增及62项相关测试通过；显式ref快照复用最后10项中9过、旧查询数断言1失败（7→6）；嵌套候选历史读内复用仅跑过红测试，绿实现尚未验证。以上均未提交，临时command计时钩子仍须在修复恢复后移除。
