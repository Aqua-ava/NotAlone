# 导入追踪批写与后台召回复用
Triage: ready-for-agent
State: resolved

## Problem Statement
最新 main 已完成前一轮三路性能优化，但导入追踪仍逐记录查写，后台记忆召回仍逐候选重建同一语料统计和向量范数。用户已批准这两项并行实现，要求基于最新 main，由主会话统筹、合并和验证，并提供相同负载的优化前后数据。

## Solution
导入在现有事务与范围约束内批量核验捕获撤销标记并分块写入；召回只在一次调用内复用不变的语料统计和向量范数。保持现有接口、正文、顺序、失败关闭、来源删除及隔离合同。两个执行会话独立工作树并行，主会话串行合入本地 main。

## User Stories
1. 用户导入长历史时，追踪写入的 SQL 数量随分块数变化，而不是每条消息分别查写。
2. 用户仍能查看完整、按原输入顺序排列的处理依据和收据。
3. 一条捕获已撤销时，整批拒绝，不过滤后继续保存其他正文。
4. 后续块、序列化或事务失败时，不保留部分消息、追踪或游标推进。
5. 并发删除、来源停用和绑定撤销不允许迟到写入恢复旧正文。
6. 重复导入、同 locator 多次事件、UUID/locator 收据优先级和新授权捕获身份保持原合同。
7. 后台处理同一批候选时，旧记忆分词、语料频率和范数只计算一次。
8. 用户得到相同的 BM25、余弦、RRF 与有序候选；零向量、同分、非法编码及不可用状态保持原行为。
9. 逐条采纳改变记忆池后，评分仍依据当时真实池，不能沿用过时统计。
10. 用户看到明确的前后操作数、耗时、样本数和内存数据，合成边界与真实编码结果分开报告。

## Implementation Decisions
- 固定原始性能基线为 `746bb40b7a0a90105c39f76d2786c451a55c93f7`；两个实现工作树统一从含本规格的最新 main 规划提交创建。不得在原工作区旧分支或协调 main 中实现。
- 导入保持现有保存接口和调用方事务，按 owner/contact 与明确捕获 ID 集合分块查墓碑；任一命中整批失败，实际追踪记录不得去重。
- 采用参数化多行 VALUES 分块写入，暂定墓碑块最多 4096 个 UUID，记录块最多 500 条、普通编码参数目标 2 MiB。超预算单条单独写入，禁止截断或新增隐式丢弃；不按块提交，不使用忽略冲突掩盖记录缺失。
- 先以双连接复现写入/删除/撤销的实际交错；若证据要求统一范围锁，必须在相关行锁之前按现有锁顺序取得，不据静态差异直接认定 Bug，不在保存末端补锁制造锁环。
- 逐次规则文件摘要读取、真实执行时刻、捕获 UUID/位置/收据及删除路径保留，不顺手缓存规则版本。
- 召回保持公开函数签名，只增加本次调用内的私有语料预计算与记忆向量范数复用。保留算术顺序、筛选、top-k、RRF 和 memory_id 决胜规则，不保存完整 Q×N 矩阵。
- 独立 bm25_scores 调用继续按当时语料构建；本轮不改逐条采纳的动态池与追踪重新评分。不得新增跨批、全局或持久正文/向量缓存，不延长来源正文生命周期。
- 两个会话各自维护代码、测试和任务单。共享规格、planning、架构及最终集成由主会话维护；必要跨范围改动先报告。所有人均不得回退他人已有改动。

## Testing Decisions
- 用户已认可的现有接缝：导入/同步入口、生产仓储与处理追踪公开查询及删除流程；召回公开 hybrid_candidates/bm25_scores。行为断言不依赖新增私有类；SQL/往返与 tokenizer/sqrt 计数为性能证据，不能代替结果验证。
- 导入使用合成记录与随机自有 PostgreSQL 测试库，核对查询/正文顺序、范围、重复导入、撤销、来源删除、两种事务交错及后续块失败回滚；兼容同 locator 多事件、空批次和大单记录。现有追踪/导入/同步回归优先。
- 导入基线与实现串行运行相同 100/1000/10000 条负载，区分本保存函数业务 SQL、完整入口 SQL、协议同步/往返和 commit。1000 条普通记录的保存路径目标为 2001→4 条业务 SQL；锁与额外来源检查另计。记录实际耗时中位数、样本数、离散范围及独立内存测量，不把 execute 方法次数冒充协议往返。
- 召回固定相同 Python/hash seed、文本、记忆 ID 和向量，比较分数及有序 ID；覆盖空/重复/中英文、不同 top-k、同分、零及负余弦和非法 embedding，并运行现有纠错、合并、范围和来源变化调用链回归。
- 20 条候选、1000 条记忆目标：tokenize 与 sqrt 各 20020→1020；embedding 输入保持 1020。分离计数探针、重复计时与内存测量，报告中位数及有足够样本支持的 P95。若本机固定模型已预置，可用合成文本补真实本地编码前后对照；禁止下载或调用外部模型，不把假向量收益解释为整体提速。
- 按单例→相关模块→有界扩大验证；全量最长 600 秒。详细日志与基准原始数据留端侧临时目录，仓库只记录必要的合成聚合结果和可复现方法。
- 主会话独占实际桌面：先检查并复用 npm run dev；需要时正常退出原实例，使用最新 main 与独立合成资料验收导入/追踪，不使用业务库、不并发启动、不操作外部发送、不打包。
