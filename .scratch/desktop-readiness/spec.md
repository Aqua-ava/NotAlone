# 本机启动与自主验收

Type: task
State: resolved
Triage: ready-for-agent

## Problem Statement

用户希望 Agent 按仓库工作流操作本机、启动 NotAlone 并自主完成普通验证；仅在真实身份、私人资料外发或重要范围决定无法确定时请求用户参与。完成标准是可复核的运行结果。

## Solution

使用现有原生 App、标准本地后端及 PostgreSQL 接缝完成验收。业务环境只检查启动状态和结构元数据；独立新建随机 `_test` 数据库，应用全部现有迁移，使用明确标记的合成用户、联系人与消息验证导入、记忆、候选、依据及删除。真实模型仅接收本次合成材料并使用现有已配置的供应商；验证后恢复普通 App 运行。

## Implementation Decisions

- 保留既有业务库、共享测试库、项目配置及微信绑定，不接管无迁移账本的旧库。
- 真实微信适配器在隔离验收进程中设为不可执行路径；不开启新联系人的正文读取，不发送外部聊天消息。
- 普通测试发现的确定性缺陷在原有公开接缝修复；不为验收新增产品能力或扩大架构。
- 原生启动遇到连续 SIGABRT 后，将既有后端重启缺陷纳入阻塞修复：沿用 `BackendSupervisor.launch` / `terminate` 公开接缝，用合成后端验证每轮独立进程和旧回调隔离；重建过期的签名 App 后再次实机验收。
- 重建发现脚本漏编译两个新增视图；打包收集两个既有 Swift 目标的全部源文件并使用 Swift 6，验证实际 `.app` 构建。
- 新 owner 首次历史导入遇到 `OwnerChannelIdentityNotFoundError`：App 确认导入沿用既有事务安全建立首次渠道身份；已有/撤销身份与跨 owner 冲突仍拒绝，保留 CLI 显式初始化语义。通过原有 HTTP/导入公开接缝回归验证，不新增数据表。
- 全量测试的握手夹具清理顺序误删默认文件，导致 App 在隔离后端仍存活时启动普通后端；清理先作用于夹具路径，再恢复环境。用随机临时外层握手哨兵验证修复前被删、修复后内容完整，后续 HTTP 写入仍核验隔离 PID。
- 实机显示发现置信度 1.0 被标为 1%，将两处记忆置信度展示转换为百分比。编辑后的候选继续生成此前忽略编辑正文；沿用 `rewrite_draft` 接口将当前编辑正文作为本次草稿，并保留显式历史候选关联，不覆盖原始候选快照。
- 运行过程中的凭据和握手 token 仅在受控临时文件或进程内使用，记录只保存状态、计数及合成资料。

## Testing Decisions

- 沿用既有 `MemoryAdoption` / `MemoryPort` 测试接缝、后端 HTTP 契约、PostgreSQL 集成测试及 Swift 核心测试，不新增接缝。
- 初次全量：Python 989 项，1 失败、5 错误、3 跳过；App 19 项和探针 21 项通过。
- 最小复现：记忆采纳 7 项中 3 个 IndexError，夹具失效日期写死为 2026-10-01；来源删除 15 项中 1 失败、2 错误，旧测试库未具备迁移 036 的约束。
- 修正日期夹具后先运行原模块；再在新建且迁移完整的隔离库运行 Python 全量，明确跳过真实模型专用测试的原因。
- 使用真实原生 UI 验证消息展示、导入预览/确认、手工记忆管理、候选生成/编辑/依据和来源删除；用最小合成输入检查现有模型服务路径。
- 删除、范围隔离、关闭同步停读及恢复语义以现有公开行为测试验证；真实微信新增消息延迟若缺少用户发送的新测试消息，明确记录未验证。

## Out of Scope

无迁移账本业务库升级、正式部署、远端 Git、未确认真实联系人、私人聊天导入或外发、微信发送、关系分析、新权限、新自动化和新回复策略。

## Answer

本轮完成原生 App 启动、阻塞修复及合成数据闭环验收，已恢复普通运行环境。两个独立子评审分别检查 Standards / Spec，含最后的界面及握手夹具补评，均无可操作问题。

- 原生界面分别预览、确认并导入甲 3 条、乙 2 条消息；来往说话人与消息内容对应，切换联系人时资料隔离。

### 数据影响与剩余风险

代码修复不增加权限、发送能力或数据表。导入、记忆、回复和删除验收写入独立合成测试库；项目 `.env`、原有业务绑定和既有数据库结构未修改。普通环境恢复后继续采用已有的确认同步范围。临时凭据未进入仓库，本次文件按主题创建本地提交，不推送远端。

原业务库及原共享测试库没有迁移账本，且缺少迁移 036 所需的来源删除任务约束；不得据新隔离库通过而宣称旧库已升级或删除可用。普通环境补齐元数据有 50 项 `failed / cli_command_failed`（恢复运行时更新）和 65 项既有 `paused`，全局流在线不等于全部历史已补齐。此稳定错误码仅证明一次性 CLI 子进程非零退出，不能从聚合元数据确定权限、运行库或会话根因；本轮没有修改同步、CLI 或补齐代码，也未通过重试改变暂停范围。真实微信新增消息延迟、权限持久性及候选语义质量全面评测未在本轮完成；后续需要独立处理旧库基线与补齐失败，保持人工发送边界。
