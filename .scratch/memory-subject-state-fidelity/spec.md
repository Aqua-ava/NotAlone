# 主体与事实状态保真第一轮

## Problem Statement

用户已确认持续修改、自动验证、最后用原文与记忆对照验收。前轮复刻没有减少错误自动采纳：逐字证据存在仍会放过主体错位、已发生事实改成未来计划。需要修复现有生产提取与来源核验，而不是继续叠加外部平台。

## Solution

先用保留的合成首次输出复现错误，固定候选比较修改前后来源核验，再以新合成案例检查回退。首版逐维度结构化核验实测出现回退，保留实验源码快照与首次结果但不接生产；最终采用更小的提取与核验提示词修正。原文仍是权威依据，核验不能修改主张。真实聊天只在本机按既有确认范围作只读验收对照。

## User Stories

1. 作为用户，我希望单方经历不被记成另一方或双方的经历。
2. 作为用户，我希望已发生、当前状态、计划和转述不被互相替换。
3. 作为用户，我希望原文与记忆对照展示来源时间、判断理由和仍待解决的问题。
4. 作为用户，我希望每轮修复有固定失败证据和新的检查案例，正确记忆不会被全部拒掉。

## Implementation Decisions

- 保持既有提取、来源核验、Flow 和采纳公开 seam；用户已认可原文→记忆→去向的验收边界，不重复申请普通实现权限。
- 修复从现有提示词、模型 I/O 契约和只降不升的结果合并着手。每窗口仍至多一次有界来源核验调用；无新依赖、数据库字段、供应商或模型切换。
- 生产核验的模型协议、公共 SourceVerificationRuntime 结果与确定性证据契约保持不变；逐项核对正文、人物字段、语用和日期，明确主体错位及双向阶段反转均无支持。正文忠实而语用标签不对沿原 uncertain/pragmatics 规则。首版四维结构方案仅作为失败的实验比较，不加入默认调用。
- 提取端明确双向状态保真与省略回答的人物/物品归属，不按具体用例特判。sender 不是 subject 的硬判据；第三方关系资料仍保留第三方和转述。
- 核验输入去除候选置信度、风险、备选解释及理由，保留需要核对的正文、人物、来源与语用日期字段，降低候选自述对独立核验的影响。不落库、不保存模型内部思考。
- 使用已配置模型只处理合成消息；真实数据不外发、不重提取、不改写旧记忆。验收报告保存在仓库外私有目录，展示的是来源与现有记忆的本地语义复核。

## Testing Decisions

- 在既有 LangChainSourceVerificationRuntime.verify 与 ExtractionFlow.run seam 保留真实模型 red→green：同一错误候选修改前放行、修改后拒绝或降级；普通结构/来源/失败接口回归不变。只读合成固定重放与可控模型边界测试分别证明语义效果及输入契约，不以 fake unsupported 自证模型准确。
- 第一自然失败与结构输出均保留，不补抽覆盖。固定候选实验隔离核验变化；新案例及其答案在模型调用前冻结并独立检查，包含正确对照，报告误拒、错误放行、失败和成本。
- 第二组新案例未参与提示词调整；第一组在实测回退后作为开发材料，旧留出已经看过也作为回归材料，不再称新留出。完整提取效果与固定候选核验效果分别报告，不能把后者当真实聊天提取准确率。
- 最后执行相关单元测试、类型检查、完整 Python 测试和 Standards／Spec 两轴评审。本地提交，不 push。

## Out of Scope

批量修正已有记忆、真实数据模型评测、自动提高采纳范围、外部聊天发送、部署、同步权限或绑定变更、叙事复刻成为默认流程、UI 改版。

## Further Notes

按 grill-with-docs 核对的决策均已由用户确认目标及既有约束收敛；沿用领域术语，无需新 ADR。范围为一个完整修复 ticket，不新增需另行确认的多任务拆分。
