# 持续会话与上下文管理：测试接缝与六票提案

日期：2026-10-11。阶段：用户已确认测试接缝与六票拆分，现已发布[正式规格](spec.md)及[六张独立任务](planning.md)。本文保留提案与代码核验来源，执行范围以正式规格和原票为准。

## 范围与来源

产品行为以[原草图](../../architecture/drafts/assistant-session-context.md)为准。本提案覆盖持续讨论、候选版本、恢复、删除、新消息、并发及预算；不改变 OCR，不加入自动发送、经验提炼、自动摘要、云端部署或运行时迁移。上一会话临时要求不随候选自动带入，额外“携带要求”功能留待另议。

## 已核验的现有接缝

- [桌面回复控制器](../../desktop/src/main/reply/session.ts)已有联系人校验、消息提醒、候选选择/编辑及取消；当前回复状态保存在主进程内存，切换联系人会取消请求并清空当前结果。因此持久会话和跨会话继续生成是待实现行为。
- [回复应用入口](../../backend/src/notalone/application/reply_service.py)先验证绑定和范围，再调用生成端口；[PostgreSQL 回复集成测试](../../backend/tests/integration/reply/test_postgres_reply_flow.py)已经使用合成模型验证实际存储链路，可复用这种边界。
- [来源清理](../../backend/src/notalone/persistence/reply_cleanup.py)已递归清理依赖候选的后继请求，撤销受影响运行中请求的租约。新增讨论、修改记录、恢复副本必须接入同一删除语义，不能只删候选表。
- [页面验证入口](../../desktop/scripts/test-pages.mjs)与[改写场景](../../desktop/tests/rewrite-page-scenarios.ts)可用于用户操作链路；受控页面不能替代真实 App 的关闭/退出验证。
- [会话实验](../dsh-session-probe/report.md)是框架实验，不能证明产品已实现恢复和删除；沿用现有运行时，不引入 DSH。

## 推荐测试接缝（已确认）

主接缝采用桌面已有公开操作到后端 HTTP、隔离 PostgreSQL 的完整路径：用户创建/选择助手会话、提交要求、选择/编辑候选、删除、重新连接，然后核对可见结果和恢复结果。真实业务存储与控制器运行，只替换模型和消息到达输入为可控合成适配器；不读真实微信、不调用外部模型。

后端应用入口用于系统化验证 owner/contact 越权、幂等、取消与来源删除竞态。模型适配器可控制迟到、失败和调用次数；断言公开结果及是否发起调用，不依赖内部函数调用顺序或数据库表布局。

最终以一次另行约定的有限真实 App 窗口验证小窗关闭、应用退出及重开；使用合成联系人和模型。自动测试可以先完成，不能用页面结果替代原生生命周期验收，也不因此恢复 OCR 验收。

## 推荐实现边界（已确认）

- 在既有回复应用边界增加助手会话的创建、列表、读取、删除及提交操作；会话属于 owner/contact，窗口只显示所选会话。每次读取、生成、恢复、携候选均重新核验范围与来源状态。
- 产品存储保存讨论、请求、候选版本、选择/修改/纠正关系和来源依赖。沿用 PostgreSQL 业务存储，不以框架 checkpoint 作为权威记录；不要求模型拥有跨请求隐式记忆。
- 每次生成引用确定的助手会话、输入版本及既有幂等请求身份。应用层使旧生成失效，后端提交同样拒绝失效结果，不能只在 UI 隐藏。
- 当前会话讨论与本次已确认表达方向分开处理；新要求覆盖不兼容旧要求，兼容要求保留，含糊指代先澄清。编号以当前显示的候选组解析到明确候选 ID，再检查归属；不按时间猜测历史候选。
- 使用痕迹不是关系记忆或发送证据。所有派生内容保留实际使用的上下文依赖；删除来源时传递清理后续派生内容及可恢复副本，无关讨论保留。删除一段助手会话不连带删除独立微信来源和关系记忆。
- 每次提交按实际模型输入上限与输出预留计算预算；历史讨论不静默截断、不自动压缩。既有检索/工具预算仍受限制，本功能不扩大外发授权。

## 现行架构衔接

[核心流程](../../architecture/current/core-flows.md)的“持续聊天与滑动上下文”和 [ADR-009 第 4 节](../../architecture/adr/009-langchain-create-agent-bounded-reply-loop.md)允许压缩较早运行消息。若用于本次持续助手讨论，会与已确认 Q2/Q17 冲突；重新讨论的原因是用户明确要求第一版保留讨论、到上限新开，不自动摘要。

正式规格阶段须明确助手讨论与单次 Agent Tool 运行消息的边界，并通过 ADR 修订有冲突的适用范围；不能静默覆盖已采纳 ADR，也不能把现有工具消息中间件一并删除。该衔接现已通过 [ADR-042](../../architecture/adr/042-assistant-session-context-boundary.md)完成；实现与验证尚未进行。

## 逐票提案

### 01：创建、恢复和删除一段助手会话

**Blocked by：无。**

交付：为已确认联系人创建助手会话，提交一次回复请求，保存讨论及候选；重新连接后可查看，主动删除后无法恢复。

验收：跨 owner/contact 读取和提交拒绝；恢复不自动生成；同键重试不重复；来源删除清理这一轮及恢复副本并显示占位，无关内容保留。删除/失效竞态从第一票就覆盖，不留到最终验收补安全。

### 02：连续修改、明确指代和候选版本

**Blocked by：01。**

交付：“第二条自然一点”等明确要求可延续当前讨论；新版为主、旧版可展开和重新选择；保存选择、修改前后及纠正关系。

验收：指代歧义先澄清，不能跨会话猜测；新意图覆盖冲突旧要求、保留兼容要求；重开仍有版本记录；来源删除能清理派生版本；痕迹不变成关系事实或已发送状态。

### 03：生成中新要求和新消息的处理

**Blocked by：02。**

交付：用户提交修改要求会使旧生成失效；外部新消息只提示并保留当前生成/编辑，点击“结合新消息继续”才重新生成。

验收：可控迟到旧结果不能覆盖新结果或重新落成有效候选；新消息不自动调用模型；新消息提示绑定正确会话；重试不产生重复候选；来源删除与正在生成相遇时不恢复已删除内容。

### 04：会话列表、切换及应用生命周期

**Blocked by：03。**

交付：同一联系人可新开、选择旧会话；切换联系人或会话、关闭小窗时，原生成继续且只回到所属会话；彻底退出停止，重开显示中断并等待手动重试。

验收：新开/切换不自动生成；A 返回不覆盖 B；已完成结果不会被误标中断；退出前的迟到结果不能复活旧请求；新会话不自动继承候选或临时要求。模拟生命周期先验证，最终原生验证在 06。

### 05：长度预算与显式携候选新开

**Blocked by：04。**

交付：接近预算提示，硬上限阻止生成但保留查看；支持全新开始或携明确选中候选新开。

验收：计入系统、讨论、检索/工具及输出预留；上下限边界可重复测试；超限不调用模型；只带选中候选，不携整段讨论或临时要求；候选及其来源失效时不能带入；不使用摘要绕过限制。

### 06：完整合成回归与真实 App 生命周期验收

**Blocked by：05。**

交付：把已完成行为组合验收，记录每条结果、未通过项和剩余风险，回写对应票与总览。

验收：双联系人、多会话、长讨论、版本修改、新消息/取消竞态、断开恢复和来源删除的组合路径通过；有限真实 App 窗口验证关闭/退出/重开。没有真实 App 证据时保留该验收未完成，不能以合成回归宣称全部完成。

## 为什么本功能按顺序推进

01 → 02 → 03 → 04 → 05 → 06。版本引用依赖持久会话；新消息替换依赖连续修改；跨会话任务归属依赖失效规则；携候选新开依赖会话切换入口。当前共同修改回复控制器，硬拆并行会引入额外接口协调，不建议为并行而拆层。

其他草图的问题整理、Mac 交付来源核查、记忆评测的离线准备可以并行；不因此启动额外 Agent、真实微信操作或模型评测。本功能暂不新增任何其他任务的前置阻塞。
