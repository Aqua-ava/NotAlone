# 持续会话与上下文管理

Triage: ready-for-agent

规格状态：已确认并发布；功能尚未实现。
确认日期：2026-10-11。用户已确认 Q1–Q18、公开测试接缝及六票粒度/依赖。

## Problem Statement（用户问题）

用户围绕一位联系人反复讨论和修改回复时，不应每次重新解释要求，也不应因切换窗口、关闭应用或新消息到达而丢失编辑。当前桌面回复状态主要在内存中，不能提供可靠的多轮记录、版本回看和跨启动恢复；只保留最后候选也无法还原用户选择与纠正过程。

## Solution（解决方案）

为已确认联系人提供持续助手会话，默认继续当前讨论，允许明确新开与选择旧会话。讨论、生成候选及修改痕迹保存到用户删除；新消息先提示、由用户决定是否结合。请求取消、窗口切换和来源删除均保持结果归属与恢复安全。第一版不摘要，到长度上限显式新开，可只带选中的候选。

## User Stories（用户故事）

1. 作为用户，我希望继续同一联系人的讨论，以便发送后或对方回复后无需重新交代语境。（Q1）
2. 作为用户，我希望默认继续当前会话、不按空闲时长自动重开，以便跨日继续。（Q2）
3. 作为用户，我希望提前看到长度提醒并在硬上限时新开，以免早期要求被静默丢弃。（Q2、Q17）
4. 作为用户，我希望选择全新开始或只带明确选中的候选，以便控制新会话的输入。（Q3）
5. 作为用户，我希望关闭后恢复原讨论及候选，并由我决定何时生成，以免产生意外调用。（Q4）
6. 作为用户，我希望按联系人查看、选择旧会话，以便继续尚未达到上限的讨论。（Q5）
7. 作为用户，我希望新消息到达时保留当前编辑，由我决定是否结合，以免修改被覆盖。（Q6）
8. 作为用户，我希望改口后采用最新明确意愿、保留兼容要求，并对含糊要求澄清，以免继续执行旧意图。（Q7）
9. 作为用户，我希望“第二条”等明确编号对应当前会话最近展示的一组候选，歧义时让我选择，以免改错对象。（Q8）
10. 作为用户，我希望生成中提交新要求可以替换旧生成，迟到旧结果不能覆盖新结果。（Q9）
11. 作为用户，我希望会话保留到主动删除，并能独立删除一段助手会话，以便控制留存而不误删微信资料。（Q10）
12. 作为用户，我希望保存候选、实际选择、修改前后及纠正的关系，以便回看过程，而不把这些当作关系事实。（Q11）
13. 作为用户，我希望以新版候选为主、展开查看修改记录并可选旧版，以便找回更合适的表达。（Q12）
14. 作为用户，我希望切换联系人时原生成继续且只回到原会话，以便处理不同联系人而不串线。（Q13）
15. 作为用户，我希望同一联系人下新开或切换会话不取消原生成，也不自动触发新生成。（Q14）
16. 作为用户，我希望关闭小窗时继续生成、彻底退出时停止，重开看到中断并手动重试，以便理解执行状态。（Q15）
17. 作为用户，我希望生成中收到新消息时看到“尚未结合新消息”，点击继续后才取消旧生成并结合新内容。（Q16）
18. 作为用户，我希望达到上限的历史仍可查看，并可全新开始或携候选新开，以免失去原讨论。（Q17）
19. 作为用户，我希望来源删除后清除依赖内容并显示无正文占位，保留无关讨论，且恢复不能带回被删内容。（Q18）
20. 作为用户，我希望所有操作始终限于已确认联系人，候选只供我选择、修改和亲自发送，以免误用其他关系资料。（全局边界）

## Implementation Decisions（实现决定）

### 会话、记录和范围

- 助手会话独立于微信会话、窗口和单次回复任务，具有稳定身份并属于 owner/contact。新开、列表、读取、提交、删除、恢复和携候选均通过既有回复应用边界验证范围与来源状态；昵称不能代替身份。
- 沿用 PostgreSQL 业务存储及现有有界回复运行时；讨论、请求、候选版本、实际选择、修改前后、纠正关系和来源依赖是产品记录，不依赖框架隐式记忆或 checkpoint 恢复。
- 默认继续该联系人的当前会话；新会话不删除旧会话，不自动继承其他会话候选或临时要求。新开、选择、恢复均不触发生成。授权失效不能借已有会话绕过生成门禁。
- 记录持久化失败必须显式报告，不能把未可靠保存的结果宣称为可恢复。历史单次请求不凭时间或昵称推断归并成助手会话；旧功能兼容路径保留，必要 schema 变更用项目迁移机制，真实资料迁移不在本任务授权内。

### 连续意图和候选版本

- 当前讨论保留用户历史要求；每次提交以最新明确意图覆盖冲突要求，保留兼容要求，无法确定时澄清。生成输入仍是本次表达方向，不把会话要求升格为长期偏好。
- 明确编号解析到当前助手会话最近展示候选组的具体候选 ID；缺项或歧义要求用户确认。不能按最新生成时间、复制动作或发送观察自动选历史候选。
- 新版为主要展示，旧版及对应修改要求可展开并重新选择。候选及选择/修改痕迹不作为实际发送或已确认关系事实。

### 并发、消息与生命周期

- 每次生成绑定助手会话、输入版本和既有幂等请求身份。同键同输入复用，输入改变需要新请求；继承既有冲突和失败重试语义，不重复写入候选。
- 用户提交新要求使旧生成失效并重新生成；应用层取消与后端有效性检查共同阻止迟到结果重新落成有效候选。取消不承诺供应商停止计算或计费。
- 已授权新消息到达只提示，保留生成和编辑，标记尚未结合新消息；用户“结合新消息继续”才捕获新的有效输入并替换旧生成。提示/结果始终归属原联系人和助手会话，不扩大同步授权。
- 切换联系人、切换/新开助手会话或关闭回复小窗不取消原生成；结果只保存在原会话，不覆盖当前界面。真正退出应用停止运行中任务，重开将未完成任务显示为“上次生成中断”，只有用户重试才继续。已可靠保存的完成结果保持完成。
- 完成、取消、退出和删除的竞争必须由有效请求身份及提交检查裁定；旧进程或迟到响应不得复活已失效结果。

### 留存、来源和删除

- 会话记录默认保留到用户主动删除；删除助手会话清除其讨论和使用痕迹及可恢复副本，但不连带删除独立微信来源或关系记忆。
- 来源依赖覆盖实际使用的全部上下文及候选延续关系，不能只看直接引用。来源删除清理传递依赖的讨论、候选、修改记录、输入快照及恢复副本；同一来源影响多个会话时全部处理。
- 保留无关讨论，受影响位置显示“相关来源已删除”，占位不得含可恢复正文。删除期间阻止旧上下文提交；失败可重试，完成必须验证不可再检索/恢复。联系人删除沿用既有范围并覆盖新增记录。
- 显式携候选新开也保留其来源依赖；新会话不是绕过删除的副本。删除单段会话不扩大为删除其他会话，但不能留下可恢复已删内容的隐藏副本；实际携入的候选继续受原始资料来源删除约束。
- 敏感正文不进入普通日志或最小出站台账；本地清除不代表供应商已清除外部副本。

### 输入预算

- 按实际配置模型验证输入能力、计量方式、提醒阈值和输出预留，不在规格写死未经验证的数字。预算包括系统指令、讨论、检索、Skill/工具及输出预留，初次调用和后续有界调用都不能越界。
- 接近上限温和提醒，仍可在预算内继续；无法容纳时拒绝提交超限调用，但保留历史查看与新开入口。既有检索/工具材料预算仍有效，不静默截断助手讨论。
- 第一版不自动摘要或压缩助手讨论。只携用户明确选中的候选，不复制整段讨论或临时要求；候选/来源失效时拒绝携入。额外显式携带要求不在本轮。
- ADR-042 局部修订 ADR-009 的适用范围：单次 Agent 内部运行消息机制保留，不得用它压缩持续助手讨论来绕过上限。需验证中间件不会损失会话要求；不迁移运行时框架。

## Testing Decisions（测试决定）

用户已确认主接缝为桌面公开操作 → 后端 HTTP → 隔离 PostgreSQL，使用真实业务控制器与存储，只替换模型和消息到达输入为可控合成适配器。观察用户可见结果、恢复结果及模型调用次数，不绑定表布局或内部调用顺序。

- 基于现有回复 PG 集成和页面场景，覆盖创建→生成→断开/重连→恢复→删除路径。系统化 owner/contact 越权和幂等在后端应用入口验证。
- 可控模型覆盖失败、延迟、取消后返回；同时测试提交新要求、新消息、切换、来源删除和退出，不以仅 UI 忽略结果代替后端失效验证。
- 验证独立来源与多来源依赖、后继候选、修改记录、携候选新开的传递删除；删除后重新读取、恢复及生成均不能获得已删正文，无关内容仍存在。
- 每票新增数据路径都执行范围、来源及恢复检查；01 即纳入基本删除与竞态，后续票扩展对应新路径。边界预算用可控模型配置验证临界值，不用不稳定真实模型结果做确定性断言。
- 合成测试证明编排行为，不证明自然语言语义质量或真实模型质量。意图改口和含糊指代至少验证明确场景及澄清去向；真实模型评测若需扩展，另定数据范围和预算。
- 受控普通页面可按项目 test:pages 验证；最终另约有限真实 App 窗口，以合成联系人/模型验证小窗关闭、退出及重开。页面测试不能替代原生生命周期，不恢复 OCR。
- 无真实微信读取、无外部发送、无外部模型调用；不把文档、合成结果或旧包验证描述为完整原生交付。

## Out of Scope（排除项）

自动发送、主动读未授权联系人、OCR 调整、微信媒体提取、经验提炼/自进化、自动摘要、跨会话自动继承临时要求、DSH 或框架迁移、云端部署、多设备同步、真实资料迁移、未约定的模型评测及其他草图实现。
