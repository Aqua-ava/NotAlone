# 当前联系人优先同步与延迟修复

## 已确认范围

用户批准先前方案并要求开始实现：接通当前联系人优先读取、后台单执行器按会话分片、单次 CLI 有界超时、分阶段计时及真实桌面复验。

- 当前联系人只从 main 的有效联系人会话取得，沿用已有确认绑定和同步总开关。
- 选中、可靠自动切换及后端重连后协调优先目标；切回微信或输入小窗失焦不清除目标。
- 优先请求串行合并为最新值，旧连接和迟到响应不得复活旧范围。
- 优先请求快速登记并唤醒后台，不等待一轮至多 32 位联系人的任务。
- 一个执行器每完成一个绑定任务后重新调度，后台仍公平前进；有待处理任务时不额外每片等待三秒。
- 每个切片的 tail 及必要 version 命令共享三秒绝对截止时间，超时保持可靠游标与补齐状态，不采纳部分输出；不修改 has_more 完整性契约。
- 关闭同步、解绑和退出仍停读，不引入并行 cursor 写入或产品发送能力。

## 已认可测试 Seam

1. 生产联系人会话、后台连接及同步控制器，通过认证 HTTP 验证优先请求、A→B 串行、重连与关闭。
2. 公开 SyncHost/同步引擎，用可控慢 CLI 与合成时钟验证快速登记、单片让出、公平性和停读。
3. CLI 适配器执行合成子进程，验证真实超时、回收、拒绝部分结果及默认调用兼容。
4. 公开状态 HTTP、桌面状态控制器与页面，验证时间指标、自动只读更新和联系人范围一致。
5. 正式持久化合成夹具验证可靠 cursor、去重、范围隔离和补齐生命周期；不查询真实正文作为测试夹具。

上述测试沿用用户已批准方案的验证范围；先 RED 再 GREEN，不以私有字段或源码字符串断言代替行为。

## 计时合同

状态报告新增可空的 `cli_priority_*` 字段：`contact_id`、`last_success_at`、`last_duration_ms`、`last_cli_duration_ms`、`last_store_duration_ms`、`last_failure_code`、`queue_wait_ms`。

只提供当前有效优先绑定的身份与耗时，不含昵称、正文、凭据或视觉帧。无法实际测出的指标保持 null；切换范围后不显示旧联系人的指标。

## 验收

- 大量授权会话且一个后台任务缓慢时，当前联系人不再等待整轮任务；没有重叠 CLI 读取或跨联系人写入。
- 桌面状态自动更新；最近成功读取时间与读取失败明确可见，不将连接成功等同消息追平。
- 建议性能目标为正常环境发送至入库 P95 不超过十秒、入库至列表不超过一秒；必须记录实际样本量和最长值，不把三秒检查节奏当作 SLA。
- 真实桌面只复用 `npm run dev`；新发测试消息必须另有明确对象与内容授权，既有一次发送许可已经使用，不重用。
- 记录实际命令、RED/GREEN、桌面结果、数据影响、清理与局限；完成规范/需求双轴审查后仅提交本任务变更，不推送。
