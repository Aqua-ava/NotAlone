# 08 — 菜单栏驱动前台同步与状态展示

Type: task
Triage: ready-for-agent
State: resolved
Blocked by: 07

## What to build

把 07 的端到端接线挂进 `NotAloneSyncProbe` 菜单栏应用：App 周期性调用
`notalone-front-sync status` 循环，在状态栏持续显示同步开关、阶段、当前
联系人与异常原因；菜单提供开启/关闭同步与一次性绑定确认入口（候选 ->
联系人两级选择）。屏幕录制权限只需授予 App 自身，探针作为 App 的子进程运行。

## Acceptance criteria

- [x] 状态栏持续显示：同步开关、阶段、当前联系人 display name、本轮入库计数。
- [x] 待确认绑定时菜单展示候选与联系人选择，确认后下一轮自动进入活跃。
- [x] 微信非前台、CLI/探针不可用时状态栏显示稳定原因，不写入消息。
- [x] 菜单栏与菜单内容不出现消息正文或选中行预览原文。
- [x] 经授权的真实微信冒烟全程经菜单栏完成：绑定、真实消息入库、失败自愈。

## Verification

- 状态输出与联系人列表的解析器有合成单元测试。
- 真实微信冒烟全程经菜单栏完成：开启、确认、入库计数、离开/恢复、关闭。

## Out of scope

- 不做完整产品 UI、常驻守护或自动发送；OCR 聊天区观察保持探针原有行为。

## Answer

已完成菜单栏驱动的前台同步，并经真实微信冒烟验证：

1、Core 新增 `FrontSyncStatusReport`/`FrontSyncContactEntry` 解析器（解析 status/contacts
的 key=value 输出，候选 display 允许空格与表情符号，必备字段缺失失败关闭），5 个合成单测。
2、菜单栏 App 每 3 秒调用 `notalone-front-sync status`（探针作为子进程，屏幕权限归于
App），状态栏显示开关/阶段/联系人/本轮计数/失败原因（不可定位时带具体原因）；菜单提供
开关与候选→联系人两级绑定确认，操作结果与失败原因直接显示在菜单；确认/开关期间暂停
后台循环，避免两个探针互抢屏幕资源。
3、冒烟发现并修复两个真实缺陷：① OCR 把标题表情符号读变形（`FSM💕cxk`→`FSM~cxk`）
导致 `resolve-chat` 落空——匹配器新增最近会话回退：已绑定会话自动认出，未绑定转一次性
选择，回退路径中证据矛盾只收窄不清空（该证据同样来自 OCR）；6 个单测 + 1 个端到端测试。
② dev 库漏应用迁移 021（message 旧结构拒绝无导入来源的观察消息）导致入库失败，已在
dev 补迁移；App 在失败退避后自动重试恢复，41 条真实消息经 CLI 规范化入库，水位推进。
4、构建改用本机稳定签名证书（无证书时回退 ad-hoc）：屏幕录制授权按签名身份记忆，
重建不再要求重新授权；构建脚本打印当前签名身份。

验证结果：

- `swift test` 21/21；`python -m unittest discover -s tests -q` 全部通过（2 跳过）；
  `compileall` 通过。
- 真实冒烟（用户授权并手动操作微信，全程经菜单栏）：绑定确认成功、同步活跃、
  41 条真实消息入库（DB 计数独立核验）、失败自愈；日志只含计数/状态/字段。
- 终端冒烟向导保留在 `.scratch/local-wechat-cli-observation/smoke/wizard-smoke-front-sync.sh`。

剩余风险：

- OCR 观察名可能随帧波动（如 `FSM~cxk < •••`）；观察名与绑定保存名不一致时会回到
一次性确认路径，不会误写，但可能再次要求用户确认。
- App 的 1 秒 OCR 观察循环与 3 秒同步循环共享截屏资源，密集操作时探针可能偏慢；
未做常驻守护，退出 App 即停止同步。
