# 三路并行性能优化
Triage: ready-for-agent
State: open

## Problem Statement
合并后的主分支仍存在后台模型许可占用过长、回复依据反复全量读取，以及输入时完整会话状态反复传输。用户明确授权三个会话并行实现，并由主会话统筹、合并与验证。

## Solution
保持现有产品行为，通过更细的模型调度、范围内批量复验和桌面增量更新降低等待与重复工作。三路独立工作树从同一最新 main 起点执行，最后集成到本地 main，不 push。

## User Stories
1. 用户发起回复时，后台退避或两次物理请求之间能让前台优先执行。
2. 已经开始的物理请求完成或明确结算前不释放其许可，不把调用方超时冒充实际取消。
3. 用户关闭应用或来源失效后，等待与后续重试及时停止，不再发送新请求。
4. 回复依据少时，读取规模随依据数量变化，而不是重复读取联系人全部记忆。
5. 删除、纠错、授权、有效期或版本变化后，旧依据仍不能生成或恢复。
6. 长会话输入保持流畅，生成和联系人切换使用最新输入，迟到事件不能串联系人。
7. Skill 页面慢请求能够完成，空闲和隐藏时减少刷新，审核发布仍做权威复验。

## Implementation Decisions
- 模型调度：许可按每次物理模型请求持有，保留单次外部请求互斥、前台优先、绝对期限、逐请求台账及核验额度；退避使用可中断等待，不增加模型调用、重试或工具预算。
- 回复检索：按用户/联系人、证据类型及明确 ID 集合读取；同一发送边界只保留必要复验，不合并不同时点的检查。不用正文缓存绕过权威来源、修订和删除检查，不新增连接池或数据库迁移。
- 桌面交互：输入轻量状态与大段历史减少重复复制/传输，按窗口和修订避免无效更新；兼容既有恢复、删除、候选编辑与生成合同。Skill 刷新单轮在途、结算后调度，隐藏暂停、恢复立即刷新；写操作不得自动重放。
- 三路文件所有权分别为模型运行时、回复上下文与检索仓储、desktop 展示/IPC/控制器；跨范围先向主会话报告，由主会话协调。
- 工程基准为代码提交 f17f099a，启动前最新 main 为 1db93d20；三路统一从包含本规格的 main 规划提交派生。原工作区架构图删除保持原状。
- 来源、owner_id+contact_id、人工保护、完整追踪、逐项隔离及用户手动发送边界不变。

## Testing Decisions
- 模型调度：使用公开优先级协调与正式运行时/HTTP 装配，外部模型和时钟作为可控边界；验证慢调用、退避、轮间交接、停止、来源撤销、迟到结果及台账。
- 回复检索：使用公开上下文/检索接口及随机隔离 PostgreSQL 测试库，固定合成依据对比内容、排序、引用、来源与失效结果；用查询/取回行数证明减少读取，不只测内部方法调用次数。
- 桌面：使用公开控制器、IPC 与真实 React 页面，覆盖输入后立即生成、跨联系人恢复、迟到/删除、慢 GET、隐藏/恢复及写操作失败；记录合成历史规模下 IPC 字节、快照次数和输入延迟。
- 先红测单切片，再相关模块；全量给 600 秒上限。真实桌面由主会话独占，先核验并复用 npm run dev，不打包、不并发启动其他 App 实例、不发送外部消息。
- 每项报告同一合成负载的前后证据；没有实机测量不得宣称用户可感知加速比。

## Out of Scope
导入追踪批写、本机 embedding 缓存、持久调度索引/轮询重构、连接池、原生像素处理、模型/供应商或提示词策略更换、真实聊天重建、业务库迁移、发布与远端操作。

## Further Notes
用户已认可三项拆分并明确授权执行，三项均可立即开始；集成验证依赖三项完成。旧模型协议夹具、未知无头租约及历史公开检查命中是既有基线，须先对照再归因，不能降低新行为断言来让测试通过。
