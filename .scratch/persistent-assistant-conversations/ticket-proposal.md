# 持久助手会话任务拆分草案

Triage: ready-for-agent
State: open

状态：用户已确认，七张独立任务已发布，执行入口见[任务索引](planning.md)。依据 [正式规格](spec.md)及 [ADR-106](../../architecture/adr/106-persistent-assistant-conversations.md)。

## 共同交付要求

- 每票交付一段可演示、可从公开入口验证的完整行为；不按数据库、服务、界面等横向分层拆票。
- 各票通过真实宿主、隔离数据库、官方 DSH 与本机合成供应商验收，按需贯穿生产桌面控制器。来源和删除能力完成前，仅在隔离合成配置验证长期日志，不对正常用户启用未闭环能力。
- 业务模块保持来源、范围、预算、幂等与删除控制；实现遵守官方装配，不重写 DSH 核心。
- 开发及桌面验收只用热更新实例，不打包、不发微信、不推送远端；先最小红绿，再相关模块、类型检查与必要全量。
- 每票完成后按 Standards／Spec 双轴审查，按仓库规则只提交本票变更；进度不能用 SDK 方法调用或静态 UI 截图替代外部行为验证。

## 建议拆分与真实依赖

| 编号 | 标题 | Blocked by | 完整交付行为 |
| --- | --- | --- | --- |
| 01 | 连续生成与重启后恢复同一会话 | 无 | 经正常助手入口连续生成两轮，释放／重启宿主后明确继续仍有正确运行历史；稳定私有存档、可靠关联、基础会话清除和身份／配置守卫随路径交付。 |
| 02 | 历史回看与明确继续分离 | 01 | 小窗回看旧段不切当前、不续期；明确继续才恢复原段、设为当前并刷新活动；新开及候选版本携入保持可控。 |
| 03 | 十二小时空闲分段与提示 | 02 | 新任务受理前判断严格超过 12 小时，恰好新开一次并提示可回上一段；主动活动续期，被动事件不续期，在途任务不迁移。 |
| 04 | 最新背景与旧讨论按需接入 | 02 | 旧段继续使用当前有效资料并提示变化；既有 DB 历史首次继续才建立运行存档；配置、来源和 Skill 变化后安全更新或重建。 |
| 05 | 删除流程清除运行文件及恢复副本 | 01 | 从公开删除入口删除会话、来源或联系人，协调在途写者并清理相关存档、分叉、索引与副本；失败不报成功，重启与迟到回执不能复活。 |
| 06 | 中断、损坏和未提交结果安全恢复 | 04 | 正常退出、异常退出、缺失／损坏／不兼容日志及文件先成功 DB 后失败均按业务主记录恢复；未完成轮不自动生成、不伪装完成，保留用户输入与正确历史。 |
| 07 | 正常开发入口启用与整体行为验收 | 03、05、06 | 完整新流程在正常开发小窗可用；恢复后的真实消息预算、并发切换、输出契约和耗时完成端到端验证，形成实现与剩余风险记录。 |

01 提供集中运行管理和稳定身份边界，02 与 05 可在其后独立推进；02 完成后，03 与 04 可分别推进；06 使用 04 的有效资料修复能力。07 的其他前置条件由传递依赖保证，不重复列无实质阻塞的边。

## 已确认的测试接缝

1. 主接缝：真实产品宿主＋公开助手 API＋隔离 PG＋本机合成模型网络边界。跨两次真实启动保持同一业务目录，检查实际历史消息、业务记录和磁盘状态。
2. 桌面接缝：生产 Main/preload IPC、历史与当前会话投影、必要的渲染断言；最终复用正常开发小窗做实际操作。
3. 最小夹具扩展：领域时间控制、测试自有宿主异常退出、磁盘故障与删除屏障；不等待 12 小时，不在公开产品接口添加调试后门。

## 核对结果

用户已确认上述测试入口、七票粒度和阻塞边。独立任务均以 ready-for-agent、open 发布；以任务索引及各票为准，发布不表示已开始实现。
