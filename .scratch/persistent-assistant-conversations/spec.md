# 持久助手会话与空闲分段规格

Triage: ready-for-agent
State: open

状态：已发布，待实现。用户已确认测试接缝、七票粒度及阻塞关系；发布任务不表示已开始实现。

决定依据：[ADR-106](../../architecture/adr/106-persistent-assistant-conversations.md)。术语遵循 [CONTEXT](../../CONTEXT.md)。本规格综合已确认的产品决定，不重新访谈产品范围。

## 问题陈述（Problem Statement）

用户需要在同一联系人下持续讨论、修改和选择候选，关闭应用后仍可继续，也需要有用的历史讨论可回看、可明确恢复。当前每轮生成都建立临时 DSH 会话，依靠业务记录重建讨论，重复的资料准备与来源遍历造成延迟。既有去重修复只减少重复查询，尚未提供持久会话、空闲分段及其删除链。

## 方案（Solution）

一位联系人有一个当前助手会话及若干历史助手会话。连续讨论复用可持久化的 DSH 运行会话；空闲超过 12 小时后，下一次明确生成开启新会话，并提供回到上一段的入口。旧会话默认保留，回看不切换当前，明确继续才切换并刷新活跃时间。

数据库继续作为用户可见输入、候选、修改、选择和来源的主记录；本机 DSH 文件保存可恢复执行历史。正常续用不再每轮重建完整讨论，恢复、出站及保存仍校验身份、来源与业务提交。源资料变化后安全更新背景，真实删除覆盖相关运行文件及恢复副本。

## 用户故事（User Stories）

1. 作为用户，我希望同一联系人下连续生成复用同一段讨论，以便补充要求时保持语境。
2. 作为用户，我希望不同联系人互相隔离，以免资料或表达方向串入另一段关系。
3. 作为用户，我希望关闭应用后保留已完成讨论，以便重启后继续。
4. 作为用户，我希望宿主正常退出后恢复同一运行历史，以免每次重新组织全部内容。
5. 作为用户，我希望应用异常退出后仍能查看已经保存的候选，以免完成记录丢失。
6. 作为用户，我希望中断生成明确显示中断，以免重启时未经操作再次请求模型。
7. 作为用户，我希望跨午夜连续使用仍属于同一段讨论，以免按日历打断交流。
8. 作为用户，我希望空闲严格超过 12 小时后，下次生成自动新开，以便进入新的交流时段。
9. 作为用户，我希望空闲刚好 12 小时时仍按同一会话处理，以便边界可理解且可验证。
10. 作为用户，我希望自动新开时看到轻量提示及回到上一段的入口，以便需要时找回旧话题。
11. 作为用户，我希望主动生成、补充要求和修改候选刷新活跃时间，以便计时反映实际使用。
12. 作为用户，我希望后台同步、新微信消息、查看历史和打开应用不刷新计时，以免被动事件让旧段持续活跃。
13. 作为用户，我希望查看旧会话不改变当前会话，以便回看后仍能接着当前讨论。
14. 作为用户，我希望明确继续旧会话后将其设为当前并刷新活跃时间，以免立即又被自动新开。
15. 作为用户，我希望在历史会话修改候选时保留版本痕迹，以便不丢失原文，也不隐式切换当前会话。
16. 作为用户，我希望旧会话保留到主动删除，以便有价值的讨论长期可查。
17. 作为用户，我希望新会话默认只使用当前聊天和有效关系资料，以免旧助手要求被自动当作新要求。
18. 作为用户，我希望明确选择旧候选后才将它携入新段，以便引用范围和版本可控。
19. 作为用户，我希望继续旧会话时使用当前有效背景并提示变化，以免旧事实被当成现状。
20. 作为用户，我希望只作用于一次生成的要求不静默变成长期偏好，以便后续表达仍由我决定。
21. 作为用户，我希望原有历史讨论仍可查看，以免升级要求重导入或丢掉旧候选。
22. 作为用户，我希望首次明确继续某段旧讨论时才建立其运行存档，以免批量转换不需要的历史。
23. 作为用户，我希望读取、恢复和迁移历史本身不调用模型，以免后台产生额外生成与费用。
24. 作为用户，我希望修改或删除来源后，旧运行文件不能把不合格内容重新带入模型，以便删除与纠正有效。
25. 作为用户，我希望删除一段助手会话时清理其运行副本，同时保留独立合法的微信来源与记忆。
26. 作为用户，我希望删除联系人时清理该联系人的运行存档，以免跨重启复活内容。
27. 作为用户，我希望删除失败有明确状态并能重试，以免界面误报成功。
28. 作为用户，我希望恢复文件缺失、损坏或版本不兼容时保留可见历史，以免运行存档成为唯一可用副本。
29. 作为用户，我希望未成功提交的模型结果不能被恢复成已保存候选，以便状态可靠。
30. 作为用户，我希望重复点击和重试复用原任务身份，以免生成或保存两次。
31. 作为用户，我希望生成中切换联系人、回看历史或开启新段不迁走原任务，以便结果仍保存到原归属。
32. 作为用户，我希望同一运行会话不会被两个生成同时写入，以免历史损坏或结果串轮。
33. 作为用户，我希望接近输入预算得到提醒、达到硬上限后明确新开，以免历史被静默摘要或截断。
34. 作为用户，我希望生成的候选仍可编辑、选择并由我亲自发送，以便最终表达受我控制。
35. 作为用户，我希望能感受到内部准备减少，并能区分模型耗时与应用耗时，以便不把局部计时误当成总耗时。

## 实现决定（Implementation Decisions）

### 业务会话、当前指针与活动

- 沿用稳定业务会话身份，关联可恢复运行会话身份；产品会话与底层运行实例不是同一个生命周期。重建运行实例不改变原讨论身份。
- 沿用每位联系人唯一当前会话约束，扩展可靠的用户活动元数据；不能用被后台处理更新的通用更新时间代表用户活跃。
- 空闲由后端权威时间与持久化的最后主动活动时间计算，严格大于 12 小时才触发。测试通过领域时钟边界控制时间，不开放用户可伪造的时间字段或生产调试接口。
- 超时分段在新生成受理、绑定任务与输入版本之前原子决定，不能修改既有在途任务的归属。重复请求仍返回原受理决定，不能重试时再次分段。
- 回看使用只读行为；明确继续与新开是写行为。明确继续先核对归属和来源资格，再切当前并刷新活跃时间。
- 修改历史候选只刷新被操作会话，不替代明确继续、不隐式改变当前会话；只读浏览不刷新任何会话活动。
- 没有可靠活动时间的旧记录不伪造活跃；默认新段与明确继续旧段分别按 ADR-106 处理。

### 本机运行存档与受控恢复

- 使用锁定版本的官方 DSH JSONL 持久化与恢复能力，配置 NotAlone 管理的稳定私有数据目录；不能使用每次启动后清理的临时宿主目录。
- 会话存档关联 owner、contact、业务会话、运行会话、运行配置及有效来源状态；路径由可信应用配置和内部身份构造，不接受渲染层或用户输入的任意路径。
- 运行管理边界集中承担创建、续用、恢复、释放、隔离不合格存档及清除；业务模块仍掌握权限、来源、任务、幂等与删除，不让通用 DSH 存储接管业务事实。
- 同一运行会话只允许一个写者，复用现有任务领取、调用许可与 SDK 文件锁；不同联系人不共享模型历史。模型请求期间不持有长数据库事务。
- 数据库与文件不能用跨介质原子提交假设掩盖故障。存档与业务提交不一致时，以数据库决定已完成候选，隔离未提交运行轮，按有效记录修复或重建；不能把文件中出现候选当成保存成功。
- 正常退出释放运行实例但保留存档；重启可恢复合格历史。SDK 对未完成轮的关闭不等于半步续跑，未完成任务按业务规则中断，需用户明确重试。
- 文件缺失、损坏、格式不兼容或身份不符时不得直接继续外发；安全修复不能无限重试，失败保留输入和可见历史并给出可处理状态。

### 上下文、来源与预算

- 正常连续生成复用 SDK 派生的真实会话历史，追加本次任务与必要的最新有效材料，避免再次将完整旧讨论复制进新提示词。
- 当前任务的意图、有效背景和消息作者身份优先；旧候选或旧用户要求不能自动代表已发送、当前事实或长期偏好。
- 继续旧会话时刷新当前有效背景，变化时提示。修正、失效、来源删除、绑定变化和 Skill／工具资格变化都须在恢复及出站前处理，必要时重建运行上下文；仅追加更正说明不足以允许已删除正文继续出站。
- 每次出站和保存继续核验范围、输入版本、来源、允许的工具与业务提交；保留既有一次复验内的查询去重，不能把成功缓存跨生成阶段使用。
- 零 HTTP 准备与正式出站按本轮实际派生请求计量，包括恢复历史、工具结果、系统提示与控制字段；不能继续用一个空白临时会话低估预算。模型配置、输出契约与总调用预算保持。
- 保留接近预算提示、硬上限要求明确新开的行为，不自动摘要或静默截断。会话复用不保证供应商缓存命中，也不消除模型输入历史的成本。

### 删除与既有数据

- 公开删除流程先阻止相关存档恢复和新的出站，协调在途任务与文件写者，再清除相关运行文件、分叉、派生索引、缓存及应用管理的恢复副本；SDK 无产品级删除 API，由 NotAlone 接管此职责。
- 来源和联系人删除覆盖所有受影响运行记录；清理失败不得报告成功，不得继续使用未清理状态。清理只处理核验归属的应用管理路径，不擅自删除未知目录或用户另存资料。
- 业务数据库继续保留无关讨论或无正文占位；删除助手会话不删除独立合法的微信来源和记忆。读取、重启、索引重建或旧请求重放不能恢复已删内容。
- 既有讨论首次明确继续时，按有效业务记录建立运行存档；不假装恢复从未保存的原 DSH 日志，不批量转换、不重新生成旧候选、不自动提取全部历史。
- 新模块仅作用于候选回复助手会话，后台提取、整理等任务继续遵循原运行及日志边界。

### 桌面与交付

- 明确区分正在查看的历史会话与当前助手会话，提供继续、新开及自动分段提示；界面更新依赖后端权威受理结果，不在渲染层另算超时或猜测会话归属。
- 来源清理、恢复、版本读取或提交失败必须收敛到可重试状态，不能无限停在加载占位；迟到完成、旧 scope 或旧连接回执不污染当前视图。
- 在删除与恢复合同完成前，不在正常用户配置中启用未闭环的长期运行日志；各实施切片在隔离合成 profile 中可独立演示，完整验收后才启用正常开发入口。
- 日常开发和真实桌面验收只用热更新开发实例；本规格不授权打包、远端推送、外部聊天发送或真实资料批量迁移。

## 测试决定（Testing Decisions）

### 已确认的测试接缝

主接缝采用既有真实产品 Host、公开助手会话接口、真实隔离 PostgreSQL、本机合成供应商网络接口；复用生产联系人／回复控制器与 HTTP 客户端。DSH、持久化适配、业务数据库和协议解析均真实执行，只替换模型网络边界。验证第二次实际请求收到的合成历史与引用，不只断言 ID 相同或调用过 resume。

桌面补充生产 Main/preload IPC 与渲染断言，并在正常开发小窗实际检查回看、继续、新开和提示。现有静态 React 渲染不能证明挂载 effect 的竞态，因此状态迟到和订阅顺序由真实控制器及 IPC 屏障补足；必要的挂载行为再用现有页面验收入口覆盖。

最小新增夹具能力为：相同稳定 businessHome 跨两次真实宿主启动、仅控制测试自有进程的异常退出，以及领域时钟注入。复用现有供应商 Promise 屏障，不用长睡眠模拟中断，不实际等待 12 小时。

### 验收矩阵

| 场景 | 对外可观察的通过条件 |
| --- | --- |
| 连续两轮 | 同一业务讨论和运行历史延续；实际第二次模型请求有预期历史，未再次复制整段讨论 |
| 正常退出与重启 | 已完成记录可读；明确继续恢复原讨论；恢复本身不调用模型 |
| 崩溃恢复 | 中断轮不伪装完成；无模型自动重发；用户明确重试仍保持幂等 |
| 空闲边界 | 小于或等于 12 小时续用，严格超过后下一次生成恰好新开一次 |
| 被动事件 | 同步、新微信消息、只读浏览和打开应用不续期，不改变当前指针 |
| 明确继续 | 回看不切当前；继续旧段切当前并续期，立即生成不会再次自动新开 |
| 新段内容 | 不自动带旧助手讨论；显式携入只使用已选、已保存的正确候选版本 |
| 背景变化 | 继续旧段使用有效最新材料并提示；已删或禁用材料不会重新进入模型 |
| 旧数据 | 未继续的旧讨论保持只读；首次继续才建立存档，无批量转换及额外模型请求 |
| 删除会话 | 相关存档和恢复副本清除；重启不复活；独立合法来源与记忆保留 |
| 删除来源或联系人 | 受影响运行记录均清理；在途出站和迟到回执不能越过删除边界 |
| 清理失败 | 不报告成功、不继续恢复；重试后可完成，未知目录不被误删 |
| 文件与提交异常 | 文件缺失／损坏／版本不兼容、文件先成功而 DB 提交失败均不伪造已完成历史 |
| 并发与切换 | 同 key 单次受理、同运行会话单写者；切联系人、新开或回看不迁移原任务 |
| 真实输入预算 | 恢复历史计入实际请求；预检零 HTTP；超限按既有规则提示并要求新开 |
| 候选与人工发送 | 生成、保存、编辑、选择及引用依据保持正常，无外部自动发送 |
| 性能与计数 | 同材料比较应用准备／复验／保存与模型阶段，统计物理调用、查询及输入量；同时报告完整墙钟时间 |

测试只断言行为、实际请求、磁盘结果与业务状态，不镜像内部函数调用。已有公开生成回执、宿主退出重启、历史切换、来源删除及候选版本隔离测试作为先例；新增回归先红后绿。模块验证通过后，再按仓库阶梯运行相关模块、全量和类型检查。

同一场景如需真实模型效果对照，应使用正常配置、既有授权范围和有界小批预算，单独记录真实与合成验证的差别；合成供应商不能证明表达质量或供应商缓存收益。

## 范围之外（Out of Scope）

- 云端或多设备会话同步、跨联系人历史合并、自动生成或自动发送微信消息。
- 自动摘要、静默截断、自动跨会话检索、将讨论静默转为长期事实或偏好。
- 任意插件安装、通用 Shell／文件工具、模型或供应商切换、后台任务长期日志化。
- 批量转写旧讨论、重导入或重新提取全部真实资料、恢复已删除正文。
- DSH 核心分叉、从崩溃的半步工具调用续跑、保证供应商缓存命中或固定总时延。
- 打包、发布、远端分支和 Pull Request。
