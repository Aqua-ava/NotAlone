## 当前已证实的失败

1. **历史事实仍会在提取后丢失。** 首轮模型已提取“2024 年实习期间周三不能接电话”和“2025 年实习已结束、现在周三未知”，但 event 输出纯日期。离线重放当前 `_to_fact` 均抛“事件发生时间必须有明确时区”，两条未进入来源核验与已保存记忆。相同输入下，补证模型这次输出有时区时间，解析通过；但确定性日历核对将 `2024年实习期间` 降为 unknown，自动采纳门不放行，公开记忆缺该条（离线代码路径核对）；第二条已保存。不能把理解出文字算作成功保存。
2. **更新后的 L2/L3 仍未稳定完成。** 首轮初始 L2、L3 成功；生日和茶饮更正后 L1 旧值失效、新值生效，但 L2 返回 `faithfulness_rejected`。离线复现代码为 `source_quote_mismatch`：核验把 `evolution.explanation` 的解释文字当成来源引文，协议要求逐字引用 `memory.text`。公开场景为空、profile=null，更新后的 L3 没有成功。
3. **无矛盾的描述也可能阻塞整理。** 补证初始 L2 把“暂无已确认矛盾”列为 contradiction；核验认为没有真实冲突主张而判 supported=false，离线 `verify_result` 返回 `model_unsupported`，整份场景未通过，后续 L3 未运行。
4. **同批更正存在部分成功后失败。** 补证更新任务 `worker_step_failed`；生日/红茶替代已落库，晚间限制已提取并获来源支持，但未完成保存。其裁决把晚间限制作为旧乌龙茶记忆的补充，而该父记忆此前已在同批被失效；这是故障线索，具体抛错未捕获，不能写成已证实根因。
5. **知道条件仍会给出冲突候选。** 首轮晚间邀饮 3 条中，候选 1“今晚想请你喝点东西，红茶可以吗？”、候选 3 含“红茶或者别的”，与已知晚上不喝含咖啡因饮品冲突；risk_notes 自己提醒红茶含咖啡因，不能补救候选正文。该组逐候选 1/3 pass，2/3 fail。
6. **回复仍偶有扩大原意。** 首轮粘贴回复候选 3 把“本周忙得无法见面”写成“工作忙确实顾不上别的”，扩大事实范围；否定作用域没有翻转，但“不增加事实”维度失败。
