# 统一表达工作区

用户于 2026-10-19 确认本方案并要求直接实现。开发只使用现有 `npm run dev`，不打包、不推送。

## 用户问题

改写、回应消息和主动聊聊要求用户先区分聊天场景，回应还要指定消息并确认方向。实际需求只有“有想法，帮我表达”和“没思路，帮我想想”；两者最终都需要可编辑的候选语句及建议理由。

## 已确认行为

1. 单一联系人工作区提供可选的想法／草稿输入和两个显式动作：帮我表达、帮我想想。移除场景和消息来源切换入口。
2. 帮我表达要求非空想法，保持原意；帮我想想允许空输入，提出不同方向的候选，不能伪装为用户确认的立场。
3. 默认参考已确认联系人范围内的最近对话与相关资料，不要求选目标消息。可查看最近材料、排除不适用消息、关闭背景使用，并单独补充聊天文字；缺少背景时明确显示不足。有排除消息时保守停用派生资料和长历史补查，避免经关系摘要带回排除内容，并在界面说明。
4. 每次直接生成 1–3 条候选及基于实际背景的简短理由。理由默认可见；允许直接修改、复制及在同一会话继续调整，最终用户亲自发送。
5. 点击才生成；新消息提示更新，不自动替换输入、候选或编辑。
6. 补充聊天、表达要求和模型建议不自动保存为关系事实、用户确认方向或长期偏好。

## 实现决定

- 复用现有唯一候选生成、来源复验、持久化、会话和继续生成链路。
- 在 `rewrite_draft` 合同中新增 `input_kind=workspace`，明确 `workspace_action=express|suggest`，独立 `context_text` 和 `excluded_message_ids`。suggest 的 draft_text 可为空；不构造虚假草稿或 ConfirmedDirection。
- 桌面 generate 命令原子固定动作、联系人和输入；旧输入合同只为历史及内部兼容保留。
- 候选已有 basis 字段承载建议理由；继续沿用编辑、复制和来源查看。
- ADR-079 修订 ADR-043 的产品入口与先确认方向要求，保留资料隔离、Skill 范围、来源删除与手动发送规则。

## 验证接口与验收

- 现有公开回复请求／生成边界：验证空suggest、有意图express、资料隔离、排除项、保存恢复与继续生成，不测试私有实现。
- 现有桌面命令边界：验证两个动作到真实请求的映射、动作原子性、旧模式迁移、来源失效与重试。
- React 可见输出及实际开发 App：验证两按钮、无旧切换、独立补充框、候选与理由、连续调整。
- 合成与真实模型质量分开记录，真实聊天内容及截图不提交。

## 不在范围
