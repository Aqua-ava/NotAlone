# 本地想法编辑与生成授权分离

Triage: ready-for-agent
State: in-progress

规格：[统一表达工作区](../spec.md)。全量前台授权验收发现工作区把生成权限门禁错误用于本地输入。

## Answer

- 联系人未确认、前台暂停时允许填写并保留当前联系人本地想法；生成按钮及主进程请求继续拒绝。
- 无渠道绑定的联系人读取默认讨论应拒绝，但不能因此永远显示恢复并隐藏本地输入。
- 区分实际恢复中的状态与明确无读取资格的状态；不得把旧联系人输入带入新联系人，也不得让旧联系人确认授权新联系人生成。
- 修改限于必要工作区展示和输入就绪判定；不放宽默认讨论、新开或生成资格。

先用最小组件或逻辑测试复现后修复。页面由协调任务唯一串行Chrome验收；只复用npm run dev，不打包、不发送微信消息。

## 验证进展

- 本地输入禁用与无绑定无输入两项SSR先失败后修复；连同真实恢复中禁止编辑与既有回归共18项通过。类型与差异检查通过。
- 独立审查核对范围、默认会话失败的窄条件、无隐式读取或生成、同联系人确认保留草稿，未发现阻断。
- 复用现有开发版和合成联系人：未确认时写入本地想法，两个生成按钮禁用；真实切换手动输入后原文完整保留，两个动作开放。未调用模型或发送消息，临时想法已清空。
- 动态组件及原前台暂停、手动确认、安全边界页面待唯一浏览器队列验证；未增加浏览器页或服务。
