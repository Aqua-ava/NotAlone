## Answer

已合并三个入口为统一表达工作区，提供“帮我表达”和“帮我想想”。两个动作直接生成候选及默认可见的简短理由；默认使用已确认联系人最近背景，可关闭、排除消息或在独立输入框补充聊天。旧输入按原含义迁移，不将对方消息或模型推断冒充用户想法。保留候选编辑、版本、复制、讨论恢复与连续调整。

数据处理：复用联系人隔离及来源删除链路；空想法仅用于建议动作；排除消息后保守停用可能间接带回内容的派生背景、历史工具和旧讨论。补充文字、一次性要求和模型建议不会自动成为长期关系事实或用户确认方向；发送仍由用户完成。

- 后端83项相关单元测试通过：workspace_reply、fidelity_input、unified_inputs、context_retrieval、history_tools、prepared_context_codec、reply_quality、assistant_continuation_identity；最后调整理由提示后又通过13项请求／保真测试。
- 5项隔离 PostgreSQL + 生产 HTTP 集成测试通过：空想法生成和继续、准备中断重试、来源删除、排除消息不经历史回流、改口切换表达且保留背景。仅外部模型被替换，数据库已清理。
- 桌面 npm run typecheck 通过；npm test 默认安全集合197项通过；工作区桥和React可见输出13项通过，相关纯Node回归51项通过；场景兼容测试10项通过。
- 复用 npm run dev，以合成联系人操作实际 Electron App 和真实模型：空输入只能帮我想想；填写自己想法并独立补充对方聊天后可帮我表达；两者均直接显示3组候选及理由；重启恢复候选；编辑自动保存为修改版本1；继续修改经既有要求确认后生成更短候选并显示保存完成。未发送外部消息，未读取真实联系人正文进行生成。
