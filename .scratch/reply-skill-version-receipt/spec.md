# 自动 Skill 版本身份回执

Triage: ready-for-agent
State: resolved

用户反馈异步准备上线后仍显示泛化生成失败。此次请求准备成功、模型调用成功，但运行时因模型声明的Skill版本与实际读取版本不一致而拒绝候选。

## 根因与修复

自动模式的目录和正文不提供实际版本UUID，却要求结构化输出填该UUID；现有假模型预先硬编码身份，未发现此缺口。

- 受控read_file成功读取SKILL.md后，向模型同时返回由已核验版本生成的无正文身份回执与所选正文行。
- 提示及输出字段说明要求复制该回执中的版本UUID，不能拿版本号或证据ID代替。
- 保留原范围、单版本、版本失效与输出声明一致性检查；不接受跨联系人的版本、不放宽错误声明。
- 不更换模型、不扩大工具或资料范围，不修改外部发送边界。

## 测试

在现有生产LangChain生成接口验证模型第二轮实际收到对应不可变版本身份；先观察缺失断言失败，再验证绿色。补动态模型按实际回执填写UUID的完整生成，以及多页读取和错误版本拒绝。

相关Skill/输入预算/运行时模块回归后，复用npm run dev在用户报告的同一联系人范围检查候选保存及恢复。临时诊断仅含异常类别和代码位置，结束前移除，私人内容及凭据不进仓库。

## Answer

受控读取现在返回经过版本与范围复验的UUID回执，提示与结构化字段要求原样复制；严格版本一致性校验保留。动态模型、分页空页及错误声明测试通过，实际开发App在原失败场景显示3条可编辑候选。验证细节、数据影响及剩余限制见[验收记录](validation.md)。
