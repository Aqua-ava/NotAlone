# 腾讯记忆流程对齐：实现与验证

## 本轮结果
- 默认 L1 改为按场景直接生成完整记忆，保留原文来源及主体、时间和否定等校验。
- 支持多条自动采纳记忆合并：重新核验合并正文，原子替换父版本，保留全部来源和旧版本；手动确认记忆不被自动替换。
- L1 候选、L2 主题、L3 条目分别隔离失败；整份不可解析、输入版本变化仍停止该次发布。
- 完整生成正文独立记录全部来源依赖，删除任一必要来源时同时清理候选和已采纳正文，不将此标记当作更高等级的核验证明。

## 验证
- 最后一次相关单元验证：43 项通过，覆盖直接提取、裁决隔离、多条合并和来源依赖。
- 生命周期 PostgreSQL 集成：23 项通过，包括联系人与本人、来源删除、候选副本、追踪清理、原子回滚。测试使用随机隔离库并已清理。
- L2/L3 项目隔离单元验证通过；HTTP 局部发布用例通过，确认结构不合格和核验失败主题不影响合法主题发布。
- 代码审查发现的合并召回与裁决错误传播问题已修复并针对性复验。
- 曾执行记忆提取全模块验证；仍有 3 个历史 reference16 子进程夹具在 evaluation_deadline_invalid 处失败，不宣称全套通过；未反复重跑整场。

## 明确限制
- 本轮没有调用真实 DeepSeek、没有重新生成用户聊天记忆，也没有授予真实生成质量验收通过。
- 相似召回仍用现有文字算法；未引入腾讯的完整向量基础设施。
- 保留有据背景边界，不生成性格动机推断或长期回复指令；现有采纳与质量门禁继续生效。
- 历史升级入口不具备多父合并预览时保持待确认；多父历史保留，但未扩展旧的单父撤销协议。
- 无打包、发布或推送。公共扫描仍有历史及并行文档改动的已有命中，未修改其他任务内容。
