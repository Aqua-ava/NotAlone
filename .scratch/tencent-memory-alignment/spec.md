# 参考腾讯的分层记忆流程

状态：用户于 2026-10-18 确认范围，正在实现；真实模型质量尚未据此通过。

## 问题与目标

原 L1 分句标签编译会因孤立 prefix 拒绝整批有效信息。改为模型按场景直接写出能独立理解的完整记忆；来源、主体、时间和采纳仍由既有流程核验。参考本地 TencentDB-Agent-Memory 的 e9a82935b52741e0c798c75326e90b7144eb4d5f，不声称逐行复制。

## 已确认决定

- L1 完整正文生成、相似记忆去重更新、多条合并、L2 持续主题、L3 长期背景整体衔接。
- L2/L3 只整理有依据背景，不自动推断动机、性格，不产生回复指令。
- L1 逐候选、L2 逐主题、L3 逐条目隔离失败；不可解析的顶层输出、来源或输入版本变化仍停止该次处理。
- 合并需重新核验新正文，保留全部来源与旧版本；不自动替换人工采纳记忆。
- 保持联系人隔离、本人资料隔离、来源删除、预算、资格门禁及最终手动发送。

## 实现边界与 Seam

1. `DirectExtractionRuntime.extract` 用一次结构化调用生成场景内的完整记忆，直接进入 `ExtractionFlow`；移除默认路径上的分句编译依赖。CLI、Worker、服务及升级预览使用同一默认；显式历史 bounded 配置继续旧协议。
2. `LangChainAdjudicationRuntime.adjudicate` 保留新增/更新/重复/并存，新增 merge 的父版本 ID 和完整正文。`MemoryMergeVerifier.verify` 使用当前已授权消息重核正文；同类、同主题、同期限、无事件的自动记忆可以合并，异类/不同事件阶段保留独立记忆。父来源缺失或跨联系人不能补读。
3. `confirm_merge` 在单事务中确认新候选并失效旧自动版本，校验来源、采纳门、修订及人工决定。完整生成及合并正文的候选与已采纳记录均通过 requires_all_sources 标记依赖全部原始来源；此生命周期标记不改变 v3/v4 核验信用。版本读取及删除遍历全部父版本。
4. L2/L3 继续现有提案→独立核验→版本发布，不额外为每个条目调用模型。核验和评测共同使用逐项结果；失败原因与原始输出保留在原可删除运行记录中。
5. 已批准升级计划绑定实际代码和协议摘要；不能用旧批准执行新规则。历史升级执行没有合并预览合同的路径保持待确认，不绕过批准执行多父写入。

## 与腾讯的必要适配

- 腾讯 persona/episodic/instruction 与人机角色不直接搬用：本产品使用真实联系人、事实/偏好/禁忌/近期状态/关系经历和来源 ID。
- 本轮不引入向量库；相似召回沿既有有界文字匹配，去重和合并由模型提议及程序核验。
- 腾讯文档文件更新适配为数据库有来源、可撤回的版本；L2/L3 的心理特征推断不采用。
- 不取消原来的自动采纳放行表与整理质量资格。工程通过不代表 DeepSeek 真实质量通过。

## 验收

先测完整候选和坏条目隔离，再测合并正文独立核验、事务回滚/人工保护/删除及版本来源，最后测 L2/L3 混合成功发布和预算。全部用不含私人信息的协议夹具验证工程，不冒充真实聊天质量结论。不重跑真实全场评测、不开启后台整理、不迁移用户现存数据、不打包。
