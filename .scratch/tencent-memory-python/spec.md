# 参考腾讯源码自行实现自动记忆
Triage: ready-for-agent
State: open

## Problem Statement
现有自动记忆链路与腾讯源码实现存在提取、混合召回、批量裁决、场景工具维护和画像触发差异。

## Solution
参考本地腾讯 e9a8293，在现有 Python 后端自行实现。禁止接入腾讯服务、引入 MemoryCore 运行时或 Node sidecar。腾讯目录只作为只读来源。

## User Stories
1. 已授权聊天进入后自动提取，无需手动确认。
2. 新信息可新增、跳过、更新和合并多条旧记忆。
3. 自动更新已有场景、合并重复场景，不按批无限追加。
4. 根据变化场景增量更新画像，无变化跳过。
5. 消息量及空闲时间触发，重启可恢复且幂等。
6. 联系人和本人资料隔离，保留来源、撤销、人工修正和删除路径。
7. 在 App 查看当前记忆和整理状态。

## Implementation Decisions
- 现有 Python/PostgreSQL 运行栈自行实现，逐项保存腾讯源码行号映射；沿用已配置模型及本地检索能力，不新增外部供应商。
- L1 参考新消息与背景窗口、完整叙述提取、混合召回统一候选池和批量 store/skip/update/merge；支持跨类别、多目标更新。
- L2 参考场景 Markdown 及受限文档工具维护流程；工具只触达当前隔离范围文档。
- L3 参考变化场景与已有画像的增量生成和上游触发判断。
- 联系人主体、来源核验、事务版本、人工保护和失败保留待处理是明确的产品适配差异，不宣称零差异。
- 替换现有正式入口，预览与正式流程共享业务实现，禁止并行双写旧新流程。
- 旧接入提案和未跟踪 memory-engine 不作为交付，先保留未知来源文件。

## Testing Decisions
用户已确认测试边界：从聊天进入系统到读取当前记忆、场景、画像，通过现有导入/任务/资料读取接口验收。模拟仅允许外部模型与时钟等系统边界。按 TDD 单切片推进。
覆盖首次提取、重复输入、跨类型更新、多目标合并、场景增量、画像更新、无变化跳过、失败恢复、联系人隔离、手动保护及删除。
真实模型只发送合成聊天到既有配置，次数不限（用户已授权），使用同一累计账本；完整链路与未参与调试样例独立审查。开发桌面仅 npm run dev，禁止打包和 push。

## Out of Scope
腾讯服务/运行时接入；自动发送外部消息；扩大联系人读取权限；新增 embedding 外发供应商；真实私人历史全量重建。
