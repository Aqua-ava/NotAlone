- 调度：1→2→4→5 预热、600 秒空闲、事务记账、丢通知补扫和重启恢复；显式导入立即处理。

发现并修好的真实失败：
1. 首轮4次请求：场景模型读不存在的绝对路径，失败。补明确完整索引、空索引创建规则和五轮内工具错误反馈；未放开路径或发布校验。
2. 修复后24次请求：初次及更新正确，但重复D只返回文本JSON，留下pending。独立审核纠正了脚本的误报，新增无pending断言。D改为非思考模式指定唯一结构化工具，仍拒绝文本降级；E/V和供应商不变。协议依据见[官方说明](https://api-docs.deepseek.com/api/create-chat-completion/)。
3. 最终两条46次请求完整通过。

本次实现验收合计74次；沿用原累计账本，含之前60次后共134次。用户额外授权最多三轮续验，以追加授权记录保存，未重置计数、旧轮次或失败记录；续验已使用两轮，不再追加请求。原始合成证据和独立审核保存在仓库外 `python-reference-contact-final`、`python-reference-owner-observation` 对应私有目录。

## 工程回归

所有后端命令使用指定 Conda Python，`PYTHONPATH` 显式指向工作树 `backend/src:backend`，避免 editable install 意外读取主目录。

- L1 HTTP 16项；L2/L3 HTTP 16项；观察＋持久调度26项；真实观察入口离线边界1项；累计账本8项，最后相关分组验证通过。
- 合并专项首次67项中5项失败来自旧逐条触发假设；测试改为在输入记录边界模拟已空闲601秒，保留原重试、水位、删除和不丢消息断言，观察/调度26项复验通过，未恢复逐条派发。
- L1单测首次981项发现5项失败；2项旧追踪断言按新窗口和无效裁决待处理语义修正，相关16项通过。其余978项最终通过。
