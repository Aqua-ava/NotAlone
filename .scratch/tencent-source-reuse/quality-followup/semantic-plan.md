# 完整命题核验接口草案

状态：设计候选，尚未采纳、实现或证明质量改善。基线为 `4f89bb97`；本轮只读源码并写本文件，不改生产源码、不调用供应商、不新建或续期预算。

## 问题和完成条件

已观察原 E/V 离线回放确认：声明来源覆盖修复拒绝 P2，并保留 P1/P4；P3 只有一个来源且引文齐全，仍被错误支持。P3 的 E 元数据是 `recent_state/assertion/asserted/literal`，`event/conditions=null`。现有非空事件未核实时的拒绝逻辑没有被证明失效；缺口是自由正文中的主体、对象、动作或时间关联仍由一个总 verdict 代签。

新 Interface 必须审查完整正文及其模态，不以合法 ID、逐字引文、完整来源覆盖、空 event 或自报 supported 代替语义支持。无法消解时不进入自动采纳；明确来源的单源事实、完整问答、第三方转述和保留不确定性的陈述仍有可通过路径。语义支持依然是模型判断，不能把新增结构宣传成程序证明。

## 推荐的最小外部 Interface

生成候选仍由腾讯源码的 E 构建；只替换 V 的版本化结果合同。工具名保持 `SourceVerificationOutput`（`deepseek-strict-verification.ts:3`），继续走原严格调用、permit、物理台账及预算；不能改名后落入另一发送分支。

输入保持同一已授权窗口，新增策略版本和候选／来源快照绑定。模型不查询新消息，不改变正文、subject、模态、来源、事件或条件，也不生成修正版；不要求输出思维过程。

以下是待定的类型草图，约束以验证器为准，尚不是实现规格：

```ts
type Support = 'supported' | 'uncertain' | 'unsupported';
type Facet = { verdict: Support; evidence_indices: number[] };
type ClaimCheckV1 = {
  version: 1;
  parts: Array<{
    candidate_span: { start: number; end: number };
    attribution: Facet & {
      scope_subject: 'self' | 'contact' | 'shared' | 'unknown';
      actor_kind: 'self' | 'contact' | 'shared' | 'third_party' | 'unknown';
      resolution: 'explicit' | 'unique_context' | 'unresolved';
    };
    arguments_and_relation: Facet;
    temporal_and_modality: Facet;
  }>;
};
// 原 results 每项保留 candidate_index / verdict / issues / evidence，
// 在新策略版本中必填 claim_check，不复用旧有限图 proof 字段。
```

`evidence_indices` 引用本候选原 evidence 数组，复用引文而不重复复制原文。按完整候选的所有可见码点校验 `candidate_span` 的覆盖，不能只取一个容易支持的子句；区间按原文顺序、不得重叠或越界，空白／标点由固定可审计规则处理。切分只管理覆盖，不把标点切分冒充语义原子化。

三个 facet 的职责分别是：

1. **归属**：区分资料所属 `scope_subject` 与正文实际主语 `actor_kind`。第三方资料可归 contact/self 范围，但正文须保留第三方，不能把亲友事实归到本人。sender 仅是说话人，不自动等于命题主体；转述中的第一人称也不能机械绑定到外层 sender。指代需相连来源唯一支持，否则 `unresolved/uncertain`。
2. **对象与关系**：检查谁对谁做什么、对象是否由来源给出、方向／否定／限定是否保留。引用同一句话不允许新增受事、因果、获知、参与或确定承诺。候选是一条完整复合命题时，不能以一个子动作有据代签整条。
3. **时间与模态**：始终核对完整正文，包括 `event=null` 的候选。区分消息时间、获知时间、事件发生时间、安排与适用期；引用消息发送日不支持新增“某日得知／发生”的关系。保留计划、假设、转述和已知的不确定性，不按当前时间推完成。

没有显式日期的正确事实也可得到时间／模态 supported，表示未添加来源没有的关系；不强制补日期或 event。来源明确表示“尚未确定日期”，候选忠实保留这个未知，也可 supported；这与核验器无法判断主体或含义的 unknown 不同。三个 facet 都须显式判断，不用空值或 not_applicable 绕过未检查的内容。`resolution=unresolved`、unknown 归属、任一 facet 非 supported 或缺合法依据，都不能自动采纳。

## 程序可执行的准入及其边界

- 先验证策略、候选正文／字段摘要、同联系人窗口及全部来源版本；摘要由程序生成，不让模型计算可信身份。每条 candidate_index 恰好一次，不能交换候选或复用另一条的核验。
- 逐字引用和区间必须来自本候选声明的消息，完整声明来源仍全部覆盖；字段为实际有界枚举，part 全文覆盖、引用索引有效。引用与覆盖只是必要条件。
- 校验归属字段与候选的 scope 一致、明确支持的主体映射不自相矛盾；第三方与 scope 分开。不能借通用代词／关键词规则宣称已证明人物关系。
- 本地聚合 facet 状态；顶层 supported 若与 facet 的 uncertain、unsupported、unresolved 或缺失相冲突，则降为不可采纳并记录原因，不能听从顶层总 verdict。已有非空 event/conditions 仍须分别通过原专项核验，与新 facet 取合取条件，不能互相代签。
- 新策略只有完整检查通过且 source support 为 supported 的候选可进入 B。语义 unknown 留在可删除追踪中，按默认流程记录未通过并终结；不默认新增人工待办，也不由 risk_flags、低置信度或候选计数暗中放行。
- 新核验仍不能确定性识别“模型所有 facet 均错误宣称 supported、但结构和引文合法”的情况。这个剩余风险必须由独立盲评／真实质量信号检验，不能靠构造 fake provider 全绿结案。

## source 版本、缓存和恢复兼容

- 新策略暂名 `complete-claim-v1`；`legacy-v4`、`nullable-proof-v3` 及旧结果保持历史身份，不把其缺省 claim_check 解释为已通过新策略。
- 新任务／窗口冻结策略版本、schema/prompt 摘要与实际来源／候选版本；旧任务 runtime config 为 null 时不静默升级或重发。若要采用新策略，应在已确认的任务生命周期中建立显式配置，先核已知回执，绝不换 task 绕过旧 unknown。
- 已查 `extraction-batch-service.ts:133`：输入指纹当前包含 window、rule_version、model；未显式包含新 V policy。实现前必须把策略及合同摘要纳入冻结 ruleVersion／指纹，并核对调用端是否原样传递；不能用旧 cached accepted 签新策略。
- 已完成旧结果可作为历史读取，不产生新策略资格；cache policy 不匹配要明确拒绝复用，不覆写旧 trace，不把旧 artifact 的 mode 标签改新。
- 结果绑定原 owner/contact、候选正文和字段、来源状态及原许可回执。来源修正／删除、候选变化、任务世代改变均使旧核验失效；提交 B 前沿现有事务再核，不新增跨联系人实体库或长期指代缓存。
- 类型／追踪版本与 DTO 新增字段需显式兼容；`proof_verification.verified`、来源状态新鲜度与新模型 semantic support 分开记录。实现时需要根明确调用端／任务快照模块的文件所有权，本轮不跨界改动。

## 可测试与预算约束

| 层次 | 必须保留的负向信号 | 必须通过的正向控制 |
| --- | --- | --- |
| 纯验证器 | 遗漏 candidate 片段、坏／重叠区间、他人候选／来源、顶层支持但 facet 未定、unknown 归属、缺策略或版本不符均不进入 B。 | 不改原文的同义表达可被结构完整的语义核验支持；标点／Unicode 不造成误拒。 |
| 正式 E→V→准入（合成端口） | 复合命题只核一个子句；把说话人等同主体；新增未明示对象或“获知时间”；event=null 不能跳过时间／模态 facet。 | 明确单源事实、完整双源问答、保留亲友称呼的第三方转述、忠实计划／假设和明确未知日期。 |
| 来源与任务合同 | 不同 policy 的旧 cache 不能复用；来源或候选版本变化、删除、取消、旧 unknown 均不签新资格。 | 同窗口同版本已知回执、取消和恢复的现有确定性合同保持。 |
| 独立语义验收 | 对结构完全自洽但含义错误的 V，单元测试不能冒充判对；继续盲评完整原失败及未参与调整的样例。 | 原两个正确项 P1/P4 必须保留，不能全部拒绝；P3 的未明示对象／时间关联需实质改善。 |

主假设只设一个：把完整命题拆成可审阅的归属、对象／关系和时间／模态支持检查，能降低“总体 supported 掩盖无据关系”的假阳性，且不误拒正确对照。其预测要经生产模型和独立判定验证，离线 schema 成功不算 improved。

E/V 仍各一次，不添加第三个语义模型，不自动分批重试。引文通过索引共用，避免长篇解释。建议初版默认一个 part 覆盖全文、最多四个 part；这是返回大小上限，不强制把复杂陈述拆进四类语言模板，任何 part 的三项检查仍须审其完整范围。每项引用索引去重且不超过该候选实际 evidence 数，不能扩大来源集合。具体 token 可行性需在离线最大合法输入上核定，不能以该上限默默截断候选或改固定分母。若现有 token／输出预算放不下，发送前明确失败，不能静默增加调用或放宽 calls/tokens/质量阈值；字段增加不自动等于预算合格。

原问题 8 次／30 分钟账本已截止，累计 2；本方案不续期、不重置、不新建账本。当前只做离线设计／合成验证；任何后续真实验证由根按既有停止规则和用户范围另行处理，费用豁免不提供额外调用授权。

## 推进顺序与停止点

1. 私有 Reviewer 给完全虚构的最小机制例，核对本 Interface 是否真能表达错误和两个正向；只把非识别逻辑写进合成测试。
2. 根确认这个单一主假设、版本接法及文件范围后，先实现纯验证器的 RED→GREEN，再接现有一次 V；不扩展腾讯 E 或删除依赖，不追加泛化 prompt 规则。
3. 用已经观察的结果做私有离线回放，只能说明工程过滤，不能证明新的模型会正确给 facet。
4. 正式质量仍按完整分母、旧失败、正确控制和独立盲评签收；若模型继续把全部 facet 错签 supported，保留失败并停止，不以改字段、补关键词或重设问题编号制造改善。
