# CLI 排序游标与本地历史可用性

用户要求修复编号变小的合法后续消息无法同步，并区分本地无记录与读取失败。

## 范围与决策
- CLI 实时 tail 页按微信排序位置读取，事件编号不代表顺序；保存最后事件游标。
- 来源、规范消息与游标仍原子提交；以已读起点做并发校验，拒绝陈旧任务覆盖进度。
- 可靠位置按成功批次顺序恢复，重试和重启不回到数字最大的编号。
- 新迁移保留既有数据，调整观察批次的数值约束及恢复顺序。
- 仅完整检查消息分库后明确缺表，才只读核验同一授权会话的实时会话元数据。
- 确认空会话或删除记录时展示本地无记录；保留游标、不声称历史完整，仍响应后续新消息。
- 密钥、超时、分库覆盖不足、未知或存在消息元数据仍按读取失败处理。
- 不扩大联系人授权，不读取媒体正文，不发送外部消息，不改用户暂停设置。

## 验证边界
- LocalWechatCli + CliBackgroundSync：非单调编号跨页、媒体事件、无进展页和损坏游标。
- PostgresObservationStore：真实数据库事务、重启恢复、并发旧起点、幂等和失败回滚。
- CLI 元数据分类：合成只读 SQL 响应、删除、空会话、无法确认与超时。
- 桌面状态：无记录为中性说明，真正读取失败保留错误。
- 复用 npm run dev，真实已确认会话验收同步位置推进及重试去重。
- 真实身份与聊天正文不写入规格、测试或提交。
