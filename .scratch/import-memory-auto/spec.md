# 历史导入后的自动记忆处理

Triage: ready-for-agent

## Problem Statement

用户希望优先把核心业务流程接通。当前 HTTP 导入已将联系人确认、来源、规范消息和后台任务同事务保存，但提交后不唤醒 Worker；用户还必须另外执行任务，才能获得记忆候选和检索资料。一次启动遇到 Worker 忙时也不会持续保留唤醒，宿主缺少完整关闭协议。直接自动启动会让后台模型调用与前台候选回复争抢执行机会。

本轮先闭合历史导入路径。增量同步缺少 observation 任务来源、迟到消息覆盖及删除后的调度契约，后续另行设计，不能将其伪装成导入任务。

## Solution

用户确认联系人并提交历史导入后，消息立即可用；后端在事务成功之后自动唤醒原记忆任务，用户可以按原任务身份查看数据库中的进度、成功或失败。Worker 忙时保留本次唤醒，候选回复获得前台优先级。后端关闭时停止接收新工作并停止后续后台调用，原任务保留既有恢复路径。

## User Stories

1. 作为用户，我希望确认联系人并提交导入后自动处理记忆，以减少额外启动步骤。
2. 作为用户，我希望导入返回原任务身份，以查询与本次资料对应的处理状态。
3. 作为用户，我希望消息导入与记忆处理分别显示结果，以区分消息可用和记忆完成。
4. 作为用户，我希望模型暂时不可用时仍保留已导入消息，以免重新导入资料。
5. 作为用户，我希望执行条件不足时有可查询的最小原因，以知道任务为何仍在排队。
6. 作为用户，我希望重复提交相同资料复用原任务，以免重复写消息或重复处理成功结果。
7. 作为用户，我希望失败任务由我显式恢复，以保留当前模型重试预算。
8. 作为用户，我希望自动处理只唤醒本次导入的原任务，以免顺带执行旧队列。
9. 作为用户，我希望同一任务的并发唤醒合并，以免发生重复执行。
10. 作为用户，我希望当前任务运行期间提交的下一份资料不会丢失唤醒，以便随后继续处理。
11. 作为用户，我希望 CLI Worker 占用全局锁时本次任务继续排队，以免导入后静默停滞。
12. 作为用户，我希望长时间锁忙采用间隔有上限的退避，以控制资源消耗。
13. 作为用户，我希望候选回复优先于尚未开始的后台模型调用，以尽快完成当前表达。
14. 作为用户，我希望后台的提取、来源核验和裁决共同遵守优先级，以避免某一阶段继续插队。
15. 作为用户，我希望前台等待不消耗候选生成器自身的运行时限或请求租约，以避免尚未生成就超时。
16. 作为用户，我希望后台调用的成功与失败都释放执行许可，以便后续工作继续。
17. 作为用户，我希望关闭后端时不再开始新任务或后续模型调用，以限定后台处理时间。
18. 作为用户，我希望停机等待有上限，以免退出无限卡住。
19. 作为用户，我希望未完成任务保留成功步骤和租约恢复能力，以便之后明确继续。
20. 作为用户，我希望重启不自动扫描旧队列，以保持本轮自动处理范围清楚。
21. 作为用户，我希望删除来源会停止相应未完成工作，以免删除后产生可检索的新资料。
22. 作为用户，我希望其他联系人和其他用户的任务不受本次唤醒影响，以保持资料隔离。
23. 作为用户，我希望候选和依据仍可查看、编辑和删除，以验证自动处理形成的资料。
24. 作为用户，我希望最终消息仍由我亲自发送，以保留产品人工发送边界。

## Implementation Decisions

- 导入的消息、来源与固定任务模板仍在原事务中保存；自动唤醒发生在提交之后。后台不可用或模型失败不把已经成功的消息导入改报为失败，也不回滚消息。
- 唤醒携带后端运行身份、已确认联系人及原任务身份。相同任务合并唤醒；成功、失败或取消终态不自动重做。失败恢复继续使用既有显式入口。
- 默认 CLI 的最早任务领取规则保留。HTTP 自动处理按本次原任务领取，属于 ADR-018／ADR-034 的新局部例外，由 ADR-035 记录；ADR-020 的界面显式启动约束同时局部修订。
- 指定任务身份只限定被调度的业务任务。提取仍复用现有执行器，依照该已确认联系人的有效消息、既有水位和窗口处理；本轮不改覆盖算法，不把任务身份宣称为来源级独立提取范围。
- 复用现有确定性 Worker、全局 advisory lock、联系人租约、心跳、三次失败预算和来源复验；不新增队列服务、schema 或自动恢复失败任务。
- 自动唤醒在本后端内保留最小任务引用。Worker 忙时按有上限的退避继续尝试，间隔最多 30 秒；后端关闭时结束等待。退避仅尝试执行条件，不增加模型失败重试预算。
- 缺少模型配置或执行资源时，在领取前停止，原任务保持可明确启动的状态，并提供持久、无正文的原因。配置修复后可显式执行；本轮不扫描重启前的旧排队任务。
- 新增进程内调用协调，通过既有提取、来源核验、裁决运行时接口和候选生成入口接线，保留原模型适配器、提示词、解析、采纳门和台账。前台等待发生在候选生成器启动任务与运行时计时之前。
- 前台需求登记后，尚未开始的后台模型调用等待。已经开始的一次提取／核验／裁决调用返回或抛错后，前台回复优先；此调用可能包含 SDK 内部重试，不承诺在每次 HTTP 重试之间抢占。整次前台回复期间暂停后台模型调用。
- 协调范围为本后端中的候选回复与进程内 Worker。独立 CLI Worker 保留原行为，并仍受全局 Worker 锁约束；本轮不新增跨进程模型额度调度。
- 关闭时拒绝新唤醒、通知等待者停止，并在模型调用或步骤边界结束后续工作；等待上限 5 秒。已经开始的第三方调用不能保证立即中断，超时后的未完成工作依靠既有租约与显式恢复，不能误报业务完成。
- 锁连接、执行许可和线程登记在成功、失败与停止路径中释放。任务状态仍以 PostgreSQL 为权威；宿主线程启动或结束不能代替业务任务成功。
- 自动处理只复用既有模型配置与数据范围。本轮验证全用合成资料、专用测试库和 scripted fake，不读取业务配置，也不接入或验收外部模型。

## Testing Decisions

- 用户已确认最高行为接缝为 BackendServer 公开接口：真实回环 HTTP 业务请求及公开 shutdown 生命周期。新测试不直接针对协调器、线程字典或其他私有实现。
- 复用既有核心 HTTP 合成验收、任务恢复和回复权限验收的隔离设置。导入、Worker、PostgreSQL 消息／记忆／检索／候选存储、台账和状态查询保持真实，仅外部模型输出使用脚本。
- 测试先在模型边界准备响应和可控制的等待，再提交导入，避免依赖线程快慢或用 sleep 猜测脚本安装时机。
- 先验证现有手动任务与前台回复的优先执行、许可释放和有界关闭，再验证自动导入无需额外 run 能到达持久 succeeded，并产生可检索、带来源的资料。
- 覆盖重复与并发提交、正在运行时的新唤醒、不同联系人排队、全局锁忙后续跑、缺配置、三次失败后停止、终态不自动重做、旧队列不执行以及恢复入口兼容。
- 覆盖提取／核验／裁决中的前台插入；观测模型边界和公开回复结果，证明下一次后台调用让位，等待不占用候选生成器运行时间。
- 覆盖等待期间删除来源、关闭期间旧调用返回、停机后拒绝新业务动作，以及新服务只查询原状态而不扫描旧任务。保留现有联系人隔离、来源删除、候选依据和幂等重放断言。
- 每个垂直切片先记录公开行为 RED，再做最小修复；复用相关旧测试，完成 Python 编译与差异检查。测试驱动显式禁用业务 dotenv、排除真实模型冒烟并阻止外部网络；不把配置测试残留的假凭据当作模型调用授权。
- 本轮固定审查基线为 6e67f275cb40cbc1e8f230c153101402f15ff0da；每张任务分别执行 Standards／Spec 审查，并只提交本任务路径。

## Out of Scope

App 界面或打包、真实微信同步与私人资料、业务数据库、外部模型质量或在线验收、增量 observation 任务及迟到消息水位、提取／核验／裁决语义与算法、方向建议、自动扫描旧任务、跨进程模型额度服务、无预算自治循环、正式部署、push、PR 和旧库接管维护进程误判修复。
