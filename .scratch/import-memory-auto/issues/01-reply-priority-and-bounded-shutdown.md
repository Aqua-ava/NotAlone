# 01：后台调用让回复优先，并可有界关闭

Triage: ready-for-agent
State: open
Type: task
Blocked by: None

**What to build:** 用户已有后台记忆任务运行时，新的候选回复能在当前后台调用结束后优先执行；关闭后端能够停止后续工作，并保留真实的未完成状态。

- [ ] 在 BackendServer 公开 HTTP 接缝复现并修复后台下一次模型调用抢在已等待回复之前的问题；候选请求的等待发生在生成器启动任务、取得请求租约和 runtime 计时之前。
- [ ] 提取、来源核验和写入裁决都复用相同进程内控制；原适配器、提示词、解析、采纳门和台账保持。一次调用包含其内部 SDK 重试，不假设可中断一次正在执行的第三方调用。
- [ ] 整次前台回复期间暂停后续后台模型调用；成功、失败和拒绝路径释放许可，后续合法工作可以继续。
- [ ] 通过公开 shutdown 生命周期及运行时 HTTP 入口验证拒绝新工作、唤醒等待者停止，并在模型调用或步骤边界停止后续工作；等待上限 5 秒，不将未完成任务误报为业务完成。
- [ ] 来源删除或租约失效时保留既有防护，等待中的旧工作不得在来源不可用后继续产生可检索资料。
- [ ] TaskHost 的锁连接、线程登记及控制许可在成功、失败和停止路径中正确收尾；CLI 默认行为、全局 Worker 锁和每轮三次模型失败预算保持。
- [ ] 仅在用户确认的最高公开接缝增加合成行为测试；真实 Worker、PostgreSQL 及存储参与，仅模型脚本化。显式禁用业务配置与真实模型冒烟，并阻止外部网络。
- [ ] 相关回归、Python 编译、差异检查完成，按固定基线执行 Standards／Spec 双轴审查，独立本地提交。
