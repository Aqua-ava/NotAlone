# 02：导入后可靠自动处理与状态查询

Triage: ready-for-agent
State: open
Type: task
Blocked by: 01

**What to build:** 用户确认联系人并提交导入后，无需额外 run 即可由后台完成原记忆任务；重复提交、执行条件不足和失败都有可查询的持久状态。

- [ ] 通过 BackendServer 公开 HTTP 接缝先观察提交后未自动处理的失败，再使事务成功后唤醒本次原 task_id；消息可用不等待模型，后台失败不回滚或误报导入结果。
- [ ] 原任务成功后可检索同范围的派生记忆，并能生成、回看候选依据、同键重放和删除来源；用户无需另发任务启动请求。
- [ ] 重复或并发提交相同来源复用原任务并合并唤醒；成功、失败或取消终态不自动重做，失败继续由用户显式恢复。
- [ ] 正在运行时的新导入保留唤醒，Worker 全局锁忙后按间隔最多 30 秒的退避继续；后端关闭停止等待，不增加模型失败重试预算。
- [ ] 自动处理固定本次原任务，不顺带执行较早旧队列；重启仅保留持久查询与显式恢复，不扫描旧排队任务。默认 CLI 最早领取规则保持。
- [ ] 缺模型配置或执行资源时不领取步骤、不回滚消息；原任务保留可明确启动的状态，持久查询提供无正文的最小原因。
- [ ] 不同用户和联系人隔离；来源删除、租约失效、等待期间关闭及旧调用返回均不能使已删除资料重新可检索。
- [ ] 复用 01 的前台优先和有界关闭，适配模型脚本的异步准备，保留核心闭环、显式恢复与普通润色权限回归。
- [ ] 只使用合成资料、自建测试库和 scripted fake；不修改 App、schema、记忆提取／核验／裁决语义或增量同步。
- [ ] 相关回归、Python 编译、差异检查完成，按固定基线执行 Standards／Spec 双轴审查，独立本地提交并报告真实证明边界。
