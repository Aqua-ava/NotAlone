# 核心业务闭环与恢复

Triage: ready-for-agent

## Problem Statement

用户希望优先跑通核心业务流程，App 属于次级问题。现有测试分别验证导入、Worker、检索、回复和删除，尚未证明同一份合成来源能通过这些真实模块形成可回看的候选回复。失败任务缺少业务恢复入口；普通草稿润色运行时仍暴露历史检索能力。

完整 HTTP 验收复现了首个真实断点：历史 Tool 命中已在初始上下文中的消息时，运行时重复附加该证据，触发生成入口的重复引用拒绝，合法请求返回 500。

## Solution

先通过公开 HTTP 接口验证完整核心闭环，再分别补齐失败任务恢复和普通润色权限。用户明确确认联系人及表达方向，显式执行 Worker，查看候选及依据，重复请求复用结果，删除来源后无法恢复相关资料。

## User Stories

1. 作为用户，我希望确认一位联系人后导入其单独的资料，避免混入其他联系人的内容。
2. 作为用户，我希望导入消息成功与后台记忆处理状态分别可见，避免把消息可用误认为任务完成。
3. 作为用户，我希望显式启动 Worker 后，真实处理步骤能够完成并用于后续回复。
4. 作为用户，我希望候选回复使用本次联系人范围的资料，并能查看来源依据。
5. 作为用户，我希望同键同输入请求返回原候选，避免重复生成。
6. 作为用户，我希望删除来源后其消息、记忆与旧候选依据不可继续使用，其他联系人不受影响。
7. 作为用户，我希望失败任务可通过 HTTP 或 CLI 明确恢复，复用原任务且跳过成功步骤。
8. 作为用户，我希望恢复任务时不能操作其他用户或联系人的任务。
9. 作为用户，我希望普通润色只处理草稿，不因模型调用工具而查询联系人历史。
10. 作为用户，我希望明确要求结合背景的润色仍可在已确认范围内检索资料。

## Implementation Decisions

- 复用既有应用服务、任务宿主、确定性 Worker、PostgreSQL 适配器和 LangChain 回复运行时。
- 历史 Tool 保留完整命中和轨迹，只将本次上下文尚未包含的消息附加为新证据；生成入口继续严格拒绝重复或越界引用。
- 验收使用隔离测试库和合成资料；仅在模型边界使用 scripted fake，不替换导入、记忆持久化、检索或候选存储。
- Worker 仍由用户显式启动。恢复必须显式指定原任务和联系人范围，不自动恢复所有失败任务或改变模型预算。
- 沿用现有重试计数语义：步骤 attempt_count 表示本轮尝试，手动恢复后重新获得最多三次自动尝试；任务 retry_count 保留累计失败与恢复次数。不把它们宣称为累计模型调用次数。
- 已删除或删除中的来源不能恢复导入任务；既有删除任务遵守删除状态许可，失败的删除验证仍可恢复。
- 显式恢复按原任务领取，是对 ADR-018 默认最早领取规则的局部例外，已由 ADR-034 记录；未指定任务时仍取最早可执行任务，全局锁及预检查保持。
- 普通润色在工具暴露及结果校验层遵守本次请求授权；请求背景资料时保持现有有界检索路径。
- 不新增数据库 schema，不修改记忆提取、来源语义核验或采纳算法。

## Testing Decisions

- 用户已确认最高测试接缝为公开 BackendServer HTTP 入口；CLI 恢复通过公开命令入口验证。
- 同一来源依次经过预览、联系人确认、提交、显式执行 Worker、真实检索、候选生成、依据回看、幂等重放和来源删除。
- 覆盖两个联系人及不同用户的隔离，旧依据不可读和候选不能继续；模型不具有外部聊天发送能力。
- 失败恢复证明自动重试耗尽后的实际失败，再通过业务入口恢复原任务，已成功步骤不重做。
- 润色模型主动尝试历史检索，证明未授权时不能读取历史，明确授权时仍能查询。
- 正常闭环可能直接通过，应如实记录；Bug 修复先观察公开接口的行为失败，再最小修复，逐个垂直切片推进。
- 复用既有首导入 HTTP、Worker、PostgreSQL 回复与来源删除测试的设置模式；不使用真实聊天、业务库或外部模型。

## Out of Scope

App、微信渠道现场验收、自动启动记忆处理、增量观察任务接线、空方向建议、回复错误状态分类、记忆语义质量及算法、真实模型评测、正式环境部署、push 和 PR。
