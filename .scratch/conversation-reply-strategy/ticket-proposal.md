# 聊天回复策略：五票提案

2026-10-11。范围和测试接缝已确认，[正式规格](spec.md)已发布；以下粒度与依赖待用户确认，尚无 issues。

1. **回应消息的理解、方向与候选闭环**。Blocked by：无。用户选择消息→查看/纠正理解→换组/自填/确认方向→候选；明确意愿直接生成，暂不回应不生成。覆盖范围、依据、删除、过期建议及既有草稿兼容。
2. **主动聊聊与目的探索**。Blocked by：01。无待回复消息也能从目的生成开口方式和候选；缺关键内容才澄清，不伪造目标消息；目的改口保留兼容约束。
3. **方向探索的受控 Skill 辅助**。Blocked by：01。已启用包可辅助理解/方向，至多一个，可关闭更换；无匹配仍通用流程。用合成包验证 revision、删除、越权拒绝，不创作具体邀约 Skill。
4. **消息组、持续修改与新消息分阶段处理**。Blocked by：02，以及持续会话 04（其前置含会话存储、版本、取消及跨窗口生命周期）。逐条编辑复制消息组；未确认方向只在活跃任务中有界更新；已确认方向/生成/编辑只提醒；复用持续会话版本、取消和删除。03 的 Skill 能力不是本票前置。
5. **两条路径与真实表达组合验收**。Blocked by：03、04。以公开页面、HTTP/PG 验证所有路径、组内一致性、隔离/删除和调用边界；语义对照参照真实表达的已确认评测协议，不等其真实模型评测或外部预算才做合成验收。记录质量缺口，不把原型当产品通过。

可并行：01 后 02 与 03 的验证准备可并行；共享接口改动需协调。真实表达离线评测准备可独立推进。跨功能依赖指向持续会话 04：关闭/离开任务停探索而候选继续、整体退出停止的组合验证需要该生命周期；不要求全部六票结束。最终原生功能若涉及宿主变更，仍须另约有限窗口，合成页面验收不替代真实 App。

确认后依顺序发布 issues/01–05，一票一文件，State: open、Triage: ready-for-agent；现在不创建占位任务冒充已拆票。
