# 04 — 收敛 ReplyStore 的幂等与候选生命周期

Type: task
State: open
Triage: ready-for-agent

**What to build:** 将 ReplyStore 收敛为回复请求和结果的持久化边界，不再负责 Context 选择。它保存最小请求摘要、已验证范围、证据快照、候选和运行状态，并支持幂等重放、冲突、处理中、失败重试、租约过期和用户显式继续历史候选。

**Blocked by:** 02 — 统一回复与改写输入。

**Status:** ready-for-agent

- [ ] 相同联系人范围、请求键和规范化输入的已完成请求直接重放原候选，不再次调用 Runtime。
- [ ] 相同请求键但输入不同返回稳定冲突；有效运行租约内的重复请求返回处理中。
- [ ] 失败或租约过期的请求可以安全重试，并保留尝试状态且只产生一个成功结果。
- [ ] 历史候选只能由用户显式选择后继续；继续会创建新请求并再次验证 owner、contact 和会话绑定。
- [ ] 删除“上一轮未发送候选”的自动继承路径，不根据未观察到发送来推断用户意图。
- [ ] 候选只有在保存成功后返回；Store 不调用模型、不读写 Memory、不识别联系人、不发送消息。
