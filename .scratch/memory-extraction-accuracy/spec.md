# 记忆提取准确率评测与修复规格（v1）

> Triage: ready-for-agent
> 来源：2026-09-15 grilling 两轮决定，用户逐项确认；上游：ADR-024、ADR-026、ADR-027、`architecture/current/pragmatic-interpretation.md`，以及 `.scratch/pragmatic-memory-smoke-test/` 的原型与 24 条对分脚本。
> 范围：只做测量与判对（提示词、字段语义、模型配置、确定性降级兜底）；不改自动采纳安全规则，不做待确认参与回复。

## Problem Statement

记忆提取的判断不止"真假"一种。已知两类错误来自真实使用和上一轮修复：开玩笑、吹牛、假设被当成事实；第一人称完成事实（"我已经提交贷款申请"）被标成转述，导致永远只能进待确认。除这两类外，主体归属、转述与本人、时间与时效、指代消解、改写保真、媒体占位都没有系统测量。没有测量，就既不知道还错在哪，也不能安全地提高自动采纳覆盖率——用户希望不用逐条确认，但那必须以"判得准"为前提。

## Solution

建立一套合成、分维度的标注评测集和正式链路对分工具，用真实模型按最终去向（自动采纳 / 待确认 / 不生成）判对错；按允许手段修错；每个维度达到"假事 0、记错人 0、一般错误 ≤1/15"后才允许该类事实进入自动采纳；用一次模型对照实验选定生产配置；真实聊天只在本机一次性找错，仓库里只保留合成用例与聚合记录。

## User Stories

1. 作为用户，我想让玩笑、吹牛、假设、转述不被记成事实，避免回复引用错误信息。
2. 作为用户，我想让"我已经…""我平时…"这类第一人称真实陈述被自动记住，不因为标签判错而永远进待确认。
3. 作为用户，我想让主体判断准确（self / contact / shared），不把别人的事记到联系人头上。
4. 作为用户，我想让时间状态准确（计划、已发生、已取消、有时效），不把取消的行程记成要去。
5. 作为用户，我想让指代清晰（"他""那个事"指谁、指什么），不产生含糊记忆。
6. 作为用户，我想让记忆文本忠实原意（改写保真），不放大也不缩小事实。
7. 作为用户，我想让语音、图片、表情占位只影响发送行为偏好，不推测媒体内容。
8. 作为用户，我想让自动记忆只在被评测证明可靠的维度上自动采纳，其余安静待确认。
9. 作为用户，我想让待确认候选不打扰我，不需要逐条处理。
10. 作为用户，我想让真实聊天只在本机参与找错，原文不上传、不进仓库。
11. 作为用户，我想让错误在评测里被发现并修复，而不是靠偶然发现。
12. 作为用户，我想知道每类事实的自动采纳可靠度有据可查。
13. 作为开发者，我想用一组可重复的对分用例回归每次提示词或模型改动。
14. 作为开发者，我想让评测走正式链路（同一套提示词、外壳、语用分流），保证测的就是线上行为。
15. 作为开发者，我想用达标签决定每类自动采纳的放行，避免拍脑袋放宽。
16. 作为开发者，我想用一次对照实验在默认配置、思考模式、官方模型之间选定生产配置。
17. 作为开发者，我想禁止"为通过用例写死句子"的修法，保证修的是能力而不是答案。
18. 作为用户，我想在这轮结束后拿到下一轮清单（待确认参与回复、放宽门槛的准则）。

## Implementation Decisions

1. 评测维度与优先级：②主体、①真假与意图、④时间与时效、③转述与本人、⑤指代消解、⑥改写保真、⑦媒体占位。
2. 评测集：每维度至少 15 条合成中文用例（总量约 105 条）；每条包含发送者、目标消息与上下文消息、期望最终去向（自动采纳 / 待确认 / 不生成），可选期望主体；全部为合成内容，不包含真实私人资料。
3. 判定口径：按最终去向判对错，同时记录模型字段错误；术语：假事 = 玩笑、假设、转述等被自动采纳；记错人 = 主体错误；一般错误 = 其余不符。判定由对分工具自动给出，用例期望由用户抽查确认。
4. 对分工具：复用正式提取链路（窗口 → 结构化候选 → 外壳校验 → 语用分流的最终去向）；不连接数据库、不写入记忆；只在显式凭据下发起真实模型调用；输出逐条标签、去向与失败汇总。
5. 修错手段白名单：提示词与示例、字段语义、模型与思考模式配置、生成后的确定性降级兜底（只降不升）。黑名单：写死句子、按用例特判、放宽安全规则。
6. 达标签与放行：某维度在至少 15 条用例中假事 0、记错人 0、一般错误 ≤1，才允许该类事实进入自动采纳；一次只放行一类；放行结果记录在案。
7. 自动采纳安全规则本轮保持不变（语用 CONFIRMABLE + 置信度门槛 0.7 + 风险标签白名单）；修改规则必须单独立项并附评测证据。
8. 模型对照实验：一次性比较当前默认配置、同模型思考模式、官方 DeepSeek（仅在提供凭据时）；检查结构化输出稳定性；胜出配置写入生产默认并记入 `research/`。
9. 真实数据边界：真实聊天只在本机运行找错；只输出聚合统计；原文、命题文本、联系人标识不进仓库、不上传；发现的真实错误经去标识改写、用户过目后可沉淀为合成用例。
10. 词表与 ADR：`CONTEXT.md` 补充记忆候选、自动采纳、待确认候选；ADR-027 记录本轮准确率门槛与待确认方向。

## Testing Decisions

- 只测外部行为：从消息窗口到最终去向（以及主体），不测内部函数或提示词字面内容。
- 合成用例作为仓库内的集成冒烟测试：默认跳过，显式提供凭据时才调用真实模型；开发期对分脚本保留在 `.scratch/`。
- 现有 fake model 单测继续覆盖确定性外壳与语用分流；真实模型准确率不进常规单测（需要凭据、结果非确定）。
- 回归方式：每修好一个维度，用该维度用例回归；新增用例必须来自维度清单，不允许只为已修句子补测。
- 真实聊天原文不进入任何测试夹具。

## Out of Scope

- 待确认候选参与回复（下一批：回复链路证据类型、解释理由落库、界面展示）。
- 修改自动采纳安全规则本身（需要评测证据后单独立项）。
- verifier 复核员（等测量暴露具体问题类型后再定）。
- 记忆巩固任务（合并近义、解决历史矛盾、防膨胀）。
- 语义相似检索（pgvector）。
- 真实数据上传或仓库化。
- 产品界面改动。
