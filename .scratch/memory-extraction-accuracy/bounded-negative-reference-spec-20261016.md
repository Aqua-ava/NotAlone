# E2有限负向指代说明：来访者、家归属与借贷方向

Triage: ready-for-agent

日期：2026-10-16。状态：实施前规格；本文两类规则尚未实现或验收。本片属于[原07](issues/07-reference-resolution.md)及[原准确率规格](spec.md)允许的字段语义与生成后确定性降级，遵循[ADR-027](../../architecture/adr/027-memory-accuracy-evaluation-gate.md)及[ADR-064](../../architecture/adr/064-bounded-negative-reference-notes.md)。原票、旧失败、已封存结果、Gold及默认空放行表保持；实现和实际质量验收继续按核心事实、指代、维度顺序推进。

## 问题与交付

生产默认grounded-v2的`alternatives`目前只有空数组或泛称指代未明，不能具体说明未绑定来访者、裸家位置归属及含糊借钱方向。原文完整引用不等于这些关系已消歧；模型没有报码时，也不能把显式v3/v4的歧义类别伪装成已选标签。

本片只给下列两类完整来源及精确候选包装追加固定、中性的备选说明，不选择人物、房屋所有者或借贷方向。沿同一E2接缝并行准备的借用／请托缺产权或受益人说明复用既有完整`_lend`／`_request`语法，其实施范围单独核验；本文不重定义那一分支。[已有V后负向防护](reference-quote-fallback-spec-20261016.md)仍负责其原降级行为，不在本文改写。

交付是纯负向说明helper、E2专属接线及回归控制。模型协议、动态schema、提示及生产默认版本不变；不增加模型调用，不在V后改写候选，不提供`semantic_basis`、source trust或任何维度信用。

## 实际接缝与纯接口

现有`memory_extraction/grounded.py`的`source_units`按`[^，；;。！？!?\n]+[，；;。！？!?\n]*`定位全文分句；ASCII逗号不是分隔符。`_dependencies`构造实际依赖，编译器据此生成原作者引句、相关原文和`source_message_ids`。本片复用这些实际位置及渲染规则，不另行按关键词剪切来源。

仅在`compile_labels`完成原E2编译和全部原结构／引用校验后、返回E14前调用纯helper；不在共享`_compile`、V结果处理或保存层追加说明。`compile_draft`旧v1、`compile_labels_v3`与`compile_labels_v4`不走该hook，不能通过`ambiguity_codes`为空等宽松判断误接旧版本。

最小内部接口为：

```python
def bounded_negative_reference_notes(
    window: ExtractionWindow,
    *,
    text: str,
    source_message_ids: tuple[UUID, ...],
) -> tuple[str, ...]: ...
```

输入均为本次实际窗口及已编译候选；不接收case ID、Gold、昵称、模型置信度、自由理由、歧义码或来源认证布尔。返回值只能为空或本规格的固定说明字符串，不返回已绑定身份、角色图、已消歧结果、正向支持或写入动作。helper无I/O、不调用模型、不读取文件／数据库／其他联系人。

调用方只在原`alternatives`尾部追加尚未出现的notes，原数组每项及顺序原样保留；不能用新notes替换泛称说明。正文、`source_message_ids`、subject、category、topic、三项语用、日期、risk_flags、confidence、interpretation_reason及其他E14字段逐值不变，模型原始标签与draft追踪保持。即使模型`unresolved=false`或原`alternatives=[]`，完整负向文法命中仍可追加notes；不把它记成模型选择了新类别。

非空备选沿既有`PragmaticInterpreter`保守分流；原unsupported拒绝保持，原unknown／uncertain不能变positive，notes也不能抵消风险或恢复已拒候选。范围外返回空tuple只表示本helper未干预，不表示来源支持或已经安全。

## 共同精确约束

- 窗口及消息均是同一`owner_id + contact_id`的实际输入，消息ID互异、作者仅self/contact；顺序保持，不按时间相同、显示名或模型输出重排。
- `target_message_ids`必须显式提供并精确符合下述单target要求；`None`、空集合、重复target、窗口外target或其他target均不命中，不能沿兼容属性把全部消息推成target。
- 每条来源全文及整个候选正文长度为1–4096个Unicode码点。超限返回空notes，不截断、不缩窗口、不用短片段救命中。每次最多追加两条notes，每条最多8400码点；无法完整携带规定原引句时不追加，不截断引用。
- 所有匹配必须覆盖实际消息或候选完整字符串。不做首尾去空白、全半角、同义词、引号或标点归一化；空格、换行、额外尾句或未列标点均范围外。
- `S`表示空字符串或单个中文句号`。`；`Q`表示单个中文问号`？`或ASCII问号`?`。重复标点、ASCII句号、叹号及未列分隔符范围外。
- `AUTHOR(m)`在actual sender=self时为`用户`、contact时为`联系人`。`O(m)`只可为空或`截至YYYY-MM-DD，`，日期严格来自该消息aware `occurred_at`的来源本地日；无aware锚点只允许空。核O仅是核实际包装，不生成日期或改变原日期字段，不读机器今天。
- 完整包装须按实际SourceUnit和受控作者逐字重建并全串相等。不得用非贪婪正则猜第一个引号，或仅发现片段就忽略其他正文。不能补回候选没有引用的上下文或新增source ID。

## 单消息复数来访：人物与家归属

窗口恰一条消息`m`，显式target恰为`(m.id,)`，候选来源恰为`(m.id,)`。来源全文恰为一个完整SourceUnit：

```text
VISIT = P + T + M + L + S
P = 他们 | 她们
T = 周末 | 明天 | 后天
M = 空字符串 | 要 | 会 | 不 | 不会
L = 来家里 | 来家中
```

M只按表中一个完整值选择，不能拼成`要会`、`不不`或`会不会`；不增加`不要`、`已经`、`可能`、`不一定`、`打算`等变体。不由助词决定真实阶段、发生与否、承诺或绝对日期。

候选必须精确为`O(m) + AUTHOR(m) + 原话：“ + VISIT + ”`；MAIN覆盖来源全文，不允许context、同一原消息续句、前缀合并或第二主张。命中后按人物、地点顺序追加精确两条：

1. `原句中的复数代词未在本窗口绑定到具体来访者；不补人物身份，来访与否及时间仍以原句为准。`
2. `原句只写家里／家中，地点属于谁的家在本窗口未明确；不认定用户、联系人或其他人的住处，也不认定产权。`

这两条只说明该封闭全文没有明确绑定，不建立来访者实体，不把裸家位置归属等同于房屋法律产权。固定说明不插入推测的人名、关系称呼或某一日期。

例如合成正向文法`她们明天会来家里。`与负向文法`他们后天不会来家中。`均追加同样两条中性notes；它们是负向说明命中控制，不是事实正证。`我姐和我哥周末会来家里。`已显式人物、`他们明天会来我家。`已显式地点，以及带角色介绍的前句／第二消息均不在本片文法内，原样不干预；不在其中只补另一半说明。

## 两消息借钱问答：只保留两种可能方向

窗口恰两条实际消息，原序为前问`q`、后答`a`；显式target恰为`(a.id,)`，二者actual sender相反。候选来源必须精确为E2实际顺序`(a.id, q.id)`，两个ID都在窗口内；无依赖、仅引用其一、调换来源、其他source ID或第三条消息均不命中。

名称只作为不透明原文字面标签，不解析或补真实身份：

```text
HAN = 一个U+4E00至U+9FFF码点
LABEL = (老 | 小) + HAN
QUESTION = LABEL1 + 借你钱了吗 + Q
ANSWER = 借了， + LABEL2 + NEG + S
NEG = 没借 | 没有借
```

LABEL1与LABEL2须字面不同，不维护姓氏、人名或用例白名单；上述HAN不验证是否为真实姓氏。多字复姓、开放人名、扩展区字、其他前缀均范围外；相同字而前缀不同仍只当两个不同字面标签，不推断二者是同一个人或有何关系。

`q.text`精确为QUESTION，`source_units(window)`中归属于q的恰一个单元。`a.text`精确为ANSWER，同一实际分句集合中归属于a的恰两个连续单元，第一单元从0开始且精确为`借了，`，第二从其结束处开始，精确为`LABEL2 + NEG + S`并覆盖全文。只支持单个中文逗号；不支持反向顺序、ASCII逗号、分号、插句、额外量值、日期或未列助词。两条消息和两个单元同时全文核对，不能把兄弟单元当作不存在。

每条候选单独匹配其实际主单元`u`，候选完整形状固定为：

```text
O(a) + AUTHOR(a) + 原话：“ + u.text + ”
    + （相关原文： + AUTHOR(q) + 说“ + q.text + ”）
```

无空格或换行；上式仅为便于阅读分行。MAIN必须唯一等于后答两个实际单元之一，context必须且只能是完整前问，作者按各自actual sender核对。主引句内保留其实际逗号／句号。日期前缀若有只能用a，不用q。原标签未为该主单元保留完整前问依赖时，不替它补context或来源。

若E2把两个单元合并成带`同一原消息续句`的候选，或另加其他context／前缀，本片返回空notes；不拆候选、不剥包装、不改变E2标签救命中。对两个分别编译的候选可各自命中；它们各追加两条说明，不能把肯定单元的notes或人物替换后套到否定单元。

命中后依下列顺序追加精确模板，`TEXT`逐字替换为当前完整候选正文，包含它自己的MAIN和完整原问：

1. `所引原句中的“借”，一种可能的方向是向对方借入；人物与肯定／否定仍以所附原句为准，本窗不确认此方向，也不把否定解释为发生。 所附原引句及上下文：TEXT`
2. `所引原句中的“借”，另一种可能的方向是借给对方；人物与肯定／否定仍以所附原句为准，本窗不确认此方向，也不把否定解释为发生。 所附原引句及上下文：TEXT`

模板不把LABEL1／LABEL2认成真实身份，不把前问的人替换成后答的人，不解析肯定或否定来输出现实结论，也不新增接受、承诺、交付、金额、债务、还款或实际发生的交易。即使MAIN为`LABEL2没借。`，也只列“借”可能的词义方向，完整否定仍在附原句中；不能输出“LABEL2已向某人借入”之类肯定主张。

`向／跟／从`、`给／借给`等已明确方向词只要出现在前问、后答或候选中的任一对应位置，便不符合上述全文文法，原样不干预；不能先去掉方向词再匹配。交换输入中的两个字面标签仍须按相同参数化规则判断；只在候选中交换标签、作者或引用而不修改对应来源则必须不命中，不能靠位置猜回原角色。

## 不变项与越界处理

本片不修改E2输入、命名字段、kind枚举、动态schema、prompt、subject语义、日期编译或默认版本，不增模型字段，不用v3/v4码作旁路。notes是程序负向字段补全，不宣称模型报了`entity_identity`、`place_ownership`、`borrowing_direction`或其他code。

原v1/v3/v4提示、schema及同输入编译载荷字节保持；新E2只允许`alternatives`增加受控尾项，其他E14字段与无本片hook基准逐值相等。原model输出、V verdict/issues/evidence与既有program降级追踪分别保留；V收到的是已经带notes的候选，不在V后补写。生产空表、0.7、风险／语用门、来源及删除路径均不改变。

单消息产权分支、本文来访分支及借钱问答分支按各自完整窗口合同互斥，不靠case标签分派。未命中、超限、缺target、包装不完整或来源／作者不符均返回空notes；不能追加泛称冒充具体规则已经通过。原E2结构错误仍由原编译器拒绝，不借本helper修复非法draft。
