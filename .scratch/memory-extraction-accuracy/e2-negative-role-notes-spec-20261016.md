# E2完整引句中的未解角色说明

Triage: ready-for-agent

本片是[原07](issues/07-reference-resolution.md)允许的字段语义修复，补足[既有V负向防护](reference-quote-fallback-spec-20261016.md)只保守分流、未具体说明缺失角色的表达缺口。V片原先“不改compiler／备选”的约束仍适用于该V处理阶段；本片在E2编译阶段追加说明，二者职责不混用。当前只有隔离分支的合成验证，未认证真实模型质量或关闭原票。

## 行为与边界

仅在`compile_labels`完成原E2编译后，对每条实际候选调用共享纯helper。复用V防护已有单消息、单实际target、精确来源、实际作者完整引句、4096码点及`_lend`／`_request`完整文法；不新增匹配文法、不用case ID、Gold、昵称或关键词特判。

仅当原完整文法解析出缺失`property_owner`时，追加：

> 原句中的物品所有者在本窗口无法唯一确定；不因出借或接收认定所有者，保留原句。

仅当原完整文法解析出缺失`beneficiary`时，追加：

> 原句中顶班事项的受益人在本窗口无法唯一确定；不因提出请托认定受益人，不补接受或履行，保留原句。

既有泛称备选及其顺序原样保留，新说明置于末尾。正文、来源、主体、类别、三项语用、日期、风险、置信度、解释及所有其他E14字段不变，原模型标签和draft仍可回查。原`unresolved=false`也可命中文法，但不能记成模型选择了歧义码。范围外不追加、不补身份、不授予来源或任何维度信用。

共享helper返回中性说明或null，原V接口只复用“是否缺角色”的结果，继续按原合同仅将最终supported降为uncertain/pragmatics，并保留模型原判定。V不追加说明、不改E候选；E2增加备选后沿既有语用分流保持保守。原uncertain／unsupported不能变positive。

旧v1、v3、v4编译分支不走本hook，同输入规范载荷、schema及prompt保持；E2 schema、prompt、模型字段及默认版本也不变。生产空放行表、0.7、安全门、来源及删除路径保持。本文不实施来访或借钱问答规则，其另见[后续有限文法](bounded-negative-reference-spec-20261016.md)。

在实际E2纯编译及SDK Mock路径先复现缺具体说明的红灯，再核缺产权／受益人、否定、self/contact、既有泛称保留、已明身份、错作者／包装／来源、多消息、范围外及全部其他字段不变。SDK必须确认原grounded draft不变、说明来自compiled阶段；旧V处理和全部旧协议反控保持。
