# E2有限字段语义与来源日历：实施前修复草稿

Triage: ready-for-agent

日期：2026-10-16。状态：仅供Root复核的普通修复规格草稿，尚未实现、测试或运行模型；本稿不授权自行扩大文法，不宣称已覆盖全部公开缺口。归属[原07](issues/07-reference-resolution.md)及[原准确率规格](spec.md)，采用[ADR-027](../../architecture/adr/027-memory-accuracy-evaluation-gate.md)允许的字段语义与确定性只降不升路径，不预设升级模型协议。

## 问题、目标与不变项

固定ref源码`20d73f5e`的纯编译审计显示：模型可填写的E2 kind与程序映射不能表达若干已存在的未知语用组合；条件句首和日历范围也有限。实际140窗、138个required命题的必要字段扫描中，10项语用四元组与另15项日期组合不可达，113项仅有六字段编译见证，不是完整Gold或质量合格。这些问题早于来源参考v2；v2只改了原产权例的解释与去向。审计不能据此认定所有白名单修法无效，也不能把扩kind当作日期问题的充分方案。

本片建议保留生产grounded-v2的模型输入、prompt、命名schema、kind枚举、原model draft及默认版本，在E2实际编译路径内增加有限字段语义策略，最终E14仍沿原Adapter返回并由Flow封存`candidate_raw`。负向规则只减少确定性；日历规则仅从完整明示表达计算既有检索期间。它们都不恢复省略项或给予来源／维度信用；条件正文只由已显式标作condition／prefix的实际相邻SourceUnit按原合并渲染合同保留，不生成自由改写正文。

对原来可编译的同一成员组，可变字段为`speech_act/assertion_status/figurative_type/valid_at/invalid_at`，另有下一段唯一的期间派生标记。正文、subject、category、topic、来源、confidence、alternatives、interpretation_reason及其余E14字段不变；不增加输出键，不删除或新增候选。原来因有限condition句首校验拒绝的新合法配对，按既有条件合并合同首次生成一个含全部成员的E14，不冒称有可逐字比较的旧成功载荷。模型原kind与draft不改；独立事实错kind造成的剩余不相容如实保留，不能靠程序替模型补类型。

`risk_flags`仅允许`grounded:unresolved_period`沿原规则、由最终受控期间是否缺失派生；新的日期计算在该标记派生之前完成，不在结果上随意删风险。原period分支最终valid_at为空则保留／生成此标记，完整计算成功则不带已过时的“期间未明”；其他kind不借本片新增此标记。所有敏感风险、模型原风险及其他程序风险逐值与顺序保持。此为同一日期规则的数据流修正，不是采纳风险白名单或安全门放宽，不改变plan／unknown等保守分流。

旧v1/v3/v4的prompt、schema、同输入编译载荷字节及旧冻结结果保持；E2同窗口schema与prompt SHA保持。既有完成短答、notes-only片、原V、采纳门、0.7、风险规则、默认空放行表及来源删除路径保持。真实模型、Gold、私有材料、业务迁移、桌面和远端Git不在起草范围内。

## Module、Interface与接线Seam

按codebase-design比较两个Seam；它们都不能修改模型draft或增加一次E/V：

| 选择 | 调用方Interface与Implementation代价 | 条件硬缺口 |
| --- | --- | --- |
| a．Adapter在原编译之后处理E14 | 要新增公开wrapper／结果DTO，并从作者引句、观察前缀、MAIN和context逆向重建已经存在的units与依赖；解析和结构知识分散到两处 | 原编译已因condition句首拒绝时拿不到E14，后置规则无法修复 |
| b．E2实际compile路径的内部策略（选择） | 保留`compile_labels(window, draft) -> ExtractionPayload`；复用`_compile`已持有的units、rows、members、dependencies及原单次渲染，仅增加E2入口显式启用的私有策略 | 在旧句首判断前识别下文完整配对，合法新condition可进入原合并路径 |

现有位置见ref源码`grounded.py`：`compile_labels`约449行、`_compile_named_labels`约499行、`_checked_compile`约236行和`_compile`约248行。最小接线是在上述私有调用链传递默认关闭的`e2_semantics`开关，仅`compile_labels`置true；v1 `compile_draft`、v3／v4入口保持false，不能以`not version4`或`completed_answers`推断E2。所有共享分支在false时沿原顺序执行，旧路径字节用实际入口逐一验证，不复制一份编译器。

内部Implementation分两处，保持同一Module：先在`pending_condition`和旧`_CONDITION`检查前，用实际相邻units及rows校验完整C/A配对；再复用已定位的成员、依赖、原类型与旧期间，计算五字段的最终值，之后沿原条件派生`grounded:unresolved_period`，最后交原renderer一次生成E14。有限语义逻辑可提为私有纯函数；不暴露独立解析器、成员DTO、规则DSL或新的公共wrapper。原有泛称condition／prefix路径仍保留，本片只增加完整结构许可，不把未列条件猜成新句法。

原`grounded_adapter._extract_grounded`约291–297行已经记录`grounded_draft`（实际units＋原draft）及最终`grounded_compile`（返回E14），本片不再新增`E2FieldSemanticsResult`、decisions DTO或第三种追踪事件。新冻结记录实际源码／策略版本，给定draft可确定性重放；字段before/after在纯编译控制中与关闭本策略的原路径对账即可，生产不重复编译／渲染来保存第二份E14。现有追踪已经能回答模型标了什么、程序返回什么，新DTO没有本片必需的额外价值。

策略没有I/O、墙钟、环境变量、模型、数据库、文件或Gold依赖，不原地改window／draft。SDK Mock仍跨默认GroundedExtractionRuntime→实际`compile_labels`→最终E14，Flow封存该raw后沿同一次V；V的unsupported仍删除候选，uncertain仍保守，不恢复省略项。追踪失败沿现有停止规则，不新增修复请求或重试；schema SHA不变不等于编译字节合同不变。

与[角色notes片](e2-negative-role-notes-spec-20261016.md)及[来访／借贷notes片](bounded-negative-reference-spec-20261016.md)互补：它们仍在E2原编译返回后只追加alternatives；本片不改notes helper、模板或其余字段承诺，也不要求这些helper承担语义解析。新语义值在原E14构造前确定，notes照常消费最终原文包装。

## 所有规则共用的来源与表示核对

处理单位是已经编译的实际MAIN对应的一个完整SourceUnit，或编译器已经合并的同消息相邻MAIN成员；不要求每条来源消息都成为MAIN，也不允许从一句内部任取短串充当完整单位。窗口及target原样保留，单次处理仍沿E2原20目标及前后文预算；本片规则只在最多4条实际消息、每条与候选正文不超过4096码点、最多两个MAIN成员及最多四个已印出context的有限作用域中工作，超界不裁剪输入。

原target集合必须显式；每个候选MAIN须唯一定位到同一条实际消息，且该消息在原target集合中，不要求整个窗口只有一个target。不把其他原target改成context，不用`target_message_ids=None`的兼容推断制造命中。候选`source_message_ids`非空、唯一、同实际窗口并含该target；本Module不补ID或换顺序。完整实际消息用于SourceUnit切分、唯一位置和竞争作用域检查，其他未引用背景不参与字段语义判断。

复用现有编译对象而不逆向解析渲染文本：外层作者取actual sender；原观察前缀若存在仍按MAIN消息时间由原renderer生成；MAIN成员逐字相接；相关原文及作者直接取实际dependencies，所属消息必须在同次构造的source IDs中。语义判断只用本次renderer确定会完整印出的成员／依赖，保留实际引号、逗号和上下文顺序，不再截引号或剥观察前缀。未知第三人续句合并、位置不唯一、缺必要依赖或超界均不由本片抢救；新条件配对除外，其范围在下节明确。原模型字段、指代及Flow来源校验继续执行，不能因新策略绕过原拒绝行为。

必须区分“完整窗口存在”“候选实际引用”“相关文本已印在候选正文”三件事。依赖其他消息的规则要求三者全部成立。不得从未引用背景取得语气、原因或时间，不把source ID存在当作已保留该消息所需正文。

本片不对媒体占位做转写，不因原文出现`[语音]`赋予可信正文或媒体信用；只处理E2已经实际复制的相应文字单元，不能剥媒体标记救命中。合法来源与包装仍不认证中文主张或现实真伪，V继续核完整候选。

## 负向语用的封闭字段变化

首批仅允许以下变化，不允许inverse转换。已为unknown的字段保持；hypothetical/reported/conditional不被改回asserted；joke/sarcasm/hyperbole不改成unknown、literal或可保存条目；question／nonliteral省略不复活。对已有unknown不套更确定的conditional来缩小未知。

| 负向族 | 已有字段前提 | 仅允许的变化 |
| --- | --- | --- |
| 可能性计划 | category=recent_state，speech_act=plan，assertion_status=asserted | assertion_status→unknown |
| 可能性当前状态 | category=recent_state，speech_act=assertion，assertion_status=asserted | assertion_status→unknown；既有观察点保持 |
| 已引用质疑语境 | 原figurative_type=literal；候选已完整引用下述质疑 | figurative_type→unknown，不宣称确实撒谎／夸张 |
| 未明阶段的时钟持续句 | category=recent_state，speech_act=assertion，assertion_status=asserted | speech_act与assertion_status均→unknown；原观察型日期清为双null |
| 明确条件 | category=recent_state，speech_act=plan，assertion_status=asserted | assertion_status→conditional；不改人物、动作、条件正文或类别 |

“当前”与“计划”的选择仍来自原编译字段及完整句法，不把出现“可能”本身当成计划类型。多个规则同时适用时逐字段只沿上述更保守方向合并；发生互斥解释则不写更具体标签，保留原候选并记录UNKNOWN，不能按规则顺序选一个解释。

### 可推广词元与可能性句法

下列记号是文法符号，不是允许原文包含空格或加号。`S`为实际单元末尾空串、单个中文逗号或单个中文句号；内部只支持表中中文逗号，不新增换行、ASCII逗号或任意标点归一化。词法匹配保留完整实际偏移。

`SUBJ`只为`我/你/我们`或空；它是原文词元，不建立新的身份绑定。`U`为`可能/也许/不一定`，`FUT_UNKNOWN`为`以后/将来`。当前状态词元为`感冒/发烧/咳嗽/头疼/头晕/不舒服`，程度为`有点/有些/稍微`或空。首批可能性状态为`SUBJ + U + 程度 + 状态 + S`，不能仅扫描单字“可能”。同消息其他独立单元不被合并成同一状态或继承其不确定性，原句完整保留。

可能性计划为`SUBJ + (U + [TP] | TP + U | FUT_UNKNOWN + U) + [不] + EVENT + S`，其中TP/EVENT取下文封闭结构，不能是自由全文。时刻无法定位的FUT_UNKNOWN只保留未知，不填绝对日期。明确事实中的“可能性”名词、问句、否定“没有这种可能”、引用别人说法或未列顺序均不命中。

EVENT采用有限操作词与不透明原文参数，不用目的地、人名或具体业务句子许可表：

| 操作族 | 全部形状 |
| --- | --- |
| 移动 | `去/回/来/到 + PLACE + [玩/旅行/出差/发展/参加OBJECT]` |
| 位置状态 | `在 + PLACE + [工作/值班]` |
| 独立活动 | `入职/出发/休息/露营/爬山/吃饭`；`露营/爬山/吃饭`还可带一个紧邻的`去` |
| 参加 | `参加 + OBJECT` |
| 条件回应动作 | `请你 + (吃饭/喝茶/爬山/露营)`或`带你去吃 + OBJECT` |

PLACE和OBJECT均为1–32个实际汉字的原文字面参数，不判断其是真实城市、食物或实体，不允许再夹SUBJ、时间词、否定／完成标记、引号、连词或另一个操作词。已列尾缀为保留词，不能又吞进PLACE形成两个解析；参数若与这些结构词冲突或出现两种完整解析，UNKNOWN，不按最长城市名猜。`然后/但是/不过/另外/其实/并且/还要/已经/刚刚/刚/曾经/取消/改期`不被当成无意义尾串吞掉。此词法刻意有限，不能对任意中文谓词承诺覆盖。

`去露营/去爬山/去吃饭`作为上述完整活动匹配，不能把活动词吞作PLACE来绕开保留词约束；没有对象的`去`、重复`去`或给未列活动自动加前缀均不命中。非Gold参数控制须同时覆盖三种合法活动、显式移动到PLACE及单变量反控。

### 已引用的质疑语境

只支持恰相邻的两条实际消息：先述说法`p`、后质疑`q`，作者相反，MAIN属于p且p为实际target。p全文为一个财务说法单元，或两个以单个中文逗号相连的财务说法单元；每个单元只可为`[TP] + AMOUNT + 到手`或`[我] + 贷款 + AMOUNT + (加仓/投资/周转)`。AMOUNT为非零ASCII十进制整数1–999999、可接1–2位小数，再接`w/万/元`；只做全文定位，不换算金额或认定资产／债务。词元之间可有0–1个U+0020空格，位置固定在TP、AMOUNT、贷款和操作的连接处，不能全局trim或去空白。

q全文只为`你 + [又] + [开始] + (吹/吹牛) + [了] + [。]`。候选必须已经具有两条来源，并在其实际context中逐字印出完整q及正确作者；MAIN必须是p中的一个完整财务说法单元，不能靠窗口里恰好有q就降literal。q未列来源、未印入正文、只印半句、作者相同、有第三消息或其他竞争被质疑说法均不干预并记录能力边界。

该负向规则只表示字面可信度未明，不认证“确实在吹”、因果、心理或现实金额；不新增alternatives、reason、风险或来源。p的两个说法不能互借日期：一个单元中的“明天”不能移到另一个贷款单元。模型没有把质疑加入dependency时，保留实际编译结果，不替它补依赖来凑字段。

### 裸时钟与阶段未知

只处理完整MAIN为`[今天] + [我] + V_DURATION + 到 + H + 点 + S`，V_DURATION为`加班/工作/值班/学习/等候`，H为`一/二/两/三/四/五/六/七/八/九/十/十一/十二`。没有“已经／刚／了”等完成标记，没有计划／准备／要等未来标记；首批不处理其他日期词。此表达不足以唯一确定完成／安排阶段及12小时制时段，在表中字段前提下只降为unknown并清原观察型日期，不补上午／晚上，也不认定加班实际已完成。

显式`明天`不按此规则降阶段；明确完成或明确计划不被裸钟点规则覆盖。MAIN是同消息第二单元时，只校该完整单元；前一到家事件不能把这一单元的阶段或钟点变成已证。若候选把两项合为不能唯一拆回的完整表示，则不干预而不是删第一项。

## 条件与时间作用域

明确条件仅接受以下完整框架；C与A须由同一目标消息中紧邻、偏移连续的两个完整SourceUnit组成，前件以单个中文逗号结束，主句不是另一个条件。A为`[SUBJ] + [一定/就/才/只] + EVENT`，或带下文唯一TP的相同动作结构；末尾取S，不用context／窗口背景补C，也不临时合并两条消息或两个已有独立事实候选。

```text
[T0] + (如果|假如|要是|倘若|若) + C + ， + A
C + 的话 + ， + A
你 + 要是 + C_MOVE + ， + A
```

C的闭集为：`[TC] + (下雨/降雨/不下雨/不降雨/天晴)`；`[TC前] + (能完工/能完成OBJECT/能做完OBJECT)`；或`(我|你) + (来|去|到) + PLACE`。C_MOVE是最后一项去掉其开头“你”的形式。TC前只在条件截止位置作为deadline，不生成事件的validity；不支持开放条件谓词或嵌套条件。T0、TC及主句TA必须由不同实际位置定位，不能只见一个时间词就共用。

首批新增结构许可要求模型前件原标签为`condition`或`prefix`、主句原标签为`plan`；不能把`question/nonliteral/not_memory/greeting`或普通独立事实擅自恢复成前件，不篡改原标签。编译器先对完整两成员检验上述产生式，建立仅在本次调用有效的配对，再进入原`pending_condition`合并路径：`condition`的新全文许可替代这一个配对的旧句首失败；`prefix`在完整配对中也获得明确条件性，不能仍输出asserted。它们复用原成员、双方显式dependency并集、来源去重、最低confidence、风险／未知传播和同一次原文渲染，最后只将主句asserted降为conditional；来源循环、越界、漏标签及原指代guard仍拒绝。

因此`你来PLACE的话，A`、`你要是来PLACE，A`和`TP要是不降雨，A`在合法现有E2标签下必须真正编译成功，不能先让旧`_CONDITION`拒绝再称其范围外；使用prefix标签也不把是否合并或是否conditional留给模型猜句首。原模型把前件误标独立事实／省略、主句误选非plan、前后不连续或缺实际目标覆盖仍是错标签／来源边界，不能为救此输出改category或补未引用单元。原来已受支持的hypothesis等条件路径继续执行旧行为，本片不借新增许可升级它们。

建议首批作用域决定如下：

- T0明确位于条件连词之前时，作为整个条件安排的外层日历框架；没有另一个TA时可计算该框架，仍不认证条件已满足。
- A自身有TA时只按TA计算动作检索期间；TC是天气／完工前提的限定，不混成同一期间。“周五前能完工”不能把“周末休息”的起点改为周五，也不能因TC与TA不同就粗暴清掉TA。
- 只有条件内部TC、动作没有TA或外层T0时，不把TC转移给动作。可取得conditional字段，但本新规则不填动作日期，记录作用域UNKNOWN；这保留了已知“条件内下周天气”日期缺口，不能宣称全部解决。
- 主句和条件都明示不同框架且无法解释为上述TC/TA分工，或T0与TA冲突时，日期UNKNOWN，不按Gold选择一项。否定只作用于它所在的C或A节点；不再以全文有“不”就判整个安排取消。

新全文文法不命中时回到原编译合同：原prefix成功路径仍保持，原condition结构失败仍可见拒绝，不假造一个成功候选。新策略不修改模型schema，也不把原prefix字段回写为condition；对已完整满足上述实际成员和标签合同的配对，由编译器完成合并及负向字段变化，不再把既有有限词法拒绝列作模型待修缺口。

## 独立日历解析与检索期间

日历不是对语用结果的正向认证，也不是unknown→asserted。只在已有recent_state及相容的原计划／临时状态上，完整解析actual MAIN及其明确作用域后改日期；不把common_fact、历史relationship_note、correction或已完成问答改成近期状态。无明示期间的历史事件继续双null。观察前缀O只是陈述观察日，不当作事件日期输入。

### TP闭集与计算

以下是单个最长完整TP，不能拆短串重试。D仅一/二/三/四/五/六/日/天，日和天均为星期日；同一表达不混用两套历周。

| TP | 明确规则 |
| --- | --- |
| 今天／明天／后天 | actual来源本地日、次日／后两日的当地午夜至下一当地午夜 |
| 本周／这周／下周 | 以来源本地日期所在周一为基准；下周再加一个历周，结束为相邻周一 |
| 本周末／这周末／周末／下周末 | 对应历周周六至下周一；不因机器今天或来源已过周末滚动到另一周 |
| 本周D／这周D／下周D | 对应指定星期的当地整日 |
| 周D | 只在该日仍位于来源当前历周且不早于来源本地日时解释为该整日；已经过去的裸星期UNKNOWN，不自动滚到下周 |
| WD到WD／WD至WD | WD为上两行星期表达；右端裸周D继承左端显式历周，只支持同一已定位历周的非反向范围；结束为最后指定日的下一午夜 |
| 下个月／下月 | 来源年/月的下一个日历月首至再下一个月首，不按30天或固定秒数；12月跨年及闰年按日历构造 |
| DAY＋CLOCK | DAY为上述单日；CLOCK只支持上午一至十一点、下午一至六点、晚上六至十一点、中午十二点，开始为该明确本地钟点，结束为下一当地午夜 |

裸H点、凌晨／午夜／晚上十二点、分钟、24小时制声明、跨周范围、月份局部、绝对日期、时长、往后数日、模糊大约／左右及其他未列形式不在首批正向计算范围；它们不能短串退回某个已支持DAY。DAY与CLOCK必须属于同一实际动作节点，不跨单元拼接日期与钟点。CLOCK的结束只是既定检索边界，不宣称活动持续至午夜或真实结束时刻。

主句完整时间结构只接受`[SUBJ] + [M前] + TP + [M后] + EVENT + S`，M前/M后取空或`计划/打算/准备/要/会/约好/一起/都/临时/只/就/才/可能/也许/不一定`，两位置最多一个非空值；可能性标签仍由上文负向规则独立决定。否定动作只可在EVENT前有单个`不/不会`，保留原文字面，不据此认证动作发生。位于句尾的TP、第二个独立动作或额外前缀不凭此规则猜归属。

PLACE/OBJECT中不得藏入另一个已识别时间表达、比较边界、未列时间限定或连词。实现须先对整个MAIN及其实际依赖作最长词法扫描，检查所有时间表达，再进行唯一结构解析，不能只拿首次命中的“下周／下月”算日期。阻塞词法至少覆盖带前后缀的日／星期／周／月／年表达、数值／中文数量或半／几／数的时长、月初／中旬／月底、之前／之后／起／左右／期间／以内等完整限定；它们只使本次解析UNKNOWN，不产生新日期。裸“月／日”作为地点字的一部分不单独当时间，例如不靠单字命中把参数全局判成时间。

### 观察点与明示期间

- 原临时state只有“本周临时在PLACE工作／值班”这一当前容器时，起点仍是actual occurred_at观察点，终点为该容器结束；不冒称从周一已经开始。观察点须在该容器中，否则UNKNOWN，不替模型改成未来plan。
- 原文明确“本周一到周三”一类完整起止期间时，保留明示期间本身，包括早于观察点的起点，不机械clamp到来源日。它仍是原文给出的检索期间，不是程序认证已连续成立。
- 原计划的指定日、月、日历范围及明确钟点按TP完整区间；已有unknown／conditional／hypothetical保持原值，填期间不提高确定性，不清敏感或模型风险；唯一期间未明标记按前述最终period结果派生。
- 没有新规则匹配且沿原E2已有观察点的候选保持其原行为；不是所有日期都由本片接管。模糊阶段族已经把原观察型日期清为双null时，日历步骤不能重新写回观察日。

### 锚点与UNKNOWN

唯一锚点是实际承载该TP的已引用消息`occurred_at`，须为aware且`utcoffset()`非null；不得改用其他消息、机器今天或导入时间。跨消息只有候选已明确引用并印出该TP及其实际作用域时才可能使用对应锚点，首批正向计算建议只开MAIN自身同消息TP，其他位置保守UNKNOWN。原始本地偏移若在正式加载中已丢失，不靠旧记录推回，相关生产能力保持未验；纯UTC／offset算术控制不能替代正式读写证明。

按本地日历构造边界并保留来源tzinfo，不用“86400秒等于一天”替代日历；具名时区的不存在／重复本地边界、反向／空区间、年份越界均UNKNOWN，不任选fold或自动修正。原固定偏移同样保留实际偏移。

“看见时间词”或“框架识别成功”均不获得清日期权限。内部沿用原kind与本次日期赋值位置，区分`observed`（state／momentary_state／request的原观察点）、`period`（plan／hypothesis的原期间）与`none`；它只是同次编译的局部来源，不新增产品字段或追踪DTO。新规则的结果分别是完整计算、`out_of_scope`或`calendar_unknown`，UNKNOWN本身默认不写任何日期。

仅同时满足以下合同才可把非null原日期清为双null；否则保留原值，不为统一UNKNOWN擦掉合法日期：

1. 来源／目标／成员／依赖共同校验已通过，本片已完整接管同一动作的有限时间句法：整个MAIN是上表时间动作框架，或完整C/A配对；其中阻塞TP也须占据明确的TP位置并由封闭最大词法完整覆盖，不能靠任意尾串兜底取得接管权。
2. 原类别／语用相容，原日期确实来自当前`period`分支，且非空字段完全属于这一个动作的旧`_period(quote, anchor)`结果。观察型日期、request、已完成／历史事件、未知第三人合并结果及范围外表达均无此清除权限。
3. 已得到具体的“不可靠”见证：旧期间只取了同一TP的短日／周部分而完整TP含未支持钟点／数量／前后限定；完整作用域表证明旧期间仅来自TC而非T0／TA，或T0／TA冲突；或旧期间本地边界不能通过本稿aware／时区唯一性校验。仅有未知新词、解析器没实现、另一条未引用时间或不同dependency的时间不构成见证。
4. 本片无法完整计算替代期间；若能完整计算，直接写该受控期间，不先清空再回退。原双null仍双null，任何失败均保留原候选全文和其他字段，不转成none。

`calendar_unknown`只报告计算或作用域尚未知；满足上述四条时才清本片拥有且已证明不可靠的原period字段。尤其普通state有效观察点、momentary_state的原当天边界以及临时request的观察日期，不能因日期词法未列、锚点能力未验或新日历解析失败而清空。完整显式期间正向成功时可按上一节替换相容state的观察型期间；失败即保留原观察点。裸时钟阶段未知清观察型日期是前述独立负向规则的明确合同，不能混作calendar_unknown权限。

本稿中的`out_of_scope`／`calendar_unknown`及不可靠见证是实施与控制报告分类，实际返回仍为原E14，不要求新增说明、risk或trace事件。仅负向语用族可以改语用标签，不能因日期失败猜阶段。未接管的旧日期不被本策略重新认证；“保留原值”与“新日期已核清”分别报告。

## 主要取舍与实施时须记录的局部修订

1. 选择E2实际compile路径内的私有策略而非Adapter后置wrapper或新增model kind：原schema/prompt保持，复用现有units／members／dependencies及单次渲染。生产保留原grounded_draft＋最终grounded_compile即可，不为保存基线另加DTO／第二次编译。现有V后加risk不修raw标签，不能作为本片实现替代。
2. 来源日历是明确期间的字段计算，不等于负向规则，也不认证事实；选择只支持完整封闭TP而非通用中文时间解析。它与现行domain-data“不套固定天数”的约束一致，但不能把任何可算日期当作正确作用域。
3. 实施记录须局部续接[ADR-051](../../architecture/adr/051-grounded-memory-extraction.md)三点：E2新增有限condition／prefix完整配对许可；保留模型kind但对已列五字段执行完整来源的负向／日历规则；否定从全文一票UNKNOWN收窄为已完整解析C/A节点的作用域处理。未支持修饰继续不正向计算；观察型日期与清期间权限按本稿分别处理。原完成短答、来源／指代guard与原V不改。
4. 实施记录须局部续接[ADR-059](../../architecture/adr/059-closed-unknown-kinds-and-calendar-month.md)的版本说明：该ADR承诺的旧v2/v3字节是历史v4增量的隔离约束，本片作为后继E2-only普通修复改变当前E2编译表达，保留其旧封存，当前v1/v3/v4字节及模型报码路线继续不变。不能把v4类型／歧义码或其旧质量信用套入E2。此后继记录属于原07允许范围的实施说明，不是新增用户架构许可问题；本起草任务仍不修改ADR。
5. 首批不把只在条件内部出现的TC推成主动作期间，也不补E2没有引用的质疑；两者列为真实剩余范围。`calendar_unknown`只有完整接管＋period归属＋具体不可靠见证＋无替代计算同时成立时才清期间，观察state／request及范围外正确日期保留。该范围仍由Root审规格后分片实施，不为减少回归恢复短串兜底或泛化为开放语义解析。
