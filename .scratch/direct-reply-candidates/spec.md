# 检索后直接生成候选，由用户选择发送

2026-10-18 用户要求取消生成后的独立模型回复核验，采用检索记忆后生成候选、本人选择和发送的流程。决定见 [ADR-068](../../architecture/adr/068-direct-reply-candidates-with-user-selection.md)。

## 交付行为

- 正式回复接线不再调用 `ReplyFidelityReview`；有效候选通过确定性检查后直接保存、返回和恢复，不按模型复核结果筛选。
- 继续将当前用户意图、有效记忆、背景和 Skill 提供给生成模型；保留资料按需读取及原输入预算。
- 保留范围、来源、引用、输出结构、幂等、取消、删除与保存前复验。用户选择、编辑并亲自发送，系统没有外部消息发送能力。
- 模型台账只记录实际发生的请求，无伪造复核记录；不将候选标成已通过语义核验。
- 回复质量合同明确本次运行策略并绑定生产接线，旧资格不自动转签。记忆入库、L2/L3 整理核验和离线质量资格保持。

## 实现与验证

复用已确认的公开 HTTP → 正式回复接线 → 隔离 PostgreSQL 接缝，只在外部模型边界返回合成响应。检查直接返回、同键重放无新调用、改写与来信输入、引用拒绝、生成中来源删除仍阻止保存；保留现有助手任务和恢复路径的相关回归。旧复核协议的独立诊断测试仍可保留，但不再作为生产调用次数或候选筛选要求。

不新增界面流程、数据库迁移或真实模型对照，不重启已暂停的记忆质量任务。已有真实质量失败保留原结论。
