# 记忆与 Skill 演进：正式规格

> Triage: ready-for-agent
> State: open
> 日期：2026-10-14
> 状态说明：产品规则与实现规格已形成；任务拆分待用户确认，尚未发布实现任务或实施本规格。DSH 选型搁置，沿用现行回复运行时。

## Problem Statement（用户问题）

历史资料可能把过去状态误当成现在，重复提取可能让旧错误回来，用户也难以查看关系变化和自己的稳定资料。回复经验没有形成可审阅、可调整的长期方法；若直接自动写入，又可能把一次性意见、偶然反应或某个人的私人事实变成长期策略。

用户希望按完整功能完善记忆、检索与表达方法，参考先进项目的机制，自动发现有用经验后集中审核。基座选型不应阻塞这些功能；用户不需要重复回答已经确认的问题，也不需要审核数据库、接口或每条边界各自拆出的任务。

## Solution（解决方案）

交付 8 个完整功能：记忆持续更新、记忆纠错、长期概览、检索辅助回复、明确表达偏好、自动学习 Skill、根据反馈调整 Skill、现有资料升级。新增能力接入现有联系人、来源、记忆、后台任务、回复和 Skill 库模块，使用当前 React 界面提供操作入口。

以下规则是本规格的验收依据，不表示已经实现；与旧规格的冲突及保留边界由 ADR-048 记录。

### 1. 记忆持续更新

- 过去成立的状态保留来源和时间。区分“当时如此”“有依据的当前状态”和“当前未核实”；缺少结束时间、采纳时间较新或资料仍为 active，均不能单独证明临时状态现在成立。稳定事实不因这一规则被统一套上过期天数。
- 来源聊天时间、保存时间、事实发生时间及有效区间分别呈现。来源缺失时保留未知，不以导入时间或当前时间补齐；短期有效区间只依据可核验的时间信息确定，不发明统一有效天数。
- 新旧变化形成可追溯版本关系。相同事件和证据去重；不同时间发生的同类事件不能只因措辞类似就合并。依据不足的“同一次事件”判断不自动合并。
- 计划、约定、已发生事件分别标记；约定到期不自动变成已经发生。真实取消、改期或完成须有新的有效依据。
- 低风险自动更新仍需通过现行全部采纳门槛，并标记 `auto`、可查看和撤销。默认维度放行表保持现状；手动确认、纠正和否决不能被自动更新覆盖。

### 2. 记忆纠错

- 用户可修正或否决记忆并查看来源与版本。相同旧证据支持的同一错误含义不得因换一种说法又生成待确认候选或再次采纳；旧记录可以只用于追溯。
- 确有新证据时允许提出新的待确认结论，说明新依据及与旧纠正的关系，不静默取消用户决定。语义判断不确定时安静阻止重复发布或保留内部待核结果，不扩张自动采纳权限。
- 历史回复依据被修正、否决或替代时，显示“依据已变化”；明确继续旧候选时重新核验并生成新结果，保留用户当前意图，不直接重用旧事实。来源删除遵守内容清除，不以历史回看为保留例外。

### 3. 长期概览

- 提供一位联系人的经历与关系变化概览，以及用户本人的稳定事实和明确偏好概览。区分过去与当前未核实，每项都能追溯来源或手动录入。
- 概览是可重建的派生资料，不成为新的事实源，也不替代现有联系人记忆目录。更新、纠错和来源删除使相关概览失效或重建，旧投影不再进入生成。
- 本人概览只能包含真正归属于本人的资料；不能因多位联系人都提到某件事，就把联系人事实写成本人事实或向另一位联系人泄露私密内容。
- 后台概览不主动做深入性格、动机或关系判断。独立关系分析继续由用户明确指定范围后触发；新增完整分析入口和分析产品不属于本规格。

### 4. 检索辅助回复

- 保留词法检索基线，按同一联系人及本人范围检索当前相关资料，必要时在既有次数、条数和输入预算内补查原始消息。关键词调整不得扩大联系人或授权资料范围。
- 原始消息、已采纳记忆、未确认参考、历史状态和概览保持证据类型区别；待确认候选沿用强制标注和独立预算，不能作为确定事实。
- 概览用于导航与有界选择；使用某个概览结论时回到仍有效的底层依据。候选展示实际依据；生成前后复验来源、状态和相关修订，迟到或失效结果不能继续使用。
- 空检索说明“没查到”，不能宣称“没有这件事”。语义补充只进行独立评估；没有合格证据和启用决定时不改变生产路径。

### 5. 明确表达偏好

- 用户明确要求长期保存的表达偏好有独立的保存、查看、修改和删除闭环，并记录 owner、适用范围与用户确认来历。
- 当前明确意图优先于长期偏好。“这次简短一点”只作用于本次；无法确定长期意图时不自动持久化。
- 偏好不作为联系人事实，不由复制、选择候选或发送观察自动产生。表达样本仍须用户主动保存；自动从样本归纳长期风格不在本阶段。

### 6. 自动学习 Skill

- 在授权材料中自动选择助手讨论、使用痕迹、修改和纠正，以及同一已确认联系人内与任务有关的外部聊天或后续反应。用户无需逐条挑选；不读取任意文件、未授权会话、其他 App 或网络资料。
- 明确纠正优先，普通经验按有界增量批次整理；复用既有任务合并、租约、重试、取消和前台优先机制。一次学习可以没有值得保存的方法，不为每条消息创建新 Skill。
- 优先建议更新或复用已有 Skill。新建、更新、合并均生成独立草稿，包含来源、方法、场景、范围建议及理由。Skill 按场景组织，可以包含多条方法，不把接受、拒绝等方向各自拆成一个 Skill。
- 系统判断方法是通用、联系人相关还是场景相关并提出范围；用户审核时确定最终范围。去姓名不等于方法通用；发布正文与资源不夹带联系人身份、私人事实或原始聊天，事实仍通过受控记忆上下文提供。
- 草稿进入统一“待审核”入口，轻量提醒。用户可以查看、修改、接受、拒绝或暂留；新草稿审核前不用于回复，更新或合并草稿不替换生效版本。
- 审核显示同一输入下旧版本或无 Skill 与新草稿的对照，标明来源及输入版本。审核检查当前意图、事实与承诺、适用范围；修改草稿、输入或相关版本后，旧对照不能作为新版本的有效预览。
- 用户确认后发布不可变版本，随后通过现有只读 SkillPort 使用；显示实际名称、版本和范围。没有合适 Skill 时仍可生成候选，每次至多使用一个有效版本。
- 更新和合并要显示替代关系并获确认，保留可回滚版本及方法映射；回滚须复验当前授权、停用政策、来源和删除状态，不能恢复已经删除内容。

### 7. 根据反馈调整 Skill

- 反馈定位到当前回复、Skill 中某条方法或整个 Skill，并确定联系人与场景范围。目标明确时直接执行，不能反复确认已说清的指令。
- “这句太生硬”先修改当前回复，有长期改进价值时提出草稿；不能直接停用整个 Skill。明确“以后对这个人别用这个方法”立即按明确范围停用，不等待集中审核。
- 目标不明时先处理当前回复；长期变更前只澄清必要目标。没有回复、回复慢或变冷淡只作为有限观察，不直接认定方法无效，更不能反推对方动机。
- 方法停用在运行时具有优先约束，不改写不可变发布正文；若现有执行路径不能可靠排除某条方法，则在该范围回退到通用回复，不偷偷扩大到其他联系人或场景的停用。
- 更新、合并和回滚不能通过换版本或方法编号解除既有停用。需要恢复时由用户明确撤销；无法可靠映射的方法不能自动当作全新可用方法。

### 8. 现有资料升级

- 提供用户选择范围、查看批次新旧差异、确认应用及查看进度的完整入口。实际范围、调用预算和数据访问在执行时明确；不因升级代码完成就自动重跑业务资料。
- 保留人工确认、纠正与否决，新结果先比较，冲突不静默覆盖；自动结果仍受当前质量门槛约束。旧版来源依据不回填成新版本的有效证明，重新提取产生独立新依据与审核结果。
- 使用确定性后台步骤和幂等批次，从未完成位置恢复；应用前复验来源与资料修订。支持撤销本轮更新或恢复仍有效的旧版本，来源删除优先于恢复。

## User Stories（用户故事）

1. 作为用户，我希望看到某条状态是过去发生的还是当前已核实，以免回复误用旧近况。
2. 作为用户，我希望不知道现在情况时系统直接说明未知，以免把沉默当作状态持续。
3. 作为用户，我希望查看原话时间、保存时间和依据，以便核对来源。
4. 作为用户，我希望同一件事重复导入或提取时不重复记忆，以免概览堆积重复条目。
5. 作为用户，我希望系统分清计划、约定和已发生事件，以免替我或对方编造经历。
6. 作为用户，我希望可靠的新变化保留旧历史，以便回看变化过程。
7. 作为用户，我希望自动记忆标明自动且可撤销，以便保持控制。
8. 作为用户，我希望纠正一次后旧错误不换一种说法回来，以免反复纠错。
9. 作为用户，我希望新证据与旧纠正冲突时被清楚展示，以便作出新的确认。
10. 作为用户，我希望历史候选提示依据变化，以免把旧答案直接继续使用。
11. 作为用户，我希望查看与一位联系人的关系变化及来源，以便了解过去发生了什么。
12. 作为用户，我希望查看自己的稳定事实和偏好，以便修正或删除不准确的资料。
13. 作为用户，我希望概览不把心理推测写成事实，以免误解对方。
14. 作为用户，我希望回复找到相关资料并能补查原话，以免遗漏有用上下文。
15. 作为用户，我希望查看本次真正使用的依据，以便判断候选是否可信。
16. 作为用户，我希望未确认资料和当前未知被明确标注，以免混淆确定程度。
17. 作为用户，我希望明确保存长期表达偏好并能管理，以免每次重复说明。
18. 作为用户，我希望单次意见只影响当前回复，以免被强加长期习惯。
19. 作为用户，我希望系统自动发现可复用经验，以免手动挑选每段材料。
20. 作为用户，我希望没学到有用方法时无需创建新条目，以免审核无意义草稿。
21. 作为用户，我希望新建、更新和合并建议集中出现，以便一次查看而非频繁被打断。
22. 作为用户，我希望看到方法、来源和范围理由，以便决定给谁、在何种场景使用。
23. 作为用户，我希望比较新旧回复，以便理解方法会带来什么变化。
24. 作为用户，我希望待审核草稿不影响现有回复，以免未同意的方法先行生效。
25. 作为用户，我希望接受、修改、拒绝或暂留草稿后状态可靠保存，以便日后继续。
26. 作为用户，我希望发布、更新、合并与回滚都有清楚版本，以便追溯和恢复。
27. 作为用户，我希望不合适的方法只在我指定范围停用，以免影响其他关系。
28. 作为用户，我希望改一句回复不会停掉整个 Skill，以便保留其他有用方法。
29. 作为用户，我希望明确停用立即生效，以免继续遇到同一问题。
30. 作为用户，我希望升级旧资料前看差异，以免人工确认和纠正被覆盖。
31. 作为用户，我希望失败、重启和重复操作不会造成重复更新或发布，以便安全继续。
32. 作为用户，我希望删除来源后所有相关派生内容也被清理，以免从草稿、预览或历史版本恢复私人资料。

## Implementation Decisions（实现决定）

### 现有基座与模块职责

- 延续当前 Python 领域与应用模块、PostgreSQL 权威业务库、受控后台步骤、LangChain 候选回复循环及 Deep Agents SkillsMiddleware。DSH 选型没有阻塞边，不做运行时迁移或预建通用 Harness。
- 复用 MemoryService、MemoryPort 与 OwnerMemoryPort 承担版本、手动操作和有效资料查询；扩展时保留 scope、来源状态、采纳方式和修订检查。由首张承接任务建立时间状态返回契约，后续不各自造一套时间模型。
- 复用 RetrievalPort 和既有回复应用入口；概览、长期表达偏好和停用政策经应用层组装为有界上下文，不另建绕过意愿、引用校验或删除检查的生成路径。
- Skill 库管理继续拥有原子发布、版本、回滚与库修订；SkillPort 继续只读。新增学习与审核应用模块协调材料选择、模型提案、草稿、对照和用户操作，模型只产生提案，不获得发布或管理权限。
- 当前 React 界面承接查看和操作。旧 Swift 页面的历史完成状态不能证明当前 Skill 管理入口已存在，不复制已退役的主界面。

### Interface 与测试 Seam

主测试 Seam 为用户操作对应的公开 HTTP 用例，搭配隔离 PostgreSQL、真实应用模块和可控模型；界面验证复用生产 React 控制器。现有接口优先扩展，新增接口只暴露完整业务操作，不暴露内部提取步骤或表级读写。

| Module | Interface 必须提供的行为与不变量 |
| --- | --- |
| 记忆管理 | 范围内查看历史与当前核实状态、修正、否决、新旧版本应用与撤销；旧证据防重生；revision 冲突拒绝；删除依赖不复活。 |
| 概览与检索 | 读取联系人或本人概览、追溯依据、有界查询；派生版本与底层修订一致；没有有效依据时返回未知或空结果。 |
| 表达偏好 | 用户明确保存、读取适用项、修改和删除；当前意图优先；每个持久变更绑定已验证用户操作。 |
| 学习与审核 | 有界学习产生草稿或无结果；列出和查看待审核；修改并刷新对照；接受、拒绝或暂留；发布前检查 scope、来源、输入及目标版本。 |
| Skill 库与范围控制 | 原子发布、更新、合并、回滚；按联系人和场景应用方法/Skill 停用及撤销；每次读取复验库与政策修订，模型不可调用管理操作。 |
| 资料升级 | 明确范围与预算、准备差异、用户确认应用、查询进度、取消和恢复；重复操作幂等，不直接覆盖人工决定。 |

### 数据与生命周期

- 时间核实信息独立于 active、采纳状态和有效期。历史状态可以可见和可检索，但必须以历史或未核实证据进入回复；临时或随时间变化的状态，没有支持当前成立的时效依据时不得当作确定现状。稳定事实和明确偏好继续按来源、用户确认或质量门槛及有效性合同处理，不仅因日期未知而降为历史未知。
- 纠错保护绑定范围、错误含义及参与证据身份；归一化文本指纹只是去重辅助，不能单独满足换说法后的防重生要求。判断异常时不写新的自动事实，不删原人工决定。
- 概览保存底层资料与 revision 依赖，长期偏好保存明确用户动作及范围。二者都具有查看、修改或重建、删除路径；本人范围不豁免联系人来源依赖。
- 学习草稿保存 owner、材料范围、完整参与来源依赖、提案类型、方法身份、建议适用范围、草稿 revision、目标发布版本和对照输入身份。私人审核依据与可运行的清洗后策略内容分开存储；导出包不携带审核原文。
- 草稿生命周期区分待审核、已拒绝、已发布和失效；编辑产生新 revision。待审核是持久业务状态，生成任务结束后无需让 Agent 持续等待。重启从权威状态恢复；来源、输入或目标版本变化时重新生成对照或拒绝旧批准动作。
- 发布通过用户管理命令执行事务；同一批准操作只能发布一次。草稿或版本冲突返回可解释冲突，不静默覆盖、自动扩大范围或把旧批准复用到新正文。
- 方法身份属于逻辑 Skill，版本记录延续、替代和合并映射。停用政策是独立的用户决定；更新、合并、回滚后仍生效。只有用户明确撤销才可恢复；不确定映射按保守策略执行。
- 方法级停用不能只在 Prompt 中提醒。执行视图和可读辅助资源必须排除被停用的方法，不允许模型通过原始 `SKILL.md` 或资源把它读回来；执行视图另记原版本、政策修订和视图摘要，不冒充原不可变正文。无法可靠分离的旧包在该范围回退通用回复，原发布包不被改写。
- 候选结果提交，以及继续、重试或恢复前复验相关 `policy_revision`。即使停用发生在最后一次策略读取之后，受影响的迟到结果也不得作为有效新候选提交或继续使用；保留用户已有合法编辑和必要变化提示，不因旧结果失效静默重写用户内容。
- 新增状态和依赖使用前向迁移，不改写历史迁移。所有新增私密字段均覆盖删除、导出控制、日志白名单和恢复复验；业务库迁移与真实资料升级不由规格发布授权。

### 删除、出站与学习安全

- 学习读取最小的任务相关材料，记录完整实际参与来源，不能仅记录草稿里的直接引用。复制和选择不证明已发送；后续反应与方法效果只能按可核验关联描述。
- 来源、助手会话或联系人删除后，依赖其内容的草稿、对照、学习产物、概览、历史运行快照及恢复副本必须清理或失效；清理后不得再恢复正文。学习产物没有表达样本的独立留存例外，独立导入且无此依赖的 Skill 不误删。
- 已发布版本依赖被删除时先阻止读取和使用、递增相关修订，并清除受影响正文及副本。其他来源仍有效不等于旧生成内容可自动保留；需要重建时只用剩余有效材料重新提出草稿并审核。
- 已清洗通用方法可在审核批准的广范围使用，但审核私人依据不随之暴露给其他联系人；跨 owner 始终拒绝。Source 删除优先于回滚和恢复。
- 新用途或新供应商须满足现行出站范围和数据政策；实现默认使用合成资料与可控模型。普通日志与公开报告不保存正文、联系人身份或私人来源定位，最小出站台账继续按现行规则。
- 不增加外部发送、Shell、文件写入、任意网络或自治任务能力；最终消息由用户编辑并亲自发送。

## Testing Decisions（测试决定）

- 验证完整外部行为：输入资料或用户操作，经真实 HTTP 与隔离存储，回到可查看状态和候选依据；不以内部函数调用次数、数据字段存在或照抄实现的测试证明产品完成。
- 采用可控模型、可控时钟、失败注入和合成来源，验证时间状态、重叠事件、计划不变经历、换说法的重复错误、人工决定保护和有界检索。合成测试不等同于真实模型语义准确率。
- 对学习验证有结果与无结果、重复事件合并、待审核不启用、同输入对照、编辑使旧对照失效、范围变更、明确批准、拒绝/暂留、版本冲突、重启与恰好一次发布。
- 对反馈验证当前回复/单方法/整个 Skill 区别、明确范围立即停用、模糊目标不长期修改、版本和合并不绕过停用、沉默不判失败，及无法可靠过滤时回退通用回复；覆盖停用发生在最后一次策略读取之后、候选提交之前的竞态。
- 每张交付任务从首个新增产物起验证跨 owner/contact、来源删除、内容残留、迟到结果、重试和恢复；删除不能集中拖到最后一张任务才实现。覆盖删除与生成、批准、更新、升级、回滚的两种提交顺序。
- 复用既有 memory、retrieval、Skill 库、回复、来源删除和持续会话测试模式；必要时增加公开页面入口验证。当前任务阶段不启动真实 App、微信或外部模型；真实验收另按有限时段和独立调用范围执行。
- 真实质量报告分别记录提取正确性、覆盖与错误、方法是否符合用户意图、对照审阅、调用/延迟与剩余缺口；实际维度放行遵守现行台账。测试通过不自动批准维度或生产语义检索。
- 语义补充延续既有失败基线，只对明确改进的缺口方案作开发集校准和冻结对照；同预算下不得增加无关注入，跨范围/删除/旧 revision 注入为零，性能沿用现有评估门槛。可以交付否定结论；生产接入另需合格证据和明确启用决定。

## Out of Scope（排除项）

- DSH 选型、Harness 原型和回复运行时迁移；不增加这类任务或依赖。
- 真实聊天读取、真实模型评测、新出站、业务库迁移、自动重跑旧资料及生产部署。
- 自动放行未达标的记忆维度，或把已有失败向量实验当作启用依据；本规格不交付生产向量启用。
- 自动从表达样本推断长期风格、自动保存表达样本、具体邀约 Skill 或完整场景库创作。
- 新的完整关系分析产品、主动性格/动机判断、关系效果保证、自动摘要助手讨论、多设备同步及 OCR 改造。
- 自治 Agent Harness、额外定时自动化、任意文件/网络搜索或外部聊天发送。
