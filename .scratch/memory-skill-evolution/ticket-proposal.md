## 粒度与依赖

建议 **15 项完整交付**。8 个产品功能仍保留，较大的功能按能独立展示的完整行为分阶段；不拆纯数据表、纯接口、纯界面或每条例外。每项都负责必要的存储、应用、当前界面和验证，复用已有实现。

表中“依赖”是实现前置，不是排队顺序；同批优先级不制造虚假依赖。

## 各项验收边界

### 01：历史状态与当前未核实

- 原话、来源时间和保存时间沿既有接口可见，新增当前核实状态；不重做已经完成的日期投影。
- 合成旧近况缺少结束时间时保留历史，生成不认定现在仍成立；明确有效区间与稳定事实分别处理，不套统一期限。
- 可控时钟、缺少来源时间、来源删除及当前输入切换均通过公开接口验证；不伪造事件日期。

### 02：新旧更新、事件与去重

- 同一次事件的重叠证据合并，不同时间事件保留；计划、约定、改期、取消和发生的演变有来源，不因时间到了自动完成。
- 新旧应用是原子版本变化，失败不出现新旧同时错误生效或旧资料被单独失效；用户能查看并撤销仍合法的自动版本。
- 生产质量门保持；用可控模型验证流程，用独立质量证据评价事件同一性，不把程序判断或文本相似度当事实证明。

### 03：纠错、否决与防止旧错误回来

- 复用当前人工修正/否决，补齐“同一错误含义＋旧证据”的保护；验证换说法、重复批次和重启后不会再次提出。
- 真正新证据产生待确认结果并说明差异，不能静默撤销人工判断；同义判定不确定不自动采纳。
- 纠错记录依赖删除、来源世代和幂等复验；删除后不留下可恢复私人正文。

### 04：旧回复依据变化与重新生成

- 经当前会话读取入口区分记忆修正/替代/时效变化与来源删除；前者可显示仍合法的旧正文和变化提醒，后者清除受影响内容。
- 用户明确继续时沿原回复入口重新核验，展示新依据，保留当前意图；不存在自动继续或静默改写用户编辑。
- 验证公开会话回看、继续、迟到结果、失效重试和删除两种竞态，不仅测试新展示字段。

### 05：联系人关系变化概览

- 一位联系人的经历和变化可查看、逐项追溯，历史/当前未知清楚；不把目录标签当作完整概览。
- 用户修正底层资料后概览重建；事实与推断分开，本项不生成深入性格/动机分析。
- 来源或联系人删除清理投影、缓存和恢复副本，另一联系人的资料不能进入概览。

### 06：本人事实与偏好概览

- 本人稳定资料可查看、追溯和通过底层资料修正/删除；与联系人概览共用投影契约，不另造事实库。
- 只汇集真正属于本人的资料，不把联系人的状态搬入本人概览，也不跨关系披露私人事实。
- 来源删除和手动决定仍有效，未知或矛盾不自动归纳为人格结论。

### 07：概览与有界证据检索接入回复

- 复用现有 RetrievalPort、原话窗口和回复生成，只补概览导航到当前底层依据以及必要补查；不重建已完成的检索层。
- 在同一联系人与独立本人预算内返回相关原话、事实、历史和未确认参考，候选展示实际引用与状态。
- 验证空结果、预算耗尽、概览修订变化、生成前后删除和旧快照；保持词法生产基线。

### 08：明确长期表达偏好的管理与使用

- 当前 React 入口明确保存、查看、修改和删除长期表达要求；一次性指令不持久化。
- 下一次合适回复实际读取偏好，当前明确意图冲突时以当前意图为准；不以表达样本或 `user_instruction` 冒充长期偏好存储。
- 适用范围、来源/用户动作依赖、删除与失败恢复通过 HTTP 和受控模型验证。

### 09：自动学习并形成待审核草稿

- 在任务相关授权范围自动取材，纠正优先、普通经验有界合批；可以无新增，优先已有方法更新或合并提案。
- 当前 React 待审核页显示草稿、方法、来源和范围建议；草稿不进运行目录，重启可恢复。
- 建立供后续沿用的方法身份、草稿 revision、来源依赖和目标版本契约；被删除材料及重复触发不能产生复活或重复草稿。

### 10：对照审核、范围确认与发布使用

- 新草稿只经隔离只读试用视图对照，不临时发布试用；旧版本/无 Skill 与新草稿使用相同冻结输入。
- 用户确认联系人/场景/通用范围，接受、编辑、拒绝或暂留；编辑使旧对照失效，旧批准不能批准新内容。
- 原子且幂等发布、实际候选加载和版本/范围展示；旧草稿冲突、来源删除及不同 Owner/联系人均不能越过检查。
- 建立发布版本的方法延续映射与范围政策兼容契约；现有场景元数据不等于已具备场景门禁，本项落实运行范围检查。

### 11：Skill 更新、合并与回滚

- 对明确的已发布 Skill 进行更新或提出合并，显示差异、替代范围和来源并经同一审核后生效。
- 合并限于用户确认的候选集合，来源依赖取保守并集，冲突供审核；不做复杂跨范围自动重组或自动裁决。
- 版本历史与回滚可操作，方法映射连续，范围/停用/删除复验保持；未审核更新不覆盖现有版本。

### 12：当前回复与方法反馈调整

- 普通措辞意见沿当前修改入口处理；长期调整或明确停用定位到最小对象和明确范围，对象不明才补必要澄清。
- 方法级和整个 Skill 的明确停用即时影响后续实际执行视图；正文和资源不能重新加载被排除方法，不能只加 Prompt 提醒。
- 候选提交、继续、重试和恢复复验相关政策修订；停用发生在最后一次策略读取之后，受影响的迟到结果也不能生效，不静默覆盖已有用户编辑。
- 方法无法可靠分离时该范围回退通用回复；版本更新、合并、回滚和恢复继续遵守停用，用户明确撤销才恢复。
- 长期修订进入审核，沉默或迟回复不判方法失败；与任务11的完整组合由15验证，不制造相互阻塞。

### 13：旧资料的差异比较与批次升级

- 通过用户入口明确范围与预算、预览新旧差异、选择批次并确认应用；不清空现有水位伪装升级。
- 人工确认、纠正和否决保留；旧版依据不能回填为新证明，应用时复验修订和当前来源。
- 幂等、取消、部分失败恢复和合法撤销具备实际进度；合成演示不授权业务资料重跑。

### 14：语义检索已有缺口的独立评估

- 引用原 pgvector 已完成且失败的基线，先提出针对错误匹配的具体改进；没有新方案时可记录缺口和不启用结论，不复刻同一实验。
- 开发集校准后冻结规则和最终集，同资料、同预算、保留失败分母；分别记录召回、无关注入、隔离/删除/revision 与性能。
- 报告可以不达标，不修改生产装配或开关；模型下载、真实资料和外部调用若需要则按独立范围处理。

### 15：记忆到 Skill 的跨功能组合验收

- 各票先做自身完整回归，本项再串联原话→更新/纠错→两类概览→实际回复依据→学习→审核→反馈→旧资料升级→删除。
- 覆盖重启、版本冲突、不同 Owner/联系人、局部停用、回滚与删除并发，确认从缓存、旧对照和恢复副本都不能复活应删内容。
- 公开 HTTP/隔离 PostgreSQL/React 页面证据与真实模型质量、实际 App/渠道验收分别记录；未预约 App 或未批准真实模型时保留未验范围，不伪称全部生产验收完成。

## 为什么这样拆

- 01/02/03 先建立可复用时效、版本及纠错契约，05/06 才在其上形成可追溯概览；07交付的是两类概览的新接入，而不是重复已有检索能力，因此依赖05/06。
- 04可用既有人工修正和失效事件交付，不必等待自动事件判断的模型质量放行；02的组合变化在15继续验证。
- 08和09不等待长期概览；10承接09的草稿与方法契约，11和12随后可独立推进，不互相循环阻塞。
- 13只等待更新和纠错基础；真实资料范围与预算是执行条件，不虚构为已完成的技术依赖。
- 14独立评估，结果不合格也不阻塞其他功能；15不以语义检索通过为前置，生产继续使用现有词法路径。

## 发布方式与确认项

确认本方案后，按[本地任务约定](../../docs/agents/issue-tracker.md)在 `issues/` 逐张发布01～15，每张标记 `Triage: ready-for-agent`、`State: open` 和上述真实依赖；不自动开始实现。

确认仅涉及：这些完整交付是否仍过大或过细，哪些需要合并/拆分，以及这些前置依赖是否符合期望。具体技术接口沿用本规格，代码粒度不是新的产品问题。
