## What to build

承接已有失败原因，用冻结对照判断改进是否有价值，保持生产路径不变。

## Acceptance criteria

- [ ] 引用原 pgvector 已完成且失败的基线，先提出针对错误匹配的具体改进；没有新方案时可记录缺口和不启用结论，不复刻同一实验。
- [ ] 开发集校准后冻结规则和最终集，同资料、同预算、保留失败分母；分别记录召回、无关注入、隔离/删除/revision 与性能。
- [ ] 报告可以不达标，不修改生产装配或开关；模型下载、真实资料和外部调用若需要则按独立范围处理。
- [ ] 新增行为按已验证 owner/contact 或独立本人范围隔离，保留真实来源、用户决定及删除路径；不扩大读取、自动采纳或工具权限。
- [ ] 覆盖本票产物与来源删除的两种提交顺序、重复操作、迟到结果、失败重试和恢复；不能从缓存、旧预览或恢复副本复活应删内容。
- [ ] 记录实际命令、结果、数据影响和未验范围；代码/合成行为、真实模型质量及 App/渠道验收分别报告，不提前勾选验收或标记完成。

## 验证与交付

复用现有失败基线与隔离评估方法。先核对缺口和可检验改进，再决定是否存在值得执行的新方案；可以形成明确的不启用结论。仅使用合成或匿名资料，不能重复同一实验、修改旧失败结论或开启生产语义检索。

本票按可复核的一手证据、已有结果和明确结论交付。若需要修改隔离评估 runner，则在既有检索接口上验证新增行为、运行最小相关检查并完成 Standards/Spec 两轴评审；若只形成研究结论，不要求编写镜像实现的测试。记录实际命令、结果和限制后补充 Answer、据实更新状态并创建本地提交。评估或合成测试通过不替代真实语义质量与维度放行。

## 范围边界

沿用当前基座，DSH 搁置且不作为前置。只交付本票完整行为；共享契约由首张承接票建立，后续复用，不新增纯接口或纯数据库任务。
本票发布不授权读取真实聊天、调用外部模型、迁移业务库、重跑旧资料、启动真实 App/微信、外部发送、部署或 push。实现中的正常本地工程验证按既有工作流推进；真实数据、出站或原生验收沿用独立范围和有限时段。
