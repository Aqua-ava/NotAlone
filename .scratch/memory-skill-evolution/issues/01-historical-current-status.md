## Acceptance criteria

- [ ] 原话、来源时间和保存时间沿既有接口可见，新增当前核实状态；不重做已经完成的日期投影。
- [ ] 合成旧近况缺少结束时间时保留历史，生成不认定现在仍成立；明确有效区间与稳定事实分别处理，不套统一期限。
- [ ] 可控时钟、缺少来源时间、来源删除及当前输入切换均通过公开接口验证；不伪造事件日期。
- [ ] 稳定事实与明确偏好继续按来源、确认/质量门槛和有效性合同处理，不仅因日期未知就降为历史未知。
- [ ] 新增行为按已验证 owner/contact 或独立本人范围隔离，保留真实来源、用户决定及删除路径；不扩大读取、自动采纳或工具权限。
- [ ] 覆盖本票产物与来源删除的两种提交顺序、重复操作、迟到结果、失败重试和恢复；不能从缓存、旧预览或恢复副本复活应删内容。
- [ ] 记录实际命令、结果、数据影响和未验范围；代码/合成行为、真实模型质量及 App/渠道验收分别报告，不提前勾选验收或标记完成。

## 验证与交付

沿公开用户操作与 HTTP 用例，使用隔离 PostgreSQL、真实应用模块与当前 React 控制器验证完整行为；模型、时钟和必要失败事件可控替换。复用既有稳定接口，不另建事实库、生成链路或通用 Harness。新增接口及测试从本票用户行为切入，不只证明字段或内部调用存在。

按工作流在已约定接口上进行 TDD 和最小相关验证，完成完整相关回归及 Standards/Spec 两轴评审后记录 Answer、据实更新状态并创建本地提交。研究票按可复核证据和明确结论交付；评估或合成测试通过不替代真实语义质量与维度放行。

## 范围边界

沿用当前基座，DSH 搁置且不作为前置。只交付本票完整行为；共享契约由首张承接票建立，后续复用，不新增纯接口或纯数据库任务。
本票发布不授权读取真实聊天、调用外部模型、迁移业务库、重跑旧资料、启动真实 App/微信、外部发送、部署或 push。实现中的正常本地工程验证按既有工作流推进；真实数据、出站或原生验收沿用独立范围和有限时段。
