## 问题与范围

用户点击「基于此继续生成」后 App 报请求超时，后端请求仍为 running。
已确认普通状态接口可用；不能据此断定该次模型慢或工具循环。
修复生成运行缺少整体时限、循环预算及可识别超时响应的问题。
不改变背景检索、长期记忆或发送边界，不保存真实聊天作为测试夹具。

## 验收与测试边界

- 通过既有 LangChainReplyRuntime.generate 和 ReplyGenerator.generate 测试正常及继续生成。
- 合成模型反复调用工具时在有限步骤内停止；长时间不返回时取消等待并终止后续模型调用。
- 超时经既有 Store 失败/过期和出站台账收尾，不保存迟到候选；同请求可重试。
- HTTP 返回稳定错误码；App 结束转圈并显示中文错误，传输等待时间留出后端收尾余量。
- 正常生成、来源校验、联系人隔离与已有测试不回归。

## Answer

已实现并通过验证。

1、`LangChainReplyRuntime` 改经统一常驻事件循环的 `run_with_timeout`（新适配器 `src/notalone/reply/adapters/async_runner.py`）运行 `graph.ainvoke`，整体运行时限默认 20 秒并在构造时校验（0 < t ≤ 20）；`recursion_limit=12` 截住重复工具调用。分别新增 `ReplyTimeoutError` 与 `ReplyBudgetError`（`src/notalone/reply/errors.py`），取消后迟到结果不交给 Store。

2、HTTP 契约新增稳定错误码：504 `{"error": "reply_timeout"}`、502 `{"error": "reply_budget_exceeded"}`（`src/notalone/server/app.py`）。App 侧 `BackendClient` 传输等待提高到 45 秒并识别两个错误码；`AppModel` 显示中文提示「回复生成超时，本次生成已停止。可以稍后重试。」/「本次生成尝试过多，已停止。请调整表达方向后重试。」

3、测试：新增 `tests/unit/reply/test_runtime_limits.py`（合成模型重复请求工具在 ≤12 步内停止；慢模型被取消、总耗时 <1 秒且无迟到结果）；server 契约测试钉住两个错误码；Postgres 流程测试验证续生成超时后 attempt 记录 failed、同幂等键可重试成功。运行时改用 `ainvoke` 后为各测试合成模型补充 `_agenerate` 异步入口。全量 Python 732 项通过（2 项真实模型测试跳过）、Swift 10 项通过。

4、真实后端端到端验证（对 App 拉起的常驻后端及本任务临时验证实例进行，仅使用合成草稿文本，不读取或写入真实聊天正文）：改写生成 200（8.5 秒，2 候选）；携带候选 id 续生成 200；将模型地址注入本机挂起端点后同一续生成请求 20.1 秒返回 504 `reply_timeout`，`reply_request`/`reply_attempt` 均收尾为 failed、出站台账记 `run_failed`，不再停留 running；恢复真实模型后同一幂等键重试完成（attempt 3 completed，request completed）。

剩余风险与备注：

- 本次验证期间 macOS 无障碍与屏幕录制授权被系统拒绝，桌面 UI 中文提示未做视觉确认；该映射经代码走查、Swift 构建与后端 504 契约端到端验证覆盖，可在下次打开 App 时人工确认。
- 验证中观察到两次瞬时 500 `reply_generation_failed`：真实模型输出被运行时校验拒绝（台账记 `rejected_by_validation`）或模型调用失败（`run_failed`），均按既有通用 5xx 映射正确落库且可重试；非本 issue 范围。
- 全量测试运行中仍出现 unittest 的 `ResourceWarning: unclosed file`（`case.py:589`），全部测试通过，非本次改动引入。
