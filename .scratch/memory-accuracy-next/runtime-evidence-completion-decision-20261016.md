# 原03运行依据收口：有限范围决定稿

日期：2026-10-16。状态：**用户已明确选择“同意有限六类合同及指定任务接线（推荐）”；尚未实现。** 本次批准将下述有限六类合同作为[原03](issues/03-per-dimension-rollout.md)剩余第一条的覆盖边界，包含指定任务的显式接线与版本化依据；不代表质量验收、业务库迁移或自动放行已获批准。旧默认、空放行表和历史结果保持。

## 需要决定什么

推荐批准一个**正式任务显式选择、保留旧默认的有限六类依据合同**：给已有来源链中能够独立核清的关系生成依据，其余明确未知并保留待确认。它需要扩展旧D2的单消息作用域及依据版本；不能把当前有限“到家”正例重新命名为广泛完成。

| 选择 | 交付与限制 | 对原03的影响 |
| --- | --- | --- |
| 保持现合同 | 默认grounded-v2／legacy-v4不动，继续显式离线D1–D3及B控制 | 不新增架构；生产指代、转述及多消息依据仍有缺口，原第一条不能关闭 |
| **有限正式接线，已选择** | 旧默认保留；指定提取任务可选择新有界模式，扩展明确指称、多消息问答及直接转述；范围外未知 | 新范围已明确采纳，须按下述矩阵验收；有限覆盖不表示任意中文都可证明 |
| 普遍正向证明 | 要求任意省略、指代、转述和媒体正文均生成正向依据 | 不是本稿的最小方案；当前代码、规则与质量证据均不足，不能以有限方案承诺此结果 |

本次决定覆盖第二行的**正式运行接线、有限规则边界和原AC接受口径**。精确字段与版本配对在实施规格中固定，普通实现连续推进。默认生产维度放行仍为空；本次不包含业务迁移、新增真实资料读取或外发。

## 现有接缝与正式模式

现状已从代码核对：`server/command.py`、`tasks/worker.py`、`memory_extraction/command.py`均构造默认`LangChainSourceVerificationRuntime`；默认是`legacy-v4`。`build_dimension_evidence`的v1生产路径把`reference/reported`置为`None`。显式proof1与proof2已有纯核验、绑定、保存和回读接缝；B只适用于单条到家引句。依据结构可保存不代表正式入口已能生产它。

建议保留`GroundedExtractionRuntime`的现有v2默认及编译文本；新模式在**单次指定提取任务**中显式选择同次V证明协议，不顺带把实验grounded-v4变成默认，不增加第二次V或联网重试。现有`PostgresMemoryExtractionRunner(runtime=..., verification_runtime=...)`及server的优先级装饰器可以复用；这只是依赖注入接缝，当前没有可宣称已存在的任务级模式配置。

新增受控模式值建议名为`bounded-runtime-v1`，缺省/旧任务均走`legacy`；未知模式拒绝。模式只能由受控任务创建或指定任务运行入口设置，不能由模型、聊天正文或联系人名称指定；同一次领取、重试和恢复必须保持同一配置。新模式绑定任务ID、范围及规则版本，记录在已有任务追踪中；若要持久选项，需要在现有后台任务配置中保存一个封闭值，不用易混淆的全局环境开关或“当前worker偏好”。不能让仅带任务ID的恢复悄悄采用另一模式。具体任务参数保存字段在实施spec中固定，现有`rule_version`仅是版本记录，不能假装已经承载运行选项。

新模式仅在支持相应迁移的自有隔离库验收。旧库接到新模式时在模型调用及写入前拒绝；不自动DDL、回填或重采纳。未单独批准业务升级前，正式业务实例仍使用原默认；“正式代码入口的隔离运行”与“业务部署”分别报告。

## 最小有限语义范围

每个候选只核一个实际目标消息，保留它所在的**完整实际窗口**和来源依赖；首批最多4条消息、2个第三方角色、1个显式指称链或1组问答。超过边界未知，不为获得正例删上下文、缩原窗口或合并不同联系人。每条消息均须由正式导入/观察来源和loader产生当前活动快照；不补造公开评测的trusted元数据。候选按既有编译器实际输出的原话、相关原文和观察前缀复核，不能临时去掉上下文后套旧arrival规则。

| 类别 | 首批允许的正向依据 | 仍然未知或拒绝的边界 |
| --- | --- | --- |
| 主体与跨消息指代 | 实际sender的自指；完整来源显式声明“这里的‘她/他’指我的某位关系角色”，后条对应代词，全部绑定同一声明与角色 | 只有性别、最近出现、施事、模型选中一个target或昵称一致均不足；冲突声明和未名产权/受益人未知 |
| 省略主语 | 复用现有完成问答的有限产生式，前问“你到某目的地了吗”、后答“到了/已到了”等，作者次序、谓词、对象与完成阶段完整核对 | 计划、约定、到期语境、否定或其他谓词不补事件；无法唯一匹配问句未知 |
| 多第三人 | 完整窗口含至多两个明确关系角色，显式声明将代词唯一绑定其中一个；另一角色完整保留为上下文 | 竞争的两个可行指称、无声明、声明被后文修正均未知；不因只有一个模型target就认为唯一 |
| 转述 | 只扩已有request规则：明确请求者、受托者、事项内角色及时间；接受、履行和内外层时间分别核；另保留actual sender的direct事件 | 不把请托写成接受/义务/执行；不承认任意嵌套引语或传闻；未解受益人未知 |
| 保真与时间 | 独立解析上述有限原事件及既有否定、阶段、时间/条件/数量规则，核完整候选包装与上下文；日期来自既有受控期间计算或明确时区时间 | 逐字引用不自动证明内部指代；“刚”不造绝对日期；删限定、移时间归属或改否定须拒绝，超语法未知 |
| 媒体 | 仅证明actual `message_type`与已有文字表示的来源链；纯文字可核，已有真实处理记录才可标`processed_text` | placeholder/unknown不认证内容；模型说“已转写”无效；不新增OCR、语音处理或私人图片读取 |

以上是参数化规则，不是原用例答案表。关系词、受控目的地及肯定/否定等词元必须有明确封闭文法；新增组合使用同一解析器。新事实种类、未定义词法、任意名称推理、复杂引用和开放世界真实性均不在正向合同中。多消息和多第三人正例需要新规则；现有B以及空proof回退不能代替这些正例。

## 协议与数据版本建议

建议新增显式`nullable-proof-v3`／`proof.version=3`，保留原四槽必填、一次V、同来源和只降不升；proof仍为有界位置提案，不提交唯一性、可信性或质量布尔。新规则ID与版本集合独立，不能向proof1/2注册新语义再重解释旧证明。是否保留原四个顶层proof字段，取决于实施spec能否用已有数组无歧义表达多消息链接；即使结构相同，新规则集合和作用域仍升版。

建议新`DimensionEvidence.version=4`仅配`SemanticBasis.version=3`，记录完整多消息关系、候选原话/上下文表示定位及逐项能力；不能沿用v2的“basis非空即签四类”映射。旧NULL/v1/v2/v3按原合同解释，不回填。严格形状、跨度、角色及图边在当前全文重解析后才产生有效依据；保存和确认事务都重核来源。新前向迁移用实施时可用的下一个编号（当前最大059），不改历史迁移。

候选上的“有关/未知”与“有有效依据”分开：复用`required_dimensions`的保守超集及`valid_evidence_dimensions`，API可派生各键为有效/未知/当前失效，并附版本和受控原因。不要新增模型自由填写的维度清单，不借unknown移除AND门，也不把程序明确矛盾的`unsupported`与范围不足的`UNKNOWN`混成同一种结论。保存快照不是模型质量认证；默认空表下即使全项有效也仍pending。

## 受影响文件与实际验收

预计产品文件仅围绕已有模块：`memory_extraction/{source_proof,verification,verification_adapters,evidence,dimensions}.py`、`memory/{dimension_evidence,evidence_binding}.py`、`persistence/{dimension_evidence,memory_store,background_tasks}.py`、`tasks/{models,worker,command}.py`、`server/command.py`及受控任务创建/API投影处；必要时`memory_extraction/command.py`提供显式任务入口。新增纯解析小模块可以接受，不新建runner/harness、供应商或通用AST框架。若既有编译输出不能完整表达所需关系，先报告具体不相容，不在证明器中删改正文救正例。

批准后新增ADR明确局部修订ADR-046/047/060的作用域和正式模式边界，同步现行领域文档；只新增一条前向迁移。实现前用spec固定具体API字段、版本配对、数量上限及规则产生式，不把本稿“预计路径”当成精确实现清单。

| 控制组 | 必须实际经过的路径与断言 |
| --- | --- |
| 六类正控 | 正式合成导入→loader→指定实际任务→E/同次V严格解析→独立producer→隔离保存/API回读；六类均有至少一个独立可核正例，不手注basis/source_bound |
| 跨消息/省略/多第三人 | 每种至少一个新规则正例、一个只改角色/作者/顺序的反例及一个真正歧义例；完整窗口和全部来源依赖相同，不裁剪取得通过 |
| 转述/限定 | 请托与接受/执行、内外时间、所有者/受益人、肯定/否定分别单变量对照；规则内矛盾拒绝、规则外未知 |
| 媒体与来源 | actual文字正控；音频/图片placeholder及unknown负控；已有处理记录的positive只有正式适配器真正产生后才能签，不伪造processed字段 |
| 生命周期 | 跨scope拒绝；只作上下文的来源变化/删除也失效；保存后确认前二次重核；拒绝/候选删除/来源删除及残留0；旧库拒新写，旧数据不变 |
| 任务接线 | server普通/优先级、CLI指定任务及失败恢复保持模式/版本；旧默认不变，非法或新库能力不足在调用前拒绝，旧模式不接收新proof |
| 采纳门与质量 | 全部相关项AND、少一项不通过、原0.7/风险/语用门和默认空表；至少15例/假事0/错人0/一般错误≤1仍由正式工具输出，语义审核、真实模型proof交付与工程Mock分别计数 |

上述确定性控制先真红→绿，再跑完整相关单元/隔离集成、类型检查和两轴独立审查。真实模型验证另建有限冻结场，沿现有预算、原始响应保存、分阶段审核及关闭入口；不使用旧余量、不重开未知请求、不更改任何运行中场次的冻结来源。具体调用上限按最终矩阵计算，不能预写质量通过。
