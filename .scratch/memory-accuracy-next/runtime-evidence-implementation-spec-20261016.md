## 问题

候选可以保存来源快照，但默认入口不能生成指代、转述等有限语义依据；显式作者到家切片也不覆盖跨消息、省略和多第三人。用户需要资料可回查、未知保持待确认、来源删除能够清除相关副本，同时不改变旧默认或自动放行资格。

## 方案

在指定记忆提取任务中显式启用有限运行模式。正式来源加载、既有grounded-v2提取、同一次V、无I/O的独立证明、隔离保存及API回读形成一个完整切片。只在本文封闭语法内提供正向依据；范围外UNKNOWN，明确矛盾拒绝。既有默认和空放行表保留。

## 实施决定

### 指定任务与不可变配置

任务配置采用单个可空JSONB字段`extraction_runtime_config`。NULL是历史任务/旧默认，按legacy解释，不回填。显式配置只有三个键：`version=1`、`mode`和`rule_set_sha256`；mode闭集为`legacy`与`bounded-runtime-v1`。legacy的规则摘要为null，新模式为服务端当前有限规则集合的64位十六进制摘要。调用者只选择mode，不能提交自由规则、摘要或模型配置。

受控任务运行API接受可选`extraction_runtime_mode`，出现时必须同时指定`task_id`，且任务含记忆提取步骤。服务端在事务内锁定任务及提取步骤，只能在提取步骤首次领取前初始化NULL配置；已有相同配置可幂等读取，已有不同配置、已领取或已经尝试提取均拒绝。解析/规范化阶段不使用本配置；配置必须在提取领取前提交，再唤醒执行。失败恢复和retry不接受修改mode。

领取DTO携带已保存配置。普通server、优先级包装器和CLI指定任务均透传同一值，由共享选择边界选择该次V。缺省仍为grounded-v2和legacy-v4；新模式只选同一次nullable-proof-v3，不增加第二次V或重试。CLI增加成对的指定任务与模式参数；与原retry-task-id互斥，恢复读取原配置。直接提取命令保留旧默认，不建立第二套恢复语义。

旧库读取通过缺列兼容投影解释NULL配置；显式配置写入、新模式领取须先核对新列及已验证约束。能力不足、非法配置或已存规则摘要与当前实现不符，均在模型调用及新写入前拒绝，不自动DDL、降回legacy或升级任务。旧`model_version/rule_version`仅保留诊断用途，不能充当不可变配置。任务追踪记录task_id、mode、配置版本及规则摘要，不记录正文。

### 版本与范围

新协议严格配对为`nullable-proof-v3`／proof.version3 → SemanticBasis3 → DimensionEvidence4。旧proof1/2、basis1/2、evidence1/2/3按原合同解释，不向旧规则注册新语义。proof保留version、atom_links、reference、reported四个顶层键；规则ID及变体使用独立闭集。旧模式拒绝新证明。合法null保持UNKNOWN；形状、类型、链接或版本非法仍停止整批。

完整实际窗口最多4条消息，每条及候选正文最多4096个Unicode码点、最多两个第三方关系角色和一个显式指称链或一组问答。每候选只绑定一个实际目标消息；完整窗口和原target集合全部保存。超限或有额外未覆盖语句时UNKNOWN，不裁剪窗口、跳过不利上下文或合并联系人取得通过。

上述数量是新正向证明及evidence4快照的范围，不改变既有窗口构建或合法候选长度。实际窗口超过4条、任一消息或候选超过4096码点时，先独立核正文复制与必需来源，再保存持久all及整个`dimension_evidence=NULL`，不构造超限v4、不降回旧依据或any。完整实际窗口及原target由既有window trace保留；不能称为已保存可重绑的v4快照。范围内合法但无法证明的关系仍可保存basis为null的完整v4；非法proof始终严格失败，不能因超限吞掉。默认门开启时无依据保持pending，运维回退语义不改变。

所有消息来自正式导入/观察及loader的活动来源快照，不补造trusted元数据。提案只给Unicode码点半开位置；布尔、浮点、越界、重复及不属于当前规则的边均拒绝。现有16个atom链接、8个reference及8个reported上限保留，不扩成通用AST框架。

### 封闭规则

以下每条都独立解析完整来源与实际编译候选；只能从语法取角色，不能从case ID、Gold、模型置信度、昵称或选中target取答案。

| 规则 | 有限正向范围 | 明确边界 |
| --- | --- | --- |
| 作者到达 | 复用作者“我刚/刚刚到家”的完整事件、actual sender、原话包装、completed及just | 不把“有人说过”替代原事件；任意评价或其他谓词未知 |
| 显式指称及借用 | 复用姐/哥、她/他、车/书/雨伞的借出产生式及完整否定；允许明确指称句位于同作者的前条消息 | 产权须有完整“这里的‘她/他’指我姐/我哥/我同事”声明；出借施事不证明产权 |
| 完成问答 | 反向作者的完整“你[已/已经]到/到达/抵达某目的地了吗？”及“[我][已/已经]到/到达/抵达了” | 动词、作者、先后和对象同时相符；首批目的地闭集家/公司/学校/机场/车站；否定、将来、期限、年龄等上下文未知 |
| 两第三人 | 上述借用与单一明确指称声明，可附完整的两个关系角色介绍；角色限我姐/我哥/我同事 | 声明与目标必须同作者、同代词并唯一；竞争声明、修正、只有性别或最近出现均未知 |
| 请托 | 复用亲属/同事让实际作者在周末/明天/后天帮其顶班，以及已收请托的直接事件；受益人有明确声明 | requester、recipient、actor、beneficiary分别核对；未提接受/义务/履行不得新增；内外层时间分别核 |
| 条件及数量 | 复用晴天条件下、明天/后天、只/约、有限正数及米/公里的计划跑步产生式 | 条件、量值、单位、程度及阶段均保留；原有数值上限与规范化保持 |

每个目标在首批合同中只包含该规则可完整解释的一项事件或请托结构；条件前件与行动、请托内外层是同一结构。其他独立主张或任意嵌套引用不靠选片段取得正证。角色介绍只表达受控的两个关系称呼及明确指称，不承认开放人名或自然语言身份推理。精确标点、可选词、变体、完整JSON形状、表示定位及能力映射已固定在本文配套的精确协议合同中，实现和SQL以该合同为共同判据，不按运行输出修改。

候选表示须完整核对grounded实际输出的作者原话、观察日期前缀、相关原文及源内关系；不临时剥掉包装或context套旧arrival规则。观察前缀只证明陈述时点，不能冒充事件日期。未来期间沿现有受控日期计算及实际时区重核；无锚点或未支持时间词保持未知。

纯文字的媒体依据来自实际message_type和文字表示；placeholder/unknown不签内容。有真实处理适配器及处理记录时才可能接受processed_text，本次不新增该适配器，也不伪造处理记录制造正例。

### 独立证明、依据与API

同一次V的原verdict/issues/evidence与程序结论分别保存，只降不升。解析图中明确角色、方向、阶段、否定或限定矛盾为unsupported；范围或唯一性不足为UNKNOWN，不把未知说成已证错误。来源图与候选图完整相等、三锚及活动来源成立后才生成basis3。producer及保存/确认绑定器都独立重解析当前全文，不信任旧source_bound或摘要存在。

basis3保留严格角色、事件、限定和指称关系，另有完整候选表示定位及逐项能力集合。能力分别对应主体绑定、完整事件保真、唯一指称、转述/直接归属、时间限定；不能因basis非空签全部维度。媒体仍由真实元数据独立贡献。原truth_intent受控语用判定及全部相关项AND、0.7、风险、语用门和默认空表保持；v4保守加入time，不因未知或缺字段缩小相关集合。

evidence4新增实际`target_message_ids`：非空唯一、属于完整messages，producer取实际窗口；版本化window摘要包含原顺序及target集合。绑定器原样重建目标，不默认把全部上下文当target，也不根据候选直接来源猜测。无正文依据的查看/导出保留完整版本、窗口、target、来源校验和逐项能力；API按现有受控维度派生valid/unknown/stale状态。valid不表示已放行，stale不表示已经物理删除。旧版本投影保持。

### 正文依赖与删除

完整窗口的新鲜度依赖与正文必需来源分开。新v4只允许一组共同支持正文的message IDs：全部原话/相关原文、正文/解释/备选实际使用的上下文及语义图依赖均须在`source_ids`中，且每项都是同范围、实际活动的规范消息，不能用source_document或observation ID冒充消息。纯窗口背景不因此加入必需集合。不同的独立支持组不合并成一组。

候选、联系人确认资料及本人资料各新增持久`source_dependency_mode`闭集any/all。旧默认any沿原替代来源规则；新v4为all，把既有source_ids解释为一组合取依赖，不重复存一份ID集合。同一规范消息的多个有效source_ref仍是替代关系。清proof不清mode；普通确认、AUTO、MANUAL、owner回退路径、拒绝指纹及手动修正版完整继承mode与来源集合。独立手动录入沿any且不借旧候选链。去重比较mode及实际依据输入，不把新all记录吞入旧any或已清依据记录，也不静默升级旧资料。

删除前，在收缩source_ids或清proof前收集所有状态下受影响的all候选、确认/本人资料及派生版本。任一必需消息失去全部有效来源时，先以这些资料ID播种既有回复递归清理，再擦除正文、解释、备选、依赖及索引并同事务复核。owner资料覆盖其他联系人已捕获回复及可能使用旧owner上下文的运行租约。人工确认不切断依赖；独立手动资料、无关联系人及仍由其他有效引用支持的消息保留。

仅无关窗口背景被删除或完整来源快照改变时，旧proof失效、自动采纳失败；不能据此删除没有依赖该正文的已保存资料，也不能因另一来源有效自动恢复旧proof。旧evidence1–3保持既有“清proof、按原source_ids清正文”合同。新all传播和全部状态擦除只用于新记录，不改旧认可资料。

## 测试决定

沿用户已批准的最高接缝验收：正式合成导入→真实loader→指定实际任务→E/同次V→独立producer→隔离保存/API→当前来源复核/删除。复用既有任务、E/V、证据保存和删除工具；不新建runner或评测框架。SDK Mock只给模型响应，不手注trusted、basis或source_bound；直接纯解析测试只作规则控制，不代签正式链路。

每个工程纵切先记录能捕获实际缺口的红灯，再作最小修复。先最小相关单元/隔离集成，再完整相关检查、类型、独立Standards/Spec审查及中文本地提交。隔离库、模型进程及本任务资源逐一关闭和查残留；不接共享业务库。
