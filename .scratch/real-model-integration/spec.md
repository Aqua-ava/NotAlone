# 真实模型接入规格

> Triage: ready-for-agent
> 来源：2026-08-22 grill-with-docs 会话。当日已定方向：真实模型优先于前台同步与记忆提取；Harness 插件路线经复议不进入主线（见 `architecture/drafts/agent-runtime.md` 0.4 节）。

## Problem Statement

候选回复纵切已经建成并通过合成数据验收，但只运行过 scripted fake model。真实模型（DeepSeek）下的中文候选质量、结构化输出成功率、校验拒绝率、延迟和成本行为全部未知；同时对外部模型供应商的调用没有任何台账记录，无法满足"外部连接必须有明确范围和用户授权"的产品边界。在真实模型未接入前，任何 UI 或前台同步工作都建立在未验证的生成质量之上。

## Solution

通过现有 `ReplyRuntime` 接缝把 DeepSeek 真实模型接入候选回复纵切：模型经 LangChain `BaseChatModel` 注入现有运行时 adapter，不新增接缝、不修改领域对象。供应商凭据只经环境变量提供。每次真实外部调用记录一条出站台账（仅元数据，永不记录消息正文或候选正文）。全部单元与集成测试继续使用 fake model；真实 API 只在显式配置环境下以合成数据运行可选冒烟验证。

## User Stories

1. 作为开发者，我想用环境变量配置 DeepSeek API 凭据，以便密钥永不进入仓库。
2. 作为开发者，我想在缺少或为空的凭据环境变量下得到明确的构造错误，以便配置问题在启动时暴露而不是调用时。
3. 作为开发者，我想通过现有 `ReplyGenerator.generate` 入口发起真实模型生成，以便领域外壳（范围验证、上下文装配、候选校验、持久化）不因供应商接入而改变。
4. 作为开发者，我想让真实模型输出继续通过既有结构化输出 schema 和确定性校验，以便无效候选在入库前被拒绝。
5. 作为开发者，我想让超时、限流、网络错误映射为既有运行时错误并标记请求失败可重试，以便真实供应商抖动不会产生未落库候选或悬挂的进行中请求。
6. 作为开发者，我想让结构化输出解析失败也计入失败路径，以便观察真实模型对 schema 的遵循率。
7. 作为开发者，我想按请求配置调用超时，以便慢速供应商响应不会无限占用流程。
8. 作为用户（Owner），我想让每次外部模型调用都记录台账，以便知道我的哪些联系人范围的数据在何时被发送给了哪家供应商。
9. 作为用户（Owner），我想让台账永不包含消息正文、候选正文或联系人名称，以便审计记录本身不成为隐私泄露面。
10. 作为用户（Owner)，我想让台账记录 token 用量与延迟，以便观察成本走势。
11. 作为开发者，我想让台账按 owner 隔离查询，以便审计时不会跨用户串读。
12. 作为开发者，我想在测试套件默认不发起任何真实外部调用，以便测试保持确定、免费且不外泄数据。
13. 作为开发者，我想在显式提供真实凭据时运行一次端到端冒烟（合成数据），以便验证从配置到候选落库的完整链路。
14. 作为开发者，我想让冒烟验证断言台账已记录该次调用，以便台账与真实调用同步生效。
15. 作为开发者，我想保留现有 fake model 测试全部通过，以便接入工作没有回归既有行为。
16. 作为用户（Owner），我想让候选生成仍然只发生在应用内、由我编辑并亲自发送，以便接入真实模型不改变人工发送边界。

## Implementation Decisions

1. **零新接缝**：模型对象经现有 `BaseChatModel` 参数注入现有运行时 adapter；`ReplyRuntime` Protocol、`ReplyGenerator` 外壳、`ReplyStore` 生命周期均不修改。
2. **供应商构造**：新增 DeepSeek 模型构造入口，从环境变量读取凭据与模型名；凭据缺失或为空时构造即失败并给出可操作的错误信息。供应商包按 LangChain 官方 DeepSeek 集成接入，接入前按仓库规则核对当前锁定版本与官方文档。
3. **模型选择**：默认模型名显式定义于配置常量，可经环境变量覆盖；模型名与版本记入台账。
4. **出站台账**：新增台账 port 与 PostgreSQL 实现（跟随现有迁移序列），每次真实外部调用记录一条：时间、供应商标识、模型名、owner/contact 范围、输入与输出 token 数、延迟、结果状态（成功、运行失败、校验拒绝）。台账不含任何正文类文本；条目属于最小操作记录，联系人与来源删除时不作为派生资料级联清除，但范围字段保留以供审计。
5. **失败路径**：网络错误、超时、限流与结构化输出解析失败统一映射为既有运行时错误类型；请求按既有失败重试语义处理，不产生部分落库候选。
6. **测试边界**：真实 API 凭据不进入默认测试路径；冒烟验证沿用隔离环境变量模式（仿既有测试数据库连接串惯例），未配置时跳过并在结果中明示。
7. **隐私边界**：发送给供应商的内容与现有上下文装配完全一致（同一联系人有界上下文），不因接入真实模型而扩大；台账不新增正文数据流。

## Testing Decisions

1. 好的测试只断言外部行为：fake model 驱动的既有纵切测试保持不变，作为回归基线。
2. 模型构造测试：凭据缺失、为空、合法三种路径的单元测试。
3. 台账测试：进程内与 PostgreSQL adapter 的集成测试，使用合成数据与隔离测试库，断言字段完整、按 owner 隔离、正文永不入账。
4. 冒烟验证：显式环境变量开启时运行一次合成数据的端到端真实调用，断言候选结构合法、台账有对应记录；默认跳过。
5. 先例：`tests/integration/reply/` 的 PostgreSQL 流程测试、`NOTALONE_TEST_DATABASE_URL` 隔离惯例、既有 fake model 注入模式。

## Out of Scope

- 产品 CLI 或 UI（独立纵切）。
- 外部聊天发送能力（永久禁止，不注册任何发送 Tool）。
- 多供应商抽象与供应商路由（先 DeepSeek，经 `BaseChatModel` 天然可替换）。
- 前台同步、记忆提取、记忆目录、删除级联（后续独立纵切）。
- 成本预算硬限制与告警（本次只观察记录，不做强制限额）。
- 批量质量评测基准（候选质量系统性评测属后续工作）。

## Further Notes

- 本 spec 的方向决策来自 2026-08-22 会话：真实模型接入被定为当前最优先纵切，因为它验证已建成纵切的真实价值，且其结果影响前台同步与 UI 的形态。
- Harness 插件路线当日复议后不进入主线，本 spec 不引入任何 Harness 依赖。
- 接入后首次冒烟的观察点：结构化输出遵循率、校验拒绝率、单次调用延迟与 token 成本、中文候选的可读性。
