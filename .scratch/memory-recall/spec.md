# 记忆召回第一期规格（v1）

> Triage: ready-for-agent
> 来源：2026-09-17 三轮 grilling 决定，用户逐项确认；正式决定见 ADR-028 与 `architecture/drafts/recall-phase-1.md`。
> 范围：回复上下文按当前正文做确定性中文词法召回，联系人记忆与本人记忆独立双预算；不含向量检索、LLM 查询计划、待确认候选注入与界面改动。

## Problem Statement

用户回复联系人时，系统带进模型的关系记忆实际接近最早写入的前 20 条，而不是与当前消息相关的资料；带空格分词对中文基本不可用，当前消息对召回几乎不产生作用；本人事实记忆完全进不了回复；记忆注入没有字符上限。结果是候选回复要么缺少对方刚提到的偏好、禁忌或共同事实，要么被无关旧记忆干扰，用户无法信任"系统到底看了什么"。

## Solution

系统以当前待回复正文（或改写草稿正文）为 query，用确定性的中文词法覆盖率评分，从联系人与本人两个范围独立召回少量高相关记忆；低于相关性阈值宁可不注入；联系人记忆最多 5 条且不超过 600 字符，本人记忆最多 3 条且不超过 240 字符；每条记忆的入选原因（分数、命中词、排序因素）随回复快照落库；整套行为由无需模型、无需数据库的离线评测门槛放行。

## User Stories

1. 作为用户，我想让系统只带进与当前消息相关的记忆，而不是最早写入的固定条目。
2. 作为用户，我想让当前消息里出现的人和事直接决定召回结果，而不是被表达方向或旧对话稀释。
3. 作为用户，我想让中文短消息（如"他最近怎么样"）也能命中词法相关的记忆。
4. 作为用户，我想让与当前消息毫无重合的记忆不被注入，而不是凑数。
5. 作为用户，我想让"关于我"的本人事实和"关于对方"的联系人事实分别注入并明确区分，不混为一谈。
6. 作为用户，我想让本人事实不占用联系人记忆的条数与长度预算。
7. 作为用户，我想让手动录入的记忆在同等相关度下优先于自动记忆。
8. 作为用户，我想让已失效或已删除的记忆绝不进入回复依据。
9. 作为用户，我想让其他联系人的记忆在任何情况下都不会泄漏进本次回复。
10. 作为用户，我想在改写草稿并明确开启"参考关系资料"时，按草稿正文召回记忆。
11. 作为用户，我想在回复依据里看到每条记忆为什么被选中（分数与命中词），便于判断是否误召回。
12. 作为用户，我想在没有任何相关记忆时仍然正常生成候选，只是不带记忆。
13. 作为用户，我想让粘贴的长消息不会因为长度淹没真实信号。
14. 作为用户，我想让记忆注入的总长度有上限，避免候选生成被背景淹没。
15. 作为用户，我想让召回质量变化可以被离线评测提前发现，而不是上线后靠感觉。
16. 作为开发者，我想让评分、阈值、排序、预算都有确定性规则，出问题时能归因到具体一环。
17. 作为开发者，我想让评分器被 PostgreSQL 与内存适配器共用，杜绝两条实现漂移。
18. 作为开发者，我想让评测门槛在无凭据、无数据库的常规测试里运行，作为放行条件。
19. 作为开发者，我想让阈值与预算由评测标定后固化，修改必须附评测证据。
20. 作为开发者，我想让同义改写漏检的规模被持续度量，作为将来评估向量补充（ADR-005 第 5 节）的依据。

## Implementation Decisions

1. **查询构造**：query 只取当前正文——`reply_to_message` 取待回复消息正文，`rewrite_draft` 取草稿正文；表达方向与近期消息不参与评分；query 截取前 200 字符。
2. **分词与评分**：CJK 连续段取 unigram 权重 0.5、bigram 权重 1.0；拉丁字母与数字按小写词，权重 1.0；标点与空白只作分隔；两侧使用同一分词器，命中要求 token 完全相等；query token 去重；分数为命中权重占 query 总权重的比例（0 到 1）；评分器为纯函数模块，PostgreSQL 与内存适配器共用；不引入 PostgreSQL 全文检索扩展。
3. **阈值**：分数低于 0.15 的记忆不注入；无 token 或无命中时不注入任何记忆，回复链路照常降级。
4. **排序**：相关性降序，其次 `manual` 优先于 `auto`，其次置信度降序，其次 `valid_at` 降序（NULL 最后），最后 `memory_id` 稳定序；不使用加权总分。
5. **双预算**：联系人记忆最多 5 条且合计不超过 600 字符；本人记忆最多 3 条且合计不超过 240 字符；两侧独立、使用同一评分器与阈值；字符口径为 `len(text)`；不截断单条正文；按排序累加，遇到第一条放不下即停止。
6. **目录职责**：召回候选不再经联系人记忆目录过滤；目录仅通过 revision 快照参与生成前后复验；按 `memory_ids` 复验的路径保留。
7. **证据类型**：新增 `owner_memory` 证据类型；本人证据携带当前联系人范围仅表示会话可见性，重新读取只按 `owner_id` 并校验一致；提示中显式区分"关于联系人"和"关于用户本人"；证据顺序为消息、联系人记忆、本人记忆、继续候选。
8. **入选原因**：`selection_reason` 记录分数、命中 token 与排序因素，并随回复快照落库；macOS 界面第一期不改。
9. **复验**：生成前后对本人证据执行与联系人证据相同的存在性、来源、状态、有效期和 revision 复验。
10. **检索端口**：记忆检索结果类型增加相关性与命中词字段；本人记忆检索补齐按 `memory_ids` 复验参数并复用同一评分器与排序；`query=None` 时保持现有复验行为。
11. **生产接线**：回复装配把本人记忆存储接入检索；改写模式开启关系资料时同时注入两类记忆。
12. **数据库**：回复证据表的 `kind` 约束需要迁移放行 `owner_memory`（下一个迁移编号 033）。
13. **评测门槛**：新建合成中文召回评测，复用真实评分器与真实上下文组装，纯离线运行、无需模型凭据；每维度至少 15 条用例：直述命中 top-5 ≥ 90%、改写命中 ≥ 60%、无关拒绝误注入 0、跨联系人泄漏 0、失效或删除注入 0、预算超限 0 且双预算独立、排序优先级正确率 ≥ 90%。
14. **参数固化**：阈值、双预算与 query 上限为模块常量，不做运行时或环境变量配置；标定结果与版本写入 `docs/memory-recall-evaluation-baseline.md`。
15. **领域文档**：`CONTEXT.md` 已补充"本人记忆"并修订"回复上下文"范围；ADR-028 与草案 `architecture/drafts/recall-phase-1.md` 记录完整取舍；实现完成后回填 `architecture/current/`。

## Testing Decisions

- 好测试只验证外部行为：给定范围、正文与记忆集合，断言回复上下文的证据组成、预算、复验拒绝与快照持久化；不测内部函数调用顺序。
- 沿用四个 seam：① 回复上下文组装（现有最高 seam，验证 query、阈值、排序、双预算、证据类型与复验）；② 纯函数评分器（唯一新 seam，精确验证分词与公式）；③ 检索适配器（PostgreSQL 集成测试验证范围隔离与来源有效性）；④ 离线评测 runner（装配真实评分器与真实上下文，门槛断言进常规测试）。
- 既有先例：回复上下文 fake 检索测试断言证据类型与范围；抽取评测的门槛数学测试；PostgreSQL 检索的范围、来源与时间窗集成测试；抽取评测的合成用例字段格式。
- 评分公式的边界用例（无 token、无命中、全命中、大小写、截断、混排）进单元测试；PostgreSQL 只保留隔离与失效集成测试，不重复门槛。
- 评测用例全部合成，真实聊天不进入仓库，也不上传。

## Out of Scope

- 向量、embedding 与 rerank（保留 ADR-005 第 5 节的后续评估条件）。
- LLM 查询计划或同义扩展。
- 待确认候选进入回复（ADR-027 的后续纵切）。
- 记忆抽取、采纳与语用判定改动。
- PostgreSQL 中文全文检索扩展。
- macOS 界面展示与交互改动。
- 消息检索的 query 行为和六轨上下文组装规则。
