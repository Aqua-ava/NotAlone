# 混合记忆调度规格

Triage: ready-for-agent
State: open

> 决策状态：用户已明确选择新增增量资料自动处理、既有历史单独显式初始化。自动调度仅处理 read_goal.kind=incremental。本文记录产品行为，尚不代表后台实现、真实模型效果或桌面验收已经完成。

## 问题与目标

目前“新文字进入处理范围”与“立即调用模型”容易被混为一件事。逐条触发会在连续聊天期间频繁运行；只等较大批次又可能让低频联系人的文字长期不处理。主题整理和长期概览也不需要与每次 L1 提取同步重跑。

本规格为 read_goal.kind=incremental 的每位联系人建立独立分层调度：消息保存时只登记待处理并唤醒调度器；调度器在达到静默、数量或等待时长条件后启动 L1。有效记忆变化和主题正文变化分别安排 L2、L3，按固定窗口合并。打开记忆页、回复或新消息本身都不直接调用记忆模型。

实现目标：

- 新文字可按联系人安全积累，不因每条消息到达就调用模型。
- 有限延迟的 L1 提取使新采纳记忆能尽早进入回复检索。
- L2、L3 只在其上游确实发生变化时调度，并通过固定合并窗口控制重复工作。
- 延迟阶段、暂停、失败或未知模型回执均不能被 UI 误报为整条处理已完成。
- 重启恢复利用已持久化的范围和执行证据，不扩大来源授权或重复未知调用。

## 范围和术语

- **待处理文字**：已按现有来源合同持久保存、归属于唯一联系人、符合当前记忆提取资格，且尚未纳入已冻结 L1 输入的文字消息。媒体占位、归属待核验或授权不符的记录不合格。
- **联系人调度范围**：稳定的 owner 与 contact 身份组合。昵称、备注不参与路由。不同联系人各自计时、计数、冷却和运行。
- **L1**：聊天文字提取、逐项来源核验及正式记忆采纳。
- **L2**：基于当前有效正式记忆整理主题资料。
- **L3**：基于当前有效主题资料生成或更新长期概览。
- **调度窗口**：从首个合格变化发生时固定开始的等待期；窗口内后续变化合并，但不重置起点。

本人范围仍按 ADR-107 与既有 owner 范围单独管理。本决定确认联系人之间互不合批；本人范围是否使用完全相同的 L1 阈值不在本规格中改写。

## 已确认的触发规则

| 阶段 | 新增工作条件 | 合并与频率 |
| --- | --- | --- |
| L1 提取 | 有待处理文字，且满足以下至少一个条件：联系人静默 10 分钟；待处理文字达到 50 条；最早待处理文字已等待 6 小时。 | 同一联系人两次 L1 启动至少间隔 30 分钟。达到条件但仍在冷却期时保留待处理状态，在冷却期结束后重新判定。 |
| L2 主题整理 | L1 或其他受支持的正式流程提交了有效的正式记忆新增、修改或失效。候选拒绝、重复无操作、未确认候选、失败或无效调用不算正式记忆变化。 | 从首个有效变化起等待 1 小时；窗口内后续正式记忆变化合并，不顺延窗口。 |
| L3 长期概览 | 有效主题文档正文首次可用或发生变化。仅发布指针、元数据或文档排序改变而正文未变，不算正文变化。 | 首次有合格主题正文时允许初始化一次。其后同一范围 L3 启动间隔至少 24 小时；冷却期间的正文变化保留为待处理，不推迟窗口锚点。 |

时间按本机持久调度记录计算。L1 静默与最早等待时长从合格文字持久进入待处理队列时开始，不用聊天的发送时间回填等待时长。L2 窗口锚定首次正式记忆变更提交；L3 冷却按同一范围上次 L3 启动时间计算。达到时限只代表可调度，仍须通过来源、授权、暂停、执行回执和预算复验。

## 调度与阶段行为

1. 合格文字提交后，持久记录其联系人归属和待处理状态，并通知调度器重新计算到期时间。该保存路径不等待模型，也不直接调用模型。调度器可用事件唤醒加持久期限检查；App 重启后必须能从持久状态找回已到期工作，不能只依赖进程内定时器。
2. L1 的三个门槛是“或”关系，30 分钟是独立的启动冷却门槛。相同联系人当前已有 L1 执行时不得并发启动另一条 L1。运行时新保存的文字不扩张已冻结输入，留待下一次 L1。
3. 有效正式记忆版本新增、正文修改或失效时，在其提交事务中一并登记 L2 调度要求；单纯保护／解除保护、拒绝候选或重复 no-op 不登记。该事务只写业务与调度状态，不调用模型。
4. L2 和 L3 的等待窗口不能改变其输入冻结规则：阶段工作到期后启动时固定当前输入及版本，模型运行期间不补入新资料；发布时按 ADR-117/118 复验版本、来源、范围和当前保护。
5. L2/L3 冷却不能阻止独立到期的 L1。内部任务如何编排仍须沿用统一处理入口、每阶段真实任务身份和固定输入；实现不得将不同联系人或不同冻结输入合并来满足调度效率。
6. L1 中每条正式采纳都可在来源和时间资格有效时立即供该联系人回复检索，不需要等 L2/L3。回复只读取当前有效记忆及经 ADR-118 完整发布且依据仍有效的文档。正式记忆失效后，依赖它的旧主题／概览文档立即不得作为回复依据；新发布完成前不能用旧正文填空。
7. L2/L3 是延迟阶段，不表示过程完成。联系人仍有待处理或已到期的适用阶段、等待冷却的合并窗口，或未解决的安全阻碍时，统一状态不能标“已完成”。只有相关阶段成功或按 ADR-118 记录为明确不适用，且没有剩余待处理工作时，才可完成。状态读取和记忆页面展示均不得启动模型。
8. 每阶段保持 ADR-107 的来源、调用预算、有限重试、未知回执检查、手动暂停优先、受阻状态与范围隔离。不因新变化、计时器、页面打开或 App 重启清除暂停、不确定调用、受阻原因或累计预算。

## 暂停、删除与重启

- 用户暂停是该联系人范围的持久控制；计时和新变化可以被记录，但不会启动暂停范围的模型工作。只有明确继续且资格复验通过才恢复。
- 来源撤销、删除、联系人边界变化或授权失效会使相应待处理输入失去资格，并按既有删除闭包清除派生资料。晚到结果不得提交；已撤销来源不能由旧队列或历史消息自动恢复。
- 失败时保留成功阶段结果、固定输入和有限累计预算。未知调用结果先核验真实回执，不能因 30 分钟冷却结束或重启而盲目重发。
- App 正常退出时停止工作进程，不在退出后调用模型。重新启动后仅恢复未暂停且来源、范围、版本、预算和调用回执都允许安全续跑的工作；同时重算持久待处理窗口。启动本身不新增数据授权。
- 处理仍按 owner 与 contact 隔离；同一范围冲突由既有租约、CAS 和发布校验处理，不能用显示昵称猜测或合并。

## 既有历史：独立显式初始化

首次处理已有历史文字须与增量调度分开：由独立显式初始化开始，采用独立固定批次、独立进度和独立累计预算，不把旧历史伪装成新消息，也不挤占或扩大某个增量 L1 冻结输入。自动调度仅适用 read_goal.kind=incremental。

历史处理不因首次同步、普通新消息、记忆页打开或 App 启动而自动创建或启动。用户已明确选择单独显式初始化；今后若要改为自动安排历史初始化，须作为独立决策提出，不阻塞本次增量调度。

## 验收条件

- 合成联系人资料验证 10 分钟静默、50 条阈值、6 小时最早等待和 30 分钟启动间隔；三个 L1 门槛各自可触发，冷却期间不提前运行。
- 连续消息、长时间低频消息及第二位联系人并行场景均保持各自独立计时；保存每条消息不直接产生模型请求，当前 L1 的冻结输入与下一批文字不混合。
- 多个有效正式记忆变化只生成首个变化锚定的 1 小时 L2 工作；候选拒绝、重复无操作和失败不触发 L2。窗口内后续变化不会重置首个截止时间。
- 首次有效主题正文可初始化 L3；后续正文变化在 24 小时冷却内保持待处理，冷却后最多启动一次。仅元数据变化不触发。
- L1 新正式记忆无需等待背景阶段即可用于回复检索；已失效正式记忆的旧主题／概览正文不进入回复依据；完整发布集合、CAS 和来源删除仍遵循 ADR-118。
- 暂停、撤销来源、启动中退出、重启、可重试失败、预算耗尽及未知调用回执场景不会误启动或重复模型请求；其余联系人继续独立推进。
- 仅 read_goal.kind=incremental 自动进入混合调度；已有历史不会被新消息或重启自动回填，且须独立显式初始化。
- 正式宿主、真实 SQLite Worker/认证 HTTP、生产具名桌面桥和记忆页面，以及 pnpm run dev 热更新 App 的合成资料交互按 ADR-107 已确认的验收边界验证。复用实际 App 前先确认并复用现有开发实例；不以构建或代码检查替代交互验收。
- 本规格的功能未完成，须在实现后按上述范围记录合成与桌面实际结果。真实资料或真实模型语义质量不从合成验收推断。

## 非目标与限制

- 消息保存、同步、回复、记忆页面访问都不是直接模型触发器；页面继续只读。
- 不改变联系人确认、同步授权、来源所有权、回复范围、用户手动发送、自动采纳来源核验和删除约束。
- 不调度媒体 OCR/ASR 或隐式处理其他联系人历史。
- 不新增外部队列、云端服务、可执行 Tool 或聊天发送能力。
- 调度需要持久化 scope/stage 队列及 run requirement 映射；这是任务状态结构，不搬迁、重导或重新读取聊天资料。字段及具体存储结构由实现设计记录，本规格不规定。
- 不在本轮宣称功能已实现；不以定时参数的代码存在替代端到端行为证明。
