## 已确认的选择

grill-with-docs 的讨论结果在本规格中保存。以下为用户回答与最终确认的共同理解；后文的装配和度量规则是用于执行这些选择的工程细化。

| 决策 | 用户选择 | 对实验的约束 |
| --- | --- | --- |
| Q1：第一轮范围 | 只测已采纳记忆 | 不比较原始聊天消息检索，不改变提取与采纳。 |
| Q2：评估对象 | 评估 Hindsight 服务 | 必须运行实际服务，不能以仿写算法或假适配器结果代替服务结果。 |
| Q3：覆盖与准确性 | 提高覆盖，无关注入不增加 | 中文改写 Recall@5 至少提高 10 个百分点；最终上下文的无关注入率不高于现有路径。 |
| Q4：等待时间 | 不超过 1 秒 | 服务预热后，完整记忆检索、本地复验和上下文选取的 P95 不超过 1,000 ms。 |
| Q5：运行位置 | 本机自托管 | 只使用新建合成资料；embedding 与 rerank 均在本机执行。 |

用户另已确认：两臂使用同一记忆集合、查询和最终预算；外部命中须回读本地权威资料；跨用户、跨联系人、已删除或失效资料注入为零；输出可复现实验与报告；实验隔离于业务数据和生产默认路径。

决策依赖为：先确定已采纳记忆范围，再比较服务；先确定本机和合成资料边界，再选择可运行模型；先固定同一输入与本地复验，再评价覆盖、误注入和完整耗时。尚未由运行证据确定的模型、阈值和部署版本，须通过独立校准及接入验证后冻结，不作为用户已作出的选择。

## 问题陈述

NotAlone 当前按中文词法重合选择关系记忆，容易漏掉与原文含义接近、措辞不同的短消息。用户希望知道：引入 Hindsight 服务，能否在现有上下文预算内找到更多有用的已采纳关系资料，同时保持联系人隔离、删除和无关注入约束，并满足本机运行的等待时间要求。

Hindsight 具备混合检索与重排，但第三方的通用记忆能力不能直接证明其适合中文关系回复。现有评测基线记录的改写用例通过率为 14/15，且不是标准 Recall@5；不能把该结果换名，也不能据此宣称新服务有收益。需要独立、规模更大且含难负例的合成对照。

## 解决方案

建立隔离的本机实验，比较 A「现有词法召回」与 B「Hindsight 候选召回加本地权威复验」。两臂最终都经过真实回复上下文的预算选择，以实际选入的本地记忆身份评分。

第一轮以联系人已采纳关系记忆为实验变量。本人记忆继续走现有本地路径，验证其独立预算、归属和复验不受影响，单独报告，不混入联系人 Recall@5 的分母。这样可以判断服务的候选导航能力，而不把新增本人记忆算法、消息检索或记忆提取混在同一结果中。

交付可重复的数据、配置、运行入口和结果报告。报告给出「达到门槛」「未达到门槛」或「运行前提未满足」，逐项说明覆盖、无关注入、隔离与生命周期、耗时和本机资源成本。实验成功也不自动启用生产接入。

## 用户故事

1. 作为用户，我希望含义相近但措辞不同的中文消息能找到相关关系记忆，以便候选回复拥有必要依据。
2. 作为用户，我希望召回范围只包含已经采纳的资料，以免待确认推断被当作事实。
3. 作为用户，我希望提高覆盖时不增加无关资料，以免候选回复被旧话题干扰。
4. 作为用户，我希望同名联系人及另一位用户的相似资料都不会进入当前回复，以便保持明确的身份边界。
5. 作为用户，我希望修正、删除和失效的资料立即被本地复验挡住，以免旧索引恢复不适用的依据。
6. 作为用户，我希望检索产生的完整等待时间满足一秒门槛，以便评估交互是否可接受。
7. 作为用户，我希望实验只处理新建合成资料，以免真实聊天和关系资料参与第三方服务评估。
8. 作为用户，我希望 embedding 与重排都在本机运行，以便明确数据流向和本机成本。
9. 作为用户，我希望比较实际服务的效果，以便判断接入价值，而不只获得算法介绍。
10. 作为开发者，我希望两臂使用相同查询、资料和最终预算，以便把差异归因于检索路径。
11. 作为开发者，我希望校准数据与最终评测数据分离，以免调参结果冒充独立验证。
12. 作为开发者，我希望按本地记忆 ID 计分并去重，以免相同正文或多个 chunk 虚增召回。
13. 作为开发者，我希望区分外部候选、过门结果、本地复验和最终上下文，以便定位收益和漏检发生在哪一步。
14. 作为开发者，我希望检索分数与本地记忆置信度分别记录，以免把相关性改写成采纳依据。
15. 作为开发者，我希望服务故障、超时和空结果都出现在报告中，以免只统计成功快请求。
16. 作为开发者，我希望验证外部副本的删除，以免把本地不再使用误报为外部已清除。
17. 作为开发者，我希望保留现有词法、本人记忆和权限回归，以免实验装配改变默认产品行为。
18. 作为开发者，我希望锁定服务、模型、数据与代码版本，以便在同一环境复现结果并判断后续升级影响。

## 实现决定

### 1. 一个主要测试接缝

采用已有 `RetrievalPort` 注入真实 `RetrievalReplyContext` 的装配边界，不增加生产公共接口。A 使用现有本地检索。B 使用实验专用包装适配器，只改变带 query 的联系人记忆候选导航；消息检索、本人记忆，以及 `query=None` 或显式 `memory_ids` 的权威复验请求均委托本地实现。

B 依次执行：按已验证范围查询实验 bank、接收外部候选、按本地记忆 ID 去重与相关性过门、按 ID 回读本地记录、验证范围和版本、交给原有 Context 做预算选择，最后执行 `validate_current`。任何本地复验失败的候选都不能计作最终命中。

本地回读使用 `query=None`，避免再次用词法匹配否决语义候选。B 的相关性门在实验适配器中完成；返回的本地 `RetrievedMemory` 使用 `relevance_score=None`、空 `matched_terms`，保留原有 `confidence` 和采纳方式。原有 Context 仅对非空相关性分数执行词法 0.15 门，因此无需修改生产常量或默认装配。此行为必须有接缝测试证明；不能利用空分数绕过 B 自身的相关性门。

### 2. Hindsight 是可清除的实验索引

- 每个新建的合成 `owner_id + contact_id` 对应一个独立、不可由昵称推断的 bank；不跨 bank 搜索后再筛选。本人记忆不复制到联系人 bank。
- 每条本地关系记忆对应独立 `document_id`，metadata 保存本地记忆 ID、范围、层和 revision。多个外部 chunk 必须映射回同一条本地记忆。无映射、越界或版本不一致的结果拒绝。
- 本轮使用 `retain_extraction_mode=chunks`，关闭 `enable_auto_consolidation`，查询显式指定 `types=[world]`。新建空 bank，验证没有既有 observations 或 mental models。关闭自动归纳不等于清除了旧观察，也不禁止手动归纳；本轮不调用手动归纳。
- 不启动 LLM 提取、reflect、观察归纳或 mental model 生成。`chunks` 仍会清洗和切块；不能称为逐字无损入库，也不能据此承诺自动实体图或事件时间提取。
- 进入上下文的正文、来源、采纳方式、置信度、状态、有效期和 revision 一律来自本地权威记录。外部正文仅参与实验检索，不成为关系事实或替代本地证据。

### 3. 分数与校准

锁定调研源码的 recall HTTP 结果提供 `scores.final`、`reranker`、`semantic`、`keyword`，不要求开启 trace；具体部署仍须实际验证。`final` 包含排序加成，`keyword` 没有统一上界，`semantic` 可能为空，均不能冒充记忆置信度。

B 优先以真实本机 cross encoder 的 `scores.reranker` 作为相关性过门输入，使用 HTTP 接口返回的归一化分值，不使用模型原始 logits。固定评分字段、方向、模型和独立的阈值 `tau_B`；同一 memory 取最佳 chunk 的该字段过门，再按通过门的 chunk 中原生 `final` 最优值排序，平分时用本地 ID 保持稳定。该规则及候选池上限在校准后冻结。

在独立校准集上选择满足「无关注入不高于 A」的配置，再在其中优先提高召回。该阈值只是在此模型与合成分布上的经验规则，不是跨查询的相关概率或事实真值保证。若实际服务未返回必要分数、使用 RRF/passthrough 而无真实 reranker 分数，必须记录能力缺口并停止该配置的收益验收，不能伪造分数或以名次代替阈值。

接入验证还须识别部分重排超时：锁定源码可能把未完成评分的项目以 `reranker=0.0` 返回，不能仅凭字段非空认定已完成真实重排。结合可核对的服务诊断记录评分完成情况；未评分项不得按真实分数过门，无法区分时该次记为失败，不计为成功快请求。

外部分数、chunk 映射、过门理由和各阶段拒绝原因只写入实验诊断产物；不写回本地记忆，也不加入生成上下文中的事实正文。

### 4. 公平对照与数据冻结

- 只使用本任务新建的公开合成夹具；包含不同 owner、同名联系人、多个相关记忆及同主题难负例。资料类别、`auto/manual`、来源和有效期均显式设置。夹具直接构造已采纳资料，因此结果不证明自然聊天提取质量。
- 校准集与最终验证集按场景分离，同一事实的直接表述与改写不能分散到两侧。先确定相关 ID 与不相关 ID，再运行两臂；不能按 A 的失败输出反复挑选最终用例。
- 最终中文改写正例至少 60 条，每个 query 的 gold 至少一条有效记忆；包含低词面重合、否定、限定、时间语境及多相关项。每个主评测 bank 至少 300 条合成已采纳记忆，报告精确规模与构成。另设直述、无关短句、同主题负例和生命周期组，不混入主指标分母。
- 主收益组的所有 gold 合计不超过 5 条/600 字符；预算无法容纳的多相关项放入独立压力组，避免把预算约束误算成检索损失或人为抬高分母。
- A、B 使用同一当前正文、资料快照、已验证绑定、名义评估时间和最终上下文预算。query 使用现有 NFKC/casefold 与长文本头尾采样规则：头尾内容合计不超过 200 字符，采样间保留分隔。表达方向、近期对话与 LLM 扩展不参与记忆评分。
- 联系人最终预算保持最多 5 条/600 字符；本人保持最多 3 条/240 字符。字符按 `len(text)` 计算，不截断单条，遇到排序前缀中第一条放不下即停止。外部 token budget 仅限制服务候选，不替代本地硬预算。
- 冻结数据与 gold 摘要、随机种子、代码提交及参与装配的未提交差异摘要、服务版本/镜像 digest、模型和 tokenizer 版本、配置、候选预算、chunk 聚合与阈值。固定 `query_timestamp` 并验证重复查询稳定性；该字段只控制 Hindsight 的时间相关行为，不冻结本地有效期复验的墙钟。静态收益和耗时组的所有有效期在整轮尝试中保持状态稳定，记录两臂实际本地时间；时间边界与竞争另组验证，按实际状态快照标注 gold。最终集运行后不回调参数；修改配置须另立实验版本并保留失败结果。

### 5. 本机数据流与环境隔离

实验使用独立数据库、bank、端口、卷、模型缓存和产物目录；不得连接业务数据库、读取真实来源、复用业务 `.env` 或修改默认 feature flag。检索文本和 embedding/rerank 请求只进入本机服务；禁止云端 embedding、rerank、LLM 及自动云端降级。

允许为本机运行下载公开模型、依赖和镜像，记录其来源与固定版本；下载行为不携带合成 query 或资料正文。运行前确认实际配置没有外部推理请求，并报告服务、数据库和模型的启动方式。源码调研版本是兼容性核验依据，不能用它代替运行镜像的版本证明。

报告本机硬件、操作系统、容器/运行时、CPU、内存峰值、存储、模型下载和冷启动耗时，以及建索引与更新成本。资源数字不设未经确认的额外放行阈值，作为是否值得后续接入的依据。

### 6. 修正、删除与故障

实验建立显式的 retain、更新、删除和重建入口，仅作用于合成夹具。幂等重试不产生重复文档；同一 local ID 的 revision 更新后，不再接受旧 revision 的索引命中。单来源、多来源、整条记忆和联系人 bank 的删除分别验证，保留其他有效来源支持的本地资料。

分别证明两件事：本地已删除/失效/修正记录不会再进入上下文；对应的 Hindsight 文档、chunk、memory unit、向量及可检索副本确实按声明清除。前者通过不代表后者完成。验证外部副本时结合 API 与锁定版本数据库检查，检查运行缓存和重启后的检索；纯观察性检查无法证明的备份或存储介质残留必须列为限制。清理仅覆盖本实验资源。

服务不可用、超时、分数缺失和映射异常均产生显式失败记录。B 不隐式换成 A 后再计作 B 的成功；失败尝试保留在运行分母和耗时统计中。生命周期竞争用例按实际状态快照标注 gold，不与静态收益用例混算。

## 测试决定

### 1. 主指标与验收

计分单位为 `(layer, owner_id, contact_id, local_memory_id)`；本人记忆身份不包含联系人归属。相同正文的不同 ID 不合并，同一记忆的多个 chunk 只计一次。

对于最终中文改写正例 q，G(q) 为预先标注的当前有效 gold，S(q) 为完成本地复验及 `validate_current` 后实际选入的联系人记忆。`Recall@5(q) = |S(q) ∩ G(q)| / |G(q)|`，主指标取各 query 的算术平均。若运行失败，该静态正例的 S 为空并按漏召回计，不只删除失败样本。

| 验收项 | 门槛与口径 |
| --- | --- |
| 中文改写收益 | 最终组 B 的宏平均 Recall@5 减 A 至少 0.10，即至少提高 10 个百分点。 |
| 无关注入 | 在同一冻结质量组上，B 的「至少选入一条非 gold 的 query 数 / 全部 query 数」不高于 A；同时逐项报告误注入 ID 和总数，不能隐藏在平均召回中。 |
| 范围与状态 | 最终上下文跨 owner、跨 contact、已删除或不在有效期资料注入数均为 0。 |
| 预算与去重 | 条数、字符超限和同一 memory 重复选入均为 0；本人预算独立。 |
| 本地证据 | 所有最终记忆的正文、来源、采纳方式、状态与 revision 均可与本地权威记录核对。 |
| 完整耗时 | 预热后 B 的完整记忆检索与本地复验、上下文组装 P95 ≤ 1,000 ms。 |
| 现有路径回归 | A 的现有召回与权限回归仍满足原有门槛；本人记忆本地路径不因 B 的装配发生变化。 |
| 外部生命周期 | 完成可验证的索引更新与删除场景；未清除的副本必须标记失败或限制，不能宣称删除完成。 |

无相关资料的 query 不定义 Recall 分母，计入无关注入与空结果报告。隔离/失效组须同时含可用正例并断言其可选入；不能用始终返回空集合同时冒充召回与隔离通过。另报告 Precision@5、正例空结果率、直述表现、预算压力结果与本人路径回归，不将不同分层合成一个数字。

### 2. 耗时与可重复性

计时从记忆检索入口开始，包含 HTTP、query embedding、各路检索、重排、去重映射、本地读取、来源/状态/revision 复验、双方记忆预算选取及最终当前性校验；不包含模型首次加载、建索引或回复生成。P95 是 B 的完整耗时，不是 B 减 A 的差值，也不是只测 HTTP 服务内部耗时。

在固定规模上预热，预先固定重复次数和交替运行顺序；A、B 各至少 100 次正式尝试。报告全部尝试的 P50/P95/最大值、成功尝试分布、失败/超时数量与失败比例；超时计实际等待时间，不能以短路或回退隐藏慢请求。P95 使用排序后第 `ceil(0.95 × N)` 个值，并保留每次测量及查询分组。存在运行前提缺口时，结论为「未满足前提」，不能只凭快失败放行。

### 3. 外部行为测试

主要通过真实 Context 接缝验证输入范围、选入证据和拒绝行为；实际收益和时延必须由真实自托管 Hindsight 提供。测试替身只用于确定性故障和竞态，不代替服务验收。

- 低词面重合正例通过 B 的门后可选入，即使 A 词法低于 0.15；本地 confidence 与 `auto/manual` 未被改写。
- B 低分结果在 Context 之前被拒绝；空相关性字段不成为全量注入入口。
- 多 chunk 去重、相同文本不同 ID、缺失映射、错误 bank、跨用户同名联系人、旧 revision、无效来源和失效时间均产生预期证据或拒绝。
- 回读和选入后分别注入删除/修正竞争，最终当前性复验须拒绝旧快照。另有多来源删除、幂等重试、重建和重启后检索测试。
- `query=None`/ID 复验委托本地，不访问外部服务；普通改写未授权参考关系资料时，不访问历史检索。
- 保持联系人与本人双预算、无 query/无 token、长文本头尾查询、直述、无关短句及服务超时的行为。

复用现有记忆召回夹具及 Context 测试的组织方式。现有记忆评测 runner 固定装配内存检索，须支持实验装配或由独立 runner 复用其夹具；消息检索评测入口不能冒充记忆评测。旧 109 条是回归集，原有 `hit_rate` 是用例通过率，不重命名为 Recall@5。

### 4. 实验交付

应交付以下可核对材料：运行与清理说明、合成校准集及最终集、gold 与版本清单、本机服务配置、实验适配器及 runner、接缝/生命周期测试、逐 query/逐尝试结果，以及中文报告。报告按门槛逐项给出实际值、通过/失败和证据，区分候选覆盖与最终上下文覆盖；记录安装或运行失败，说明本机成本及证据范围。

只有完成真实运行及上述验收，才可将本实验执行状态改为完成。下一阶段是否接入服务、与词法融合或只借用方法，依据报告另作决定。
