# 本机已有记忆的原文核验与修复

> Triage: ready-for-agent
> 来源：用户要求直接核对实际聊天与已有记忆，发现不对就按仓库工作流修复，并授权 Agent 完成普通验证。
> 上游：ADR-024、ADR-026、ADR-027；记忆准确率规格中已有的公开提取、采纳与评测边界。

## 用户问题与完成条件

核对当前用户已有记忆和候选的直接来源及最小上下文，区分原意错误、采纳错误和历史时间缺失。原文支持且无明确错误的资料保留；未经证据支持的身份、长期偏好或人格推断不得变成已知事实。

本轮盘点为 6 条自动采纳记忆与 5 条待确认候选；自动采纳记录创建于语用与风险门槛上线之前。运行核验不得把它们归因为当前模型的新产出。真实正文与联系人标识不写入此规格、回归夹具、提交或公开评测请求。

## Implementation Decisions

1. 使用一个小任务完成原文审计、最小修复、回归、双轴评审与本地提交；不创建新聊天或远端产物。
2. 删除提示词中“未知第三人默认联系人”的规则；保留原文归属和歧义。不得从机构提及推断身份，或从一次玩笑、情绪、建议推断长期偏好。
3. 有明确期间的临时状态保留消息时间和期间含义；未确定失效日不发明 TTL。本轮不修改风险白名单或 0.7 门槛，不新增 verifier 或维度放行体系。
4. 自动采纳创建联系人候选时保留真实 `subject`，避免 shared 隐式回落为 contact。
   对来源校验已通过、但生效时间晚于全部证据时间的候选，增加不可自动采纳的风险标记；候选带生效时间而引用证据时间未知时也保守降级，不补时间。这仅按时间字段降级，不凭关键词判断事实，也不改变既有门槛。
5. 真实旧资料通过已有 port 的失效、候选创建与拒绝能力修复，保留旧行、来源和自动采纳标签；不以 manual 新增冒充用户确认。准确资料不重新提取或覆盖。修改前保存权限受控的本机恢复凭证，逐项核验且可恢复；保留全部来源消息、联系人身份与暂停范围。
6. 对明确存在问题的旧计划降级为带 plan 阻塞的 pending；历史临时故障降级为注明发生时间的 pending。缺乏来源支持的旧身份和稳定偏好候选退出待确认集合；不能据此断言现实世界中的相反事实成立。

## Testing Decisions

- 沿用已确认边界：`ExtractionFlow` → `PragmaticInterpreter`/`can_auto_adopt` 的候选输出，`MemoryAdoption.adopt` → `MemoryPort.get_candidate/list_confirmed` 的来源与主体，以及现有 `evaluate_case` 对分入口。
- 先运行能暴露 shared 主体丢失的合成回归，修复后复跑；不测试提示词字符串。
- 新增独立合成挑战覆盖未知第三人、身份过推、玩笑转长期偏好与明确时间限定；真实模型只接收合成输入，并逐条检查人物、否定、状态与日期，不能将总通过率称为真实聊天准确率。
- 有明确期间的时间用例比较实际日期和等价时区，不只检查字段是否非空；已取消事实的期望与现行时间维度规则统一，不将正确的取消陈述误计为假事。
- 实际资料修复后经公开 port 验证可检索集合、待确认主体、来源与原数据保留；最小相关单测、类型检查及一次完整测试后完成 Standards/Spec 双轴评审。

## Out of Scope

重新导入或全量提取真实聊天、上传原文到项目模型服务、用户手动确认资料的重写、聊天发送、来源删除、固定 TTL、自动维度放行、云端与 Git push。
