# 空会话展示名阻断读取授权列表

Triage: ready-for-agent
State: resolved

## 问题

CLI 会话元数据列表中出现空展示名时，适配器拒绝整批结果，导致其他正常会话无法出现在授权列表中。

## 范围与实现决定

- 仅在 `display_name` 为字符串且为空或全空白时，使用同条已校验的 `username` 作为展示回退。
- 缺失、null、非字符串名称与无效 `username` 继续报错。
- 保留所有会话记录、稳定会话标识及类型，不猜测联系人或新增读取授权。
- 已确认绑定与前台自动切换的既有资格规则保持。

## 验证要求

- 通过 `LocalWechatCli.sessions` 的合成批量响应复现一条空名称阻断正常记录。
- 验证空白回退、无效字段拒绝及同批正常记录保留。
- 先运行单例，再运行相关 CLI 适配模块；最后在已有 `npm run dev` 实例核对授权列表与联系人自动切换。
- 实际桌面操作和本机资料变更只报告范围与结果，不提交私人身份或聊天正文。

## Answer

- 已修复：空白名称仅回退为同条有效稳定标识，严格字段校验及身份、授权规则保持。
- 新增公共入口主回归修复前稳定失败，修复后通过；适配模块 29 项、相关 CLI 目录 103 项测试通过，桌面类型检查通过。
- Standards 与 Spec 独立审查均为 0 项问题。
- 实机授权列表从 HTTP 500 恢复为正常返回；在用户明确授权后，仅新增目标私聊的联系人与读取绑定。
- 桌面工具可操作后台微信窗口但未能将其激活；用户切回目标私聊后，Computer Use 核对 App 当前联系人已自动切换，无需再次点击联系人确认。
- 本机元数据索引已维护刷新；快照、私人联系人标识、聊天正文及授权数据不进入提交。未发送外部聊天消息。
