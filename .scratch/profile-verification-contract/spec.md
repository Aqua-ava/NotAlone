# 个人画像核验的时间引用合同

## 用户问题与已观察证据
已确认的一条静态身份事实在两次生成后被统一报为真实性核验拒绝；用户要求定位具体原因、修复并验证。
历史只保留通用拒绝说明，无法恢复两次原始核验响应。单范围授权快照的有限复验发现：模型明确支持内容，摘要、类别、普通来源引用均匹配，但在 `current_unverified` 下返回非空 `temporal_references`，触发程序拒绝。

## 实现决策
- 明确核验提示合同：`temporal_references` 仅为 `current_verified` 提供当前性证据；其他三种时间分类必须为空。普通事实来源仍放 `sources`。
- 不篡改或自动清空模型返回，不放松摘要、逐字引用、版本、时间或行动指导检查。
- 保留各项拒绝的固定原因码与中文说明，不保存或回显完整核验原文来代替诊断。
- 同时核对推断不得借 `current_verified` 升级为已核验现状，与既有提示合同一致。
- 原聊天、已确认记忆不修改；实际生成后仍暂停自动维护。

## 验证决策
- `ResponseModel → DeepSeekOrganizationVerification(personal=True)` 合成回归：两种合法姓名时间分类、错误字段的不同原因码、非空未核实时间引用拒绝、推断时间门。
- 同一真实候选与同一来源快照修前/修后核验。实际资料只在仓库外私有诊断目录；持久问题账本与 suite 共用最多8次请求预留、30分钟，不重置历史。
- 再沿正式后台恢复入口验证画像能否发布，检查原资料及自动维护状态。
- 历史两次原始拒绝未留完整响应；不得将本次复现推断为历史响应的直接证据，不把单点通过当作全局质量通过。
