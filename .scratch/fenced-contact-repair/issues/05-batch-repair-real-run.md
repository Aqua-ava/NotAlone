## 步骤

1. **运行前**：`cd desktop && pnpm run dev:status` 确认是开发实例；确认没有其他会话在改源码（热重启会让当次修复失败）；停读后对业务库做 SQLite 备份，`quick_check` 与外键检查通过（与 2026-11-01 做法一致）；记录基线：围栏数、各 `history_source_recertification` 状态数、消息/来源/别名/终态总数、图片已保存数和尝试按结果分组、`model_call` 行数。
2. **小批**：`limit=3`，包含一位图片多的、一位很小的。判定同任务 01 的 P1–P4；记录每万条消息耗时。
3. **中批**：`limit=20`。核对失败码分布，出现新类型先停下来问用户。
4. **全量**：无新类型再放开全部。期间每 10 分钟只读观测一次，不改任何数据。
5. **结束后核对**：围栏数；新增修复记录按 `state/stage/failure_code` 分组；同步页汇总“已保存本机历史 X / Y”；图片新尝试按 `state, error_code` 分组与已保存数变化；`model_call` 行数不变；与备份逐范围比较消息/来源/别名/终态，缺失或改写为 0。
6. **记录**：写 `docs/verification/fenced-contact-batch-repair-<日期>.md`：计数、耗时、原因码分布、限制，不含名称；分别写“自动检查”“用户实操”“Agent 只读观测”。无法验证的写明原因。
