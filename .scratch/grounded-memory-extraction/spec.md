# 原文分句驱动的结构化记忆提取

用户已确认：保持每窗口一次提取，让模型输出带原文定位的事实结构，再由程序校验人物关联、来源和时间并生成候选，无法核实的保留待确认。

## 接口与实现

在 MemoryExtractionRuntime.extract(window) 接缝新增 grounded-v1 adapter，输出仍沿原14槽，由原 ExtractionFlow 解析、V核验及采纳。旧 adapter 保留供历史评测；生产入口显式装配新 adapter。

程序按原文标点构建有界分句编号；模型对每个 target 分句恰好返回一条结构标签，不能生成任意正文、理由、日期或消息ID。必要上下文使用输入分句编号，每条最多一个直接依赖，编译器收集传递依赖，外部环或超过8层即失败；不按邻接自动补问句；可见第三人指代缺少外部定位时保留未知；不足以表达的复杂指代保留未知，不强称支持。完整原文仍在窗口与追踪中。

编译器检查编号、全覆盖、依赖和枚举；缺项/重复/越界停止整批，不进行隐藏重试。明确未纳入的分句有固定原因并保存追踪。正文由原文引句、原作者及必要上下文生成，不自由补人物、关系、日期和计划。未知第三人同一消息的分句合并成保留原顺序的引句，避免拆散原句关系。类别、语用和时间取自固定类型合同；相对日期用来源偏移计算，不接受模型写日期。条件从明确分句结构绑定；无法解析时间保持未知并降级，而非捏造。

这不是通用中文语义证明：模型仍判断类型、指代和纳入；V只降不升、默认放行表不变。程序的来源与结构校验不构成来源语义认证。风险标签不能通过此变更升级为可自动采纳。

## 测试

通过公开 compiler(window, draft) 与真实 Runtime.extract 接口，测试漏项、重复、跨联系人/越界编号、时间边界、条件、未知身份合并、无自由文本扩写、来源最小集合与trace故障。使用不同人名/活动/日期/偏移的合成变体，避免按六例特判。原六窗、Gold、额外输出检查均保持，实际请求/模型返回/编译输出分别记账。初次六窗后仅固定复测一次（共12次请求），之后只离线重编译，不重试到通过。
