# DSH 回复 Skill 接入规格

Triage: ready-for-agent
State: resolved

## 问题

用户希望回复助手自动使用合适的回复 Skill，而不必自己挑选或编辑 Skill。当前 SQLite 回复链只在显式选定时加载 Skill，且禁止模型调用工具；DSH 的通用目录和按需加载能力尚未完整接入。直接启用 DSH 文件扫描可能读取未授权的文件或跟随符号链接，无法满足 NotAlone 对读取范围、有效版本和联系人隔离的要求。

## 方案

使用 DSH 的 Skill 注册与模型加载能力，并以业务适配层控制可发现和可加载的内容。优先接入官方文件系统 Skill provider，通过受控文件服务在读取前实施业务约束；只有在正式组合验证满足约束后才使用该路径，否则保留必要的业务受控读取。模型根据本次对话判断是否使用一个 Skill，结果显示实际使用的 Skill 名称。Skill 暂时不可读时，在本次资料和授权仍有效的条件下不使用该 Skill 继续生成，并显示“回复策略暂不可用”。

管理刷新及每轮回复前自动发现已授权根的新包，不提供手动添加或填写包目录名/安装路径的入口。用户明确启用和停用保留；新增内容不要求用户自行安装或编辑文件。

## 用户故事

1. 作为用户，我希望回复助手根据当前对话判断是否使用 Skill，以便不用手动选择策略。
2. 作为用户，我希望没有合适 Skill 时仍能生成回复，以便不被策略库限制。
3. 作为用户，我希望每次回复最多使用一个 Skill，以便策略保持清晰。
4. 作为用户，我希望看到这次实际使用的 Skill 名称，以便理解回复采用的策略。
5. 作为用户，我希望没有使用 Skill 时不显示名称，以便界面准确反映实际情况。
6. 作为用户，我希望 Skill 暂时读取失败时仍能在条件允许时生成回复，以便继续完成当前任务。
7. 作为用户，我希望 Skill 读取失败时看到简短提示，以便知道这次没有使用该策略。
8. 作为用户，我希望新发现的 Skill 在我启用后才可供模型使用，以便控制策略库。
9. 作为用户，我希望应用负责更新 Skill，以便不需要自己编辑文件或逐次确认更新。
10. 作为用户，我希望停用的 Skill 不再被用于新的回复，以便撤回我的选择。
11. 作为用户，我希望 Skill 的旧版本或已失效内容不会被悄悄恢复，以便停用和删除有效。
12. 作为用户，我希望模型只使用当前联系人允许的 Skill，以便不同关系之间的资料和策略范围不混淆。
13. 作为用户，我希望读取范围受到限制，以便 Skill 扫描不会读取未授权正文。
14. 作为用户，我希望目录中的符号链接不会让系统读取其他位置，以便本地资料范围受控。
15. 作为用户，我希望辅助资料只在需要时从有效的 Skill 版本读取，以便策略内容保持一致。
16. 作为用户，我希望读取的策略内容经过校验，以便修改或替换文件不会绕过有效版本检查。
17. 作为用户，我希望撤销联系人授权或删除来源后相关资料不再用于生成，以便撤销真正生效。
18. 作为用户，我希望能够看到和编辑候选回复，并亲自发送，以便始终由我决定发什么。
19. 作为用户，我希望一次性表达要求只影响本次回复，以便它不会静默成为长期偏好。
20. 作为维护者，我希望通用 Skill 发现和模型加载优先复用官方 DSH 接口，以便减少重复维护。
21. 作为维护者，我希望业务规则由受控适配层执行，以便更换或升级框架时保留产品边界。
22. 作为维护者，我希望能区分模型选择了 Skill 和实际读取了正文，以便展示与追踪反映真实行为。
23. 作为维护者，我希望模型请求和提交前复验当前资料与 Skill 资格，以便失效内容不被继续使用。
24. 作为维护者，我希望在失败、取消或超出预算时有明确结果，以便不会重复出站或留下不合规的运行副本。
25. 作为维护者，我希望通过正常入口和合成数据验证交互，以便不依赖真实联系人资料或发送外部消息。
26. 作为用户，我希望刷新后自动看到新发现的 Skill，并可明确启停，以便无需手动添加或填写目录与安装路径。

## 实施决定

- 延续正式 DSH profile、官方 `dsh-skill` registry 和作用域。优先组合官方 `dsh-skill-filesystem` 与 `dsh-tool-skill`；使用正式公开的插件及服务接口，不修改或分叉 DSH 核心。声明直接使用的依赖并固定版本，按项目 DSH 源码查证流程核对导出、调用、服务注入和生命周期。
- NotAlone 业务插件或受控适配层负责账号与已确认联系人的资格、启停、有效修订、来源、输入记录、预算和删除。业务模块不要求全部插件化；用户 Skill 是策略文本，不是 DSH 可执行插件，不能注册 Tool、Shell、网络或发送能力。
- 对文件 provider 的目录枚举、路径解析、元数据和正文读取实施读取前约束。禁止扫描默认项目／用户目录与未授权路径、读取未启用 Skill 正文、跟随符号链接和路径遍历；只提供当前业务范围允许的内容。发现新包与读取其正文、启用是不同动作，不能把过滤模型目录当成读取前控制。
- 若采用自定义 `ctx.fs`，必须确保每次业务读取确实经过受控服务；服务缺失应拒绝该接入路径，避免 Node fallback 和绕过控制的 bundled 根。watcher 需要独立验证其文件接触与释放；不能只凭 `watchFollowSymlinks` 声称读取已安全。若官方文件插件无法满足约束，使用现有受控 provider 及必要文件读取作为替代，不静默扩大读取范围。
- 对每次实际返回的正文及辅助资源验证其归属、目录身份、有效修订、范围和完整性；目录、文件或资源发生替换时不得将未核验内容交给模型。实际返回内容与修订的绑定要考虑并发和路径变化，不能仅凭前后两次状态检查。确保每轮零或一个可用版本，并处理撤销、停用、更新、取消和迟到结果。
- Skill 新增通过管理刷新和每轮回复前的受控自动发现完成；不提供管理页、IPC 或 HTTP 手动目录添加入口。内部目录登记仅供自动发现实现使用，不是用户操作。新发现的 Skill 经明确用户启用后才可用于模型。应用负责 Skill 更新，用户不需要自己修改或逐次确认；更新需要完成格式、安全、来源和版本技术核验，保持既有停用与删除决定。受影响现行规格对目录包自动发布的描述须按本次确认收敛，保留已采纳 ADR 的历史并按仓库规则记录必要修订；不借此改变自动学习草稿审核。
- 模型根据本次对话自动选择零或一个 Skill。对正常回复入口移除需要用户手选的交互；已有显式版本 API 仅按现有兼容与管理范围保留，不引入第二套资格规则。
- 官方 Skill 工具只能获得本轮业务 provider 的受控视图；受控资源只能读取已选版本的允许路径。调整当前单次调用和禁止工具的执行链为有界模型／工具流程，明确调用次数、时间和输入输出预算、取消及错误处理；仅开放本次所需只读工具，不开放通用文件、执行、网络或外部消息发送能力。
- 保存实际选择与实际读取的区别、使用版本、必要来源及完整模型请求的业务追踪；UI 仅展示实际使用的 Skill 名称，未使用不显示。追踪、会话和缓存应受来源、删除及授权约束，恢复会话不能使已失效内容重新可用。
- Skill 暂不可读时，若联系人资料与授权仍有效且能确保后续上下文不含失效 Skill，继续生成并显示“回复策略暂不可用”；不能保证时拒绝使用失效内容。联系人资料或本次授权失效时停止生成。不得以 Skill 故障降级绕过其他错误或保留失效工具结果。
- 保持联系人资料按 `owner_id + contact_id` 隔离；Skill 只影响表达方式，不能生成联系人事实、长期偏好或发送动作。更新与在途生成按现行版本失效和安全检查处理；不隐式引入无界重试或改变外部出站授权。

## 测试决定

- 用户已确认：以合成 Skill 通过正常应用入口检查自动选择、界面显示和读取失败；文件安全与联系人隔离使用自动测试覆盖。优先复用正式 profile、正常宿主和现有 SQLite 行为入口，使用受控合成模型替身观察模型请求、工具调用和结果；替身与真实模型差异必须记录。
- 通过业务入口验证自动刷新发现、无需手动新增/填写路径、明确启用停用，以及模型选择一个或不选、实际加载与显示一致、不可用提示、无需手选、用户编辑和手动发送边界。桌面验收使用隔离数据及 `pnpm run dev` 热更新实例，检查真实界面、相关状态与交互；无需发送外部消息。
- 以正式 DSH 组合验证自定义文件服务的发现、读取、作用域和释放；覆盖未关联／未启用目录、链接及目录链接、目录外路径、遍历、服务缺失、禁止的 bundled 根、取消和迟到结果。断言未授权文件在扫描前未被读取，而不仅是未进入模型结果。
- 使用受控时序验证读取期间替换、恢复、版本更新、停用和来源撤销；核对实际返回字节及模型请求与有效修订的一致性。覆盖资源变更、目录缓存、多个联系人和账号隔离、删除后持久会话恢复。测试面向可观察行为和安全边界，不只镜像实现。
- 覆盖 Skill 加载失败后继续生成的实际上下文、提示与用量；分别验证联系人资料或授权失效必须停止，不能把权限撤销视为普通 Skill 失败。
- 以现有 SQLite Skill 正式 profile、回复候选 profile、讨论生成和桌面入口的合成测试为先例，从最小相关检查开始逐步扩大。实际 App、真实模型质量和端到端渠道能力分别报告，仅以真实运行证据宣称对应结果。

## 不在范围内

- 自动学习、学习草稿、审核、发布或从联系人经验生成 Skill 的产品规则，保持现行约束，留待后续讨论。
- 修改 Skill 教学内容、引入 Skill 市场、网络下载、脚本执行或外部聊天发送。
- 用户私人 Skill 目录的删除、资料迁移、打包发布、远端推送及 Pull Request；除非另有明确授权。
