# 真实 ECNU 回复预算接入修正

Triage: ready-for-agent
规格状态：用户于2026-10-12明确确认；接入代码已验证；原库升级与真实 App 体验随后执行，不代表供应商或真人质量已验收。

## 用户问题与已确认决定

用户已授权当前集成版合入本机 main、验证后备份升级原库，并打开20分钟真实 App，由用户选择联系人、触发生成。集成及数据库升级演练已通过，但生成入口缺少真实 ECNU 完整计量配置，现有守卫拒绝短请求。用户确认改为已核实模型容量、明确输入估算和充足余量；接受估算仍可能得到供应商超长错误。不自动摘要或截断，超长明确提示新开。

## 实现范围

- 保留现有 LangChain 有界回复与方向探索，二者共用实际模型绑定计量器；不更换 harness。
- 仅已核实的 `https://chat.ecnu.edu.cn/open/api/v1` 与 `ecnu-max` 启用生产估算装配；实例、实际 SDK 接收地址和有效参数错配拒绝。其他未配置模型能力仍未知。
- 计入最终系统、消息、工具、结构化输出、有效模型设置及 framing 估算。采用完整出站 JSON 的 UTF-8 字节数加4096 framing估算，明确不是供应商 token 精度或已证明上界。
- 采用保守可用容量512000、输出上限4096、安全余量65536、提醒比例0.8。预算总量为输入估算＋实际输出预留＋安全余量，余量不是只有提醒作用。
- 新 `approximate` 类型与 `safety_margin_tokens` 正数元数据贯通守卫、可靠保存、HTTP、桌面解码及恢复；旧 `exact`、`verified_upper_bound` 回执保持兼容。
- 正常短请求可进入模型；估算标签在 `ready` 状态也可见。估算超过配置容量时零模型调用；供应商实际超长时保留历史并明确错误，不编造超限计数或静默重试。
- 不新增数据库 DDL；现有回执使用既有 JSONB。原库只在修正验证完成后按已授权操作升级。

## 验证决定

沿用已确认的公开桌面操作→生产 HTTP→隔离 PostgreSQL；仅外部模型边界使用合成受控适配器。真实 SDK 载荷以本次自有 loopback 或明确离线传输验证，不访问供应商或私人资料。

1. 短请求使用生产 ECNU 装配，返回明确估算回执；超长请求、后续工具增长、未知或错配配置在调用前拒绝。
2. 输出上限与预留一致，计量覆盖完整协议，安全余量与总数算式严格一致。
3. 新回执保存重读、旧回执兼容、错误不泄露正文；桌面 `ready` 也显示估算。
4. 真实服务超长错误明确展示，历史仍可读取；不触发自动裁剪、摘要或追加生成。
5. 最小相关检查后进行 Standards 与 Spec 两轴评审；本地提交并合入 main。实际 App 只由主 Agent 在20分钟有限 `test:app` 内启动，用户选择真实联系人、主动触发模型；不操作微信或发送消息。
