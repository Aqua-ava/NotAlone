# 持续前台定位与按联系人保留助手内容

State: open
Triage: ready-for-agent

> 日期：2026-10-14。产品范围依据已确认的 Q1–Q6；规格与架构修订已发布。现有单次入口的单帧链路已按[任务01](issues/01-single-frame-locator.md)完成代码及合成验证；02–06 仍待实施或验收，不能据此宣称完整目标或真实 App 已可用。

## Problem Statement（用户问题）

用户希望助手在微信前台时持续识别正在与谁聊天，并能在一个助手窗口中自由切换联系人。切换不应丢掉原联系人的输入或编辑，也不应中断已经发起的生成；结果必须始终回到发起任务的联系人。

规格发布时，前台定位在显示助手前单次触发，一轮采集两帧；有草稿或回复编辑时会转入手动确认。联系人选择会清空当前草稿，回复展示也会重置部分输入。这与已确认的持续跟随、切回恢复要求存在差距。01 已将该单次入口改为单帧，其余增量范围见任务索引。

现有助手会话和生成作业已经具有切换后继续执行、按原会话保存及阻止迟到结果覆盖其他联系人的基础。本规格扩展这些能力，不把它们列为从零建设，也不把历史测试结果当作本次持续单帧流程已验收。

## Solution（解决方案）

保留一个助手窗口，按已确认联系人分别保存输入、候选编辑、当前助手会话和生成状态。应用运行、前台定位允许且微信在前台时连续执行观察：每轮只截一帧，在本机内存定位两处会话名称并执行局部 OCR；一轮结束后再安排下一轮。

唯一匹配到已验证绑定后自动切换展示；切回来恢复该联系人的内容和任务状态。进入助手或其他 App 后暂停视觉采集，保留最后确认的联系人；CLI 继续独立同步已授权范围。识别不可靠时明确显示“当前联系人未确认”，保留内容和旧任务，选定联系人前不接受新的生成。

只有用户明确点击生成操作才创建候选回复任务。任务固定使用发起时取得的联系人、助手会话、输入版本和回复上下文；切换仅改变展示，新消息只提示。后台执行指应用仍在运行时继续处理，退出后的中断及恢复沿用持续助手会话约定。

## User Stories（用户故事）

1. 作为用户，我希望一个助手窗口显示不同联系人的内容，以便切换时无需管理多个窗口。
2. 作为用户，我希望微信在前台时持续识别当前会话，以便切换联系人后助手能跟随。
3. 作为用户，我希望每轮只截一帧，以便省去第二帧复查带来的等待。
4. 作为用户，我希望微信移动或缩放后重新定位会话名称，以便无需手填坐标。
5. 作为用户，我希望只有两处会话名称被 OCR，以便聊天正文和其他联系人列表不参与视觉识别。
6. 作为用户，我希望进入助手或其他 App 后暂停截图，以便采集始终限定在前台微信。
7. 作为用户，我希望回到微信后恢复观察，以便再次切换联系人时助手仍能跟随。
8. 作为用户，我希望已经验证且唯一的绑定自动识别，以便无需每轮重复选择联系人。
9. 作为用户，我希望首次绑定、改名、重名、低置信度或匹配失败时由我选择，以便避免错误归属。
10. 作为用户，我希望有草稿或候选编辑时也能切换展示，以便自由处理其他联系人。
11. 作为用户，我希望切回后恢复原草稿、表达方向和待回复对象，以便继续尚未完成的输入。
12. 作为用户，我希望切回后恢复候选选择和修改，以便已经调整好的文字不会丢失。
13. 作为用户，我希望切回后保持此前选择的助手会话，以便不跳到该联系人的另一段讨论。
14. 作为用户，我希望切换联系人不取消已发起的生成，以便原任务可以继续完成。
15. 作为用户，我希望后台完成的结果只保存到发起任务的联系人和助手会话，以便不会串到当前页面。
16. 作为用户，我希望切回后看到该任务的真实状态或已完成结果，以便判断下一步操作。
17. 作为用户，我希望不同联系人各自保留我发起的任务，以便无需等一人完成才处理另一人。
18. 作为用户，我希望看到排队、生成、完成和失败状态，以便区分等待与执行。
19. 作为用户，我希望识别和切换本身不创建生成任务，以便模型调用始终由明确操作触发。
20. 作为用户，我希望识别失败时保留已有内容和任务，同时明确提示联系人未确认，以便不会误认当前展示代表微信当前会话。
21. 作为用户，我希望手动确认前不能启动新的生成，以便旧确认不能被用于不可靠的当前定位。
22. 作为用户，我希望生成使用发起时的输入和上下文，以便后续切换、编辑或消息到达不会改变正在处理的请求。
23. 作为用户，我希望新消息只提示尚未结合，并由我重新生成，以便任务不会被自动反复重启。
24. 作为用户，我希望重复观察同一联系人不重置输入或重复提交任务，以便持续识别不会干扰操作。
25. 作为用户，我希望来源删除、联系人删除或授权失效后旧缓存和迟到结果不能恢复失效内容，以便保留功能遵守删除边界。
26. 作为用户，我希望退出后如实显示未完成任务的中断，重试由我发起，以便后台执行不会变成隐藏常驻服务。
27. 作为用户，我希望候选带依据、可修改且由我亲自发送，以便助手始终服务于我的表达决定。

## Implementation Decisions（实现决定）

### 持续观察与单帧语义

- 沿用现有前台定位控制器、认证观察入口及原生自动窗口观察边界，增加由可信宿主控制的连续调度。renderer 不得声明微信处于前台、扩大采集范围或直接启动原生读取。
- 同一运行时最多一轮观察在途；一轮结束后才调度下一轮，不按固定计时器堆积 OCR。观察间隔、失败退避和超时通过测量确定，保持有界和可停止，不预设未经实测的稳定延迟。
- 微信不在前台、窗口不可见、权限不可用、同步/定位停止或应用退出时停止新采集。迟到的暂停前观察不得重新启动调度或覆盖暂停状态；回到微信后重新检查允许条件。
- 每轮最多一次窗口图像采集。标题名称和选中行名称均来自该帧；已有同一裁剪上的 OCR 质量复核不等于再次截图，不得借复核增加窗口帧。
- 保留采集前后及 OCR 结束时不采图的前台进程、唯一窗口、几何和运行代际校验。能检测到的失焦、窗口变化或失效必须拒绝；未知布局、多个高亮候选、截断、不一致和低分名称继续失败关闭。
- 移除第二帧采集、第二次布局检测及跨帧名称像素比较。单帧结果只代表采集时刻的会话；同一窗口中发生的会话切换可能在下一轮才被发现，不宣称结果返回时仍是该人。
- 原始帧及名称裁剪只在本机内存处理并及时释放；不保存或上传画面、不 OCR 正文或其他列表、不切换或滚动微信、不读取其他 App。
- 每轮携带有效观察身份和采集时点；暂停、恢复、连接变化或新观察后，不接受旧代际结果覆盖新状态。人工确认仍沿用有界证据和已确认绑定契约，不长期复用过期的首次绑定证据。

### 展示联系人与任务归属

- 当前展示联系人和候选回复任务的归属分别管理。切换展示不能重写在途任务的 `owner_id + contact_id`、助手会话、请求键或输入版本。
- 复用现有持续助手会话、候选版本、明确选择及生成作业管理能力。运行中的输入保留以 owner/contact 和助手会话身份隔离，昵称、备注、外部会话定位标识不能成为隔离键。
- 进入另一位联系人前保留当前输入模式、草稿、表达方向/目的、待回复对象、纠正/要求、Skill 选择、候选选择和编辑；返回时恢复该联系人的当前助手会话和相应内容，重新核验资料有效性。只复用仍有效的状态，不能用整份旧权限或来源快照覆盖最新校验结果。
- 重复识别同一绑定不视作新会话，不清空、不重复拉起生成。识别到另一已验证联系人时自动切换，即使原联系人有内容或任务，也不因“已有编辑”要求额外确认。
- 识别失败时保留上一份内容供回看，但明确标示其所属联系人及“当前联系人未确认”，禁用新的生成。旧任务继续，因为识别失败不等于撤销其原有资料授权；用户明确选择有效联系人后才恢复新生成资格。
- 微信离开前台只暂停定位，保留最后确认的联系人及其内容，不将这种正常暂停等同于识别失败；用户仍可在助手内对该已确认联系人操作。返回微信时重新观察，遇到不可靠识别再进入未确认状态。
- 保留既有管理窗口和单一助手窗口宿主，不为每个联系人新建窗口或新增产品外部聊天接口。

### 生成调度与固定输入

- 打开助手、快捷键唤出、OCR 成功、切换、恢复内容或消息事件都不创建候选回复任务。只有用户明确点击生成操作才创建；单独确认联系人或方向不隐式提交候选生成，既有“结合新消息继续”等操作须清楚表达会生成。
- 在接受生成、取得有效准备回执时固定发起联系人的助手会话、输入版本、幂等请求身份和有界回复上下文。排队后不得在实际执行时改用另一联系人或后来才到达的消息；材料无法可靠固定时明确失败，不展示已成功排队。
- 后续只读检索仍限定在同一联系人和发起时取得的资料范围内，并保留既有预算、来源/授权及版本复验；固定输入不授权使用已删除、已撤销或已失效材料。无需为此复制完整联系人历史。
- 沿用现有生成作业和回复请求存储，增加或补全用户可见的排队、生成、完成及失败投影。允许不同联系人各保留显式发起的作业，按有限调度执行；后台继续不要求无限并行，不另建自治 Harness、每联系人常驻进程或通用任务队列。
- 同键同输入沿用幂等重放；同键不同输入报冲突。原有同一助手会话内的明确替换和显式重试规则保持，切换联系人本身不构成替换，也不绕过当前会话的活动请求限制。
- 完成结果先保存到原任务范围。当前展示其他联系人时不能推送原正文覆盖页面；切回时通过同一范围的可靠结果或只读恢复展示，不重发请求或重复调用模型。
- 新消息按原联系人记录“尚未结合新消息”的提示，保留正在生成的请求、原上下文和候选编辑；用户主动重新生成时才取得新输入。不同联系人的提示相互隔离。
- 来源删除、联系人/会话删除、授权撤销、Skill 失效和连接代际变化仍走既有失效及提交复验，禁止以“保留内容”为由恢复旧正文、执行旧授权或接纳晚到结果。
- 关闭/隐藏助手与切换展示沿用已有继续执行语义；真正退出应用沿用有限停机、中断记录及显式重试，不承诺进程退出后继续生成。CLI 停读与重新开启补齐仍按原同步约定执行。

### 架构关系

本规格依据 ADR-050 局部修订 ADR-049 的“识别后第二帧复查、每次最多两帧”规则，并修订核心流程中快捷键直接生成及将会话变化一概视作生成中断的表述。连续调度扩展现有显示前单次触发实现；ADR-049 没有规定持续调度方案，其唯一前台微信窗口、端侧内存布局和局部名称 OCR 边界保留。

ADR-042 的助手会话持久化、输入预算、显式替换、退出中断和删除规则保持。这里的“后台生成”仍是候选回复任务，不将短请求强行改成 ADR-007 的导入/删除步骤任务，也不更改 ADR-018 的命令 Worker 全局锁。ADR-023、ADR-025、ADR-030 的 CLI 授权、独立同步、停读与补齐保持。

## Testing Decisions（测试决定）

沿用持续助手会话规格中用户已确认的主接缝：生产桌面公开操作 → 认证后端 HTTP → 隔离 PostgreSQL，只替换消息到达、模型延迟和前台观察为可控合成输入。既有生成归属测试已经覆盖切换后继续、原会话保存和晚结果隔离；本次增加完整内容恢复和连续观察，不重复另造一套测试控制器。

原生单帧约束沿用现有自动窗口观察入口的注入接缝，检查实际采集次数、裁剪范围及外部观察结果。调度时钟可以受控，断言公开状态和采集行为，不绑定定时器实现、内部类数量或方法调用顺序。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 微信在前台连续观察 | 同时最多一轮在途；有效轮恰好采集一帧，两处名称来自同帧；每轮结束后才安排下一轮。 |
| 微信失焦、助手获焦、窗口不可见或停止 | 不启动新的图像采集；在途旧结果不能解除暂停；允许恢复后重新观察。 |
| 移动/缩放与不支持的布局 | 后续轮重新定位；可检测的中途窗口变化拒绝；歧义、低分和名称不一致保留人工选择门。 |
| 在 A 的 OCR 期间同窗切到 B | 不追加第二帧；结果仅描述采集时点，下一轮可更新为 B，不把一次结果宣称为当前实时保证。 |
| A 输入/编辑后 A → B → A | A 的输入、待回复对象、候选选择/编辑和助手会话恢复；B 不显示 A 正文；重复识别 A 不重置。 |
| A 排队/生成时切到 B | A 继续；B 可显式创建自己的作业；排队及执行状态真实，无切换触发的模型调用。 |
| A 在展示 B 时完成，再返回 A | 数据只保存到 A 的原助手会话；B 页面不接纳 A 结果；返回 A 只读恢复，没有新请求。 |
| 未绑定、改名、重名或低分 | 原内容和已有任务保留；标记未确认并拒绝新生成；明确选择后才恢复资格。 |
| 打开、恢复、切换或仅确认方向 | 候选生成调用次数为零；用户明确生成才建立请求。 |
| 排队/生成时新消息到达 | 原输入及上下文不变化，只产生同联系人提示；用户重新生成后才使用新材料。 |
| 删除、撤销和迟到结果竞争 | 原范围失效规则生效；删除后缓存、恢复及晚响应不能返回已删正文或复活任务。 |
| 关闭助手、退出及重开 | 关闭助手沿用继续执行；真正退出执行有限停机，重开如实显示中断，由用户显式重试。 |

自动验证分层执行最小相关原生测试、后端前台定位/回复集成测试和桌面公开控制器测试。需要普通页面时遵循受限 `test:pages`；真实 Electron、屏幕录制、原生采集、实际切换和耗时另经主 Agent 在用户认可的有限时段使用 `test:app` 验收。

实机验收需确认测试联系人及操作范围，本功能无需发送测试消息。只记录匿名场景、次数、采集次数、固定错误与耗时；画面和实际联系人身份不进入仓库。单帧减少工作量是设计预期，性能成功率和 OCR → 正式 App 绑定闭环必须由新实现实测，不能用旧原生预览或一次成功耗时代替。

## Out of Scope（排除项）

自动发送或填写微信输入框、控制微信切换/滚动、后台视觉采集、OCR 聊天正文或其他联系人列表、未确认会话正文读取、群聊及媒体正文适配、退出后隐藏常驻生成、无限并行、自动触发生成/重试/摘要、联系人合并与私人资料迁移、模型运行时框架更换、云端部署及多设备同步。

本规格不包含正在推进的记忆/Skill 演进实现，也不把旧自动定位任务或 Mac 最终交付任务直接标为完成。

## Further Notes（依据与当前缺口）

- Q1 确认只在前台微信持续观察，进入助手或其他 App 暂停；用户明确要求每轮单帧。

- Q5 确认识别失败保留内容和任务，但新生成前必须选定联系人；Q6 确认固定发起时上下文，新消息只提示。
