# 05：多联系人后台任务与状态恢复

State: open
Triage: ready-for-agent
Blocked by: 02, 03

## 交付行为

用户为 A 显式发起生成后可以切换到 B 并为 B 发起任务，各自保留真实的排队、生成、完成或失败状态。切换不取消原任务，后台结果保存到原联系人和助手会话；切回恢复状态或结果，不重复提交和调用模型。

## 依赖理由

- 02 提供按联系人及助手会话隔离的展示与恢复，任务状态需要回到对应内容中。
- 03 提供显式创建和固定输入/上下文的准备回执，排队后的执行必须复用原请求。

## 验收条件

- [ ] 不同联系人可各保留用户明确发起的作业，使用现有生成作业和回复存储按有限调度执行；记录实际调度上限及排队含义，不要求无限并行。
- [ ] 排队、生成、完成和失败投影来自实际准备、执行和持久化状态；仅取得回执不能被显示为已完成，准备失败不冒充排队成功。
- [ ] A 排队/生成期间切到 B 不取消 A、不改变其 owner/contact、助手会话、输入版本和请求键；B 可显式创建自己的任务，切换本身零生成调用。
- [ ] 等待调度期间的新消息、页面编辑及当前展示变化不重新装配原输入；原请求仍使用 03 固定的上下文和资料范围。
- [ ] A 在展示 B 时完成，只保存到 A 原助手会话，不覆盖 B 或收起其窗口；返回 A 只读恢复正确状态与结果，不重复请求或调用模型。
- [ ] A/B 的消息更新提示、错误和重试状态隔离；新消息只提示，原候选编辑及任务不自动替换或重启。
- [ ] 同一助手会话的活动请求、幂等重放、显式替换与重试沿用既有规则，不能因联系人往返而重复排队、保存候选或规避活动请求限制。
- [ ] 来源/会话/联系人删除、解绑/授权撤销、Skill 失效及连接代际变化处理所有受影响的排队/运行任务；迟到结果不能复活失效正文或覆盖新请求。
- [ ] 隐藏/关闭助手只离开展示，范围有效的作业继续；真正退出停止新调度并走既有有限停机、中断记录与可靠完成判定，重开由用户显式重试，排队任务不能隐式续跑。
- [ ] 排队和终态清理保持有界；任务元数据与操作日志不复制正文，不创建每联系人常驻进程、导入/删除步骤任务、自治 Harness 或外部发送接口。

## 测试与完成条件

在生产公开操作 → 认证 HTTP → 隔离 PostgreSQL 的接缝上使用延迟/失败可控模型。以有限调度形成 A 运行、B 排队/运行、A 晚完成、切回只读恢复及显式重试场景，断言状态、原/新请求身份、上下文、模型次数和候选归属；追加排队或执行阶段的来源删除、撤销、连接变化和退出竞争。

复用已有生成归属与退出恢复证据，新增队列和状态恢复必须单独验证。04 不构成本票先决条件，可通过手动切换完成闭环。在 `## Answer` 记录最小相关验证、数据影响、调度参数依据和剩余风险后改为 `resolved`；真实 App 生命周期由 06 组合验收。
