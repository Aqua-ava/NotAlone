# 05：多联系人后台任务与状态恢复

State: resolved
Triage: ready-for-agent
Blocked by: 02, 03

## 交付行为

用户为 A 显式发起生成后可以切换到 B 并为 B 发起任务，各自保留真实的排队、生成、完成或失败状态。切换不取消原任务，后台结果保存到原联系人和助手会话；切回恢复状态或结果，不重复提交和调用模型。

## 依赖理由

- 02 提供按联系人及助手会话隔离的展示与恢复，任务状态需要回到对应内容中。
- 03 提供显式创建和固定输入/上下文的准备回执，排队后的执行必须复用原请求。

## 验收条件

- [x] 不同联系人可各保留用户明确发起的作业，使用现有生成作业和回复存储按有限调度执行；记录实际调度上限及排队含义，不要求无限并行。
- [x] 排队、生成、完成和失败投影来自实际准备、执行和持久化状态；仅取得回执不能被显示为已完成，准备失败不冒充排队成功。
- [x] A 排队/生成期间切到 B 不取消 A、不改变其 owner/contact、助手会话、输入版本和请求键；B 可显式创建自己的任务，切换本身零生成调用。
- [x] 等待调度期间的新消息、页面编辑及当前展示变化不重新装配原输入；原请求仍使用 03 固定的上下文和资料范围。
- [x] A 在展示 B 时完成，只保存到 A 原助手会话，不覆盖 B 或收起其窗口；返回 A 只读恢复正确状态与结果，不重复请求或调用模型。
- [x] A/B 的消息更新提示、错误和重试状态隔离；新消息只提示，原候选编辑及任务不自动替换或重启。
- [x] 同一助手会话的活动请求、幂等重放、显式替换与重试沿用既有规则，不能因联系人往返而重复排队、保存候选或规避活动请求限制。
- [x] 来源/会话/联系人删除、解绑/授权撤销、Skill 失效及连接代际变化处理所有受影响的排队/运行任务；迟到结果不能复活失效正文或覆盖新请求。
- [x] 隐藏/关闭助手只离开展示，范围有效的作业继续；真正退出停止新调度并走既有有限停机、中断记录与可靠完成判定，重开由用户显式重试，排队任务不能隐式续跑。
- [x] 排队和终态清理保持有界；任务元数据与操作日志不复制正文，不创建每联系人常驻进程、导入/删除步骤任务、自治 Harness 或外部发送接口。

## 测试与完成条件

在生产公开操作 → 认证 HTTP → 隔离 PostgreSQL 的接缝上使用延迟/失败可控模型。以有限调度形成 A 运行、B 排队/运行、A 晚完成、切回只读恢复及显式重试场景，断言状态、原/新请求身份、上下文、模型次数和候选归属；追加排队或执行阶段的来源删除、撤销、连接变化和退出竞争。

复用已有生成归属与退出恢复证据，新增队列和状态恢复必须单独验证。04 不构成本票先决条件，可通过手动切换完成闭环。在 `## Answer` 记录最小相关验证、数据影响、调度参数依据和剩余风险后改为 `resolved`；真实 App 生命周期由 06 组合验收。

## Answer

已完成多联系人后台生成与状态恢复。生产 Main/preload 沿用原作业归属和后端准备/执行协议；只有取得真实准备回执才进入队列。当前连接最多 8 个未结算任务，桌面一次派发一个有效执行，后端仍用既有单次回复模型许可。8 项是有限用户积压的保守边界，不代表吞吐最优值；一个执行许可与既有后端串行能力一致。实际替换回执确认、权威删除或连接失效会释放本地许可，已失效的旧传输可继续收尾。

不同联系人切换和编辑只离开展示，不取消已准备请求或重新装配材料。真实排队/执行/完成/失败状态按原联系人、助手会话、输入版本及请求键显示；未知传输保持待核对。切回只读恢复，后台失败的普通、策略及继续操作均以原身份和原协议显式重试。新消息提示按会话保留标识并重新核验，既不影响其他联系人，也不自动触发生成。隐藏/关闭继续原作业，真正退出停止派发并使用原中断流程；会话删除确认后不被旧 ACK 阻塞下一作业。

旧连接退出证据不占用新连接的 8 项额度；跨代际未结算身份累计上限 32，达到上限要求先完成退出核对并显示旧连接待核对数量，同键已结束请求仍可接管原身份。终态元数据、消息提示标识、原策略/继续命令引用各最多 32 项。命令引用复用既有冻结对象，不复制正文到作业元数据；完成、失效权威读取、删除检查和连接变化会清理。没有数据库迁移、每联系人常驻进程或外部发送接口。
