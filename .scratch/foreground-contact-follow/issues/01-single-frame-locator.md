# 01：单帧定位贯通现有入口

State: open
Triage: ready-for-agent
Blocked by: None

## 交付行为

用户通过现有助手入口进行一次定位时，原生探针、认证后端和助手展示共同使用一帧取得的名称证据。每轮只采集当前唯一前台微信窗口一帧，保留必要的质量与绑定检查；结果描述采集时点，不能被解释为返回时仍是该会话。

本票先完成现有单次入口的单帧链路；连续调度由 04 交付。

## 验收条件

- [ ] 有效观察恰好采集一帧；顶部名称与选中会话名称来自该帧的两处局部裁剪，移除第二帧采集、布局检测及跨帧像素复查。
- [ ] 移动、缩放后的新观察使用当次窗口布局，无需手填坐标或旧人工 profile；未知布局、多个选中候选、截断、不一致、非法置信度或低分继续失败关闭。
- [ ] 保留不采图的前台进程、唯一窗口、几何和代际检查；采集或识别期间可检测的失焦、窗口变化、连接失效不交付有效旧结果。
- [ ] 同窗会话切换不能导致补截第二帧；公共结果与助手状态明确保留采集时点语义，不宣称消除了同窗切换滞后。
- [ ] 已验证且唯一的绑定通过认证观察链路映射到原联系人；首次、改名、重名、未绑定或低质量继续要求人工选择，外部会话定位标识不能替代 `contact_id`。
- [ ] 无前台微信、不可见窗口、缺失权限或定位停止时零图像采集；原始帧和裁剪及时释放，仅端侧内存处理，不 OCR 正文或其他列表、不保存或上传画面。
- [ ] 单次观察有明确超时与错误投影，不降低质量门槛或无界重试；匿名耗时证据与真实 App 性能通过结论分别记录。
- [ ] 定位不读取 CLI 正文、不改变后台同步开关、不创建候选回复任务、不操作微信或发送消息。

## 测试与完成条件

沿用原生自动窗口观察的注入接缝，以合成像素及可控上下文检查采集次数、裁剪、移动/缩放、质量拒绝和失焦。再通过生产认证观察入口与桌面公开控制器验证有效绑定、人工选择和错误状态传递，只替换 OS/CLI 输入为合成适配器。

执行最小相关原生、后端前台定位及桌面协议验证，记录实际命令、通过/失败、数据影响和剩余风险。合成链路不代替真实 App、屏幕录制权限或微信版本验收；实机组合由 06 接续。完成后在 `## Answer` 记录证据，再将本票改为 `resolved`。
