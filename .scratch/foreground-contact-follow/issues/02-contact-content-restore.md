# 02：按联系人恢复输入和候选编辑

State: resolved
Triage: ready-for-agent
Blocked by: None

## 交付行为

用户在一个助手窗口中手动从 A 切到 B，再返回 A 时，恢复 A 原来的输入、助手会话、候选选择与编辑。联系人切换不清空内容，也不把另一人的资料带入当前页面。

本票交付完整的手动切换闭环；自动跟随由 04 接入，在途任务状态的完整恢复由 05 扩展。

## 验收条件

- [x] A → B → A 恢复 A 的输入模式、草稿、表达方向/目的、待回复对象、纠正/要求、Skill 选择，以及仍有效的候选选择和编辑文字。
- [x] 每位联系人恢复此前选定的助手会话，不擅自选择另一段讨论或继承其他会话的候选、临时要求。
- [x] 状态按 `owner_id + contact_id` 及助手会话身份隔离；同名联系人保持独立，跨 owner 或连接代际不能复用旧确认、权限或正文缓存。
- [x] 重复选择当前联系人不重置输入、不新建助手会话、不重复保存或触发生成；新建、清空和删除仅沿用既有明确操作及其范围。
- [x] 保留并恢复输入不取消原来范围有效的生成，不重新提交请求；恢复可靠的候选版本和已保存结果时复用现有持久化能力。
- [x] 恢复前复验来源、联系人、助手会话和 Skill 有效性；删除或撤销后不能从缓存、异步旧读取或恢复副本带回失效正文，无关内容仍可保留。
- [x] 异步 A 读取在展示 B 时返回，不得覆盖 B；再次选择 A 时通过有效身份恢复，状态保存/读取失败有可见结果。
- [x] 保留一个助手窗口及既有管理窗口；切换、恢复、候选编辑均不填写微信输入框或发送消息，也不将临时要求变为长期表达偏好。

## 测试与完成条件

主接缝为生产桌面公开操作 → 认证 HTTP → 隔离 PostgreSQL，使用合成 owner/contact、助手会话和可控模型。验证 A → B → A、多段助手会话、同名不同身份、候选编辑、旧读取迟到、来源/会话/联系人删除、连接变化和恢复失败；断言公开输入、候选正文、有效选择及生成调用次数。

不另造一套会话存储或测试控制器，不要求提前实现任务调度。执行最小相关控制器和后端会话验证；在 `## Answer` 如实记录证据、数据影响和剩余风险后改为 `resolved`。本票不启动真实 App 或采集微信数据。
