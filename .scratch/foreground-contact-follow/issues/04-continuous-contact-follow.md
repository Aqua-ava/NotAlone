# 04：持续识别与自动跟随联系人

State: resolved
Triage: ready-for-agent
Blocked by: 01, 02

## 交付行为

应用运行且定位允许时，用户在前台微信切换已验证联系人，助手持续识别并自动切换展示，切回时恢复该联系人的内容。进入助手或其他 App 后暂停视觉采集；识别不可靠时保留内容和旧任务，明确标记当前联系人未确认，选定前不接受新生成。

## 依赖理由

- 01 提供单帧公共观察及采集时点语义，连续运行不得继续调用旧双帧链路。
- 02 提供完整内容保存/恢复，使已有草稿或编辑不再成为自动切换的额外确认门。

## 验收条件

- [x] 同一运行时最多一轮观察在途；一轮结束后才安排下一轮，没有计时器堆积、重复观察进程或无界立即重试。
- [x] 微信不在前台、助手获焦、窗口不可见、权限不可用、定位/同步停止或退出时不启动新图像采集；暂停前迟到结果不能解除暂停或覆盖新代际状态。
- [x] 返回前台微信且允许条件有效时恢复观察；正常定位暂停保留最后确认联系人，用户仍可在助手内对该联系人操作。
- [x] 唯一且已验证绑定自动切换展示，即使原联系人有输入、编辑或在途任务；重复识别同一联系人不重置、不新建会话、不生成。
- [x] 自动完成 A → B → A 后恢复该联系人的输入和候选编辑；观察及切换本身的候选生成调用次数为零，已有生成保持原归属。
- [x] 首次绑定、改名、重名、未绑定、低分、布局失败或超时进入明确的未确认状态；保留原内容并标明所属联系人，用户明确选择有效联系人前不能提交新生成。
- [x] 人工选择后，只接受符合当前有效观察/确认身份的状态；过期证据、旧观察及新的不可靠观察不能静默延续旧自动识别资格。
- [x] 同窗会话切换可以由下一轮更新，不补截第二帧；移动/缩放后重新定位，观察间隔、退避和超时有界且有测量依据。
- [x] OCR 与 CLI 分离：定位暂停或失败不停止已确认范围的 CLI 后台同步；定位不读取正文、控制微信或扩大绑定集合。
- [x] 解绑、联系人删除、连接变化、停止及重启使对应确认和在途观察失效；新调度不能恢复旧授权或已删内容。

## 测试与完成条件

通过可信宿主和生产公开控制器驱动认证观察接口，替换前台观察和时钟为合成输入；覆盖单轮在途、前后台切换、暂停/恢复、自动 A/B 跟随、失败后人工选择、旧响应、停止及删除。与真实后端/隔离 PostgreSQL 联合核对绑定资格及内容恢复，并以合成 CLI 验证同步不受定位失败门控。

本票使用 01、02 的完成行为；03、05 的新增生成/调度能力不构成本票先决条件，已有归属路径可用于验证原任务继续。运行最小相关验证并在 `## Answer` 记录证据、数据影响和剩余风险后改为 `resolved`；正式 App 持续采集及资源开销由 06 实测。
