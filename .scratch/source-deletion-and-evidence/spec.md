# 导入来源删除与回复依据可读化

## 用户问题与范围

用户要求继续修复项目审查发现的问题。本轮交付单一导入来源的查看、删除、持久化结果与显式恢复，以及候选回复的实际依据正文展示。用户已明确选择删除来源后保留不含正文的 AI 调用记录（ADR-031）。

## 实现决定

- 读取接口与删除接口限定当前 owner + contact；回复依据只读已完成请求的快照，不重新检索或调用模型，区分上下文材料和候选引用。
- 来源删除以后台任务持久化请求、固定步骤、租约、重试和结果；无需模型密钥。清理派生资料、索引与回复快照在同一数据库事务完成，后续步骤复核已提交的凭证。来源读路径在请求后排除待删来源。
- 保留共享来源支持的资料；清除所有状态下失去来源的记忆正文、候选失败说明及历史版本。单条记忆撤销语义不变。
- 应用重启或全局 Worker 忙时可由用户显式继续删除，不引入定时调度；只有来源凭证和任务终态均确认成功才显示完成。
- 界面说明本机原文件、微信原聊天不受影响；外部模型副本不随应用内删除自动清除；最小调用记录保留。
- 切换联系人、重新生成和删除后丢弃过期的异步显示结果。

## 测试决定

沿用 `.scratch/native-app-backend/spec.md` 已确认的进程内 HTTP seam 和 `.scratch/contact-identity/issues/03-implement-source-deletion.md` 的 `delete_source(...)` 与隔离 PostgreSQL seam。使用合成资料与独占 `_test` 数据库，不访问真实聊天或模型。验证跨联系人、幂等、共享来源、历史正文清除、持久化恢复及依据读取。Swift 编译并运行既有测试；不宣称已完成真实微信端到端验证。

## 排除项

联系人/账户整体删除、微信聊天删除、外部模型副本自动删除、上下文材料手动增删、自动恢复调度与真实环境迁移不在本轮范围。

## 实施状态

已实现。HTTP/真实 PostgreSQL 验证覆盖来源目录、重复删除、跨联系人拒绝、共享来源保留、所有状态记忆正文清除、最小台账保留、失败三次后的手动恢复、清理提交但步骤回执丢失的恢复，以及删除后依据接口返回 404。缺少可核验任务的旧删除凭证拒绝新建“成功”任务并提示单独核验；不对旧库残留自动做范围不明的清理。

Standards 与 Spec 双轴复核发现的失败原因缺失、刷新取消删除轮询、无任务终态误报完成均已修复并复核通过。候选编辑缓存随候选列表清理，异步记忆和消息结果受联系人/删除代次约束。
