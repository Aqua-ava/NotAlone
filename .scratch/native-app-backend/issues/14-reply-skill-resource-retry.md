# 14 — 回复生成中的 Skill 资源重试导致 500

Type: bug

**Triage:** ready-for-agent
**State:** resolved

**Symptom:** App 的回复工作区在生成候选时显示“后端返回错误状态 500”；同步状态、联系人消息流和本地模型服务本身均正常。

**Confirmed cause:** 当前 Skill 的 `SKILL.md` 可能列出多个参考路径，但本次目录实际只授权其中一部分。模型读取一个 Skill 后继续尝试读取未授权资源，运行时只返回模糊的“Skill 不可用”，没有明确告诉模型停止读取。模型于是重复调用 `read_file`，在结构化候选输出之前耗尽 Agent 步骤预算，最终被 App 显示为 500。

**Blocked by:** none

## 修复

- Skill 辅助资源读取失败时返回明确的终止反馈：停止继续读取资源，直接使用当前上下文生成候选。
- 在 Skill 运行提示中固定同一停止规则，避免模型把权限失败误判为可以换路径重试。
- 资源失败仍按失败关闭处理：标记本轮 Skill 资源状态异常，不扩大路径、联系人或 Tool 权限；候选可以安全退回无 Skill 路径。
- 增加合成回归测试，覆盖非法资源读取后的重复调用不会耗尽运行预算。

## 验证

- TDD：新回归在旧实现上稳定得到 `ReplyBudgetError`，修复后生成合成候选并在 3 次模型轮内结束。
- 回复资源与运行时测试：15 项通过。
- 回复 API 与持久化集成测试：16 项通过。
- 当前真实配置的运行时测试：返回 3 条候选；资源不可用时安全显示未使用 Skill。
- 重启后的 App 改写入口：显示“已生成 3 个候选”，每条带依据和引用。
- 重启后的 App 直接回复入口：显示“已生成 3 个候选”，本次 Skill 与上下文依据正常展示。
- 未发送任何真实联系人消息；测试只使用已授权联系人和已有数据。
