# 02 — 事件总线与 SSE 契约

Type: task

**Triage:** ready-for-agent
**State:** open

**What to build:** 后端服务向界面单向推送事件的通道打通：订阅方带上 token 即可收到结构化事件（新消息到达、同步状态变化、任务进度共用同一事件模型），断线可以重连。事件的 JSON 形态被契约测试钉住，作为 Swift 端解析的依据。

**Blocked by:** 01（后端服务骨架与进程内测试接缝）

- [ ] 事件订阅要求有效 token；事件只推送给持有对应连接的订阅方。
- [ ] 事件模型至少覆盖新消息到达、同步状态变化、任务进度三类，统一携带联系人范围与时间。
- [ ] 事件不包含消息正文；正文读取走联系人范围的查询接口。
- [ ] 契约测试钉住每类事件的 JSON 结构与出现顺序。
- [ ] 订阅断开后重连不丢事件语义（重连后以当前状态为准，不伪造历史事件）。
