更新日期：2026-10-10。本文替换旧 Swift UI、菜单栏和 `⌃⌥⇧S/E/I/1–8` 操作步骤。ADR-039 已退役这些入口；当前 React 管理页尚未接入 follow 诊断控制面。后端保留鉴权 HTTP 诊断接口，不能把接口存在当作新 App 已提供验证页。

本文记录当前后台诊断入口及真实验证边界；OCR保持暂停。原生App仍须单独有限时段，不因后台验证而自动获得启动许可。

## 当前入口与已验证范围（2026-10-10 23:55）

现有鉴权 `/api/sync/follow-smoke/*` 已接入当前 `CliFullSyncEngine` → `CliBackgroundSync`，不再委托旧 fallback，也不调用 OCR。开始诊断只观察正式全局流；中断仅关闭当前持有的流并走正式退避；结束仅关闭诊断标志，正常后台同步继续。关闭总开关或宿主 stop 才证明停读。全局流瞬时失败后3秒起指数退避、最长60秒，期间保留有界轮询；CLI明确不支持时不自动重试。流继续使用既有全局cursor，正文只读取当前active绑定。

真实固定CLI v1.6.25、生产引擎/SyncHost/控制器、进程内鉴权HTTP路由和独立PostgreSQL已验证：启动模式global_follow；入口中断后旧进程退出、联系人cursor不变，自动重建新流；直接终止本轮自有CLI也能检测并自动恢复。恢复后用户手动发送的新测试文字入库，总消息从1到2，安全对账后仍2；结束诊断后正常流继续，关闭总开关后流停止且新增CLI调用0。自有进程及临时库全部清理，未运行模型或OCR。

本轮HTTP是进程内请求经过真实路由与鉴权，没有外部监听；宿主按真实时钟逐次驱动，未启动正式常驻线程或Electron。前台输入在测试边界明确返回不可用，未调用探针。不能据此宣称签名App、网络HTTP传输、长时间运行、双联系人切换或退出App全部完成。测试消息是在恢复后发送，不作为中断期间新增消息缺口补齐的证据。

## 2026-10-11 复验更正

前一轮进程内路由脚本使用host.check驱动，它会主动请求重试，不能单独证明自动退避。最新使用正式SyncHost.start后台线程、不调用立即检查，已确认主动中断约3.2秒自动重连、意外进程退出自动恢复，替代先前的自动恢复证据。

首轮关闭期间零CLI调用、零新流、消息数不变已通过；重开补齐被验收适配层acceptance_scope_exceeded拦截，整批没有写入临时库，不据此推断生产漏读。随后核对用户重发的约定测试文字，单条入库及重启去重通过。

最终以该条为新基线，正式后台线程关闭同步后等待用户发送第二条约定测试文字，确认发送后重新开启：关闭期间CLI调用0、新流0、消息数不变；重开从保存的联系人游标补齐，消息数1→2，继续等待16秒后台安全对账后仍2，backfill_failure=null。最后关闭流、自有进程全部退出、临时库精确删除。没有调用host.check、OCR、模型或发送消息；此轮证明总开关关闭期间的新增消息补齐，不代替故障期间新增消息、长时稳定性、双联系人或最终App退出验收。

执行入口为私有忽略目录中的thread_gap_acceptance.py、confirmed_gap_message_acceptance.py和gap_confirmation_acceptance.py，均在Conda NotAlone环境运行；聚合审计不含正文、身份或精确游标，真实资料和临时脚本不进入Git。本轮仅更新验证记录，没有生产代码变更。

## 2026-10-11 故障窗口补齐补验

Conda NotAlone环境执行私有fault_gap_acceptance.py，正式SyncHost线程保持同步开启。终止自有真实CLI流，并在验收runner边界注入流重建和正文读取暂时不可用；故障确认生效后用户发送约定测试文字，确认后解除注入。累计7次注入失败，故障期间真实CLI调用0、新流0，消息数和联系人游标不变；解除后无需手动检查或重试，11.77秒补入1条，消息数1→2，全局流自动恢复、游标推进，后续16秒安全对账仍2，补齐错误为空。脚本退出0，最终关闭流、回收所有自有进程并删除临时库。仅记录聚合结果，不提交私有脚本、正文或身份；未运行OCR、模型或App。此项仅证明当前注入故障与真实单联系人消息恢复，长时、双联系人、最终App退出及视觉边界仍待验收。

## 现有入口及范围

React“同步设置”已有总开关、后台状态和补齐暂停/重试；联系人绑定使用“会话读取授权”。follow 专用控制暂由预约内的受控诊断客户端操作，不借用旧快捷键或让 renderer 持有认证 token。

[后端实际路由](../../backend/src/notalone/server/app.py)和[控制器](../../backend/src/notalone/server/follow_smoke.py)提供：

| 操作 | 鉴权本机端点 | 请求及作用 |
| --- | --- | --- |
| 状态 | `GET /api/sync/follow-smoke/status` | 只读当前策略、流状态及检查点。 |
| 开始 | `POST /api/sync/follow-smoke/start` | 仅在总开关已开时观察当前全局流；不自动扩大 active 集合。 |
| 固定检查点 | `POST /api/sync/follow-smoke/checkpoint` | JSON 仅提交固定 `label`，不提交自由文本或聊天正文。 |
| 中断本轮流 | `POST /api/sync/follow-smoke/interrupt` | 仅在本轮验证已开始且流 active 时中断；不用宽泛 PID 杀进程。 |
| 结束 | `POST /api/sync/follow-smoke/stop` | 结束诊断，正常全局流与后台同步继续；不等于关闭总开关或证明已停读。 |

响应可能包含展示名称、最近有效前台观察和联系人级计数。记录客户端必须只提取下文的允许字段，不把整个诊断响应保存到 Git 或普通日志。读取失败、流未 active 或前置条件改变时停止，不以空状态替代通过。

旧 [SH 向导](smoke/wizard-follow-smoke.sh)已改为退役提示并固定退出 2，不读取配置、不创建日志、不启动探针、后端或微信 CLI；本轮从仓库根目录和 `backend/` 分别验证该退出结果。现有固定鉴权 HTTP 操作仍需预约内由主 Agent 核对本次受控后端后执行；本轮通过忽略目录中的受控验收脚本完成进程内鉴权路由与真实引擎验证，结果见上方范围；不把该脚本当作产品界面。不要绕过新的桌面测试调度入口直接启动原生 App 或探针。

## 人工步骤与检查点

本轮只读一个已确认联系人的正文。没有第二个已授权联系人时，不为“切换”测试临时授权另一个；用户可切到其他可见会话验证其正文未被导入，再返回原会话。若要证明两个绑定各自 cursor 连续，需在新的范围内明确加入第二个联系人后单独验收。

| 步骤 | 操作者和动作 | 检查点及判定 |
| --- | --- | --- |
| 1 | Agent 核对唯一 active 绑定、正式轮询与模型关闭；用户手动开启已确认范围总开关。 | `baseline`：记录消息/观察计数、cursor 和重复数；等待稳定。 |
| 2 | Agent 在认可范围开始全局流诊断并确认实际 stream active。 | `before_follow`：保留真实模式、状态和安全错误码；流未 active 则本次未验证。 |
| 3 | 用户从另一个账号/设备向该联系人发送两条互不相同的合成短文字。 | `after_live_message`：各一条入库，记录聚合延迟和计数增量。Agent 不发送微信消息。 |
| 4 | 静置 30 秒。 | `after_idle`：重复身份数 0，计数不再增加；不记录正文。 |
| 5 | Agent 仅中断当前诊断流；用户再发一条合成消息。 | `after_follow_restart`：记录退避/恢复耗时，消息不丢不重，水位不回退。 |
| 6 | 用户切到其他会话再返回；让微信离开前台。 | `wechat_background`：已确认绑定 CLI 同步继续，未确认正文不入库；OCR 暂停不算 CLI 失败。单绑定结果不冒充双绑定 cursor 验收。 |
| 7 | 用户关闭总开关，确认停读；关闭期间发一条合成消息，然后重新开启。 | `after_reenable`：关闭期间不新增观察；重开只在已确认范围按 ADR-025 补齐 baseline 之后缺口，失败不推进水位。 |
| 8 | Agent 记录最终状态并结束诊断；用户关闭总开关或退出。 | `final`：独立确认总开关关闭/认证 shutdown 后停读，follow stop 的成功不能替代这一证据。 |

总时长预计 15–20 分钟，实际仍受新预约约束。Agent 不切换、滚动、点击微信或读取其他 App；所有微信操作由用户执行。

## 记录和完成条件

允许记录：固定 label、阶段、检查时刻和时区、内部随机联系人/绑定标识、消息与观察计数增量、cursor 变化、重复身份数、真实模式、流状态、错误码及聚合恢复耗时。票面仅保留聚合结果与代码版本；不保留联系人昵称、会话名、正文、完整 CLI 输出、原始诊断响应、精确聊天时间或凭据。

每项验收缺实际检查点即记未验证，不把“看起来正常”、接口单测、无头页面、签名通过或手册准备当作真实微信通过。后台 CLI 与前台视觉分别判断；票 04 的前台/关闭措辞已按 ADR-023/025/030 同步，微信退出前台只停止视觉采集，已授权 CLI 后台同步继续。

失败时停止本次，不补跑掩盖：结束诊断；随后关闭同步或认证退出并确认停读。保留失败阶段、计数和安全错误码。收尾不确定时不清除未知租约、不按 PID 猜测归属、不启动下一轮。真实结果由票 04 的 Answer 记录；目前仍 `claimed / ready-for-human`。
