# 腾讯记忆核心复用：规格草案

Triage: ready-for-human
State: open

## Problem Statement

当前 NotAlone 只部分参考腾讯提取流程；真实全量预览另走临时编排，按批追加 L2/L3，造成场景与画像增殖。用户要求以本地腾讯项目为准，完整复用记忆核心，不能继续用部分相似行为代替对齐。

## Solution

锁定 TencentDB-Agent-Memory e9a82935b52741e0c798c75326e90b7144eb4d5f，优先复用实际核心模块、提示与状态推进，通过宿主适配接入 NotAlone。先验证可直接运行的接入方式，不预先承诺全部模块可作为独立库导入。无法直接复用时列明依赖、替代方式及行为差异，不静默改写后声称完全复刻。

同一条核心管线同时服务正式运行和隔离预览。预览仅改变存储范围，不替换业务编排。

## User Stories

1. 用户能知道当前核心版本及有意保留的差异。
2. 聊天按已确认联系人进入核心，不跨联系人检索或合并。
3. L1 直接生成完整候选，并实际调用相似召回及批量新增、更新、合并、跳过裁决。
4. 同一输入重放不会重复写入；相似的新信息可更新已有记忆。
5. L2 根据新增或变化的 L1 更新已有场景，也能创建、合并场景。
6. L3 根据变化的 L2 与已有画像更新同一份逻辑画像，没有变化时可跳过。
7. 本人与联系人资料分别保存，关系背景保留准确主体。
8. 失败输入保留可恢复进度，补跑不重复成功部分。
9. 来源删除、纠错或停用后，各层及缓存不继续使用失效内容。
10. 用户能在 App 查看生成状态、当前版本和来源，并修正、删除资料。
11. 真实预览走正式流程，显示明确的成功、失败、未采纳与未发布状态。
12. 不把 Agent 审阅登记成人工通过，也不把模型请求成功登记为质量合格。

## Implementation Decisions

- 以锁定版本建立核心入口、依赖、提示、状态机、异常处理的逐项对照；保留许可证及来源说明。
- 首先完成最小接入验证，确定 Node/TypeScript 核心与现有 Python/Electron 宿主间的受控通信、进程生命周期和存储适配，不整套引入腾讯无关服务。
- L1 必须实际具备上游支持的候选召回能力。明确采用哪条官方实现分支及依赖；不能把现有简单文字匹配标成全文与向量混合检索。新增外部 embedding 供应商或外发范围须另行明确，不能沿用 DeepSeek 聊天授权推定。
- 复用上游场景和画像状态更新行为，不能以各批列表拼接代替当前状态。
- 上游文档读写能力限定于当前资料范围的受控存储，不授予整个主机文件系统、网络或消息发送能力。
- 保留用户既定边界：owner/contact 隔离、来源与删除、手动发送、不推断性格动机。手动确认事实不被模型自动覆盖；候选、采纳和系统整理身份保持可区分。由此产生的行为差异须列入适配清单。
- 现有额外的格式、证据、采纳及质量约束逐项核对：保留的约束解释理由；与上游行为冲突的约束不得静默忽略，也不得宣称零差异。
- 不直接修改本地腾讯源码作为运行时隐式依赖；接入方式应可从固定版本重建并核对变更。
- 失败恢复覆盖输入身份、检查点及写入幂等，不仅在 HTTP 层重试。各实际请求计入同一运行累计预算；删除、取消及版本改变阻止后续写入。
- 先复用已有私有 L1 候选验证后半段；此数据未经独立核验，只可用于隔离预览，不导入为用户确认事实。
- 完整全量重建前，先用已授权联系人小批真实聊天验证同一正式管线；不再次启动临时的分批累加脚本。

## Testing Decisions（待本轮确认）

主验收边界为统一记忆管线的“提交同范围输入、执行/恢复、读取当前 L1/L2/L3”接口。优先复用现有公开导入、后台任务、关系资料读取和删除接口。

1. 同批重复提交不新增重复记录或场景。
2. 同主题新信息更新原场景；L3 更新原画像，非无限追加。
3. 第一次失败、补跑成功后只有一次有效写入；成功批次不重新调用模型。
4. 无 L2 变化不无故更新 L3。
5. 不同联系人与本人隔离；来源删除与运行中删除均阻止残留使用。
6. 预览与正式运行使用同一核心，区别仅在存储和发布范围。
7. 保存上游原流程与接入流程的受控对照，逐项解释差异，不以模型输出逐字相等作为验收要求。
8. 最小相关测试后做实际开发 App 验收；只用 npm run dev，不打包、不推送。真实模型调用按小批累计预算执行。

## Out of Scope

腾讯的无关聊天代理、云平台、Skill 系统和其他产品模块；自动发送微信消息；扩大联系人授权；无说明的自动全量重跑；预设必须压缩到某个记忆数量。

## Further Notes
