# 腾讯记忆核心复用：任务拆分提案

待用户确认粒度与依赖后，逐张发布为 Local Markdown 任务。默认一个实现负责人按依赖推进，不创建多个活跃聊天。

1. **核心接入与差异基线**
   - Blocked by: None
   - 交付：固定上游版本，实际运行最小核心链路；明确宿主、存储、模型、召回依赖和产品差异。若关键模块不能复用，提供具体阻塞，不能退回自写流程却标为已复刻。
   - 验收：从固定版本可重复启动，模型和读写只在注入的授权范围执行；来源与许可证齐全。
2. **L1 去重更新贯通**
   - Blocked by: 01
   - 交付：真实聊天经核心提取、相似召回和批量裁决，关系资料页可读取当前记忆、状态和来源。
   - 验收：重复输入不增殖，更新与多条合并可观察，手动资料保护及来源删除有效；未配置所需召回不能假报去重可用。
3. **持续场景与画像贯通**
   - Blocked by: 02
   - 交付：L1 变化更新已有 L2，变化的 L2 更新已有 L3；App 可读取当前场景与画像。
   - 验收：同主题更新原场景；画像不按批累加；无变化可跳过；本人/联系人分开；来源变更传播至上层。
4. **统一预览、恢复与真实小批验收**
   - Blocked by: 03
   - 交付：预览和正式管线共用核心；失败可补跑，重启可恢复，旧临时生成路径不再作为功能验收入口。
   - 验收：只重试失败部分且成功写入不重复；用已有候选验证后半段，再用指定联系人小批聊天验证完整流程；Agent 提供实际 App 与来源删除证据。小批通过后才进行受控全量重建。
