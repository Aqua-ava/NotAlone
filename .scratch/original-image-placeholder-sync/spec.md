# 聊天图片原图提取与占位替换

State: resolved
Triage: ready-for-agent

## 用户确认范围

图片消息随现有授权聊天同步先入库占位，原图取得后在同一条消息关联受管文件并显示图片；确认只有缩略图时仅标记，不取缩略图。用户已明确采用此前成功的 wechat-cli 定位、wxkey 图片密钥、WXGF／HEVC 解码流程。

本轮只改图片取图、解码、保存、提取结果及必要聊天展示，不改记忆、回复生成、联系人规则、语音和视频能力。后续图文记忆可按稳定消息 ID、文件版本、来源和提取状态组装图片与相邻文字；本轮不启用该输入，也不把占位当作记忆事实。

## 行为

1. 消息先保存，图片处理不阻塞文字水位，不删除／重建原消息，保留发送者、时间、稳定 ID 和来源。
2. 原图必须通过当前账号、已授权会话及完整消息身份与唯一资源关联，原始明文长度／摘要和实际解码核验。文件名、变体、尺寸或可打开不能单独证明原图。
3. 当前账号图片提取可调用既有外置 wxkey image-key；仅在已核验账号与图片来源后按账号准备和复用，不调用 bootstrap／重启／改签微信，不把密钥写业务库、日志、argv 或 HTTP。
4. 对 WXGF 先验证原始解密内容的来源、长度和摘要，再有界解码为 PNG；质量证明分别绑定源摘要与输出摘要、转换方式及尺寸，不把 PNG 摘要冒充微信明文 MD5。
5. 原图文件保存在应用受管目录；SQLite 复用消息、媒体关联、尝试和文件表保存身份、状态及引用。未经验证的内容不发布。
6. 原图成功显示图片；pending/running 显示加载占位；确认仅缩略图显示“仅有缩略图，原图未取得”且不读取缩略图内容；缺资源显示“图片资源不可用”；缺钥／解码／格式失败显示“图片暂不可用”。失败不能推断只有缩略图。
7. 只处理当前有效授权的已保存历史图片及新增图片，新版本对旧图片失败重试一次，普通重复同步不重复保存、不忙轮询。用户清除不恢复，来源／联系人删除沿统一删除链及预览撤销 ACK。
8. 聊天中多张图片可同时预览；联系人或后端代次变化、清除与删除时撤下旧 DOM／Blob 并确认释放，不能串入其他联系人。
9. 图片保存／失败／清除后通过现有事件或正常刷新更新聊天摘要，只有 original 状态可返回原图 fileId；回复和记忆继续只用原有文字输入。

## 已确认验证接缝

- `notalone-history` 图片协议：合成数据库上的授权来源、原图证明、密钥缺失／错误、仅缩略图、转换及取消，不能替代真实微信验证。
- `media-validation wxgf`：合成原图内容及 HEVC 的实际原生解码、坏帧、边界及输出限制；不读取微信。
- SQLite 媒体公开服务与聊天历史 HTTP：落盘、状态、去重、隔离、清除及删除；不从内部实现推导预期。
- 聊天页面与既有媒体桥：占位替换、多图片、不同联系人、清除／删除撤销，原生能力另验。
- 正常开发实例：通过 pnpm run dev 复用热更新，真实授权图片按生产入口读取，核对受管文件可打开和数据库归属，不打包、不发送外部消息。

## 完成条件

相关最小测试、类型检查和独立 Standards／Spec 审查通过；真实原图至少一个成功保存并实际查看，未覆盖格式与环境限制据实记录；任务相关变更本地提交，未经明确同意不推送。图片密钥条款与原图解码证明同步形成后续 ADR，旧决定保留历史说明。

## Answer

按范围完成原图取图、WXGF 有界解码、专用密钥管道、状态投影及聊天占位替换。真实开发 App 已显示原图并核验仅缩略图提示与联系人切换；重复同步未新增文件或尝试，原有消息和授权摘要保持不变。自动检查、独立审查、实际结果、wxkey 权限及历史 WXGF 缺 HD 元数据的限制见 `docs/verification/chat-image-placeholder-original-20261101.md`。本地提交收尾，不推送。
