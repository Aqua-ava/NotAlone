# 讨论删除、跨联系人与历史规模回归

Triage: ready-for-agent
State: resolved
Blocked by: 01, 02

## 目标

验证旧讨论隔离不会破坏删除、跨联系人范围和历史规模边界，并证明新候选的成本不随旧讨论数量增长。

## 范围

- 删除历史讨论继续清理讨论、候选及运行时副本，不误删原始聊天、关系记忆或本人记忆。
- 联系人删除和来源删除继续传递清理相关讨论依赖。
- 历史讨论、当前讨论和候选请求不能跨联系人读取或恢复。
- 已删除正文、失效来源和已撤下候选不能通过回看或继续恢复。
- 构造多段旧讨论时，新候选的资料读取范围和查询次数不随历史数量增长。

## 测试 Seam

公开边界：删除请求、跨联系人讨论读取和新候选生成。

1. 多段历史讨论分别回看、继续、删除，核对删除影响清单。
2. 删除旧讨论后核对最近聊天、关系记忆和本人记忆仍存在。
3. 使用两个联系人交叉读取讨论 ID、候选 ID 和运行时副本，全部拒绝。
4. 删除来源后回看和继续不恢复旧正文。
5. 构造较多合成历史讨论，比较新候选的输入材料数量和读取范围；不以唯一固定毫秒阈值作为结论。

## 验收

- 删除闭包和跨联系人隔离无回归。
- 历史讨论数量增加不会改变新候选使用的资料集合。
- 性能证据与实际筛选结果分开记录；没有真实测量时不宣称性能已优化。
- 相关合成回归通过；真实数据与桌面验收范围单独说明。

## 不在范围

- 修复后台图片同步或记忆读取占用 SQLite worker 的既有性能问题。
- 自动压缩、归档或自动删除历史讨论。
- 远端发布、打包或外部消息测试。

## Answer

- 新增真实 SQLite 公开回归：先同步一条真实聊天、手工建立联系人记忆和本人记忆，再让候选冻结实际消息来源并在模型出站前受控失败；精确删除讨论后，请求、上下文、候选输入和失效发言闭包清空，兄弟讨论仍可读，聊天、关系记忆和本人记忆正文保持不变。
- 新增来源删除回归：候选实际来源删除后，聊天正文、候选输入和关联讨论发言均不可恢复；回看只剩空讨论，显式继续后仍为空，不会复活旧正文。
- 既有精确讨论删除用例补充断言：删除中的讨论不能回看，也不能通过继续动作恢复；联系人/账号删除、运行副本身份清理、错误联系人删除范围和副本规模回归继续通过。
- 新增规模回归比较 1 段与 40 段历史讨论：均为 3 项实际候选材料（同一条近期聊天与两项本次输入），读取动作集合均为 `discussion.localMessages`、`discussion.messages`、`reply.freezeInput`，未调用 `discussion.list` 或 `discussion.view`。不作为毫秒性能结论。
