# 讨论删除、跨联系人与历史规模回归

Triage: ready-for-agent
State: open
Blocked by: 01, 02

## 目标

验证旧讨论隔离不会破坏删除、跨联系人范围和历史规模边界，并证明新候选的成本不随旧讨论数量增长。

## 范围

- 删除历史讨论继续清理讨论、候选及运行时副本，不误删原始聊天、关系记忆或本人记忆。
- 联系人删除和来源删除继续传递清理相关讨论依赖。
- 历史讨论、当前讨论和候选请求不能跨联系人读取或恢复。
- 已删除正文、失效来源和已撤下候选不能通过回看或继续恢复。
- 构造多段旧讨论时，新候选的资料读取范围和查询次数不随历史数量增长。

## 测试 Seam

公开边界：删除请求、跨联系人讨论读取和新候选生成。

1. 多段历史讨论分别回看、继续、删除，核对删除影响清单。
2. 删除旧讨论后核对最近聊天、关系记忆和本人记忆仍存在。
3. 使用两个联系人交叉读取讨论 ID、候选 ID 和运行时副本，全部拒绝。
4. 删除来源后回看和继续不恢复旧正文。
5. 构造较多合成历史讨论，比较新候选的输入材料数量和读取范围；不以唯一固定毫秒阈值作为结论。

## 验收

- 删除闭包和跨联系人隔离无回归。
- 历史讨论数量增加不会改变新候选使用的资料集合。
- 性能证据与实际筛选结果分开记录；没有真实测量时不宣称性能已优化。
- 相关合成回归通过；真实数据与桌面验收范围单独说明。

## 不在范围

- 修复后台图片同步或记忆读取占用 SQLite worker 的既有性能问题。
- 自动压缩、归档或自动删除历史讨论。
- 远端发布、打包或外部消息测试。
