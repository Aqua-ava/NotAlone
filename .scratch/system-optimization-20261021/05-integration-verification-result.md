## 实际开发 App 与微信

先核验并正常退出已有 root 开发实例。其配置指向原资料库；本轮禁止业务迁移，因此没有重新连接该库。仅用 `npm run dev -- --user-data-dir <自有合成目录>` 启动一个 App，夹具使用独立随机合成数据库、脚本化本地模型及不可用 CLI；没有外部模型请求。

Computer Use 实际操作并核验：甲联系人输入草稿→乙联系人空白→乙草稿→切回甲恢复甲草稿；生成两条合成候选；编辑候选并失焦保存，依据显示同一甲联系人合成历史；复制保存文本再粘贴到本轮输入确认完全一致；资料页在联系人／本人范围切换、离开到 Skill 后重入恢复正确范围。没有触发外部聊天发送，也没有以合成计数冒充实际 UI 请求计数。

微信 Qt 窗口的 AX 不暴露会话控件，坐标操作返回 `AXError.notImplemented`；通过 Finder 的已有 WeChat 应用入口激活后，正式 `--foreground-status --json` 返回微信前台 ready，`--session --json --single-frame` 返回 exit 0、ok、`automatic-header-v4`、`layout_verified`、`name_complete`。仅在内存解析标题结果，未将名称和视觉帧写入证据；置信度 0.5，只证明真实前台标题采集链可用，不能认定联系人自动绑定。内置传输助手的选择未能证实，不能记作该会话的完整验收。没有滚动正文、执行正文 OCR 或发送消息。收尾通过搜索菜单执行全选清除并退出搜索，Qt AX 无法核对搜索框值；已确认关闭本轮 Finder Applications 窗口，保留用户微信和原有浏览器页。

App 通过正常 Quit 退出；两次自有合成夹具与随机库、用户目录均清理。首次启动被本轮崩溃留下的开发 socket 拒绝，核验精确路径、所有者、0600、无进程引用、ECONNREFUSED 和无开发实例后才删除本轮 socket；未修改失效关闭策略。原开发配置未改，root `dev:status` 为 stopped。没有发布或运行打包版。
