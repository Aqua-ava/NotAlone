# 本地 main 集成收敛

Triage: ready-for-agent
State: claimed

## Problem Statement

用户发现开发产物持续累积，随后确认重要交付代码散落分支、独立 App 与本地 main 不一致。用户于 2026-10-17 明确要求开始整合。起点为 d174538f6d01028404a6d0532f2c12c269051277；原主仓的未提交记录保持原状。

## Solution

将已获批准且有实际实现的功能按覆盖链收敛到经过验证的本地 main。区分已合补丁、重复验收端点、独立实现与尚无实现的规格，不按分支数量重复合并。只使用一个额外集成工作树，复用已有依赖和锁定下载缓存。

## User Stories

1. 使用者能从统一 main 构建当前独立 App，不必猜测交付来自哪个工作树。
2. 已完成的记忆、Skill、手动输入和受管运行时成果保留，同时保留 main 更新的官方模型、来源核验、权限及磁盘保护。
3. 已有 canonical 数据库能够前向更新，未知开发分叉停止且保留资料与恢复入口。
4. 未提交改动、旧分支独有源码及私人验收材料能够追溯，整合和归档不丢失资料。
5. 自动测试、真实 App 操作和未覆盖条件分别报告，代码集成不冒充质量或渠道认证。

## Implementation Decisions

- 先冻结命名分支及 detached HEAD，按祖先、同树、补丁等价和实际文件差异归并候选。主链只接收最终实现，不重新引入历史未脱敏的提交谱系。
- 在临时集成分支逐批合入：记忆/Skill 主链、独立 App 交付链，以及仍有独立功能的命名或 detached 候选。冲突保留双方意图，较新的已采纳模型和来源合同保持；未完成候选不得默认为放行或用户确认。
- 现有 main 迁移 001–059 保留原文件字节；独立 App 的 060 手动联系人确认保留。记忆集成原 059–068 以新名 061–070 追加，原 SQL 字节和内部顺序保持；后续独立迁移顺延且记录来源。D4 保留旧分叉库，不伪造或转换其账本。
- 不执行实际业务资料升级，不读取私人聊天，不调用外部模型或发送微信消息。旧版本来源证明、用户纠正、授权范围、删除依赖及手动发送边界保持。
- 集成测试通过和独立审查后，快进本地 main；主仓既有未提交记录逐项保持。已确认重复或完整覆盖的工作树只在可恢复且归属核验后归档，未知材料保留。

## Testing Decisions

- 保留已有公开 CLI、生产 HTTP/隔离 PostgreSQL、TypeScript、合成调度和打包测试接缝。
- 新增集成回归覆盖迁移新库、main059、standalone060、幂等和旧分叉拒绝，以及主链关键功能并存。
- Python 使用 NotAlone Conda 环境；测试关闭 dotenv，使用合成资料及随机 _test 库；不接管运行中的真实库。
- 相关最小验证后再跑完整相关后端、桌面类型/安全检查；仅保留一次最终 App 构建并用 Computer Use 操作真实界面。每批自有数据库、进程和临时产物收尾。
- Standards/Spec 独立审查及本地公开历史检查通过后报告实际提交与剩余边界。

## Out of Scope

远端推送、PR、发布、公证、修改系统权限、真实模型评测、真实业务库迁移、改写私人事实和自动发送。
