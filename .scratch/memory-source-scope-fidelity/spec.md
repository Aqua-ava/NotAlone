# 记忆主张、直接证据与语境的语义保真

## Problem Statement

用户要求继续修复记忆语义准确性，并使用同一批聊天复测，最后只验收确有歧义的原话与实际记忆。上一轮已保存结果中仍有建议变本人计划、第三方与收款主体迁移、历史与当前阶段混淆，以及正文子主张只在未引用语境里出现。原审计又混合了正文错误、主体字段错误与引用遗漏，必须分别测量。

## Solution

先冻结原候选、来源与评审基准，沿现有公开提取／来源核验接缝重现失败；逐变量测试直接证据与语境的区分，以及提取时的主体、状态与引用完整性。修改只针对已复现问题，保持语用和风险采纳门。用固定正负对照与同一已确认联系人代表性窗口复测，分别展示误放、误拒、漏提与结构失败；有争议的原话保留给用户判断。

## User Stories

1. 作为用户，我希望别人的建议不被记成我的既定计划。
2. 作为用户，我希望第三人、公司和用户／联系人的事件归属不被互换。
3. 作为用户，我希望历史经历、当前状态、未来计划和条件分别保留。
4. 作为用户，我希望正文中的每个独立主张都有实际引用，语境不会被偷当成新增证据。
5. 作为用户，我希望相连问答仍可用于解析人物、指代和省略，不因收紧来源而全部拒绝。
6. 作为用户，我希望共同经历、约定或双方明确一致的主张仍可使用 shared，不限于已发生的共同生活事件。
7. 作为用户，我希望正确的复合事实和已完整引用的限定仍被保留。
8. 作为用户，我希望复测不静默改写已认可的五条资料或既有水位。
9. 作为用户，我希望看到首次失败、修改后的真实输出及仍需判断的少量项目。

## Implementation Decisions

- 固定工程起点为 `4b04692`。一个完整修复 ticket；目标、测试边界和数据范围由用户本次“好的继续”及此前“原话→记忆→去向”的授权收敛，不重复询问普通实现权限。
- 保持现有 ExtractionFlow、LangChain 来源核验运行时、语用分流与 MemoryAdoption 接缝；优先改变模型输入的证据角色表达及必要提示原则。未通过真实正负对照的结构方案不进入默认路径。
- 在首个留出集揭盲前冻结“thinking＋先恢复原命题”候选组合，但其后对冻结自然产物的受控核验出现安全退步，因此撤去七行新提示；最终只保留同一已配置模型和目的地的已有 thinking 请求选项。提取、核验与既有裁决共享该记忆模型，回复模型的默认构造不变。原协议、提示、序列化和库版本不变。后续该留出集只称回归复核，不继续称未见数据，也不据其具体错误调提示。该开关在当前服务真实公开调用中核验兼容性；耗时明显增加，不能声称对所有兼容供应商都有效。
- 核验不得改写正文、增加引用、改变人物或提高采纳；核验只有降级和拒绝作用。每窗口仍至多一次有界核验，原预算、0.7 门槛、风险白名单、模型与供应商保持不变。
- 不按具体私聊句子或评测答案特判；不强制引用每一个来源 ID，不将所有复合句、转述或 sender 与 subject 不同的候选一概拒绝。
- 冻结新合成开发／留出场景；真实窗口仅来自上一轮同一已确认联系人，采用只读消息和撤回前结果快照。语用标签未保存的重建须明确声明，不冒充原始模型调用的精确重放。
- 用户已授权用同批聊天及现有模型服务复测：只发送选中窗口所需规范化文字与候选，保持既有目的地，每次写无正文出站台账。已知凭据消息及不必要的身份信息在请求边界排除；不扩大到其他联系人或上传整个历史。
- 实验输出、真实聊天、UUID、基准与验收对照仅存仓库外私有目录；首次输出与失败不覆盖，不保存模型内部思考。固定候选核验效果与自然提取效果分开，不把 Agent 标注说成人类金标或总体准确率。

## Testing Decisions

沿用用户已授权的公开模型 I/O、ExtractionFlow.run 和采纳去向 seam：合成边界回归验证输入来源角色、原来源隔离、结构失败和只降不升；真实模型固定候选对照验证语义效果，不能用 fake unsupported 自证准确。

- 先形成 red-capable 固定重放，记录首次真实错误；模型非确定性用冻结输入、首次输出及重复次数表达，不按结果补抽成功。
- 冻结 16 个新合成场景（4 开发、12 留出），正负候选配对；留出不用于改提示。既有合成用例作为回归，不重新称未见数据。
- 原 43 条问题重新区分正文、主体与引用支持；校准争议不放进硬语义失败分母。真实代表性窗口做相同输入与预算的前后对照，保留模型失败、成本和全部额外输出，单独统计覆盖。
- 相关单元测试、类型检查、完整隔离 `_test` 库回归、Standards／Spec 两轴评审与中文本地提交。私人数据和凭据不提交、不 push。

## Out of Scope

新供应商、依赖、核验持久化 schema、扩大自动采纳门、全历史生产重提取、未经评测的多维协议、新后台调度、同步权限、App UI 改版、外部聊天发送、部署和远端 Git 操作。复测默认不写业务记忆或水位；若需要落地纠错，只在本轮模型输出和来源复核完成后使用现有接口，保留原文、来源及动作对照，不改用户确认事实。

## Further Notes

ADR-026／027／033 的现行外壳和只降不升规则继续生效。其历史任务“只用合成模型实测”的范围限制不扩大成本轮用户明确授权的同批复测；本轮仍按现行隐私表中已有模型提取与来源核验数据流处理最小窗口，不新增外部连接。
