# 本地 HTTP 毫秒级退化的非阻塞验收决定

日期：2026-10-26。用户明确要求：“把这几个本地 HTTP 接口的毫秒级退化记为非阻塞项，更新验收标准，通知主会话继续剩余验收，其他硬门槛不变。”

## 生效范围

- 仅覆盖本轮迁移中 `contacts`、`sources`、`session-default` 三个既定本地 HTTP case 已观测到的毫秒级耗时退化；下表记录本次决定对应的测量范围。
- 这项已知退化记为 `non_blocking_by_user`，不再阻塞 Ticket 25 或作为 Ticket 26 的前置；不要求先优化到旧比值门槛或查明其完整根因，才能继续其他验收。
- 原 p50≤1.15 倍、p95≤1.25 倍及统计区间要求保留在[冻结协议](baseline/evaluation-protocol.md#性能费用与噪声)中。本决定是用户明确批准的窄范围修订，不改冻结协议字节、统计器、原始样本、历史失败或未定结论，也不将超线结果改记为 `passed`。
- 后续验收汇总同时列出原测量结论与 `non_blocking_by_user` 决定，排除该项的阻塞作用；既有报告中的 `failed`／`undetermined` 不因本次决定被覆盖。本决定不表示整体性能或迁移已通过。
- 其他接口、新增退化、明显卡顿、超时或随资料规模放大的问题不在本次豁免内；不设全局无限容忍范围，也不据此新增未经确认的数值门槛。

## 对应的已有测量

单位为毫秒；使用最近一次 480 请求诊断中未增加私有阶段计时的 A 旧版与 B 完整新版，每格 30 个计分样本。

| 本地 HTTP case | 旧版 p50 | 新版 p50 | 旧版 p95 | 新版 p95 |
| --- | ---: | ---: | ---: | ---: |
| `contacts` | 1.736187 | 3.863250 | 2.032573 | 5.011313 |
| `sources` | 1.193479 | 4.043937 | 1.587733 | 5.250110 |
| `session-default` | 2.252854 | 2.594749 | 2.803463 | 3.520194 |

本轮请求 480/480 成功；上述局部诊断不替代完整正式性能验收，也不证明用户操作端到端没有卡顿。原始数据、旧锚漂移、观察器限制和根因未知保持原样，见[原测量报告](http-host-boundary-diagnosis/run-v1/result-report.md)。

## 继续有效的要求与执行顺序

- 启动时间、整个后台进程树 RSS、模型端到端及最终持久结果的耗时要求、正式回复对照、真实开发 App／微信验收，仍按未豁免的既定范围执行。
- 联系人身份与 `owner_id + contact_id` 隔离、权限、来源、删除、取消、持久化、数据兼容、唯一执行／写入方、物理调用记账与 unknown 不盲重放等硬要求保持。
- 此前已明确的输出／费用豁免及记忆内容质量 `deferred_by_user` 保持各自原范围；本次既不撤销，也不扩大这些决定，详见[验收范围更新](acceptance-scope-update.md)。
- 主协调立即继续剩余必要回归、启动／内存测量、正式回复对照及实际 App／微信验收；已开始的有限性能诊断仅收尾、保留失败与证据、核对资源清理，不再为这三路已知退化扩大实验或优化。
- Ticket 25 仍为 `claimed / not approved`，Ticket 26 仍为 `open`；全部其他未豁免条件通过后按原顺序签收，不提前标完成。
- 日常桌面仍仅使用并优先复用 `npm run dev`；本决定不新增打包、运行打包版、外部发送、真实资料范围、无限模型调用、push 或 PR 授权。
