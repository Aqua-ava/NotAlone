# 前台 OCR 自动识别暂缓验收决定

日期：2026-10-26。已直接读取用户原话：“先这样吧，ocr后面在说，先跳过这个问题，告诉主任务”。

## 生效范围与状态

- 仅将当前已知未通过的前台 OCR 自动识别记为 `deferred_by_user`，暂不作为本阶段迁移、实际桌面收口或后续退役的前置条件；保留为后续待处理问题。
- 本次是用户批准的验收顺序调整，不改为 `passed`，不宣称自动匹配可用，不降低识别、联系人绑定或隐私规则，也不覆盖其他视觉能力的验收结论。
- 已有实测返回 `quality_unverified` 并要求手动选择，未宣称自动匹配成功；仅沿用[原实测记录](actual-priority-registration-fix/root-r7-foreground-quality-gate.json)，不新增原因推断或改写历史证据。
- 不再为这个已知问题扩展 OCR 专项排查、修复、采样或重复实测；必要的非 OCR 功能验收继续执行，后续 OCR 工作另行安排。

## 可继续使用的手动路径

- 用户可沿用已明确选择且资格有效的已有联系人进行本阶段验收；每次请求仍绑定本次确认的 `owner_id + contact_id`、助手会话、输入及有效版本，不从展示名猜测身份。
- 手动输入确认不冒充微信会话绑定，不新增微信读取、同步或发送权限；失败或低置信度时仍不能自动确认联系人，跨联系人资料与任务继续隔离。
- 手动选择路径的功能、来源、授权、持久化、删除／取消及联系人切换仍需按原合同验证；前台识别暂缓不能替代这些证据。
- 继续遵循[隐私与删除规则](../../architecture/current/privacy-deletion.md)及[顶部名称 OCR 边界](../../architecture/adr/052-header-ocr-foreground-locator.md)：原始视觉帧默认仅在端侧内存处理，不持久化或上传，不对聊天正文或其他联系人列表做 OCR，不读取其他 App。
- 公开文档不记录私人联系人名称、识别原文或视觉帧；本次只记录用户决定和已有状态。

## 继续有效的验收与推进顺序

- 主协调继续最终必要回归、启动时间／整个后台进程树 RSS、正式回复对照和其他实际开发 App／微信验收，不再等待本项自动识别通过。
- 联系人身份隔离、权限、来源、数据兼容、删除／取消、持久化、唯一执行／写入方、物理调用记账、unknown 不盲重放，以及模型端到端等其他未豁免硬要求保持。
- [三路本地 HTTP 已知毫秒级退化](local-http-latency-scope-update.md)仍为 `non_blocking_by_user`；记忆内容质量、输出／费用等此前决定保持各自原范围，见[验收范围更新](acceptance-scope-update.md)。
- 冻结基线、原阈值、旧样本和失败／未定证据不改写；验收汇总分别列出原观察结论与本次 `deferred_by_user` 决定，不将暂缓登记为成功。
- Ticket 25 仍为 `claimed / not approved`，Ticket 26 仍为 `open`；待其他未豁免条件通过后依序签收，本决定不直接完成任何任务。
- 日常桌面仍仅使用并优先复用 `npm run dev`；本决定不新增打包、运行打包版、外部发送、资料范围、无限调用、push 或 PR 授权。
