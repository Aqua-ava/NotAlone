# JSON 正文保真修复

日期：2026-10-25。来源是针对 `030d3e1c` 的独立 Standards／Spec 审查，两轴均复现同一正文回归；不是费用优化。

## 问题与行为

原实现递归解析任意合法 JSON 字符串，把订单号等业务字段当作系统身份，并把超安全整数转换成另一数值。实际供应商输入因此与用户原文、保存来源不一致。

修复后，草稿、用户要求、补充聊天、来源及普通讨论正文逐字保留。只有系统拥有的讨论 DTO 与具名序列化关联字段继续进行有界投影；内部来源、会话、Skill 和版本标识仍使用请求局部别名，提交时恢复真实身份。

原单测将自由正文误当内部序列化 DTO，现改用明确的系统 envelope；保留递归上限、未知引用、别名往返及内部身份不出站断言，新增实际供应商请求的正文、空白和大整数保真回归。
