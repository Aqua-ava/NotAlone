# 精简 DSH 与 TypeScript 后端迁移

Triage: ready-for-agent
State: open

> 2026-10-25 执行范围更新：用户明确要求[费用暂豁免并调整记忆真实验收对象](acceptance-scope-update.md)。仅覆盖该记录列出的条款；固定材料、历史测量及其余功能、质量、权限和性能要求保留。

> 用户于 2026-10-23 确认完整方案；设计已采纳，尚未实现。用户已认可任务粒度、依赖及下述验收入口；[26份任务](planning.md)已发布，均为 ready-for-agent / open，尚未开始。本规格不授权直接切换现有业务库或打包发布。

## 问题与目标

现有后端使用 Python、LangChain／LangGraph 及 Deep Agents 的部分能力，回复、提取、整理和 Skill 学习各有模型调用适配。用户希望统一 AI 执行底座，按需增加经过验证的插件，减少长期维护；保留全部现有用户功能、身份与资料，不以重写为由减少功能。

## 方案

采用精简 DSH，以 TypeScript 逐步承接全部 Python 后端职责。Electron 界面独立；一个官方 profile 启动的后台通过薄插件装配普通 TS 业务模块与 DSH。模型及工具通过公开接口协作，确定性业务流程不交给 Agent 自主决策。沿用原 PostgreSQL 和资料位置，优先保持 HTTP／事件等界面对外行为；实际接口等价性通过基线检查，不宣称当前已兼容。

先固定基线并验证新运行方式，再迁移回复、记忆与 Skill、其余后端，最后删除旧实现。新旧共存只用于迁移，按功能明确唯一执行和写入责任方。

## Implementation Decisions

### 运行与模块

- 后台经官方 profile 启动；业务代码保持普通 TS 模块，薄插件负责装配和运行事件。共享故障域需要监督、健康状态、明确退出与资源清理，不重新引入常驻 Python／DSH 双运行层作为最终设计。
- 优先保持既有业务接口及运行时接口的输入、输出和错误语义；框架对象不泄漏为领域对象。单次语义调用与有界 Agent 循环共享模型配置、预算、记账和错误规则，不强迫所有调用成为循环。
- 精确版本、插件 package、配置和依赖闭包由首项验证固定。官方 minimal 中的默认压缩、Shell、持久化、日志上报等不自动继承；无必要的能力不向模型暴露。
- 用户明确要求先看 DSH 再改：涉及 DSH 的实施先阅读锁定版本官方文档、相关源码及示例，记录版本／commit、来源及适配理由；禁止凭印象猜接口、绕过官方机制或擅改核心。无直接接口的业务票也须核验交互边界并说明依据；无查证记录不得签收。
- 不运行时安装最新插件；自有扩展使用公开接口。无法实现功能等价或必须修改 DSH 核心时记录具体冲突并返回决策，不静默放宽。
- 产品不需要的通用编码、任意文件执行、自治任务和子 Agent 不因迁移新增。必要的内部文件服务不等于赋予模型通用文件权限。

### 身份、资料与状态

- PostgreSQL 继续为权威业务库，联系人范围使用 owner_id + contact_id；昵称、目录、DSH session ID 均不能替代业务身份。
- 保留已执行迁移、原身份、来源和版本，不改写历史 SQL。必要变更采用兼容方式，失败或版本不明时停写；不因迁移创建替代空库、搬库或强制备份。
- 业务讨论负责用户可见连续性。每次 DSH 执行只见本次核验后的上下文；临时会话与作用域工具必须在结束、取消和删除后清理。禁止额外长期 JSONL 会话副本、隐式恢复和完整会话上报。
- 队列、租约、幂等、提取水位和恢复资格仍为业务状态。后台崩溃不授权盲目重放模型请求、重新发布资料或复活已删内容。
- Skill 内容仍按既有目录与业务状态规则管理；“开发阶段安装 DSH 插件”不替代用户导入、创建、审核和管理回复 Skill 的功能。
- 本地语义向量、分词和检索结果需要跨语言兼容验证；保留本地模型准备和不外发 embedding 的边界，不用云端服务替代现有本地路径。

### 并发、预算与切换

- 2026-10-24 用户明确废除 ECNU／ecnu-max，不再要求兼容；停止仅为 ECNU 的协议适配、插件依赖和验收工作。遇到旧配置时明确提示重新配置，不自动切换供应商或改写原配置；资料与历史调用记录不删除。其余功能保留要求及下列预算、恢复、验收条件不变，见[范围记录](provider-scope-update.md)。
- 每次物理模型请求都受范围、版本、预算、时限与取消检查；保留前台优先、后台有界并发以及迟到结果丢弃与实际调用记账。官方 retry/token 插件不能自动视为等价。
- TS 回复先于 Python 后台迁移时，也必须共享有效的模型调用仲裁和退出控制；单任务不双领取不能替代跨实现的前台优先与总并发约束。切换前验证仲裁或既有暂停／恢复机制，不能以两套进程各自限流冒充全局合同。
- 候选、提取、核验、裁决与学习各自保持结构化输出、引用和业务校验；解析失败不作为成功，不依赖自然语言提示词保证权限。
- 过渡路由以业务功能为单位明确移交责任；切换前停止接收、收尾或中断在途任务并核验租约。新旧不能同时处理同一任务，不做请求级自动回退。
- 回退前验证当前数据对旧实现的兼容性。不能安全回退则保留资料并停止该功能，不倒退数据库或恢复过时副本。
- 已退役功能不因机械移植复活；尚未完成的既有首用、删除或同步验收也不能算作既有成功基线。盘点并关联原任务，明确单一负责人，不重复建设。
- 首用同时覆盖已有 owner 与首次初始化，模型配置及本地检索模型的显式准备要有具名承接任务；微信工具准备继续关联原首用任务，不能在移除 Python 后遗留唯一旧入口。首条检索回复切换前即验证 TS 的本地 embedding、分词和排序兼容，不推迟到记忆写入迁移。

## Testing Decisions

### 验收入口建议

优先从既有桌面控制器使用的 HTTP／事件业务入口验证请求到数据库及可见结果；回复、提取和任务接口用于聚焦验证。只在后台启动、退出和取消等必须跨进程的行为上增加宿主测试。避免把 DSH 插件数量或私有内部调用顺序当作业务成功标准。该具体入口及任务拆分已获用户确认。

### 基线与验收矩阵

| 范围 | 通过条件与证据 |
| --- | --- |
| 基线盘点 | 每个当前功能映射入口、资料、已有测试和缺口，区分已实现、已采纳未实现、已退役；迁移前固定代码与配置快照 |
| DSH 运行方式 | 固定版本组合完成启动、工具、单次调用、结构化结果、取消、退出；捕获合成网络请求和临时文件验证无额外会话上报或长期落盘 |
| 功能与隔离 | 合成多联系人经公开业务入口验证正常、空结果、错误、越权、引用失效及删除；每项确定性合同通过，不能用模型质量抵消权限失败 |
| 数据兼容 | 独立合成 _test 库验证原结构、迁移中断、重放拒绝、唯一写入方、幂等与显式回退；原身份、资料、用户修改和删除决定保留 |
| 记忆与检索 | 同来源和输入版本核验采纳、纠错、演进、L2／L3、向量与词法检索，关注跨语言数值、时间、排序和标识符差异 |
| 生命周期 | 验证取消、超时、前台优先、后台并发、进程崩溃、租约恢复、模型错误和晚结果；真实物理调用仍准确记账 |
| 模型质量 | 固定模型、参数、材料及评审标准，比较依据正确性、提取核验准确性、回复可用性；文字不逐字比较 |
| 性能费用 | 记录启动、空闲内存、请求延迟、物理调用数和 tokens；每项公布基线、重复次数、分布及差异原因，不以单次偶然结果定输赢 |
| 桌面与微信 | 复用 npm run dev 实例，分别记录页面自动化、实际 App、真实渠道及模型验证；不发送未经明确指定对象与内容的外部消息 |
| 退役 | 清点生产入口、Worker、诊断、脚本和锁文件，不再启动或导入 Python 后端／旧框架；评测脚本迁移或明确隔离退役，不掩盖产品运行依赖 |

基线阶段必须在迁移结果产生前固定质量判定标准、样本与性能费用退化阈值，避免事后放宽。确定性合同必须全部通过；不能从当前对话推导未测量的数值承诺。未通过或无法解释的明显退化阻止对应切换；若修复需改变用户已确认范围，返回决策。

沿用现有回复有界循环、输入预算、场景与历史工具、来源核验、任务幂等及公开 HTTP／PostgreSQL 集成测试的行为合同；替换 LangChain fake model 等框架替身。测试从单用例到相关模块，按工程规则再做有界全量，不使用私人聊天夹具。

## Out of Scope

- 改产品定位、删现有功能、重新设计界面、换数据库、云端化或多设备同步。
- 自动发送、扩大微信读取授权、通用 Shell 或任意文件工具、用户插件市场、自动升级插件。
- 自动过程摘要、把 DSH 状态作为关系记忆、额外会话日志上报或长期副本。
- 为缩安装体积维护专用发行包、长期维护 DSH 核心分叉、同时长期维护 Python 和 TS。
- 本轮文档直接安装依赖、运行真实资料迁移、打包发布、push 或创建远端 PR。
