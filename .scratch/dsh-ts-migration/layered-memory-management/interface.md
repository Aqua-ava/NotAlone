# 分层记忆管理 TS 接线

- 范围：原联系人／本人 `layered-memory` 的读取与全部 11 个管理动作；不复制腾讯算法或模型调用层。
- 入口：`backend-ts/src/layered-memory-management.ts` 的 `createLayeredMemoryManagement(options)`。
- `matches(method,url)` 在旧 handler 前判定；`handle(method,url,body,signal)` 返回 `{status,body}` 或 `undefined`。
- `ownerId` 来自宿主配置；公开正文不能自证 owner/contact 或注入内部 verified scope。
- `transaction` 复用原 HostStorage 事务；模块保留事务内业务错误，避免被折叠成数据库不可用。
- `wake(scope,taskId)`、`cancel(scope,taskId)` 在提交后通知唯一原 Worker；scope 为 `{owner_id,contact_id}`。
- `modelWorkAvailable()` 只限制开启、刷新和继续；读取、停用、删除、纠错与撤回不依赖模型配置。
- `qualityInput(client,scope,versions)` 在原范围锁与同一事务内调用 `OrganizationQualityStore.insertInputInTransaction`。
- `versions` 为原 `memory_versions: [{memory_id,revision}]`；质量输入由 quality 模块唯一持久，不在管理模块重复保存。
- `/api/layered-memory/*` 的输入审核、运行、报告及评测由独立 `organization-quality-*` 实现与接线。
- 管理任务仍写原 `background_task`、`background_task_step`、`layered_memory_job`；没有第二套任务库。
- 实际 contract 必须含 `document-tools-v1`、`profile-tools-v1`，并绑定实际模型、预算与算法身份。
- 推荐 contract 后缀使用同一质量服务的 `contractId`；预算传同一 L2 六字段合同。
- 新 `layered-memory-management-source-policy.ts` 过滤实际待修原叶、总结纠错版本链及消息身份。
- `runMaintenance(signal)` 返回 `{enqueued,nextDueAt,nextDelayMs}`，提交后自行唤醒原 Worker；宿主不重复唤醒。
- 调度监听原 `layered_memory_changed`，按到期时间唤醒；该模块不创建 Timer 或 PG 监听连接。
- 原 `next_boundary_at` 持久跟踪生效／过期边界；暂停、失败和停用不自动恢复。
- `layered-memory-management-target.ts` 冻结原目标，按合法成功批次排除已覆盖项，旧主题带回完整实际输入。
- 根已批准两个既有 L2/L3 service 窄改调用过滤策略；四个腾讯算法及模型层未改动。
- 已有合成证据：公开开启到原 TaskStore 领取、实际 L2/L3 生成与独立核验、暂停晚写拒绝。
- 已有合成证据：有限继续幂等、停用保留历史、删除派生正文、本人隔离、未知结果不重放、空范围零模型完成。
- 无真实 App、微信、私人配置、真实模型或预算操作；根负责统一集成、独立验收与 Git 提交。
