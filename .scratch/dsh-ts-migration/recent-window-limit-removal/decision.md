# 取消近期聊天独立 token 上限

2026-10-24，用户明确要求解除近期聊天独立 8k 限制，并同步修改文档。该决定取代旧 `core-flows.md` 的近期独立 8000 token 要求和后续精确分词修复提案。

- 近期聊天仍最多 50 条；显式待回复消息占其中一条，其余按最近顺序选取完整消息。
- 准备、生成、冻结恢复及继续回复均不再按近期独立 token 阈值裁剪或拒绝；固定身份、来源有效性、目标正文及删除资格仍须复验。
- 完整模型请求仍受模型上下文容量、输出预留、安全余量和调用额度控制；整请求超限必须在外发前拒绝。此次不允许无限历史或放宽总预算。
- 移除仅为近期 8k 引入的回复分词资产和准备入口，不删除仍服务 BGE 检索的 HF tokenizer 依赖，不删除本机既有缓存。
- 旧实验、错误估算及失败结果保留历史事实，只标记本决定已取代其要求。消息覆盖对照不等同真实模型语义、性能或整票验收通过。

实现已移除近期独立 token／字节计量和专用分词资产前提，准备与冻结复验仅保留原50条、来源与身份守卫。原HF依赖继续服务检索，本机缓存未删除。

主协调在实际合并树验证：窗口4/4、相关准备／冻结／来源回归35/35、全项目严格类型检查通过；完整请求超限零模型HTTP、零调用回执。官方模型profile也由旧资产依赖错误转为1/1通过，独立后端公开链1/1通过；这两项使用本机模拟服务，且含尚未另行提交的宿主装配，不代表本次窗口提交已完成宿主或真实模型验收。当前默认 Python 所有权及迁移质量门保持。

独立干净基线复验及可重跑命令见[验证记录](validation.md)。
