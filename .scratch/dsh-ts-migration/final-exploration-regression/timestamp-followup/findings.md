# 探索根时间尾零回归

原全量的失败来自测试格式假设，未发现生产时间、存储值或指纹错误，生产补丁范围为无。PostgreSQL `::text` 会省略小数尾零，而 Python `datetime.isoformat()` 对非零微秒输出六位；仅替换空格和 `+08` 无法把 `.78469+08` 转为 `.784690+08:00`。

先通过真实隔离 PostgreSQL、正式 `PostgresExplorationStore.begin/read` 固定根时间为 784690 微秒，原比较稳定 RED，耗时不足一秒。修复只在 `exploration-store.test.mjs`：以独立 Python 标准库将原始数据库文本转为原 Python 格式，保留精确字符串比较；另以 PostgreSQL `root_created_at=$2::timestamptz` 验证存储值与任务值相等。没有使用 JS Date、生产 `pythonISO` 或毫秒截断作为测试预期。

新增六个独立夹具固定覆盖 784690、0、1、123456、10、100000 微秒及 `+08:00`、`+00:00`、`+05:45`、`-05:00` 偏移。每个用例都校验 Python 格式、数据库同一时刻、数据库六位微秒、任务末尾的完整精度与偏移，以及原快照不变。零微秒按 Python 原格式不带小数，不误写成额外的六位小数要求。偏移是测试连接时区的呈现，未将其当作 PostgreSQL 保存的原始偏移。

原“记忆最多两条”用例保留完整 Python capture 深比较、来源依赖和指纹验证，并固定五条近期消息为尾零、零微秒、1 微秒、六位非零、单个非零小数位；该用例单独通过。其他原存储合同断言均保留。

探针中曾在同一冻结快照上切换连接时区，触发 `exploration_stale`：快照指纹的时间文本依赖捕获时的连接时区。最终测试在各自独立连接时区内先捕获再校验，不修改或跳过生产来源复验，也不宣称跨时区旧快照兼容；该失败探针仍以独立 raw/public SHA 留档，不列为通过结果。
