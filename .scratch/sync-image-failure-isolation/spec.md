# 修复图片失败连带中断微信同步

状态：方案待实施。本文用于后续实现与验收，不代表修复已上线。

## 用户问题和目标

同步页长期只有少数联系人显示历史读完，大量联系人显示“聊天来源需要核验”。后台反复恢复和建立读取任务，用户无法判断聊天是否已经保存、现在是否仍在同步。

修复后的行为：一张图片无法获取时，该消息保留图片占位和失败状态，其他联系人的文字同步继续；真正的账号、聊天来源、授权或协议异常仍按原规则停止读取。已保存的历史进度与当前可读状态分别展示。

## 已确认的原因

1. `NarrowWechatClient` 收到原生错误后，除缺图片密钥和已登记的引用局部错误外，会关闭原生进程。图片 `image-open` 的普通失败也走这条路径。依据：`backend-ts/src/history/wechat/native-client.ts:1273`、`:1298`。
2. 历史读取与图片提取共用原生进程。进程退出会使其他停放会话的守卫失效，`readCoverage` 将这些会话投影为 `history_source_continuity_unverified`，协调器随后重新核验和创建任务。依据：`backend-ts/src/history/wechat/shared-client.ts:29`、`backend-ts/src/history/sqlite/wechat-channel.ts:52`、`backend-ts/src/history/sqlite/service.ts:119`、`backend-ts/src/history/sqlite/read.ts:82`、`backend-ts/src/history/sqlite/continuity.ts:196`。
3. 已用生产 TS 读取链路和合成原生进程复现：两个联系人的历史均为 `complete`，注入一次图片关联失败后，两者同时变成 `incomplete / history_source_continuity_unverified`。原生进程以 `history_image_association_unverified` 停止。
4. 不能直接把这个错误码放入白名单：Go 的 `openImage` 目前会将 `ensureMessageGuard()` 的真实来源错误改写成 `history_image_association_unverified`；`openImageMessage` 也将快照检查失败和单图关联缺失合并返回。依据：`desktop/wechat-history/cmd/notalone_image.go:924`、`:1043`。

现场图片关联错误、读取进程重建与任务增长符合上述故障链路；尚未逐张确定图片关联失败的原始原因。隔离失败不能降低图片关联要求，也不能承诺每张图片最终都能取得。

## Implementation Decisions

### 一 先让错误表达真实影响范围

改动集中在 Go 图片读取实现及其测试。

- `ensureMessageGuard()`、账号与会话变化、快照来源或文件实例失效等错误保留原有准确错误码，避免包装成单图关联失败。
- 拆开 `openImageMessage` 中“目标不匹配”“来源代次变化”“快照检查失败”“单条消息或资源匹配不到”等组合判断。只有能确认属于本次图片的缺失、歧义或不可用才返回单图失败。
- 普通打开失败返回前，释放本次新建的临时快照和图片资源守卫，不留下资源句柄，不撤销仍有效的账号和聊天来源守卫。
- 文件缺失、关联不唯一、缺密钥、无法解码或内容核验失败仍不得保存为有效图片。不改变 ADR-170、ADR-171 的标准图、高清图和缩略图处理规则。

### 二 在原生客户端隔离已查证的单图失败

复用 `PendingResponse.recoverableErrors` 和现有引用读取的处理方式，将错误处理留在原生客户端这个 Module 内。图片调用方只接收本次操作结果，不自行恢复原生进程或修改守卫。

- 为 `image-open` 定义封闭的可恢复错误集合，逐个核对 Go 返回点与资源清理。至少覆盖已复现的图片关联失败；本地缺文件、无可用副本、大小超限、格式或解码能力不支持等，只在证明局部性后加入。
- 只有当前操作明确登记、原生返回的合法错误回执才可局部失败：结束当前请求，保留进程、选择范围和其他联系人的守卫。
- 来源变化、图片来源变化、账号或会话变化、超时、取消、读写资源状态不明、未知错误、非法响应和响应校验失败继续终止读取。`image-read`、`image-close` 不因错误前缀相同自动获得可恢复资格。
- 保持缺图片密钥的一次性补钥语义及引用读取既有恢复规则；禁止按 `history_image_*` 前缀统一放行。
- 可恢复语义绑定到完成上述 Go 审查的新制品哈希支持档。旧制品不能因 TS 升级而自动获得这个资格，不新增面向用户的宽松开关。
- 原生制品按既有固定版本构建、完整性核验和已审查配对升级流程接线。若改动超出既有来源身份兼容范围，继续执行正式来源核验，不扩大身份别名规则绕过检查。

### 三 让失败按原规则退避并恢复正常同步

复用 `media_extraction_attempt`、图片占位和持久退避，不增加第二套重试计时器。

- 单图失败只更新该图片尝试；普通图片错误不唤醒全部联系人的首次历史读取。
- 验证现有 1 分钟、5 分钟、30 分钟、6 小时、最多 24 小时退避在重复唤醒及重启后有效。若已有行为满足要求，不修改调度算法。
- 部署开发修复后，旧的临时失守卫状态经现有 `normalUseRevalidationCandidate` 和来源元数据重验恢复。继续核对账号、会话、来源代次、表实例、授权、删除和排除记录。
- 原生进程真实退出后不得沿用旧的内存游标；仅接续当前核验通过的持久检查点，缺少证明时允许必要的重新扫描。
- 不直接改写业务数据库，不删除 `history_continuity_fence`，不把旧租约改成有效。独立的真实来源阻断由用户通过正式入口逐一核对，不能批量恢复授权。

### 四 把历史进度和当前状态分开显示

`readCoverage.phase` 继续表达当前业务资格，不为了进度条好看而返回可用状态。

- 为状态摘要增加只读字段 `saved_history_complete`，桌面映射为 `savedHistoryComplete`。只按当前绑定、授权和数据代次内的最新历史目标及完整遍历证据计算，不查询跨绑定的“曾经完成”最大值。
- 该字段仅用于展示保存的读取进度；不参与正文读取、检索、记忆、回复出站或守卫判断。旧后台缺字段时显示进度待确认，不推断成功。
- 进度文案改为“已保存本机历史：X / Y 位联系人”；另行显示“正在同步新消息”“正在恢复连接”或“部分联系人需要核对来源”。真实来源失效时保留相应警示。
- 单图的失败原因放在对应图片及现有处理状态中。没有联系人同步故障时，不把图片重试累计次数当作联系人故障人数，也不把运行期失败次数冒充待处理图片数量。
- 状态查询只读、不触发微信读取；复用批量覆盖查询和当前目标索引，不在前台为每位联系人遍历全部历史任务。

## Testing Decisions

先把已复现链路固化为失败测试，再实现；无需模型调用或真实聊天夹具。

1. **Go 错误和清理**：普通单图关联缺失保持原会话可用；来源守卫失效返回真实来源错误；快照实例变化、资源文件替换不能降级为单图缺失；失败无临时守卫和句柄泄漏。
2. **正式原生客户端**：用合成子进程返回各个允许的 `image-open` 错误，确认本次拒绝后同一进程仍能处理后续请求；在其他操作、旧制品、非法回执和来源错误下确认仍会停止。覆盖补钥与引用原有行为。
3. **共享读取集成**：两个联系人先读完历史，再让一个图片请求失败；进程与其他守卫保持有效，文字增量继续，图片保持占位。不得只测试一个假的 `HistoryChannel`，必须经过真实 `SharedWechatClient`、`WechatHistoryChannel`、`SqliteHistoryService` 和 SQLite。
4. **恢复和退避**：重复唤醒不形成紧密重试；重启保留到期时间；真实退出仅走正式重验，真实围栏、停读、删除与排除决定均不能自动恢复。
5. **同一负载对照**：分别用 10、100 位合成联系人和相同图片失败序列，对照成功或正常关闭图片资源的控制组。记录原生进程代次、守卫失效人数、新历史目标数、历史正文页读取数和重试次数；普通图片失败不得额外触发跨联系人的历史重建。必要的正常切换和重启恢复单独计数。
6. **进度展示**：覆盖历史完成但连接待重验、真实来源失效、历史部分完成、清空或换绑、旧后台缺字段；展示字段不得使派生资料重新可用。
7. **实际桌面**：先查并复用 `pnpm run dev` 实例；在隔离合成资料与替身模型下，通过 Computer Use 操作 App，验证进度、问题分类、图片占位、恢复和同步开关。需要微信现场核验时只检查授权范围所需的状态，不发送消息。开发验收不制作或运行打包版。

## 实施顺序和完成条件

按以下顺序推进，每一步先跑最小相关检查；出现新的事实再扩大范围。

1. 固化共享读取失败测试，完成 Go 错误分类与客户端隔离，保持来源保护测试通过。
2. 核对并修复实际暴露的退避或恢复遗漏，完成同一负载下的任务增长对照。
3. 接入只读进度字段与界面文案，完成正式链路和实际开发 App 验收。

完成时必须同时满足：普通图片失败不关闭共享读取器、不使其他联系人守卫失效、不额外造成全量重读；来源真实变化仍停止；失败图片不保存错误内容；旧状态经正式核验恢复；界面能区分已保存历史和当前同步状态。

## 数据与范围

复用现有资料、失败尝试、检查点、授权和来源保护，默认无需业务数据库迁移。不清理私人资料、不批量重建联系人、不扩大微信范围、不调用外部模型、不新增发送能力。本机真实资料的迁移、来源重新认证和授权调整按已有确认流程执行。

本任务解决单图失败的影响扩散与错误进度展示；个别图片缺失或无法唯一关联继续保留准确失败状态。DSH profile、Agent 和 Tool 编排、图片择图策略、发布包和远端操作不属于本方案。
