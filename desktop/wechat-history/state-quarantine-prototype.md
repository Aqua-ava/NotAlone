# 消息状态隔离原型（未集成）

本分支只使用合成数据；不得凭此支持档读取真实聊天。状态和跨进程来源连续性尚未认证，原型不能合入正式路径。

已探索：原生页明确区分已认证与未认证状态，未认证状态不读取正文；原生会话内的消息文件守卫跨快照保持，在合成测试中可检测快照间文件移走后放回；隔离已有来源及依赖，并在页接收失败、关闭读取和重开后保留隔离；历史和增量覆盖不把未解决的隔离标成完整。测试仅证明所构造的合成情况。

仍需完成：

- 应用目前每批结束会关闭原生会话，需延长应用端持有期；守卫意外断开、进程退出或重启后，在证明连续前持续停读。文件标识、表结构哈希和单次 FSEvents 回放均不能单独证明来源未替换。
- 微信真实状态值、撤回等语义和固定来源映射仍未认证；不得启用 `supported`、用不透明状态策略读取正文或复用旧版原生制品。
- 将新协议用于所有受影响的渠道夹具并完成必要检查；确认存储迁移和 UI 对“暂时不可用”状态的表达。
- 在可证明更新的同来源状态后设计恢复资格，旧记忆、候选和运行副本不得静默复活；当前隔离没有自动恢复入口。
- 隔离来源已批量计算依赖闭包；需继续核验跨联系人依赖、在途请求、异常退出窗口和删除交错。
- 原生页返回至独立隔离事务提交之间仍可能发生进程崩溃；要结合持久守卫、运行恢复和测试封闭该窗口。

仅当守卫、身份和状态能力均有充分真实证据，才可在用户既有授权范围内导入单个会话的文字。
