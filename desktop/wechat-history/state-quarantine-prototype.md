# 消息状态和来源守卫原型（未集成）

普通历史的真实状态及跨次来源身份仍未认证。2026-10-30 用户另行明确允许指定私聊的未知文字仅本机隔离保存、显示未核验、支持删除并禁止检索/记忆/生成；隔离快照不授予普通历史资格。

当前原型在应用运行期间为单个联系人跨批次保留原生守卫；文件实例变化、子进程退出或关闭读取后持久停读。持久记录在读取前建立，数据库重开后的运行代次不能冒充旧守卫。失证会使覆盖变为不完整，撤下来源详情，并沿依赖关系阻止旧回复及运行副本使用该来源。独立原生事件队列用于空闲通知，避免消耗读前核验的事件。

用户再次发送两条文字并撤回其中一条后，只读元数据观察到该条本地及服务器编号不变、类型从 `1` 变为 `10000`。原型对同编号已保存文字出现该类型变化时先隔离旧文字，即使后续页失败也保留保护；这不把所有系统消息认作撤回，也不认证此前未观察的历史状态。

合成测试覆盖守卫跨批次复用、停读和删除、子进程异常退出、数据库重开、失证写入失败、跨联系人依赖和原生空闲事件；守卫意外退出时立即中断在途读取，不等待失证写入。桌面开发版在临时合成数据库中显示“聊天来源已无法确认连续，正文读取保持关闭”。这些证据不等于真实渠道认证。

- 明确重新同步历史的独立入口尚未接入持久守卫；当前对具备守卫的渠道在正文读取前保守停下。
- 可信新观察后的消息恢复、旧派生版本不复活、在途请求和异常退出窗口仍需完成验证。
- 已用锁定源码和当前原型离线重建开发 CLI，构建脚本核对输入摘要和开发签名；CLI SHA-256 为 `c06f748ee333a8ae27c50c67c4c1df0356f88856bf8feeb3130c447f2e07c850`，manifest 标记 `realWechatVerified=false`。此前开发制品不代表当前源码；新制品也不代表真实支持能力。

## 2026-10-30 独立隔离快照

- 新增独立 `quarantine-target` / `quarantine-page` 与 `selected-quarantine-history-v1` 同意；仅已解析的单一私聊、已核验结构/声明主键及同进程守卫可使用。所有结果仍为 `stateAssurance=unverified`，普通 target/page 保持既有门禁。
- 独立隔离协议允许取文字；非文字载荷不读取。客户端用独立目标和带 `kind=quarantine` 的页封装，拒绝伪造 verified 状态，不将其送入普通历史服务。
- 新增进程身份核验以可执行路径和微秒启动时间绑定PID；两套独立kqueue队列监听退出/exec，快照结束后仍保留守卫。退出、PID身份不符或监控失败沿现有停读链处理；不证明原位恢复或跨重启映射。
- 正式客户端在获准对象上已验证账号、唯一目标、8分片/2目标表及隔离快照就绪；该预检没有请求隔离页或读取正文。实际保存与查看/删除结果另行记录，不能据此声称已导入。

- 原生新制品fresh source相关race测试154通过、1既有跳过；来源进程退出、两次快照间退出、错误路径/旧启动身份及隔离协议正反例均覆盖。开发制品继续标 `realWechatVerified=false`。
