# 双窗口交互原型

> 阶段：prototype，待用户选择布局。只演示合成会话和内存状态，所有操作均为模拟。

## 要回答的问题

在独立 `/prototype/notalone-windows/` 路由比较三套结构不同的浮窗：

- A：草稿优先，先写意思，再比较完整候选。
- B：消息优先，先理解当前对话，再填写方向或草稿。
- C：候选优先，使用紧凑列表挑选，草稿收拢在底部。

管理窗口提供联系人、历史导入、关系记忆、后台同步和配置的模拟操作。
既有产品前端为空，没有可嵌入的页面，因此使用独立原型页面；旁边展示合成微信会话，
用于观察浮窗在聊天环境中的密度和位置，而非孤立展示卡片。

## 启动

在本工作树根目录执行一条命令，无第三方依赖：

```bash
node desktop/prototype/start.mjs
```

直接预览：[A · 草稿优先](http://127.0.0.1:4176/prototype/notalone-windows/?variant=A)、
[B · 消息优先](http://127.0.0.1:4176/prototype/notalone-windows/?variant=B)、
[C · 候选优先](http://127.0.0.1:4176/prototype/notalone-windows/?variant=C)。
端口占用时可设置 `NOTALONE_PROTOTYPE_PORT`。底部箭头或键盘左右箭头切换布局，
URL 的 `variant=A/B/C` 可单独分享；输入框获得焦点时不拦截方向键。
服务拒绝以 `NODE_ENV=production` 启动；切换器只在原型路由显示。

## 体验路径

1. 编辑草稿、选择一次性的语气要求、模拟生成、修改候选和展开依据。
2. 切换“帮我回复”，明确输入表达方向后再模拟生成。
3. 点击“复制并收起”，在合成微信窗口点击“模拟粘贴”，再重新呼出浮窗。
4. 切换合成微信会话，体验已有绑定自动定位和未绑定会话的手动确认。
5. 模拟新消息，确认已有草稿与候选不会被替换，用户主动更新上下文。
6. 在管理窗口模拟配置、单联系人导入、记忆修正／删除、绑定选择和同步开关。
7. 关闭管理窗口后后台保持；点击模拟退出后停读；重新开启仅恢复已确认范围。

## 已确认的设计边界

用户确认后续使用 Electron + React，首版先 Mac 微信。日常入口是快捷键呼出的
可拖动／置顶小浮窗；关闭只隐藏。同一联系人保留本次草稿与候选，联系人变化时清空。
已有且唯一的已确认绑定允许自动定位；不确定时要求选择。

首版草稿由用户输入或粘贴；改写保留原意和立场，不新增事实、承诺和情绪。
关系背景默认关闭，语气要求只影响本次生成。两到三个候选可编辑，依据默认折叠；
提供复制及复制并收起。未提交草稿不跨运行保存。管理窗口关闭只隐藏，明确退出应用
停止后台读取；首次设置由管理窗口承载。原型中的这些行为只用于交互讨论。

## 数据与能力边界

默认场景演示“已有确认绑定”；“首次确认”场景默认不选任何联系人。所有名称、消息、
来源、记忆、任务和模型结果均为合成样例。默认场景有三条预置候选；自定义输入的
“生成”只演示原文、分句和紧凑排版，不代表模型改写质量。草稿和操作仅留在浏览器内存中，不使用
localStorage，不发送网络请求，不读取真实剪贴板，也不写入剪贴板。

没有 Electron 宿主、真实快捷键、实际置顶、输入框读取、后端、数据库、模型、微信
或系统权限接线；页面内的唤起、拖动、复制、导入、配置、删除和同步都是模拟。
原型不能直接作为正式前端发布；选定布局后再形成规格、确认测试接缝与任务拆分。

## 保存与验证

原型留在本地分支 `codex/prototype/notalone-windows`，原主工作区不修改。
按原型流程只做 JavaScript 语法检查和浏览器人工操作检查，不添加产品回归测试。
目前尚未选定布局，未创建正式规格或实现任务。选定后在实现任务中回填此分支与路径，
正式版本按规格重新实现，不直接合并这套原型代码。
