## 范围、台账与阶段门

1. 在明确服务、模型、该服务专用凭据和用户决定后，先完成离线参数／出站范围检查；不将现有ECNU凭据自动发送给新地址，不修改常驻App或项目.env。
2. 一段合成窗口跑原E／V，最多2次公开invoke。检查具名工具、字段、来源、target、引用、公开用量与隐私过滤；失败即停，不修补模型首输出。
3. 兼容通过后，原冻结四段匿名开发窗口各两次完整E／V，最多16次公开invoke；沿原Gold与原11/18严格必需覆盖、完整正确候选和错误auto基线比较。全部额外候选、成功空输出、失败、遗漏与正确候选损失均审，不只数事实数量。
4. 新模型原始输出先独立判语义，再揭核验与采纳去向。必须有严格完整保留收益、没有新增错误auto或原正确主张损失；大批转pending不算改善。无收益即关闭，不循环调配置或提示。

这次拟授权上限18次公开invoke，与已关闭修订试验的24次台账分别标识并关联，不重置或借用其剩余预算。SDK内部HTTP重试仍不能冒充逐次已观察的公开调用。逐调用记录服务、模型、用途、用量、耗时和结果；只保留允许的公开响应，内部思考不读取或落盘。公开笔记与代码约定不是运行通过证据。

当前没有该新服务的已选配置与任务授权，18次也尚未允许执行。用户选择其他服务或模型时须先重新核其官方接口和数据条件，不将这份提案当成任意供应商授权。

## 完整目标的后续条件

这18次只是前置对照，不替代实际聊天验收。若开发组达门，仍须明确新接收方的实际聊天范围与数据处理条件，再单独决定同一联系人六窗各两次的完整自然路径；严格必需保留须超过原6/12，错误auto不得增加，原正确主张不能丢失。随后冻结最终配置、首次比较原四段留出；不读取留出调参。有效结果还须生产最小修改、相关测试、隔离全量、两轴审阅、任务专属本地提交和新进程运行核验。当前都不宣称完成。

官方缓存说明称通常数小时到数天清理，不能据此承诺固定留存或逐请求删除；已查资料未证明该账号API输入免训练、零日志或可按来源删除外部副本。通用隐私政策也不能代替开发者下游应用的数据处理约定。这些未明确前，提案只涉及合成／匿名开发资料，不纳入实际聊天。[缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)、[隐私政策](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html)、[现行边界](../architecture/current/privacy-deletion.md)

业务记忆、旧五条认可资料、水位、回复模型、后台同步、外部聊天与远端Git均不在本试验修改范围。
