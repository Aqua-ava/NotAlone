## 问题与不同之处

[上一轮](memory-atomic-coverage-pilot-result-20261003.md)原第一轮两条第三人事实正文正确，却被E标为`assertion/asserted`；V收到这些标签仍判supported，形成两条评测坏auto。现有第三人规则和错标应uncertain的示例已经明确，程序没有丢字段或绕过门。旧九项逐字段V也已失败，不能只重写同一检查说明。

本方案检验“隐藏E标签＋来源独立标注＋确定性比较”联合方案能否减少V错误放行：模型仍看同一原话、候选正文、关系范围、类别、主题、来源及日期，但不看候选的`speech_act/assertion_status/figurative_type`。这些字段不能经动态system、工具描述、kwargs或示例泄漏；允许静态枚举定义，不能暴露哪个候选原本取哪个值。V按每个候选对应的来源主张独立给三个`source_pragmatics`标签，并返回原四项核验字段。输入、输出和system同时变化，即使成功也不能把收益单独归因于隐藏标签。正文和类别仍可影响判断，这不是全盲，也尚未证明标签锚定就是本次错误原因。

程序仅比较标签：raw verdict为supported而任一来源标签与E标签不同时，编译为uncertain并加入pragmatics；候选正文、14字段、来源、主体和日期均不改。原uncertain／unsupported不升级。source判断同样可能错误；两次模型一致判错仍能产生坏auto，必须保留这个反例和真实评分。

V公开Interface仍为现有`verify(window, facts)`到原四键结果，Flow和采纳门不变；私有wire增加临时`source_pragmatics`并隐藏输入标签，不增加模型阶段。supported缺完整来源标签、非法枚举、索引不完整／重复、额外键、混合非法tool或非法证据整包失败，不回退原V；先保留完整首次公开raw，再编译和校验，所有更严格结构损失计分。

`source_pragmatics`键始终必需；raw uncertain／unsupported允许其值为null，supported不允许。null只在结构上合法，来源标签准确采用门仍保留该机会且计未正确给出，不能给12/12信用或以拒绝全部达标。联网前必须完成五个公开字段的隐私投影保护，不复制content／metadata中的内部思考，也不访问additional_kwargs或model_dump；完整raw指允许的公开返回，不包含隐藏字段。

旧正文冻结标注也让模型在未见E标签时从原话标注，但它从N首包产生全14字段，再过V；本方案保留原E全部字段，独立来源标签只用于一致性降级，不替换字段。旧语义错误仍构成风险，没有凭此增加模型能力。新信息差异是候选标签在V中不可见、判定职责改为来源标签加确定性比较，不宣称论文完整复现。
