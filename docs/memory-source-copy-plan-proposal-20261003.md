## 问题与机制

[上一轮](memory-frozen-claim-annotation-result-20261003.md)锁定的是模型已经写出的正文，首包新增无据性别、漏限定或漏项仍会遗留。0API差异核对还确认，拟“优先原词”提示主要重复旧规则，不能把它包装成新的有效方法。

本方案检验一个不同的限制：模型不直接提供自由正文，正文的非模板字符必须由程序从实际来源片段复制。它拟针对旧六损失中的四项扩写污染，效果须同窗实测；不承诺修好另外的标签／知识分量缺和整项漏提。尤其允许细片段重组时，有出处的字也能拼出新词、无据动作或错误人物关系，不能称程序已禁止全部扩写语义。

这是借鉴[SpanCopy的来源跨度复制原则](https://aclanthology.org/2023.codi-1.9.pdf)，没有复制其NER、神经Copy Gate或训练流程，不称完整论文复现。[实体一致性研究](https://aclanthology.org/2021.eacl-main.235.pdf)和[CONFIT](https://aclanthology.org/2022.naacl-main.415.pdf)说明：来源词齐全仍可能拼错关系、否定、指代与时间，全部语义门继续保留。

## Interface与职责

外部Seam仍为MemoryExtractionRuntime.extract(window)返回原14字段，接原ExtractionFlow／V／采纳。新私有Adapter内部只用一次E调用，无N、A或R额外阶段；原V不改。两臂常见窗口仍各E、V两调用。

内部Tool每项返回原12元字段及copy_plan，暂不返回自由text或source_message_ids。元字段类型、枚举、语义、风险、置信度与时间规则保持。copy_plan包含：

- support_message_ids：同窗、语义相连的完整支持消息，无重复，至少含target；必须包含所有正文片段来源。问答的提问与确认回答均可列入，不能仅用context造事实。程序按此列表的原顺序复制ID，不从text推导主体范围。
- body_parts：1至32个带kind的对象，kind只取source_quote、punctuation、source_time_reference；按数组顺序组装，不自动重排、清理或补句。至少一个source_quote，组装正文必须非空。允许单字片段、重复及模型计划中的片段重组，不给这些操作赋予语义正确保证。source_quote含message_id、非空逐字quote、零起始occurrence_index、reference_scope及prefix_substitution。occurrence_index必须为严格非负整数（bool／数字字符串不接受），按原文中所有匹配位置（含重叠）由左至右定位；未知／越界位置失败，不模糊匹配、Unicode归一或补字。
- prefix_substitution只允许keep、sender、recipient、shared。keep逐字复制；sender仅接受我的或我开头，recipient仅接受你的或你开头。最长前缀和plural排除按所选occurrence在完整原文的位置检查，片段须包含该完整前缀：不能截取“我们／我们的”里的“我”走sender，也不能截取“你们／你们的”里的“你”走recipient；“我的／你的”不能截短来绕过最长前缀。按该消息已知sender与另一方分别换成用户／联系人、用户的／联系人的；未知sender、错误模式／前缀组合均失败。source_quote还含严格布尔shared_participants_explicit，shared须为true且仅接受完整我们的／我们前缀，分别换成双方的／双方；其余模式该值须false。“我们公司”不能仅因两位发送者而推断双方，true声明的语义仍须核验。
- reference_scope只取direct、quoted、unknown；非keep必须声明direct，quoted／unknown不得作上述替换。嵌套转述中的我／你不能套发送者；错误声明direct或双方参与仍可能通过结构校验，必须由原V和独审按原话判错，不称代码能证明引用人物。subject仍是关系资料范围，不等于事件actor，程序不据替换结果改任何元字段。
- punctuation的value只允许中文逗号、分号、句号。source_time_reference含message_id及严格整数source_part_index，后者是body_parts零基索引且必须指向紧邻前一项、同message_id的source_quote；显示“〔第N段来源消息时间：ISO值〕”，N为索引加一。unknown显示未知，固定模板之外不能生成日期文字。多个来源的相对期间逐段锚定，不用一个无关联日期统管。附注不称事件日期，不用当前时间；valid_at／invalid_at仍沿原元字段核对，不由附注替代。

程序复制片段、作上述有界人物称呼转换与时间附注，构造text；从完整支持列表构造source_message_ids，再装配原14Fact。每种part仅接受其规定键，模型不能另加正文、改来源、补模板外词；结构异常整臂失败，不回退原E、不发V、不重抽。候选上限60，空facts合法；原12元字段仍交原解析与校验，不以新copy_plan的严格结构声称覆盖旧E全部容错输入。范围、窗口、target和所有旧采纳校验保持。

合成机制示例：原话“我还在比较，没有决定”，sender为联系人。复制整句并转换开头“我”，可得到“联系人还在比较，没有决定”。若窗口确实没有组成“想购买”“大约”的来源字符，计划就无法直接装配这些文字。这个例子只说明字符来源限制，不是模型结果或准确率；从别处借字拼词、选择错误片段或重排原词仍会语义错误。模型应选完整原词／句法片段，程序不把片段字面存在当整条主张被支持。

## 必须先解决的可表达性

现有14字段能表达正确事实，不表示受限复制也能做到。批准后先在本机0API原型中检查：相连问答、未知性别第三人、历史报酬与当前知识边界、复合报价、否定对象、不同期限、本人和双方正例，能否构造独立完整且等价的Fact。

此0API原型门须覆盖现开发全部9必需语义（重复后18机会）、旧12保护语义及匿名4必需语义；不得提前解码实际或当前留出来填门。完整期间、条件、否定不能为适应复制而删掉；不得把裸引文或“说过某话”当关系事实，不改Gold、分类敏感性或topic评分。若必须新增自由词、其他人物／时间转换或改变事实含义才能表达，方案关闭并保留反例，不临时扩大renderer或再开变体。当前人工预期表达不是模型输出，不计入准确率，也不替代此原型门。
