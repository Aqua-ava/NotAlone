# 2026-10-23 微信首次接入排障与体验问题记录

## 结果与记录范围

本次已完成外置工具安装、App 路径配置和本机密钥初始化；CLI 返回 `live_read_ok=true`、`schema2_ready=true`，NotAlone 实际点击“检测微信账号”后成功显示配置账号，进入同步范围确认页。

问题由多层阻塞叠加造成：外置工具缺失、应用数据库服务未启动、微信数据访问权限不足，以及普通扫描未捕获数据库密钥。仅补一个 CLI 文件不能完成全新电脑接入。

前半段安装、环境和 PostgreSQL 恢复情况依据本次用户提供的检查报告；后半段初始化、只读检查、App 检测和临时权限关闭由 UU 远程实际界面核对。本文仅保存状态、版本、通用路径和操作步骤，不保存账号标识、联系人、密钥、密码或聊天内容。

## 本次环境

| 项目 | 本次环境 |
| --- | --- |
| 系统与架构 | macOS 27.0（26A425），Apple Silicon，arm64 |
| 微信 | 4.1.15，通用二进制 |
| NotAlone | 开发实例 0.1.0，Electron 44.7.0；未找到已安装的 `NotAlone.app` |
| 微信读取工具 | `wechat-cli 1.6.25`、`libWCDB.dylib`、`wxkey v1.4.8` |
| 应用数据库 | PostgreSQL 16.15，使用已有数据目录 |
| 初始化辅助组件 | Command Line Tools 提供的 LLDB、系统 Python 3.9.6 |

本次结论只适用于上述实测组合，不能视为所有 macOS／微信版本或正式发布包的兼容性认证。

## 遇到的问题与处理

| 问题 | 依据与原因 | 本次处理及结果 |
| --- | --- | --- |
| App 提示没有微信读取工具 | `wechatCliPath` 为空，回退到不存在的 `unconfigured-cli`；本机未找到 CLI 和 WCDB | 安装独立补充包，保存外层启动脚本的绝对路径；缺少 CLI 的提示消失 |
| 安装 CLI 后仍未就绪 | `db_root_missing`、`key_store=missing`、账号及数据库根目录未配置 | 区分“可执行文件可运行”和“本机微信账号已初始化”，继续补齐初始化工具 |
| 补充包没有 `wxkey` | CLI 与 WCDB 包未包含首次密钥初始化组件 | 另装 `wxkey v1.4.8`，完成包校验、arm64 架构、执行权限和签名检查 |
| App 内检测按钮不可用 | PostgreSQL 未运行，启动诊断为 `database_unavailable` | 使用同一版本 PostgreSQL 和原数据目录恢复服务，App 后端重新连接；未新建空库、重置资料或执行迁移 |
| 独立 Python 无法导入 `lldb` | LLDB 组件存在，但系统 Python 默认模块路径未包含其 framework 资源目录 | 核对 `lldb -P`；显式加入该路径后导入成功，初始化工具的 PBKDF 路径负责处理此环境；未全局修改 Python |
| 手机确认登录被误当作命令失败 | 工具先启动微信副本，实际登录需要手机确认；LLDB 回退又启动了一次副本 | 按当前微信窗口完成对应登录，不在初始化仍运行时反复重跑 |
| 数据库目录看似不存在 | 已知存储目录访问出现 `PermissionError`；“文件与文件夹 → 终端 → 微信”关闭 | 用户授权后临时开启该项；复查找到账号根目录及 27 个数据库，阻塞变为 `key_config_missing`，证明目录访问问题已解决 |
| 普通扫描找不到数据库密钥 | 已能访问目录，stored-sudo／`task_for_pid` 路径可用，但扫描仍返回 `no keys found` | 等待工具自动进入针对微信 4.1.x 的 PBKDF／LLDB 回退，不能继续归因为缺文件或缺管理员密码 |
| LLDB 需要系统开发者授权 | 出现 `Developer Tools Access` 系统认证窗口 | 用户在远端输入 Mac 登录密码并确认，随后完成手机登录；密码未进入聊天或文档 |
| 远程操作造成重复与不确定性 | UU 鼠标部分可用，但键盘、粘贴和部分点击转发不可靠；一次粘贴带入前导中文句号导致 `command not found` | 人工执行精确代码块中的命令，Agent 核对新输出；传输检查脚本后通过 `/bin/bash` 运行，不依赖可执行位 |
| 等待阶段没有新输出 | PBKDF 子进程输出由父进程收集，终端只显示启动信息和 5 分钟时限 | 保留正在运行的初始化，等待有界任务结束；没有因终端暂时安静而再次启动 |
| App 错误提示过于笼统 | 路径错误、账号未初始化、密钥缺失都可能只呈现“微信读取工具尚未就绪” | 用只读状态码逐层定位；实际检测成功后，页面进入配置账号与同步范围确认阶段 |

## 实际采用的恢复步骤

### 1. 安装并配置外置工具

安装前核对指定 ZIP 的 SHA-256，安装前后核对包内 `SHA256SUMS`；验证二进制架构、签名和执行权限。WCDB 通过实际动态加载，CLI 报告 `wcdb.available=true`。

```text
$HOME/Library/Application Support/NotAloneDesktop/wechat-tool/
├── wechat-cli            # App 保存的外层启动脚本
├── libWCDB.dylib
├── bin/
│   └── wxkey
└── licenses/
```

以上仅列关键文件，实际安装必须保留对应版本声明的全部依赖和目录结构。App 的“设置 → 高级 → 故障排查 → 微信 CLI”保存外层 `wechat-cli` 的绝对路径，不能改填 `wxkey` 或内部二进制。

恢复 PostgreSQL 后，App 已能调用 CLI，并返回 `wechat_tool_not_ready`。这与找不到可执行文件的 `wechat_tool_unavailable` 不同，说明应继续排查工具初始化状态。

### 2. 完成一次本机初始化

本次在用户明确授权后运行以下命令。命令用于记录已采用的版本特定步骤，不作为未来普通用户需要手动执行的产品流程：

```bash
/usr/bin/env \
  -u WXKEY_SHADOW_WECHAT_APP \
  -u WXKEY_PBKDF_WECHAT_APP \
  -u WXKEY_KEEP_SHADOW_WECHAT \
  -u WXKEY_NO_REOPEN_ORIGINAL_WECHAT \
  WXKEY_BOOTSTRAP_ORIGINAL_WECHAT=0 \
  "$HOME/Library/Application Support/NotAloneDesktop/wechat-tool/bin/wxkey" bootstrap
```

`WXKEY_BOOTSTRAP_ORIGINAL_WECHAT=0` 用于限定本次不走原版微信重签分支。工具创建并使用独立微信副本；本次没有关闭 SIP，也没有重签原 `/Applications/WeChat.app`。

初始化包括管理员授权／用户 Keychain 凭据存储、访问微信数据、启动副本、手机确认登录和 LLDB 调试授权。这些系统影响需要在开始前清楚说明；密码由用户在系统窗口输入，不能要求发到聊天中。

普通扫描失败后，工具自动进入 PBKDF 回退，在 LLDB 管理的副本登录后，打开“文件传输助手”触发数据库加载，没有发送消息。最终输出为：

```text
PBKDF fallback got partial key coverage (26/27).
Core opened DBs are usable.
key config written
keys: 26
```

配置写入本机 `~/.config/wxcli/config.json`；未复制或展示其中的密钥。26/27 是部分覆盖，不能写成全部数据库已完成验收。

相关行为核对来源：[本次锁定的 wxkey 源码](https://github.com/r266-tech/wxkey/blob/9b70eecdde47a7172b19465c3f977c86b6050e8a/cmd/wxkey/main.go)。

### 3. 只读检查与 App 检测

只读检查脚本通过以下命令运行：

```bash
/bin/bash "$HOME/Downloads/NotAlone-WeChat-Check.command"
```

脚本收集签名、目录元数据、`wxkey doctor` 及外层 CLI 的 `status --include-debug --strict-read-only`；原始子进程输出在本机处理，只显示筛选后的状态，不显示密钥或聊天正文。该脚本是本次辅助检查文件，不是已实现的 App 接入能力。

| 检查 | 最终可见结果 | 含义 |
| --- | --- | --- |
| 原版微信可执行文件摘要 | 与初始化前一致 | 原版可执行文件未改变 |
| 原版微信严格签名、Team ID、CDHash | 校验通过，身份与基线一致 | 没有把原版微信重签为副本身份 |
| `cli_status_exit` | `0` | CLI 状态检查执行成功 |
| `db_root_configured`／`identity_configured` | `true`／`true` | 已配置数据库根目录和账号身份 |
| `schema2_ready` | `true` | 数据库密钥配置就绪 |
| `key_store` | `config_legacy` | 工具识别并使用本机配置中的密钥存储 |
| `live_read_ok` | `true` | CLI 自身报告读取检查通过；未展示消息正文 |
| `strict_read_only`／`wcdb.available` | `true`／`true` | 严格只读及 WCDB 可用 |
| `image_key_ready`／`readiness` | `false`／`degraded` | 仍有能力降级，不能称为全部能力就绪 |
| App 实际点击“检测微信账号” | 显示配置账号，进入同步范围确认页 | App → 后端 → CLI 的账号检测链路通过 |

同次 `doctor` 报告 `wechat_not_running`，因此其账号根目录检测未通过；目录元数据和 CLI 配置检查仍正常。不能把这一结果重新解释为数据库目录丢失。检查时副本已退出，持续登录状态未单独验收。

Agent 只点击“检测微信账号”，未点击“确认连接并同步全部私聊”。后续界面另观察到“自动同步已开启”，但本次没有验收该状态下的消息增量、去重或历史补齐，也不以联系人列表出现作为正文同步成功的证明。

### 4. 权限收尾

初始化及上述检测完成后，已在系统设置关闭临时的“文件与文件夹 → 终端 → 微信”，并核对开关为关闭状态。本轮没有授予完全磁盘访问权限。

原版微信文件及签名保持不变；配置和工具授权保存的 Keychain 凭据仍留在本机，关闭临时文件访问权限不等于删除这些资料。未在权限关闭后再次执行 CLI／App 读取验证，因此关闭后的持续可用性不能沿用关闭前的结果认证。

## 尚未解决或未验收

- 数据库密钥覆盖为 26/27，缺少的一个数据库未定位；未证明所有数据库均可读取，不因部分覆盖直接要求用户重复初始化。
- `image_key_ready=false`，图片能力未就绪。普通扫描曾显示派生图片密钥，但最终状态未就绪，不能用中间日志代替最终结果。
- `readiness=degraded`；本轮已通过账号检测，不代表全部读取、图片、后台刷新和长期运行能力通过。
- PostgreSQL 本次为恢复已有服务，尚未由 LaunchAgent／服务管理器托管；系统重启后的自动恢复未验证。
- 未完成正式安装包、无开发环境机器、微信升级后密钥刷新、权限收回后的持续运行，以及正文同步／去重／停读的完整验收。
- 当前外置工具交付模式见 [桌面说明](../desktop/README.md#外置微信工具)。本次独立补包和初始化成功，不代表 App 已具备自动下载、安装或首次配置能力。

## 用户体验问题与后续目标

用户明确提出：普通用户接入必须简单，目标是一键式；当前先记录问题，尚未实施此改进，也未更改既有交付或隐私决策。

当前体验的问题是：用户需要理解 CLI／WCDB／wxkey 区别、安装两份补充包、填写绝对路径、恢复应用数据库、处理环境变量、复制终端命令、多次确认副本登录，并自行区分扫描失败与等待。现有通用错误文案没有把具体原因和下一步操作说明白。

后续产品应提供一个“连接微信／准备微信读取工具”入口，由应用组织完整流程：

1. 自动检查应用服务、系统／微信版本、架构、已有配置和依赖，明确区分服务未启动、工具缺失、权限不足、未登录和密钥缺失。
2. 按确定的来源、校验和许可方案准备完整依赖，固定安装位置并自动保存启动路径；已有有效配置可复用，失败可以重试。
3. 在一个连续向导中解释并引导必要系统授权和手机确认，显示“正在等待授权／登录／捕获密钥”等真实阶段；提供有界超时和具体恢复动作。
4. 默认保护原版微信，说明副本与凭据生命周期，结束时核对副本退出和临时权限收尾；不能以用户难理解为由隐藏系统影响。
5. 自动完成只读状态和 App 检测，分别展示文字接入是否可用、图片能力是否降级、哪些项尚未通过。
6. 将“工具准备完成”和“授权同步范围”分开。完成初始化不自动开启全部私聊同步，后续仍按用户确认的范围和总开关读取，外部消息由用户亲自发送。

“一键式”指用户从单一入口完成流程、应用承担技术步骤。管理员密码、macOS 系统授权和手机登录确认仍由用户在对应系统／微信界面完成；无需让用户手动理解工具链或反复执行命令。

本文件记录问题和改进目标，不作为已实现规格；后续实现方案、交付方式和版本验收应单独评估。
