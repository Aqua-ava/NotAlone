# 单联系人文字的开发验收隔离导入

2026-10-30，用户明确允许：状态无法确认的指定私聊文字可仅在本机隔离保存，显示未核验，禁止进入检索、记忆和生成，并支持删除。本入口用于已授权的开发验收；正常历史支持档和产品业务库保持独立。

## 范围和来源

- 从已配置工具账号读取 verified 元数据，唯一解析用户确认的一个私聊；不读取整份名单或其他会话。
- `quarantine-target` / `quarantine-page` 使用独立 consent，要求当前程序版本、完整目标结构、声明主键和来源守卫可核验。一次固定快照同时持有全部分片读连接，按同一目标和一次性游标遍历。
- 来源守卫绑定文件实例、微信可执行路径、PID和微秒启动时间；独立事件队列监听文件命名空间及进程退出/exec。失证即停止。它不证明原位恢复、跨重启身份映射或后续增量能力。
- 所有页记录仍为 `unverified`。只求取文字正文，不读取非文字载荷、source/XML或媒体文件；超限或无法解码的文字不截断，计入无法保存数量。
- 本次快照遍历完成仅代表已遍历该固定切面，不表示普通历史完整、送达/撤回状态已认证或可恢复旧游标。

## 本机存储和查看

开发验收隔离仓位于显式新目录，仅有专用 `vault.sqlite`，目录0700、文件0600。它没有正常消息、记忆、索引、模型或DSH消费者，不向业务运行时注册Tool。每仓绑定一个范围摘要，失败保留已保存的未核验文字并标明不完整。

查看器只监听127.0.0.1随机端口；每次启动生成随机令牌放入URL fragment，接口校验Bearer、Host和Origin，响应no-store。界面只提供未核验文字的分页查看、单条删除和删除全部，不提供采纳、检索或生成。

开发分支的 App「设置 → 未核验历史」枚举系统应用资料目录 `NotAlone-Quarantine` 下一层 `snapshot-YYYYMMDD-UUID` 隔离仓。管理页只拿名称、计数和快照完成状态；点击后在无 preload、无 Node 权限、独立临时会话的窗口中查看或删除。窗口网络只允许该隔离查看器的回环来源，关闭时释放查看器和仓句柄。目录列举和身份复核使用严格只读检查，不中断正在写入的导入；正在导入或尚未开始的仓拒绝打开。

这不是 App 联系人的资料来源列表：不会按昵称自动归属 `contact_id`，也不向正常消息、检索、记忆或生成服务接线。切回管理页会刷新计数。查看器显示的来源守卫状态只描述原来的快照期间。

删除会清除隔离表行并执行SQLite清理，合成测试核对正文不留在数据库文件中。该结论不承诺操作系统备份或介质的物理擦除。

## 开发命令

从 `backend-ts` 使用当前Node≥24运行；以下均为开发验收工具，不启动常规后台同步。

```sh
node src/history/quarantine-cli.ts import --root /绝对路径/新的隔离目录 --contact 已确认联系人 --executable /绝对路径/已核验开发CLI
node src/history/quarantine-cli.ts view --root /绝对路径/已有隔离目录
node src/history/quarantine-cli.ts verify --root /绝对路径/已有隔离目录 --executable /绝对路径/已核验开发CLI
```

查看器是常驻进程，Agent启动时须按工程工作流放后台；不打包、不替换用户组件，不向外部模型或聊天发送消息。命令只输出计数或本机查看链接，不输出正文、账号、来源身份或SQL错误。

`verify` 只读当前账号和指定会话的元数据，重新计算 `[accountKey, conversationKey, sourceGeneration]` 摘要并与隔离仓比较，不读取新的消息页。匹配时仍返回 `normalHistory:false`、`stateAssurance:unverified`、`continuity:not_verified_across_restarts`；失败统一返回 `identity_unverified`。摘要相符只说明当前身份键匹配，不证明消息分片跨重启连续，也不认证送达、撤回或删除状态。

## 验证入口

- 原生：来源进程退出、快照之间退出、旧PID启动身份、文字隔离/非文字无载荷、独立consent和普通历史门禁。
- 客户端：隔离页的类型/范围/目标校验，拒绝伪造verified；普通历史仍不接受未知正文。
- 导入：完整固定切面、来源失证停止并保留不完整隔离仓、伪造认证记录拒绝。
- 隔离仓/查看器：临时合成库的范围、权限、重开、稳定分页、单条/全部删除，以及匿名/跨Origin/错误Host拒绝与正文安全渲染。

依据：[Apple kqueue(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kqueue.2.html)，本机SDK `libproc.h`/`sys/proc_info.h` 的进程路径与启动时间接口。实际运行结果在后续验证记录中追加，不用源码或合成检查代替真实导入。

## 本轮实际结果

获准的单一私聊一次固定切面遍历7页，保存89条隔离文字，无法保存文字0条。全部记录仍为未核验、normalHistory=false；普通历史支持档继续unverified，未授权正常检索、记忆、生成、增量或跨启动恢复。没有读取非文字载荷、其他联系人、source/XML或媒体文件，没有外发或模型调用。

隔离仓重开后89条独立记录均保留，目录0700/文件0600，SQLite integrity_check=ok，没有正常业务表。导入结束后受控CLI读者0。真实资料及可恢复定位仅留仓库外本机私有目录，不进入Git。上一轮仅提供独立查看器；本轮接入开发 App 的独立隔离入口，仍不接入正常联系人资料。此结果不关闭03/04/06/21的正常渠道验收。

代码审查：Standards未发现硬性标准违背；信任模式布尔参数已改为显式模式。Spec初审发现原生意外退出的部分失败原因过于笼统，现已按守卫证明丢失标记并覆盖回归，delta审查无阻断。守卫唤醒失败的极端清理路径仍为非阻断观察项，不能据此声称所有系统故障均已认证。

最终自动检查：新的固定源码制品原生race测试154通过、1既有跳过；后台相关7文件94项通过，类型检查通过。实际浏览器已看到合成未核验文字和隔离提示；原生JS删除确认框触发工具焦点超时，查看器改用页面内二次确认，后续交互结果另记。NotAlone开发实例检查为stopped/pids[]，本轮界面是独立隔离查看器，不是正常App接线验收。

实际界面补验：合成仓通过页面内二次确认完成单条删除2→1及删除全部1→0；恶意HTML字符串按纯文字显示。随后打开真实隔离仓，仅核对状态栏89条/不可保存0条和未核验提示，没有对真实记录执行删除。原生确认框的工具阻塞已由页面内确认消除，删除后重载首屏以防游标失效。

## App 接线与身份复核补验

2026-10-30，使用同一已授权隔离仓执行 `verify`：当前账号、会话和元数据来源代次摘要相符，返回 `identity:matched`；同时明确保留 `normalHistory:false`、`stateAssurance:unverified`、`continuity:not_verified_across_restarts`。复核前后均为89条，快照状态和更新时间不变；只调用账号/会话元数据，不读取新的消息页。

通过 `pnpm run dev --user-data-dir <独立目录>` 启动并核对开发宿主与监督器。在实际 App 设置页打开合成隔离仓，验证纯文本显示、单条删除2→1、全部删除1→0，关闭后释放窗口并清理该合成仓。最终打开原获准隔离仓，仅输出状态栏核对89条/不可保存0条和未核验提示，未删除真实资料。隔离入口可在业务后端未连接时使用；本轮独立用户目录中的普通联系人/生成链未验收，不能据此标记正常业务可用。

审查发现目录列举使用可写重开会中断正在导入的仓，现已改为共享严格预检的只读 `inspect`；目录与身份复核均不恢复状态、不修改权限或mtime，显式查看拒绝ready/running。回归覆盖原写入者仍能继续追加和完成。最终相关后台26项、桌面控制器5项、两端类型检查及测试登记检查通过；Standards与Spec独立复核无剩余阻断。测试清理钩子的先后顺序错误已修正，不涉及真实资料。
