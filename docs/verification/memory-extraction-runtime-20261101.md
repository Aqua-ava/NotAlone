日期：2026-11-01。结论：明确饮食偏好的合成样例已使用当前真实模型完成提取、来源核验、自动采纳、主题与长期概览发布及回复检索；实际开发 App 重开后显示本轮完成。此结论不覆盖任意聊天的准确率。

本机服务恢复复用提交 `8a15eef6`：受管数据库目录中的备份完整迁出；单个失效图片来源不再使整个宿主启动失败，原访问拒绝继续保留。详情见[聊天时间与启动恢复记录](contact-chat-time-order-20261101.md)。本轮实际操作默认开发 App，确认“本机服务已连接”；验收结束恢复同一默认开发入口。

本轮修复四处记忆链路问题：

- 桌面自有 DSH 子进程透传显式问题预算和轮次，仅传这两个诊断键，不透传模型凭据环境。
- 正常 SQLite 文字窗口补齐 `text_representation: 'text'`，使事件核验的逐字引文能按现有协议转换来源位置；解析器和来源检查不放宽。
- 核验提示说明多条引文只列实际出现的主体词，不为省略主体的引文虚构人称提及；保留无法消解时拒绝的规则。
- 文档前置阶段不能覆盖已有的提取失败原因；真正的文档阶段失败仍记录其错误。

模型为正常配置的 `deepseek-flash`，沿官方 DSH `0.2.1-rc.2` profile、当前提示词、共享 provider、许可与认证业务 API 执行。没有绕过来源核验或手工写入正式记忆。仅历史读取准备使用合成 metadata/channel；真实微信读取关闭，未操作微信或发送外部消息。

r3 的唯一事实是联系人的“我不吃香菜。”，其余为“收到”“谢谢”等填充。结果核对如下：

- 正式记忆“联系人不吃香菜。”为 `auto`，来源引文、联系人、消息、记录与版本一致，可在 App 查看来源和撤销首次自动采纳；未把填充或该偏好写入本人范围。
- 发布一份饮食主题和一份长期概览，正文均只保留该事实，引用同一正式记忆版本；未增加健康原因或其他忌口。
- 两条回复候选包含点餐避开香菜，并以该记忆和主题／概览作为 `actual_input` 依据。仅生成候选，没有选择或发送。
- 真实 `pnpm run dev` 使用同一隔离资料重开，Computer Use 核对“本轮已完成”、6/6、自动采纳、逐字来源和资料发布；重开前后累计调用数均为 13。实际 DSH 子进程的预算环境绑定已核对。

各轮均由独立 Agent 审阅，不登记为用户人工验收。r2 的改善只限主体提及子问题，不能作为整轮通过。r3 的泛指“不吃香菜”可合理归为持续偏好，但来源没有证明永久性。原 8 条复杂居住／计划样例在文字表示修复后未完成真实模型复验，保留失败记录；不得用 r3 替代其验收。
