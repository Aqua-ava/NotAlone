# 多联系人同步恢复与分范围验收

日期：2026-11-03。用户要求覆盖全部已加入联系人，并实际验证多位联系人；本记录不以单联系人成功代替全部范围通过。

最终范围核验为 285／285：284 位具备当前有效范围的完整终页与持久检查点，1 位经正式认证为无表空目标；全部正常消息接口复核成功，未发现跨联系人归属。总开关开启，新增确认联系人默认同步，用户暂停、撤销和删除的排除规则保留。以下区分当前结论、修复过程和不同轮次证据。

## 已实现

- 共享读取器切回联系人建立新历史目标后，始终唤醒首次历史接续；已有新持久增量检查点时解除旧快照的调度阻塞，不能复用失效游标。
- 空闲守卫失效后，只有仍允许正常使用元数据续证的联系人自动请求恢复；真实来源围栏和撤销授权不自动解除。
- 历史记忆调度先跳过未完成历史，并单独计算阻塞条件，避免重复统计未使用的增量输入。调度顺序、到期规则和模型配置保持。
- 各领域同时收到关闭请求，全部排空成功后才关闭共享微信进程、模型和 SQLite；任何失败保留共享资源供原操作重试。
- 来源读取预检在同一事务选择元数据重验或严格代次检查，避免认证刚完成或瞬时守卫超时被旧预检结果重新围栏。真实来源变化仍停读。
- 旧读取器来源按 ADR-161 独立证明所选物理表，正式重新认证保留撤回抑制；已完成审计只用于后续删除与排除闭包，不恢复旧资料资格。维护意图位于 SQLite 目录外，启动归属检查只认可私有固定文件，未知对象继续保留并拒绝。
- 两个历史协调器使用只含原授权字段的轻量目录。定点唤醒只查询相关联系人的覆盖，仍核对所有排队与在途任务的授权；全局唤醒、重试、绑定换代和停止继续保持原规则。

## 最后轮转审计发现与修复验证

- 全部最近页接口成功后继续检查真实后台轮转，发现新历史任务仍可能使用已停车的旧原生目标。严格通道复现：两位联系人交替建立新目标，首次接续读取旧目标被拒绝；来源准备替换保留守卫目标时也存在同类错误。候选修复只复用与当前原生目标完整一致的持久任务，新目标建立对应历史任务，保持旧增量游标失效。
- 原共享通道夹具没有严格拒绝旧目标。现补充唯一原生目标标识校验，并增加 32 位联系人真正关闭、重新打开 SQLite 后首次与增量协调器同时启动的负载，覆盖正常启动的并发交接。
- 旧增量任务已阻塞后，后来发生可恢复的守卫失效，也必须重新核验当前恢复资格并唤醒首次历史；真实来源变化继续拒绝自动恢复。
- 逐批确认加入 3 位合成联系人的默认同步资格回归通过；新增不恢复已撤销联系人，总开关关闭后所有联系人停读。
- 同一份 285 位只读备份，固定四次授权目录读取交替比较：全目录两轮 2766／2651 ms，轻量目录 30.9／32.7 ms，SQL 28 → 8，正文或来源统计查询 8 → 0；绑定和总开关投影摘要一致。对应同步状态、图片和引用调度仅需授权字段，状态入口的两次独立授权快照继续保留。

以上修复已合入开发实例：主仓相关检查共 105 项通过，后台 TypeScript 检查通过。严格 8／32 人轮转、32 人重开后并发启动均通过；生产增长唤醒可正常接续，因此未修改首次协调器队列。独立审查发现的一次恢复资格查询失败后不再重试问题已修复，并验证下一次普通轮询恢复。另有既有守卫测试的旧回复夹具失败在未修改主仓单例复现，不计为本次通过。

以下保留修复过程中分段验证的事实；最终全目录范围结论见“真实范围检查”，不以合成测试代替真实读取。

- 后续按稳定授权范围累计观察到 190／285 位联系人有修复后的成功分页，其余 95 位尚未轮到；这里统计成功分页，不代表每位均已到终页。一个大目标被并行开发热重启打断前已接受 822 页，仍未到终页。其没有新增 `capture_record`，但去重会复用旧来源，因此不能据此推断原生页为空。
- 原生分页最多读取 16 行，未完分页游标仅属于当前快照，持久检查点只在终页保存。真实 Go 合成复现确认：首个未完页后释放选择，恢复找不到检查点并退回新目标。与后台 1000 页预算及共享读取器切换组合，会使大目标重新扫描。现共享正常使用通道保留同一固定快照租约至终页，每 1000 页只让出事件循环；取消、授权与守卫仍逐页核验。
- 超过 1000 页的新检查在主仓 7／7 通过，覆盖 1001 页与随后另一联系人完成，以及第 1001 页在途时取消、停读、撤销授权，迟到正文均未接受；类型检查通过。原非共享通道的 1000 页预算续接规则保持并已验证。大快照期间其他共享原生请求需要排队，纯 SQLite 聊天显示和状态查询继续可用；本次没有增加逐页跨重启恢复，退出仍可能重扫未完成部分。
- 并行头像开发和界面开发多次触发热更新，真实观察均在运行时变化时结束并保留分段；没有将不同运行时的结果混算为单运行时全目录完成。
- 读取工具升级制品后，唯一无表空目标在正常重验之前比较旧支持报告而误建围栏。现只在需要正常重验且报告变化时进入现有完整目标与守卫证明路径；报告相同仍只探测空目标元数据。新增 4 项主仓检查与类型检查通过，覆盖重开后制品更新、连续元数据探测不新增历史页，以及分片变化、活守卫报告变化、真实已有围栏继续拒绝。已出现的围栏仍需正式重新认证，不直接清除。
