# 聊天图片占位与原图提取验收（2026-11-01）

实现依据：[ADR-138](../../architecture/adr/138-chat-image-original-extraction-and-placeholder.md)。本次覆盖图片提取、状态、受管文件及聊天展示；回复、记忆、联系人匹配、语音和视频业务流程没有扩展。

## 实现结果

- 图片消息先按原有稳定身份入库，提取结束只更新媒体关联；聊天历史专用 `history-messages` 返回图片摘要，原 `/messages` 合同保持不变。
- 只有经过来源、HD 长度、明文 MD5、内容摘要及解码验证的原图才发布文件。WXGF 转 PNG 的证明分别绑定源内容与输出内容。
- 确认仅有缩略图时只核对存在性和关联元数据，不读取其内容、不保存缩略图。缺资源、缺密钥、解码失败及质量失证分别记录。
- 缺密钥时可在同账号已授权图片提取内调用既有 wxkey；密钥只在宿主内存和专用继承管道中传递，不写业务库、参数或日志。未调用 bootstrap、重启、改签、注入或微信图片下载。
- 新版幂等键对旧版失败补处理一轮；成功和清除的图片不随普通同步重新提取。聊天按稳定分页游标刷新同一消息，多图预览沿用活动引用和删除撤销 ACK。

## 实际 App 与微信

使用正常 `pnpm run dev`，验收后 `dev:status` 确认为 development 实例。没有打包、运行打包版或发送外部消息。通过 Computer Use 核对正在运行的微信主实例，并在实际 NotAlone 管理后台完成：

1. 一条真实原图消息显示为图片，原来的加载占位消失；切换联系人后旧图片撤下。
2. 一条真实 `thumbnail_only` 消息显示“仅有缩略图，原图未取得”，没有图片元素。
3. 数据快照为 26 个当前原图文件、36 次仅缩略图结果，缩略图文件数为 0；后台继续处理时数量可变化。
4. 对同一已授权联系人再次正常同步返回 200，文件数保持 2，尝试数保持 19，未重复保存或重新派发。

没有为了验收清除真实用户图片；在途清除、来源删除、撤销 ACK、多图片及迟到响应由合成服务和页面测试覆盖。实机截图及聊天内容没有落入仓库，用户体验反馈未单独采集。

## 已知限制

- 当前环境的 wxkey 单独取钥仍以权限错误退出；没有擅自 bootstrap、改签或重启微信。因此不能宣称真实加密 WXGF 的完整自动取钥链已成功。
- 复查此前独立成功的那张 WXGF 图片，现有消息元数据只有 mid 资源字段，缺少本版原图证明所要求的 HD 长度和 big URL。当前返回 `media_quality_unverified`，未保存为原图。历史独立成功与本次集成通过的样本不能混为一谈。
- 合成 WXGF／HEVC 原生解码和管道密钥传递已通过；实际成功保存并显示的原图不能据此代表所有微信图片格式可用。未覆盖格式继续保留失败状态及来源，未回退使用缩略图。
- 既有 6 条连续性隔离仍使全局同步状态可能显示降级；本轮没有解除隔离或扩大授权。

本次没有启用图文记忆处理。后续可依据稳定消息、文件版本、来源与独立图片进度组装模型输入，不能让文字处理水位覆盖尚未取得的图片。
