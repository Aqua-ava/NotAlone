# 引用回复随正常同步读取验收（2026-11-01）

用户要求先收尾原引用任务，再将正常同步中新遇到的引用直接读取、携带并保存，旧占位继续后台补齐。原任务在 `0f2f03c4` 提交后释放源码和桌面，本轮按 [ADR-141](../../architecture/adr/141-inline-quoted-reply-sync.md)实现，不以全量旧历史追平为完成前提。

## 实现与数据边界

- 正常历史页和增量页直接返回精确 49/57 类型的结构化引用；首次历史同步也适用。显式 `quote-read` 与内联读取共用固定快照、账号／会话、消息身份、发送方、状态和大小校验。
- 仅六类已有单条失败可保留占位并继续页面；来源、授权或守卫变化仍终止读取。回复及被引文字各限 65,536 UTF-8 字节，不展开被引非文字媒体或持久化 XML。
- 内联引用只在内存中的准备记录携带，与消息、来源和游标在原事务中写入引用扩展及完成／失败记账；引用正文不写入普通 `capture_record.raw_payload`。
- 成功保存后不再进入后台引用候选。旧 CLI 继续普通同步和旧占位补齐；内联解码必须同时匹配固定 `quoteProtocol`、`quoteReader` 和 `quoteInline` 声明。
- 沿用同 owner/contact/binding 的稳定消息关联与删除排除。重复来源首次补齐或首次记录失败会发布消息更新；相同内容重放不重复刷新。扩展写入失败回滚整个同步页及游标。
- 新增引用附加字段不改变原有 tail 记录摘要，保留旧检查点语义；制品变化仍通过固定源码配对和来源别名升级。
