# 历史与增量记忆处理验证

对应 [ADR-152](../../architecture/adr/152-history-and-incremental-memory-processing.md)。

## 实现范围

- 当前已授权联系人历史导入终页提交后，自动以最多50条文字建立固定历史批；启用边界前的旧增量归历史补齐，新增增量独立排队。
- 增量沿用静默10分钟、50条、最旧6小时和启动间隔30分钟；历史批不推进增量冷却，每个历史批之前重新检查增量，各联系人轮转。
- 候选待决定和主题／概览阶段不单独阻挡新的文字提取；主动暂停、真正L1失败和未知调用继续保留。
- 已知失败最多自动恢复一次；系统中断使用明确原因，可沿原输入安全续跑。恢复前及写事务重新核对来源、控制修订和回执；结果未知不重发。
- 增量建轮、领取、处理前复验和结果提交支持同一来源一次元数据续证；已返回模型结果继续使用原结果，不重调模型。
- 共享微信读取器正常停车后重开通道，完整查证成功才交接原持久守卫；真正身份／来源变化和当前通道停止仍使来源失效。
- 联系人处理卡分别显示历史、增量排队数量，最近一批提取进度不表示累计全部完成。

## 返回格式与遗留运行状态修复

- 实际拒收记录表明：一次提取返回只有单个文本块，其中是完整、可解析且符合原提取结构的JSON，缺少工具调用外壳。提取入口现可显式归一这一外壳，继续使用原严格JSON解析、字段与来源校验；不放行多个文本、错误工具名、重复键或截断内容，来源核验入口仍要求原具名工具。未将私人原文写入测试或本记录。
- 文档阶段在创建步骤前发生来源失败时，专用轮次现在沿正常失败路径结算；启动恢复也会结清旧版本留下的假运行状态。活租约、用户暂停和真实未知调用保持原样，不发布失效内容或标记成功。
- `backend-ts/`执行提取参数、流程、失败合同、文本JSON、核验包络及文档调度／终态回归，共40/40通过；`node node_modules/typescript/bin/tsc --noEmit`通过。测试使用合成资料，证明格式与执行状态合同，不代替真实记忆语义验收。

## 大历史轮与来源恢复

- 旧大轮沿原固定输入、步骤和预算每20条让出执行机会；提取及后续裁决通过同一FIFO串行，恢复登记不再阻止正常调度启动。步骤完成后主动检查到期增量，支持同一联系人在历史步骤间继续处理新增文字；未知、失败、暂停和在途状态仍受保护。
- 正常来源重新认证撤销旧授权后，旧轮保留原输入与回执，但不再阻挡新认证资料的第一批处理。仅持久撤销的授权／绑定退出当前进度门，临时守卫失证仍需正常续证。相关7模块37/37通过，含正常重新认证后旧unknown和暂停完全不变的回归。
- 取消判定增加按调用隔离的实际fetch前门证据：明确未到前门才结为未发送；到达前门或缺少证据继续保守。依据锁定的`dsh-llm-deepseek@0.2.1-rc.2`制品`lib/index.js:2197、2215、2217、2229`，扩展结束后检查取消，普通请求构造fetch参数时同步经过匿名身份钩子；strict请求使用自身fetch前门。没有修改官方adapter或全局fetch。
- 正式DSH、ModelHost和SQLite本地供应商回归11/11、独立路由边界5/5通过；确定取消场景在原源码的临时工作树复现失败，当前实现通过。真实发出后无回执仍未知，取消前未发送能正常继续且无未决占用。
- 正式自动处理回归确认增量先行、历史随后，重启不重复；手动跨联系人测试用未封口合成历史隔离自动队列，保留本人汇总和来源隔离验证。全部模型响应为隔离合成供应商，未将这些结果冒充真实模型语义验收。
