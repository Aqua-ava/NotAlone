# 助手讨论耗时扩大复测

日期：2026-11-03。起点为 `794e05a2`；测试期间其他工作仍在修改开发入口及历史同步代码。此记录是性能反证，不是新增修复的验收结论。

## 结论

原来的全账号重复扫描、撤下内容协议和草稿恢复已分别修复，但三次 345.17／16.34／0.74 ms 的接口观测不能证明整体耗时稳定。扩大采样确认当前实际后台仍有秒级等待，不能仅解释为首次连接或客户端 JSON 解析。

## 实际开发后台

复用 `pnpm run dev` 实例，不主动重启或清缓存。客户端为 Node 24.22.1 中的生产 `JsonClient → readAssistantSession → readSqliteDiscussion`；固定同一会话，约每 250 ms 发起一次且只允许一个会话请求在途，整批约 30 秒。模块编译、导入不计入请求耗时；这不包含 Electron IPC 或屏幕绘制。

| 分组 | 次数 | 成功 | 中位数 | 本批 P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 后台 PID 前后相同，全部读取 | 41 | 41 | 57.623 ms | 3669.008 ms | 4199.684 ms |
| 其中复用连接 | 40 | 40 | 49.763 ms | 1551.620 ms | 3695.539 ms |

中位数在偶数样本时取中间两项的均值；P90/P95 使用 nearest-rank，只描述本批样本。

- 41 次共 9 次超过 1 秒，其中 8 次使用已复用连接；返回始终为同样 2 条发言、1030 字节，完整发言投影未变化。
- 复用连接的两个慢样本分别为 3695.539、3669.008 ms：请求写出均不超过 0.253 ms，几乎全部时间在等待响应头；正文结束后的解析和严格校验约 0.1 ms。
- 本批客户端事件循环最大延迟不超过 3.394 ms，正文结束至读取完成最大 0.947 ms。没有证据将数秒等待归因于客户端解析。
- 该批开始靠近后台就绪时间，不能称长期运行后的稳态分位数，也不能据此承诺日常延迟。PID 未变只排除了该批内的后台替换。

第一版探针另有 53 条原始观测：52 成功、1 次 8 秒超时。但未记录结束时后台身份，且临时探针对复用 socket 重复注册了不会触发的 connect 监听，产生警告。这一版不用于稳定性分布；原始样本仍保留。探针已修正，产品代码未改。

随后全线程 `sample` 与配对请求期间发生了热重启：第一对缓存 `/api/runtime/status` 用时 24.564 ms，而会话读取为 4314.576 ms；后续出现退出中的 503 与旧连接失败。这一批单独标记为中断，不纳入上表。采样时主线程大多等待事件，存储 Worker 有大量 `StatementSync::All` 栈，指向数据库 Worker 执行或队列争用；由于采样跨退出且缺少动作级计时，尚不能认定具体后台 SQL。

## 隔离合成对照

正式 SQLite profile，无真实微信、记忆任务或模型；相同生产读取代码，响应固定为一条合成发言、1133 字节。所有请求成功，独立后台与临时资料均已清理。

| 场景 | 次数 | 中位数 | P90 | 最小—最大 |
| --- | ---: | ---: | ---: | ---: |
| 五个新客户端进程的首读 | 5 | 25.035 ms | 28.757 ms | 22.740—28.757 ms |
| 同进程复用连接读取 | 45 | 0.576 ms | 0.849 ms | 0.432—1.304 ms |
| A/B 交替，解析当前会话后读取 | 31 | 1.124 ms | 2.128 ms | 0.786—26.082 ms |
| A/B 交替，已知会话身份直接读取 | 31 | 0.324 ms | 0.436 ms | 0.234—0.774 ms |
| 并发刷新 92 个 Skill，再解析会话读取 | 15 | 120.627 ms | 175.775 ms | 107.724—176.049 ms |
| 并发刷新 Skill，已知会话身份读取 | 15 | 106.463 ms | 111.224 ms | 99.762—119.825 ms |

新客户端首读的 socket 分配至 connect 事件为 19.300—22.381 ms，包含 Node 和系统调度；JSON.parse 仅 0.022—0.033 ms。新连接能解释部分差异，不能解释实际后台复用连接上的 3.7 秒等待。

另 5 次在 Skill 刷新中途发起缓存状态读取，分别等 98.433、88.586、85.685、83.567、83.991 ms；同轮会话为 104—119 ms。已核验目录刷新会在循环中调用 `spawnSync`，这是已复现的独立宿主阻塞来源，但没有证据将实际后台的全部秒级等待归因于它。

## 边界与后续定位

- 已知 SID 读取与解析 SID 后读取分组；解析包含删除状态、会话目录和正文，不发切换会话的 POST。
- 常数连接代次的临时脚本没有完整复刻 `BackendHost` 的退出取消；中断批不能直接换算成正常 App 的可见等待。
- 不删除慢样本，不把隔离数据冒充实际后台，不把接口耗时冒充界面完成时间。
- 本轮只做测量并修正记录，没有修改产品实现或真实聊天、发起模型、发送消息、制作发布包。
- 下一步应在不受热重启干扰的版本中记录后台存储动作的排队时间与执行时间，再处理具体阻塞；不能继续只用连续三次快读作为完成依据。
