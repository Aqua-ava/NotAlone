# 守卫登记修复的读取器升级验收（2026-11-07）

## 目标与完成边界

本轮承接[重启围栏调查与守卫登记修复](fence-root-cause-and-guard-registration-20261107.md)，让已修复的原生监听登记缺陷具备安全升级路径，核验新制品在真实微信来源上的元数据重验与跨运行代次续租。历史 219 位围栏的实际触发原因仍未复现，不据本轮升级结果改写历史归因。

真实配置切换属于用户此前保留的下一阶段决定。本轮只修改隔离工作树中的升级脚本、合成测试和本记录；配对输出与业务验证均在私有目录／数据库副本中进行，不修改真实业务库、真实启动配置，不执行“修复同步”。

## 验证入口与数据边界

使用 SQLite 备份接口准备 00:05 历史备份及当前库的私有副本。旧读取器先在迁移后的历史副本上完成正式重验并正常关闭；关闭、确认没有 WAL 后复制该副本，执行旧→新读取器升级及后续重启验证。原备份和真实库仅只读访问。

历史副本先通过官方 SQLite Worker 完成 schema 45 的离线准备；随后每轮均使用未修改的 `SqliteStorage.open` 及正常预算开库，产生新的运行代次。重验装配为正式 `SqliteContactService`、`SharedWechatClient`、`createWechatHistoryChannel` 与 `SqliteHistoryService.prepareSource`，包含授权、账号、会话、来源代次、支持档、物理目标、连续性和守卫核验。

没有启动历史协调器、模型或记忆服务；历史页、增量正文、引用正文及边界读取在回放器中显式拒绝。省略的 checkpoint 范围回调仅用于派生页索引文件绑定，本轮不验证这些文件或正文同步。来源元数据取证只透明记录原 `inspectSelected` 的返回值，不额外调用或跳过原验证。最终回放器在任何准备异常时均保存证据、立即中止当轮并正常关闭资源。

每轮在关闭前核对：

- 所有有效未围栏联系人均成功准备来源，守卫为当前运行代次的 `active`。
- 围栏逐行集合、既有围栏的守卫、绑定、读取授权、认证记录及来源代次摘要不变。
- `read_goal`、`sync_capture`、`model_call` 数量不变，正文拒绝入口调用数为零。
- 正常关闭后再打开同一副本，运行代次递增，重新完成来源核验和续租。

旧未完目标允许按正式规则变为 `invalidated/history_runtime_revalidated`，不把该合法变化误报为新建目标。账号／范围标识和来源元数据仅保留在端侧私有证据中，报告不包含联系人姓名、账号、聊天正文或凭据。

## 剩余工作与回滚

真实应用尚未启用新读取器。只有用户决定切换后，才对真实库做一致备份、部署已核验制品、更新 `wechatCliPath` 并通过 `pnpm run dev` 正常重启，再检查围栏集合、运行日志及正常使用效果；不打包、不运行打包版。

旧制品、旧别名和原配置保留。配置指回旧制品只回滚程序，不能自动撤销切换后新增的围栏或覆盖期间的新业务数据；不得通过删除围栏冒充回滚成功。

副本通过只能证明本次覆盖的来源重验和续租，不能证明历史 219 条围栏已归因、正文增量同步已验收或未来不再出现围栏。真实启用后仍需在正常使用中观察常驻诊断日志，按新增事件的实际入口与分支继续定位。
