# 混合记忆调度验收（2026-11-01）

状态：实现、正式宿主集成检查与热更新开发 App 合成验收已完成；既有夹具失败单独记录。

## 范围和数据边界

- 用户采纳 ADR-143 混合方案，并明确选择：自动处理新资料，已有历史由用户单独启动初始化。
- L1 只处理启用边界之后首次保存且首个来源为 `incremental` 的有效文字，按联系人计算静默 10 分钟／50 条／最长 6 小时，以及两次开始间隔 30 分钟。每轮冻结目标；读取授权、来源及删除资格仍由写事务复验。
- 实际正式记忆版本变化在同一事务登记 L2，首个变化起固定 1 小时合并；主题正文相对最近成功概览消费的正文发生变化时登记 L3，首次可初始化，后续保留 24 小时成功时间基线。
- 后续等待不阻塞新 L1；新 L1 立即进入回复依据。失效文档不进入依据。页面只读展示全局队列和最近一轮进度。
- 结构版本 27/28 增加持久任务状态、轮次登记标记和首次启用的最大消息序号；不搬迁、重导或回填私人聊天。边界之前的增量消息也排除，历史消息在增量页重见不改变资格；清空消息后新序号仍跨过边界。旧轮次默认没有自动续接标记，不能因升级而自动处理已有历史。
- 验收只使用隔离的合成联系人、合成聊天和环回供应商；网络守卫仅允许本轮环回服务与自有许可 socket。未发送外部聊天，未打包，未调用真实模型。

## 空提取后的文档状态补验

- 正常空提取经 `enrollRun` 持久登记 `no_formal_change`／`no_formal_memory_change` 后，轮次已完成，但文档读取仍返回 `processing`，实际主题资料页持续显示“本轮处理中”。先用正常 SQLite 服务链和实际 React 页面分别复现，再修复读取投影。
- 仅在当前范围的 L1 已结束、具有上述持久登记且无待审候选或未解后续工作时，无发布集合显示现有 `idle`；已有发布仍通过原来的完整集合及来源资格检查后显示完成。没有用空提取、空文档列表或缺少文档步骤推定完成，也没有新建发布集合或状态。
- `node --test test/sqlite-memory-documents-empty-status.test.mjs test/sqlite-memory-documents-schedule.test.mjs`：17 项通过。新增 4 项覆盖正常空提取、缺少持久证明、同范围旧待办／失败／unknown、范围隔离及旧有效发布保留。

## 既有夹具问题

在不含本功能的主线独立复核了以下既有失败，未将它们作为本功能通过证据：

- `sqlite-memory-documents-deletion.test.mjs` 的“同一消息的来源按实际 record 区分”父测试及两个子项假定重复历史同步会留下两个来源；现行去重后只有一个来源，形成上述扩展检查的 3 项失败。
- `sqlite-memory-unknown-deletion.test.mjs` 在调用提取前就假定重复历史同步会留下两个来源；现行去重后只有一个来源，断言 `1 !== 2`。
- `sqlite-memory-documents-migration.test.mjs` 的 12→13 夹具在联系人目录读取时 `storage_invalid`，早于本次轮次代码。实际 App 会先完成连续结构升级，再加载业务服务。
