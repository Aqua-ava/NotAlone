# 微信图片版本分类验收（2026-11-02）

按 [ADR-154](../../architecture/adr/154-source-grounded-image-versions.md)保留微信图片资源版本及分类依据，不按像素尺寸或大小阈值判定原图／缩略图。分类不影响图片保存，不接入记忆处理。

## 实现

- 固定 CLI 使用 `wechat-message-image-content-v2`，保留已绑定资源的主图／缩略图角色和匹配资源原始类型。主图需同一消息声明与内容证明匹配才认证原图；缺少声明或声明损坏时仍保存合法图片。
- 客户端复验消息身份、资源集合、源与输出摘要及分类一致性；资源变体数字不作为原图推断规则。保存模块通过追加迁移31持久化分类依据，删除时同步清除，公开聊天投影只携带类别。
- 手动媒体提取先核验同一联系人的来源元数据，再校验已有文件引用；重启后重建来源守卫不读取历史页，不推进历史目标。来源失败时保留已有文件，不创建新提取尝试；取消信号贯通元数据核验。
- 聊天图片显示原图、缩略图或图片版本未确认；同步设置文案与允许保存已绑定缩略图的实际行为保持一致。

## 本机验收

仅使用 `pnpm run dev`。新版开发组件 `image-quality-20261102-v1` 的 CLI SHA-256 为 `8c2711c5ec49221ac293c1bf79785d735f72960602b2cd124a4c4c873ce8f7fe`，overlay 为 `0226344fc635b1599cfce677dadaf59f9f171a3d1c86909d592a211eacb003aa`。与先前组件逐文件对照只有两份图片 Go 源码变化；既有账号、来源身份、普通消息、引用和共享进程代码保持一致。别名准备不启动 CLI、不读微信数据库，只核验已固定组件及旧别名。

切换前备份业务数据库、启动配置与指定图片副本。沿正常配置保存函数更新 CLI 路径，再启动开发 App；后台保持 `manual`。实际仅对单个已授权联系人的4张旧未知图片调用正常媒体提取入口，4次均完成，分类依据均已保存。结果为1张已认证缩略图、3张主图资源但缺少原图证明；原有2张原图及证明保持。6份当前图片内容摘要与验收前一致，磁盘大小及摘要复验通过。

Computer Use 在实际 App 选择该联系人、分页及滚动到图片，观察原图与缩略图预览和对应版本标签。未发送外部消息。捕获记录与模型调用计数均未增长，未启动记忆或全联系人处理。SQLite quick_check 通过、外键问题为0。私人身份、消息、图片和操作收据未进入仓库。

保留当前组件及旧组件作为回滚依据，清理本轮约2.4 MiB隔离 Go stage；新增开发组件约275 MiB。未制作 App 发布包、推送或创建 PR。图文共同进入记忆模型仍是 ADR-153 的后续接线范围。
