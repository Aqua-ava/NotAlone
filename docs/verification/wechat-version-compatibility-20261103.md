# 微信读取器版本诊断与准备说明验收

## 变更与边界

- 账号元数据检测仅在未通过版本或结构核验时返回检测版本、构建号及当前固定支持范围；响应不包含账号路径、渠道摘要、正文或任意上游文本。成功检测不返回兼容失败字段。
- 支持版本常量由账号元数据适配器与检测诊断共用，避免升级时两处值漂移；HTTP 只接受精确的兼容诊断对象，不再使用任意字段袋子。
- 桌面控制器只透传四个受控版本字段，页面明确显示检测值与支持值，并说明应更新读取器适配，不能关闭版本核验或改读未知数据表。
- 已连接用户可从同步设置页主动重新检测微信版本与来源；检测失败时保留已知账号并显示兼容范围，不自动重放授权。
- 外置读取器首次准备和阻塞态补充自行安装、绝对路径、账号密钥、只读状态检查及重新加载步骤；明确 `wxkey bootstrap` 的管理员密码取舍由用户自行决定，NotAlone 不执行该流程或接收密码。
- 同步诊断补充非文字占位语义：占位只表示消息存在，语音、视频、文件和表情正文未取得，不能作为聊天或回复依据；同时显示增量消息身份基线 100,000 条上限。
- SQLite 存储诊断明确当前业务数据库和本机资料尚未由应用层加密，不能据通道安全、文件权限或测试通过宣称静态加密。
- 未改变微信版本支持范围、数据库结构、来源核验、读取授权、同步去重、删除或外部模型调用。现有“大历史分片轮转”和“当前联系人优先”实现不在本轮重做。

## 开发 App 检查

- 核对并复用现有 `pnpm run dev` 实例，未打包、未启动第二份开发实例。
- 实际查看同步设置与设置页故障排查；已连接页显示“重新检测微信版本与来源”，存储诊断显示“当前业务数据库和本机资料尚未由应用层加密”的提示。开发服务的同步开关随后恢复显示为开启。

## 剩余风险

- 当前只改善版本不匹配的可诊断性与处理说明，没有新增对新版微信表结构的认证，也没有保证微信升级后继续读取。
- 应用层静态加密仍未实现；本轮只把现状提升到存储诊断中明确可见。数据库、媒体、备份和模型凭据的加密方案、密钥生命周期、迁移与回滚仍需独立设计及用户授权后才能实施。
