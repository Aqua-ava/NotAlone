## 已确定与未确定

在已认可的公开extract接缝重放匿名首次E请求／返回，三次均明确报漏项：原话“我不知道那位做设计的朋友现在的报酬”已送入请求，首Tool只返回3条copy_plan，没有任何计划引用该句；程序收到3条并组装3条。给相同接口注入已冻结的人工合法知识计划时可以完整组装，说明程序有能力表达它；这个正控制不是模型生成、修复或准确率提升。

现规则一般性支持本人当前状态和否定；“不知道真的假的”排除示例限定于转发外部信息，不是见到“不知道”就删除。原14字段、Flow与语用层没有这一关键词删除规则。合法知识状态可以保留；无V时仍带semantic:unverified，不把本机保留称为允许自动采纳。

旧知识text单叶匿名曾4/4，当前copy为3/4；两次源窗口及用户正文完全相同，模型配置相同。旧text专门说明“谁不知道什么”，copy没有迁移它；但输出Tool、正文／来源表示、协议及schema长度也不同，因此这两个单次结果不能证明哪一差异造成漏项。旧单叶开发已失败，不能据此恢复或循环调整它。

前3／4／12项试探及后来的text剥离已经明确区分说话者知识状态与模型证据不足。assertion_status这处叶位置未单独测，不等于换位置就有新机制。当前没有证据表明此遗漏由status混淆造成，不据此追加API。完整结构对象仍输出后面的喝茶事实，60事实／32片段上限未触碰；捕获未保留finish_reason，不能证明或否定服务端截断。

## 新候选与范围

检验“单次只选择一条target，减少多条消息之间的遗漏”这一假设。它可能仍会漏提，收益必须与本次原臂比较。本轮只拟使用既有四消息匿名合成窗口，不读取真实聊天或留出。

- 原臂：四条消息全部target，一次原E／原V。
- 候选臂：按原消息顺序拆成四个窗口；每窗仅一条原target，其余三条为context。全部消息正文、ID、sender、未知时间、顺序和owner/contact保持；不删、改、补或重排原话。
- 两臂都使用当前默认LangChainExtractionRuntime、原system、原14字段schema、原Flow／V／语用和采纳门。不使用copy_plan或任何失败提示变体，不增加第三个模型阶段、自由字段、确定性补造事实或业务写入。
- 保留相连上下文及完整引用；不是强制每条消息产生事实。context只辅助理解，每个候选仍须由当前target直接支撑，不能把context事实挂到它上面。

这与[已失败的target分组wire](memory-target-group-wire-result-20261003.md)不同：后者全部target仍放在一次E里，只组织结果groups，没有真正拆成多次E。只读审查未找到上述精确分窗条件的独立实测；此结论仅覆盖已审文档和静态脚本，不宣称搜索过全部私人返回。

产品已有batch_size=1参数，但run_extraction按前后各最多20条重新裁上下文；不能把它等同于保留任意原长窗全部messages。本提案只对四消息匿名窗保留全文，不改产品批次配置，不将结果外推为全历史可用。
