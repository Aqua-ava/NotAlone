# 来源连续性围栏诊断

每次实际新增来源围栏并提交事务后，后台在应用资料目录的 `logs/history-continuity.jsonl` 追加一行 JSON。普通重启追加，不覆盖旧文件；最多保留当前文件和 `.1`、`.2`、`.3` 三份归档，每份不超过 1 MiB，记录保存 7 天，在启动和追加时清理过期内容。

日志只包含 `time`、`entry`、`contactPrefix`、`branch`，部分来源失证入口另有固定白名单 `errorCode`。`entry` 为实际存储动作，`contactPrefix` 只有联系人编号前 8 位。日志不保存姓名、聊天、备注、完整联系人编号、账号、路径、异常正文、堆栈或凭据，不自动上传。

## 分支编号

| 编号 | 判据 | 所属核验 |
| --- | --- | --- |
| G01 | 既有守卫非 active、运行代次或绑定／会话／来源不匹配 | `preflightGeneration` |
| G02 | 已存 scope 的会话／来源不匹配 | 同上 |
| G03 | scope 表基线为空但已有历史或抑制资料 | 同上 |
| G04 | scope 缺失但已有历史或抑制资料 | 同上 |
| T01 | 目标预检时 scope 缺失但已有资料 | `preflightTarget` |
| T02 | 已存目标不能接受当前目标转移 | 同上 |
| T03 | 目标预检未取得可用 scope | 同上 |
| N01 | 租约的绑定／会话／来源不匹配 | `prepareNormalUseTarget` |
| N02 | scope 的会话／来源不匹配 | 同上 |
| N03 | 已存目标格式或账号不成立 | 同上 |
| N04 | 已存目标至当前目标的转移不成立 | 同上 |
| N05 | scope 缺失但已有历史或抑制资料 | 同上 |
| N06 | 旧租约失效且不具备 normal-use 重验证明 | 同上 |
| N07 | 无租约但已有读取目标 | 同上 |
| A01 | 无 proof 取得守卫时既有租约不匹配 | `history.guardAcquire` |
| A02 | 无 proof 取得守卫时无租约但已有目标 | 同上 |
| R01 | 非 normal-use 守卫释放 | `history.guardRelease` |
| R02 | 已独立观察到来源失证后释放守卫 | 同上 |
| L01 | 当前有效绑定及 scope 匹配，明确标记来源失证 | `history.markContinuityLost` |
| C01 | 重新认证失败需要重新插入缺失的围栏 | `history.recertifyFail` |

编号在代码中固定，不依赖会随修改移动的行号。入口和编号共同定位实际写入分支；`errorCode` 可进一步区分来源、结构或目标失证。它们记录程序实际经过的分支，不自动证明外部来源真的发生变化。对既有围栏的重复请求不会重复写记录，事务回滚不留伪记录。

## 故障与清除

日志目录须由当前用户持有且权限为 0700，日志为 0600 普通文件，拒绝符号链接及多硬链接。普通写日志失败时只报告一次固定 `history_continuity_diagnostic_unavailable`，不输出原始异常，不撤回围栏或放宽读取；这类文件系统故障期间可能没有诊断，不能把日志缺失当作没有围栏。

整联系人删除在原删除任务结案前过滤全部日志及归档中的该编号前缀，整账号删除清除全部围栏日志。清理失败时删除任务受阻并可重试，不报告删除完成。由于只保留前 8 位，前缀碰撞时相同前缀的诊断一并移除；它不改变其他联系人的业务资料。单份来源删除、历史清空和重新认证不删除这些无正文的故障诊断，仍按 7 天／4 MiB 上限淘汰。

日志不是来源认证证明，不参与联系人身份、读取资格、围栏恢复或模型输入。历史日志缺失时只能通过隔离复现归因，不能根据当前分支说明补写过去的错误码。
