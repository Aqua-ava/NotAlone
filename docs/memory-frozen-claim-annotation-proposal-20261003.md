## 问题与证据

当前E一次生成全部14字段；Flow对已生成条目做结构及来源范围校验，V只能拒绝／降级，不能改正文或补漏。subject说明澄清、正文说明、字段顺序、分组、R及模型对照均已有关闭结果。没有找到具备直接机制、可立即在当前spec内启动的新主问题试验；这不表示一切新文字或组合已被证明无效。

旧叙事方法也已实测，不能把“先理解再提取”重新叫作新方法：第一轮产生 `text/source_message_ids/evidence`，第二轮仍能重新生成全部14字段。旧合成B全流程完整9/32，低于原11/32，详见[原复刻结果](memory-method-replication-experiment-20261002.md)。

## 候选Interface

保留外部 `MemoryExtractionRuntime.extract(window) -> ExtractionPayload` Seam和原 `ExtractionFlow`。新的实验Adapter内部承担两步，再走原V：

1. 使用既有 `NARRATIVE_SCHEMA`、系统提示和验证器形成临时条目，输出仍为 `text/source_message_ids/evidence`，上限60。不设少量硬配额、不增加actor字段；只用冻结窗口及target/context规则。第一阶段仍可能幻觉、漏提、混合主张或缺来源，真实片段不代表语义完整。
2. 代码按同一次窗口中的条目顺序分配 `claim_index`，绑定窗口、正文和来源指纹。标注工具只返回 `claim_index`及原14字段中除 `text/source_message_ids`之外的12字段，共13键。模型阅读原窗口和该临时条目，填写类别、资料范围、置信度、风险、语用、日期及解释；无权增加、删除、拆合条目，或改正文／来源。
3. 代码逐索引装配原14字段Fact：正文和来源从冻结首阶段复制，其余字段从对应标注复制。按原Flow／V与原采纳门决定去向；全索引覆盖不等于全部自动采纳，问题／转述／计划／歧义继续按原规则处理。

新标注输出缺索引、重复、越界、结构非法或携带禁止改写字段时，整个新臂失败，保留首次输出与完整分母；不从相邻条目借期限、补来源、猜人物，不回退原E。源码和匿名契约测试只证明装配不可改写，不能证明第一阶段正文或后续标签正确。

相比已试路径，本假设的区别是第二阶段的正文／来源改写和条目遗漏在Interface中被移除。旧叙事第二阶段可重写，旧R修订已成型Fact，分组只组织完整Fact，evidence-first只改字段顺序。冻结可能阻止有益修复，必须以实测反向检查；单纯增加actor或继续修改来源说明暂不采用。

首阶段漏提不会被此Interface找回，首阶段的错误或缺来源也会被保留到核验前；混合人物、不同语用或不同期限的条目不能在标注时拆开，可能没有一套完整正确标签。它们都计作错误／遗漏，不通过丢掉原文分量、借其他条目的字段或只降置信度消分。首阶段只具备正文／来源，不称完整Fact正例；先独审其含义和必要来源，再审各最终Fact及原V去向，记录可改写臂修复正确而新臂未能修复的反向证据。
