# 主体与事实状态保真第一轮（2026-10-02）

最终采用较小的提取与核验提示词修正。第二组新合成场景的全流程完整语义正确从 **20/32 到 27/32**，正文／主体／语用不忠实而潜在自动采纳的候选从 **4 条到 0 条**。但固定候选仍有错判，两个旧错误复现仍可能放行；不能宣称已解决全部记忆准确性问题。

## 实际修改

- 提取保留“已发生／当前／计划”的原阶段，不因省略回答补出打算；明确计划不能无依据标成假设或条件。
- 正文中的参与者与 `self/contact/shared` 字段一起核对。双方讨论或赠送物品不证明共同执行后续动作；没有维修者等执行主体时保留被动结果。
- 用户亲友资料使用本人范围，联系人亲友使用联系人范围，仍保留第三人称呼及转述；发送者不直接决定事实主体。
- 否定归属保留原来被否定的人，不能把逻辑上仍可能成立的另一否定子句当作忠实改写。
- 来源核验输入去掉候选置信度、风险、备选解释与自述理由，只保留要核对的主张字段及原消息，降低候选自证的影响。

保持现有模型、温度 0、公开提取／核验接口、逐字证据契约及采纳门槛。核验仍每窗口至多一次，支持不改主张、未知只降级、无支持拒绝；没有新增调用阶段、数据库字段或扩大自动采纳范围。

## 复现与两次比较

先将上轮保留的三种错误候选送到现有真实核验：单方状态标成 shared、否定对象换人、当前位置改未来打算均被放过。第一自然失败和后续失败均保留，未补抽覆盖。

首版尝试四维结构化检查，并由代码合并最保守结论。可控接口测试能阻止缺失或矛盾的字段，但实际模型仍会把四项全部误判成支持，且出现回退，故撤下该方案；实验源码和测试快照保存在本机审计目录，未挂接默认流程。

第一组 16 个新场景（8 主体、8 状态）及正负双候选在模型调用前独立检查。四处转述歧义先修正再冻结。首版结果暴露新的标签与范围错误，遂改成较小的提示词修正。第二组另外 16 个独立场景也经独立 gold 检查后冻结；没有据其模型输出调提示词或改答案。第一组不再称留出验证。

每组分别跑固定候选核验与自然提取完整流程，修改前后各两次，共 **256 次运行**。四组实验顺序固定随机交错，最多三并发。同一既有配置模型；实际响应元数据报告 `deepseek-v4-flash`。不能把配置名称当作底层模型身份的独立证明。

自然提取每次只执行一次，再重放原候选；修改前后共享来源输入，不共享自然候选，完整流程差异含模型波动，不能孤立归因于核验或某条提示词。固定候选比较另行隔离核验变化。

## 评审、成本及失败

两位 Agent 在隐藏方法、模型、置信度、风险与核验理由的材料上逐条核对两组共 128 个自然输出，每条分别看初始和核验后结果。这是 Agent 语义盲评，不是人类标注者验收，核验器自己的 supported 不是评测答案。第三位 Agent 对 14 条疑难记录独立复核，主 Agent 回看原文裁决：一条冒号扩张转述归因的首版输出由完整改为不完整，四条新增“验收通过”的候选补记状态错误；第二组完整语义正确数仍为 20/32→27/32。原评审、独立意见、裁决及重算脚本分别留存，没有修改来源、冻结 gold 或首次模型输出。

两组共观察到 **379 次逻辑 invoke**，827335 输入 token、97174 输出 token；不等于 HTTP 次数或账单，供应商内部重试不可逐次观测。额外 9 次诊断核验不在上述仪表统计中。第二组自然流程平均耗时修改前约 3.91 秒、修改后约 3.52 秒，只是本次并发观察。

两次整批核验结构失败保留：首版自然 `subject-04/after/1`、第二组固定 `holdout-subject-05/before/0`。其余诊断循环仍有语义放行失败，不用重跑成功覆盖首次失败。
