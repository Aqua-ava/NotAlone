## 2. 为什么当前放行表是空的

1. **用户 2026-10-05 的决定（路线 A + B′）**：默认放行表先置空，不沿用
   2026-09-15／16 台账里的旧去向达标结论。ADR-033 明确要求"不以旧去向达标签
   替代语义准确率"，因此那些旧数字只能证明评测工具能跑，不能充当本轮放行证据。
2. **已按新口径跑过首批评测，两个维度都没达标签**：在 ADR-036 之前，
   `summarize().meets_gate` 额外要求"该维度全部用例带语义标注且语义场景 ≥15"，
   与 ADR-027 第 2 条不一致。口径对齐后于 2026-10-06 按用户批准的档 B′ 跑完档 A
   （79／80 次调用）：`subject` 用例 20、假事 0、记错人 0、**一般错误 2**（超限 1）；
   `paraphrase` 用例 20、**假事 3**、记错人 0、一般错误 5。两者均未达标签，
   且三条假事触发预注册的停止规则，第二阶段（`time` ＋ `truth_intent`）未启动。
   聚合指标见[档 A 结果](memory-dimension-release-tier-a-result-20261006.md)。
3. **fail-closed**：无法从既有字段明确判定维度键的候选一律视为未放行。

放行表为空的效果：所有通过原有三道门槛的候选都走既有
`_create_pending_candidate` 路径，安静保留等待用户确认；不写 `confirmed_memory`，
`AdoptionStats.adopted` 不增加，`pending` 增加。

## 3. 放行一个维度需要什么

按顺序全部满足才允许把维度写进放行表：

1. **可推导**：该维度的运行时键能由既有字段确定性判定（见第 1 张表的
   "是否可推导"与 `dimensions.py` 的规则表）。不可推导的维度到此为止。
2. **评测达标签**：用 `notalone-memory-evaluate` 的正式链路跑该维度，由
   `summarize()` 输出"用例数 ≥15、假事 0、记错人 0、一般错误 ≤1"。数字必须
   由工具输出，不得手写；语义标注覆盖（`semantic_cases`／`semantic_scenarios`）
   要一并如实记录，用来判断这批用例的语义强度。
3. **预算与范围先获批**：评测预算按
   [按维度放行的评测预算提案](memory-dimension-release-evaluation-proposal-20261005.md)
   单独报用户批准（2026-10-06 已批准档 B′）；未批准前不读凭据、不联网、不运行评测。
   档 A 已用 79／80 次，档 B′ 余量为第二阶段保留但**未启用**（档 A 未过门即停止）。
4. **用户逐类批准**：达到门槛只是必要条件。每次只放行一类，由用户明确批准。
5. **写入台账**：在本文第 1 张表把该维度改为"已放行"，并追加一条记录：

   | 字段 | 说明 |
   | --- | --- |
   | 维度 | 运行时键与评测维度名 |
   | 用例数 | `summarize()` 输出的 `cases` |
   | 假事数 / 记错人数 / 一般错误数 | 同一行的计数字段 |
   | 语义标注覆盖 | `semantic_cases` / `semantic_scenarios` |
   | 模型与配置 | 模型名、是否思考模式、日期 |
   | 批准 | 用户批准的时间与原文要点 |
   | 回退条件 | 什么情况下撤销该维度 |

6. **同步代码默认值**：把 `DEFAULT_DIMENSION_RELEASE` 改成对应的显式放行集合，
   并让测试断言默认放行表与本文一致。

一次只放行一类；不因为某个维度达标就顺带放行其他维度。

## 4. 怎么回退

按影响面从小到大：

1. **运维级全量回退（不改代码，立即生效）**：
   设置 `NOTALONE_MEMORY_DIMENSION_GATE=0`，重启提取命令或 Worker。按维度放行
   门关闭，恢复到本门启用前的行为（通过原有三道门槛即自动采纳）。该变量只接受
   显式 `0` 才关闭；未设置、空值或其他值都保持门开启。
2. **撤销单个维度**：从 `DEFAULT_DIMENSION_RELEASE` 的放行集合里移除该维度，
   在本文第 1 张表把状态改回"未放行"，并补一条撤销记录（时间、原因、影响范围）。
   已自动采纳的记忆不因此自动删除，需要走既有的修正／失效／删除路径。
3. **回退后的核对**：重新跑 `tests/unit/memory_extraction/test_adoption.py`
   与 `test_dimensions.py`，确认默认放行表与台账一致。

回退不改变置信度 0.7、风险白名单、语用分流与来源语义核验规则；这些规则的任何
修改必须单独立项并附评测证据（ADR-027 第 4 条）。

## 5. 复核节奏

- 每次放行、撤销或调整门槛口径后，同步更新本文并重新核对代码默认值。
- 评测用例集变化（新增、删除、改写用例）后，已有放行记录要标注"用例集版本已变化"，
  并在下一次评测时重新确认达标签。
- 本文只记录维度级结论与聚合数字，不记录任何聊天正文、联系人名称或用例原文。
