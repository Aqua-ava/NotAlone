# 记忆语义与直接来源复测（2026-10-02）

本轮沿用户授权的同一已确认联系人与既有模型服务，冻结原话和候选，先复现再比较修复方案。局部 Agent 参考标注不能换算为全聊天准确率，也不是用户确认事实。

## 冻结材料与评价边界

43 条旧问题重新区分为正文结合必要语境无支持 30 条、争议 6 条、正文有支持 7 条。正文正确仍可能漏直接引用或主体字段错误；这组复核不是全部 216 条的新总体评分。双方共同主张、共同安排与共享经历分别校准，不能把 shared 限定为共同当事人，也不能仅因双方讨论过就使用 shared。

新增合成 16 场景／32 正负候选，开发 4、独立留出 12。首次冻结前由另一 Agent 复核并修正有歧义的 Gold，旧版与修改理由保留；调用后不按模型结果改答案。实际冻结为 12 固定候选（6 正文／主体／限定负例、2 纯引用不全、4 正例），另有 6 个自然提取窗口、9 条参考主张。自然复合内容按独立主张记完整／部分／缺失，额外输出另行核对。

原语用标签没有完整持久化，固定候选标签为明确记录的重建；窗口是显式新有界窗口，不是原始请求的精确重放。Baseline 从 `4b04692` 的完整 Runtime 快照独立加载，包含原 schema、提示词和序列化，不用新序列化加旧提示词冒充旧臂。

## 首次基线

开发合成两次重复共 16 判断全部符合 Gold，但实际候选两次重复共 24 判断出现 9 次误放：7 次正文／主体／限定错误、2 次引用不全；其中 7 次会通过公开自动采纳门。正例误拒 0，运行／契约失败 0。这证明短合成通过不能替代实际来源核对。

实际自然两次重复共 12 窗口、16 raw 候选，接受 14、拒绝 2。接受正文准确 9、明确错误 2、歧义 3；全部契约符合的保留结果 5。另有 4 条正文有据但第三人转述标签升级为本人事实；两条范围拒绝均合理。公开门槛 auto 9、pending 5，其中有问题的 auto 5（1 条频率推广、4 条转述标签升级）。必需参考主张 12 个机会中完整 4、部分 3、缺失 5；可选 6 个机会中完整 2、部分 2、缺失 2。核验模型的 supported 与真实逐字 quote 不能自行证明全部语义正确。

## 耗时、接口与验证

最终思考模式的固定两轮共 269.276 秒，原基线 33.783 秒，约 8 倍；自然提取由 34.329 秒增至 304.376 秒，约 8.9 倍（公开调用分别为 20 与 24 次，空提取少调用核验）。没有扩大每窗口调用预算；不能据此计算费用金额，实际单价与内部重试费用未提供。思考模式仍有随机波动，不因构造时温度为零就视为确定性。

本机 `langchain-deepseek 1.1.0` 支持已有 `extra_body` 入口；[DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)说明该开关及工具调用接口，且思考模式不采用温度参数。当前 ECNU 网关实际返回模型为 `deepseek-v4-flash`；官方网关页面读取超时，因此兼容性结论来自本轮真实公开调用，不能外推所有代理地址。内部思考字段过滤后才持久化，正文之外的隐含思考不作评测依据。

生产组件还用于既有写入裁决；两条合成 smoke 均返回可解析工具结果，但动作期望只符合 1/2：重复事实为 `noop`，独立资料为 `add` 而非期望的 `keep`。现有 `MemoryAdoption.adopt` 的 `add` 与 `keep` 都追加保留，不撤销旧记忆；本轮不改裁决协议，也不据两条例子宣称裁决准确率。两调用、两台账、数据库连接和业务写入均为 0。

记忆组件配置测试先真实 red（`extra_body=None`），改动后 green；168 项记忆单元测试通过，三个相关源码文件 mypy 通过。最终代码的全量 `unittest discover -s tests` 在本轮新建并确认的独立 `_test` 库运行：36 个迁移、1,143 测试通过（跳过 3），结束后只删除该临时库。全量日志为 `/tmp/notalone-memory-source-fidelity-final-full-20261002.log`。

Standards 轴：硬标准违反 0、heuristic 建议 0，12 项逐项检查。Spec 轴：代码规格冲突／越界 0；指出 1 项 P2 统计口径问题，已按两份冻结独立审计区分 raw、接受及全契约核心覆盖修正，并单列正例损失。两轴都以固定 `4b04692` 到含新增文件的工作区 diff 审阅，不遗漏未提交变更。

只让本机后端经既有正常 shutdown／App 监管路径重新加载代码，App 进程保持运行；新后端确认 running、HTTP 200、CLI 增量流 active、仍为原 115 个已绑定会话，界面保持原联系人与输入状态。既有历史补齐 `cli_message_table_missing` 未由本轮解决，不将增量运行说成全部历史集成成功。本轮没有 Swift／签名或系统权限修改。

## 数据处理

仅选同一联系人所需规范化文字；保留 target／context 与候选直接引用范围。已知凭据消息排除，无关身份 padding 裁剪；不扩大其他联系人或上传完整历史。输入、公开模型输出、失败、哈希和 Agent Gold 均在仓库外私有目录（目录 0700、文件 0600）；每次公开 invoke 记无正文出站台账。模型 SDK 内部 HTTP 重试未逐次观察，不能把公开调用数说成实际 HTTP 请求数。

本轮评测不写业务记忆、旧五条认可资料或水位，不创建用户确认，不发送聊天消息，不操作远端 Git。来源消息日期、提取时间与事实实际期间分别保留；原话没有明确事件时间时写未知，不能用提取日期替代。
