## 已核实的问题

第一版匿名R正确补漏，但漏交嵌套evidence对象，整体失败。原来源核验V本来就负责按主张选择引用并判断支持；新增R要求再次生成逐来源quote，增加了重复输出责任。当前只证明一次公开响应漏字段，不能证明删除这个要求一定提高语义准确率。

## 建议的具体改变

保留E→R→原V的三阶段路径与同一接口责任。R继续返回changes与additions，替换／新增数组直接使用原14字段Fact，不再输出fact＋evidence包装。每条来源仍须是当前窗口合法UUID，包含目标消息；原V负责输出并校验原文片段与语义支持。V未成功核验的候选依旧不能自动采纳。

原候选索引、来源／目标／窗口／60候选预算、置信度不升、原风险与语用／时间阻塞、字面重复新增拒绝、失败不回退、独立台账全部保持。原14字段的严格seed门也保持；已知额外字段拒项照计，不顺带改另一个变量。只删除R中重复引用输出的要求，不修改其其他语义原则、原E／V提示或Gold。

原版1次失败、源码与公开输出完整保留，不修改或补造缺失引用。第二版先0API边界与独审，冻结后只允许一次新匿名R＋V检查，最多2次公开invoke。失败即停止，不再循环改提示；通过后才按原六窗捕获输入、开发、完整实际、最终留出的逐阶段门推进。

## 为什么需要决定

这改变了已冻结R的输出与证据职责，并超过原匿名阶段累计调用上限，需要修改原有限试验。仓库[工作流](agents/workflow.md)在决策模式列明“测试失败要求改变原定方案”和“实际实现需要超出当前 spec 或 ticket”；原版[提案](memory-candidate-revision-proposal-20261002.md)也规定失败后停止及单一冻结候选。用户在确认受阻原因后回复“同意”，此变更的决定已经收到，继续当前工作流，不重复询问普通实现或测试操作。

授权范围仅为上述一次第二版私有试验。仍须严格正确保留增加、没有新增坏auto或正确候选损失，才考虑发布；成功调用与结构通过不算准确率证明。
