# 工程工作流

修改仓库文件、运行项目、安装依赖、执行测试或准备部署时使用本文件。

## 代码与模块

- 核验实际能力时读取 `README.md`、配置、代码和测试；调研笔记保留在 `research/`，架构文档不能代替运行验证。
- Python 使用四空格和 PEP 8 命名：模块、函数和变量使用 `snake_case`，类使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。优先小型、带类型标注的函数；副作用放在明确的适配层。
- 按职责分离导入与规范化、联系人数据、记忆与检索、回复生成、后台任务、工具适配器及展示层。文件 I/O、模型调用、持久化和 UI 决策不得混在同一模块。

## 环境

- Python 产品代码使用 Conda 环境 `NotAlone`（Python 3.12）。开发、启动、安装依赖、运行 Python 命令或测试前先执行 `conda activate NotAlone`。
- `macos_sync_probe/` 是 ScreenCaptureKit 与 Vision 的原生 Swift 探针，只验证前台同步能力，不承载领域、存储或回复生成逻辑。

## 测试与验证

- 除非仓库记录了替代方案，Python 测试使用 `unittest`。测试夹具只能使用合成或匿名化数据。
- 覆盖范围随实现推进，至少包括正常导入、损坏文件、联系人隔离、来源与删除、空或模糊检索、已绑定前台会话的增量去重、未绑定或非前台窗口不采集，以及候选回复不会发送外部消息。
- 每次改动运行最小且相关的验证；报告数据处理影响、实际命令和剩余风险。只有端到端验证才能证明消息渠道集成可用。

## 部署

正式环境目标服务器为 `example.invalid`，不代表已经部署。schema、迁移、配置和部署脚本必须区分本地与正式环境，并保证同一套迁移可重复执行。实际连接、安装服务、传输数据或切换流量前，单独确认访问方式、数据范围、备份和回滚方案并完成运行时验证；仓库中不得保存密码、私钥、数据库凭据或其他秘密。

## Git

1. 新增或修改仓库文件后，在最小相关验证完成时自动创建本地提交；纯读取、分析或无文件变更时不提交。
2. 只提交当前任务产生或明确属于当前任务的变更，不捎带用户已有修改，不强行加入被忽略的调研、产物或私密数据。
3. 每个提交只处理一个主题。提交标题使用中文；正文用 `1、2、3、4` 形式列出 3-5 条改动、边界和真实验证结果。
4. `git push`、强制推送、创建远端分支或 Pull Request 前必须取得用户明确同意。
