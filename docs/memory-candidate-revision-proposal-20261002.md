# 记忆候选修订的有限试验提案

状态：用户已明确同意有限试验；私有原型已冻结并通过30项离线契约测试，首次匿名调用因缺少必需引用而失败。没有进入实际组、留出或正式提取路径。离线测试只证明接口与边界，不证明记忆准确性改善。

## 为什么需要单独决定

当前来源核验只能判断已经提交的候选，不能补出遗漏，也不允许改写主张。只改提示、档位、字段说明或内部输出组织没有证明同批实际聊天稳定改善。下一项拟检验：单独对照来源修订候选，能否找回遗漏、拆开污染主张并纠正错误标签，然后继续接受原来源核验。

这是候选形成流程的新责任，超出原任务“不增加模型阶段”的范围。用户已在阅读本提案后明确同意有限试验，规格据此记录范围变化。不能把它藏在原提取器里，混记两次模型调用的耗时或失败。[工作流](agents/workflow.md)、[ADR-027](../architecture/adr/027-memory-accuracy-evaluation-gate.md)要求先明确接口和范围。

## 拟试验的完整路径

1. 原提取器处理同一已确认联系人的有界消息窗口。
2. 首次提取成功后，候选修订器最多调用模型一次。即使首次成功返回空列表，也允许核对漏项；首次调用或结构失败时仍沿原失败路径，不冒充成功补救。
3. 修订器仅输出按原候选索引声明的替换、拆分或删除，以及新增候选。未声明改变的候选保留；不强制每条消息产出记忆。所有候选仍用原14个字段，不接收或改写既有记忆。
4. 应用计划前，验证索引唯一、范围与预算；应用后重跑原字段、来源和目标消息校验。最终候选不得超过原核验上限，超额或非法计划整体失败，不静默截断。
5. 原来源核验器逐条判断最终候选，不参与修订；原语用、风险、置信度和自动采纳规则继续执行。

新接口拟为 `CandidateRevisionRuntime.revise(window, candidates) -> CandidateRevisionPlan`。替换不得提高原置信度或删除原风险、语用及时间阻塞；修正内容不能顺带提高原候选的自动采纳权限。新增候选仍须有目标消息直接来源，不能把“模型建议”当成用户事实。

## 已冻结的原型约定

- 输入索引指向字段与来源检查后的候选，并保留其原始索引和每个拒项的原因。原型严格要求原14字段；旧解析器能容忍的额外字段、缺少可空键或类型转换不视为等价输入。这类损失单列计入，不能藏在漏提统计里。
- 每条新增或替换候选，所声明的每个来源都须有该消息的原文片段；仍须包含目标消息。此修订计划契约比原核验的引用要求更严格，新增结构失败和正确候选损失都计入评测，原核验规则不改。
- 未改候选保持原值；替换和拆分沿原索引保留风险与阻塞。修正错误转述标签时仍保留原待确认权限，不随标签修正升级自动采纳。
- 与任一原候选正文逐字相同的新增候选整体拒绝，删除后再新增也不例外，应通过原索引修订。这里只检查字面重复；同义改写是否绕开原风险仍由独立语义审计检查，引用结构不能证明语义新颖。
- 计划绑定当前窗口与候选的精确指纹，应用时再次检查。来源时间从当前消息重建；不接收草稿自带的来源时间，不允许跨联系人、跨窗口重放。

冻结源代码、提示、工具schema、首次失败与测试日志仅保存在仓库外私有目录。后续模型输出不得用于循环调提示；每阶段审计通过后才开始下一阶段。

## 失败、记录与数据

- 每次公开模型调用独立记录用量、耗时与结果；修订失败不能改记首次提取失败。修订失败时不写业务记忆、不推进水位，不回退成未经修订的自动采纳。
- 只用当前已授权的同一服务、同一联系人冻结窗口及匿名开发组。不增加供应商、完整历史上传、后台任务、写库或聊天发送能力。
- 原话、初提、修订和核验公开输出可追溯，保存在仓库外私有目录；内部思考不读取或保存。Agent参考答案不标为用户确认。
- 常见有候选窗口从提取、核验两次调用增为三次；既有写入裁决另算。额外等待和token尚未实测，必须随准确性一同报告。

## 判定是否有效

先用冻结的原候选检查修订前后，再运行完整自然路径；固定阶段分别使用原六窗口两次采样的原始候选，共12个实例、17条初提，不复制第一次输出代替第二次。这一阶段证明对捕获输入的效果，完整自然路径才检查重新提取时的重复表现。源文与参考答案不按新输出修改。全部额外输出、漏项、结构失败和正确候选损失计入。

实际组和匿名开发组须有可重复的严格完整契约收益，且不得新增错误自动采纳、牺牲原正确候选或靠大批转待确认取得表面改善。通过后冻结最终方案，才首次比较独立留出；留出不能继续用于调提示。未达标不发布默认路径。

实验分阶段推进，每阶段未达标便不启动后续：匿名兼容最多2次公开invoke；同六个冻结实际窗口原候选各两次，修订加核验最多24次；四个匿名开发窗口各两次完整路径最多24次；六个实际窗口各两次完整路径最多36次；最终四个留出窗口各两次比较原方案和新方案，最多40次。全部通过时上限126次公开invoke；SDK内部HTTP重试沿原配置，不当作已逐次观察。不会因本提案循环增加新的调参轮次。

拟授权范围仅为设计接口、私有原型与上述有限实验。正式路径的发布仍取决于真实复测、相关测试及两轴审阅；不包括全历史重提取、部署或远端Git。
