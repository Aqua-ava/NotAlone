## 1. 导入与关系资料采纳

按 [ADR-087](../adr/087-wechat-confirmed-contact-onboarding.md)，空目录新用户须先配置微信并确认首位联系人，或按 [ADR-089](../adr/089-all-private-wechat-sync-scope.md)明确授权全部私聊以按稳定身份加入联系人；已有联系人支持手动表达，完成本人和模型设置并明确选择后进入统一表达工作区，表达阶段不要求微信前台或开启同步。按 [ADR-084](../adr/084-topbar-contact-search.md)，桌面独立创建入口已退役，搜索只位于顶部选择器内；空目录引导添加微信联系人。按 ADR-079，自己的想法与补充聊天分开输入，通过“帮我表达／帮我想想”主动生成；生成前仍检查本次联系人资格，默认使用已授权的同联系人背景，也可关闭。手动确认限定当前 App 连接代际及具名助手请求，前台观察失败不撤销已明确选择的手动输入范围；重开须重新选择。设置重载和资料更新先通过原认证连接排空接纳的生成，失败保留连接；中断来历记为`configuration_reload`，退出App仍为`app_quit`，仅用户明确重试才能恢复。后台任务、续写和重试沿已保存的执行标识、输入版本与来源复验，不靠一次旧确认覆盖新联系人或已失效输入。此项实现和安装验收状态见[任务06](../../.scratch/standalone-app-delivery/issues/06-manual-input-first-release.md)。

首次连接微信按 [ADR-095](../adr/095-first-wechat-connection-and-account-grant.md)独立于同步宿主：完成本机本人初始化后，用户主动用只读状态检测已配置工具的候选账号，核对账号并一次确认全部现有及未来私聊与开启同步；此时尚未证明会话可读。服务端先复验账号，再检查会话可读性并再次核对账号，在同一事务保存本人渠道身份、范围和开关，再重载受控后端；无需先导入历史。普通刷新不探测或授权；授权前不读取会话列表，上游列表附带的摘要仅在确认后接收并丢弃，不保存或外发；响应丢失及重启失败可读回恢复，不重置授权起点或覆盖后续关闭决定。已有用户继续使用原范围与开关。无可用工具时真实显示未完成，不能把这一接入链当作未配置机器的工具初始化或独立交付证明。

```text
用户手动选择联系人
  -> 确认 owner 渠道身份；首次导入可显式初始化 owner
  -> 创建 source_document 和 background_task（type=import）
  -> 按固定模板创建 background_task_step
  -> Worker 依次执行 parse、normalize、extract_memory、index
  -> 进入 verifying，确定性检查来源、隔离、数量和索引一致性
  -> 验证通过后任务 succeeded
  -> 异步提取的 memory_candidate 通过结构、逐项来源及适用的条件、事件和版本检查后自动裁决（ADR-085）；不因额外语用、置信度或风险标签转为人工待办，人工保护与矛盾待定例外保持
  -> 用户可随时查看、修正、撤销或删除已采纳资料
```

规则：一次导入只属于一个联系人。检测到多位联系人混杂、说话人不能可靠区分或文件已损坏时，任务必须失败或要求拆分，不能静默归并。

OCR、转写与无界长历史分析仍是未来可选的后台专职处理；它们都向主流程返回带来源的结构化结果，不能直接写入已采纳资料。关系提取的证据契约始于 ADR-002，默认自动采纳现见 ADR-069／070／085；ADR-024 的版本化修正仍有效，其风险门与 ADR-036 的维度门仅用于显式历史协议；历史导入窗口和异步调度见 ADR-014。提取在后台异步执行：任务空闲时生成、跳过活跃或短暂会话、不与回复生成抢占额度。

按[ADR-046](../adr/046-source-bound-dimension-evidence.md)，Flow从实际同范围窗口装配可证明的定位与元数据，未知指代／转述保留未知。候选保存后，自动确认前在存储事务中再核完整窗口与活动来源；显式历史协议中来源变化或证明丢失改为待确认，不能先失效旧记忆；默认 automatic 按 ADR-085 终结本轮失败，保护旧人工待确认记录，并保留 ADR-081 的关系矛盾例外。正常默认采纳策略由ADR-070修订为逐项来源核验；旧显式协议仍按其冻结合同处理，候选 API 的来源当前状态不认证全局模型质量。

[ADR-047](../adr/047-bounded-source-semantic-proof.md)的同次V有界提案→完整规则核验→版本二依据合同已批准、实现并完成隔离验证；另按[ADR-060](../adr/060-author-arrival-quote-representation.md)增加可信单消息完整作者引句的有限包装分支，新合同与旧NULL／v1／v2精确配对，旧数据不回填或重解释。原V4入口、模型原评分、只降不升和未知归属边界保持；生产默认已由ADR-069改为完整记忆直接生成，显式历史任务保留grounded-v2，生产接线、隔离读写与真实模型质量分别验收，不把有限句法、包装形状或字段存在视为四类质量认证。

### 1.2 本人概览读取与底层管理

用户查看本人概览时读取 `GET /api/memories/owner/overview`。服务端只取 owner 锁，
不在该锁之后申请 contact 锁；只沿本人资料与实际来源 ID 核验原 SELF 身份、完整原
窗口和版本，再原子写入相同的无正文清单。本人集合修订沿canonical 062 的原事务触发器
递增。错误只返回安全错误码，空集合合法，HTTP 继续禁用缓存。

修正、删除和版本查看沿现有本人入口，旧历史只能通过真实当前叶管理。来源排队删除、
人工决定、原消息或引用世代变化先撤下投影；失败重试、同库租约恢复与迟到构建均须
重新核验当前权威资料。原来源联系人的定位文字、姓名或原话不写入本人响应；逐项
追溯只在用户已明确确认的原联系人范围进行，不自动切换或按当前关系猜原范围。
本人概览读取和刷新不调用模型，不自动创建偏好，也不改变回复检索或发送边界。

### 1.3 旧资料升级退役

用户于 2026-10-18 明确取消旧资料升级功能，不保留独立入口或记忆管理中的重跑操作。
日常记忆由导入和已授权同步后的自动提取、更新与整理负责，默认策略见[ADR-070](../adr/070-automatic-memory-maintenance.md)；移除升级功能不删除已保存的记忆。
历史升级任务不再领取或执行，旧比较及工作副本继续随来源、记忆或联系人删除而清理。

## 2. Mac 微信增量同步与前台定位

```text
用户明确设置同步范围（默认仅所选会话）
  -> 仅所选：添加微信联系人，列表默认不选，勾选后确认并创建绑定
  -> 全部私聊：一次确认当前微信账号的现有及以后新增私聊
  -> 总开关开启时周期发现私聊，核验稳定身份并幂等建立联系人和绑定
  -> 为新绑定保存 baseline，为既有绑定读取联系人独立 cursor
  -> 启动一个 CLI sessions --follow 全局会话事件流
  -> 只对已确认且发生变化的外部会话定位标识调用一次性 tail
  -> 按 owner_id + contact_id 校验、规范化并按稳定消息 ID 去重
  -> 写入 local_wechat_observation（mode=cli_background）和该联系人的 message
```

后台同步使用稳定外部会话定位标识，不使用展示名猜测联系人。按 [ADR-089](../adr/089-all-private-wechat-sync-scope.md)，默认仅所选会话沿用 ADR-030 的手动确认；全部私聊范围持久保存于当前 owner、渠道与账号内，周期发现当前及新增私聊并复用唯一有效渠道身份，否则创建独立联系人。同名不同账号保持分离，身份冲突不猜测，撤销或删除排除项不自动恢复。切回仅所选停止自动纳入，保留已有有效绑定；修改范围不切换总开关。v1 只处理 CLI 可见的一对一文字消息，不处理群聊或媒体正文。实现与实际验证见[规格](../../.scratch/all-private-sync/spec.md)。

每个已确认联系人独立保存 cursor。新绑定从 baseline 之后读取，已有 cursor 在应用重启后恢复；关闭 App 或手动关闭总开关时不运行读取进程，重新开启后把可检测的缺口交给后台补齐，并保留来源、状态和进度。全局 session 事件流不可用时，按绑定集合做有界一次性轮询，不启动每联系人长 Follow。

按 [ADR-083](../adr/083-automatic-sync-recovery.md)，补齐暂时失败后按绑定自动退避重试，旧补齐暂停在引擎重启后恢复，总开关关闭时仍停读。本机已删除或没有记录的会话等待新事件，并以五分钟低频重探防止漏事件，不在普通心跳反复读取。页面将补齐并入自动同步：进行中一行提示，完成后隐藏；持续异常和本机不可读历史折叠说明，不展示独立暂停／重试按钮或内部计数。

当前实现将桌面已选择的联系人登记为优先提示，只改变已确认绑定的读取顺序，不增加授权，也不依赖微信焦点或 OCR。后端保留最新提示，在每个绑定任务完成后重新调度，后台队列仍轮转前进；有待处理任务时立即继续，空闲时按三秒节奏检查。确认绑定和诊断入口也使用同一切片。每片的 CLI 命令共享三秒绝对截止时间，超时不采纳部分结果、不推进可靠游标，后续轮次重试。该预算不强行中断规范化或数据库事务，也不是发送至展示的延迟保证。桌面自动更新当前联系人最近成功检查时间；排队、读取、入库及失败指标未取得时保持空值，检查成功不能表述为消息必已追平。这是 ADR-023 既有只读与有界轮询决策的实现说明，不修订授权范围；验证见[修复规格](../../.scratch/sync-priority-latency/spec.md)。

前台 OCR 另行报告微信是否在前台和当前会话定位。按 ADR-049 的窗口边界、ADR-050 的单帧语义及 ADR-052 的顶部名称修订，每轮在本机内存分析当前唯一微信窗口的一帧，并仅 OCR 顶部名称；一轮结束后才调度下一轮。按[ADR-076](../adr/076-session-list-assisted-name-matching.md)，完整标题结合所有类型及授权状态的完整 CLI 名单核验：按[ADR-077](../adr/077-exact-session-name-before-edit-neighbors.md)，有效完整名称命中优先，同名集合仍含全部类型与授权状态；没有完整命中才作有限编辑消歧，低分仍需至少两个真实文字锚点，原始分数不变。独立尾部文字按[ADR-075](../adr/075-isolated-emoji-tail-text-evidence.md)取得同图几何证据，再与原始 OCR 的候选合并；不再局限 emoji。唯一私聊还须稳定标识唯一及同范围 active 绑定完整名未变。竞争、未知类型、截断、改名、名单达上限和超时均不猜测身份。通用匹配的新鲜成功仅解除单纯质量门，其他人工门保持。移动、缩放后重新定位，不要求用户手填坐标或复用人工 profile。进入助手或其他 App 后停止新视觉采集，返回前台微信后恢复；结果描述采集时点，同窗切换可能由下一轮更新。OCR 不参与后台消息写入，不读取正文，不切换或滚动微信；微信离开前台或 NotAlone 获得焦点不停止 CLI 后台同步。CLI 读取失败时不退回 OCR 正文，只显示后台同步不可用并重试。

同步得到的是原始消息，不是长期关系事实。后续模型据此产生 `memory_candidate`，低风险、达到门槛且落在**已放行维度**上的候选按 ADR-002、ADR-024、ADR-036 自动采纳写入 `confirmed_memory`；未放行维度、敏感或未知风险候选必须等待用户确认。

群聊前台按[ADR-055](../adr/055-group-foreground-pause.md)暂停联系人匹配及新生成，清除群标题预览、保留原私聊内容，已授权私聊后台同步继续。人数尾缀只作保守类型线索，不剥离后授予私聊身份；返回新鲜可靠的已有私聊绑定可恢复，之前其他原因开启的人工门保持。为发现返回私聊仍保留有界顶部复查，真实效果由人工可视验收确认。

按[ADR-056](../adr/056-foreground-busy-and-observation-budget.md)，认证观察接口明确返回409繁忙时，本轮撤销资格，待下一轮可靠绑定重新验证，不新增永久人工门；此前身份或真实超时人工门保持。UI／后端／探针预算分别为3.5／3.2／2.5秒，仍单轮在途、五秒新鲜度，超时不放行。

按 [ADR-088](../adr/088-normal-switch-one-second-optimization-target.md)，一秒是正常联系人切换的优化目标，不是首次启动、暂停后恢复及异常场景的统一硬门。分场景记录动作、观察、状态发布和界面更新，不能将状态发布当作屏幕绘制或抹去慢样本；现有 UI／HTTP 3.5 秒、后端 3.2 秒和原生 2.5 秒超时上限及身份安全规则保持。

### 2.1 同步连续性与用户补录

CLI 可以在用户切回已绑定联系人时补读本地数据库中水位之后的消息，但只在同步仍开启时进行。用户手动关闭同步期间不读取；重新开启后的可检测缺口由 ADR-025 在已确认范围内恢复，baseline 之前历史仍需单独导入。

- CLI 返回稳定消息 ID 时，历史导入与本地增量观察按该 ID 去重；同一规范消息可以保留多个来源引用。CLI 的 `from_me`/sender 字段用于保存联系人和我方消息的说话人。
- 每个联系人独立保存 `local_id` 或不透明 `cursor`；不能用一个全局水位覆盖多个联系人。
- 用户手动向上滚动不是自动同步触发条件；只有单独设计并明确开启的补录流程才处理该段历史。
- CLI 能提供的原始发送时间直接保留；缺失时间时保留未知状态，不以读取时间伪装为发生时间。

### 2.2 快捷键唤出与显式生成

后台同步开启后，CLI 在已确认绑定范围内接收并持久化文字增量；前台 OCR 独立通过 display name 等线索定位当前联系人。这条采集与入库路径不需要用户按快捷键。

用户需要回复建议时按下全局快捷键唤出唯一的助手窗口。系统通过已验证的前台定位或用户手动选择确认本次联系人，并恢复该联系人的内容；用户明确点击生成后，才从有效资料取得本次有界输入和上下文并创建候选回复任务。

按[ADR-078](../adr/078-request-driven-native-observation-worker.md)，后端按请求串行复用一个原生观察进程，保留系统模型加载状态；每轮仍重新执行前台、唯一窗口和新帧门禁，不保留上一轮图帧、文字或身份。JSONL传输有界且逐请求校验标识；超时、取消、权限熔断及关闭回收对应进程，下轮可重建；空闲最多60秒。变化通知取消正常两秒空等，在途变化合并一次后续立即复查，技术失败退避仍保留。正式开发流程真实切换、慢样本及测量边界见[验收记录](../../.scratch/foreground-worker-latency/validation.md)。

联系人身份先发布，讨论、候选与输入来源随后异步恢复；快速切换时合并短暂途经联系人的自动恢复请求，旧读取即使迟到也不得覆盖当前联系人。复用按联系人隔离的草稿和编辑缓存，已保存内容及来源删除状态仍须复验。按 ADR-057，正式观察确认的展示联系人切换不重建采集许可，也不触发全局同步状态重载；权限、目录及连接变化仍按原规则撤销许可。

- 快捷键、打开助手、观察成功、切换及恢复内容都不创建候选回复任务，也不触发、开启或替代自动同步。
- 按 ADR-052／076，顶部 display name 完整、结合完整 CLI 名单证明唯一私聊并核验已确认的 active 绑定时，可自动确认联系人；不要求用户每轮重复确认，但生成仍须明确操作。
- 若顶部名称质量不达标、CLI 元数据无法证明唯一私聊、绑定未确认，或所需消息仍在读取，系统应等待或明确提示同步状态，不得静默使用旧联系人或旧水位生成候选。
- 已验证的联系人切换只切换展示，不取消原候选回复任务。绑定失效、匹配不唯一或读取未就绪时暂停接受新的生成，并依原授权/来源规则处理已有请求；识别失败本身不取消原来范围有效的任务。
- 系统不得用消息正文或模型推断选择联系人，也不得把未归属或 CLI 校验失败的消息写入消息层或回复上下文。
- 按 ADR-087／089，新联系人只从真实微信会话加入，可逐会话确认或在全部私聊授权下按稳定身份建联，文件导入只补充已有联系人；ADR-065 的手工输入与单联系人导入继续适用于已有联系人，其无需微信即可空目录首用的旧承诺已退役。原自动渠道目标保留后续验收；其识别与后台同步门槛不因手动路径开放而降低。

### 2.3 按联系人保留内容与任务

一个助手窗口按已确认联系人分别保留当前助手会话、输入和候选编辑；自动切换到另一位联系人后，切回恢复原内容及任务状态。有草稿或任务不构成额外的切换确认门，重复识别同一联系人不重置内容。

识别失败时保留原内容和已有任务，标明内容所属联系人及“当前联系人未确认”；用户明确选择前不接受新生成。进入助手导致的正常定位暂停仍保留最后确认联系人，不冒充识别成功或失效。

每次生成固定属于发起时已确认的联系人、助手会话、请求和输入版本，使用当时取得的有界上下文。不同联系人可各保留显式发起的排队/生成作业；新消息只提示，不自动替换或重启。完成结果仅回到原会话，切回只读恢复；删除、撤销、来源失效及退出中断优先于内容保留。具体行为和验证接缝见[正式规格](../../.scratch/foreground-contact-follow/spec.md)。

## 3. 候选回复生成

```text
用户通过已验证的前台会话绑定或手动选择确认本次联系人
  -> 唤出助手并恢复该联系人的内容，CLI 独立同步已授权消息
  -> 用户明确点击生成操作
  -> display name 未解析或 CLI 尚未完成时等待或提示；绑定或识别异常时要求用户确认
  -> 确定性代码执行联系人/授权校验
  -> 执行确定性请求风险预检并展示核实提醒
  -> 按用户点击的帮我表达／帮我想想固定本次动作，后者允许空想法
  -> 结合用户输入、补充聊天、近期对话、相关记忆及可用 Skill 精简目录；建议不冒充确认方向
  -> 仅在明确生成操作下固定本次联系人、助手会话、输入版本及有界上下文并接受候选任务
  -> LangChain create_agent 在有界循环中按需调用受控 Tool，不创建模型 Todo 或步骤进度（ADR-091）
  -> 按需调用已接入的受控 Skill 与联系人检索 Tool（ADR-090）；当前不接入时间、日历或网络搜索工具（ADR-092）
  -> 根据 Tool 结果继续查询，不使用 Todo 表达多步骤进度
  -> 在五轨上下文内返回 1-3 条带依据引用的 reply_candidate，或返回澄清需求
  -> 校验输出结构、引用与禁止动作并持久化本次运行轨迹
  -> UI 显示候选或澄清问题，以及本次实际使用的上下文范围
  -> 用户选择、编辑、手动发送
```

按 [ADR-080](../adr/080-unified-memory-list-and-retired-exclusion.md)，修改资料仍区分“纠正错误”和“记录变化”以保留来历，但所有失效和过期条目都在统一记忆列表划线显示，不再参与生成。取消独立版本历史模块。资格覆盖历史导航、概览、L2/L3、旧候选、助手讨论和恢复，并在生成前后及提交时复验；旧候选可回看但失效依据需重新生成。来源删除及纠错防复活规则保持。

按 [ADR-068](../adr/068-direct-reply-candidates-with-user-selection.md)，候选生成后不追加模型语义复核；结构、范围、来源与引用检查继续由程序执行，候选的最终表达由用户选择和修改。来源引用有效不等于语义已核验。记忆入库、L2/L3 整理核验及离线质量资格独立保持。

回复运行时固定为确定性外壳 `validate_scope -> assess_request_risk -> assemble_initial_context -> create_agent bounded Tool loop -> validate_agent_output -> persist_trace -> return_result`。内部循环使用 LangChain `create_agent`，并接受 LangGraph 作为底层 runtime；v1 不直接手写自定义 `StateGraph`。若以后出现明确的暂停恢复或复杂固定流程，可以把整个 `create_agent` 作为自定义图中的节点。完整边界见 ADR-006 与 ADR-009 及现行运行时装配；历史草案见 `../drafts/agent-runtime.md`，不作为现行约束。

每次生成由调用方提供联系人范围内的幂等 `request_key`。同键同输入的已完成请求直接返回原候选；同键不同输入明确报冲突；有效租约内正在执行时返回“处理中”；失败或租约过期后可以复用同一请求身份重试，不得产生第二份请求或重复候选。

用户可以显式选择一条历史 `reply_candidate` 继续生成；系统为此创建新的 `reply_request`，并记录 `continued_from_candidate_id`。没有该显式选择时，不得按时间自动取“上一条”或“最新未发送”候选。前序候选必须与当前已验证的 `owner_id + contact_id` 一致。

按 ADR-048，记忆修正、替代、否决或时效变化与真实来源删除分开处理。仍有合法
来源的已完成回复及用户编辑版本可回看、选择和明确携入新会话；`basis_changes`
只投影内部依据标识、类型和变化原因，原依据正文与时间仍来自当时的快照。旧快照
缺少版本或时间时保持未知，不用当前资料补造旧证明。实际来源或记忆删除仍清除
受影响正文、编辑版本、携入输入和恢复副本，历史模式不能成为留存例外。

明确继续和退出后明确重试沿既有回复入口重新检索当前依据，保留服务器保存的
当前意图、用户编辑和选定表达参考；旧候选带变化状态供表达参考，不能直接当作
本次新事实。历史读取仅核验原来源仍真实有效；模型调用和提交本次新结果继续
复验当前资料、完整来源与当前输入。候选 writer 在同一 owner 事务锁内核验历史
依据状态摘要、本次记忆正文／版本／来源／时间及输入身份后保存，人工修正和
删除使用同一锁；变化发生在保存前须拒绝迟到结果，可靠保存后才发生变化则保留
完成正文并显示提示。读取、刷新、变化提示和失败恢复均不自动生成或发送消息。

原 `/api/reply/generate` 的 `continued_from_candidate_id` 也遵循同一边界：新领取
或失败重试时只在新请求中捕获本次历史依据摘要，模型前和原候选 writer 提交时
复验摘要与真实来源。旧候选引用带无正文变化提示，本次允许背景时重新检索当前
资料；重放不重建旧证明，也不向旧父请求回填版本摘要。

v1 的检索应可解释：先用联系人过滤，再用时间、关键词、资料类型、采纳状态和显式有效期排序。每个候选应能回看"本次用了哪些近期消息和已采纳资料"，但不必把完整历史给模型。

按 [ADR-079](../adr/079-unified-expression-workspace.md)，统一工作区以显式动作区分表达辅助与表达建议：前者保持用户想法原意，后者允许无预设方向并直接生成可选择的候选及理由，不把建议记录为已确认立场。用户不必先选目标消息或确认模型方向。默认在已确认联系人范围内组装最近聊天与相关资料，可关闭背景、排除不适用消息或补充聊天；本次材料调整不修改或删除权威来源。生成结果需能回看实际使用的依据。

旧方向探索接口为历史和内部兼容保留，沿其原任务、版本、来源及 Skill 校验继续执行；新工作区不调用“先确认再生成”的旧交互。ADR-074 的自动 Skill 相关性选择、零或一个版本、明确场景权限及来源失效约束继续有效。新消息只提示，由用户明确点击更新候选。

消息依据的说话人必须从规范消息经检索、近期上下文、历史 Tool、保存和恢复一直保留到模型可见正文，使用 `owner/contact/system/unknown` 区分本人、联系人、渠道系统消息和未知作者。资料类型与 API 的 `user/assistant` 不替代私聊作者；渠道系统消息及聊天中的指令仍为被引用资料。候选始终由本人向当前联系人表达，本人连续发言或最后一句是本人都不改变该主体，也不自动选择更早的联系人消息作为未回复目标。已知时间按早到晚呈现，缺失或相同时间不伪造精确先后。发送方变化使旧准备依据失效；旧准备格式需要重新准备，缺身份的旧完成结果只保留未知，不倒填或宣称修复。未知归属不得被猜成联系人，仅在本次建议确实依赖该归属时要求补充。

记忆的来源聊天时间、保存时间与有效期随检索结果进入回复上下文和模型输入，
也进入本次依据快照供用户回看；生成前后重新核对时间投影。历史快照缺少新时间
字段时显示未知，不以当前来源状态倒填。来源日期表示原话记载时间，已有生效期
只说明当前可引用，两者均不能独自证明旧状态今天仍成立。

旧方向探索的兼容界面使用一个“补充你的想法或要求”入口，用户不必先区分背景、理解纠正和表达要求；模型按语义分别用于理解情境与约束本次表达。补充本身不确认方向、不触发生成、不静默成为长期偏好。旧纠正与要求在界面合并展示，编辑时原子替换，避免隐藏旧内容继续生效；统一补充可能包含来源派生背景，来源失效后按依赖清理并防止联系人切换时恢复。

### 3.0 上下文组装层级（v1）

生成请求的上下文按"五轨"组装，历史本身永不进入提示词，每轨都只取少量：

1. **轨一 硬规则（代码层，必加载）**：不自动发送、联系人隔离、高风险标记。确定性代码规则，不是记忆提示词（见 3.4）。
2. **轨二 回复 Skill（按需加载）**：只加载本次选中的一个不可变版本，作为可撤销的策略参考，不作为联系人事实，不覆盖当前请求、近期对话或硬规则（见 3.7）。
3. **轨三 自动记忆基线**：上下文模块按当前正文对有效联系人与本人记忆做确定性中文词法评分，低于 0.15 不注入；联系人记忆最多 5 条且合计不超过 600 字符，本人记忆最多 3 条且合计不超过 240 字符，两类预算独立。联系人记忆目录只提供 `memory_revision` 复验，不参与候选过滤，也不作为新的事实或固定全量提示词。
4. **轨四 按需补查**：模型可在运行预算内分别调用消息检索和确认记忆检索 Tool，补充轨三未覆盖的资料；结果仍按 3.1 排序并经应用层校验。
5. **轨五 近期对话（最强事实依据）**：该联系人的近期 `message`，是当前语境的最直接依据。

组装原则：冲突时硬规则和用户当前明确要求优先，近期对话压过旧记忆，Skill 只指导回复方式而不改变事实。超预算时移除低分补查结果和低分自动记忆基线；已选 Skill 仅保留完成当前策略所需的最小正文。记忆是辅助回忆层，不是规则——安全规则只放轨一代码层，不放记忆或 Skill 正文。

按 [ADR-092](../adr/092-defer-time-calendar-web-tools.md)，当前回复不提供时间、日历和网络搜索工具。若未来另行采纳，其结果只能作为有来源的本次请求证据，不自动写入长期关系资料；日历仅可读取明确授权范围，网络查询不默认携带聊天正文、联系人身份或关系资料。未来方案仍须记录实际调用、用途与引用，不能将未查询的信息写成已核实结果。已有时间戳与有效期处理保持。

#### 持续聊天与滑动上下文

同一联系人的聊天是长期连续的消息线程，不因生成一次候选而创建新的聊天窗口。每次生成仍创建独立的 `reply_request` 和上下文快照，用于复现本次实际使用的消息、资料、Skill 与规则；这项审计边界不等于切断后续聊天上下文。

按 [ADR-042](../adr/042-assistant-session-context-boundary.md)，持续助手会话的产品讨论与单次 Agent 运行消息分开。第一版助手讨论不自动摘要或静默截断：接近预算提示，达到上限保留查看并要求显式新开；仅用户选中的候选可携入新会话。讨论、候选与修改痕迹属于可删除的产品记录，不能由 checkpoint 或摘要代替。该功能已按[规格](../../.scratch/assistant-session-context/spec.md)接入数据库版助手会话服务与 HTTP 入口，并提供桌面历史会话列表、选择恢复及生成操作，见[后端装配](../../backend/src/notalone/server/app.py)和[桌面会话控制器](../../desktop/src/main/reply/session.ts)；此实现状态不表示全部规格用例或真实 App 验收完成。

按 [ADR-091](../adr/091-retire-runtime-todos-and-auto-summary.md)，单次运行也不增加模型任务计划或自动过程摘要；受控查询循环和逐轮输入预算检查保持，不压缩运行消息或助手讨论以绕过上限。既有检索材料仍按独立预算选取。来源或联系人删除必须使所有相关派生内容、摘要和 checkpoint 失效，恢复前重新核验范围、授权及删除状态。具体模型计量、提醒阈值和输出预留在实现时验证，不按固定时间重开助手会话。

按 [ADR-045](../adr/045-explicit-estimated-ecnu-input-budget.md)，已核实的 ECNU 配置允许明确标注的完整输入估算，并另计实际输出预留与安全余量。初始和后续调用均重新检查；计量器、模型实例、接收地址或配置不匹配时拒绝。估算超限或服务端实际超长均提示显式新开、保留历史，不自动摘要或截断；估算不能被标成供应商精确计数或已证明上界。该接入修正已通过生产 SDK 离线与公开 HTTP／桌面桥合成验证，真实 App 与模型验收单独记录。

按 [ADR-090](../adr/090-bounded-runtime-history-retrieval.md)，Runtime 可在应用层固定的本次联系人范围与预算内按需搜索历史和读取邻近消息，正式替代 ADR-012 的初期动态检索禁令。工作区关闭关系语境或存在排除消息时，按现行资格检查停用历史补查；工具只读已保存且当前合法的资料，不直接读取微信、扩大同步授权或执行写入。Context 的初始组装、Retrieval 的范围及来源复验、Store 的保存职责保持，其他外部工具不因本决定获得权限。

### 3.1 检索排序规则（v1）

联系人过滤后，按以下优先级降序排序；键相同则落到下一键比较：

1. **采纳状态**：`confirmed_memory` 优先于 `memory_candidate`；`pending` 候选不进入已确认记忆集合，只能在独立预算内以 `pending_candidate` 证据类型带「未确认」标注作为参考，不得表述为确定事实；用户确认后转为已确认记忆，否决后永久不再参与（见 ADR-035）。
2. **显式有效期**：`valid_at <= now <= invalid_at` 的资料优先；无有效期的资料视为长期有效，排在未过期之后、已过期之前。
3. **时间**：资料创建或消息发送时间更近者优先。
4. **资料类型**：共同事实与禁忌优先于偏好与一般备注（分类见 `domain-data.md`）。
5. **关键词**：与当前消息的文本重叠或语义相关度更高者优先。

### 3.2 上下文预算（v1，写入生成接口入参约束）

生成请求的上下文是硬性预算，超出即截断，不允许把完整历史塞入提示词：

- **近期消息**：最多 50 条，且合计不超过 8k token；超出按时间取最近部分。
- **已确认资料**：最多 20 条。
- **自动记忆基线**：按当前正文词法召回，联系人记忆最多 5 条且合计 ≤600 字符，本人记忆最多 3 条且合计 ≤240 字符，两类独立计费；阈值与预算为模块常量，标定结果见 [`../../docs/memory-recall-evaluation-baseline.md`](../../docs/memory-recall-evaluation-baseline.md)。
- **待确认候选基线**：同一词法评分与 0.15 阈值，最多 3 条且合计 ≤300 字符，与上面两类独立计费；只作为带「未确认」标注的参考进入上下文，未确认预算尚未经正式评测标定（见 ADR-035）。
- **回复 Skill**：最多 1 个不可变版本；目录摘要与完整正文分别计入选择调用和生成调用预算。
- **截断策略**：按 3.1 的排序从队尾截断，并在生成接口返回本次实际使用的引用清单，用户可回看"用了哪些、丢了哪些"。

模型/Tool 调用次数、单次返回数量、总 token、超时和重试次数属于可配置运行预算，具体初始值在实现与合成评估时确定。联系人隔离、删除状态、只读 Tool 和禁止外部发送不属于可调预算。

### 3.4 高风险内容交互

高风险内容（转账、验证码、地址、借款、承诺、见面安排、关系冲突）由独立适配层的确定性规则标记，不混入生成提示词。命中时仍可检索并生成，但生成前必须展示核实提醒；判定规则放独立模块，便于更新和测试。

风险字段在生成环节的核实提醒要求保留。敏感或未知风险阻塞采纳并进入 pending 是 ADR-024 的显式历史协议；默认 automatic 按 ADR-085 不因风险标签本身转入 pending，仍须通过来源及适用检查，并保留 ADR-081 的关系矛盾待定例外。安全保险仍在发送环节：候选回复带依据引用，由用户选择并手动发送。

### 3.5 引用展示契约

每条候选回复必须携带依据引用：`retrieval_segment`/`source_span` 标识、入选原因、排序分数与状态（消息/已采纳资料/未确认候选），并单独记录实际使用的 `skill_version_id` 与选择原因。`pending_candidate` 引用必须同时展示「未确认」标注，不能与已确认资料并列呈现。用户可回看"为什么用了这些上下文和套路"，便于发现误导入、过期资料或不合适的策略。

桌面首版在一组候选下方提供共享的「本次参考」只读入口，默认收起，摘要显示实际材料分类与数量。展开后区分聊天、关系／本人资料、长期表达偏好、回复方法和本次输入；主题目录与实际读取正文分开，来源与时间可继续展开，技术诊断保持折叠。这里只说明材料曾提供给模型，不宣称每项均被每条候选引用。切换联系人、请求或历史会话后恢复收起并重新核验归属，不提供本轮调整按钮。历史快照缺失的信息保持未知，不用当前资料补填。

### 3.6 主动表达样本退役

按[ADR-082](../adr/082-retire-explicit-style-samples.md)，不再提供主动收藏表达样本、样本管理或生成时样本参考。候选编辑、复制、继续与携入仍是普通助手操作，不产生风格收藏或长期偏好。用户明确管理的长期表达偏好继续独立生效，本次明确意图优先。

### 3.7 回复 Skill 的渐进式加载

Skill 采用 progressive disclosure：LangChain `create_agent` 组合 Deep Agents `SkillsMiddleware`，middleware 只从当前 owner/contact 的受控 discovery backend 发现已启用版本，并通过 NotAlone 定制提示词把 `name + description` 等精简目录放入模型上下文。模型需要完整策略时调用受控只读 `read_file(file_path, offset=0, limit=1000)`；该读取能力只接受目录中已列出的 `SKILL.md` 或允许的 Skill 辅助资源相对路径，经 `SkillPort` 校验范围、状态、不可变版本和目录修订后返回内容，不是通用文件系统读取。定制提示词不展示 `allowed-tools`，不允许脚本执行，也不允许外部 URL 下载。

用户显式选择 Skill 时，应用层通过同一个 `SkillPort` 校验并预加载，不要求模型再次调用 `read_file`。按 [ADR-074](../adr/074-automatic-conversation-skill-loading.md)，正常回复入口自动判断并按需加载；可以不加载 Skill，UI 仅展示当前结果实际使用的名称和版本或通用流程，不提供手选控件。旧显式版本 API 保留管理、历史兼容与内部固定版本用途。每次最多使用一个不可变版本；Skill 及其辅助资源只提供经校验的策略文本或静态素材，其内容不能注册 Tool、MCP、Shell、文件写入、子 Agent 或外部资源访问。

Skill 库管理不属于 Agent Loop。按 [ADR-096](../adr/096-directory-backed-reply-skills.md)，用户可明确导入或把本地包放入本人管理目录；管理刷新和每轮运行前自动发现新增和修改，正文及资源保存为目录文件，数据库仅管理必要业务状态；安装、更新、启用和停用先校验并固化不可变版本，候选回复运行时只读取已经启用的版本。同一 owner 的 Skill 名称唯一，库使用 owner 级 `skill_library_revision`；任一 Skill 导入、更新、启用、禁用或删除时都递增该 revision，并使该 owner 所有联系人范围的旧目录失效。Skill 目录缓存仍绑定 `owner_id + contact_id + skill_library_revision`；任一项变化时，下一轮运行先清除旧目录、旧 Skill Tool 结果、辅助资源结果和包含旧 Skill 正文的摘要，或使用新的运行状态。采用 `SkillsMiddleware` 不等于采用完整 `create_deep_agent`，候选回复不启用 Deep Agents 的通用文件系统、Shell、Subagent 或长期任务 harness。

消息检索和确认记忆检索 Tool 的模型参数只包含查询意图、limit 和允许的时间范围；已验证的 `owner_id + contact_id` 通过 runtime context 注入并传给 `RetrievalPort`，不能由模型提供或修改。返回携带引用标识、采纳状态、有效期、排序分数与检索器版本，用于复现与审计“本次为何返回这些结果”。

高风险内容，包括转账、验证码、地址、借款、承诺、见面安排和关系冲突，必须提醒用户自行核实；系统既不能自动发送，也不能替用户做最终决定。

### 3.8 统一表达工作区

按 [ADR-079](../adr/079-unified-expression-workspace.md)，助手只提供一个联系人工作区。主输入接受想法、方向或草稿；“帮我表达”要求有输入，“帮我想想”允许为空。旧改写／回应／主动联系入口和消息来源切换不再出现在主流程。

默认参考同联系人的最近对话和相关关系资料，不要求选消息。最近聊天支持查看、刷新及本次排除；用户补充聊天文字单独输入，不混作本人想法。没有可用背景时明确提示不足。每次直接展示 1–3 条可编辑候选及简短理由，保持查看依据、复制、版本编辑和连续修改，最终由用户手动发送。

同一生成入口以 `rewrite_draft` 的 `input_kind=workspace` 和 `workspace_action=express|suggest` 明确语义。suggest 可以没有 draft_text；context_text 与 excluded_message_ids 独立保存、恢复并沿来源依赖清理。用户点击后原子固定动作和输入，旧保存合同继续可读，不用虚假原句或确认方向补齐。新消息不自动重生成或覆盖编辑，补充与建议不自动升级为长期资料。

已有快捷键只能唤出同一工作区，不根据输入是否为空替用户触发生成或选择立场。旧接口与历史版本继续保留原来源核验，历史通过不作为新工作区验收结论。

### 3.9 候选回复浮动窗口

用户按下全局快捷键后，NotAlone 在当前微信窗口旁显示独立的候选回复浮动窗口，不遮挡聊天内容。窗口至少展示已确认联系人、上下文状态、两个生成动作和 1-3 条带理由的候选回复。

- 窗口使用同一工作区及“帮我表达／帮我想想”两个动作；前者要求已有想法，后者允许空输入，点击才创建生成任务。
- 不要求先选择消息或确认方向；模型建议保持未采纳状态，用户选择、修改并亲自发送。
- 每条候选都可以在浮动窗口内编辑和复制，并能展开查看本次使用的依据；窗口不得写入微信输入框或发送消息。
- 候选卡直接复制当前显示的已保存版本，不要求先勾选候选或版本；未保存编辑、来源失效或版本核对失败时仍阻止复制。历史版本通过“上一版／下一版”按钮回看，切换只改变显示，不删除版本或自动产生新的候选任务。
- 携入新助手会话由候选卡上的“用这组回复新开会话”明确发起，使用该卡当前显示的已保存版本。携入身份校验及使用痕迹只服务于这次携入动作；复制和回看均不得自动选择后续生成基础，也不表示已发送。
- 按 ADR-091，不增加模型运行计划及步骤进度界面；现有生成状态与确定性后台任务进度保持，不创建 `write_todos` 工具或将计划写成业务事实。
- 初次回复、替换及退出后重试的准备支持可选异步 HTTP 等待：接纳后返回无正文任务身份，后续短请求只查询原任务；准备完成后才沿原生成入口执行。通用网络超时不再代表整段准备期限，任务另有协作式期限与取消守卫；不进入记忆 Worker、不自动恢复或调用模型。并发、失败重试、原输入与来源复验继续生效，协议及验收范围见[异步准备规格](../../.scratch/async-reply-preparation/spec.md)。
- 本次生成在取得有效准备回执时固定所属输入和有界上下文。迁移 058 将固定材料保存于所属助手轮次；历史补查限于准备时最近 500 条有效来源消息 ID 加初始消息证据 ID，不复制全量历史。此后新消息不得进入初始材料或后续补查；窗口提示上下文更新，由用户明确重新生成。来源删除、授权撤销、Skill 及版本失效检查仍优先，输入正文失效时同步清空固定材料。
- 浮动窗口取得键盘焦点后，微信不再是前台应用，前台定位暂停，保留最后确认的联系人和内容；已确认绑定的 CLI 后台同步及范围仍有效的生成继续。用户返回微信后重新观察，唯一已验证绑定自动切换展示，失败则标记未确认并阻止新生成（ADR-050）。
- 浮动窗口关闭后不改变后台同步开关；解绑、暂停同步或联系人校验失败时，不得继续使用旧窗口为该会话生成候选。

### 3.10 关系分析任务边界（未来）

分析数月聊天、整理关系变化时间线或跨大量证据复核矛盾，不属于候选回复任务，也不能因用户打开聊天窗口或按下候选回复快捷键而自动开始。未来若提供关系分析任务，必须由用户从独立入口主动创建，明确联系人、时间范围和资料范围，并在独立界面展示进度与报告。

第一阶段不实现关系分析任务，也不为其预先引入完整 Deep Agents harness；候选回复使用独立的 `SkillsMiddleware` 不改变这条边界。只有明确功能证明需要动态规划、大量中间材料、跨进程恢复或多个专业子 Agent 时，才比较普通 Worker、直接 LangGraph 与完整 Deep Agents；无论采用何种 runtime，结果都不能自动发送到外部聊天渠道。

## 4. 候选编辑与表达偏好

按[ADR-082](../adr/082-retire-explicit-style-samples.md)，候选文字只用于当前编辑、复制、继续与经用户选择的携入；不再另存为可检索的表达样本。长期表达偏好使用独立的明确创建、查看、修正和删除流程，不能由候选选择或复制自动学习。旧样本及受其影响的冻结、携入和恢复资料按退役迁移清理，不能改名为偏好或事实继续使用。历史样本功能的测试记录仅证明当时版本，不证明退役实现已验收。

授权同步可以在已确认的绑定会话中，通过本地微信 CLI 的结构化 `from_me` 消息事件正向观察用户发出的消息；该观察可以作为后续“已观察到发送”的证据。但同步暂停、CLI 不可用或消息未被本地数据库观察到时，系统没有发送回执，因此“未观察到”只能记为未知，不能推断用户没有发送。无论是否观察到发送，都不能把生成候选或复制动作自动归纳为长期偏好。

## 5. 删除与修正

```text
用户删除来源、关系资料或联系人
  -> 创建 background_task（type=delete，scope 限定 account/contact/source）
  -> 计算消息、候选、确认资料、索引和缓存的影响范围
  -> 执行级联删除或失效
  -> 重新建立受影响联系人的检索索引
  -> 展示完成状态与未能删除的原因
```

按 [ADR-094](../adr/094-ledger-erasure-by-deletion-scope.md)，删除单份来源保留最小无正文调用记录；删除整个联系人或账户资料须清除对应范围调用记录及可恢复副本，并复核关联引用、并发与晚到写入。当前底层台账清理和整体产品接线尚待完成，不据流程描述宣布已交付。

修正关系资料应保留修正时间和原始来源关联，但不需要长期保存已被用户要求删除的私密正文。删除和重试过程应显示进度、失败原因和结果，不能在后台静默失败。

删除来源时，先移除该来源对规范化 `message` 的引用；消息仍有其他有效来源时保留，所有来源引用都删除后才清除消息及仅由它支持的派生资料。用户若想保留某条内容，必须先执行"另存为不依赖该来源的手动资料"（切断与原来源依赖），再删除来源。删除流程须区分两种关系：同一规范消息的多个有效来源引用互为替代；按 ADR-063 保存的正文必需消息则是合取依赖，任一必需消息失去全部有效来源，就必须清除依赖正文及其派生副本，不能等待所有证据全部删除。旧记录沿原依赖合同处理，独立手动资料不受无关来源删除影响。

## 6. 后台任务边界

后台任务只处理用户已经触发的资料：导入、解析、规范化、索引、候选提取、删除和重建。已启用的 CLI 后台同步可在用户已确认绑定的联系人范围内运行增量观察，前台定位不作为后台写入门禁；授权范围外的会话不在正文读取范围内；全部私聊模式先在已授权账号范围内核验稳定身份并建立有效绑定，再进入相同的正文读取路径。关系提取按 ADR-002 和 ADR-014 的调度策略异步执行：任务空闲时生成、跳过活跃或短暂会话、不与回复生成抢占额度。v1 可使用同一应用内的任务表和 worker；只有并发量、可靠重试或部署规模成为真实问题时，再引入独立队列和 worker 服务。

`jobs` 的运行方式固定为“任务记录 + 步骤记录 + Worker”，完整约束见 ADR-007：

```text
API 创建 background_task 与固定 background_task_step
  -> Worker 使用租约领取下一条可执行步骤
  -> 普通处理器执行解析、规范化、索引或校验
  -> 只有语义步骤经 ModelPort 调用 AI
  -> Worker 原子更新步骤状态和业务引用
  -> 全部业务步骤完成后进入 verifying
  -> 确定性验证通过后标记 succeeded
```

- v1 不先引入 Airflow、Temporal 或独立消息队列；Worker 可以是同一代码库、同一云服务器上的独立 Python 进程，PostgreSQL 同时承担权威任务状态与领取协调。
- 导入、级联删除和重建索引可拆为步骤；一次候选回复仍由基于 LangGraph runtime 的 `create_agent` 同步执行，观察消息按 ADR-041 合并为联系人级记忆任务，不为每条消息创建步骤清单。
- `background_task_step` 是持久化工作记录，不是 Agent prompt 或模型 Todo；步骤及依赖由代码模板确定。
- AI 只返回某个语义步骤的结构化结果。Worker 和确定性校验器拥有状态迁移权，AI 不得领取任务、修改状态或宣布成功。
- 同一联系人任务串行、不同联系人可并行；暂时错误最多自动重试 3 次，成功步骤不重做，Worker 租约过期后可接管。任务元数据终态保留 90 天，不记录聊天正文或模型完整输入输出。

不在 v1 实现：读取其他 App、未经确认同步所有会话、在同步开关关闭时读取、自动切换或滚动微信会话、自动发送、无预算的开放式自治循环或为短文本回复强行调用多 Agent。

按 ADR-041，本地后端在已确认绑定的观察消息提交后创建或重排同一联系人 observation 任务，
再唤醒现有 TaskHost；观察和任务分属两个事务，调度失败不回滚消息、来源或游标。
原观察上的排队时间戳与任务重排原子提交，批次重放不重开终态。运行中新批次保留下一轮，
失败轮次仅在存在仍有效的新批次或显式恢复时继续；不扫描重启前旧队列。
事件仅携带非正文元数据，排队及执行均复验联系人、原绑定与来源；撤销、删除和关闭
不因晚事件重新授权。继承前台回复优先、全局锁等待、步骤租约及有限停机协议。

记忆页面默认展示处理状态，仍保留“对方／我／待确认”三个入口。进度来自已提交的处理批次及其实际目标范围；处理聊天数与产生记忆数分别展示，缺少可信统计时明确未知，不用步骤权重推算聊天处理百分比或剩余时间。提取与背景整理分别显示状态，来源、各任务及错误原因收在详情里。

状态读取结合持久任务与执行租约，区分等待、正在处理、已完成、已中断、失败和主动停止。重启后没有执行者的未完成任务不能继续显示正在处理；读取、刷新和打开页面不启动模型。用户明确点击继续后才恢复未完成工作；已取消任务以重新处理入口区分，恢复前复验归属、来源、删除状态及执行租约。恢复不扩大原任务来源范围，不重新开启同步或已停止的背景整理，不绕过人工修正和删除保护。此项保留 ADR-041 的不扫描旧队列约束，具体实现和验证见[记忆处理进度规格](../../.scratch/memory-processing-progress/spec.md)。
