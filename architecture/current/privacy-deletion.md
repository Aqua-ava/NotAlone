## 默认原则

明确方法或整个Skill停用是独立的用户范围决定，默认不保存反馈原话或候选正文。13候选将执行投影绑定到真实允许正文，并在候选提交、继续和恢复时复验；政策变化保留合法历史和用户编辑，来源删除仍擦除受影响策略、使用和恢复副本。无正文决定的撤销不能复活已删策略；实际验证范围见[13集成记录](../../.scratch/memory-skill-integration-preparation/frontier-13-validation.md)。

- 手动当前文字只在用户明确选择联系人后处理；生成前不发模型请求，也不静默保存为长期记忆或规范消息。显式生成后的文字与表达方向属于助手讨论及候选依据，可随助手会话删除。明确的历史文件导入另走单联系人预览、确认、来源与删除流程。手动确认不授予微信读取或发送权限，未完成渠道不作为首版使用前提（ADR-065）。

- 聊天、截图、语音、关系资料均为敏感数据。独立桌面版的后台、规范化文字、关系资料、任务状态和备份按 [ADR-061](../adr/061-standalone-local-app-onboarding-and-updates.md)保存在本机，由 PostgreSQL 作为权威业务库；不因独立分发而新增云端资料存储或扩大模型出站范围。
- 按 [ADR-066](../adr/066-in-place-schema-updates-and-database-reuse.md)，普通结构更新沿用原本机库，不再自动生成备份或复制资料。历史 App 管理快照仍属于敏感副本：明确删除来源、过程、关系资料或助手会话时，继续核验归属并清理相关完整快照；未知、损坏、未完成或清理失败时不得宣告删除成功。停止创建新快照不授权丢弃已有副本；外置原库、用户另存文件和供应商副本不由 App 擅自删除。
- 原始视觉帧仍默认仅在端侧内存中按 ADR-052 用于窗口布局分析和顶部 display name 局部 OCR，不读取左侧选中行或提取头像指纹，不上传整张微信界面。当前实现的正文工具仍由用户自行安装；ADR-061 新增由首启向导准备工具与用户明确授权初始化的目标，尚未实现，不代表后台获得安装、提权、重签或重启微信的能力。初始化先说明影响，由用户亲自完成必要的一次性系统授权；App 不接收或保存管理员密码，保留原微信安装包，不保存全量导出文件。
- 外部模型调用不是默认授权。每次接入新模型、云端 OCR、存储或连接器前，必须记录发送数据、用途、接收方、保留期与删除行为。
- 用户手动提交的原始 JSON 只用于来源复核和可追踪的重新解析，不进入回复检索，也不默认发送给外部模型；它必须与来源一起删除。
- 用户必须手动创建会话绑定、触发导入或开启会话同步。首次私聊列表默认不选，只有用户最终确认的 active 绑定可由 CLI 在应用运行且总开关开启时后台读取文字；全局 session 流仅提供会话变化触发信息。前台定位按 ADR-049／052 在本机内存分析当前微信窗口布局，仅对顶部会话名称做 OCR；整窗原始帧不保存、不上传，聊天正文和其他联系人列表不做 OCR。其他 App 不在采集范围内；关闭时停读，重新开启后按 ADR-025 恢复已确认范围内的缺口（见 ADR-030）。
- 候选回复只在应用内展示，不能由系统发送到任何第三方聊天渠道。

## 允许的数据流

| 场景 | 可处理的数据 | 必须满足的条件 |
| --- | --- | --- |
| 本地文字导入 | 用户选定联系人对应的原始文本和元数据。 | 明确来源、联系人归属和删除入口。 |
| OCR / 转写 | 用户主动提交的截图或语音及其原始引用。 | 说明端侧或云端处理方式，产物进入统一文字模型。 |
| CLI 后台增量同步 | 会话变化触发元数据，以及已确认一对一绑定的文字增量。 | 用户主动选择并最终确认绑定、应用运行、总开关开启；按稳定会话标识和联系人范围只读，不要求微信前台，不保存全量导出。 |
| Mac 微信前台定位 | 顶部 display name 与用于唯一性核验的有界CLI会话元数据。 | 按 ADR-049／052 仅在微信前台且会话可见时在本机内存分析该窗口布局，再仅 OCR 顶部名称；定位不唯一时要求选择，不推断联系人。OCR 不读取正文，不阻塞已确认绑定的 CLI 同步，原始视觉帧不落盘或上传。 |
| 模型提取关系候选 | 选定联系人下的最小必要消息片段。 | 请求前说明发送范围；结果为待采纳候选并保留证据。 |
| 模型核验来源语义 | 同一已授权提取窗口的必要原消息与候选。 | 使用既有供应商与模型，至多一次有界调用；不检索新范围、不改写事实。每次调用保留元数据台账，含正文追踪已接入后端，按 ADR-037 的独立保存与删除要求处理；覆盖范围与历史缺口见[追踪契约](memory-extraction-trace.md)，不据此认证真实模型质量。 |
| 记忆提取完整追踪 | 已授权原始来源映射、实际输入窗口、模型请求/返回、程序处理和写入结果。 | 所有提取默认保存，保留到手动删除或来源删除；不扩大读取和外发范围，独立受控存储，全部内容来源进入删除依赖，记录失败停止本批；后端与 React 查看、反查及删除入口已实现，历史／不可观察载荷缺口与验收范围见[追踪契约](memory-extraction-trace.md)（ADR-037）。 |
| 模型建议表达方向 | 当前待回复消息或主动联系目的、少量近期对话、极少量相关记忆、连续性提醒，以及按 ADR-043 受控加载的至多一个有效 Skill 版本。 | 旧方向探索沿 ADR-043／074 的有界任务约束；统一工作区按 ADR-079 在用户显式点击后直接给出建议候选，新消息只提示。建议不代表已确认意图，最终由用户选择、修改和发送。 |
| 模型生成回复 | 当前消息、少量近期消息、相关已采纳资料与适用的长期表达偏好。 | 限定 `owner_id + contact_id`，记录本次实际使用的上下文。 |
| 本人事实与明确偏好概览 | 同 owner 的已保存本人资料、真实 SELF 原版本和来源 ID。 | 复用无正文清单；不复制联系人原话、姓名或定位文字，来源逐项回到已确认原范围核对。 |
| 当前时间 / 日历查询 | 当前时区，以及用户已授权日历中的必要只读查询结果。 | 时间由确定性代码返回；日历连接器单独授权，不创建、修改或删除日程。 |
| 公开网络搜索 | 模型不知道或可能变化的公开信息查询及结果。 | 查询不默认携带聊天正文、联系人身份或关系资料；记录接收方、用途和出站类别。 |
| 回复 Skill 导入 | 用户明确选择的本地 Skill 包、经允许的辅助资源与必要来源元数据。 | 导入发生在独立用户操作中，记录来源定位和内容摘要；不得发送聊天正文或联系人资料，所有文件校验通过后才能启用。未来网络安装仍需单独授权。 |
| 授权经验提案 | 同一已确认联系人内有界的实际助手任务、编辑／选择及关联可靠后续观察；当前可用的同范围Skill教学策略。 | 默认关闭，单独确认学习用途；每批最多8份／24000字符，复用前台优先、租约和有限重试。清洗策略与私人依据分开，未审核不运行。全部实际来源和偏好依赖参与世代复验与删除，实际状态见09集成任务。 |
| 对照审核与范围发布 | 用户明确审核输入、同一冻结上下文、旧策略或无Skill及隔离草稿。 | 不临时发布；范围和替代关系双确认后原子发布。完整来源、导航和偏好进入删除证明；原删除锁及事务内物理擦除输入、对照、发布正文、资源、方法、操作摘要与跨联系人准备/实际使用副本。 |
| 删除 / 级联清除 | 消息、候选、采纳资料、索引、缓存、任务产物与权威库记录；不含正文的最小出站台账保留。 | 删除任务接入同一数据流模型；按 scope 限定范围，跨存储面级联，完成后不可再检索。 |

不允许把整个历史、其他联系人的资料、未选择的原始截图或无关账户信息默认发送给模型。

## 回复 Skill 指令安全

- 回复 Skill 包是不可信指令。v1 只有用户明确选择本地包时才能导入；候选回复 Agent 不得自行搜索、下载、更新、启用或删除 Skill。未来网络安装也必须是独立用户操作。
- 导入器必须校验格式、大小、路径、资源类型和内容摘要，拒绝路径遍历与符号链接逃逸。经校验的 `SKILL.md`、references 和允许的静态 assets 与不可变版本绑定；scripts 不进入可运行版本，`allowed-tools` 等能力声明被忽略且不进入模型目录。
- Skill 正文不能注册或授权 Tool、MCP、Shell、文件写入、外部网络或聊天发送能力；即使正文提出这些要求，实际 Tool 注册表和应用层 permission policy 仍具有唯一执行权。
- `SkillsMiddleware` 的 backend 只暴露当前已验证 owner/contact 可用的 Skill 虚拟路径；受控 `read_file` 只允许读取该版本列出的 `SKILL.md` 和辅助资源，不得读取任意服务器文件、外部 URL 或其他用户、其他联系人的 Skill。
- `skills_metadata`、Skill Tool 结果和相关摘要必须绑定 `owner_id + contact_id + skill_library_revision`。联系人变化或 Skill 导入、更新、禁用、删除后，旧运行状态必须失效，不能从 checkpoint 恢复旧目录、正文或辅助资源。
- `skill_library_revision` 按 owner 管理；同一 owner 的任一 Skill 发生导入、更新、启用、禁用或删除时都必须递增，避免其他联系人范围继续复用旧目录。Skill 名称在同一 owner 内唯一。
- 用户删除回复 Skill 时，所有版本正文、辅助资源和来源定位必须清除。历史请求只可保留内部标识、名称、简述、内容摘要、删除时间与删除凭证形成的最小删除记录，不得借审计或复现名义保留可恢复正文或资源。
- 旧回复的依据变化提示不复制记忆或来源正文，也不改变原快照。修正、否决和时效变化可保留仍有合法来源的历史表达供用户回看；按 [ADR-080](../adr/080-unified-memory-list-and-retired-exclusion.md)，所有失效及过期记忆和依赖它们的派生正文不得再次进入生成，旧候选、讨论和续写均复验资格，状态变化旧版也只供查看；真实来源或记忆删除须物理清除受影响回复、编辑版本、携入内容和恢复副本，旧幂等键、迟到结果及中断重试不能复活正文。本人手录根必须确为同 owner 的合法手录版本链；其后混入聊天依据的版本仍受真实聊天来源删除约束，不能用本人引用豁免聊天依赖。

## 后台同步与前台定位控制

- 用户在首次绑定时明确看到后台同步范围、前台定位所需的屏幕录制权限、停止入口、重新开启后的恢复行为和“不会自动发送”的说明。首次不预选；主动全选只作用于当前未绑定列表，刷新不扩大选择范围。
- 同步 UI 分开显示后台开关/状态和前台定位状态。微信失去前台、会话不可见或定位不唯一时停止该次自动定位；已有稳定绑定的后台 CLI 读取继续。绑定失效时停止该绑定的正文读取。
- 顶部 display name OCR 与有界 CLI 唯一私聊元数据及已确认绑定核验只负责定位当前会话（ADR-052）；CLI 以用户已确认的稳定外部会话定位标识调用只读 `tail`，只处理文字消息，并保存最小来源元数据、消息 ID 和每联系人独立水位。
- CLI 不可用时不退回 OCR 正文；关闭同步或退出应用时停读。重新开启或应用恢复后，按 ADR-025 从可靠位置恢复仍有效的已确认绑定，不追溯 baseline 之前历史；恢复状态按 ADR-083 简化展示，暂时失败自动退避重试；不能把恢复中或本机无记录标为完整。

## 模型适配器约束

模型调用应通过独立的 `ModelGateway`，而不是散落在导入、检索或 UI 中。该适配器至少需要：

- 接收已裁剪的请求，不自行查询全量聊天历史；
- 区分方向建议、生成候选、抽取候选和 OCR/转写等用途；
- 记录模型名、请求时间、发送字段类别、响应状态与错误；普通运行日志硬禁止复制完整私密正文，只能含内容无关的引用（哈希或条目 id），并定义留存期限与清除任务。ADR-037 新增的含正文记忆提取追踪独立管理，不能写入普通日志或出站台账；
- 将 API key 和供应商配置与业务资料隔离；
- 在供应商、地域、留存、训练使用和删除机制不清楚时，阻止把敏感资料投入生产调用。

每次对外发送必须产生一条强制出站台账记录（`outbound_ledger`），不可关闭：

- 非正文标识：`owner_id`、`contact_id`、来源 id、条目 id、请求 id；不得复制私密正文；
- 供应商与模型名、用途、请求时间；
- 保留期与删除能力（供应商是否支持删除外部副本、如何删除）；
- 删除来源后保留不含正文的最小调用记录，按 ADR-031 验证不残留聊天正文、候选正文或来源文件名。联系人和账户删除不由本次决定扩展授权。

`ModelGateway` 接口契约（执行机制，非仅规范要求）：

- 仅接受隔离键域内检索结果作为输入，拒绝越权上下文；
- 发送前校验上下文规模与字段白名单；超预算、含未声明字段或未知供应商政策时硬失败（不发送）；
- 配置的供应商数据处理政策（地域、留存、训练使用、删除能力）未知或不满足要求时，直接拒绝调用；
- 上述拒绝行为纳入单元测试与验证清单。

## 记忆提取追踪的正文与删除边界

按 [ADR-037](../adr/037-complete-memory-extraction-trace.md)，完整追踪为默认保存的敏感资料，具体阶段与查询契约见 [记忆提取完整追踪](memory-extraction-trace.md)。这明确修订 ADR-033 的核验正文只在运行中使用限制；不改变模型准入、发送范围、原始视觉帧、来源核验或自动采纳规则，也不表示功能已经实现。

追踪持续保留到手动删除或来源删除；来源依赖覆盖实际使用的原始记录、全部窗口消息和参与判断的旧记忆，而非仅候选引用的消息。来源删除须清除受影响整份追踪的含正文内容、原始请求/响应、解释、缓存和可恢复副本，并验证不可再检索；多来源的权威消息与记忆继续按既有规则处理。联系人和账户的含正文资料清除同样包括追踪，最小台账的整体删除规则仍待原规格另行确定。

含正文追踪不进入普通操作日志、控制台、Git、公开评测或自动外部上传，不含连接凭据。记录失败停止该批后续处理与水位推进，保留已提交结果并暴露失败和部分写入。物理存储、可靠提交、查询与级联清除尚须实现和验证，不能据文档声称已具备这些保证。

## 加密与密钥管理（云端生产前置阻塞项）

在云端数据进入生产前，以下事项必须全部决定并落地，否则权威业务库按"明文存储假设"处理并明确记录风险：

- **云端静态加密**：PostgreSQL 与对象存储的静态加密方案、密钥管理（KMS）与备份加密；
- **端侧缓存加密**：客户端本地缓存的加密与密钥存放方式；
- **密钥管理**：供应商 API key 仅存于云端 `gateway`，端侧不持有；密钥的轮换、撤销和解绑/删账户时的吊销流程；
- **明文存储假设**：在加密方案落地前，权威库中的数据视为明文存储，不能声称"已加密"，该假设列入风险登记与验证清单。

未满足以上前置项前，不得将私密资料写入云端存储或投入生产调用。

## 删除保证

按[ADR-082](../adr/082-retire-explicit-style-samples.md)，主动收藏表达样本及其独立于助手会话的留存例外已退役。升级须清理旧样本和来源依赖，并撤销受其影响的冻结输入、携入和恢复能力，避免旧快照重放样本。独立合法的原始聊天、记忆和长期表达偏好不因样本退役被误删；删除来源、联系人和助手会话仍沿各自删除边界执行。旧样本生命周期记录只作为历史证据，不代表退役迁移或当前 App 已验收。

独立集成候选的[纠错保护](../../.scratch/memory-skill-integration-preparation/issues/02-correction-and-erasure.md)将完整纠错参与窗口及来源世代加入原删除事务。排队删除即撤下旧比较，执行删除清除纠错正文、候选证明、受影响追踪和恢复副本；仅当仍有效规范消息需要防止旧错误复活时保留无正文`erased_guard`，最后一份有效依据删除后移除决定。该合成工程结果不表示业务库迁移或S分叉库已被处理，S分叉库继续保留原样。

已退役的[旧资料升级](../../.scratch/memory-skill-integration-preparation/issues/10-versioned-memory-upgrade.md)所遗留的比较、
提取结果和裁决也是敏感副本。排队删除即失效旧批准；真实删除在原来源／资料／联系人
事务内清除受影响批次的可恢复内容及完整追踪，不依赖下一次 GET 补清。工作中只保留
隔离身份、有限状态与非秘密算法配置，算法身份不含密钥、正文、任意环境变量或带凭据端点。
模型外部副本仍沿原独立删除边界；本轮仅使用合成资料和本地 Mock，不调用外部模型。

1. 用户能删除单一来源、单条关系资料、某联系人所有资料或整个账户资料。
2. 删除必须覆盖规范化消息的来源引用、候选资料、仅由该来源支持的确认资料、检索索引、缓存和任务产物；同一消息仍有其他有效来源时不得误删。含正文提取追踪按 ADR-037 清除全部受影响记录，不按直接证据引用缩小范围。

   候选维度依据按[ADR-046](../adr/046-source-bound-dimension-evidence.md)覆盖完整参与窗口及活动来源，而非只有候选直接来源；只作为上下文的来源被删除也须清除旧证明。多来源消息仍保留时不得以另一来源恢复旧证明。候选拒绝／删除同步清除依据，来源删除完成复核检查残留定位；来源标识、摘要和标签虽无正文仍属私密关系资料，不进入普通日志或公开上传。

   [ADR-063](../adr/063-bounded-runtime-evidence-and-source-dependencies.md)已采纳并完成隔离工程验证的新合取来源合同进一步要求：清证明后仍保留正文必需消息依赖；任一必需消息失去全部活动来源时，先收集全部状态的相关资料及版本、清理引用回复与运行租约，再擦除正文、解释、备选和索引并核残留。人工确认不切断依赖；独立手动资料、无关联系人和仍有有效来源的消息保留。仅作窗口背景的消息删除使证明失效，不因此删除无正文依赖的资料；旧记录继续沿原删除合同。
3. 对已发送至外部模型或外部存储的数据，界面必须明确其独立删除路径、留存期限和剩余限制；应用内或权威业务库中的删除不能被描述为已删除外部副本。删除来源时保留不含正文的最小 `outbound_ledger` 调用记录，用于核对调用时间、供应商、模型、用量和结果；它不证明外部副本已被清除（ADR-031）。联系人和账户删除的台账规则另行确定，不沿用本次单一来源决定。
4. 删除任务应可重试、可查看失败原因，并避免在操作日志中残留可恢复的原始聊天正文。
5. 级联删除建模为可重试、幂等的后台任务（`background_task`，type=delete）：逐存储面确认删除结果（消息、候选、确认资料、索引、缓存、任务产物、对象存储；另检查保留台账不含正文），失败可续跑；结束后复核“删除后不可再检索”。删除顺序与部分失败的补偿语义在实现时固化，并在测试覆盖跨来源场景。
6. 操作日志只记录存储键与条目 id 等与正文无关的标识，不记录可恢复正文。
7. `deleted` 是通过不可检索验证后的最终状态。删除请求、执行中和失败必须使用独立状态；只有状态更新而消息或派生资料仍可检索时，删除不算完成。
8. 用户再次导入已删除的同一文件时，必须重新预览和确认并创建新的来源记录，不得静默恢复旧来源。删除完成后只保留不含联系人名称、来源文件名、文件哈希或聊天内容的最小删除凭证。
9. 删除联系人时清除其全部来源、消息、关系资料、回复候选和会话绑定；删除单一来源时遵循多来源引用规则。导错联系人时同样先删除错误来源，再重新确认和导入，不允许直接迁移私密资料的归属。
10. 删除回复 Skill 时清除其所有版本正文、辅助资源、来源定位、目录缓存、Tool 结果和相关摘要；完成后只保留不含正文或资源的最小删除记录，旧 checkpoint 不得恢复该 Skill。

联系人与本人概览的无正文清单均属于删除范围。底层记忆、候选、人工决定、来源、规范消息、
来源引用、观察记录或实际追踪依赖变化时，canonical 061 的投影失效触发器与 canonical 062
的本人集合修订触发器在原事务内分别撤下投影、记录真实集合变化，
不改变业务资料的采纳或授权。来源进入 `delete_requested` 即失效，清理失败仍不可从
旧清单恢复；重复请求、显式重试及清理已提交而 Worker 回执未保存时，重建都重新核验
真实来源。自然过期或人工修正仍有合法来源的历史可以查看；真实删除不得借历史保留。

本人手录根须沿实际合法版本链核验，不能用 owner 归属引用豁免后续聊天依赖。本人
概览的来源定位文字固定为空，仅保留真实范围与引用 ID；旧 NULL 证明保持未知，
不能用后续人工决定或另一个来源恢复旧提取的证明。本人集合修订与清单失效沿原事务
提交或回滚，删除完成后不从旧投影或中断 Worker 回执恢复正文。

概览不保存 HTTP 正文、原话、模型摘要或另一份恢复正文，数据库约束拒绝在投影、
记忆依赖或引用层追加正文。HTTP 禁用缓存，客户端按范围和操作世代撤下旧内容。

回复使用概览时，导航和检索过程以生成时无正文回执保存；实际证据正文保留合法底层快照。
准备阶段尚无回复请求时也在输入 CAS 中固定完整参与依赖；来源排队删除在同一事务内
擦除相关固定 JSON、输入和恢复副本。最终写入继续在同一 owner 锁事务内复验；概览读取失败
或补查失败不授权新读取或扩大预算。联系人原话补查与本人资料预算独立，本人资料的
原 contact 不能成为自动查询另一关系原话的入口。导航依赖即使未作为候选引用也进入
来源删除路径；旧快照、失败重试、同库恢复和迟到输出不得恢复应删正文。只用于删除
追踪的隐藏依赖不展示为模型依据，回执也不能替代既有 `basis_changes` 或原来源证明。

当前联系人整体 DELETE 产品入口尚未提供；本票工程覆盖真实 contact 外键删除导致
清单物理清除、目录撤下与概览 HTTP 不可访问，不据此宣称已有联系人删除用户流程。

## 最小验证清单

- 导入两位联系人的合成资料后，A 的回复请求永远检索不到 B 的消息或资料。
- 删除来源后，其消息、候选资料和索引均不可再次被检索。
- 将来源状态写成 `deleted` 前，确定性验证必须证明其消息和派生资料已经不可检索；只改状态的实现必须判定失败。
- 删除后再次导入同一文件必须产生新的确认和来源记录，旧删除凭证不得恢复聊天内容。
- 解除会话绑定或暂停同步后，应用不会再捕获该会话；删除由会话同步产生的来源后，其消息和派生资料按相同级联规则清除。
- 方向建议请求只包含有界消息/目的、相关记忆、连续性提醒与 ADR-043 允许的受控 Skill 资料；无完整历史、业务 Tool 补查或外部查询结果。旧探索接口仍沿原确认生命周期；ADR-079 的工作区可在用户点击“帮我想想”后直接生成建议候选，不视为确认立场。任务关闭、范围或 Skill revision 失效后，不接受旧结果。
- 模型生成请求只包含本次声明的上下文，且不存在自动发送调用。
- 时间 Tool 返回确定性当前时间；日历 Tool 只能读取已授权范围，网络搜索不默认发出聊天正文、联系人身份或关系资料，二者都不存在写入或发送聊天消息的能力。
- 回复 Skill 未经用户明确导入和完整校验不能启用；恶意 Skill 不能增加 Tool、读取任意文件、跨 owner/contact 加载策略或获得外部聊天发送能力；Skill 目录变化后旧 checkpoint 不能恢复已禁用、已删除或旧版本正文、辅助资源。
- 删除回复 Skill 后，数据库、资源存储、缓存、Tool 结果、摘要和 checkpoint 均无法恢复正文或辅助资源；历史候选最多显示最小删除记录，不能宣称完整策略仍可复现。
- 删除来源或联系人后，相关 Agent 摘要、Todo、Tool 结果缓存与 checkpoint 不得继续恢复或被检索。
- 每次对外模型调用都产生一条 `outbound_ledger` 记录；删除来源后保留最小调用记录，不保留正文；可列出已配置的外部供应商及其独立删除路径，未知政策不得描述为已完成外部删除。
- `ModelGateway` 拒绝越界上下文与未知供应商政策；出站载荷符合字段白名单。
- 操作日志不含可恢复的正文残留；删除后检索不到对应消息、候选、确认资料与索引。
- 完整提取追踪落地时，验证只作为窗口上下文使用的来源删除，也会清除受影响追踪的请求、响应、快照、解释和可恢复副本；记录故障停止本批且不推进水位，部分业务写入可查；普通日志与最小台账始终无正文。
- 在加密与密钥管理前置项落地前，验证清单必须断言权威库以明文存储假设运行，且界面对用户明示"未加密"；落地后改为断言静态加密与密钥轮换/吊销有效。
- 损坏导入文件、空检索、模糊关键词和后台任务失败都有用户可见的结果。

## 检索记录与度量

### 检索记录生命周期（M9）

检索日志（入选引用、排序分数、检索器版本）不属于长期关系资料，需要独立生命周期策略：

- 默认持久化到权威库并设保留期（如 30 天），到期由后台任务清理；
- 随其 `reply_request` 的删除级联清除，用户可在界面查看并主动删除自己的检索记录；
- 日志只记录引用标识、分数与版本，不复制消息正文。

### 检索质量度量（M10）

"可测量的检索问题"以指标落地，作为是否引入向量检索的前置数据：

- 指标：空结果率、降级率（见 3.3）、候选被拒绝率、引用纠错率；
- 采集点：检索接口与生成接口的返回/接受/拒绝动作；
- 触发升级：指标连续超阈值且有真实用户反馈时，才评估 embedding 与向量检索；引入向量检索列为需重新过隐私评审的独立决策。

### Embedding 条款（M11，预留）

在引入 embedding/向量检索前必须满足：

- 向量化时机与位置（端侧还是云端）在接入前明示；
- 发送字段与供应商核验；向量与文本按同一隔离键隔离，不得绕过联系人隔离；
- 向量留存与删除语义与文本一致，删除来源/联系人时向量一并清除；
- 作为需新增数据处理影响说明的决策点，接入前完成评审。
