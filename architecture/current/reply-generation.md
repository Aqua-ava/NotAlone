# 现行候选回复与助手会话

回复面向本次已确认联系人，使用获准且仍有效的本机资料，由用户明确发起、选择、编辑并亲自发送。来源和删除见[隐私规格](privacy-deletion.md)，身份与资料对象见[数据契约](domain-data.md)，Skill 的唯一完整合同见 [Skill Library](skill-library.md)。

## 一个工作区与明确的生成动作

- 主输入统一接受本次想法、方向、草稿、语气与具体要求，不再提供独立语气选择或要求输入；“帮我表达”要求有输入，保持原意并遵循其中的表达约束，“帮我想想”允许为空，候选不代表用户已采纳的立场。
- 本次输入按原文冻结，不将要求文字当成待发送正文，也不自动采纳为长期偏好或关系事实。用户不必先选目标消息或确认模型方向；建议、候选选择和复制同样不构成长期采纳。历史记录中的独立设置和要求材料仍按原快照只读回看，不重写旧输入。
- 生成时自动提供同一联系人最近最多 50 条有效聊天、合法长期背景和场景目录，L1 由模型按需检索。工作区不提供最近聊天查看／刷新、关系背景开关或补充聊天输入；候选仍展示本次实际依据。候选列表读取不附带近期聊天正文或展示专用覆盖投影，不改写或删除权威来源。旧请求中的背景选择和补充输入仍按其原快照与来源合同回看，不因入口退役重写。
- 已有联系人可在明确选择后手动表达，不要求微信前台或同步开启。手选不建立渠道身份、恢复读取授权或关闭前台跟随；重开 App 需重新确认本次对象。
- 快捷键、打开窗口、切换联系人、新消息及回看只改变展示，不创建生成任务；新消息只能提示用户明确更新候选。旧方向探索和确认方向后生成的独立产品入口已退役，正常入口使用当前 SQLite 助手讨论与候选链路。

依据：[统一工作区](../adr/079-unified-expression-workspace.md)、[消息排除退役](../adr/165-remove-message-exclusion.md)、[最近聊天区块退役](../adr/187-retire-workspace-recent-chat.md)、[语气与要求设置退役](../adr/188-unify-workspace-writing-input.md)、[旧流程退役](../adr/163-retire-disconnected-reply-workflows.md)。

## 本次请求与资料资格

```text
确认本次联系人并明确点击表达／建议
  → 固定联系人、助手会话、请求身份、动作及输入版本
  → 选取合法本机资料并冻结实际依赖与有界上下文
  → 核实提醒、完整输入预算与受控 Skill／资料工具
  → DSH 有界生成 1–3 组候选
  → 程序核验结构、依据、来源和当前请求资格后保存
  → 用户查看依据、编辑、复制并亲自发送
```

回复读取已持久接纳的本机消息、正式记忆及正式发布资料，不恢复来源、不启动或等待微信同步、L1、L2 或 L3。微信暂时不可读、同步暂停、历史尚未追平，不阻塞合法本机输入；覆盖不足如实进入本次依据，候选区不额外展示历史覆盖提示。既有失证围栏、删除排除和真实来源冲突不会因此解除；可用背景为空时只使用本次合法独立输入。

新生成请求不接受旧历史确认参数 `acceptIncomplete`／`accept_incomplete`；已保存覆盖事实与历史输入仍按原快照回看。近期聊天的有界选取、正文及稳定来源由同一读取动作提供，准备层不跨两次读取协调身份与正文；冻结、出站与提交仍各自复验精确依赖。[ADR-194](../adr/194-single-runtime-facts-and-reply-preparation.md)

新请求只能选取当时有效的消息、记忆版本及 current 正式发布集合，冻结实际来源、解释版本、保护修订、publication、完整成员及递归底层依据。出站和保存的短事务复核**本轮精确依赖**，不以整个联系人／本人集合的修订号变化判失效：无关新消息、记忆或新的场景／画像正式发布不改变在途快照；实际依据被纠错、删除、隔离、换图、明确撤下或出现来源冲突时拒绝旧输入和迟到结果。该规则不豁免 Skill 包集合及 head 修订的目录快照复验。模型调用期间不持有业务写锁或事务。

同一范围内同幂等键、同输入的完成请求重放原结果；同键不同输入拒绝，仍在执行返回处理中。失败和中断只沿原持久请求、租约、回执与累计预算恢复，不创建重复候选或盲重发未知调用。界面切换不改变已接纳任务归属，完成结果只回到原联系人和会话。

生成请求已报错且同一请求身份的状态为 `not_found` 时，候选面板保留原始安全错误说明，后续核对也不以“尚未找到原请求”覆盖真实原因。来源待重新核验时提供“处理同步问题”入口，打开管理后台并引导到联系人页的同步设置；该入口不启动修复、恢复授权或生成请求。已受理仍在准备及状态暂不可读时继续按原请求核对，不猜测未发送；模型结果未知的调用按下一段自动放弃。

模型请求已发出但本机没有收到最终结果（调用超时、连接中断或应用重启）时，本机确认不再有在途调用后自动放弃该次调用（[ADR-183](../adr/183-auto-abandon-unknown-reply-model-calls.md)，实现状态见该 ADR）：调用记为失败（`unknown_abandoned`），成本与回执仍记未知，界面承认可能重复计费；旧请求的迟到结果一律拒收；不自动重发原请求，也不沿用原请求身份。该联系人不因此被阻断，用户可新建请求重新生成；仍在本机在途的调用继续阻止同联系人并发新请求。

设置重载或资料更新先通过原认证连接排空已接纳生成，失败保留连接；`configuration_reload` 与 `app_quit` 分开记录。退出后的中断不能自动恢复发送，只有用户明确重试并通过资格复验后继续。

依据：[本机资料与精确依赖](../adr/162-local-reply-context-and-independent-model-lanes.md)。

## 初始上下文与使用次序

| 材料 | 当前用途 |
| --- | --- |
| 本次动作与统一主输入；历史独立设置和补充聊天 | 区分用户明确意图、表达约束与模型建议，保留原始来历；历史材料不改写为新输入。 |
| 近期消息 | 当前语境的直接证据；按本人／联系人／系统／未知作者传递，API 的 user／assistant 角色不能替代私聊作者。 |
| 联系人及本人 L1 记忆 | 初始不注入；模型根据当前信息缺口，通过固定只读工具在冻结范围内检索。 |
| L3 长期背景、L2 场景目录及按需正文 | 受独立预算限制；目录不是已读正文，也不是 L1 的唯一过滤入口。 |
| 受控 Skill | 正常候选先提供当前有效修订的名称与简介，由官方 `skill` 工具按需加载零个或多个正文；只指导表达方法，不提供联系人事实或覆盖本次意图，资源仍按需受控读取。 |
| 明确继续／携入的历史材料 | 保留原请求、版本、实际来源与变化状态；旧事实不冒充当前事实。 |

硬边界由代码控制。出现冲突时，本次明确要求与真实近期语境优先于旧记忆，Skill 不改变事实或身份；任何材料都不能覆盖来源、联系人隔离、删除和人工发送边界。

已知消息时间按先后呈现，同一或未知时间不伪造顺序；冻结输入时每条聊天消息前附其发送时间（本机时区，精确到分钟，形如「（2022-11-02 13:57）对方：……」），时间未知不补造、不加标注，召回查询仍只用不含时间的原话；本人连续发言或最后一句为本人，不改变“本人向当前联系人表达”的主体，也不自动挑更早的联系人消息作为未回复目标。未知作者不猜成联系人，仅在建议确实依赖其归属时要求补充。作者修正使依赖旧身份的准备失效；旧完成记录缺身份时保留未知，不倒填。

记忆的原话时间、保存时间、有效起止及条件随实际检索结果进入输入和依据快照。新回复冻结正式记忆输入时，在正文末尾附其直接来源消息的聊天发送时间，形如「（聊天时间：2022-11-02，约4年前）」：多条来源取最早至最晚日期，距离按最晚来源相对冻结时刻粗略给出（近30天内、约N个月前、约N年前），部分来源缺时间如实标注，全部缺失标为「聊天时间未知」；时间只附在输入文字上，不写入记忆正文，也不以保存、提取或采纳时间代替，文档整理资料暂不标注。历史未确认候选材料保留其生成时的原时间快照，不据此恢复新注入入口。来源日期与当前有效期都不能单独证明旧状态今天仍成立；旧快照缺字段保留未知，不能由当前资料补造历史证明。失效、过期和已否决资料先排除生成资格，再在合法集合内排序；不能把过期资料仅降到队尾后仍注入。

## 记忆检索词

按 [ADR-185](../adr/185-on-demand-reply-memory-and-history-search.md)，取消最新五条或草稿自动构造 L1 查询。初始不预计算记忆向量；模型先读最近最多五十条、本次独立输入及合法 L3/L2 资料，信息足够时直接生成。

需要偏好、约定或历史事实时，模型从完整当前语境构造具体 `query`，调用 `search_relationship_memory`；需要原话、时间和上下文时调用 `search_relationship_history`。模型不能提供身份、来源、版本或路径参数，关闭关系背景时两工具都不可用。

检索触发指引参考腾讯 MemoryProxy，由纯业务模块 `retrieval-policy.ts` 集中维护，提示、工具说明与执行预算共用同一合同。先检查当前已读原话、记忆／L2 正文或 L3 是否直接提供所需事实；已有可引用答案时不重复查，用户本次明确要求实际搜索时仍按要求核对。缺少直接依据且相应工具已开放时，历史指代、身份偏好、明确回忆查找、答案依赖过去安排／约定／结论四类场景要求先查再生成；按实际信息需求理解，不以孤立关键词硬触发。模型结合当前语境组织具体查询词，资料中的命令不成为用户授权，指代不清及工具不可用时保持未知。规则通过既有 DSH 官方系统提示和 scoped Tools 执行，是模型调用指引；不新增关键词检测器、业务自建循环或模型必然遵守的硬门禁。

按 [ADR-190](../adr/190-tencent-style-local-hybrid-retrieval.md)，L1 与 L0 共享本机 BM25＋向量召回及 RRF 名次融合。中文写入与查询使用 jieba 搜索分词；全文侧为 FTS5 BM25，向量侧为固定本机模型与 sqlite-vec 余弦距离，两路按稳定身份等权 RRF（k=60）融合。取消原 0.8／0.2 综合分和 0.48 门槛；模型缺失、失败或超时时使用 BM25 单路，检索名次不等于事实置信度。

L1 仍限定本次冻结 ID、版本与正文摘要；L0 覆盖本轮接纳边界内当前联系人全部获准历史，不截取五百条候选。在合法范围与当前来源集合内分别召回，再执行候选和返回预算。正文分词与向量增量维护，正文未变则复用；query 向量和当次得分只在内存中使用。新消息不混入，删除及来源失效实时生效；实际返回后冻结精确来源、作者和时间。每次历史搜索计算预算五秒，超时明确为未完成，不追加部分结果。索引回填不阻塞首轮生成；尚未齐备时明确本次覆盖不足，不能冒充完整未命中。

搜索结果入选前及实际出站、保存时复验版本、来源、原作者和时间。目录、冻结池和未返回的候选不算模型已读材料；只有真实返回并进入后续请求的材料编号可引用。一次搜索失败或为空后，模型可在剩余预算内换词或换工具，不自动扩大范围。

### 检索后的证据使用与语境核对

`evidence-use.ts` 集中维护检索成功回执与模型的证据使用指引；触发合同只组合该指引，工具适配层复用其渲染，不另建模型、复核器或工具循环。成功回执只证明本次返回了可引用材料，不证明用户问题的所有部分都已回答。已找到的阶段、范围或历史安排应按资料精度使用；缺少确切日期、时刻或当前状态时，只保留该项未知，不能把部分缺失概括成整件事未找到。用户要求核对细节且资料已证明时，至少一条候选应实际写出该项已知内容，不能只在依据里引用或泛泛重复话题；按本次表达意图组织措辞。保留原话中的推测、条件和不确定性，过去的计划不自动成为今天仍成立的状态。

比较两条资料前，模型须核对主体、所指对象、活动或场所、时间和适用条件。词语相似、日期较晚、排序靠前或 `actual_input` 均不能单独证明属于同一制度、前后变化或矛盾。候选中的具体命题应由引用材料直接支持；不明时保持分开或自然询问，不拼接结论。助手侧的检索过程和缺失状态不写成用户对联系人的经历；除非用户明确要表达自己的真实查询经历，不将“我查过／没查到”等工具状态写入私聊候选。

L0 可在本轮合法命中的同一绑定、已知发送时间三分钟范围内补充有限邻近原话。命中与邻近语境分别标识，每条原话仍是独立编号的实际输入和精确来源；邻近是有界片段，不保证完整连续会话；仅帮助核对所指对象与条件，时间接近不证明话题一致。同一时间的先后未经核验时明确保留未知，未知时间不自动扩展。补充原话仍须通过当前联系人、接纳边界、来源、状态及删除资格，旧 v1 范围不扩大。命中与邻近原话共同消耗原有消息条数、正文文字量、去重和计算耗时预算。

## 有界选取与完整请求预算

按 [ADR-189](../adr/189-editable-model-thinking-and-temperature.md)，回复生成与助手讨论使用独立于记忆处理的思考档位和温度设置，默认关闭思考、温度 0；可在「设置 → AI 服务」手动保存并安全重载。思考可选 low／high／max，温度为 0–2 且仅非思考模式生效。每次调用显式使用本次配置参数，完整请求计量和原输出校验保持。

| 项目 | 当前合同 |
| --- | --- |
| 近期消息 | 最多 50 条，取最近有效消息，保留完整正文；不设另一个消息 token 上限，仍受完整请求容量约束。 |
| 联系人 L1 | 按需搜索，整轮去重后最多 5 条；不截断正文，仍受完整请求容量约束。 |
| 本人 L1 | 按需搜索，整轮去重后最多 3 条，与联系人额度独立。 |
| L2 初始目录 | 最多 12 项、合计 1,600 字符，只含标题、提示和段落数量。 |
| L2 按需正文 | 仅按本轮冻结目录的材料编号读取；每轮最多成功读取 2 次，每次最多 3 个完整段落、1,800 字符。 |
| L3 长期背景 | 每份最多 8 条完整陈述，实际加载的背景合计不超过 1,200 字符。 |
| Skill | 零个或多个包，每包固定一个不可变修订；没有旧的“整轮最多一个 Skill”上限。目录、实际正文及资源均计入完整请求容量，静态辅助资源每轮总计最多 2 份。 |

这些预算的单位和范围分别核验，不把字符数说成模型 token 数；超长完整条目跳过或明确拒绝，不截半句冒充全文。候选引用只指向实际进入请求的材料，不把未读取正文或隐藏删除依赖算成模型依据。

按 [ADR-191](../adr/191-reply-retrieval-contract-simplification.md)，新回复只通过正式记忆与文档入口取得关系资料，退役没有正常入口的未确认候选选择／注入适配及其 3 条／300 字符、0.15 旧词法预算。待确认资料继续可管理；已保存候选材料的 `pending_candidate` 与「未确认」标注、原时间展示、来源复验、否决和级联删除约束继续适用，不改写旧请求或将其升级为事实。

每次模型调用计量完整序列化请求、实际输出预留与安全余量，包括工具、已加载材料和保留的运行历史；初始和后续调用都检查。已核实配置的估算须明确标注，计量器、模型、接收地址或配置不匹配时拒绝，不把估算称为供应商精确计数。接近上限提示，达到上限保留可查看历史并要求明确新开，不自动摘要、截断助手讨论或运行消息以绕过上限。初始检索材料的有界选取与连续讨论的完整历史是不同预算责任。

容量依据：[L1 与分层读取](../adr/067-layered-scenario-and-profile-context.md)、[多 Skill](../adr/136-multi-skill-reply-composition.md)、[完整请求估算](../adr/062-official-deepseek-reply-input-budget.md)及[接收地址配置](../adr/146-editable-deepseek-endpoint.md)。旧 ECNU 接线已随 DSH 迁移退役，不能由历史估算记录恢复该入口。数值是当前合同及合成容量边界，不代表真实回复质量已标定。

## 工具、输出与核实提醒

TS 业务外壳负责范围、预算、来源、事务与输出检查，DSH 通过官方机制执行内部有界循环，领域接口不暴露旧框架类型。模型不得改变 owner／contact、调用任意文件、Shell、外部聊天发送或写业务状态；Skill 正文不注册能力。当前不提供时间、日历和网络工具，不增加模型 Todo 或自动过程摘要。

正式候选装配通过已安装的官方 `@deepseek-ai/dsh-tool-skill` 发布 eligible Skill 的名称与简介目录，首次请求不携带全部 Skill 正文。模型按需调用官方 `skill` 工具读取所选修订，正文载入后才可使用受控 `skill_resource`；按 [ADR-193](../adr/193-retire-explicit-reply-skill-preload.md)，新请求不再接收显式选包参数，不保留预加载分支；历史选包及已加载回执继续按原快照读取。其实际启用条件以正式装配为准。当前 SQLite 候选通过官方 scoped Tools 开放上述记忆和历史搜索，L2 正文继续沿冻结目录读取。两搜索工具共用最多三次已接纳尝试，空结果、执行失败及超时占次数；参数、重复或超预算拒绝不执行。补查消息包含命中与邻近原话，整轮去重后共同最多十六条、2,048 估算 token（当前按 UTF-8 正文字节估算）；超长完整条目跳过，材料编号及语境标识作为协议元数据随完整请求另行计量。历史范围只保存接纳序号上界和联系人资料代次，不列举或截断历史 ID；模型不能改变身份，新入库资料不混入。查询当前获准历史的共享索引及补充邻近语境，共享五秒计算预算，超时不追加部分结果。邻近语境随既有搜索结果返回，不新增 Tool、微信读取或任意数据库接口。旧上下文缺冻结范围时不补造。

工具空结果、失败及预算耗尽分别记录无正文回执；未命中不证明资料不存在。只展示本次实际使用的材料与查询结果，失败或缺失的历史回执保持未知。查询重复、越界或超预算时拒绝，不借改关键词扩大授权。

模型输出须通过结构、候选依据及禁止动作校验，任意普通正文不算合法候选；来源或格式校验失败保留可区分的错误原因，诊断日志不保存模型原文。候选后不再追加模型语义复核，引用有效不等于表达语义已核验，最终表达由用户选择和修改。

转账、验证码、地址、借款、承诺、见面及关系冲突等核实提醒由确定性适配层负责，生成前提示用户核实；不因此新增记忆采纳的风险人工门。当前请求、提醒、结构检查及实际 UI 接线的验收分别核验。上述提醒是已采纳要求，回复侧确定性适配层的当前接线状态见[文末核对](#实现验证与未开放目标)。

依据：[受控历史补查](../adr/090-bounded-runtime-history-retrieval.md)、[不追加语义复核](../adr/068-direct-reply-candidates-with-user-selection.md)、[未接入工具范围](../adr/092-defer-time-calendar-web-tools.md)。旧输出 Tool、旧生成 API 与旧选择链的具体机制保留于[历史记录](../history/core-flow-implementation-notes.md)。

## 助手会话、回看与恢复

- 每个联系人独立维护当前助手会话；产品讨论与每次候选请求分开，一次生成不切断关系消息线程。明确新开或空闲超过 12 小时后的下一次生成创建新会话，并轻量提示，不迁移在途任务。
- 自动续用及空闲分段由正式生成受理事务统一选择，不保留仅供测试独立调用的分段写入口；新开与明确继续仍按用户动作执行。[ADR-194](../adr/194-single-runtime-facts-and-reply-preparation.md)
- 用户主动生成、补充要求、修改候选或明确继续刷新活跃时间；后台消息、同步、打开 App 和回看不刷新。回看不切换当前会话，只有明确继续才将旧会话设为当前并续期。
- 新会话不自动带入旧讨论；只有用户明确选择的已保存候选可按原版本与来源携入。旧会话保留到删除，来源与联系人删除仍传递清理。
- SQLite 是可见历史、候选、版本和来源的主记录，DSH 文件保存受控的可恢复执行记录。恢复和出站前核验范围、配置、业务提交及来源，必要时从合法业务记录重建，不能恢复已删正文。崩溃中断不自动重发或宣称半步续跑。
- 桌面讨论展示由 `ReplySession` 持有唯一读取请求；新读取、联系人或连接变化、来源撤下和删除会撤销旧请求。提交结果同时核验当前请求所有权、取消信号、联系人范围和连接代次，不另建持有展示快照的读取状态机。运输层继续核验响应格式及会话身份，后台继续拥有来源资格与删除裁决。
- 讨论回看只使用 SQLite 会话的 `entries` 投影；候选、原版和用户修改分别从候选与版本接口读取。历史独立要求、补充背景与设置由候选实际输入材料接口按原快照回看。旧助手 `turns`／`inputs` 客户端协议没有当前后台生产者，不为保留历史而继续维护；材料接口中的 `inputs` 路径不属于该旧协议。
- 打开助手只读取合法业务历史，不同步初始化或恢复 DSH 副本；存在尚未核验的副本报告 `unchecked`，不冒充可执行。讨论读取中或失败时仍可编辑当前联系人的独立草稿，旧聊天不转成新意图；联系人草稿是未提交独立输入的权威；读取、回看、来源失效和新开不消费该草稿，当前输入实际提交成功后才清空。旧候选、引用与恢复材料仍须撤下并重新核验，不从独立草稿恢复旧来源。
- 已撤下发言对外投影为 `text: null`、`call_id: null`，不改写原始审计字段，也不通过旧调用身份恢复撤下正文。
- 历史目录、正文和候选回看使用独立只读 Worker，与前台定位和后台写入分别排队。短读前后核验实际依赖及删除状态，失效结果丢弃；读者关闭失败仍阻止删除完成。Skill 文件核验也使用独立只读 Worker，异步等待不跳过内容与提交检查。
- 历史回看允许读取候选、原版、已保存修改和实际参考材料，并复制合法正文；生成、保存新修改、选用和携入前需明确继续该讨论。历史回看保留仍合法的正文、用户编辑和依据变化提示；来源或实际资料删除清除相应候选、编辑、携入与恢复副本。历史模式不能成为留存例外，旧快照缺版本或时间不补签。

依据：[持久会话与空闲分段](../adr/106-persistent-assistant-conversations.md)、[回看隔离](../adr/160-assistant-read-and-skill-worker-isolation.md)。

## 候选展示、编辑与发送

助手浮窗使用同一联系人工作区，展示确认对象、上下文状态、两个生成动作和 1–3 组可编辑候选。浮窗获得焦点造成的正常前台定位暂停不影响仍合法的本机生成；窗口关闭不改变同步总开关。

每条候选带实际依据引用，记录材料类型、来源、版本、时间、选择原因及可用的排序信息；聊天原文只随候选引用展示，不另列全部近期消息。Skill 选择与实际读取分别记录。共享「本次参考」默认收起，区分关系／本人资料、长期偏好、回复方法及本次输入，目录与已读正文分开，不宣称所有材料都被每条候选引用。切换联系人、请求或历史会话后重新核验并恢复收起，缺失信息保持未知。

复制当前显示的已保存版本，不要求先勾选候选；未保存编辑、来源失效或版本核对失败时阻止复制。上一版／下一版仅改变回看，不删除版本或自动创建任务；“用这组回复新开会话”才显式携入当前保存版本。复制、回看或候选被选中不等于已发送。

候选可以作为历史表达参考，但失效事实不得重新注入；明确继续重新取得合法背景，保留本次意图、用户编辑及选定参考。普通编辑复制不生成独立表达样本，也不静默训练长期偏好；用户明确管理的长期偏好应有独立查看、修正和删除路径（已采纳要求，当前 SQLite 后台尚未开放，见[文末核对](#实现验证与未开放目标)）。

授权同步能从结构化我方消息正向记录“已观察到发送”；同步暂停、CLI 不可用或本机尚未观察到时只能保持未知，不能推断未发送。产品始终不写入微信输入框或代为发送。
