# 现行领域与数据契约

本文定义当前已采纳的数据与关系边界；业务存储使用受控本机 SQLite，具体结构见[存储合同](../../backend-ts/src/storage/sqlite/README.md)。决定、实现和验收分别核验，本文不证明功能已经交付。术语见 [CONTEXT.md](../../CONTEXT.md)，操作流程见[核心流程](core-flows.md)。

## 核心原则

1. 每次回复都属于一位用户已确认的联系人。联系人身份来自确认范围内的稳定渠道身份；昵称和备注用于展示与既有绑定定位，不创建或合并联系人。
2. 联系人范围的读写先按 `owner_id + contact_id` 过滤，再做内容检索或排序；本人资料按 `owner_id` 独立管理。用户身份显式持久化，外部标识不能充当内部隔离键。
3. 原始资料、规范化消息、模型候选和已采纳记忆分层保存；来源、版本、采纳来历、时间与删除路径随资料保留。
4. 自动采纳标记 `auto`，可查看、修正、撤销和删除；用户确认与人工录入保留各自来历。一次性回复策略不能静默成为长期偏好。
5. 最终候选可编辑并带依据，外部消息始终由用户亲自发送。产品数据对象、Tool 与后台任务均不提供代发能力。

## 身份、同步范围与输入来历

- `owner_id` 由本机受控运行身份确定，导入资料不能指定或覆盖它。本人渠道身份另存并核验；账号缺失、冲突或变化须先解决身份与来源资格，不能按展示名猜测。
- 联系人从真实微信私聊加入：默认逐会话确认；用户明确开启当前账号全部私聊范围后，可按稳定渠道身份自动纳入现有及新增私聊。换账号不继承范围，撤销／删除排除项不自动恢复；切回仅所选范围不删除仍有效的绑定。依据为 [ADR-087](../adr/087-wechat-confirmed-contact-onboarding.md)、[ADR-089](../adr/089-all-private-wechat-sync-scope.md)及根产品边界。
- SQLite 空库重建按 [ADR-110](../adr/110-selected-sqlite-contact-read-grants.md)重新核验账号、私聊身份与逐人读取授权，不继承旧库资格。该实施范围不取消产品的全部私聊选项；界面只能呈现当前已认证能力，协议中存在 `all_private` 不证明已经可用。
- 稳定联系人、会话绑定、核验证据、选择代次和正文读取授权分别记录。取消授权立即阻止新读取与旧在途结果提交，但不因此删除合法保存的资料；重选不能恢复旧资格或解除清空排除。来源失效、身份冲突及删除屏障继续复验。
- 用户明确选择既有联系人，只确认本次输入归属。手动输入确认不建立渠道身份、外部会话或读取授权，也不停止前台自动跟随；每次请求须核验确认记录及 `owner_id + contact_id`。参见 [ADR-158](../adr/158-contact-selection-keeps-foreground-follow.md)。
- 粘贴的对方文字保留用户提供、未经渠道核验的来历，与本人草稿和规范消息分开；不进入记忆提取。只有用户明确生成后才沿助手讨论与候选生命周期保存，并继承相同删除路径。

### 前台名称定位

按 [ADR-132](../adr/132-existing-contact-name-matching.md)，前台使用新鲜、完整的会话名称与配置账号下已有稳定绑定进行关联。当前前台、唯一窗口、五秒新鲜度、来源一致、有界会话元数据和唯一私聊匹配均须核验；只有已核验的结果携带联系人及绑定标识。

原始 OCR 30%／50% 不单独阻断，无关群名缺失不作全局门；既有联系人的正常关联不逐人要求新桌面证明。匹配失败、改名、重名、截断名单、过期帧或其他实际质量失败仍需用户选择或重新核验。名称关联不创建或合并联系人、不恢复读取授权，也不证明前台登录账号已独立认证。

前台观察是内存瞬时结果，不产生规范消息或持久观察历史。仅分析当前前台可见的唯一微信窗口，并对自动定位的会话名称区域做 OCR；不读取正文或联系人列表，不切换或滚动会话。预览和置信度不写业务库或普通日志，预览最多保留原采集时点起五秒，刷新不续期；失效、范围变更、进入助手或退出时按生命周期清除。桌面控制器拒绝连接代际、范围修订或观察轮次过时的结果。

前台定位与后台同步分别核验：定位失败不阻断已有有效授权的后台读取；清除前台预览不删除联系人、草稿或已固定归属的任务。切换联系人不把旧请求、候选或迟到结果移交给新对象。

## 数据对象与资料分层

下表表达领域职责；数据库表、DTO、迁移版本及接口名称由对应模块合同定义。

| 对象 | 数据与隔离职责 |
| --- | --- |
| 用户与本人渠道身份 | 内部 owner 与经核验的外部账号分别保存；同一 owner/channel 的活动账号范围明确。 |
| 联系人与会话绑定 | 内部 `contact_id` 稳定；绑定保存账号范围、稳定外部定位标识、展示名称映射及核验状态。外部 `talker/username` 不等同于内部身份。 |
| 同步范围与读取授权 | 保存账号范围、选择代次、有效授权和独立排除决定；范围选择、总开关、资料可用性分别表达。 |
| 来源资料与微信来源记录 | 一份来源仅属一位联系人；保留原始资料或必要来源定位、确认来历、来源资格及删除状态。微信重扫不为每次观察保存正文副本。 |
| 规范消息 | 显式携带隔离键、说话人、文字或明确媒体信息、可用时间及来源关系；原始类型码、渠道消息身份和游标用于来源核验与去重。 |
| 记忆候选 | 保留主张、`self/contact/shared` 主体、来源、核验结果和明确状态；未采纳候选不能冒充已知事实。 |
| 联系人记忆与本人记忆 | 保存当前及历史版本、分类、有效期、采纳方式和来源依赖；本人资料属 owner，关系资料属 owner/contact。 |
| 目录、概览、场景文档与画像 | 可重建派生资料；保存实际成员、版本、来源依赖与构建时间。导航目录不成为新的事实源，生成资料保留推断及不确定性。 |
| 回复请求、候选与助手讨论 | 固定联系人、输入来历、幂等键、实际上下文快照、使用版本及来源；候选可编辑，讨论按联系人隔离。 |
| Skill 及不可变修订 | 保存策略身份、范围、启停来历与实际使用回执；正文和受控资源沿目录与版本合同管理，不承担联系人事实存储。 |
| 后台任务、步骤与执行尝试 | 保存业务范围、固定输入、真实进度、状态、租约、失败及恢复依据；状态不等于模型质量或消息覆盖完整。 |

```text
已确认来源 → 规范消息 → 记忆候选 → 联系人／本人记忆版本
                                      ↓
                               目录、场景文档、画像
                                      ↓
本次用户输入 + 当前有效资料 → 回复请求与冻结依据 → 可编辑候选
```

Skill 的发现、默认启用、组合、审核、不可变修订、目录失效和删除统一见 [Skill Library](skill-library.md)。一次候选采用不自动发布 Skill；策略读取不扩大 Tool、网络或文件权限。

## 消息、去重与图文来源

- 规范消息直接携带 `owner_id + contact_id`，查询不能仅依赖来源连接推导范围。消息必须能回到原始片段、文件引用或经核验的微信来源及稳定消息身份。
- 按 [ADR-128](../adr/128-deduplicated-wechat-message-storage.md)，同范围、绑定及来源内稳定身份相同的消息保存一份正文；重复观察只更新必要状态。身份冲突不猜测合并，同一消息可以有多个合法来源引用。
- 每位联系人只保留最近同步结果、时间、计数和必要失败原因；可靠续读、来源资格、身份映射、排除与恢复状态按其生命周期保留。迁移 46 将来源资格折叠为一行 `source_proof`，记录稳定账号／会话、来源代次、物理目标、`ok`／`needs_confirmation` 与实际核对时间；运行守卫不持久化，不作为合法本机资料的跨重启资格。微信端消息暂时不可见不等于本机删除或可靠撤回。
- 可靠撤回与普通缺失分别处理：已保存的撤回正文可回看，新的生成与记忆处理不使用它；缺正文时只保留撤回占位，不能猜造原文或凭系统记录猜测撤回。这是 ADR-128 的已采纳要求，其实施范围和验收单独核验。
- 消息列表按已保存的完整原始类型码显示已知类型并统计占位；未识别类型明确显示未知，系统元数据单独计数，不凭正文猜测载体。
- 引用回复保留真实回复正文、独立作者、引用快照与原消息关系；引用目标缺失时保持未解析，不能冒充当前消息。原消息身份与时间不变，引用正文不混入普通来源元数据；其他富消息和转发不据此获得任意 XML 展开权限。依据为 [ADR-139](../adr/139-quoted-reply-sync-and-history-enrichment.md)和 [ADR-141](../adr/141-inline-quoted-reply-sync.md)。
- 按 [ADR-153](../adr/153-joint-text-image-memory-input.md)，记忆输入将同一联系人的聊天文字与实际图片共同组装，保留顺序、说话人及消息来源。占位不能代替图片证据；缺失、失败和已清除图片如实保留状态。记忆正文与检索表示仍为文字。
- 图片只保存标准图或高清图，缩略图不保存，也不再保存原图／缩略图／未知分类、原图证明或来源分类依据（旧列因已发布迁移保留，不再写入或读取）。每条图片消息只有已保存、仅缩略图（最近尝试 `media_thumbnail_only`）、取失败三种结果。有效授权范围内按 [ADR-156](../adr/156-automatic-image-reconciliation.md)／[ADR-170](../adr/170-no-thumbnail-storage-and-no-original-classification.md)补查没有已保存图片的消息；尝试及退避不改变消息身份、联系人归属或清除状态。完整图片依据参与来源和删除链，聊天投影只传安全枚举。

### 来源核对与遗留删除等价事实

按 [ADR-176](../adr/176-in-place-source-recovery.md)，绑定持续表示联系人与稳定会话，来源资格独立核对。元数据一致且有界锚点相符时恢复同一绑定并增量续读，不旋转绑定、不增加认证代次。原生守卫只保护本轮独占读取，页提交仍复验来源、授权和删除代次；已有合法本机资料的资格不依赖空闲活守卫。真实来源变化或核验不足仍停读，本次退役不新增异源采纳或重新授权能力。

按 [ADR-177](../adr/177-retire-source-recertification-and-cleanup.md)，重新认证、取消和副本清理请求流程退役。已完成且有效的历史证明提取为 `history_source_equivalence` 中的删除等价事实，保持用户、联系人、稳定会话、来源代次及已验证物理出现范围；不建立普通消息别名，不授读取或旧证据复用资格。删除任一已证明出现时，其等价来源、派生结果和未来排除继续进入原闭包，即使另一代次尚无捕获也不能恢复已删内容。

表前缀证明与逐键点证明分别保留原边界。后者只覆盖旧审计已独立核对的相同分片、物理表实例和规范本地键位置；旧撤回点必须有当前代次同位置独立撤回证据，不能由单点推及整表。未完成、摘要无效或归属不符的旧审计不能建立映射，不能凭正文、时间、昵称或服务端别名猜测等价。合法保留的旧消息与原始来源归属不因流程退役改写，必要事实随联系人或账户删除。

## 历史导入与规范化

本节保留已采纳的文件导入合同；当前 SQLite 正常入口尚未开放文件导入，[正式宿主](../../backend-ts/src/sqlite-host-plugin.ts)将 `imports` 登记为 `unavailable`。以下要求不表示产品入口已经可用。

- 一次导入只属于一位已选择的已有联系人。需要新增时先按真实微信来源及确认范围建联；文件、昵称和展示名称均不能新建或合并联系人。历史 `manual_create` 仅保留溯源和删除语义。
- 本人渠道标识须与当前活动渠道身份一致；缺失、多个、变化或联系人来源不一致时停止并重新核验。跨账号或跨渠道联系人合并没有隐含授权。
- 保存来源、确认的联系人、确认时点及确认方式。整份资料先做确定性预览与校验，损坏、混合联系人、群聊或绑定不一致时拒绝，不能部分写入；校验通过后，来源与该份规范化消息同事务保存。联系人切换使旧预览与确认失效。
- 同一文件重复提交返回原结果；部分重叠的新文件不得静默跳过、覆盖或合并。已删除文件重新主动导入必须重新预览、确认和建立来源，不能按哈希恢复旧资料。
- 文字缺时间时保留未知；明确媒体类型可以保存结构化占位，正文和媒体信息都缺失时拒绝。系统不编造时间、媒体正文或发送方。
- 原始 JSON 可随来源供复核，但不参与回复检索或默认出站。重新解析必须形成可追踪版本，显式失效或重算依赖资料，不能无记录覆盖。

## 候选采纳与人工保护

默认规则由 [ADR-085](../adr/085-source-verified-automatic-adoption.md)／[ADR-086](../adr/086-source-meaning-without-repetition-threshold.md)规定：结构合格、独立来源支持且仍有效的候选，经过适用的条件、事件与版本检查后进入新增、更新、合并或跳过裁决。通过核验不保证新增一条记忆。

- 有来源支持的正常状态、条件或纠错变化可自动更新；新候选与 1～8 条旧记忆可按互补内容或同一事件演化自动合并，保留实际时间顺序、未知精度及仍成立的限定，最终正文另行核验。变化标记、事件或时间差异本身不新增人工门，主题相关但可独立保存的新信息仍可新增；动作／关系不兼容的技术结果不直接证明原始资料冲突。依据 [ADR-184](../adr/184-source-grounded-memory-update-and-merge.md)，具体恢复及未解决问题按[记忆处理](memory-processing.md)执行。
- 来源核验逐条支持正文、主体与原话限定，引用来自候选既有合法证据并包含主消息。计划、假设、转述或可能性保持原意，不能改写成已发生事实；未知第三人不能凭对话人数推归属。
- 语用、置信度与风险字段用于描述，不独立增加人工门；不设统一重复次数门槛。一次明确长期偏好可有据采纳，一次情绪、临时状态或回复要求不能仅因重复而成为长期偏好。
- 候选级内容核验拒绝与正常裁决跳过都记录真实原因，不导致整批失败；没有合格候选时按 `no_new_memory` 收尾并继续后续批次。配置、调用、整次协议或写入故障保持受阻或暂停，不能伪装成无新增。具体分流见[内容结果与技术故障](memory-processing.md#内容结果与技术故障)及 [ADR-149](../adr/149-content-rejection-is-not-failure.md)。既有人工待确认记录保持，关系未知与未解决矛盾保留待定，不能静默覆盖旧记忆。
- 候选状态须明确区分待决定、已采纳、拒绝或失效，正文、主体和证据可回看。`self` 候选进入 owner 范围；采纳后仍保留原候选关联及证据链，自动写入标记 `auto`。
- 人工录入、确认、修正、否决和删除分别保留来历。原规范消息的旧证据不能通过改写正文、分类、主题或主体重新自动采纳，新增来源引用也不等于新增消息。
- 真正新消息与已有人工决定冲突时，形成带原决定的待确认差异；确认在范围事务内复验完整窗口、来源与决定身份。自动替代只作用于当时确切的自动版本，新版写入和旧版失效同事务提交，不追随之后的人工版本。
- 旧 NULL、旧证据与历史版本按原合同保留未知，不自动回填、重解释或重新采纳。已拒绝或失效候选沿来源删除，短期复核记录按既定生命周期清理。

来源核验与提取的完整追踪是独立、可删除的资料，见[记忆提取追踪](memory-extraction-trace.md)。旧三门、维度门及有限证明字段只在[显式历史协议](../history/domain-data-legacy.md#显式历史采纳与有限证明协议)中追溯；当前语义边界另见[原意与不确定性](pragmatic-interpretation.md)。

## 资料分类与时间

| 分类 | 含义 |
| --- | --- |
| `common_fact` | 共同或长期事实。 |
| `preference` | 喜好及明确长期偏好。 |
| `taboo` | 有来源的禁忌及需避免的话题。 |
| `recent_state` | 带时间或条件限定的近期状态；期限模糊时保持未知。 |
| `relationship_note` | 其他关系备注，可编辑并使用标签。 |

分类采用有限枚举，不把自由语义扩展成复杂本体。按 [ADR-081](../adr/081-source-grounded-memory-time-and-conditions.md)，来源聊天时间、可选事件时段与阶段、保存时间和 `valid_at/invalid_at` 分别表达：

- 按 [ADR-150](../adr/150-optional-event-time.md)，发生时间 `event` 是可选标注；无法核实时由核验协议层丢弃该标注，正文按其余证据结果处理。`time_unverified` 只进入核验结果与执行事件，不写记忆事实字段。正文、主体、分类、语义、有效起止 `valid_at/invalid_at` 及 `conditions` 仍须逐字证据核验，整体核验不确定不能因字段降级而升级为通过；完整规则见[提取、核验与采纳](memory-processing.md#提取核验与采纳)。
- 有效期只表达来源支持的适用期间，使用半开区间；未知留空，不默认采纳时刻生效，不为瞬时状态自动设置当天结束。
- 相对日期按对应消息原有时区解释，跨消息分别绑定来源；日期或时区无法核实时保留未知。年、月和模糊表达保持原精度，不把区间边界当成精确事件时刻。
- 来源聊天时间由实际直接引用确定，多条证据形成范围；仅引用整份资料时不能把整份资料的全部消息、导入或读取时间冒充直接证据日期。缺失时显示未知或不完整。
- 保存时间属于该候选或版本，修正版本有自己的保存时点。来源时间表示“当时说过”，不保证事情当日发生；无结束日不能证明临时状态仍成立，计划到期也不证明已经完成。
- 条件保留原命题限定与来源，条件变化不等于原禁忌自动撤销。时间投影和历史／当前未核实状态不能反写原事实、采纳决定或未知有效期，不为所有资料设置统一寿命。
- 所有失效及过期记忆仅供管理回看，不能经历史导航、概览或派生资料进入生成；错误纠正、状态变化的来历仍保留。`retired_at` 不等于事实变化时点，删除后不得借历史恢复正文。依据为 [ADR-080](../adr/080-unified-memory-list-and-retired-exclusion.md)。

### 新旧关系与版本

版本化 `evolution` 保存关系类别、说明、关联版本、来源支持与独立的主张／条件变化标记。补充、状态变化、错误纠正、历史补充、未解决冲突和独立事项分别表达；旧记录缺失保持未知。内部范围、来源摘要与父版本摘要仅用于复验，不进入 API、页面或模型投影。

新旧裁决使用各版本合法来源、事件与消息时间；晚导入、晚回忆或较新的保存时间不能单独证明应覆盖现状。替代需要独立关系核验与父版本事务复验，未知关系保留待定。当前反证按实际关联事实及版本有界进入生成依据与冻结依赖；父版本及反证来源参与删除。人工保护仍优先，历史父版本只因被引用为变化来历也不能重新成为生成事实。

## 本人资料与派生概览

本人记忆按 owner 共享保存，不能复制为每个联系人一份。本人长期事实与明确偏好概览只从合法本人资料及版本构建，保留稳定、历史及当前未核实等区别；不汇总联系人事实、未采纳候选、近期状态或关系备注来生成新的性格与动机结论。矛盾主张按原条目呈现。

来源候选须核验同 owner 的 `self` 主体，修正继续沿真实版本链核验。手动资料有明确手录根，含聊天依据的后续版本继承聊天删除依赖；旧依据缺失不能用现在的引用或人工决定填补过去。

本人概览返回经核对的来源与消息标识及原联系人范围，不复制其他关系的原话、姓名或定位文本。查看原话与提取过程须回到对应已确认联系人，不能以当前联系人或昵称猜范围或自动切换。概览没有独立事实写入接口，逐项修正与删除沿原资料入口。

L2 场景文档与 L3 画像允许按 [ADR-072](../adr/072-personal-memory-insights-without-action-guidance.md)保留有来源的隐含特征与动机推断，但必须标记推断、依据、不确定性及矛盾；它们不改变底层事实，回复策略与行动指导不进入画像。生成资料与确定性导航概览分别管理。

## 检索、目录与资料修订

- 目录与概览只提供有限导航，不复制全部记忆正文、不充当事实源；每项保存范围、底层身份、版本、状态、来源依赖与构建时间。主题摘要不能作为事实直接引用。
- 联系人与本人资料集合分别维护单调修订；有效写入、修正、删除及影响资格的变化推进修订，回滚和真实 no-op 不推进。修订不是条目计数，也不是旧来源资格证明。
- 派生目录须对应合法当前资料；过期、缺失或构建失败时明确待更新并按任务恢复。源资料、人工决定、版本及实际依赖变化使相应派生结果失效；本人资料不复制进每位联系人的目录。
- 回复选择当前有效 L1 记忆，按正文做确定性中文词法排序；相关性门槛及联系人／本人各自独立的预算统一见[有界选取与完整请求预算](reply-generation.md#有界选取与完整请求预算)。近期相关对话优先进入本次语境，但事实冲突仍按来源、事件顺序与人工保护裁决，不能只凭较新的导入或保存时间覆盖旧事实。排序实现见[排序器](../../backend-ts/src/retrieval/retrieval-ranking.ts)，检索不要求用户设置固定常驻记忆。
- 导航按有界底层 ID 读取，历史入口不能退化为无界扫描；最终读取仍复核范围、来源、状态、版本和有效期。回执只记录实际模型可见输入，旧空回执不补成“已查空”或“已查到”。
- 按 [ADR-162](../adr/162-local-reply-context-and-independent-model-lanes.md)，回复冻结并复验本轮实际来源、版本、保护修订、正式发布及完整成员与递归依据。集合修订用于资料管理与派生更新，不再因无关新增使在途回复失效；实际使用依据被纠错、删除、换图、隔离或撤下时仍须拒绝出站和保存。

记忆处理在本地模块执行，历史与增量分别调度并冻结输入，L1 提取、L2 场景维护与 L3 画像保持各自资格和发布边界。待决定候选、后续整理和等待窗口不单独阻止新的合格 L1；主动暂停、未知调用及真实来源故障保留保护。阈值、完整状态和调度流程集中见[记忆处理](memory-processing.md)。

## 回复请求状态与幂等

回复使用持久接纳且仍有效的本机资料，不要求当前微信读取进程的活守卫，不恢复或等待同步及记忆处理。该资格不授予外部读取、不解除旧失证围栏或删除排除；资料为空时仅使用本次独立输入并保留真实覆盖限制。

记忆页查看沿用同一已保存来源资格：读取授权暂时不可用（如重启后尚未重建）时仍显示正式记忆的正文与来源日期，并标注“来源待重新核验”；来源被删除、隔离、换绑或失证时仍隐藏，采纳、修改、纠错等写入继续要求实时核验。[ADR-167](../adr/167-memory-page-saved-source-display.md)

- 请求固定当前联系人、规范化输入、输入来历、动作、实际资料快照和使用的 Skill 修订；模型建议不能冒充用户已确认意图。
- 幂等范围为经验证的 `owner_id + contact_id + request_key`。同键同摘要复用请求，已完成时返回持久结果；同键不同摘要返回稳定冲突，有效租约内运行的请求不能重复并发。
- 失败或租约过期后可按原身份重试并记录尝试，成功结果只持久化一次。未知外部调用按台账处理，不能盲目重放。
- 继续候选或旧讨论由用户明确发起，服务端重新核验同一 owner/contact 及实际来源依赖，不能自动推断最新候选或其发送状态。新请求只选择当前有效资料，客户端不能任意指定历史发布。

助手会话、候选保存与恢复的详细合同见[回复生成](reply-generation.md)。

## 后台任务的数据边界

- 完整业务任务、可恢复步骤和执行尝试分别记录；短回复或轻量操作不强行拆成长期任务。步骤由确定性业务模板建立，模型不能自由增删、跳过或重排。
- 任务固定账号、联系人或本人范围、实际输入和业务引用；本人任务不能通过任务 ID 命中联系人任务，联系人列表也不混入全局本人任务。任务记录只保存元数据及业务引用，完整模型追踪沿独立生命周期保存。
- 同范围冲突写入按有效租约与版本合同串行；领取与状态变更原子完成，过期租约恢复仍须复核旧执行者及迟到结果。幂等步骤不能产生重复消息、候选、索引或删除副作用。
- 成功依据实际步骤和验证结果，不能由百分比、线程存在或模型结论宣布。临时网络或模型错误最多自动重试 3 次，恢复复用任务和已成功步骤；未知模型调用不得自动重放。
- 用户停止推进控制代次并撤销原租约，迟到结果不得提交。恢复保留原范围、预算、成功步骤与回执；删除任务沿自身删除合同恢复。活动任务持续保留，终态记录保留 90 天后清理。

任务的具体状态枚举、调度与停止恢复见[核心流程](core-flows.md)及对应模块合同，旧表结构和迁移票号不作为数据接口。

## 页面中的联系人范围

整个 App 共用当前联系人。顶部选择器搜索已有名称、明确选择后切换；输入小窗同步这一对象，记忆、详情、导入和调试页面随之切换。联系人目录管理微信关联与读取授权，不借普通列表点击隐式切换表达对象；首次不默认选人。

记忆页面的“对方”“我”“待确认”保留分类但清除旧详情、编辑态和迟到请求结果。未选联系人显示提示，不回退到全局本人列表。记忆处理主卡只呈现当前联系人的轮次、处理量与待处理阶段，无轮次时如实显示，不能混入本人任务；依据为 [ADR-145](../adr/145-contact-scoped-memory-processing-view.md)。

“我”只展示来源可核对到当前联系人的本人记忆；owner 存储及回复检索范围不随页面筛选改变。无联系人来历、混合联系人来源及全局本人摘要不出现在此视图。失效或过期项可在相同来源范围内管理回看并标记不再引用；筛选不删除底层资料。

从此视图手动补充本人资料须保留当前联系人来源关联，查看历史、修正、删除及撤销自动更新同样核验范围，不能凭昵称或文本猜测来源。

## 来源依赖与删除

- 每条候选和记忆保留可解释的消息／来源依赖，不能只保存摘要。完整提取窗口的新鲜度依赖与正文成立所需的消息集合分别记录。
- 同一规范消息的多个有效来源引用是替代关系；删去一个引用后仍有合法来源可保留消息。正文要求多条消息共同成立时，必需消息构成合取依赖，任一必需消息失去全部来源就清除依赖正文。无关窗口背景删除不能误删独立成立的事实。依据为 [ADR-063](../adr/063-bounded-runtime-evidence-and-source-dependencies.md)。
- 人工确认、修正、去重及本人资料回退不得切断原来源依赖。旧替代语义或未知记录沿原合同处理，不回填成新的合取证明；来源重新匹配也不能恢复旧资格。
- 来源删除清除失去支持的规范消息、候选、记忆、目录、概览、场景文档、画像和回复派生副本及缓存；仍有其他合法替代来源的资料保留并重新核验。联系人和本人资料及其跨联系人使用副本均进入实际依赖闭包。
- 用户若明确另存为独立手动资料，须创建新的记录、清空来源与候选依赖并保留手动来历；普通修正或确认不等于另存，不能据此免除来源删除。
- 前台瞬时预览不是消息来源，清除它不删除合法 CLI 消息；取消读取授权、来源暂时不可见与真实资料删除分别处理。
- 只有内容及派生副本清除并通过不可检索复核后才能标记 `deleted`；请求中、执行中、失败或未知必须保留真实状态。软隐藏、目录移除或 UI 消失不证明删除完成。
- 导错联系人时不能原地改 `contact_id`；应删除错误来源及派生结果，再由用户重选后导入。重新主动导入已删除文件仍须创建新来源，不静默恢复旧记录。
- 删除联系人清除其来源、消息、关系资料、讨论、候选、受管副本、绑定及实际派生依赖；保留必要排除与最小删除凭证，不能保留名称、原文件名、文件哈希或聊天正文。详情、备份、外部副本和停止读取的边界见[隐私与删除](privacy-deletion.md)。
