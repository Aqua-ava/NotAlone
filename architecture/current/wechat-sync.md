# 现行微信同步与前台定位

后台正文同步、前台联系人定位和候选生成是独立流程。身份对象见[数据契约](domain-data.md)，授权、出站及删除见[隐私规格](privacy-deletion.md)，回复使用本机资料的规则见[回复生成](reply-generation.md)。

## 连接、联系人与同步范围

产品默认仅同步用户所选会话；明确授权当前账号全部私聊后，范围包含该账号现有和以后新增的私聊。全部范围允许按稳定渠道身份自动建联，昵称、备注和导入文件不创建或合并身份；同名不同账号分开，稳定身份冲突由用户处理，撤销／删除排除项不会随扫描或重启恢复。切回仅所选停止自动纳入，保留仍有效的已有绑定，范围变更不替代总开关。

正常首次连接按「连接账号 → 选择联系人 → 确认并开始同步」进行：

1. 完成本机本人初始化，用户主动检测并核对读取工具配置的候选账号。检测不证明前台微信登录账号或会话可读；工具准备也不授予正文权限。
2. 账号确认事先说明会话名单访问，只保存 selected 范围。成功后读取必要元数据并丢弃夹带摘要，进入默认不勾选的名单；支持搜索、多选、已选查看和分页。搜索词不持久化或外发，普通刷新不重新触发授权。
3. 最终确认说明所选会话本机可读的历史及后续消息；复验账号、来源、稳定身份和名单代次，先保存授权，同一连接确认成功后才开启同步。部分失败或连接换代不自动放行；开启失败保留已建联系人并给出同步设置入口。
4. 后续添加联系人保持已有总开关状态，暂停不自动恢复。响应丢失和重启按原操作身份核对，不重放授权。

全部私聊是已确认的产品可选范围；ADR-110 的“不启用全部私聊”限定了当轮 SQLite 实施范围，不能据此取消产品分支，也不能据产品决定宣称当前入口已开放。当前能执行的范围以正式入口、配置及相应验收为准；空 SQLite 不继承旧 PG 授权或排除记录。无可用工具时明确未完成，不宣称独立机器交付可用。

依据：[范围决定](../adr/089-all-private-wechat-sync-scope.md)、[SQLite 授权边界](../adr/110-selected-sqlite-contact-read-grants.md)、[首次选人流程](../adr/142-first-connection-contact-selection.md)。

## 历史、增量与恢复

```text
有效范围 + App 运行 + 同步总开关开启
  → 稳定身份与读取来源核验
  → 每个首次进入范围的私聊分页读取本机当前可读历史
  → 历史及期间新增消息以稳定身份去重、保存来源与独立检查点
  → 持续读取变化页，提交后发布无正文消息事件
  → 界面按当前联系人读取已保存正文；记忆另行调度
```

- 每个授权私聊首次同步本机可读最早文字到当前，再接续增量；仅所选和全部范围使用同一历史规则。旧授权若未包含历史，须明确扩展后才能读取。文件导入只补充已有单一联系人，不作为逐联系人授权历史的默认准备方式。
- 每位联系人保留独立历史覆盖与增量游标；新旧用户及以后新增私聊同样适用。只有本机可读范围已追平才能报告完整，空结果、故障或本机缺失不能冒充完整；也不承诺恢复本机不存在的记录。
- 正常重启按已接受的持久检查点和变化页恢复，来源不变时不再每次全量重扫。新历史、增量和重复扫描按稳定消息 ID 幂等保存；同一规范消息可有多个有效来源，不重复堆积正文。
- 共享单个 CLI 进程，业务操作持有独占租约；释放会话状态后才切换联系人，取得租约后再次复验账号、授权及来源。读取结果仍严格按 `owner_id + contact_id` 归属。
- 关闭同步或退出应用立即停读；重新开启只在有效范围补齐可检测缺口。暂时故障按绑定退避，单联系人故障不阻断其他联系人。低频重探不把已删除或无本机记录的会话标为完整。
- 当前联系人仅作为已有授权内的读取优先提示，不新增资格、不依赖微信焦点或 OCR。每片有有限执行预算，超时不采纳部分结果或推进可靠游标；成功检查时间与消息追平状态分别表达。
- 同步数据提交成功后才发布事件。事件本身只有标识，界面按当前联系人读正文；消息入库与记忆处理分离，记忆失败不回滚同步。
- 历史未开始、同步中或不完整都不阻塞已确认联系人使用当前合法本机资料生成；实际覆盖进入依据，不额外索要“接受不完整”确认。

来源无法独立认证时停读；来源重新关联、重新认证与一般重试分别处理。旧失证资料保持原围栏，新来源或新代次不能补签旧证明；删除／清空排除及终态抑制须延续。无法可靠映射时继续停读，不能用清库、改身份或解除围栏代替认证。该规则与回复读取已接纳本机资料的资格分开。

依据：[首次历史](../adr/100-authorized-private-history-sync.md)、[来源合同](../adr/113-sqlite-private-history-source-contract.md)、[变化页](../adr/133-page-delta-private-history-sync.md)、[共享读取进程](../adr/151-shared-wechat-cli-process.md)、[重新认证](../adr/144-preserved-history-source-recertification.md)。旧 `sessions --follow`／逐次 tail 与固定轮询参数保留为[历史实现说明](../history/core-flow-implementation-notes.md)，不作为新读取器的强制接口。

## 图片、引用与消息状态

图片获取只在用户授权消息范围内进行，唯一来源关联、完整读取及实际解码通过后才能成为受管副本；失败保留消息及具体状态。图片保存和记忆派发分开，图片任务不直接调用模型、不驱动微信下载、不扩大读取范围。

| 图片状态 | 自动补查规则 |
| --- | --- |
| 旧未知角色、缺副本或失败 | 遍历当前有效授权的联系人，持久退避为 1 分钟、5 分钟、30 分钟、6 小时，最多 24 小时；重启或重复唤醒不重置。 |
| 已确认缩略图 | 按 60 秒窗口有界复查，取得合法主图后更新受管副本；无改善时保留旧副本。 |
| 旧未知副本仅取得缩略图 | 新旧内容 SHA-256 一致才补分类，内容不同或依据不足保留旧副本与未知状态。 |
| 已确认主图／原图，或用户已清除结果 | 主图不自动重取，清除结果不自动恢复。 |

资源角色与原图证明独立：主图不等于发送时未经处理的原图，缺原图证明不掩盖已确认主图；不按尺寸或文件大小猜角色。依据随副本保存和删除，关同步或退出时停止补查。图文记忆处理规则见[记忆处理](memory-processing.md)。

引用回复在正常历史页和增量页中同时读取本次正文、引用快照与原消息标识，与消息、来源和游标同事务保存。历史占位按独立版本进度补齐，保留原 ID 与时间，不重置文字游标；原文或来源删除须清除引用副本。引用缺失保持未解析，不把快照冒充当前消息。

已采纳的重复扫描去重不代表撤回功能完成。撤回正文可查看但不得参与新生成或记忆的目标仍暂缓；当前继续执行来源资格与删除保护，不据未核验状态数字推断已读、送达、撤回或正文资格。微信端删除也不自动代表 NotAlone 资料删除。

依据：[图片角色](../adr/155-image-variant-display-and-thumbnail-refresh.md)、[自动补查](../adr/156-automatic-image-reconciliation.md)、[引用同步](../adr/141-inline-quoted-reply-sync.md)、[去重与撤回范围](../adr/128-deduplicated-wechat-message-storage.md)。

## 前台识别与联系人跟随

每轮只在微信为前台且会话可见的唯一窗口内获取一帧，在端侧内存分析布局，再仅 OCR 顶部名称区域。原始帧默认不持久化或上传；不 OCR 正文或联系人列表，不切换、滚动微信，不读取其他 App。微信离开前台或助手获得焦点时停止新视觉采集，已授权 CLI 同步独立继续；CLI 故障不回退为 OCR 正文。

名称匹配关联配置账号的已有稳定联系人：

- 使用有界全类型会话元数据及完整名称候选；唯一 private 的稳定 locator 对应同账号 active 联系人的 verified 既有绑定且保存名称一致时关联。身份投影不按正文 read grant 过滤，不创建／合并联系人，不授予或恢复读取授权，不宣称独立认证了前台账号。
- 完整名称命中优先于编辑近邻。不存在完整命中时才作有限消歧；保留名称算法 0.30 下限，低分路径仍需至少两个真实文字锚点。原始 OCR 30%／50% 不单独阻断已成立的唯一匹配，无关群名缺失不全局否决既有私聊，也不逐人要求新的桌面证明。
- 同名、改名、已知群冲突、截断、未知类型、名单达限、超时或其他实际质量失败仍需选择或新观察，不能沿用旧身份。群标题人数尾缀只是类型线索，不剥除后授予私聊身份。
- 已知群聊暂停新的联系人匹配及生成，清除群标题预览，保留原私聊内容；返回新鲜有效私聊观察后可恢复，历史失败不永久阻断新观察。已授权私聊后台同步保持。

前台通过独立只读 SQLite Worker 获取账号、联系人及绑定快照，名称元数据使用独立窄协议 CLI 客户端，与后台历史和记忆写入分别排队。前后快照、账号、来源、删除代次逐轮复验；附属读者纳入删除持有者，排空及退出必须实际关闭连接。

原生观察按请求串行复用进程，仅保留模型预热状态，不复用旧帧、名称或身份。预热只用合成图，ready 前不截图；取消、超时、权限熔断或关闭回收进程，下轮可重建。在途变化合并为一次后续复查，技术失败退避；暂时名单故障保留模型预热，但不保留识别资格。

读取繁忙、超时或失败撤销当轮资格，等待下一次可靠核验，不新增永久人工门。现有 UI／HTTP 3.5 秒、后端 3.2 秒、原生 2.5 秒预算和五秒新鲜度不构成一秒体验保证；一秒仅是正常切换的优化目标，首次启动、预热和恢复分别测量。

依据：[视觉范围](../adr/049-automatic-foreground-window-layout.md)、[单帧跟随](../adr/050-continuous-single-frame-contact-follow.md)、[名称关联](../adr/132-existing-contact-name-matching.md)、[独立读取通道](../adr/159-foreground-read-channel-isolation.md)。

## 快捷键、内容恢复与任务归属

一个助手窗口按联系人保留会话、草稿、编辑与任务。快捷键只唤出窗口，识别、打开、切换或恢复内容均不触发生成，也不替用户开启同步。

显式选择联系人只确认本次对象，不建立独立手动模式或关闭自动跟随；返回微信后的新鲜有效匹配可以切换对象。重开 App 须重新选择或取得有效匹配。识别失败保留原内容并标明归属与未确认状态，新的有效观察或明确选择前不接受新生成；进入助手造成的正常定位暂停保留最后确认对象。

联系人身份先发布，内容异步恢复；快速切换可合并途经联系人的读取，迟到结果不得覆盖当前对象。重复识别不重置草稿，有草稿／任务不新增切换确认门。

每次已接纳生成固定原联系人、助手会话、请求和输入版本；切换只改变展示，不取消仍有效的原任务，结果只回到原会话。新消息只提示，不自动替换或重启候选。删除、真实来源失效、授权变化和退出中断按各自合同处理；仅同步暂停或微信不可用不撤销合法本机回复资料。

依据：[显式选择仍跟随](../adr/158-contact-selection-keeps-foreground-follow.md)及[本机回复资格](../adr/162-local-reply-context-and-independent-model-lanes.md)。
