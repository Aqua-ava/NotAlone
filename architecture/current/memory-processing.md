# 现行记忆处理与后台调度

本文说明何时处理已保存资料、怎样采纳记忆及何时算完成。身份和资料对象见[数据契约](domain-data.md)，全过程记录见[提取追踪](memory-extraction-trace.md)，出站、删除与副本清理见[隐私规格](privacy-deletion.md)。本页的规则不等于真实模型质量或渠道验收已通过。

## 输入与处理边界

- 一次导入或处理只属于一个已确认联系人；本人资料使用独立 owner 范围。混有多人、作者无法可靠区分或损坏的输入必须拆分或拒绝。文件及展示名不创建联系人，也不授予微信读取资格。
- 消息与来源先可靠入库，记忆是独立派生处理；提取失败不回滚消息或同步游标，不阻塞历史同步，也不阻塞基于当前可用资料的回复。
- 记忆输入共同使用同一联系人的聊天文字与实际图片，保留顺序、说话人和来源；图片只限当前可查看的已保存图片（标准图或高清图；缩略图不保存），仅缩略图或从未取图的图片消息保持未就绪（[ADR-197](../adr/197-chat-image-and-memory-image-input-consolidated.md)）；媒体占位不能冒充图片内容。文字、图片由内容模块组装，记忆正文及检索表示仍为文字。实际图片可按[ADR-197](../adr/197-chat-image-and-memory-image-input-consolidated.md)仅在内存中生成规范化发送版本：正常长边上限 1536、单张降级 1024、JPEG 质量 85、单张最多 2 MiB，透明白底、应用方向且动画只取首帧；不保存派生图片。来源仍引用原图 `file_id`／`sha256`，运行追踪另记实际发送尺寸、格式与字节。批次按实际配置有界选取，完整输入及未观察到的内容如实记入追踪。
- 本地领域模块构建提取、核验、裁决、主题和长期背景的业务提示。模型只提出结构化结果；来源资格、事务、版本和采纳由确定性业务代码控制。
- 每个阶段开始时冻结自己的实际输入；运行中新到资料留作后续工作，不扩张已冻结批次，不用新资料补签旧证明。

依据：[聊天图片合并决定](../adr/197-chat-image-and-memory-image-input-consolidated.md)、[记忆领域实现边界](../adr/104-tencent-source-memory-engine.md)。

## 提取、核验与采纳

```text
在合法范围领取并冻结一批目标及必要上下文
  → 联合文字和实际图片提出记忆候选
  → 在同一有限窗口逐项核验主体、正文、限定与实际来源
  → 与仍有效的旧资料进行有据的新建、更新、合并或跳过裁决
  → 同一事务复验实际输入、版本、人工保护与删除状态并保存
  → 记录逐项结果、完整追踪与真实处理进度
```

1. 默认自动路径通过结构、独立来源核验及适用的条件、事件和版本检查后自动裁决。置信度、语用、不确定性痕迹和风险标签本身不新增人工审核门：`alternatives` 含自由文本的候选继续裁决并自动采纳，采纳历史记 `adopted_with_alternatives`；低于 0.5 的低把握候选在提取解析后丢弃并记 `low_value_dropped`，不算内容拒绝（[ADR-174](../adr/174-align-tencent-uncertainty-degrade-not-intercept.md)）。自动采纳必须带来源、标为 `auto`、可查看和撤销。
2. 来源支持不等于现实为真，也不证明过去状态今天仍成立。计划、可能性、转述和未知第三人不能改写成已发生的确定事实；限定、时间精度和条件随记忆保留。
3. 人工修正和保护优先。产品裁决采用新增、跳过、更新、合并四种语义，内部 `add / noop` 与历史 `keep` 可兼容。主题相关的新信息可新增；同一事实有来源支持的状态、条件或纠错变化可自动更新；新候选与 1～8 条旧记忆的互补内容或同一事件不同阶段可自动合并，最终正文须另行核验。主张／条件变化标记、事件或时间差异本身不新增人工门；新旧合法来源必须支持对应事实、时间顺序与原话限定，未知时间仍保持未知（[ADR-184](../adr/184-source-grounded-memory-update-and-merge.md)）。
   原始来源中未解决的矛盾、主体或关系无法核实及人工决定冲突继续保留待定。动作／关系不兼容、核验不支持或证据协议异常保留实际原因（`memory_relation_conflict`／`memory_relation_unsupported`／`memory_relation_inconsistent`／`memory_relation_evidence_incomplete`）；不能单凭技术原因码认定原始记忆冲突或让用户替模型判断。独立关系的证据只须引用候选自身来源；同义重复可自动跳过并记 `skipped_duplicate`。矛盾沿实际事实 ID／版本进入回复不确定性，依赖失效的旧分层资料撤下使用资格。
4. 发生时间 `event` 是可选标注。无法核实时只丢弃该标注、记录 `time_unverified`，正文按其余证据结果处理；该标记只在核验结果与执行事件中记录，不写入记忆事实字段。`figurative_type=literal` 仅表示按字面理解，不新增解释；核验明确判为 `supported` 时可不单列该标记的引文编号，字段缺失、非法引用及未定／无支持判定仍不接纳，也不补造引用。非字面表达及正文、主体、分类、语义、有效起止 `valid_at`／`invalid_at` 和适用条件仍须逐字证据核验。整体核验不确定不能被字段降级擅自升级为通过。
5. 来源聊天时间、事件时间、保存时间和有效期分开；缺失或不能核实的时间保持未知，不以“瞬时状态”推定当天失效。晚导入或较晚回忆不自动覆盖较新的真实状态，早期补导入须保持幂等。
6. 同范围真实来源、解释版本和人工保护在写入前再次复验；回执未知、删除、撤销或证明丢失时不先失效旧记忆。正文追踪写入失败独立停止该批，保留已提交结果，不推进水位。
7. 记忆处理只纳入当前内容插件支持且实际内容可用的消息；其他类型的占位不进入模型，也不计为已处理。文字与实际图片共同进入提取、来源核验、新旧记忆比较和合并；内容模块统一准备输入并复验引用，记忆流程不因来源类型单独增加人工门。文字证据定位原文，视觉证据绑定实际文件版本，模型观察描述不冒充原文。比较页同时受旧记忆数量与实际图片容量限制，不能删减来源绕过预算；真实冲突、来源不足及人工保护仍按原规则处理。
8. 来源核验的主体归属须落在原文的人称或逐字主体上：模型报的人称位置数错一两位时，按引文中同种类、邻近且唯一的真实人称词定位。省略主语句（常见中文零人称句）只在 `resolution=unique_context`、引文全部来自同一发送者、不含你／您或复数人称词、且判定主体恰为该发送者时按发送者定归属；`explicit` 不得凭发送者自签，第三方、共同主体、含你／您的句子仍须逐字提及。

采纳边界依据 [ADR-085](../adr/085-source-verified-automatic-adoption.md)、[ADR-081](../adr/081-source-grounded-memory-time-and-conditions.md)和 [ADR-150](../adr/150-optional-event-time.md)。旧语用／风险／维度门及 grounded 协议只在[历史协议](pragmatic-interpretation.md)明确限定的范围内使用。

## 内容结果与技术故障

| 情况 | 处理结果 |
| --- | --- |
| 单条候选结构不合格、来源语义不支持或引用不成立 | 拒绝该候选并记真实原因；其他合法候选继续。 |
| 一批没有候选，或所有候选均被内容核验拒绝 | 按已处理、无新增收尾，保留拒绝数量，继续后续批次和适用阶段。 |
| 图片局部读取／规范化失败，或图片调用明确返回终端传输失败；官方终态TIMEOUT须有当前原生请求身份且首响应头/状态均未观察到 | 在原冻结目标树上有界二分、单图更小版本一次，每个不同请求单独记账；仍失败的单项隔离，其他目标继续。隔离数与成功数分开，连续三次同类隔离持久暂停。 |
| 模型未配置、凭据／认证／服务故障，或整批／整次协议、证据合同异常（包括无法解析、缺项、非法证据、来源绑定不成立） | 保留阻碍；仅可确认安全的暂时故障进入有限重试。 |
| 未知物理调用回执、授权撤销、来源失效、删除或预算耗尽 | 保持受阻或暂停，不借新批次、另一个队列或重试重置预算和调用身份。 |
| 正文追踪存储失败 | 停止该批，不计作模型内容拒绝或可自动跳过的非法输出。 |

全部候选拒绝不会使整轮失败；技术故障也不能伪装为“无新增”。每条真实原因、调用身份、实际处理范围和后续阶段结果分别留存。依据：[ADR-149](../adr/149-content-rejection-is-not-failure.md)。

图片恢复按[ADR-197](../adr/197-chat-image-and-memory-image-input-consolidated.md)执行：明确终端失败不等于未知执行回执，不能伪造HTTP响应或费用。首响应前TIMEOUT仅在fetch已开始、原生undici观察到并绑定当前请求、且没有响应头或HTTP状态时进入图片降级；非原生／无请求身份的超时、有HTTP响应、取消、真正未知、授权撤销、来源失效和ACK丢失均不进入此降级，保持原响应／未知保护。隔离项保留原图依据、可查看并稍后显式重试；旧轮隔离在新轮出现后仍可恢复。重试不绕过待确认门槛，新增本人贡献须继续交接；图片、来源和联系人删除清除隔离／重试事实与逐图诊断。

## 历史、增量与后续整理

历史和增量按稳定消息身份及持久启用边界分类；队列是已保存资料的处理范围，不是新的读取授权。

| 工作 | 何时安排 | 交接规则 |
| --- | --- | --- |
| 历史 L1 | 当前联系人的本轮历史导入完成后，自动发现来源有效且尚未成功处理的历史；包含已有积压和启用边界前保存的旧文字与晚到已保存图片。 | 有界分批；批次间先检查到期增量。成功目标跳过；可恢复的中断沿原轮继续，已失败／已退休且释放占用的目标可在后续历史轮领取。隔离项只按显式重试恢复。 |
| 增量 L1 | 启用边界后首次保存且首个来源为 `read_goal.kind=incremental` 的合格文字先登记待处理。静默 **10 分钟**、待处理 **50 条**、最早等待 **6 小时**三者之一满足，且同联系人两次增量 L1 启动至少间隔 **30 分钟**。 | 时间从进入合格待处理队列计算；历史批次不占用或推迟增量启动间隔。 |
| L2 主题整理 | 有效正式记忆新增、正文修改或失效，从首个有效变化起合并 **1 小时**。 | 后续变化并入窗口，不重置锚点；仅保护状态、拒绝候选或无实际内容变化的操作不触发。 |
| L3 长期画像 | 有效主题正文首次可用时可初始化；后续正文变化安排更新，同范围两次 L3 启动至少相隔 **24 小时**。 | 元数据变化不触发，冷却内变化保留且不滚动窗口。 |

- L2/L3 等待窗口、候选待决定和后续整理未完成，不单独阻止独立到期的新 L1。合法 L1 可立即用于回复；来源或底层记忆失效的旧主题／概览不得继续使用。
- L2/L3 可以分阶段、分任务运行，每次发布逐项核验并原子提交完整当前合格集合。L3 的单条未获支持只拒绝该条新提案，其余通过条目可发布；全拒绝不创建空画像，已有有效版本不因失败更新而丢失。原始回执与索引保留，整份协议、来源、版本或容量异常仍阻断提交；阶段等待不豁免完整成员与删除复验。依据 [ADR-181](../adr/181-l3-item-verification-and-partial-publication.md)。
- L2 待处理变化与引发它的正式记忆版本变化在同一事务登记，避免内容已提交但整理需求丢失。
- 合格新文字在历史处理期间进入增量；单联系人失败不终止其他联系人的扫描。新增资料不解除当前范围真实来源、配置、预算或未知调用阻碍。
- 消息提交只登记待处理并唤醒调度，不直接调用模型。调度唤醒失败不回滚已保存消息、来源或游标；启动及后续调度重新发现积压，持久期限在重启后重查，页面读取不是触发条件。
- 统计和领取分开：只读统计复用无正文元数据与批量内容可用性，每批至多 32 位联系人；实际领取逐项复验并冻结。单联系人变化仅唤醒该范围，启动、范围变化及 30 秒兜底重新检查。内存提示不授予执行资格。
- 后续队列的一次同步扫描先缩小到当前范围任务，同一运行的释放资格只核验一次；缓存不跨读取保留，实际领取仍复验。manual运行时的单联系人收尾只持久登记后续需求，未正式启动调度时不唤醒后续Worker；一次手动请求不能隐式启动全owner的L2/L3。
- 失败或退休运行只有在完整调用链已结算、候选与效果占位均已释放时才不再占用联系人。联系人范围代次或本人反馈版本永久失配的暂停轮由产品恢复逻辑安全退休；有效用户暂停和未知调用不自动解除。晚到图片进入下一轮，汇总显示未纳入数量，不扩张旧冻结输入。

调度依据：[ADR-143](../adr/143-hybrid-memory-processing-schedule.md)及 [ADR-152](../adr/152-history-and-incremental-memory-processing.md)；自动调度须先开启[总开关](#总开关)。本人范围独立管理，不套用未经决定的联系人 L1 阈值。

## 总开关

- “记忆自动处理”总开关**默认关闭**，保存在库内（迁移 42），重启保持；既有库升级后同样关闭。关闭时不发起任何记忆模型调用：不扫描建轮、不恢复积压、不续后续整理、不执行主题与概览整理，用户显式的开始／继续也被明确拒绝；同步入库、查看和回复使用已有记忆不受影响。
- 关闭时在途小批完成并提交后停在步骤边界（沿用用户暂停语义，不中止已发出调用）；开启时只继续由关闭动作暂停的轮次，用户手动暂停保持。下文的“App 启动后自动续跑”与历史／增量调度均以开关开启为前提。
- 页面开关与处理动作共用同一份权威状态；失效后先撤下旧值，迟到回执不能恢复旧状态。未核实开关时不提供恢复动作，保存后仍读取失败则保持未知，不宣称已取得最新值。
- 依据：[ADR-166](../adr/166-memory-auto-processing-switch.md)。

## 状态、暂停与恢复

主状态只有 **等待处理、处理中、已完成、已暂停、处理受阻**。提取、核验、主题、画像和自动重试是阶段说明，不是额外主状态。

- 聚合优先级为已暂停、处理受阻、处理中、等待处理、已完成；手动暂停优先展示，原阻碍保留在说明。只有全部适用阶段完成或明确不适用，且无待处理输入或未到期窗口，才能显示整体完成。
- 尚无可处理资料且从未处理时显示等待处理并说明暂无资料；状态读取失败显示暂不可用及刷新入口，不猜测成功、失败或处理中。没有有效执行者时不得仍称正在处理。
- 聊天处理数量、产生记忆数量、历史／增量待处理和单批进度分别展示。仅使用持久步骤及已提交批次的实际数量，未知时只显示阶段，不将不同单位相加或估算整个流程百分比。
- 记忆页「对方／我」分类中的处理卡均跟随顶部当前联系人，不回退全局最近轮次或混入独立本人任务。任务和错误详情保留真实范围与执行事实；独立本人处理有自己的 owner 范围。
- 用户暂停保留已完成结果并暂停余下工作；新消息、期限到达和 App 重启不解除暂停，只有明确继续才恢复。读取、刷新、打开页面不启动模型、唤醒 Worker 或重排任务。
- 用户明确要求单联系人完整收尾时，可在总开关开启的手动调度实例中，仅恢复该联系人候选的自动裁决，再沿原联系人任务执行主题资料与长期概览并实际发布。该入口不重新提取消息、不处理独立本人任务、不领取其他联系人队列，也不伪造未来时间满足自动调度窗口；仍复验来源、版本、暂停、删除和未知回执，真实矛盾及人工保护仍保留待确认。
- 主题与概览的正常推进、暂停后继续及启动恢复共用同一份持久任务和各阶段最新步骤，展示投影不作为执行决策输入。画像输入统一应用本任务的主题替换关系，并相对冻结的旧发布计算新增／移除说明；暂停或恢复不能补回已被合并替换的旧主题。阶段结果已经成功保存而尚未发布时，只复验并发布原结果，不重做成功阶段或重发模型；来源、版本、未知回执和删除守卫仍在实际领取及发布事务内检查。
- 安全自动恢复只适用于来源有效、未手动暂停、回执及执行者可确认的工作；保持原任务、成功步骤、来源范围和累计预算。明确继续也必须复验来源、删除、租约和回执；不能扩大范围、开启同步或解除另一项用户暂停。
- 多页裁决每取得一份已结算且落盘的成功模型输出，才可复验并续期本次候选的完整执行组；租期仍为原五分钟，重复进展不重复续期，过期、暂停、来源变化、未知回执或执行者变化均不能借此恢复。单联系人完整收尾可显式重试该联系人已知且已结算的失败步骤，不推进整轮控制修订或启动其他范围；旧成功调用与费用保留，重新调用另行记账，不冒充本地复用。
- 裁决冻结依据包含实际提示词、工具结构和动作兼容规则的策略摘要。策略改变后，旧策略下已完成但待定的结果须重新核验；同策略、同依据的完成结果仍不重复发送。关系核验同时检查拟用动作及关系，不能只因关系有据就认可互相矛盾的动作字段，也不能篡改来源中的变化以迎合动作。
- 主题草稿被独立内容核验拒绝时，可携带真实核验反馈在同一暂存空间内修正一次，再重新独立核验；原生成回合、总调用、范围和工具权限不重置。再次失败保留真实失败。显式单联系人完整收尾可在冻结依据仍有效且旧调用均已知结清时重试失败的主题或概览阶段；旧步骤和账本保留，当前状态及发布检查按各阶段最新执行判断，不能以旧成功掩盖较新失败或未知。
- **裁决类未知回执的用户放弃重试**：未知回执默认不自动重发。只有未知全部来自裁决阶段（裁决、关系核验、合并核验）时，后端才发布 `abandon_unknown`；提取核验、任务级或主题／概览阶段的未知不提供。该次调用占位整轮目标资料，未核实前同轮其余候选停止领取，不制造无调用记录的失败尝试。用户二次确认后，该调用记为 `failed/unknown_abandoned`，`settlement_state` 与回执保持 unknown（成本仍记未知，可能重复计费），占位释放并推进控制修订后重新裁决；裁决只在成功输出后于事务内写业务数据，重发不产生重复写入。动作写入 `adjudication_unknown_abandoned` 事件（actor=user）。不做超时自动清除，也不提供给其他阶段。已完成裁决且依据（候选、同范围记忆版本、对比池）未变的候选，继续或放弃重试时不重复发送模型请求；依据变化才重新裁决。失败原因保留底层稳定错误码与供应商失败分类（名称、码、HTTP 状态），不带上游消息。
- 明确停止使原执行租约失效，迟到结果不得提交。无法核验归属的存量任务进入独立隔离，当前 Worker 和新轮次不能领取；新任务成功不能倒推旧任务完成。
- 裁决与文档执行器的同范围复用、冲突拒绝和关闭排空使用同一份在途登记，已知结果的本地发布重放同样登记。关闭先停止接纳，等待在途工作实际结束后才关闭模型端口；失败可重试原关闭操作，内存登记不替代持久任务、步骤或模型回执。[ADR-194](../adr/194-single-runtime-facts-and-reply-preparation.md)
- 处理历史默认折叠，保留原停止、失败及中断记录；技术 ID 与错误码进入详情。主卡显示中文原因和下一步，只有满足安全恢复条件才提供继续入口。

依据：[统一处理生命周期](../adr/107-unified-memory-processing-lifecycle.md)、[存量隔离](../adr/108-isolate-unresolved-legacy-memory-processing.md)、[处理卡范围](../adr/145-contact-scoped-memory-processing-view.md)。

## Worker 与模型许可

记忆提取、来源核验、裁决／合并及 L2／L3 整理使用同一组用户可配置的记忆模型参数，与回复参数独立。思考可选关闭、low、high、max，温度范围为 0–2；默认关闭思考、温度 0。开启思考时供应商忽略温度。参数保存与生效沿 [ADR-189](../adr/189-editable-model-thinking-and-temperature.md) 的安全重载规则；不改变 strict 核验合同、内容准入或既有处理结果。

后台采用持久任务、步骤和 Worker；步骤模板、租约、状态迁移和成功判定由业务代码控制。只有语义步骤调用模型；模型不能领取任务、写任务状态或宣布完成。成功业务步骤之后还须通过确定性完整性核验。候选回复保持独立有界执行，不进入记忆 Worker。

同联系人冲突写入按租约与版本合同串行；不同联系人有独立待处理窗口。等待 L2/L3 不占执行租约。通用任务的重试上限与无正文元数据留存期统一见[后台任务数据边界](domain-data.md#后台任务的数据边界)；成功步骤不重做，过期租约接管仍需证明旧执行者和调用状态，未知回执不属于可盲重试故障。含正文追踪另按来源及用户删除合同保留。

同一提取任务可按批次流水线并行提取与核验，采纳、写入和水位仍按批序串行。唯一 DSH 模型宿主与统一台账提供两类独立许可：前台固定 1 路，后台 N 路（默认 3，可配置 1–4），互不借槽、互不等待清空，同类 FIFO。已授权但未结算的调用继续占槽；孤儿只冻结所属类别。全局暂停、配置切换、停止和账本故障仍保护两类调用，运行期孤儿须等真实结算；重启须证明旧执行者停止。退出只等待真正在途的调用（有上限，默认 3 秒），不等待孤儿：进程内没有任何路径会结算孤儿，其权威记录在 SQLite 台账，下次启动仍按未知调用阻塞，退出本身即证明执行者已停止。许可由同一宿主内共享的仲裁端口管理，SQLite 台账保留调用与结算权威；不再通过 socket、自检进程身份或独立 journal 重复记账。

旧资料升级任务不再领取或重跑，移除入口不删除已保存记忆；旧比较和工作副本仍进入删除闭包。同步、记忆处理与 Skill 学习各有独立范围和控制入口，互不冒充授权。外部发送、跨范围读取和无预算自治循环始终不属于这些后台能力。

依据：[任务外壳](../adr/007-background-task-steps-and-worker.md)、[批次并行](../adr/099-parallel-batch-extraction.md)、[独立模型许可](../adr/162-local-reply-context-and-independent-model-lanes.md)。
