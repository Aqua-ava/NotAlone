# Skill Library（Skill 库）

本文定义当前回复 Skill 的目录、读取、范围与生命周期合同。正常 SQLite 入口使用授权目录中的只读包、受核验的内容修订和 DSH 受控 provider；已采纳但尚未在该入口开放的学习与发布合同单列在后文。旧框架、旧表结构和阶段验收记录见[历史记录](../history/skill-implementation-notes.md)。

## 1. 作用与范围

Reply Skill 是影响本次候选表达的策略文字及静态素材，属于一个 Owner。它不是联系人事实、关系记忆、Tool 或长期表达偏好，不能直接修改这些资料或发送消息。通过技术及来源核验的全局 Skill 仅对所属 Owner 的已确认联系人可用，不跨 Owner 共享。

正常回复根据本次意图和受控目录自动选择零个或多个相关 Skill；没有合适项时可以不加载。界面显示实际读入回复的策略，不提供强制手选步骤。显式 `selectedPackageId` 兼容入口只定向一个包，不改变正常自动入口的组合规则。

特定教学视频在项目外完成清洗；进入目录的是整理后的规则、步骤、案例和反例，不是原始视频或自动收藏的表达样本。Skill 包不默认接收联系人资料、聊天原文或候选正文。

内容优先级为产品安全与权限约束、用户本次明确要求、联系人已确认事实、当前 Skill 策略及示例。Skill 文本及 `allowed-tools` 等声明不能授予文件系统、Tool、MCP、Shell、网络、子 Agent、写入或聊天发送能力。

## 2. 授权目录、包身份与内容修订

### 2.1 当前存储合同

宿主配置并授权目录根，自动发现其合法直接子目录；管理接口和模型均不能传入任意根目录。原 Skill 目录保持只读，SQLite 保存包身份、归属、启停及来历、当前修订、物理定位、清单与内容摘要、来源资格和删除相关状态，不复制已发布正文或资源字节，也不从旧 `.versions` 目录猜测审核或启用历史。

`owner_id + package_id` 是稳定业务身份；路径、设备编号和 inode 只定位当前物理目录。每个修订的内容锚点不可变，技术更新建立新修订。旧修订失效后，即使字节恢复相同也不能复活；旧正文只可从仍合法的实际调用记录中追溯，不能承诺原目录提供文件历史、回滚或恢复。

正文与资源是同一受核验版本的组成部分。每次读取核对实际完整内容与本轮固定修订；目录摘要、选择事件或 DSH 缓存均不能代替字节与业务资格复验。数据库缺引用、空库、目录消失或包不可用，不构成删除用户原目录的授权。

### 2.2 包结构与技术校验

```text
reply-skill/
├── SKILL.md
├── references/       可选：长说明、规则和案例
└── assets/           可选：受控静态模板或素材
```

`SKILL.md` 必须声明 `name` 和 `description`；目录名与 `name` 一致，名称使用小写字母、数字和单连字符，长度 1–64。描述说明用途与触发场景，最多 1024 个字符；正文没有强制标题，可按需要包含适用边界、步骤、好坏示例及资源路径。格式依据见 [Agent Skills 规范](https://agentskills.io/specification)，本项目实际支持的校验以当前锁定实现为准。

辅助资源使用包内相对路径，记录媒体类型、大小和内容哈希；仅在对应 Skill 已成功加载且确有需要时读取。读取拒绝路径遍历、符号链接、硬链接、越界、可执行类型、超限及读取期间变化，不从外部 URL 临时下载。含脚本的包不得进入可运行版本。

当前 macOS 适配器以授权根和逐段目录 FD 进行原生窄读取，以完整安全快照及实际字节复验包身份和修订；缺少该服务时拒绝读取，不回落通用路径读取。它不向模型开放原生文件系统接口。

### 2.3 包限制与整轮预算

| 范围 | 当前限制 |
| --- | --- |
| 技术核验 | `SKILL.md` 最多 500 行、估算 5000 tokens；辅助资源最多 100 个、单个 1 MiB、合计 4 MiB，超限拒绝可用修订。 |
| 一次回复 | 所有 Skill 共用最多 5 次物理模型请求、最多 2 份静态辅助资源和原截止时间，不增加自动重试。 |
| 每次物理发送 | 完整计算本次上下文、Skill 正文及资源和输出预留；组合多个 Skill 不扩大输入预算。 |

运行时资源通过范围和版本核验后返回全文，记录准确 Skill 名称及相对路径；不另加独立单次／累计资源 token 额度或自动裁剪。`SKILL.md` 保留受控 offset／limit 读取。包通过核验不保证某次回复能容纳全部内容；超出模型输入预算沿既有失败流程处理，不绕过上限或静默压缩讨论。

依据：[ADR-093](../adr/093-retain-current-skill-resource-budget.md)、[ADR-136](../adr/136-multi-skill-reply-composition.md)。

## 3. 发现、启停、更新与迁移

### 3.1 自动发现与默认启用

1. 管理刷新和每轮回复前，在已授权根发现合法子目录；发现与完整核验是不同阶段。
2. 新包及既有未知启停项通过目录、格式、编码、内容、资源、范围和安全核验后，才建立可用修订并默认启用；来历记录为 `default`，不能标为用户确认。
3. 已启用包的合法变化自动核验为新修订，不逐次要求用户确认；同内容不重复发布。任何文件失败都不能形成半成品，也不能静默回退到先前失效内容。
4. 用户明确停用记录为 `user_action`。刷新、更新、迁移和重启保留该决定；停用项自动刷新只检查目录身份，重新启用时才核验当前正文。显式管理核验本身不等于启用。
5. 来源撤销或删除不由扫描恢复；带审核来源的变更也不能绕过其审核要求。

每个管理动作以预期当前修订核验并提交，过期动作或重放不能覆盖用户后来的关闭。启停、有效更新、发现及删除资格变化使旧运行锚点失效；在途结果须在发送和提交前再次复验。

管理页显示后台真实状态、中文场景标题与标签、单个可键盘操作的滑动启停开关，并提供刷新。无效、未知、失效及在途状态可辨认；不让用户手填目录名或安装路径。中文翻译保留来源、许可和内容对应关系，不冒充上游逐字摘录。

### 3.2 物理定位恢复与根迁移

目录迁移或设备编号变化时，只能在授权根中用完整安全快照恢复定位。正文及全部资源的清单摘要和内容摘要必须与该包最新历史修订一致；不能凭同名、单文件或任意更早版本认领身份。事务复验 Owner、当前 head、旧定位、最新摘要和来源资格，再建立新定位与新修订；包 ID、启停及其来历保持，旧失效修订与迟到结果仍拒绝。

无核验基线、内容不符或来源失效时保持不可用。停用包的迁移不能自动读正文或启用；需用户明确重新启用后核验。界面说明文件缺失、内容不一致或核验未通过，不向用户暴露内部磁盘身份术语。

宿主明确迁移根目录时允许旧根已不存在，但目标须与数据库最新历史双摘要一致；旧根可读时还要比较两处内容。迁移意图、数据库提交和配置切换必须可重试；准备后目标发生变化时重新核验，完成后由正常刷新重建定位。迁移不扩大授权根，也不恢复来源资格。

依据：[ADR-129](../adr/129-controlled-dsh-reply-skill-discovery.md)、[ADR-135](../adr/135-default-enabled-localized-skill-library.md)、[ADR-157](../adr/157-portable-skill-directory-identity.md)。

## 4. 回复运行与失败边界

当前适配通过正式 DSH profile、官方 scoped registry 和业务受控 provider 装配，领域接口保持框架无关。正常入口不使用旧 `SkillsMiddleware`，也不启用通用 filesystem 插件、默认项目／用户根或 watcher。

```text
核验已确认联系人及本次输入
  → 组装当前 ReplyContext
  → 冻结可用目录与各包当前修订
  → 按本次意图自动选择零个或多个 Skill
  → 按需读取对应正文及静态资源
  → 发送前复验并检查完整预算
  → 生成后复验实际输入、修订和来源，再保存候选
  → 用户选择、编辑并亲自发送
```

运行端只取得目录元数据、当前可用修订正文及该修订的受控资源；不能调用管理接口，也不能直接查询数据库、其他联系人、原始截图或未授权媒体。检索负责关系资料，Skill 负责表达方法，两者不能互相替代。

一次回复对每个包最多使用一个当时当前的不可变修订。读取及返回、每次模型发送和候选提交时，复验 Owner、已确认联系人、启停、来源资格、目录／包修订及实际字节。运行缓存绑定 Owner、联系人和目录修订，scope 释放、取消或资格变化均拒绝迟到结果。

每次实际选择和实际输入分别记录包身份、修订、准确 Skill 名称、资源路径、正文摘要与使用结果。选择或列入可选目录不能算作已加载，读取事件不能冒充已发送模型；界面只显示真正进入本次回复的策略。

任一 Skill 读取失败时，清除本轮已加入的全部 Skill 正文和资源输入，重新核验其余输入，再沿无 Skill 路径生成；不能带着部分失效的多 Skill 内容继续。联系人身份、授权、来源或其他非 Skill 输入失效时停止生成，不能以无 Skill 回退绕过资格。

## 5. 当前读取与删除边界

SQLite 管理包／修订的业务资格，原目录负责当前内容来源，实际模型输入与 DSH 运行副本由各自业务记录承担来源和删除依赖。读取前及实际输入记录写入、发送和提交的同一资格边界内复验；单独的目录检查不能替代正式输入检查。

原包不登记为应用受管文件删除目标。账户删除清除对应包／修订元数据、定位与摘要；联系人或来源删除按其实际参与关系清理 Skill 输入、追踪和运行副本，不清除不属于该范围的 Owner 原包。来源资格封禁后，不能只凭相同文件恢复可用状态。

对应用实际持有的含正文副本，删除须覆盖准备输入、已返回正文与资源、缓存、运行状态、Tool 结果、摘要、导出或恢复副本。先撤销使用资格，再清理并核验；失败保留未完成状态以便重试，不能以某域“不适用”掩盖其他副本。保留的最小删除凭证不含正文或可恢复来源定位。

普通日志仅保留非正文元数据，不复制完整 Prompt、Skill 正文或聊天。需要保留实际调用输入的业务记录必须受联系人范围、来源及删除合同约束。

## 6. 已采纳的学习、审核与发布目标

以下合同保留已确认的产品要求；当前 SQLite 正常宿主尚未开放 Skill 学习、审核发布、版本回滚、删除包、导出或试用的产品入口，不能由旧后端签收记录推断可用。外部原目录的默认启用流程也不能替代这些审核要求。

### 6.1 授权经验草稿

- 学习授权按已确认 `owner_id + contact_id` 保存，默认关闭；同步授权不等于允许新模型用途。启停绑定操作 UUID 和授权修订，旧动作不覆盖后来的关闭。
- 只整理本范围的实际助手任务、用户编辑／选择及同绑定有实际任务锚点的可靠后续观察。纠正优先，普通经验有界合批；模型许可后与提交时持续复验授权、来源和完整参与代次。
- `skill_draft` 保存修订、逻辑 Skill／方法身份、清洗策略、私人依据、目标版本、依赖及无正文来源摘要，与运行目录分离；允许无新增或复用，不直接发布。
- 合法历史材料可以局部核验，但不能放宽当前生成依赖。实际使用偏好保留原始来源闭包；材料被消费或助手会话先删，不消除参与依赖。
- 来源、偏好、记忆、助手会话或 Skill 删除清空受影响工作副本；无正文消费身份防止重复草稿，迟到写入重新复验。选择、复制或接受候选不证明已发送或方法有效。

### 6.2 对照审核与明确范围发布

用户提供审核输入和精确场景，选择联系人、场景或本人范围。旧版本或无 Skill 与草稿共用一次构建的冻结上下文，只替换策略；草稿经隔离只读端口试用，不临时发布，不写消息、记忆或长期偏好。审核输入不是外部来话或发送证明。

编辑递增修订并撤销旧对照；暂留保持待审，拒绝保存明确决定。对照绑定输入、草稿、来源代次、偏好、目标版本及库修订。用户明确确认范围和替代关系后，以同一持锁事务幂等发布不可变内容版本、来源记录及方法映射；已有本地包不能回填为用户审核来历。

授权场景只按用户明确声明逐字匹配，贯穿准备、继续、中断恢复和缓存；入口模式不是场景授权。私人依据留在原取材联系人范围，扩大策略范围不扩大依据读取权限。对照材料、偏好与概览导航都承担删除依赖；来源删除清除发布正文、资源、方法、跨联系人使用副本，以及尚未形成回复请求的明确版本准备输入。

### 6.3 更新、合并、历史与回滚

更新与合并沿用相同对照审核，精确匹配当前目标版本。合并仅处理用户明确确认且适用范围相同的集合，展示旧正文、范围、替代对象和方法延续。历史读取再次核验范围和完整发布来历，可读取仍合法的非当前或停用历史。

回滚同时核验当前版本和库修订，只切换目标的当前版本，保留用户停用，不恢复合并中的其他目标；原操作键不能覆盖后续决定。来源排队删除后拒绝加载、预览、导出及回滚；独立合法旧包可显式恢复为当前，但仍保持停用。

已明确本人或精确场景范围的版本，可在同 Owner 其他已确认联系人范围更新；父发布仍在原取材联系人范围递归核验，私有祖先不能成为其他联系人的独立目标。学习模型只见本联系人的普通材料、清洗策略和合法版本锚点，完整私人来历保留在删除依赖；去身份不自动取得广范围资格。

### 6.4 方法与整个 Skill 的长期停用

用户明确选择方法或整个 Skill，并确认联系人、本人或各自的精确场景范围后，停用立即生效。普通措辞反馈先修改当前候选；长期调整仍形成待审草稿。回复模型没有政策或发布管理 Tool。

政策与不可变正文分开保存，更新、合并及回滚沿方法和逻辑 Skill 祖先继承停用，明确撤销才恢复许可。目录及资源许可只读取方法身份、映射、祖先和政策，不预读未选正文或伪造执行凭证。

实际选择后，投影正文只含允许方法，描述替换为安全说明，未分离的资源拒绝读取；全部停用或无法可靠映射时回退通用回复。执行凭证绑定实际正文、允许方法及相关政策最大修订，不能与 Owner 全局政策修订或目录修订混同。

最终候选事务复验实际投影，重放、继续、携入、讨论后代和中断恢复递归检查真正使用的旧输入。政策变化保留合法历史与用户编辑，并展示依据变化；来源删除优先擦除正文和恢复副本。撤销无正文决定不能恢复已删除策略。

### 6.5 发布内容与删除、导出、试用

目标发布内容和方法指令与无正文业务状态分开：正文、资源及方法内容按不可变版本管理，身份、顺序、延续映射、范围政策、来源与审核状态由业务记录维护；运行时不从待审策略或对照回退读取正文。

删除清除受影响的全部版本正文、资源、来源定位、工作／暂存／发布副本、索引、缓存、使用与恢复副本，最小内部关联不能恢复正文。导出仅含当前明确允许的包内容和必要元数据，不含联系人范围、聊天、候选、关系记忆或使用日志。试用只产生应用内预览，不发送、不创建表达样本、不改关系记忆或长期偏好。

以上目标依据 [ADR-048](../adr/048-memory-skill-evolution-lifecycle.md)与已确认的[演进规格](../../.scratch/memory-skill-evolution/spec.md)；旧实施阶段和迁移编码不作为当前 SQLite 接口要求，追溯见[历史记录](../history/skill-implementation-notes.md)。

## 7. 实现与验证入口

当前装配、数据表及公开操作以 [SQLite Skill 模块](../../backend-ts/src/skills/sqlite/README.md)和[正式 HTTP 适配](../../backend-ts/src/skills/sqlite/http.ts)为实现依据。DSH 接线遵循[源码查证流程](../../docs/agents/dsh-development.md)；本规格不代替实际模型、桌面、跨平台或发布验收。

验证需覆盖：格式／大小／路径／链接拒绝，授权根与双 Owner／联系人隔离，未知项核验后默认启用与显式停用保留，技术更新与迁移不恢复旧修订，按需多包和同名资源不串读，整轮请求／资源／输入预算，迟到结果及失效输入拒绝，完整无 Skill 回退，以及应用持有副本的来源删除。学习发布目标另需核对审核、范围继承、回滚和删除闭包，不能用当前只读包测试代替。

项目内原始教学视频处理、脚本执行、网络运行资源、跨 Owner 共享、候选自动发送，以及仅凭候选采纳自动改写／启用／发布 Skill 均不在当前能力范围。
