## SQLite 切换与逐人授权阶段

[ADR-110](../adr/110-selected-sqlite-contact-read-grants.md)第 11–19 行限定了新 SQLite 从空库重建、逐人授权的实施阶段；“不启用全部私聊”局部作用于该阶段，不取消根 AGENTS.md 与 ADR-089 明确保留的产品分支。旧身份和读取授权不得直接迁移，账号隔离、来源核验、删除排除和停读边界继续有效。实际 UI 只能展示已认证的后台能力，不能由配置枚举推断全部私聊已实现。

归并前的顶部实施摘要为：

> 联系人身份与逐人授权按 [ADR-110](../adr/110-selected-sqlite-contact-read-grants.md)：不延续旧授权、不启用全部私聊，取消立即封禁旧资格；首用搁置不取消授权核验。

> 业务资料现由受控本机 SQLite 保存；实例身份、事务及删除路径按 [ADR-109](../adr/109-controlled-sqlite-storage-foundation.md)和[切换记录](../../docs/verification/20-sqlite-cutover-and-legacy-cleanup.md)实施。来源、范围、删除及 DSH 约束继续适用。

首用、工具准备、独立新装和模型设置在不同任务分别推进；某一实施票搁置首用不取消其必要授权。旧“工具必须用户自行安装／向导目标尚未实现”与“完整首用待验收”均是当时阶段状态，当前入口与实际能力须按代码和具名验证核对。

## 纠错与旧资料升级的隔离实施

以下保留原独立集成的执行范围和验证方式，不能据此推断真实库或历史分叉已经迁移。当前仍可能留存的纠错、比较、提取结果、裁决和恢复副本继续受来源删除约束：

独立集成候选的[纠错保护](../../.scratch/memory-skill-integration-preparation/issues/02-correction-and-erasure.md)将完整纠错参与窗口及来源世代加入原删除事务。排队删除即撤下旧比较，执行删除清除纠错正文、候选证明、受影响追踪和恢复副本；仅当仍有效规范消息需要防止旧错误复活时保留无正文`erased_guard`，最后一份有效依据删除后移除决定。该合成工程结果不表示业务库迁移或S分叉库已被处理，S分叉库继续保留原样。

已退役的[旧资料升级](../../.scratch/memory-skill-integration-preparation/issues/10-versioned-memory-upgrade.md)所遗留的比较、
提取结果和裁决也是敏感副本。排队删除即失效旧批准；真实删除在原来源／资料／联系人
事务内清除受影响批次的可恢复内容及完整追踪，不依赖下一次 GET 补清。工作中只保留
隔离身份、有限状态与非秘密算法配置，算法身份不含密钥、正文、任意环境变量或带凭据端点。
模型外部副本仍沿原独立删除边界；本轮仅使用合成资料和本地 Mock，不调用外部模型。

## 概览的旧迁移号与验证范围

以下 canonical 061／062 与旧“本票”表述只标识当时实现；当前规格保留投影失效、真实来源复验、输入依赖和恢复防复活的要求，不以迁移号代替现行 SQLite 合同：

联系人与本人概览的无正文清单均属于删除范围。底层记忆、候选、人工决定、来源、规范消息、
来源引用、观察记录或实际追踪依赖变化时，canonical 061 的投影失效触发器与 canonical 062
的本人集合修订触发器在原事务内分别撤下投影、记录真实集合变化，
不改变业务资料的采纳或授权。来源进入 `delete_requested` 即失效，清理失败仍不可从
旧清单恢复；重复请求、显式重试及清理已提交而 Worker 回执未保存时，重建都重新核验
真实来源。自然过期或人工修正仍有合法来源的历史可以查看；真实删除不得借历史保留。

本人手录根须沿实际合法版本链核验，不能用 owner 归属引用豁免后续聊天依赖。本人
概览的来源定位文字固定为空，仅保留真实范围与引用 ID；旧 NULL 证明保持未知，
不能用后续人工决定或另一个来源恢复旧提取的证明。本人集合修订与清单失效沿原事务
提交或回滚，删除完成后不从旧投影或中断 Worker 回执恢复正文。

概览不保存 HTTP 正文、原话、模型摘要或另一份恢复正文，数据库约束拒绝在投影、
记忆依赖或引用层追加正文。HTTP 禁用缓存，客户端按范围和操作世代撤下旧内容。

回复使用概览时，导航和检索过程以生成时无正文回执保存；实际证据正文保留合法底层快照。
准备阶段尚无回复请求时也在输入 CAS 中固定完整参与依赖；来源排队删除在同一事务内
擦除相关固定 JSON、输入和恢复副本。最终写入继续在同一 owner 锁事务内复验；概览读取失败
或补查失败不授权新读取或扩大预算。联系人原话补查与本人资料预算独立，本人资料的
原 contact 不能成为自动查询另一关系原话的入口。导航依赖即使未作为候选引用也进入
来源删除路径；旧快照、失败重试、同库恢复和迟到输出不得恢复应删正文。只用于删除
追踪的隐藏依赖不展示为模型依据，回执也不能替代既有 `basis_changes` 或原来源证明。

当前联系人整体 DELETE 产品入口尚未提供；本票工程覆盖真实 contact 外键删除导致
清单物理清除、目录撤下与概览 HTTP 不可访问，不据此宣称已有联系人删除用户流程。

## 第一版方向探索的冻结验证口径

以下是旧方向探索接口的验证要求；统一表达工作区与现行受控检索按当前[回复流程](../current/core-flows.md#3-候选回复生成)及其后继决定核验，不能把旧接口的禁补查条款当作所有回复的统一门槛：

- 方向建议请求只包含有界消息/目的、相关记忆、连续性提醒与 ADR-043 允许的受控 Skill 资料；无完整历史、业务 Tool 补查或外部查询结果。旧探索接口仍沿原确认生命周期；ADR-079 的工作区可在用户点击“帮我想想”后直接生成建议候选，不视为确认立场。任务关闭、范围或 Skill revision 失效后，不接受旧结果。

## 已被明确修订的验证条款

归并前的验证清单仍写“新发现包须用户明确启用”。该句已被 [ADR-135](../adr/superseded/135-default-enabled-localized-skill-library.md)的完整核验后默认启用修订；用户明确停用、来源撤销与不可恢复旧修订的约束保持。[ADR-157](../adr/superseded/157-portable-skill-directory-identity.md)进一步允许内容与最新历史修订完整一致时恢复物理定位，这不恢复来源资格或用户停用项。

[ADR-128](../adr/128-deduplicated-wechat-message-storage.md)中消息去重与旧记录清理、撤回新展示和使用规则的实施范围分别记录；后者仍暂缓。保留的旧来源资格保护不得误写为已经实现了全部撤回目标。

## 受管发布目录与当前外部原包的区别

旧隐私正文沿 ADR-096 将“全部版本、可编辑包、隐藏历史、暂存”的删除写作通用 Skill 合同。后续 ADR-129 的正常 SQLite 路径只读取外部授权原包，不建立正文历史库，也不把原目录登记为受管删除目标；账户清理元数据不能授权删除用户文件。应用实际持有的调用输入、追踪和运行副本仍按来源清除。

已采纳但当前尚未开放的学习／审核／发布目标另保留受管内容与历史版本的删除合同，见[现行 Skill 规格](../current/skill-library.md#6-已采纳的学习审核与发布目标)。旧阶段的“已具有主线工程装配”不证明当前正常宿主开放这些入口。
