# ADR-129：DSH 回复 Skill 的受控发现与启用

> 状态：已采纳（2026-10-31），根据 [DSH 回复 Skill 接入规格](../../.scratch/dsh-reply-skill-integration/spec.md)收敛用户已确认的决定。
> 2026-10-31 用户后续修正：取消管理页的手动添加和目录名输入；由管理刷新及每轮回复前自动发现，不要求用户手动安装或填写导入路径。历史手动关联入口不再适用，明确启用/停用、技术核验和自动回复选择保持。
> 局部修订 [ADR-096](096-directory-backed-reply-skills.md)、[ADR-098](098-skill-business-state-only.md)及 Skill Library 中“放入目录后直接发布并可运行”的条款。保留目录内容来源、版本完整性、来源撤销、自动学习审核、预算、原目录删除边界和人工发送约束。

> 2026-10-31 后续修订：[ADR-135](135-default-enabled-localized-skill-library.md) 按用户要求将新包及既有未知项改为核验成功后默认启用，并保留显式停用；下文逐包明确启用及未知包不读正文的旧要求由此替代，其余边界保留。

## 决定

发现、技术核验与用户启用是三个动作。由管理刷新和每轮回复前检查自动在宿主已配置并授权的目录根发现合法直接子目录；新包先显示目录名及待启用状态，不读取正文或辅助资源，不进入模型可用目录。用户明确启用时才完整核验格式、安全、资源类型、来源和版本，再发布可用修订。显式管理核验可检查用户指定包，但核验本身不等于启用。

应用负责已发现包的技术更新：管理刷新和每轮运行前核验当前已启用内容，有效变更发布新修订，不要求用户逐次确认。未知或停用包的自动刷新仅检查目录身份，不读取正文；重新启用时再核验最新内容。来源撤销、删除和目录身份冲突不能经扫描恢复；旧修订永远不能仅因字节恢复相同而重新成为有效版本。此决定不授权候选回复 Agent 搜索、下载、写入或管理 Skill，也不改变自动学习先形成草稿、由用户审核和确认范围后发布的要求。

DSH 继续使用正式 profile、官方 `dsh-skill` registry 和独占 scope。先核验官方 `dsh-skill-filesystem` 与受控文件服务的组合；锁定版本的发现流程会先读取每个 `SKILL.md`，缺少文件服务和 bundled 路径还有 Node 读取分支，watcher 则独立接触宿主文件系统。因此当前产品保留 `registerProvider` 业务受控 provider，不启用该 filesystem 插件、默认项目/用户根或 watcher，也不维护 DSH 核心分叉。变更处理采用上述有界刷新和每次读取复验。

实际读取必须将账号、联系人、启停、来源、当前修订与具体字节共同校验。当前 macOS 只读适配器从已授权根逐段 `openat(O_NOFOLLOW | O_DIRECTORY)`，根身份在实例初始化时固定，包身份在读正文之前核验，包内目录通过绑定 FD 枚举，普通文件相对该 FD 打开；拒绝符号链接、硬链接、越界路径、可执行类型、超限与读取中变化。正文与资源来自一次有界快照，再用实际字节计算并核对业务修订摘要。运行时缺少该服务时拒绝读取，不回落 Node 路径读取。

## 取舍和验收边界

业务层保留目录资格与读取控制，官方 DSH 负责 registry、scope 和模型 Skill 工具。新增原生组件只读取 Skill 包，不向模型提供文件系统、执行、网络或外部消息发送能力。原包保持只读，不因数据库缺引用或目录消失删除用户文件。

`native/skill-read/build.sh` 在开发启动及默认测试前显式构建并按源码时间复用；业务运行时不临时编译。5 秒、12 MiB 输出、单文档/资源大小与整包资源数量/大小均有限额，取消后仍由业务资格和迟到结果检查拒绝返回。该实现当前仅覆盖 arm64 macOS 15 部署目标；跨平台和发布包接线尚未验收，不得以本决定解除发布门禁。

源码依据与合成验证见 [Skill 只读器说明](../../native/skill-read/README.md)、[SQLite Skill 模块](../../backend-ts/src/skills/sqlite/README.md)及任务记录。自动选择、失败降级、资源加载、实际 App 和真实模型效果分别按任务验证，源码核验不构成端到端验收。
