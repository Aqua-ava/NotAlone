# ADR-165：退役逐条消息排除，固定关系背景自动上下文

状态：已采纳（2026-11-04）。实现与验收状态分别记录。

## 背景

ADR-079 为统一表达工作区保留了逐条查看和排除本次消息背景的能力。后续界面长期提供消息级勾选、排除数量提示和恢复操作，用户需要维护一套不改变权威资料来源、只影响本次请求的额外选择状态，却没有获得对应的产品价值。当前要求改为：关系背景开启时自动使用同一联系人最近最多 50 条有效消息，关系背景关闭时不带入自动聊天和派生关系资料。

## 决定

- 删除逐条消息排除能力。当前 SQLite 工作区、共享类型、IPC、HTTP 请求、请求指纹、生成输入和旧桌面回复合同都不再产生 `excludedMessageIds`／`excluded_message_ids`。
- 保留“参考最近聊天和相关关系资料”总开关。“最近聊天 · 查看／补充”和刷新入口继续存在，但消息列表只读，不参与逐条选择，也不显示排除数量或恢复操作。
- 关系背景开启时，按现有来源资格、联系人隔离、排序和预算自动纳入最近最多 50 条消息及相关资料；关闭时，最近聊天、旧讨论、关系记忆和关系文档都不作为自动背景带入。用户本次补充聊天和独立输入仍按各自合同处理。
- 当前 SQLite 工作区只接受 `action + draftText + tone + instruction + contextText + includeRelationshipContext`，请求指纹升为 `version: 2`。新请求携带旧排除字段时按输入无效拒绝，不静默忽略，也不创建请求或调用模型。
- 历史请求、候选和运行记录不因本次决定删除或重写。旧请求不能再生成或按“无排除项”重试，只能保留状态查询、已保存轮次回看和删除路径；旧完成候选可在保存轮次中查看，但不能恢复成可比对新输入。
- 不新增数据库迁移。历史 JSON 中不可执行的旧字段可以作为遗留数据保留；需要破坏性清理时另立明确任务。

## 取舍

保留旧字段并静默当作空数组会让升级前的敏感排除项重新进入模型输入，扩大出站资料范围；继续显示勾选但发送后忽略则会让用户误以为排除生效。明确拒绝旧请求并保留历史回看，牺牲旧请求的直接重试兼容性，换取资料范围不静默扩大和当前交互单一明确。

该决定局部替代 ADR-079 中关于消息背景排除、排除后停用派生关系资料及长历史补查、逐条消息选择的条款。ADR-079 的统一工作区、空输入建议、来源复验、上下文不扩大同步授权、手动发送和删除边界继续有效。

## 影响与回滚

回滚时保留数据库和历史载荷不动，恢复旧客户端合同、工作区指纹版本及消息选择界面即可重新启用旧请求语义；不要求迁移业务数据。正向回滚仍须验证旧完成候选、历史请求和当前 SQLite 候选不会因合同切换而静默扩大资料范围。
