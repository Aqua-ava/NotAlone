# ADR-078：按请求复用原生前台观察进程

> 后续时延口径：[ADR-088](088-normal-switch-one-second-optimization-target.md)保留正常切换一秒优化目标，取消所有场景统一一秒硬门；本文调度、进程复用、隐私和失败处理规则不变，历史验收结果不重写。

> 状态：已采纳并实现；正式接入和真实切换耗时见[验收记录](../../.scratch/foreground-worker-latency/validation.md)。
> 决策日期：2026-10-19
> 局部修订：ADR-052第15行的“短生命周期子进程”；其他采集、身份和隐私要求保留。

用户明确要求将同进程复用接入正式流程。端侧对照中，独立新进程的实窗采集链中位约433ms，同进程后续约156ms；反复初始化增加成本。选择由后端宿主管理一个按请求串行工作的原生进程，复用系统模型加载状态；不按联系人创建进程，不主动采集，也不保存上一轮图帧、文字或身份。

握手仅证明协议就绪。每次带唯一请求标识的观察都重新执行正式前台、唯一可见微信窗口、几何、内存布局及标题局部OCR门禁，输出当轮采集时点。仍须经完整CLI名单、唯一私聊和同范围active绑定核验。消息后台同步独立，OCR不读取正文、其他列表或其他App，不增加读取授权或外部发送。

请求与响应有字节上限、版本和标识校验；同一时刻最多一轮。错误、超时、取消或权限熔断回收对应进程并拒绝该轮结果；不得用上一轮结果补齐或在同轮重试采集。宿主退出或关闭时回收，空闲最多60秒。原始视觉帧仅在当轮端侧内存使用并及时释放。

变化通知继续只作无身份触发：取消正常两秒等待，在途只合并一次后续复查；技术失败退避及身份安全门保留。显式验收可记录固定事件、耗时和匿名状态，日志不含姓名、联系人标识或图像。进程复用原型不代表真实界面时延；实现及验收见[任务规格](../../.scratch/foreground-worker-latency/spec.md)。
