# ADR-016：用本地微信 CLI 读取消息正文，OCR 只定位当前会话

> 状态：已采纳
> 决策日期：2026-08-24

NotAlone 的前台同步需要识别当前微信会话，但用 OCR 解析每条消息的正文、说话人、时间和分行会带来不必要的错误。决定采用混合路径：用户自行安装并初始化只读微信 CLI；OCR 只识别当前前台窗口顶部的 `display name`，CLI 通过解析后的 `talker`/`username` 按会话读取文字消息。

## 决策

1. 同步必须由用户手动开启，且只对微信前台的一对一会话生效。NotAlone 不自动安装 CLI、提取密钥或接管其生命周期。
2. `display name` 是会话定位线索，不是 `contact_id`。首次遇到重名时，用户从候选会话的 display name、最近活动时间和头像中选择一次，保存对应外部会话定位标识和本地会话视觉指纹；之后使用二者自动切换。没有匹配、头像不一致或存在多个无法区分的候选时暂停，不写入消息。联系人改名或头像变化时只需确认一次新旧映射。
3. 解析成功后保存外部会话定位标识，使用 CLI 的 `tail --follow` 读取当前联系人；每个联系人在 NotAlone 中独立保存 `local_id`/`cursor` 水位。切换联系人时停止旧监听并启动新监听。
4. 切回联系人时，从该联系人的水位补读期间消息，来源模式标记为 `cli_catchup`；这些消息通过校验后可以正常参与回复和记忆提取。用户手动关闭同步期间不补读；应用异常重启且同步仍开启时可以恢复当前前台联系人的水位。
5. v1 只接收 CLI 的文字消息，包含联系人和我方消息；使用 CLI 的 `from_me`/sender 字段确定说话人。稳定消息 ID 用于与历史导入去重，同一规范消息可以保留多个来源引用；不保存 CLI 全量导出文件。CLI 不可用时不退回 OCR 正文，显示同步不可用并重试。
6. CLI 读取必须保持联系人范围，不能监听所有联系人或在微信不在前台时持续抓取；外部聊天发送永远不由 CLI 或 NotAlone 执行。

## 取舍

- **完整 OCR 消息路径**：拒绝。它需要额外判断气泡分组、说话人、时间和重复消息，而 CLI 已提供结构化消息字段。
- **全局 CLI 后台监听**：拒绝。它会扩大读取范围，绕过当前前台会话和同步开关边界。
- **仅使用 display name**：拒绝。改名、重名和标题变化会把消息写入错误联系人。

## 后果

消息正文的权威输入从视觉 `session_capture` 转为 `local_wechat_observation`；前台 OCR 只负责 display name、选中会话视觉指纹和前台状态。CLI 版本、微信版本、本地数据库权限和只读行为必须在接入前单独验证；第一轮验证只运行单联系人 `resolve-chat -> tail` 的严格只读测试，不写 NotAlone 数据库。
