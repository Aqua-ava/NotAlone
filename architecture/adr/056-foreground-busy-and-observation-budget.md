# ADR-056：前台观察繁忙恢复与有限执行预算

> 2026-10-21 设计审查：纯质量失败后的人工门后由 [ADR-076](076-session-list-assisted-name-matching.md)、[ADR-077](077-exact-session-name-before-edit-neighbors.md)增加窄例外；独立前台执行见 [ADR-073](073-foreground-observation-independent-of-background-sync.md)。本 ADR 的执行超时上限不等于取消旧任务中的一秒体验目标，后者是否继续作为验收目标尚待澄清。

> 状态：已采纳；修复包实机结果另行记录
> 决策日期：2026-10-15
> 后续局部修订：[ADR-073](073-foreground-observation-independent-of-background-sync.md)将正常后台同步与前台观察执行锁分离，并允许未绑定会话之后的新鲜有效私聊绑定自动恢复；其他人工门保持。
> 局部修订：ADR-054 只允许三个采集上下文错误自动恢复，以及 ADR-052 的旧900ms探针预算；其余身份与人工门保持。

与 ADR-054 的“其余传输失败均保持人工门”规则冲突；重新讨论的原因是实机诊断已证明后台同步占锁返回的认证 HTTP `409 foreground_observation_busy` 被桌面端压成普通传输失败，后续完整可靠的绑定观察仍无法恢复。繁忙只证明本轮未取得同步锁，不证明名称、质量或绑定失败。用户已明确要求修复移动缩放后的人工门及探针超时。

仅当可信后端客户端收到响应类型错误、HTTP409 且固定码为 `foreground_observation_busy` 时，保留该原因，清除本轮名称并撤销生成资格，使用原四／八秒退避等待下一轮。不打开新的永久人工门，也绝不清除此前低分、歧义、未绑定或真实超时等原因开启的门。下一轮必须独立取得新鲜完整名称、至少0.90置信度、唯一私聊及已有 active 绑定，才能恢复资格。普通断线、未知409及真实超时继续遵循原保护，不把所有409或失败当成可恢复；取消仍拒绝晚结果。

完整原生调用实测曾超过900ms；主进程、后端与探针的旧1.5／1.3／0.9秒预算会截断有限的有效单帧观察。改为 UI／HTTP3.5秒、后端3.2秒、探针最多2.5秒；锁等待仍最多200ms，CLI元数据仍最多250ms。探针超时仍终止自有进程，不增加帧数或重试；全链路仍只允许一轮在途。五秒采集新鲜度、代际／范围校验、助手焦点暂停、停止与晚结果拒绝保持。

代价是失败观察最多多等待两秒，正常完成仍立即交付。预算不是耗时保证或身份有效期；真实挂起仍失败并要求确认。没有新增权限、后台视觉采集、外部连接、消息发送、持久化或数据迁移。回归经生产控制器→认证HTTP→隔离PG，仅在探针与CLI进程边界安排耗时；实际窗口效果仍需 Computer Use 复验。

同轮小屏复验另发现正文气泡边缘覆盖聊天区过半，旧亮度中位数将它作为顶部边界候选，导致持续布局拒绝。布局分数改用21个采样差值的下四分位，须至少16点支持；仍在45–110pt内要求唯一边界，顶部名称裁剪不变，不新增OCR区域或宽免未知布局错误。合成窄窗、明暗与缩放正例及缺边／歧义负例验证后，仍以同一真实窄窗重建包复验。
