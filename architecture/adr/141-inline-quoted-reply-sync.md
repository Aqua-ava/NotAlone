# ADR-141：引用回复随正常消息同步读取

状态：已采纳（2026-11-01）。用户明确要求正常同步直接读取引用内容，旧占位继续后台补齐；实现与验收结果另行核验。

原方案先保存引用占位，再由后台按消息位置重新读取详情，需要协调普通同步与补读的读取状态。引用原话本来就在引用回复自身的载荷中，正常读取时即可解析；找到被引用的原消息不是显示引用副本的前提。

1. 正常历史页和增量页遇到一对一引用回复时，在同次受控读取中返回本次回复正文、引用快照、作者角色、类型、原消息稳定标识及来源证明。首次历史同步也适用；“旧占位”指 NotAlone 已保存但尚无引用详情的消息，不按微信消息时间划分。
2. 消息、来源、引用扩展及同步游标在同一事务内接受。复用 ADR-139 的精确消息身份、状态核验、同联系人原消息关联和删除排除；引用正文不进入普通来源元数据或完整 XML 副本，不另建一条被引消息。
3. 单条引用的格式、大小或已知状态无法核验时保留占位和最小失败原因，其他合法消息继续同步。授权、账号、来源或读取守卫变化仍停止本页，不能当作可跳过的解析失败。
4. 已保存的旧占位及没有内联结果的兼容输入继续经原后台补齐。成功或失败按现有来源键、版本和载体状态记账，正常同步已保存的引用不得再发起独立 `quote-read`；来源或已观察状态变化后的重验沿既有规则处理。
5. 保留当前消息身份、时间、删除路径和普通同步检查点语义。新增引用附加字段不得单独使旧消息身份摘要失配；固定 CLI 升级继续核验来源别名和现有隔离项。

本决定替代 [ADR-139](139-quoted-reply-sync-and-history-enrichment.md) 第 4 条中新引用“正常同步提交后处理”的时机选择；历史补齐、引用存储、媒体范围和其他来源约束保持。不改变图片读取、模型任务或记忆与回复生成算法。
