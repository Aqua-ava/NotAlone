# ADR-153：图文共同参与记忆处理

> 输入规范化修订（2026-11-11）：[ADR-179](179-memory-image-input-normalization.md)允许仅在内存中生成与原图绑定的缩放／重编码发送版本；不新增缩略图保存，原图资格与来源删除合同继续有效。

> 记忆图片范围修订（2026-11-05）：[ADR-169](169-memory-uses-confirmed-non-thumbnail-images.md)规定记忆只带入确认不是缩略图的图片（原图或来源依据为标准图）；缩略图和来源未确认的图片不进入模型，聊天保存与预览规则不变。

状态：已采纳（2026-11-02）。用户明确要求处理记忆时把图片与聊天文字一起带入模型。2026-11-03 已接入文字／图片内容插件、实际图文提取与来源核验、类型化引用及图片删除闭包；一组合成图文已完成真实提取、来源核验、自动采纳及清图删除验证。工程验证与真实模型验收范围见[接线记录](../../docs/verification/pluggable-image-memory-20261103.md)，不据单样本宣称其他媒体或完整微信闭环已验收。

[ADR-138](138-chat-image-original-extraction-and-placeholder.md)第9条已提出实际图片与相邻文字一起组装。旧的“文字是统一的检索与生成表示”混淆了记忆输入与记忆正文，容易把图片排除在记忆之外，因此按以下范围修订：

- 记忆处理的输入由同一联系人、同一固定窗口内的聊天文字和实际图片共同组成，保留原消息顺序、发送者、时间及图片所属消息。模型结合图文语境提取候选；图片直接作为该次记忆请求的输入，不设置“先独立识别或OCR成文字，再送入记忆”的必经阶段。
- 记忆正文及其检索表示继续使用文字。输出文字不意味着输入只能是文字；独立语音转写、用户主动提交的截图文字提取及前台名称OCR保留各自用途，不作为聊天图片进入记忆的前置门。
- 输入只使用本次已确认联系人范围内、来源有效且可用的图片和相关文字。图片证据须绑定所属消息与实际文件版本，并与文字一并进入来源核验、追踪及删除链；缺失、失败或已清除的图片保留真实状态，占位文案不代表模型已经看过图片。
- 图片保存负责取得合法受管副本，记忆任务负责组装图文并调用模型；保存或展示图片不单独发起记忆调用。历史与增量保留各自调度和固定输入，图片处理进度须如实记录，不能用文字已处理数量代替。
- 联系人隔离、读取授权、停读、来源与删除、模型输入预算、用户暂停及未知调用保护继续适用。前台定位原始画面仍按既有端侧内存规则处理，本决定仅涉及已授权聊天消息关联的图片。

本决定替代根AGENTS及架构入口中“记忆输入统一为文字”的限制，将ADR-138的图文组装方向确认为当前目标；ADR-137／140的保存与展示边界继续适用于媒体获取模块，不再被解释为记忆模块永久排除图片。ADR-107／143／152的文字处理实现与验收记录保持其原覆盖范围，不能用它们宣称图文记忆已接通。
