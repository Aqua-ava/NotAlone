# ADR-100：授权私聊首次完整历史同步

> 状态：已采纳
> 决策日期：2026-10-23
> 实现状态（2026-10-23文档核对）：[规格](../../.scratch/authorized-private-history-sync/spec.md)票01–07已记录 resolved；票08真实微信验收仍 claimed，完整集成尚未通过。迁移104的后续修复已有记录，不能继续据旧启动失败推断当前状态。

新用户授权全部微信私聊后，当前实现只建立联系人和读取授权后的新消息；已有聊天历史仍需逐个联系人另行准备文件。这使“全部私聊已连接”与用户期待的“所有联系人都具备聊天语境”不一致。决定把每个已授权私聊的首次同步改为完整历史同步：从该会话本机当前可读的最早文字消息开始分页读取，持续写入到当前，再无缝转入常规增量同步。该规则不区分新老用户、仅所选会话与全部私聊；以后新发现的私聊首次进入授权范围时同样适用。

> SQLite 本轮实施收敛见 [ADR-113](113-sqlite-private-history-source-contract.md)：仅逐人确认，支持档、消息身份、来源与删除边界分别认证；合成通过不等于真实渠道可用。
> 2026-10-29 SQLite 实施03：已发布的历史迁移为 v5；目标仍是首次读取已确认联系人的本机可读历史，不恢复旧 baseline 限制或手动文件入口。新增窄适配层已核验当前版本结构，真实状态及来源连续性未通过，因此尚未开放正常正文；分项证据见[验收记录](../../docs/verification/sqlite-private-history-support-03.md)。

## 决定

- 每个 `owner_id + contact_id + binding_id` 保存独立、可恢复的会话历史覆盖状态。只有本机可读历史已读完并与同步启动时记录的活动水位接续后，才能标记完整；空结果、读取失败或本机记录缺失都不能冒充完成。
- 历史读取按有界分页执行，每页成功持久化消息和检查点后才推进。历史和实时事件共用稳定消息 ID 去重，同一规范消息仍可保留多个合法来源引用；不能因历史读取期间出现新消息而形成缺口。
- 用户侧只有一个“持续同步”概念。首次历史追平和后续增量是实现阶段，不是两个需要用户切换的模式；进度、已完成、历史不完整和失败可按会话展示。
- 首次历史读取在后台进行且可暂停、恢复和撤销。连接无需等待全部会话；当前联系人优先处理。当前联系人历史未追平时不得静默生成；读取失败后若允许使用已同步部分，必须明确提示历史覆盖不完整。
- 单个会话失败只影响该会话的历史覆盖与回复资格，其他会话继续；失败自动重试，总开关关闭或绑定撤销后停止该范围的新读取。
- 老用户曾明确看到授权不含更早历史，因此不能把旧授权静默解释为包含历史。升级后保存一次明确的历史授权版本确认；拒绝时保留原有增量同步，确认后与新用户走同一流程。新用户首次连接确认直接包含历史同步。
- 只读取一对一私聊的文字。图片、语音、视频和其他非文字消息不读取正文，仍按既有规则保留媒体占位或计数；群聊、其他 App、外部发送和模型用途授权不因此扩大。
- 聊天历史与关系记忆分层处理。消息先可靠入库并可供回复检索；关系提取是独立、异步、可恢复的派生任务，不阻塞历史同步或首次使用，也不因首次导入而在无边界内立即批量执行。

## 后果

首次授权可能产生远比增量同步更大的本机读取量、存储量和耗时，重复文件导入或历史重叠将更常见，因此去重、每会话检查点、失败恢复和删除路径必须按真实历史规模验证。CLI 必须支持从本机可读最早点分页到当前，并正确接受 `sessions` 返回的自定义 `username`；当前把非 `wxid_` 用户名误作显示名并要求缓存刷新的失败必须修复后才能验收。

同步状态不再以“baseline 后是否收到消息”证明覆盖完整。页面必须区分连接成功、历史同步中、本机历史不完整和持续增量正常，不能把联系人已出现或即时读取成功写成历史已完整。更大的正文留存仍受 `owner_id + contact_id` 隔离、来源删除、联系人删除和未加密本机库提示约束。

## 考虑过的方案

- **保留 baseline，只同步授权后的新消息**：拒绝。实现和存储成本最低，但新用户打开旧联系人时没有语境，不能满足产品的首次使用目标。
- **要求用户逐个联系人选择文件导入历史**：拒绝。它把 290 个会话的准备工作量转回用户，也依赖用户自行导出，不能作为全部私聊授权后的默认体验。
- **只导入最近固定条数而不覆盖完整历史**：拒绝。实现简单，但“全部聊天记录”与界面承诺仍不一致，且任意条数无法代表用户需求。
- **历史与关系记忆一起同步并等待全部提取完成**：拒绝。它会把消息覆盖和派生记忆处理耦合成超大阻塞任务；两者必须分别记录状态和恢复。

## 修订关系

- 修订 ADR-023 第 3 条和 ADR-025、ADR-030、ADR-089、ADR-095 中“新绑定从 baseline 开始”“不追溯 baseline 以前历史”的范围。总开关、稳定身份、可靠游标、去重、删除排除、只读、文字范围和人工发送边界继续有效。
- 保留 ADR-083 的自动恢复方向：故障按绑定退避重试，总开关关闭时停读；但首次完整历史不再被视为 baseline 之前不可读取的区间。
- 本 ADR 只确认设计。实现、迁移、真实微信验收及当前 24 个自定义账号兼容修复另按功能规格和任务执行。
