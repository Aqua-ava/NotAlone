# ADR-167：记忆页在读取授权暂时不可用时继续显示已保存记忆

状态：已采纳并实现（2026-11-05）。用户明确要求“显示正文并标注”。本文局部替代记忆页读取沿用的“正文展示必须通过当前读取授权实时核验”做法（见 `management/timeline.ts` 的注释与 `sqlite-memory-timeline-guard` 的原断言），与 [ADR-162](162-local-reply-context-and-independent-model-lanes.md) 对回复的“不要求活守卫”口径对齐。

## 背景

每次 App 重启后，各联系人的读取授权（来源守卫租约）要逐个重新建立，期间记忆页把整条记忆隐藏，只显示“当前无可引用版本”和“聊天来源日期未知”。库内正文、引用和来源日期完整，回复侧按 ADR-162 也并不要求活守卫，用户却在页面上看不到可用于回复的记忆。

## 决定

1. **只放宽显示**：记忆页读取正式记忆版本时，先按当前读取授权实时核验；不通过时改用与回复相同的已保存来源资格（归属、接纳范围、删除、隔离、真实围栏）。通过则显示正文、来源日期和引用，并在版本上带 `sourcePendingRecheck: true`；授权恢复后实时核验通过，标记自然消失。
2. **标注**：界面在该记忆下显示“来源待重新核验”，说明可继续查看，修改前会重新核验。
3. **真实失效仍隐藏**：来源被删除、隔离、换绑、失证或归属变化时，已保存来源资格同样不通过，仍按失效处理，只显示“当前无可引用版本”，不显示正文。
4. **写入不放宽**：采纳、修改、纠错、变化、恢复与合并等依赖来源的写入继续要求实时核验；删除不受限。
5. 不改变回复、记忆处理、自动采纳、预算和删除闭包；待确认候选的读取本次未改动。

## 验证范围

后台守卫用例改为断言“显示并标注、恢复后标记消失、来源真实删除仍隐藏、写入仍被拒绝”；桌面解析与界面各有用例。真实库只读模拟（不写入）按“全部守卫失效”读取：84 条生效记忆中 82 条可显示并标注，2 条本地资格不通过继续隐藏。未做打包验收。
