# ADR-004：用户自行导出的微信单联系人历史文件

> 状态：已采纳
> 决策日期：2026-08-03

## 背景

Mac 微信前台会话 OCR 只能观察用户当前可见的文字。手机期间、未打开 Mac 微信期间或 OCR 失败期间的消息可能形成历史缺口。用户希望一次性补齐某位已确认联系人的历史，但不接受自动发送消息，也不接受重签名日常使用的 WeChat.app。

部分第三方工具可通过读取本机加密数据库和微信进程内存导出历史。它们不是微信官方接口，通常可访问多个会话，且某些实现会在内存访问失败时重签名 WeChat.app。

## 决策

允许用户在 NotAlone 外部、手动生成**单一联系人**的历史导出文件，并将该文件作为普通文本导入的来源之一。此决定不把第三方工具变成 NotAlone 的渠道适配器。

导出和导入必须满足以下边界：

1. 用户自行安装、运行并选择导出的聊天；NotAlone 不安装、不调用、不持有第三方导出工具的数据库访问、搜索、监控或 MCP 权限。
2. 仅接受用户选择的单一聊天文件。导入界面必须预览范围并要求用户将其绑定到既有或新建的 `contact_id`；混入多联系人或群聊的文件必须拆分或拒绝。
3. 导出工具在出现 `task_for_pid` 或等价的进程内存访问失败时必须失败退出，**不得重签名、修改或降级 WeChat.app 的代码签名/调试权限**。不满足这一点的发行包不得用于用户的日常主号客户端。
4. NotAlone 将文件保存为可删除的 `source_document`，再解析为带 `owner_id + contact_id` 的 `message`。删除该来源时，必须删除其消息、派生候选资料、已采纳资料证据关联和相关索引。
5. 导入前必须提示用户：该外部工具会读取本机微信数据库或进程内存、可能保留密钥/缓存，且不是微信官方能力；NotAlone 不会取得这些密钥或原始数据库。
6. 本路径只用于一次性、用户发起的历史补录；不得用于定时轮询、实时全量同步、自动会话发现或给 Agent 查询全部历史。

## 后果

- 这是一条补录来源，不改变 ADR-001 的前台 OCR 同步边界；两类来源在统一 `message` 模型中汇合。
- `source_document` 需要保留导出器名称、版本、用户声明的导出范围、导入时间和风险确认记录，方便复核和删除。
- v1 仍优先实现不依赖具体导出器的单联系人文本导入器。第三方工具的 Markdown/TXT 格式只是输入格式之一，不构成运行时依赖。
- 若未来希望由 NotAlone 执行导出、监听增量消息或读取数据库，必须新增 ADR，重新评审账号风险、采集范围、本机密钥与缓存清理、联系人隔离和用户授权。

## 验证要求

实现导入器时使用合成资料，至少验证：单联系人正常导入、群聊/混合联系人拒绝、导入前身份确认、来源级级联删除、导出文件解析失败不落入部分消息，以及候选回复不会发送外部消息。
