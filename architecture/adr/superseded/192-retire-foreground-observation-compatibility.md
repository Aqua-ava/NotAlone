# ADR-192：前台定位仅保留名称观察与已有联系人关联

已合并入[ADR-198：前台观察与联系人跟随现行合并决定](../198-foreground-contact-follow-consolidated.md)（2026-11-18）：前台微信窗口观察、名称匹配、失败恢复、变化提示与联系人跟随的约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

状态：已合并（ADR-198）。原记录：已采纳，2026-11-17。用户授权深入清理过时设计和兼容层；实现与实际验收分别核验。

正式原生观察已经只定位并识别会话顶部名称，界面也已按 [ADR-132](../132-existing-contact-name-matching.md)在失败时使用顶栏手选。继续接受双区域旧观察、维护另一条前台确认并写桌面证明的接口，会保留与当前隐私边界不符的协议及没有正式使用者的身份写入链。测试构造旧协议不能成为保留这些入口的理由。

- 有效名称观察只接受 `automatic-header-v3`／`automatic-header-v4`；退役 `automatic-window-v2`、选中行名称和双区域质量判据，以及缺少受支持名称协议的正向观察。不在微信前台的否定结果仍可返回最小结构，不因此要求额外截图或 OCR。
- 局部替代 [ADR-052](052-header-ocr-foreground-locator.md)“旧单帧 v2 保持兼容”的条款。保留 v3／v4 的前台、唯一可见窗口、布局、名称完整性和时效检查；尾部文字证据、完整名称优先、0.30 下限、真实文字锚点、群聊冲突及稳定绑定核验继续遵循现行名称规则。
- 落实 ADR-132，删除无正式调用者的前台再次确认、观察回执与新桌面证明写入链，不再提供恒为空的建议联系人或对应界面动作。自动匹配仍只关联配置账号的已有稳定联系人；匹配失败通过顶栏明确选择本次对象，选人后继续跟随。
- 联系人首次绑定、读取授权、手动输入确认、逐请求身份核验，以及已保存绑定证明和回复依据的来源与删除合同保持。退役入口不删除历史证明，不改变数据库迁移，也不将名称匹配标为用户人工确认或前台账号独立认证。

旧双区域探针不再作为有效名称观察，需要更新到受支持探针；错误应明确拒绝，不回退识别选中行、聊天正文或其他联系人列表。原始帧仍只在端侧内存处理，前台定位失败不成为 CLI 后台同步的读取门禁。

验收覆盖正式 v3／v4 和非前台否定结果、旧正向协议拒绝、低分及尾部名称、重名与群聊冲突、过期／取消／连接换代、顶栏手选及自动跟随；初次绑定和读取范围仍由原入口复验。合成观察与实际 App／微信结果分别报告，不沿用历史通过数量。
