# ADR-186：按需搜索当前联系人全部获准历史

已合并入[ADR-195：回复检索现行合并决定](../195-reply-retrieval-consolidated.md)（2026-11-18）：回复侧记忆与历史检索的现行约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

> 2026-11-14 检索修订：见 [ADR-190](190-tencent-style-local-hybrid-retrieval.md)，L1／L0 改用 BM25＋向量＋RRF 及可删除的持久正文索引；原有范围、来源与返回预算继续有效。

状态：已合并（ADR-195）。原记录：已接受并实现，2026-11-14 用户明确决定。

## 决定与替代范围

取消 ADR-185 中最多五百条历史 ID 的候选窗口。历史搜索覆盖本次生成开始时已接纳的、当前联系人全部获准历史；只限制搜索计算耗时、返回条数／文字量和搜索次数，不用候选条数截断资料范围。原先的三次共享尝试、十六条／2,048 估算 token 返回预算及 L1、L2 独立规则保持。

初始仍只向模型提供最近五十条及合法背景；搜索过程在本机执行，模型只收到实际命中结果。继续使用 DSH 官方 scoped Tool 和 Agent loop，不新增 Harness、provider 或远程 embedding。

## 实现边界

- 新请求保存 v2 历史范围，只记录消息接纳序号上界与联系人资料代次，不复制全部消息 ID、来源 ID 或正文。L1 的 ID／版本冻结沿 ADR-185 保留。
- 本机按接纳序号分页遍历整个范围，每批仅处理有限身份；从当前获准、来源有效、未删除／隔离的消息中读取正文并评分。分页大小是工作批次，不是可搜索数量上限。
- 新消息不混入已开始的请求。删除、撤权、来源与解释修订仍实时复验；实际结果冻结搜索时的版本、作者和时间，后续出站及保存继续核对。搜索不恢复微信读取、不跨联系人。
- 排序只保留有机会进入剩余返回预算的候选；按完整字节长度分桶保留有限高分项，避免长消息挤掉仍可放入预算的短消息。工作内存不随全部历史条数线性增长，不截断原文。
- 历史搜索计算预算为五秒，在分页边界、逐条评分和返回前检查；超时不追加或返回部分结果，记录已消费尝试与未完成回执。SQLite Worker 原有执行超时继续兜底；单次同步数据库调用期间的阻塞不被表述为精确五秒墙钟保证。
- v1 已保存范围继续按旧身份集合验证，不自动扩大旧请求授权。旧格式中的已删身份仍定向剪除；v2 边界不含逐条历史身份，实际输入继续沿既有删除闭包处理。

## 验证

相关回复／讨论的五十个测试模块共三百项通过，`pnpm run typecheck` 通过。一千条合成历史中五百条之外的早期约定，可经正式 DSH 工具进入后续供应商请求；后入库、跨联系人和已删资料不可混入；超时与空结果区分，尝试不退回。十／一百／一千条历史的范围准备查询均为二十八次；返回来源核验最多十七次，实际结果最多十六条。开发版复用现有实例，本机服务连接正常；未用真实聊天调用外部模型，合成供应商不能证明真实模型选词与调用意愿。

源码与官方接口依据继续使用 [ADR-185](185-on-demand-reply-memory-and-history-search.md#dsh-与-deepseek-查证) 已核对的 DSH `0.2.1-rc.2` 和 DeepSeek 官方适配机制。本次仅替换业务历史搜索范围与执行方式，官方 Tool 注册、作用域和 Agent loop 不变。
