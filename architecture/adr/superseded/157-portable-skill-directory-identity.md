# ADR-157：Skill 业务身份与可迁移物理定位分离

已合并入[ADR-196：回复 Skill 的发现、启用与按需加载现行合并决定](../196-reply-skill-library-consolidated.md)（2026-11-18）：回复 Skill 的存储、发现、启用、数量与范围约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

> 状态：已合并（ADR-196）。原记录：已采纳（2026-11-03），依据用户要求从实际使用和迁移角度修复回复场景因磁盘标记变化而整体不可用的问题。
> 局部修订 [ADR-129](129-controlled-dsh-reply-skill-discovery.md) 和 [ADR-135](135-default-enabled-localized-skill-library.md) 中“目录身份冲突不能经扫描恢复”的绝对限制。授权根、来源资格、用户停用、读取安全及人工发送边界保持。

`owner_id + package_id` 是 Skill 的业务身份。路径、设备编号和 inode 只定位当前物理目录；设备编号变化、同内容目录复制或迁移不应永久撤销已核验场景。原生读取器继续以当前绑定的目录 FD、`dev/ino` 和完整快照检查防止读取中替换，不放宽符号链接、硬链接、路径、格式或预算限制。

管理刷新和每轮回复前，只在宿主已配置并授权的根中尝试恢复。当前目录必须经过完整安全快照，正文及全部辅助资源的清单和内容双摘要均与该包最新历史修订一致；不能仅凭目录名、单个文件或任意更早版本认领身份。数据库以单事务复验 owner、head、旧定位、最新摘要和来源资格，再更新定位并建立新修订；包 ID、启停及启停来历保留，旧失效修订不复活，旧运行锚点和迟到结果继续拒绝。

停用项不因迁移自动读取正文或启用，用户明确重新启用时才核验；来源撤销不能由相同文件或迁移恢复。没有历史核验基线或内容不一致时仍不可用，界面说明场景文件缺失、内容不一致或核验未通过，不向用户暴露内部磁盘身份术语。

显式宿主根目录迁移允许旧根已不存在：目标安全快照须与数据库最新历史双摘要一致；旧根可读时额外比较两处内容。无历史基线且旧根不可读时拒绝迁移。持久迁移意图、数据库提交和配置切换仍须可重试；准备后磁盘标记变化时复验当前目标内容，完成配置后由正常刷新重建当前定位，不因恢复过程扩大授权根或恢复来源资格。

实现与证据分别见 [Skill 模块](../../../backend-ts/src/skills/sqlite/README.md)、[可迁移性回归](../../../backend-ts/test/sqlite-skill-portability.test.mjs) 和 [迁移恢复回归](../../../backend-ts/test/sqlite-skill-root-recovery.test.mjs)。合成测试、实际开发 App 和发布迁移分别报告，不将开发验收宣称为发布包验收。
