# ADR-150：发生时间标注降级为可选信息

已合并入[ADR-200：记忆采纳、来源核验与更新合并现行合并决定](../200-memory-adoption-consolidated.md)（2026-11-18）：关系记忆的采纳、来源核验、内容拒绝、时间标注与更新合并约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

> 状态：已合并（ADR-200）。原记录：已采纳；日期：2026-11-02。用户确认时间问题参考参考实现 TencentDB-Agent-Memory 的取舍：时间核验不了时只丢时间，正文照存。
> 替代 ADR-149 原第 4–6 条关于时间标注的条款；保留 ADR-149 的内容拒绝不失败与技术故障受阻边界，以及全部来源核验要求。

## 背景

同一轮真实数据处理中，一条记忆带有“这周末”的发生时间标注，但提取结果没有给出该时间表达在原话中的位置。核验模型如实返回“时间不确定”，旧规则据此把整条候选判为不通过；叠加当时的整批失败机制，最终把整个联系人队列卡死。参考实现把时间当作可选元数据：算得出就填，算不出就省略，时间不参与记忆是否保存。

NotAlone 保留“结构化时间必须有来源证据”的要求，但不让一个可选的时间标注否决整条有据的正文。

## 已确认决定

1. 发生时间标注（`event`）是可选信息：仍校验结构，但不参与整条候选的准入聚合。可采纳还须 `event_verification` 结构通过且 `claim_check.event` 逐字段判定为 supported；否则由核验协议层丢弃 `event` 并置 `time_unverified`，正文候选按其余字段的证据结论入库。
2. 正文、主体、分类、语义、`valid_at`/`invalid_at`（事实有效起止）与 `conditions` 仍是需要逐字证据的语义字段，未核验时按原规则拒绝候选。`valid_at`/`invalid_at` 不是可选发生时间标注，不随本条降级。
3. 既有解析归一保留（例如只有日期原话、没有发生主张的空事件按既有规则置空）；本条不新增解析期预删，核验仍可自行提供 occurrence 证据并采纳时间。
4. 时间可选规则作用于 `event` 字段级判定。核验模型顶层 verdict/issues 整体判为不确定时仍按原规则不入职；这是保留的残余边界，不静默升级模型结论。
5. `nullable-proof-v3`（历史 `bounded-runtime-v1` 配置）与存档重放路径保留原语义，不适用本条；生产 `complete-claim-v1` 经 `validateSourceVerification` 的路径生效。旧路径当前不可写入，若将来启用须先对齐本条。
6. `time_unverified` 只记录在核验结果与执行事件（`verification` 事件、诊断与处理历史），不写入记忆事实字段，避免改变准入绑定与既有记忆结构。
7. 正文里出现的时间表达仍随正文入库；被丢弃的结构化时间不可用于按时间检索，这是接受的取舍。

## 取舍

- 降低“时间错误”的拦截能力：时间标注不再能挡住正文候选；代价是结构化时间可能缺失，靠 `time_unverified` 标记与执行事件可审计。
- 不降低正文与主体的来源核验门槛，也不改变未知回执、授权撤销、删除闭包与模型故障的保守处理。
- 实现保持时间规则集中在核验协议层，抽取与裁决不各写一套可选时间逻辑；新增字段或路径需同时核对 `validateSourceVerification` 与 complete-claim 的字段聚合。
