# ADR-127：SQLite 私聊历史正常重启后从头重扫

已合并入[ADR-199：微信同步授权、读取边界与恢复的早期决定现行合并](../199-wechat-sync-consent-and-recovery-consolidated.md)（2026-11-18）：微信同步早期的授权、读取边界与恢复约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

状态：已合并（ADR-199）。原记录：已采纳；原生历史／增量、App 持久化、重启去重及正式新增来信自动入库与复扫去重均已实机验证。日期：2026-10-30。

2026-10-31 后续修订：[ADR-133](../133-page-delta-private-history-sync.md) 以变化页和业务已接受的持久检查点修订正常重启必须从头重扫及每轮 tail 完整重扫的选择；首次建立基线、来源与授权核验、删除／排除保护继续适用。下述重扫条款保留为历史依据，新路径实施与验收状态见 ADR-133。

2026-10-31 修订：来源指纹及文件实例比较不再包含系统设备号，避免仅设备号变化就使同一来源失效。保留 inode、创建时间、类型及必要链接数核验，其余来源变化、授权、删除与排除边界继续适用。旧指纹涉及账号、分片与消息来源身份，兼容恢复须独立核验；这项修订不表示既有数据已迁移或全量同步已恢复。

兼容恢复采用经明确授权、逐实例核验的无设备号指纹到既有不透明标识的一对一别名，绑定配置账号、本机来源目录和读取器制品。它保留既有消息、来源、旧目标及删除／排除键，不把设备号带回运行时身份计算。误报围栏只能在完整备份、全部受影响会话的无正文目标精确复核及事务化旧状态复验通过后解除；无任何消息或来源的空会话可单独核验当前空目标。恢复后仍重新授权有效范围并完整重扫，不接续旧进程游标，不恢复其他撤销或删除决定。真实来源、分片或表实例不匹配时继续停读。

2026-10-31 原图组件升级补充：上述身份算法迁移与纯组件升级分别核验。[ADR-137](137-original-image-authorized-sync.md)的原图组件仅在固定、已审查源码配对中证明身份实现逐字不变，并逐项证明现有授权范围的新旧来源身份完全相同时，才可从旧别名事实为新制品生成独立绑定凭证。该升级不改业务身份、不迁移或重建授权、不解除任何已有停读围栏；只有制品摘要和随机目标描述符允许不同，旧制品游标不延用。不能以此规则处理身份算法、实例或授权实际变化。

仅当微信账号、数据库文件及来源分片／表实例身份都经明确能力报告 `continuity='same-source-instances-normal-use-v1'` 核验为完全一致时，应用正常重启才可恢复读取；每次恢复都从当前固定来源完整重扫，不沿用重启前的不透明游标，并以已认证本地身份幂等对齐消息。历史删除或排除对应的本地出现键必须在重扫中继续受抑制；检测到任何身份或来源变化、报告缺项或无法核验时，持久停止读取。用户接受无法识别保留相同账号、文件和表实例标识的原地回滚，因此该情形不在连续性保证内；此限制不构成恢复证明。上述日常使用范围已完成受控实机验收，未观察的消息状态仍隔离。

来源目录身份不包含随 SQLite 旁车增减变化的条目计数。目录写事件仅触发选定数据库名单及实例复核；等待被系统信号中断时重试，不将 `EINTR` 当作来源变化。两个核验之间瞬时出现后消失且未被读取的新路径，不构成可观测的恢复证明。
