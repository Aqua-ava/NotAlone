# ADR-078：按请求复用原生前台观察进程

已合并入[ADR-198：前台观察与联系人跟随现行合并决定](../198-foreground-contact-follow-consolidated.md)（2026-11-18）：前台微信窗口观察、名称匹配、失败恢复、变化提示与联系人跟随的约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

> 后续时延口径：[ADR-088](088-normal-switch-one-second-optimization-target.md)保留正常切换一秒优化目标，取消所有场景统一一秒硬门；本文调度、进程复用、隐私和失败处理规则不变，历史验收结果不重写。
> 2026-10-25 局部修订：为防止 macOS 27 首次 Vision/ANE 编译造成真实名称 OCR 冷启动，宿主进程创建即启动同一观察 Worker，并仅以纯合成名称图完成预热后发送 ready；ready 后常驻至宿主关闭或故障回收，替代本文“空闲最多60秒”的回收规则。预热不截图，不读取微信或任何原始视觉帧；真实观察仍逐请求执行全部门禁。

> 状态：已合并（ADR-198）。原记录：已采纳并实现；正式接入和真实切换耗时见[验收记录](../../../.scratch/foreground-worker-latency/validation.md)。
> 决策日期：2026-10-19
> 局部修订：ADR-052第15行的“短生命周期子进程”；其他采集、身份和隐私要求保留。

用户明确要求将同进程复用接入正式流程。端侧对照中，独立新进程的实窗采集链中位约433ms，同进程后续约156ms；反复初始化增加成本。选择由后端宿主管理一个按请求串行工作的原生进程，复用系统模型加载状态；不按联系人创建进程，不主动采集，也不保存上一轮图帧、文字或身份。

握手仅证明协议就绪。每次带唯一请求标识的观察都重新执行正式前台、唯一可见微信窗口、几何、内存布局及标题局部OCR门禁，输出当轮采集时点。仍须经完整CLI名单、唯一私聊和同范围active绑定核验。消息后台同步独立，OCR不读取正文、其他列表或其他App，不增加读取授权或外部发送。

请求与响应有字节上限、版本和标识校验；同一时刻最多一轮。错误、超时、取消或权限熔断回收对应进程并拒绝该轮结果；不得用上一轮结果补齐或在同轮重试采集。宿主创建 Worker 后先用纯合成名称图预热 Vision，预热成功才发送 ready；预热失败、超过独立上限或无响应时回收进程，后续可重建。真实观察在预热中返回 `probe_warming`，不把这段等待计入 2500ms 的本轮 OCR 结果，也不因此丢弃已完成的合成预热。ready 后常驻至宿主关闭、明确取消或故障回收。原始视觉帧仅在当轮端侧内存使用并及时释放。

变化通知继续只作无身份触发：取消正常两秒等待，在途只合并一次后续复查；技术失败退避及身份安全门保留。显式验收可记录固定事件、耗时和匿名状态，日志不含姓名、联系人标识或图像。进程复用原型不代表真实界面时延；实现及验收见[任务规格](../../../.scratch/foreground-worker-latency/spec.md)。
