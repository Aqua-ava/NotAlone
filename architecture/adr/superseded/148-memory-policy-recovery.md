# ADR-148：代码策略更新后的未完成记忆任务恢复

已合并入[ADR-201：记忆处理生命周期、调度与恢复现行合并决定](../201-memory-processing-lifecycle-consolidated.md)（2026-11-18）：记忆处理的触发、统一入口、调度窗口、历史与增量分开、总开关与安全恢复约束已收拢到该 ADR。下文保留为历史决定与原因，现行条款以该 ADR 为准。

> 状态：已合并（ADR-201）。原记录：已采纳；日期：2026-11-02。用户反馈更新模型和恢复入口后，旧轮仍在模型调用之前失败，要求修复。
> 增补 ADR-034 的恢复路径：相同策略沿原任务领取；源码策略版本变化时，不修改旧策略或放松核验指纹。

记忆轮次保存的 `source_stamp` 对应执行源码闭包。代码更新后旧轮的策略解析会失败，不能将此错误隐藏为普通提取失败，也不能直接替换旧轮策略后复用旧输出。

用户明确恢复时，原轮仍有未完成提取目标且不存在未知或在途调用，先复验原授权、来源和解释版本，再以当前策略建立后继轮。后继仅复制旧轮冻结输入中的未完成目标及相应原上下文，不读取新消息或扩大联系人范围。旧轮策略、成功步骤、候选和调用记录保持；旧暂停标记解除，旧轮控制撤下，避免阻塞后继与后续正常轮次。

后继使用按旧轮稳定生成的请求键，重复请求返回已受理状态，不重新执行已失败后继；后继自身失败只能从其当前状态明确恢复。旧轮回执继续遵循原控制接口，联系人页面随后重新读取最新轮次，不把跨轮回执直接当作联系人快照。

真实未知、在途调用、撤销授权或失效来源均拒绝迁移。仅有后续整理失败而没有剩余提取目标不在本次自动接续范围，不静默改写已有成果的策略资格。该恢复不等于证明模型输出质量，工程、真实供应商及真实资料验收须分别报告。
