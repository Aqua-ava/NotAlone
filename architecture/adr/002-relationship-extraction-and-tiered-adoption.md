# ADR-002：关系提取与全自动采纳

> 2026-10-21 决定收敛：本文早期“所有候选自动写入／风险不阻塞”后由 ADR-024 局部修订；默认采纳现统一按 [ADR-085](085-source-verified-automatic-adoption.md)：来源核验及适用检查后自动裁决，不增加语用、置信度或风险标签人工门。来源、auto 标记、可撤销、人工修正及人工发送边界保持。

> 状态：已采纳
> 决策日期：2026-08-02
>
> 输入窗口和历史导入调度的后续修订见 ADR-014；本 ADR 的自动采纳、证据契约和删除规则继续有效。

## 背景

`AGENTS.md` 规定"模型推断不能直接成为关于联系人的事实"，但一次导入或增量同步会累积大量可提取的候选资料。若每条都强制人工确认，用户负担过重；若全部自动写入，又与"模型不能直接写 confirmed_memory"冲突。需要定义自动提取与人工确认的边界，以及提取流程的触发点、证据契约与失败可见性。

## 决策

### 1. 全自动采纳

`confirmed_memory` 的写入路径为全自动，不再设置人工确认门槛：

- 提取结果进入 `memory_candidate` 后，按确定性规则自动写入 `confirmed_memory`，必须带来源证据链、标记 `auto`、可一键撤销。撤销等同删除，按删除级联规则处理。
- 用户手动录入的路径仍存在，写入时标记 `manual`。
- 风险字段（转账、验证码、地址、借款、承诺、见面安排、健康、关系冲突等）随候选保存，但**不作为写入阻塞条件**；它们用于生成回复时的确定性标记与核实提醒（见 `../current/core-flows.md` 3.4，安全保险在发送环节）。

`memory_candidate` 保留 `auto` 标记与来源证据，`confirmed_memory` 记录其来源候选与采纳方式（`auto` 或 `manual`）。

### 2. 提取触发点与输入窗口

- 触发点：一次导入解析完成后；或增量同步的未提取消息累积到阈值（如 20 条）时。
- 输入窗口：当前联系人的最近 N 轮对话（上限见检索上下文预算），不跨联系人，不读完整历史。
- 提取结果进入 `memory_candidate`，按第 1 节规则自动采纳。
- 提取在后台异步执行：任务空闲时生成、跳过活跃或短暂会话、不与回复生成抢占额度。

### 3. 证据契约

专职子 Agent（或等效自动流程）向主 Agent 返回带来源的结构化证据，契约与 `memory_candidate` 字段一一对应：

```text
事实文本
支持消息引用列表（message id + 原始片段 span）
置信度（0-1）
风险等级（low/high 或命中的风险规则）
有效期（valid_at / invalid_at，可空）
```

无引用或无法判定风险时，不得产生 `memory_candidate`；低置信候选保留并标记，由"重复才信"机制（见 `../current/domain-data.md`）决定是否升级为长期记忆。

### 4. 失败可见性

`memory_candidate` 增加 `extract_failed` 状态：当提取结果不可解析、证据不足或风险判定失败时，保留证据与失败原因，用户可查看、可重试。不允许静默放弃。

## 不做什么

- 不以风险字段阻塞自动写入；风险只用于生成环节的确定性标记与核实提醒。
- 不把自动写入的资料标记为"用户确认"；`auto` 与 `manual` 必须可区分。
- 不跨联系人提取，不把完整历史作为提取输入。
- 不因自动写入而免除删除、来源追踪和有效期规则。
- 不因全自动而免除发送环节人工把关：候选回复必须带依据引用，由用户选择并手动发送。

## 后果

- 需要在 `confirmed_memory`、`memory_candidate` 增加相应字段，并在 UI 区分展示"自动采纳（可撤销）"与"手动录入"。
- 需要在导入/同步流程中挂接提取触发点、输入窗口与后台异步调度。
- 已修订 `AGENTS.md`：模型自动提取并写入记忆（带来源、`auto` 标记、可撤销），安全保险在发送环节。
- 验证清单新增断言：全部提取自动写入且带 `auto` 标记与来源；风险字段随候选保存且用于生成环节提醒；自动写入可撤销并级联清除；生成回复命中风险规则必展示核实提醒且绝不自动发送。
