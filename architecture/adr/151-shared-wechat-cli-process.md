# ADR-151：单个微信读取进程串行切换联系人

状态：已实施，自动检查与开发实例停读／恢复通过；首次检查点重建仍按实际进度展示。日期：2026-11-02。见[核验记录](../../docs/verification/shared-wechat-cli-20261102.md)。

后续扩展：[ADR-164](164-resumable-history-slices.md)在已接受部分检查点处结束一次独占操作并排队接续，避免大历史长期占用共享进程；单进程、来源守卫和释放合同保持。

用户选择直接修改窄协议及 App 接线，使用一个共享 `wechat-cli notalone-history` 进程串行处理联系人。此前按联系人保留通道和守卫、缺少总量限制，进程数随同步范围增长。此次不采用有界进程池作为最终实现。

一个业务读取操作独占共享客户端，从取得租约到释放期间不能插入另一联系人的操作。取得租约后重新核验当前授权、联系人及来源，写入仍按 `owner_id + contact_id` 和完整资格令牌隔离。账号元数据、前台名单和图片读取同样通过受控租约复用；名单访问不授予正文权限。

新增 `release-selection` 显式释放当前会话的快照、增量临时状态、观察基线及图片资源令牌，保留账号级身份与来源守卫。成功释放后才允许解析下一会话。账号变化、释放失败、协议异常及真实来源失证继续停止读取；不能把这些故障解释为正常切换。

切出联系人时可保留由同一活进程账号及消息来源守卫保护的轻量来源证明，保持已导入资料的读取资格；会话读者、快照和令牌仍须释放。该证明不允许继续调用旧目标，切回必须释放旧会话资格并重新核验。进程或来源守卫失效时，所有依赖它的联系人证明一并失效；单联系人取消不得清除另一联系人的当前选择。

正常切换沿用 ADR-127 的同来源核验及 ADR-133 的已接受持久检查点，不把旧进程内目标或游标当作新会话资格。撤销、暂停、删除和退出必须取消待执行读取并排空在途资源；既有围栏、排除及删除屏障不会被切换恢复。共享进程不增加发送能力。

此决定修订每位联系人常驻独立原生读者的实现选择，保留 ADR-113／127／133 的来源、授权和数据隔离合同。串行执行会共享等待时间，需验证取消及公平排队；资源占用、真实开发实例与升级认证结果单独记录，不能仅凭单元测试宣称完成实机验收。
