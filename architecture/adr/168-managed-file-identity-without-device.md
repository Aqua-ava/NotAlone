# ADR-168：受管文件身份不含系统设备号

状态：已采纳并实现（2026-11-05）。用户明确要求去掉设备号相关要求。延续 [ADR-127](127-sqlite-history-normal-use-restart-rescan.md) 与 [ADR-157](superseded/157-portable-skill-directory-identity.md) 对来源指纹和 Skill 目录的做法，扩展到应用受管文件（图片、运行副本）。

## 背景

受管文件的地址保存了文件及其各级父目录的 `dev`、`ino`、`birthtimeNs`、`uid`，读取图片、预览、删除前都与磁盘现状逐项比较。macOS 上同一个磁盘卷的设备号会随重启或重新挂载变化。真实库中 6318 个受管图片文件全部记着旧设备号，而 inode、大小和 sha256 均未变；之后每次读图都报 `media_file_identity_changed`，含图片的记忆处理批次全部失败，已保存图片也无法预览。

## 决定

1. 受管文件身份只由 `ino`、`birthtimeNs`、`uid` 组成，父目录同理；新捕获的地址不再写入 `dev`。
2. 旧记录里已有的 `dev` 不迁移、不改写：比较、校验和重复提交比对一律忽略它，不需要数据迁移。
3. 文件被替换、重建或换属主仍会改变 inode 或创建时间，继续判为身份变化，删除仍不越过被换身份的父目录。
4. 不改变其余受管文件规则：私有权限、单硬链接、属主为当前用户、符号链接拒绝、内容摘要复读。
5. 同一次调用内“前后两次读取”的瞬时一致性检查（如图片解码前后、SQLite 主库句柄）不跨重启，设备号在其间不会变化，本次未改动。

## 取舍

设备号只能区分卷，不能证明文件未被替换；去掉后跨卷同 inode 的理论碰撞需同时满足相同创建时间纳秒值与属主，且受管区位于固定的应用数据目录内，风险低于误拒绝全部已存文件。

## 验证范围

新增 `sqlite-managed-file-identity.test.mjs`：新地址不含设备号；带不同设备号的旧记录仍可校验、预览、删除；inode、创建时间、父目录变化仍被拒绝。媒体删除、共享执行删除、记忆删除、讨论隔离等相关回归通过。未对真实库重跑记忆提取。
