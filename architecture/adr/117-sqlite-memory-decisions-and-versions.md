# ADR-117：SQLite 记忆候选、决定与版本

状态：已采纳（2026-10-29）。SQLite 重建任务08的统一设计落地；实际验收按任务 Answer，不代表真实模型质量已经认证。

## 背景

固定模型原稿、用户确认、自动采纳、修正与当前人工保护承担不同职责。将它们放在可覆写的一条正文中，会丢失真实决定、来源和并发修订，也可能在撤销或来源删除后恢复旧内容。

## 决定

- 复用07的 `verifiedExtractionOutput` 作为唯一候选准入，在同一短事务复验完整冻结任务贡献、实际执行输入与精确来源。候选原稿固定；编辑采纳产生正式版本，不建立采纳前多稿历史。
- 本人和联系人共用 `memory` / `memory_version`，以 `self/contact` 形状隔离；回复消费者显式映射 `self` 到 `owner`。决定和候选关系、不可变版本、当前头及范围修订同事务提交，预期版本与头修订双重 CAS。
- 系统决定从真实提取或裁决 producer 登记 `auto`；用户决定不能伪装为系统执行，系统入口不开放为 HTTP 或 Tool。待确认候选使用独立 `unconfirmed` 参考类型，拒绝后退出生成。
- 当前人工保护仅归记忆头，由保护／解除决定推进头修订。恢复自动更新时新增恢复版本，保留前驱、被恢复版本及其采纳来历；恢复不复制旧保护。首次自动采纳允许明确撤回当前资格。
- 修正错误和记录变化产生不同形成类型；历史只用于管理，普通消费者只读当前合法版本。来源删除通过05显式域闭包处理候选、全部受影响派生版本及敏感决定，本人实际输入依赖沿版本前驱和恢复关系传递，冻结贡献另保留归属及在途授权边界，不能以改写或替换 citation 保住旧证明。
- 删除期间撤下管理快照并禁止晚到提交；内容擦除后旧请求保持不可重放。独立手录必须是实际用户输入，不能由自动内容无来源洗成。

- 默认自动流程复用唯一模型宿主，使用真实 `adjudication`、`relation_verification`、`merge_verification` 用途及同名步骤。逐候选冻结新基线，分批比较必须全数完成并在提交时复验；未知回执不重发。模型相关事件只绑定本次实际输入，完整资格依赖另存冻结基线。
- 多父合并为每个退役身份记录真实 `auto_retire` 决定，不产生虚假正文版本或重复消费候选。用户恢复提交所有父当前快照；同事务验证完整集合、来源、版本、头和当前保护，并逐父追加恢复版本。原保护后解除可在刷新后恢复，旧快照仍冲突。
- 同源同事实重复由真实 `auto_noop` 决定原子消费为候选终态 `duplicate`，展示为跳过重复；不冒称采纳、不产生版本、不复活已撤回记忆。动作目标字段互斥，矛盾输出不得消费候选。
- 当前正文的来源语义核验不等于用户确认；人工改写标待重验。已完成资料沿存档核验及保存来源读取，取消读取授权不会抹去已保存合法资料；未决产物继续受原轮完整授权门禁约束。
- 迁移12以固定受控重建扩展既有执行结构，不修改已发布迁移。来源清理依照实际事件输入和typed消费者逐项反查，不将固定可用消息集视为每项结果的实际来源。

## 取舍与适用范围

保留独立候选、决定和版本需要更多关系约束，但能把真实操作、不可变内容和当前治理分开。当前基础文本读取不建立第二套记忆表或任意 SQL 接口。不实现主题文档、长期表达偏好、质量诊断或外部消息发送。

本决定具体化 SQLite 统一设计的实体31–37；保留 ADR-035 的未确认证据边界、ADR-085 的默认来源核验自动采纳以及既有纠错／变化语义，不恢复旧风险或置信度人工门。
