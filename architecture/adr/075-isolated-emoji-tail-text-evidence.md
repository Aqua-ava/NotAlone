# ADR-075：孤立尾部表情的独立文字证据

> 状态：已采纳；实现与实机验证分别记录在任务结果中。
> 决策日期：2026-10-19
> 后续局部修订：[ADR-076](076-session-list-assisted-name-matching.md)以完整会话名单核验普通增漏错字及尾部证据；保留原始分数、已有绑定和其他安全门。
> 局部修订：ADR-052 的完整名称单一路径；ADR-073 仅由质量不足建立的人工门。其余身份、隐私、授权和时效约束保留。

真实 Vision 合成对照显示，emoji 会被识别为普通字符或直接遗漏，普通短名也可能逐字正确但低分；高分并不保证逐字正确。同图放大、灰度及语言复核没有稳定修复，语言复核还会将同一错误文字升为高分。用户已同意增加受限文字匹配，不降低0.90门槛，不新增读取授权。不能用通用去符号、模糊匹配或高分覆盖原始证据。

正式 `automatic-header-v4` 保留原始名称、分数、完整性和采集时间。仅在同一标题裁片中确认有限、独立、与前部灰度文字分离的尾部彩色区域时，允许最多一次端侧遮罩及一次额外 OCR；不放大、不采第二帧、不输出图片或几何坐标。原始标题须完整且单行；裁片边界、纯表情、尾区之后仍有文字、省略或不可靠背景均拒绝。`text_fallback.version=isolated-color-tail-v1` 的 `mask_verified` 仅证明像素几何，颜色不能证明 emoji。原始结果与备用文字、置信度、完整性分别传递，预览仍展示原始结果。有备用证据时不得再绕回原始误字匹配身份。

备用文字须完整且分数至少0.90。后端在既有单轮预算内枚举所有类型及所有绑定状态的 CLI 会话元数据，最多5000项，达到上限或失败即拒绝。所有以该文字精确开头的完整名称都参与消歧；只有唯一一项、明确为私聊、剩余部分完全属于支持的简单 emoji 尾部，才继续核验。支持集锁定 Unicode 17.0 的 `Emoji_Presentation` 单码点，可各带一次 VS16、可连续；旗帜、肤色修饰、ZWJ、组合键帽、未知序列不走此路径。空格、标点、数字、大小写、简繁和中间 emoji 不被删除或猜测。保留原有空白折叠，但尾部空格不能伪装成表情。

稳定会话标识仍须唯一对应同一 owner／渠道账号范围内有效的 active 绑定，且绑定保存的完整名称与 CLI 当前完整名称一致。无表情同名前缀、不同表情、普通彩色尾字、未绑定项及群聊都可能构成冲突；不能先按授权状态筛选。群聊及人数尾缀暂停优先。未绑定、改名或无法证明唯一时要求选择，不创建联系人或授权，不读取额外正文。

成功使用独立原因 `confirmed_active_binding_emoji_fallback`，界面解释文字核验来源，同时保留原始 OCR 分数。此新鲜证据仅可解除此前完全由 `quality_unverified` 建立的人工门；混入歧义、真实超时或未知技术失败后不得自动解除。明确手动模式期间不发起观察，也不因备用证据退出手动模式；仍须用户主动恢复微信会话识别，再接收新的可靠证据。普通完整名称证据仍不能解除质量门。五秒新鲜度、单轮在途、上下文变更拒绝、取消与绑定变更门禁不变。

评测从 CLI 取得名称元数据，在内存按固定字体和1×／2×尺寸渲染后调用正式 OCR；逐项私有报告保留在端侧。它用于比较算法，不等同于逐一打开真实微信会话测得的识别率。原始视觉帧不落盘上传，联系人名称不进入公共测试夹具、普通日志或仓库。
