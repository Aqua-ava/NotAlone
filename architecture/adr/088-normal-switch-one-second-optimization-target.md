# ADR-088：一秒作为正常联系人切换的优化目标

> 状态：已采纳（2026-10-21）。用户在逐项复审 Q04 时明确选择“一秒作为正常切换的优化目标，不作为所有场景的硬性门槛”。

早期自动定位规格把一秒作为响应预算，ADR-056 后来增加有限执行超时，ADR-078 再优化原生进程复用和变化通知，但未明确旧体验目标的适用范围。此次保留正常切换争取一秒内更新联系人的目标，不要求首次启动、从暂停恢复、异常重试等所有场景均在一秒内完成。

## 验收与保留边界

- 正常切换、首次启动和暂停后恢复分别测量与报告；正常切换超过一秒仍记录为优化差距，不能删除慢样本，也不凭单个超一秒样本判定整个功能失败。不新增未经确认的百分位达标率或所有场景的新时限。
- 记录明确的起止点，区分用户切换动作、变化通知、观察请求、联系人状态发布和可见界面更新；状态发布时间不等于屏幕绘制完成，原生单链速度不等于端到端速度。未测环节明确留空，小样本最大值不作为稳定 p95。
- ADR-056 的 UI／HTTP 3.5 秒、后端 3.2 秒、原生探针最多 2.5 秒仍是执行超时上限，不是正常体验目标。不恢复旧 900ms 探针预算，也不因取消统一一秒门槛而扩大现有超时。
- ADR-078 的按请求进程复用和变化通知保留；变化通知取消正常两秒等待，在途只合并一次后续复查，常规周期与技术失败退避保持。不新增主动采集、重复帧或同轮重试。
- 身份与范围核验、单轮在途、新鲜度、失焦暂停、过时结果拒绝和超时回收继续是必须满足的条件。不得为提高速度猜测身份、跳过绑定或沿用旧观察。后台文字同步继续独立于前台定位。

## 替代范围与证据

替代[自动定位旧规格](../../.scratch/automatic-foreground-locator/spec.md)及其历史续记中“所有场景均须一秒内”的验收解释，细化 ADR-056／078 的时延目标。历史失败和测量结果不重写为通过，也不据此关闭旧任务或补签移动缩放、权限、身份准确性及端到端验收。

既有[进程复用验收](../../.scratch/foreground-worker-latency/validation.md)报告了八次状态发布测量及一个恢复慢样本，不代表稳定时延承诺。代码依据为[前台控制器](../../desktop/src/main/foreground/controller.ts)和[观察预算](../../backend/src/notalone/front_sync/observation_budget.py)。本次只统一文档，未改变调度、超时、运行配置或业务数据，未新增实机测量。
