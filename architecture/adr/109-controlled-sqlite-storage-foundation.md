# ADR-109：受控 SQLite 底座与分票切换

> 后续局部补充：[ADR-159](159-foreground-read-channel-isolation.md)允许已核验的主存储创建独立只读附属 Worker，沿用当前运行租约，不初始化或推进代次；主业务连接、具名动作、受控文件和删除排空约束保持。

> 后续局部补充：[ADR-160](160-assistant-read-and-skill-worker-isolation.md)将助手回看加入独立受控读者，并将 Skill 文件核验移至独立 Worker；保留业务资格复验、唯一写者和实际关闭确认。

> 实施20修订（2026-10-30）：本文“默认业务仍为 PG、PG 当前默认启动路径保持到 20 明确切换”的阶段条款已关闭。正常开发入口默认执行受控 SQLite 切换控制面：独立 `database_id`／owner／迁移账本，旧目标识别与清理进度保存在不随目标删除的控制面；旧 PG 启动路径与手动文件导入入口退役。真实旧对象归属不明或停写未确认时保持维护态，不创建第二个空库、不回退旧 writer；真实切库与清理仍未执行。

> 状态：已采纳（2026-10-29）。实施 01 提供生命周期、存储 Worker、增量迁移和具名短事务；默认业务仍为 PG，完整领域结构与消费者切换由实施 20 复核。首用、安装、发布与微信迁移／恢复实验继续不在本轮。

## 决定与替代范围

用户已确认从空 SQLite 重建本机业务库，不迁入旧 PG 联系人、授权、删除决定或迁移账本。与 ADR-101 保留 PG 及 ADR-102 保留原 PG 业务结构的条款冲突；新决定局部替代这两份 ADR 的数据库底座目标。保留历史原因，分票实现过程中不凭开库成功切换业务。

使用当前 Node 24 已核验的 `node:sqlite`，每个存储实例由专用 Worker 独占连接，查询和具名短事务串行执行。不模拟 pg 池，不允许业务消费者通过 Tool、HTTP 或 UI 传 SQL 或事务回调。可信代码注册迁移及动作，外部 CLI、模型、DSH 和文件 I/O 均在短事务外执行；提交时复验实例租约和领域资格。

受控路径由 App 配置的 userData 根确定，目录 0700、文件 0600，核验真实路径、所有者、文件身份、符号链接与预期 database_id。create、open、reset 分离；01 仅实现排他 create 和带身份 open，reset 明确拒绝并交由 20 的停机与清理合同处理。异常、损坏、漂移或未知版本保留现场并拒绝业务写入，不另造空库。数据库角色不单独授权删除。

实例元数据与迁移账本独立于业务；迁移 SQL 的 SHA-256、DDL、user_version 和结构摘要同事务提交。成功打开更换运行身份、推进持久代次，旧租约不能继续提交。INTEGER 精确读取为 bigint；未知值保持 NULL。所有连接启用 FK，使用 WAL、FULL 同步、secure_delete、内存临时存储与有界 busy；仅显式声明的纯数据库幂等动作可在回滚后有限重试。Worker 失败不自动重放。

普通删除不等于底层擦除。05 负责明确维护与复核，覆盖 WAL/SHM、空闲页、必要 VACUUM、受管副本和活动引用，不能只因 DELETE 成功标 completed；不承诺 SSD 或外部备份的法证级擦除。

## 继续有效

DSH 官方 profile、薄插件、官方 Skill 加载与生命周期保持；模型使用用户凭据，出站范围、来源、隔离、人工发送及删除要求保持。用户 Skill 原目录、外部原始文件与模型密钥保留，不因空库缺引用成为清理目标。PG 的当前默认启动路径保持到 20 明确切换，不接管或清理未知 PG。
