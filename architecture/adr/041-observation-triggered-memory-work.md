# ADR-041：观察提交后唤醒联系人记忆任务

> 状态：已采纳，实现与运行证据见 observation-memory-auto 任务 02。
> 决策日期：2026-10-09
> 局部修订：ADR-038 的增量观察排除项，以及 ADR-034 的失败任务仅显式恢复限制。

与 ADR-038 不实现增量同步任务、ADR-034 失败任务仅显式恢复存在局部冲突；重新讨论的原因是用户已确认继续增量观察自动记忆闭环。对已授权联系人提交的新观察，本地后端自动创建或重排同一联系人记忆任务并唤醒现有 TaskHost，继续复用 Worker、消息水位、来源复验、模型优先级、全局锁和有限停机协议。

观察提交和任务排队分属两个事务，避免调度或配置故障回滚已可靠保存的消息和游标。任务排队与观察上的无正文排队时间戳原子提交，按原批次去重；来源删除同时删除凭证。事件只是通知，数据库验证 owner、contact、原绑定和来源，不允许事件授权新的联系人。调度失败记录稳定错误分类，后续通知或新观察可继续；不引入持久事件投递器或启动扫描。

运行中新批次保留下一轮。失败轮次只有新批次仍有效时才自动重新排队，没有新资料不能重开三次失败预算；用户仍可显式恢复。旧批次重放不重开终态，重启不扫描旧队列。该取舍承认进程退出可能丢失尚未排队的内存通知，以维持当前进程范围的已确认触发边界；消息和来源不丢失。观察任务按联系人执行，不把任务身份当成来源级提取边界。

不扩展微信读取范围、模型授权、历史回补算法或独立 CLI 协议，不增加自动发送、跨进程队列和定时自治。既有业务库升级及真实微信、外部模型验收仍需独立受控执行。
