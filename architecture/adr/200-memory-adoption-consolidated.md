## 决定

1. **默认路径。** 提取、逐项来源核验、裁决（新增／跳过／更新／合并）与发布全自动进行；置信度、语用与风险字段不是人工确认门；未通过的候选记录真实原因并终结，不转用户待办。人工只出现在真矛盾、主体或关系无法核实、人工决定冲突与受保护资料上。
2. **来源与标记。** 每条自动采纳必须带来源证据链与版本，标 `auto`，可查看、修正、撤销与删除；人工录入、修正、否决、停用与删除保护优先，自动不能覆盖；来源变化与删除不能被标签放行绕过，不得复活已删除证据。
3. **核验。** 每个候选需独立来源语义核验，只降不升；来源支持不等于现实为真，也不证明过去状态今天仍成立；限定、否定、时间精度与条件随记忆保留；核验器或模型技术故障不推进水位、不伪装成“没有新增”。
4. **采纳粒度。** 单次明确表达即可采纳，不设统一重复次数；一次性情绪、暂时状态与本次回复要求不得静默升级为长期偏好或人格结论。
5. **时间与不确定性。** `event` 无法核验时只丢标注；自由文本不确定性降级放行并留痕；低把握（<0.5）丢弃；有效起止与条件仍须逐字核验。
6. **更新与合并。** 按上表四种动作处理，变化标记不构成人工门；合并正文重新核验，`requires_all_sources` 使删除任一来源即清除派生正文。
7. **分层整理。** L1 变化自动触发 L2／L3 整理，逐项隔离、有界预算、发布前复验；旧资料升级已退役。
8. **范围与隔离。** 提取不跨联系人，不读取未授权范围，规则更新不重读或重新解释存量；显式历史协议与冻结评测保留原合同，不得用于默认流程。

## 已失效取舍（不得当作新增要求）

- 置信度门槛＋风险白名单的默认自动采纳条件、高风险候选转 pending 等待用户确认、默认空维度放行表、语用分流作为人工门。
- “重复才信”、固定累积 20 条触发、固定“最近 N 轮”窗口。
- 前缀标签编译与整批标签失败策略、`grounded-v2/v3/v4` 受控标签（仅显式历史协议）。
- 内容拒绝使整批失败；时间标注无法核验即否决整条候选；`alternatives` 自由文本整体拦截。
- 独立关系须覆盖全部旧记忆来源；`noop` 须逐字相同；`keep` 与主张变化互斥；合并至少两条旧记忆；事件／条件差异一律转待定。
- 旧资料升级流程；核验结果只用于当前运行、不保存。

这些取舍的原因与数据保留在已归档的原 ADR 中，供追溯，不再约束新实现。

## 验证与限制

本文只合并文档，未改代码、运行配置或业务数据，不新增验收，也不重新采纳任何旧资料。原 ADR 记录的合成测试、离线重放与隔离库验证仍是相应行为的线索；真实模型提取质量、模型自由文本 `alternatives` 的残留风险（采纳事件含 `adopted_with_alternatives` 可追溯，记忆标 `auto` 可撤销）、`noop` 以正文长度作信息量代理的极端同长改写风险，以及实际 App／微信端到端验收，仍须分别核验。
