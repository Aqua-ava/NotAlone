# ADR-017：优先用选中会话元数据匹配当前微信会话

> 状态：已采纳
> 决策日期：2026-08-24
> 替代：ADR-016 中“头像作为主要视觉确认条件”的部分；CLI 主消息来源和联系人隔离边界继续有效。

`wechat-cli` 能返回会话的 `username`、`display_name`、`last_timestamp` 和短预览，但不能告诉 NotAlone 当前微信窗口打开的是哪个会话。当前窗口可能存在多个同名联系人，因此仅识别顶部 display name 不足；头像也不应成为唯一主要判断依据。

## 决策

1. 前台定位优先读取当前窗口顶部 display name，以及左侧**选中会话行**的选中状态、最近时间和短预览；只读取该最小区域，不读取整个联系人列表。
2. NotAlone 将这些选中会话元数据与 CLI `sessions`/`resolve-chat` 返回的候选进行比对。时间和预览只作为匹配证据，不作为联系人身份；唯一候选得到外部 `username`/`talker` 后，再映射到内部 `contact_id`。
3. 如果 display name 与选中会话元数据仍无法唯一匹配，再使用本地头像视觉指纹作为备用；仍然无法区分时暂停并要求一次性绑定。后续使用已绑定的稳定外部会话标识，不要求每次切换人工确认。
4. CLI 不负责判断前台窗口；它只提供本地会话和消息数据。前台状态仍由 macOS 适配器确认，CLI 只在同步开启且当前会话唯一时读取。

## 取舍

- **头像作为主要条件**：降级为备用证据，因为头像可能不可读、变化或无法从 CLI 候选直接得到。
- **仅使用 display name**：拒绝，当前真实数据已出现两个精确同名私聊候选。
- **CLI 单独判断当前窗口**：拒绝，当前 CLI 提供本地会话/消息读取，不提供微信前台选中状态或 UI 控制。

## 后果

前台适配器需要增加左侧选中会话行的最小元数据裁剪和 OCR/比对；这些元数据只用于绑定验证，不进入消息正文或回复上下文。第一轮可以用截图中的 display name、左侧时间/预览和 CLI `sessions` 做脱敏匹配验证。
