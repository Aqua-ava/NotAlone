# ADR-139：引用回复同步与历史补齐

> 状态：已采纳（2026-11-01）。用户明确批准实现及历史补齐，范围限引用回复。
> 局部修订：原先非文字消息仅保存类型、不展开引用正文的约束，对已认证的一对一引用回复开放有界读取；其他富消息和媒体的约束保持。

现有 wechat-cli 能解析引用回复，但 NotAlone 原同步通道只保存 `[引用回复]` 占位，无法表达“引用了谁的哪句话，本次回复了什么”。采用独立引用扩展及补齐进度，在保留原消息身份和来源的同时补足这层关系。

1. 在现有账号、私聊授权及来源守卫内增加 `quote-read` 窄操作，只读取精确原始类型 `244813135921`（49/57）的指定消息。读取前匹配分片、表实例、local/server ID 和时间，不借引用访问其他会话。状态规则独立于普通文字：当前版本仅认证本人状态 2、联系人状态 4；其他状态保留占位，不猜测正文资格。
2. 原消息 ID、发送者、时间和不可变捕获记录保留。引用扩展分别保存本次回复正文、被引快照、被引作者角色及展示名、消息类型、原消息稳定渠道标识、关联状态和必要来源证明。只保存最小结构，不持久化完整 XML。
3. 原消息关联只在相同 owner、联系人和绑定内使用已认证 server alias。原消息尚未同步时可保存合法快照并标记未关联；后续消息到达再解析关联。昵称、时间或文字相似不构成关联证明。
4. 新引用随正常同步提交后处理；已保存的历史引用逐条补齐。补齐独立于文字 cursor，按稳定来源键、解析版本和载体状态去重；失败不会被普通重复唤醒忙重试，来源或已观察状态变化后可重新核验。关停与删除等待真实读取退出，旧资格不能迟到写入。普通历史转入 tail 后，仅复用经过同源核验的活动快照，或建立完整固定快照证明、匹配来源／profile／实例的临时读取器；不得改写 tail target、checkpoint 或分页游标。临时读取器关闭失败须清空内容并停用会话，不能返回成功。
5. 删除引用载体时清除扩展及尝试中的内容；删除原目标或来源时擦除被引副本、保留仍合法的本次回复正文。先删除原文、后解析载体也必须检查来源排除记录，不能从 XML 快照恢复已删除内容。
6. 聊天及既有消息读取以回复正文和独立引用结构提供内容，明确区分引用作者与回复作者。失败说明保留为占位状态，不伪装成实际发言。引用媒体只保留类型与原消息关联，图片继续沿既有原图能力处理。
7. 固定 CLI 制品按既有来源别名升级流程验证普通会话范围不变，保留连续性隔离。后台引用补齐不创建模型任务，也不改变记忆或回复生成算法。

实施和实机证据单独记录，不能以合成解码或字段存在宣称全部历史可用。
