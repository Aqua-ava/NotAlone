# ADR-020：常驻本地后端服务与事件驱动前台同步

> 状态：已采纳
> 决策日期：2026-08-25
> 后续局部修订：历史导入提交成为原记忆任务的触发动作，后端自动唤醒并让回复优先，见 ADR-038。
> 后续局部修订：SwiftUI 主窗口和构建入口已退役，TS + React 新 UI 尚未实现，见 ADR-039；本地后台契约保留。

NotAlone 的产品形态从菜单栏调试工具升级为带主窗口的原生 macOS App，并需要把导入、前台同步、记忆、回复、任务和 Skill 库串成完整闭环。既有的"菜单栏每 3 秒拉起 CLI 子进程、解析 stdout 文本"模式无法支撑消息流展示、任务进度和候选回复交互。决定引入常驻本地后端服务，并把前台同步从一次性轮询升级为事件驱动。

## 决策

1. 新增常驻本地后端服务（`src/notalone/server/`），只绑定 `127.0.0.1`，启动时生成随机 token 供界面进程连接；不引入账号体系，不对外网暴露。主窗口 App 放在仓库根目录 `macos_app/`（SwiftUI），与探针包 `macos_sync_probe/` 平级；Swift App 负责拉起并监管后端子进程，退出时一并收掉。
2. 服务端向界面的事件推送使用 SSE；界面到服务端的操作使用普通 HTTP 请求。本机后端 API 可以返回消息正文与记忆正文（用户查看本人资料），出站台账等对外边界不变。
3. 前台同步采用事件驱动三层混合，取代 3 秒轮询：消息读取使用 wechat-cli 的 `tail --follow` 常驻流（ADR-016 第 3 条的原设计，第一阶段曾被一次性轮询替代，本决策予以兑现），切换联系人时停旧启新，崩溃后指数退避重启并从水位补读，`TailLifecycle` 的切换、补读与关闭窗口语义不变；前台与会话变化由 macOS 原生工作区事件触发一次性探针（OCR 验证与绑定门禁），不做全频率轮询截屏；低频心跳仅作兜底，`--follow` 不可用时降级回一次性轮询退避，失败关闭语义不变。
4. 后端与既有 9 个 CLI 命令共用同一应用层代码（薄壳架构），CLI 全部保留：`front-sync status` 降级为诊断入口，`task-worker` 降级为兜底恢复工具。后台任务步骤由用户在界面触发、在后端进程内执行并推送进度；不引入定时自动化，外部聊天发送仍然不是可执行能力。

## 取舍

- **继续子进程 + 轮询**：拒绝。消息延迟受轮询间隔限制，每 3 秒拉起多个子进程（含一次 OCR 截屏）资源浪费，且无法支撑进度与流式展示。
- **WebSocket 或 XPC**：拒绝。事件只有服务端到界面一个方向，SSE 更简单；XPC 与 Python 生态绝缘。
- **Unix socket 自定义协议**：拒绝。HTTP 生态成熟，开源用户可用现成工具调试接口。
- **打包分发内嵌后端**：见 ADR-021；本决策不依赖打包形态。

## 后果

菜单栏应用不再承担同步引擎职责，降级为轻量状态入口；同步循环的权威驱动方从"调用方轮询"变为"后端常驻进程"，一次只能有一个后端实例驱动同步。`--follow` 长进程在真实微信下的稳定性需要端到端验证后才能宣称事件驱动可用；验证前一次性轮询仍是可回退形态。本决策只改变进程与事件架构，不改变联系人范围隔离、一次性绑定确认与失败关闭等既有领域约束。
