# ADR-094：按删除范围保留或清除最小调用记录

> 状态：已采纳（2026-10-21）。用户在逐项复审 Q09 时明确确认：删除单份资料保留最小调用记录，删除整个联系人或账户时清除对应调用记录。实现与产品验收待完成。

ADR-031 仅决定来源删除保留无正文调用记录，没有决定联系人和账户整体删除。此次按用户选择明确三种范围，避免把单一来源的保留例外扩大为联系人或账户记录永久保留。

| 删除范围 | 最小调用记录的处理 |
| --- | --- |
| 单份聊天来源／资料 | 保留 ADR-031 允许的最小无正文记录；应删除的正文、追踪及派生资料继续清除。 |
| 整个联系人 | 清除该 `owner_id + contact_id` 对应的调用记录，不因其无正文而保留；无关联系人记录不受影响。 |
| 整个账户资料 | 清除该 `owner_id` 下全部调用记录，不影响其他用户。 |

保留字段仍仅限 ADR-031 的调用时间、供应商、模型、用途、用量、结果及必要内部范围标识，不得保存聊天、记忆、回复正文或来源文件名。内部标识不等于匿名，不能把已清除范围的调用记录改名或藏入删除凭证、普通日志、缓存或恢复副本继续保留。同步排除标记与调用台账是不同用途，按已采纳同步规则处理，不能以防重建为由保留整条调用记录。

整体删除须清理相应调用记录及可恢复副本、处理关联引用并复核不可查询或恢复；并发／晚到调用不能在删除完成后重新写回已删除范围。部分失败不得报告整体完成。仍沿既有规则处理含正文资料、来源依赖、任务状态和删除重试；本地清理不等于外部模型服务商已经清除副本，外部删除路径需明确说明。

## 替代范围与实施缺口

补齐 ADR-031 明确留白的联系人／账户范围，替代现行词汇、隐私规格及提取追踪文档中“整体删除台账规则另定”的表述。单份来源保留最小记录的规则不变；本决定不设置新的保留期，也不授权本轮执行真实资料删除。

当前[台账建表](../../backend/database/migrations/010_outbound_ledger.sql)刻意不与联系人建立级联外键，[联系人清理](../../backend/src/notalone/persistence/contact_deletion.py)未清除对应台账。因此后续需实现按范围清理、处理依赖引用与在途调用、补齐整体联系人／账户产品入口或接线，并验证单来源保留、整联系人清除、整账户清除、范围隔离、失败重试和恢复不可回填。既有底层清理不能替代这些验收。

本次只统一文档，不修改数据库、调用记录、程序或运行配置，未执行真实删除或新增端到端验收。
