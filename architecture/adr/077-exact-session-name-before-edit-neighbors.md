# ADR-077：完整名称命中优先于编辑近邻

> 状态：已采纳；按用户指出的完整名称误拦截修订。
> 决策日期：2026-10-19
> 局部修订：ADR-076 中低于 0.90 的完整全名仍与全部编辑近邻并列消歧的规则。保留质量、同名、绑定、尾部冲突及其他人工门。

用户在私有报告中发现：标题文字与名单原名完全一致、完整性通过，仅因原始分数为 0.50，就被相差一字的其他私聊及企业会话否决。这个误拦截来自名称排序规则，不是 OCR 逐字错误。把零次编辑的完整命中与推测纠错并列，偏离了结合名单确认完整名称的目的。

无独立尾部证据时，先枚举完整 CLI 名单，建立 NFKC/casefold/移除 Unicode 空白后的完整同名集合。集合非空时只在此集合内判断，不混入需要增漏改字的近邻；没有完整命中才使用 ADR-076 的有界编辑纠错。不能按已有绑定过滤完整命中集合，也不能从多条同名中挑一个。所有类型仍参与同名消歧；同名群聊保守暂停，同名非私聊不授予私聊身份，规范化碰撞及重复记录仍要求选择。

原始分数不被提高，完整性、布局和有效范围不变。原始分数至少 0.30 且低于 0.90 的完整命中仍要求至少两个真实文字/数字锚点；Unicode 展开的伪多锚点、纯符号及单字低分不因此放开。0.90 以上短名保留既有例外。分数不足 0.30、截断、省略或无效质量仍不自动确认。

完整命中只提供名称候选。唯一私聊仍须稳定标识在全部元数据中唯一、同 owner/渠道账号的唯一 active 绑定及保存的完整名称未变；不新增联系人、绑定或正文授权。低分完整命中使用 `confirmed_active_binding_name_match`，仅可解除纯质量历史门，不能解除已形成的歧义、技术故障或明确手动门。数字括号完整私聊的既有例外仍须原始分数至少 0.90，不因方法标记为 exact 被低分绕过。

独立尾部证据路径不在本次修订范围：有 tail 时仍合并原始及备用文字的合理候选，不以完整原文绕过有效尾部冲突，不以无效 tail 退回原文确认。无完整命中时，近邻竞争者即使未绑定、非私聊或锚点不足也仍参与消歧。

验证使用合成重现、绑定/范围/改名反例、认证 HTTP 和既有完整名单离线回放。公共测试不保存真实名称。离线回放只统计文字对应，不等于确认绑定或逐个实窗验收；完整文字恰好误识别成另一真实名称的风险仍存在，不能宣称概率保证或普遍零误切。
