# ADR-037：默认保存记忆提取的完整过程

> 状态：已采纳；完整追踪功能尚未实现。
> 决策日期：2026-10-07。
>
> 显式修订 [ADR-033](033-source-semantic-verification-before-adoption.md) 中“核验片段与结果只用于当前运行、不保存核验正文副本”的留存边界，并为现行隐私规范新增独立、可删除的含正文提取追踪。来源核验、采纳门槛、联系人隔离和最小出站台账语义保持有效。

## 问题

用户查到一条记忆时，已有业务来源引用与调用元数据不能说明模型当时读了哪些上下文、原始返回是什么、程序在哪里增添信息或风险、为什么待确认/采纳，以及最终如何落库。历史完整请求未保存时，附近消息和事后审计也不能替代原始处理记录。

用户明确要求从最初聊天到最终记忆的全部可观察过程可精准追溯，中间每一步的输入、处理和输出都保存。因此只增加模型调用台账、只保存成功候选或临时开启调试都不足以满足要求。

## 决策

1. **所有实际执行的记忆提取默认保存完整追踪**。覆盖原始来源与规范化映射、读取与窗口选择、各次实际模型请求/原始响应、解析与程序字段处理、来源语义核验、采纳规则、重复/相似判断、裁决、业务写入、水位、失败与重试。拒绝、跳过、待确认、零候选和部分写入同样记录。分阶段内容与关联契约以 [记忆提取完整追踪](../current/memory-extraction-trace.md) 为权威说明。
2. **持续保留，直到手动删除或删除来源**。不设置自动到期时间。完整追踪是敏感资料，具有查看和删除路径；手动删除追踪后相关记忆显示追溯资料缺失，不假称仍可完整复现。
3. **追踪写入失败停止本批**。保存输入/请求后才能调用，保存响应/阶段结果后才能继续使用。失败后停止后续调用与新业务写入，不推进本批水位；保留既有追踪和已经提交的业务记录，暴露故障位置与部分结果。日志故障不能按模型非法输出累计后自动跳过。具体可靠写入、恢复核对与事务机制须另行实现，不能假定当前批次已经具备原子回滚。
4. **独立保存含正文资料，不扩展读取或外发范围**。不把完整聊天、请求或响应塞进普通操作日志和 `outbound_ledger`，不保存连接凭据；仅记录当前已授权处理范围。原始视觉帧的端侧内存边界不变，云端接入与加密继续遵守现行隐私前置要求。
5. **删除依赖包括全部实际输入**。除直接证据消息外，窗口上下文、参与裁决的旧记忆及其来源也会影响输出。任一所用来源删除时，清除受影响整份追踪的含正文内容及可恢复副本；权威消息与记忆继续遵守多来源删除规则。联系人/账户的含正文资料清除也覆盖追踪。[ADR-031](031-source-deletion-retains-minimal-ledger.md) 的最小无正文台账留存决定不被扩展。
6. **追溯依据是实际记录**。保存模型实际返回的解释字段，程序判断与事后解读分别标明；不要求取得未返回的内部推理，不用重新调用模型伪造历史原请求或保证同样输出。本决定不自动补认证、重提取、纠正或删除已有私人记忆。

## 取舍

- 选择默认完整记录，增加敏感副本、存储容量和处理延迟，换取对每条结果及中间判断的原始证据。永久保留必须同时实现来源级联和可验证清除，不能用长期保存豁免删除。
- 选择追踪故障时停止提取，使存储故障也会阻断业务进度，换取不继续生产没有过程依据的结果。部分提交必须如实保留与核对，不能靠改写失败状态掩盖。
- 选择保守清除受影响整份追踪，可能失去同批其他候选的完整过程，但避免请求/返回和解释中遗漏被删来源的内容；同批其他权威记录不会因此自动删除。
- 允许保留核验正文副本以满足逐步追查，显式调整 ADR-033 的临时留存限制；仍不新增“现实事实已证实”状态，不改变核验只降不升和安全采纳规则。

## 后果与实现状态

需要把早于提取发生的来源处理记录，与批次、调用、追踪内候选和最终业务版本连起来；只在提取模型适配器增加一条日志不够。查询必须支持从记忆反查全过程，并能查看没有落库的结果。

当前代码只有部分原始字段、业务来源和调用元数据，没有上述完整追踪。物理存储、事件/schema、事务接缝、删除索引、恢复核对与查询入口留待实现规格；本次文档决策不构成运行时能力验证，也不授权外部部署或真实资料删除。
