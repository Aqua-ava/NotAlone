# ADR-146：AI 服务地址与密钥由用户填写

> 状态：已采纳；决定日期：2026-11-02。用户要求在 AI 服务中提供 Base URL 和 API Key 两个可填写字段。
> 局部修订 ADR-062 对仅官方接收地址的限制；既有模型、完整请求估算、来源资格、调用许可及人工发送边界保持。

用户在设置中明确保存接收地址和为该地址新输入的密钥，两项原子写入受控本机配置，重启后生效。地址可回显，密钥不回显；改地址清空尚未提交的密钥。保存不调用模型，也不自动把旧密钥转交给新接收方。环境覆盖仍明确拒绝，不能显示未生效的成功状态。

本次沿用 `deepseek-flash` 与官方 DSH 的 DeepSeek Messages 适配器，支持用户指定兼容服务的 Base URL，不增加模型选择或其他协议。官方 root／v1 保留映射到 `/anthropic` 的兼容行为；自定义地址按适配器合同补 `/v1/messages`，已有 `/v1` 不重复。来源核验沿同接收方的 Beta Chat Completions 路径；去除末尾 `/anthropic`、`/anthropic/v1` 或 `/v1` 后接 `/beta/chat/completions`，保留其余路径前缀，不回落官方地址。

Flash 请求继续按现有声明容量与完整载荷估算，不因换地址变成远端能力实测；未知模型仍不装配。兼容服务须支持相同模型及所用 Messages／Beta strict 合同，实际不兼容时保留失败，不静默改供应商或放宽来源核验。保存地址并不证明供应商的数据处理政策或模型质量；原数据范围和出站约束继续适用。

地址只接受 HTTPS 或本机回环 HTTP，拒绝内嵌凭据、查询参数、片段和环境行注入字符。API Key 只通过认证配置接口写入私有文件及运行时认证回调，不出现在状态、错误或日志中。

实现与验证见[AI 服务自填配置验收](../../docs/verification/ai-service-base-url-20261102.md)。
