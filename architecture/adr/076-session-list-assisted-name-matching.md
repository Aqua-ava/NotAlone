# ADR-076：结合完整会话名单核验标题 OCR

> 状态：已采纳；用户明确要求通用匹配，验证结果另记任务。
> 决策日期：2026-10-19
> 后续局部修订：[ADR-077](077-exact-session-name-before-edit-neighbors.md)规定有效完整命中优先于编辑近邻，修复低分逐字正确名称的误拦截。
> 局部修订：ADR-052 的完整原文与统一 0.90 身份门、ADR-075 的简单 emoji 限制；保留窗口、授权、绑定、时效和人工门边界。

全量标准渲染中存在低分正确、高分错误及普通名称的多字、漏字、错字。颜色不能证明 emoji，原始 OCR 分数也不等于联系人匹配概率。用户要求结合完整会话名单，在唯一且已绑定时自动切换，不确定时人工选择。正式输入仍是当前唯一可见前台微信窗口的一帧，整窗只作内存布局分析，仅完整单行标题进入 OCR；不扩大视觉或正文读取范围。

名称匹配成为独立纯函数，不访问联系人、绑定或正文。使用 NFKC、casefold 和 Unicode 空白移除作比较，不通用删除标点/emoji，不猜简繁或姓名词典。无独立尾部证据、原始分数至少 0.90 且规范化全名唯一时保留全名路径；规范化同名碰撞不确认。其他原始分数至少 0.30 的完整标题用有界编辑距离查找候选：文字长度不超过 6 时最多 1 次编辑，7—12 最多 2 次，更长最多 3 次；较长匹配另要求相似度至少 0.80。候选必须保留至少两个按顺序完全相同的文字/数字锚点，符号和 emoji 不充当文字锚点。输入和规范化名称均限 256 字符；非法值或超长元数据失败关闭。阈值是启发式约束，未经概率校准。

孤立尾部遮罩仍仅提供同图独立文字，须完整、几何已核验且分数至少 0.90。该文字可比较候选前缀，剩余尾部最多 8 个规范化码点，不再以 emoji 类型判身份；允许尾部为空。强备用文字可与低于 0.30 的原始分数并存，原始分数始终不修改。原始标题和备用文字各自查到的合理候选合并；不能以备用文字掩盖原始文字指向另一会话的冲突。备用证据存在但不合格时不绕回原始高分路径。

每轮在既有预算内枚举所有类型、所有授权状态的 CLI 名称元数据，上限 5000，达到上限拒绝；不依赖关键词搜索，不提前只保留已绑定项。全部满足文字邻近条件的记录参与竞争，即使自身锚点不足；不按最近距离或分数强选。群聊及人数尾缀保守暂停，未知类型不自动确认；保留既有例外：高分完整原名本身含数字括号、完整名单中无群名冲突且唯一私聊和未改名绑定均核验通过时可确认，编辑推断或低分不能使用此例外。空名称无文字资格；重复名称、相近名称和规范化碰撞均不能靠已有绑定排除。匹配运算定期检查取消/截止时间。

仅唯一私聊继续核验：稳定 CLI 标识非空且在完整名单唯一，必须对应同 owner／渠道／账号的唯一 active 绑定。绑定保存的完整名称与当前 CLI 完整名称仍按既有空白折叠规则核对，不能用 NFKC 或大小写折叠掩盖改名。尾部空白异常保守拒绝。未绑定或改名要求选择，不创建联系人、绑定或授权，不读取未授权正文。

全名原样高分成功仍为 `confirmed_active_binding`；通用核验为 `confirmed_active_binding_name_match`，界面说明名单核验，原始 OCR 名称和分数保持。通用核验仅可解除纯 `quality_unverified` 历史人工门；混入歧义、超时或未知故障的门保持，明确手动模式仍需主动恢复。五秒新鲜度、单轮在途、上下文变更拒绝、绑定变更门禁不变。

验证分别记录：纯算法/合成绑定反例、现有全量标准渲染回放及真实微信窗口抽查。标准渲染回放不等于全部真实窗口验收；文字逐字正确不等于满足绑定资格。联系人名称及逐项结果仅留端侧私有报告，不进入公共测试、日志或提交。任何启发式仍有名单变化或高分误识别恰好命中其他全名的剩余风险，不宣称完美识别或普适零误切。
