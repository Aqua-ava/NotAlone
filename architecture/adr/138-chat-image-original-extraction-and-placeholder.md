# ADR-138：聊天图片原图提取与占位替换

> 后续修订：[ADR-140](140-source-verified-viewable-chat-images.md)已按用户要求取消原图证明门槛；来源已核验且完整可解码的本机图片（包括已绑定缩略图）可以保存和显示。下文原图限制保留为历史决定，其他来源、停读和删除规则继续适用。

> 状态：已采纳（2026-10-31）。用户确认实施；代码、合成验证和实机结果分别记入验收记录。
> 局部替代：ADR-137 中只消费已有图片密钥、不自动准备图片密钥的条款，以及只接受可直接解码图片字节的原图证明。其他授权、来源、停读、删除和仅保存原图约束继续有效。

## 背景

2026-10-28 的独立开发验证曾通过 wechat-cli 定位图片、wxkey 临时取得当前账号图片密钥，再将 WXGF／HEVC 解码为 PNG，实际显示原图。ADR-137 后来的同步入口缺密钥或不支持 WXGF，不能据其失败否定此前流程的能力。本次将该流程接入现有聊天图片提取，保持其他业务模块不变。

## 决定

1. 图片消息随已授权聊天同步先保存稳定 ID、发送者、时间和来源。图片提取在消息提交后进行，不阻塞文字同步，不删除或重建消息。
2. 只有当前授权图片消息已唯一关联到本机原图资源且明确缺少图片密钥时，才在图片提取内部调用既有外置 `wxkey image-key --quiet --root`。调用前后核验同一账号、配置、数据根和工具，限定执行时间与输出大小；不调用 bootstrap，不重启、改签或注入微信，不驱动微信下载图片，不扩大聊天读取范围。
3. 同账号图片密钥仅在本后台宿主内存复用，经独立继承管道交给当前取图进程；接收方再次核验账号和数据根。密钥不经普通图片协议回执、HTTP、日志或命令参数，不写业务库或新增明文配置，宿主关闭时清理缓存。
4. 原图资格仍要求独立的消息／资源关联，以及原始解密内容的 HD 长度、明文 MD5 和内容摘要。原图可为 WXGF；有界解码后保存可查看 PNG，转换证明分别绑定源 SHA-256、输出 SHA-256／长度、转换版本和实际尺寸，不能用输出 PNG 的摘要冒充微信原始内容摘要。
5. 窄原图质量证明升级为 `wechat-cdn-big-hd-exact-content-v4`。`hdLength` 属于原始解密内容；`verifiedBytes` 和 `verifiedSha256` 属于实际输出内容。`conversion=none` 时两者必须一致；`wxgf-to-png-v1` 时分别核验。固定制品、来源别名与升级证明沿 ADR-137 的流程处理。
6. 仅原图验证成功才保存受管文件。确认仅有已绑定缩略图时，只检查文件存在性及资源元数据，标记“仅有缩略图，原图未取得”，不读取或保存其内容。缺资源、缺密钥、无法解码和质量失证分别记账，不能将失败猜作仅有缩略图。
7. 聊天历史专用读取增加图片摘要，原图成功后同一消息泡显示图片，处理中显示加载占位，其他状态显示对应说明。回复和记忆的既有消息读取合同保持不变。原图预览复用受管文件、CSP、资格校验、活动引用与删除撤销 ACK；支持同时显示多张图片，不借展示恢复读取授权。
8. 已授权历史图片补处理一轮，新增图片沿现有同步处理。旧版失败按新幂等版本重试一次；成功、清除及普通重复唤醒不重复取图。用户清除不自动恢复，来源／联系人删除沿统一删除链。
9. 后续图文记忆可按稳定消息和文件版本把实际图片与相邻文字一起组装，图片进度不能由文字水位推断。本轮不接入图片理解、不让占位或失败说明成为长期记忆，不改记忆或回复模块。

## 验收

合成验证覆盖窄图片协议、密钥复用与隔离、WXGF 真正原生解码、仅缩略图不读内容、状态投影、同消息占位替换、多图片及删除撤销。真实微信按现有授权范围经正常开发入口取图并核验受管文件；合成成功不代替真实成功。桌面只使用 `pnpm run dev`，不以原生验收为由打包。

[2026-11-01 验收记录](../../docs/verification/chat-image-placeholder-original-20261101.md)：真实原图保存与聊天展示已验证；当前 wxkey 权限及部分历史图片缺少 HD 证明字段的限制仍保留，不能宣称真实加密 WXGF 的自动取钥全链已通过。
