# ADR-083：遗漏消息自动恢复与简化同步界面

> 状态：已采纳
> 决策日期：2026-10-21

用户只需决定是否同步以及同步哪些联系人。遗漏消息恢复属于后台同步流程，不能因一次临时故障停在等待手动重试，也不应把技术计数与独立暂停操作变成日常任务。本决策修订 [ADR-025](025-cli-background-sync-gap-backfill.md) 的暂停入口及恢复状态展示要求，保留其全部资料范围与可靠写入约束。

- 开启、重启或服务恢复后自动检查缺口。临时失败及未确认覆盖按绑定独立退避重试，间隔递增且有上限，继续遵守每轮读取预算；成功后清除退避。
- 本机已删除或没有历史的会话保留覆盖未知，新会话事件到来后再检查，并保留五分钟一次的低频重探以覆盖事件流不可用或漏事件；不在普通心跳中反复空读，也不宣称历史完整。
- 同步设置移除独立历史补齐卡片、暂停／重试按钮和内部计数。进行中显示一行自动同步提示，完成后隐藏；临时异常显示自动恢复提示，持续异常才提供可展开说明；本机无记录以折叠的中性说明呈现。
- 总开关统一停止读取与恢复；旧版本持久化的补齐暂停在同步引擎重新启动后自动恢复，不改变用户关闭的总开关。兼容诊断接口不作为日常产品操作入口。
- 只读取仍有效的已确认绑定，从可靠游标或 baseline 继续；不追溯 baseline 之前，不恢复已删除来源，不解析媒体正文，不发送外部消息。自动重试不能推进失败游标、重复写入或扩大联系人范围。

选择自动恢复而不是仅隐藏按钮，是为了避免后台永久卡住。状态仍如实保留在内部报告，界面简化不代表将无法确认覆盖伪装成完整。工程测试、开发版界面验收与真实微信故障恢复分别核验。
