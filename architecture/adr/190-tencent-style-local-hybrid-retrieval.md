# ADR-190：L1 与 L0 统一采用腾讯式本机混合检索

> 2026-11-17 局部修订：[ADR-191](191-reply-retrieval-contract-simplification.md)退役无正常入口的旧词法选择及待确认候选注入适配，正式回复强制使用按需读者与已有排名；索引领取只保留 `scanMore` 继续信号。本文 BM25／向量／RRF、预算、来源、删除及旧冻结范围兼容保持。

> 2026-11-14 后续细化：检索成功后的证据使用与有界邻近语境见[现行回复规格](../current/reply-generation.md#检索后的证据使用与语境核对)。排名与召回决定保留；命中与邻近消息共同消耗原预算，实际来源和删除合同不变。

状态：已接受并实现，2026-11-14 用户明确要求；检索与存储相关验收通过，真实模型质量另行验收。

## 决定与替代范围

L1 已采纳记忆和 L0 获准原始聊天统一使用 BM25 全文召回、本机向量召回和等权 RRF 名次融合，等分按稳定身份决胜。替代 ADR-182 的 0.8／0.2 分数加权、0.48 综合门槛、每次重新向量化全文、人工确认排序加成及向量不持久化条款；替代 ADR-186 的正文逐批扫描评分实现，保留全部获准历史范围、接纳边界、结果量、耗时和次数约束。未确认候选轨、L2／L3、联系人／本人独立预算和用户亲自发送不变。

核对 TencentCloud/TencentDB-Agent-Memory 默认分支固定提交 `42d4cde50c5a83182fced8c584f9ddb32a620615`，不以 README 或 OpenClaw 自动召回推断显式工具行为。

- [SQLite 索引](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/42d4cde50c5a83182fced8c584f9ddb32a620615/MemoryCore/src/core/store/sqlite/memory-store.ts#L943-L1023)：预先维护 FTS5／BM25 和 sqlite-vec 表示；查询只对 query 向量化，不重新计算全部正文。

NotAlone 保留更严格的 `owner_id + contact_id`、本人范围、冻结成员和实时来源资格。在合法身份集合内做 BM25／KNN，再取候选，不能照搬腾讯先扩大候选再过滤隔离的路径。候选放大属于 top-K 实现，不构成历史条数窗口。

## Module 与生命周期

共享检索 Module 位于 `backend-ts/src/retrieval/`：分词与 RRF 是无业务身份的纯算法；SQLite Adapter 负责索引、具名动作、合法集合内召回和删除；普通 TS 生命周期负责本机推理、批次与排空。回复 Module 只提交可信冻结范围，按返回身份物化原文、执行各层预算并冻结实际来源。L1／L0 不各造一套向量、分词、融合或后台循环。

固定依赖为 `@node-rs/jieba@2.0.1`、`sqlite-vec@0.1.7-alpha.2`。Node 官方 `DatabaseSync` 只在可信装配时启用扩展，加载固定本机 sqlite-vec 后立即关闭扩展加载；模型与工具不能提供路径、SQL 或库名称。

索引与业务资料共用受管 SQLite。迁移 56 只登记既有资料身份，57 追加有界扫描游标并兼容已知旧删除清单；已应用迁移及校验和不改写，旧资料分批回填；新写入／修订通过 TEMP dirty 聚合，在同一事务的受控 flush 中更新 FTS。SQL 触发器不调用 JS 分词函数或 vec0；来源、时间、状态和版本仍在领取／查询／实际出站复验。

正文向量按实体、正文摘要和模型表示指纹复用。固定本机模型、revision、512 维、CLS pooling、L2 归一化、f32 和正文截断规则共同构成指纹。正文未变的时间等元数据修订不重算向量；正文变化、撤下、删除使旧表示失效。query 向量和每次得分不持久化，不建立跨联系人正文 hash 缓存。

复用现有本机 embedding 生命周期，单 lane 小批回填并让查询优先；启动先处理 L1 小池，查询按当前联系人和层级有界唤醒，完成后继续全局 L0，避免 L1 排在大量原话之后。层级范围使用独立游标，推理不持有 SQLite 事务。提交重新核对摘要、版本／资格、资料代次与模型指纹，迟到结果不能复活旧资料。启动不等待全量回填，不读取微信、不调用外部 embedding、不在运行时下载模型。模型缺失、失败或查询向量超时降级 BM25；未完成索引不能冒充完整未命中。

## 删除与兼容

FTS、向量、待回填身份和扫描游标进入既有删除 domain。FTS 启用独立的 secure-delete；sqlite-vec 删除前通过正式 UPDATE 覆写其向量槽位，避免仅清有效位后仍在活 BLOB 中保留旧向量。仍须沿现有 checkpoint／VACUUM／校验完成物理清理。

在途正文和 query 通过 ActiveHolders 登记，删除与关闭等待真实推理结束；CAS 拒绝不等于已排空。历史搜索从资格核验开始共享五秒截止时间，包含 query 排队／推理及存储等待；最终追加和深资格复验处于可回滚 savepoint，越界撤销本次材料但保留已消费尝试与超时回执。原始资料不被改写，检索表示不能成为事实源。旧 v1 冻结 ID 范围继续限制同一检索 Module，不扩大旧请求权限。

## DSH 与验证边界

继续通过 DSH 官方 profile、scoped Tool 与 Agent loop 使用两搜索工具，参数仍仅 query；不新增 Harness、provider 或对外 SQL 能力。实际声明、锁和安装均为 DSH `0.2.1-rc.2`、Cordis `4.0.5`，Tool 注册、guard、取消与释放沿 [ADR-185 的固定源码依据](185-on-demand-reply-memory-and-history-search.md#dsh-与-deepseek-查证)复核。SQLite 扩展使用 [官方 Node 接线](https://alexgarcia.xyz/sqlite-vec/js.html#node-js)和固定制品实测，不声称完成整个 DSH 制品的可复现构建比对。

验收包括：两层的字面／同义召回、RRF 排名、单路降级、冻结范围与实时来源、重复搜索不重算正文、旧库分批回填、修订／删除与迟到提交、物理槽位清除，以及十／一千／一万条同负载前后耗时比较。合成供应商证明正式工具循环与材料传递，不能代替真实模型召回质量验收。

## 性能证据

同一合成工作负载，Node 24.22.2；分别记录冷准备和热查询，向量为 512 维替身，不代表真实模型推理时长。

| 历史条数 | 原逐正文扫描 | 共享索引双路热查询 | 新读取正文 |
| ---: | ---: | ---: | ---: |
| 10 | 4.59 ms | 7.92 ms | 10 条 |
| 1,000 | 101.60 ms | 13.11 ms | 16 条 |
| 10,000 | 5,506.73 ms，超时无结果 | 52.15 ms，返回 16 条 | 16 条／256 B |

小池增加约 3 ms 双路和资格准备开销；大池避免全量正文读取、重复 KNN／MATCH 和重复资格集合计算。十／一千／一万条初始化均为二十八次读 SQL；后一万条热查询为一百二十一次读 SQL。一次冷向量准备约 10.80／227.67／8,095.23 ms，含真实 SQLite 来源资格及替身计算。

L1 连续三个查询的重复正文向量化由池大小的三倍降为零；冷准备只处理每条正文一次，后续仅处理三个 query。真实质量、真实 ONNX 冷准备耗时不由这些数字证明。

## 验收结果与限制

七十五个回复、讨论、检索、存储与迁移相关模块共四百四十二项通过；追加的按层优先回填及真实 SQLite 范围回归连同生命周期复验二十九项通过，后台／桌面类型检查通过；正式 DSH 合成供应商循环验证 L1／L0 同义召回、RRF 优先与真实材料引用。独立审查发现的 L1 资格补位、共享截止时间／最终追加回滚、旧删除清单恢复问题均已定向修复和复审。开发版复用现有实例，界面确认本机服务已连接；本机固定模型已安装，派生索引在后台回填。未调用真实外部模型或发送消息。

完整后台曾执行二千七百二十项：其中与本次相关的旧版本／旧自动注入夹具失败均已修正并在上述相关模块完整复验。仍有五项在干净基线 `6ce565fde980fe9ec524f638171966132a107053` 同样失败：两项记忆调度恢复预期、两项联系人同步状态桩缺少 avatarRevision，以及诊断静态扫描器的既有堆内存耗尽。Skill 大资源用例在完整运行中曾失败，隔离基线、当前单例及最终相关模块均通过；不把第一次完整运行写成全绿。
