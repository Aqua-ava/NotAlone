# ADR-028：记忆召回第一期采用确定性中文词法评分

> 状态：已采纳
> 决策日期：2026-09-17
>
> 本 ADR 落实 ADR-005 第 1 节的词法检索路径（向量补充路径继续推迟），并修订 ADR-011 第 2、3 节里“目录帮助定位资料”和“按当前消息、表达方向、近期对话选择记忆”的第一期加载方式。ADR-002、ADR-024、ADR-026、ADR-027 的来源、采纳、语用与评测规则不变；ADR-027 第 5 条的待确认候选参考仍是后续纵切。

## 背景

当前回复路径调用记忆检索时不传 query，实际接近固定读取最早写入的 20 条联系人记忆；query 匹配要求所有 token 是正文子串，对无空格中文基本不可用；联系人记忆目录只有受控分类与主题分组，没有语义摘要，无法承担相关性判断；Owner 记忆已经能存取，但没有进入回复上下文；上下文只有条数上限，没有字符预算。结果是模型要么看到无关旧记忆，要么看不到真正相关的资料。

## 决策

### 1. 查询只取当前正文

召回 query 就是本次要处理的文字：`reply_to_message` 取待回复消息正文，`rewrite_draft` 取草稿正文。表达方向只约束说法，不进入 query；近期消息继续作为上下文证据，不参与记忆评分。query 只取前 200 个字符。

### 2. 第一期只对记忆正文做中文词法评分

评分字段仅限 `memory.text`。`category` 和 `topic` 是英文受控枚举，对中文 query 恒不命中，第一期不参与评分或排序，只进入入选原因展示。

分词在 Python 侧完成，不引入 PostgreSQL 全文检索扩展：

- CJK 连续段取 unigram 与 bigram，权重分别为 0.5 和 1.0；
- 拉丁字母与数字按小写词切分，权重 1.0；
- 标点与空白只作分隔；两侧使用同一分词器，命中要求 token 完全相等；
- query token 去重后计算覆盖率 `score = 命中权重 / query 总权重 ∈ [0,1]`；
- 阈值 0.15，低于阈值整条不注入；无 token 或无命中时不注入任何记忆。

阈值、预算和 query 上限是模块常量，不做运行时或环境变量配置；修改必须附评测更新。评分器是纯函数模块，PostgreSQL 与内存适配器共用。

### 3. 排序使用可解释词典序

相关性降序 → `manual` 优先于 `auto` → 置信度降序 → `valid_at` 降序（NULL 最后）→ `memory_id` 稳定序。不使用加权总分，避免阈值与排序互相污染。入选原因写入 `selection_reason`，包含分数、命中 token 与排序因素，并随回复快照落库。

### 4. 联系人记忆与本人记忆使用独立双预算

- 联系人记忆：最多 5 条且合计不超过 600 字符；
- 本人记忆：最多 3 条且合计不超过 240 字符；
- 两侧使用同一评分器与同一阈值，预算互不占用；
- 字符口径为 `len(text)`，不截断单条正文；按排序累加，遇到第一条放不下的即停止，保证结果集是排序前缀。

具体数值由第 6 节的评测标定后固化。

### 5. 目录退出候选过滤，本人记忆以独立证据类型进入上下文

- 召回候选直接来自 L1 的 active 记忆；`contact_memory_index` 第一期不再做 query 过滤，只保留 revision 快照用于生成前后复验；
- 新增 `owner_memory` 证据类型；本人证据仍携带当前 `ContactScope` 表示会话可见性，重新读取只按 `owner_id` 并校验一致；
- 提示中显式区分“关于联系人”和“关于用户本人”，证据顺序为消息 → 联系人记忆 → 本人记忆 → 继续候选；
- `validate_current` 对本人证据执行与联系人证据相同的存在性、来源、状态、有效期和 revision 复验。

### 6. 第一期以确定性离线评测为放行门槛

新建合成中文召回评测，使用真实评分器和真实 Context 组装、纯离线运行，无需模型凭据，门槛断言进 CI。每个维度至少 15 条用例：

- 直述命中：top-5 命中率 ≥ 90%；
- 改写命中：命中率 ≥ 60%；
- 无关拒绝：误注入 0；
- 跨联系人隔离：泄漏 0；
- 失效或已删除：注入 0；
- 预算：超限 0，本人记忆不占用联系人预算；
- 排序：优先级正确率 ≥ 90%。

不达标时先调整词法与阈值，不得放宽门槛。阈值与预算的标定结果记入 `docs/memory-recall-evaluation-baseline.md`。

### 7. 第一期边界

不做向量检索与 rerank（保留 ADR-005 第 5 节的后续评估条件）、不做 LLM 查询计划、不做待确认候选注入（保留 ADR-027 的后续纵切）、不改抽取与采纳、不引入 PostgreSQL 中文全文检索扩展、不改 macOS 界面。

## 取舍

- **规则评分 vs 语义召回**：选择规则评分。第一期换取可解释、离线可测和零模型成本，代价是如实承认同义改写漏检。
- **目录过滤 vs 全量 L1 评分**：选择全量评分。单联系人有界记忆量下计算成本可以忽略，换取不再被无语义目录误杀候选。
- **固定常量 vs 可配置参数**：选择固定常量。避免环境差异让评测门槛失效，代价是调参需要发版并附评测。
- **独立双预算 vs 共享预算**：选择独立。本人事实不挤占联系人资料，避免两类证据互相稀释。
- **词典序 vs 加权总分**：选择词典序。每条入选原因可逐步解释，代价是排序表达力受限。

## 后果

- `retrieval` 新增共享的纯函数中文词法评分模块，`RetrievedMemory` 增加相关性与命中词字段；`search_owner_memories` 需要补齐按 `memory_ids` 复验和同一评分器。
- `RetrievalReplyContext` 承担 query 传递、阈值过滤、排序和双预算；生产装配需要把 `OwnerMemoryStore` 接入检索。
- `reply_context_evidence.kind` 的 CHECK 约束需要迁移放行 `owner_memory`。
- 召回质量可以离线回归；同义表达漏检的规模由评测的改写维度持续暴露。
- 未来若评测证明词法不足，再按 ADR-005 第 5 节把向量路径作为补充候选集评估。

## 验证

- 评测门槛断言在 CI 通过，标定结果落 `docs/memory-recall-evaluation-baseline.md`。
- 回归覆盖：中文改写、无关记忆不注入、跨联系人隔离、失效与删除、双预算截断、排序优先级。
- PostgreSQL 侧保留隔离与失效集成测试；`selection_reason` 与证据类型随回复快照持久化。
