# ADR-182：回复时联系人／本人记忆改用本机混合检索

> 2026-11-17 局部修订：[ADR-191](191-reply-retrieval-contract-simplification.md)退役没有正常入口的待确认候选选择适配及旧回复词法回退；正式检索仍按 ADR-190 运行，历史材料、来源及删除保持。

> 2026-11-14 检索修订：见 [ADR-190](190-tencent-style-local-hybrid-retrieval.md)，L1／L0 改用 BM25＋向量＋RRF 及可删除的持久正文索引；原有范围、来源与返回预算继续有效。

> 2026-11-14 局部替代：见 [ADR-185](185-on-demand-reply-memory-and-history-search.md)。生成前预计算与不开放主动搜索的条款被替代；本机混合评分、失败词法降级和内存向量要求保留。

状态：已接受，已实现；真实模型效果待验收；2026-11-12 用户明确决定。

局部修订 [ADR-028](028-lexical-memory-recall-phase-1.md) 的匹配方式（纯词法）和 [ADR-035](035-pending-candidate-unconfirmed-reply-reference.md) 以外的 L1 召回。词法评分器、联系人／本人独立预算、来源与删除规则继续适用；未确认候选轨仍只用词法。

## 背景

真实资料只读对照（联系人王威，106 个回复时刻，不调用模型）显示：纯词法匹配下，联系人记忆平均每次只命中 0.68 条，52／106 次一条没有；检索词改为按模式取（帮我表达用草稿，帮我想想用最近 5 条消息）后升至 1.57 条，但仍无法匹配同义或改写（“徒步”对不上“爬山”），过短或泛化的查询又会命中无关记忆。[隐私规格](../current/privacy-deletion.md)要求“持续出现空结果且有实际反馈才评估 embedding”，上述数据满足评估条件。

## 决定

1. **混合召回。** 对联系人记忆和本人记忆，分别用本机 embedding（固定的 `BAAI/bge-small-zh-v1.5`，CPU 推理，不联网）计算余弦相似度，并与词法覆盖率、BM25 一起用于排序。
2. **综合分与门槛。** 稠密为主、稀疏为辅：综合分 = 0.8 × 语义余弦相似度 + 0.2 × 词法覆盖率（沿用 ADR-028 的 CJK 单字／双字评分器），综合分不低于 0.48 才有资格，按综合分降序、人工确认优先于自动、稳定 ID 决胜。没有语义得分的记忆（检索期间被修订）不入选。没有够格的记忆时一条不放。权重与门槛为模块常量，不做运行时配置。
   标定依据（王威真实资料，帮我想想模式，27 个回复时刻、61 条人工标注相关；标注、抽样与选参均在同一小样本上，结论仅作起点）：纯词法（现状）精确率 46%、召回 54%、F1 0.50，平均放入 2.6 条；本方案 0.8／0.2、门槛 0.48 精确率 57%、召回 69%、F1 0.62，平均放入 2.7 条。纯稠密最佳 F1 0.57，加入稀疏后升至 0.61～0.64（0.9／0.1 到 0.6／0.4 差别在噪声内）。门槛敏感：0.46 召回 77%（3.3 条），0.50 召回 52%（2.1 条），0.56 精确率 87% 但召回仅 33%。该模型的余弦分布整体偏高（无关配对中位数约 0.44），因此不用纯稠密的绝对相似度当门槛。帮我表达模式没有真实草稿，未做标注。
3. **预算。** 联系人最多 5 条、本人最多 3 条，不设字符上限（见 ADR-028 的 2026-11-12 修订）；完整请求预算不变。
4. **计算位置。** embedding 是异步推理，不能在同步存储事务内运行。回复冻结输入前，在事务外读取当前合格记忆池并计算得分（动作 `reply.memoryPool`），随冻结请求传入；事务内只在检索词与传入时完全一致时采用，并按记忆编号和版本取分，记忆在此期间被修订则该条没有语义得分、只能凭词法入选。入选记忆仍在事务内重新核验，冻结后的依据、来源、删除路径与既有回复一致。
5. **失败降级。** 本机模型未准备、推理失败或超过 8 秒，本次回退到词法路径并记录诊断事件 `embedding_unavailable`，不阻断回复，不使用云端 embedding，也不改变联系人范围。模型放在项目目录的 `.models/memory-embedding`（已被 git 忽略），惰性加载；须先运行 `node scripts/prepare_memory_embedding.mjs` 显式准备（已有缓存时 `--offline` 自检）。未准备时回复始终走词法路径，界面不提示。
6. **不持久化。** 向量只在单次请求的内存中计算和使用，不写入数据库或磁盘，因此不新增派生数据和删除路径。

## 不在本决定内

模型自行调用的记忆搜索工具、重排模型、多查询合并、向量缓存与索引、写入阶段的候选召回、未确认候选轨，均不改变。若真实模型对照显示质量未改善，应复审本决定。

## 后果

- 同义和改写类问题可被召回；词法已能命中的资料不会丢失。
- 每次生成多一次本机推理，记忆池小时开销有限；记忆增长到数百条以上时需要向量缓存，另行评估。
- 命中变多不等于回复更好，质量须按正常模型配置另行验收。
