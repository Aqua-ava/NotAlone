# ADR-038：导入触发原记忆任务并让前台回复优先

> 编号修订：与记忆追踪分支集成时，从原 ADR-035 改为 ADR-038，避免与待确认候选引用决策重号；已采纳的行为和范围不变。

> 状态：已采纳，实现与运行证据由对应任务提供。
> 决策日期：2026-10-04
> 局部修订：ADR-018／ADR-034 的指定任务范围，以及 ADR-020 的显式启动方式。

与 ADR-020“后台任务步骤由用户在界面触发”及 ADR-034“仅显式恢复按原任务领取”存在局部冲突；重新讨论的原因是用户已确认先完成历史导入自动闭环。导入已持久创建原任务，但仍需要额外启动，忙时还会丢失唤醒，不能兑现导入后形成可检索记忆的流程。

用户确认联系人并成功提交导入，本身成为该原记忆任务的触发动作。事务提交后，只在当前后端中保留本次任务唤醒并固定任务身份，重复唤醒合并；不自动重做终态、不恢复失败任务、不扫描重启前旧队列。默认 CLI 仍领取最早可执行任务，全局 Worker 锁、联系人租约、来源复验和三次失败预算保留。任务身份只限定调度，提取消息覆盖与水位沿用既有联系人执行器。

前台候选回复需求优先于尚未开始的后台模型调用。通过框架无关的提取、核验、裁决运行时和候选生成入口共享进程内协调，等待放在候选生成器启动和计时之前；已开始的一次运行时调用返回或抛错后让位，它可能包含供应商 SDK 内部重试。整次候选生成期间暂停后台调用。该决定只覆盖本后端，不建立跨进程模型额度服务，也不更改独立 CLI 的执行协议。

实现细化（2026-10-19）：Direct 显式重试及场景/画像工具循环按每次实际 SDK 调用领取许可，显式退避和工具轮间释放许可；已开始且尚未结算的 SDK 调用仍持有许可，调用方超时不代表取消。整次前台生成继续独占。停止 Event 可即时唤醒退避，来源/租约持久复验每秒一次，默认 30 秒退避至多 31 次；撤销检测增加至下一周期及复验/线程调度时间，下一次外发前仍强制检查。绝对期限、核验预留、有限重试及逐请求台账/追踪沿用，合成验证见[三路性能优化记录](../../.scratch/parallel-performance-optimization/planning.md)。

Worker 锁忙保留本次唤醒，退避间隔最多 30 秒。模型配置或执行资源不足时不回滚消息，持久状态保留必要原因。后端关闭后拒绝新工作，通知等待者停止，并在调用或步骤边界结束后续处理；停机等待最多 5 秒，无法立即终止的已开始调用由既有租约和恢复语义收尾，不能把线程停止标成任务成功。

取舍是自动处理减少用户步骤，同时引入唤醒、优先级和关闭协调；前台可能等待已开始的后台调用，重启后旧队列仍需用户明确执行。状态、台账与任务引用不保存正文；本次改变不扩展联系人来源范围或外部模型授权，也不实现增量同步任务、定时自动化或外部聊天发送。
