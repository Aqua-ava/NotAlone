# ADR-001：Mac 微信前台会话增量同步

> 状态：已采纳
> 决策日期：2026-07-30

> 后续修订：正文输入与后台范围以 ADR-016、ADR-023、ADR-025、[ADR-030](030-confirmed-contact-background-sync-consent.md) 为准。本文保留历史取舍；视觉采集的前台与最小区域限制继续有效。

## 背景

只依赖首次或定期历史导入，会使系统遗漏当天新发生的共同经历，下一次回复时无法使用这些上下文。Mac 微信当前窗口未向 macOS Accessibility API 暴露聊天气泡、联系人标题或输入框文本，不能将辅助功能树作为可靠的实时文字来源。

## 决策

支持“已绑定的 Mac 微信一对一前台会话”的用户授权增量同步：

1. 用户首次把当前微信会话与一个 `contact_id` 绑定，并显式开启同步。
2. 仅在微信为前台、绑定会话可见且同步开启时，检测聊天区域画面变化。
3. 发生变化后仅捕获最小聊天区域，在本地 OCR 为文字；原始视觉帧默认不落盘。
4. 解析后按会话绑定、说话人、时间线索和规范化文本去重，将新增消息写入原始消息层。
5. OCR 不可靠、会话标题变化、绑定不唯一或无法判断说话人时，停止写入并要求用户确认。

## 不做什么

- 不读取微信数据库、密钥、私有目录或非公开协议。
- 不在微信后台、其他 App 或未打开会话中采集。
- 不自动点击、切换会话、滚动聊天历史、写入输入框或发送消息。
- 不将 OCR 结果直接写成关系事实；自动写入必须带来源、标记 `auto`、可撤销（见 ADR-002）。
- 不以截图作为用户手动导入整段历史的方式；截图仅是授权同步的内部视觉输入。

## 后果

该决策能让用户正在查看的会话持续更新，但不能保证所有联系人在未打开时也同步。它要求一个 macOS 原生渠道适配器、屏幕录制授权、会话绑定 UI、变化检测、OCR、去重和明确的暂停/删除控制。

实现前必须以合成界面或经用户允许的本地测试验证：聊天区域裁剪不包含联系人列表；新消息只写入已绑定联系人；重复画面不重复入库；微信失去前台立即停止；没有任何发送或 UI 自动化调用。
