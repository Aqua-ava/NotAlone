# ADR-042：持续助手会话与单次运行上下文分界

> 状态：已采纳；任务07–18已有本轮受控实现及分项自动验证证据，实际完成范围与剩余验收见[持续会话规格及任务07–19](../../.scratch/assistant-session-context/planning.md)中的逐票Answer。17的真实App退出／重开未执行，State保持claimed；19不在本轮29票范围且保持open。原01–06仅拆分替代，未执行原票实现验收。
> 决策日期：2026-10-11
> 局部修订：ADR-009 第 4 节及核心流程“持续聊天与滑动上下文”对持续助手讨论的适用范围。

用户确认第一版持续助手会话不自动摘要、不静默截断，接近模型输入预算提醒、达到硬上限要求显式新开。若把 ADR-009 的运行消息压缩用于跨请求助手讨论，会改变用户保留的要求、候选及修改语境，与该决定冲突；本决定选择可见的长度边界，代价是长讨论需要用户新开会话。

助手会话是 owner/contact 范围内的产品记录，讨论、候选、选择、修改和纠正关系由业务存储持有，不以框架 checkpoint 或摘要代替。每次生成仍有独立请求、有效输入版本和来源依赖；授权、来源删除及失效检查不能因恢复会话而省略。

ADR-009 的单次 Agent 运行消息机制继续有效，但不得用其压缩或丢弃持续助手讨论来绕过本功能上限。输入预算须计入助手讨论、系统指令、检索/工具与输出预留；无法容纳时不提交超限生成。实现必须验证中间件边界，不通过更换框架规避该约束。既有检索材料的有界选取不等同于静默截断助手讨论。

新版候选不能抹去旧版和纠正痕迹；保存使用痕迹不等于长期关系记忆或已发送证据。来源删除传递清理依赖内容及恢复副本，保留无关讨论和无正文占位；删除助手会话不连带删除独立微信来源和关系记忆。产品行为及公开测试接缝以[正式规格](../../.scratch/assistant-session-context/spec.md)为准。

不采用 DSH，不扩大读取或外发授权，不增加自动发送、自进化、多设备同步或 OCR 改动。本 ADR 是实现约束，不是现有代码已具备持续会话的证据。

后续细化：[ADR-044](044-explicit-style-sample-retention.md)记录用户明确选择的独立样本留存规则；删除助手会话保留此前主动保存的表达样本，原始聊天来源删除仍约束样本，不能据此保留讨论副本。
