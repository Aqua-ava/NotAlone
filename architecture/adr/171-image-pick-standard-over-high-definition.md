# ADR-171：同一张图有标准图和高清图时取一张保存，不再比较内容

状态：已采纳并实现于 Go 读取程序（2026-11-05）。用户明确要求：自动取图，有标准图或高清图就保存一张，“随便取一个，一定要有图”，倾向取标准图；只有缩略图才不保存。
局部替代：[ADR-170](170-no-thumbnail-storage-and-no-original-classification.md) 第 7 条所述的 Go 层现状（`.dat` 与 `_h.dat` 解码内容不同时整条失败 `history_image_quality_unverified`）。延续 [ADR-154](154-source-grounded-image-versions.md) 以来“标准图／高清图优先于缩略图”的候选顺序，以及 [ADR-138](138-chat-image-original-extraction-and-placeholder.md)、[ADR-140](140-source-verified-viewable-chat-images.md) 对消息、联系人、唯一资源关联和完整解码的核验。

## 背景

微信本机对同一张图可能同时存在标准图（`<md5>.dat`）和高清图（`<md5>_h.dat`）。对授权联系人的实测：6450 张图里 4408 张有标准图或高清图，其中 314 张二者并存（约 5%）；高清图并不总比标准图大（只有约 20% 更大），两者解码出的字节多半不同。旧规则要求并存候选的解码内容逐字节相同，否则整条按 `history_image_quality_unverified` 失败，对这约 5% 的图几乎必然失败，聊天里该图只能保持占位。ADR-170 已不再区分原图等级，也不再保存来源分类依据，这个“用内容一致性猜版本”的门槛不再有用途。

## 决定

1. **候选顺序固定**：先 `.dat`（标准图），再 `_h.dat`（高清图）；二者都没有核验通过的图才读 `_t.dat`（缩略图）。
2. **取第一张核验通过的**：每个候选仍各自独立核验（文件守卫、消息与资源大小关联、缓存键唯一、解码、完整内容验证、来源变化检测）。标准图核验通过即选用，不再读取、解码或比较高清图；标准图因任何原因不可用（缺失、大小与资源不符、缺钥、无法解码、内容验证失败）时回退高清图。不再返回并存冲突造成的 `history_image_quality_unverified`。
3. **缩略图一档不变**：标准图与高清图都不可用时才读缩略图，仍按缩略图返回；后台对缩略图按 [ADR-170](170-no-thumbnail-storage-and-no-original-classification.md) 以 `media_thumbnail_only` 失败且不保存。
4. **失败原因优先级不变**：没有任何候选核验通过时，仍按解码失败、缺钥、关联未核实、质量未核实、本地文件缺失的既有顺序返回。来源变化和读取失败仍立即终止。
5. **不改协议和其余核验**：响应格式、`wechat-message-image-content-v2` 内嵌证明、制品清单字段、账号／联系人／消息／唯一资源关联核验保持；原图证明（`proof.OriginalProof`）后台已不使用，保留不动。
6. **制品切换沿用已审查固定配对**：新制品与当前在用制品的差别只有 `notalone_image.go` 与 `notalone_image_test.go`；决定来源身份的五个文件逐字不变，来源身份别名通过 `desktop/scripts/upgrade-history-image-cli.mjs` 新增的一对固定新旧配对迁移，不扩大审查范围。

## 取舍

- 标准图与高清图内容不同时，保存哪一张是任意的；用户要的是“有图”，二者都是可查看的非缩略图，因此接受。
- 不再用并存候选互相印证内容；单个候选仍经完整解码，错图风险由消息、联系人、唯一资源关联与缓存键核验承担，与单候选情形一致。

## 验证范围

Go 回归覆盖：并存且内容不同时取标准图（来源变体为 `main`）；标准图大小与资源不符或无法解码时回退高清图；只有高清图时取高清图；标准图与高清图都不可用时仍按缩略图返回；标准图优先于缩略图且不读缩略图。其余既有图片用例保持通过。

## 修订（2026-11-13）：文件存在却核验失败时报真实原因

决定 3 的“标准图与高清图都不可用时才读缩略图”原先把“文件不存在”和“文件存在但核验失败”混为一谈：后者也会退到缩略图，后台只看到 `media_thumbnail_only`，真实原因（大小与资源记录不符、无法解码、缺钥、内容未核实）被掩盖，聊天里显示“仅有缩略图”，也无法据此定位问题（实测有已发送且 `.dat` 在本机的图被这样掩盖）。

修订后：标准图或高清图文件**至少有一个存在**而没有任何一张核验通过时，读取程序立即按决定 4 的既有优先级返回真实失败，不再读取缩略图；只有标准图与高清图**文件都不存在**时才读缩略图并按缩略图返回（“微信尚未下载标准图”仍显示仅缩略图）。决定 1、2、4、5 不变；来源变化和读取失败仍立即终止。

制品切换沿用已审查固定配对：这次与当前在用制品的差别是 `notalone_image.go`（本修订与同日的零 server_id 关联）与 `notalone_image_test.go`，通过 `upgrade-history-image-cli.mjs` 新增的固定新旧配对迁移来源身份别名。

Go 回归：文件都不存在时按缩略图返回；标准图大小不符、无法解码、仅高清图大小不符、二者都失败时，报真实原因且不返回缩略图。
