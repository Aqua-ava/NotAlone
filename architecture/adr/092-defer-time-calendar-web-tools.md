# ADR-092：时间、日历和网络搜索工具保留为未来可选方向

> 状态：已采纳（2026-10-21）。用户在逐项复审 Q07 时选择沿用当前设计，暂不增加时间、日历和网络搜索工具，并要求将旧文档中的必备能力改为未来可选方向。

ADR-009 和 Agent 草案要求注册 `get_current_time`、`search_calendar`、`web_search`，现行流程及隐私表也把它们写成可用工具，但当前回复运行时没有接入。此次取消当前版本的必备与验收要求；三类工具只保留为未来可选方案，不能因为旧文档或 Skill 描述而自动补入。

- 当前候选回复继续使用本次输入、已保存的合法聊天与关系资料、受控 Skill 及 ADR-090 的只读补查，不新增上述三类模型可调用工具或相应授权入口。
- 这不取消程序已有的时间戳、时区处理、记忆有效期、过期检查和运行超时，也不影响已获授权的模型调用或微信同步；程序时间处理与“让模型主动调用时间工具”是两种能力。
- 当前不主动读取日历或通过产品工具搜索公开网络。未查询的信息不能被当作已核实的外部工具结果；未来确需使用时，先提出具体场景与独立接入决定，明确输入、返回、预算、失败处理及验证。
- 未来时间工具须由确定性代码返回明确时区的时间。日历只读且须单独明确授权范围；网络查询须限定出站字段、接收方和用途，不默认携带聊天正文、联系人身份或关系资料。保留这些约束不代表已有连接器、授权或运行许可。
- 外部聊天发送仍禁止，不因未来可选工具而成为可执行能力。资料隔离、来源删除及证据追踪保持。

本决定局部替代 ADR-009 第 3 节的三类工具接入要求及其后果中的相应当前验收要求，闭合 ADR-091 留待确认的 Q07。旧 ADR 保留历史理由；现行流程、隐私表和 Agent 草案明确区分当前能力与未来可选方向。

实现依据为[当前运行时装配](../../backend/src/notalone/reply/adapters/langchain_runtime.py)；本轮只统一文档，不修改程序、连接器、凭据、运行配置或业务数据，未新增网络访问、模型调用或桌面验收。
