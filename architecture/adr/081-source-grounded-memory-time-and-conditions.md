# ADR-081：来源锚点、日期精度与条件性记忆

> 状态：已采纳的实现目标（2026-10-20）。用户确认方案及四票拆分；实现、工程验收和模型质量分别见[任务索引](../../.scratch/memory-temporal-semantics/planning.md)。
> 局部细化 ADR-048 的历史／当前区分；替代现行数据规格及旧提取提示中“生效时间缺省为采纳时间”和无来源的瞬时状态当天到期口径。保留 ADR-069 的完整提取／独立核验、ADR-070 的旧资料边界和 ADR-071 的错误／变化来历记录，以及 ADR-080 的所有失效记忆禁止生成规则。

来源聊天时间、事件发生时段、记忆有效期和保存时间表达不同含义。用写入时刻或固定寿命补齐事实时间容易把历史导入改成现状；单纯四态标签也不足以表达条件与不确定性。因此每条事实以其直接来源作时间锚点，保留年／月／日／时刻精度及模糊表达，未知保持未知。当前时间仅比较有依据的适用期间，不证明计划完成或状态持续。

适用条件保留原意与来源。后续证据可以说明条件变化，但不能自动推导原禁忌已撤销。新旧记忆裁决同时取得各版本合法来源、事件及消息时间，区分补充、纠错、变化、历史补充和冲突；晚导入和较晚回忆均不能单独决定覆盖现状。相关证据只在已授权同联系人范围内有界获取，不将全部历史无界传给模型。

新语义贯穿提取、核验、持久化、分层资料、页面、回复及冻结／恢复依据，并继承原有来源删除与人工决定。旧合同兼容读取、旧快照缺失保持未知；不因上线自动重新解释真实存量。代价是增加版本化元数据与跨路径回归，收益是保留可追溯的不确定性，避免制造虚假的日期精度和现状结论。

## 关系证明与替代门禁

版本化 `evolution` 区分 `supplement`、`state_change`、`error_correction`、`historical_supplement`、`unresolved_conflict` 和独立事项 `independent`，同时保存 `claim_changed` 与 `condition_changed`。`source_supported` 只表示当前有界来源支持该关系，不能认证现实已发生或状态仍持续。单条与批量裁决使用同一新旧证据投影：每次最多八个旧版本、六十条必要消息和一万六千字来源，包含每条原始当地消息日期、事实有效期、事件精度和适用条件。内部范围、原始来源摘要与版本摘要不发送模型。

替代要求独立关系核验与原来源／父版本事务复验。可比较的发生顺序优先；无事件时已知更早或同刻来源不能替代更晚陈述，缺少可靠顺序谨慎待确认，不使用任意 TTL。UPDATE 还需原主张改变；条件改变不能代替此证据。MERGE 仅处理有充分补充依据、无事件／条件差异的自动资料，合并正文另行来源核验；人工决定继续优先。新导入的早日期消息沿现有处理计划与回执处理，重试和重复原文件保持幂等，不以水位吞掉新增消息。

未知关系与未解决矛盾按 ADR-070 的窄例外待确认。反证按已用事实 ID／版本有界投影到生成依据，旧 L2／L3 若遗漏该不确定性不再具备当前读取资格。完成回复保存当时元数据及来源依赖，重启不从当前资料补证；后来变化另报依据变化。关联父版本及反证来源进入删除闭环；被替代父版本仍仅管理可见，不能因其出现在变化来历中重新作为生成事实。

有相似旧资料时，ADD／KEEP 也不能以空关系自动新增。独立事项须独立核验，限新增，不授予 UPDATE／MERGE 权限；新事实正文来源仍只含自己的直接来源。无法冻结的关系保留未知候选，不保存为可复验变化证明。

已核验的计划修订按新旧声明来源顺序判断，安排日期可以提前；有据取消不要求声明包含发生时段。真实发生事件仍保留先后门禁。同条件文本换了消息或引用位置不等于条件改变；原主张改变另行核验。事务父版本摘要绑定持久记录，当前矛盾投影另入分层依赖指纹，既允许后来澄清更新，也阻止旧摘要继续漏掉冲突。

本人 L2／L3 对外模型只接收变化类型、说明、来源支持及主张／条件改变标记，剔除变化消息和版本标识。完整引用留在后端执行来源、版本与删除复验。
