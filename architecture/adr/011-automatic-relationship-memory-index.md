# ADR-011：关系记忆自动管理与主题目录渐进加载

> 状态：已采纳
> 日期：2026-08-16
> 修订：ADR-005 第 1 节的常驻卡组装和第 3 节的常驻卡视图
> 后续修订：第 3 节中 `memory_candidate.pending` 不得进入生成的绝对表述由 ADR-035 修订为“待确认候选可以带强制未确认标注、在独立预算内作为参考进入上下文”；它仍不得进入已确认记忆集合，第 4 节的固定加载规则继续有效。
> 后续目标修订：[ADR-067](067-layered-scenario-and-profile-context.md)允许关系语境开启时预加载有界 L3 背景和 L2 目录、按需读取场景正文；该分层资料例外已有受控生产接线，缺少显式配置或读取资格时不启用；实际放行与验收另行核验，见[架构索引](../README.md)。底层记忆仍不新增常驻标记，原 L1 动态检索保持。

## 背景

现行设计为 `confirmed_memory` 保存 `carry` 标记，并在每次候选回复中固定加载 5-10 条常驻卡。后续讨论确认，这会把上下文预算和检索策略暴露成用户需要理解的记忆模式，也会让与当前话题无关或已经过时的关系资料反复进入模型。Codex 和 Claude Code 的公开记忆设计表明，提取、整理、精简索引和按需加载可以自动完成，用户主要负责查看和纠错，而不是逐条管理加载模式。

## 决策

### 1. 关系记忆默认自动管理

`confirmed_memory` 不再保存 `carry`、`pinned`、`excluded` 或等价的固定加载模式。ADR-002 的自动采纳、来源证据、`auto/manual` 采纳来源、有效期、用户修正与删除规则继续有效；`auto/manual` 不是用户需要选择的加载模式。

用户可以查看、修正或删除关系记忆，也可以明确要求系统记住一项资料，但不需要逐条决定它是否进入每次回复。修正和删除作用于权威关系记忆，并触发所有相关目录、索引、缓存和运行摘要失效或重建。

### 2. 系统自动维护联系人记忆目录

系统按 `owner_id + contact_id` 从当前有效关系记忆生成 `contact_memory_index`。目录使用既有固定主分类，并由系统生成精简子主题；它只帮助定位可能相关的资料，不包含全部记忆正文，不产生新的关系事实，也不能脱离权威条目和来源证据长期保留。

目录必须有独立的上下文预算。超过预算时合并目录描述或减少低价值主题，不能删除权威关系记忆，也不能让预算外资料失去按需检索能力。

v1 逻辑上每位联系人只保留一份当前目录。目录记录联系人范围、生成时的记忆版本、可用状态和主题列表；每个主题只记录分类、一行检索提示和对应的 `confirmed_memory` 引用。联系人记忆发生新增、修正、删除、重新分类或有效期变更时递增 `memory_revision`；目录版本不一致时不得继续使用，必须重建。即使版本一致，正式加载前仍须重新校验被引用记忆的范围、状态和有效期。

### 3. 每次回复自动选择相关资料

上下文模块根据当前消息、用户已确认的表达方向和近期对话，从相关 `owner_preference` 与当前联系人的有效关系记忆中自动选择少量基线资料。方向建议使用更小的自动选择预算；正式候选生成可以在基线之上，通过受控只读 Tool 补查消息和关系记忆。

联系人记忆目录是选择输入或可重建投影，不要求完整发送给候选生成模型。进入回复上下文的每条关系记忆仍需携带引用、状态和入选原因；`memory_candidate.pending`、已失效或已删除资料不得进入生成。用户可以查看并从本次回复上下文移除不适用资料，但该操作不修改长期关系记忆。

### 4. 固定加载只保留确定性硬规则

联系人隔离、禁止自动发送、高风险标记和用户当前明确方向仍由确定性代码每次强制执行。它们不是关系记忆，也不受自动目录或检索排序影响。普通 `owner_preference` 和联系人关系记忆都不固定全量加载，近期对话继续优先于旧记忆。

## 后果

- 数据模型和用户界面不实现 `carry`、固定常驻或排除模式。
- 记忆模块负责自动维护联系人记忆目录；上下文模块负责按请求选择基线资料，候选回复 Agent 只负责必要的补查。
- 现有 5-10 条常驻卡上限被目录预算和本次已确认资料预算取代；具体 token、主题和条目阈值由合成评估确定。
- 删除、失效、修正或重新归类关系记忆后，目录和检索索引必须可重建，且不能从旧缓存、摘要或 checkpoint 恢复失效内容。
- 验证必须覆盖自动选择的相关性、无关资料不进入上下文、跨联系人隔离、来源删除后目录与检索同步失效，以及用户本次移除资料不会静默修改长期记忆。
