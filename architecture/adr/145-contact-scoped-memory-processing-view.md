# ADR-145：记忆处理卡跟随当前联系人

> 状态：已采纳；决定日期：2026-11-01。
> 来源：用户明确要求每位联系人显示自己的记忆处理状态。
> 局部修订：ADR-107 中「我」页的主卡读取全局本人处理状态的展示约定；本人任务、资料归属与调度仍保持独立。

## 背景

SQLite 记忆页曾读取全局最近一轮与全局队列，导致切换联系人后仍显示同一份进度与失败。旧轮次可能含多个联系人及本人任务，不能仅改变标题或筛选一个总数。

## 决定

1. 记忆处理卡始终跟随顶部当前联系人。「对方／我」切换只改变资料列表，不把主卡切到全局本人任务。本人任务不计入联系人处理量或失败状态。
2. 使用宿主确认的 owner 与稳定 contact_id 读取该联系人最近有效处理轮次、实际目标、调用、待处理队列及主题／概览期限。旧多联系人轮次按实际任务与来源投影，不继承其他联系人的失败或完成。
3. 未选择联系人时显示选择提示；没有对应轮次时显示暂无处理记录。两者均不回退全局最近记录。切换即撤下旧快照，迟到响应不得回填。
4. 读取只返回本联系人的任务、目标、候选及计数，保留实时授权、来源、删除和文档发布资格检查。联系人主卡保持只读，不提供会作用于整个旧轮次的控制动作。
5. 增量调度、独立历史初始化、来源核验、模型调用及删除规则不变。打开、刷新与切换页面不创建任务或调用模型。
