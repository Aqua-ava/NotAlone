# ADR-030：已确认联系人的后台同步与首次手动选择

> 状态：已采纳
> 决策日期：2026-09-22

用户确认保留 ADR-023 的 CLI 后台同步能力，并将首次私聊列表从默认全选改为默认不选。用户可逐项勾选，或主动全选当前未绑定列表，再最终确认；刷新只保留仍有效的手动选择，不自动选中新会话。它修订 ADR-023 第 1 条的默认全选规则，避免用户尚未决定范围时界面已代选全部会话。

正文读取以用户确认的 active 绑定集合和总开关为边界。NotAlone 后端运行且开关开启时，CLI 可以在微信不在前台时读取已确认联系人的文字增量；全局 session 流只提供变化触发信息，正文仍按绑定的稳定会话标识读取。OCR 只在微信前台、最小会话定位区域可见时工作；定位失败停止当前自动定位，不阻塞其他已确认绑定的 CLI 后台同步。原始视觉帧仅在端侧内存中处理，不持久化或上传。

关闭同步或退出应用时停止读取。重新开启后的缺口恢复沿用 ADR-025：仅限仍有效的已确认绑定，不追溯 baseline 之前历史，并展示恢复状态。首次确认说明应同时解释后台读取范围、停止入口、恢复行为和人工发送边界。此决定不授权未确认会话正文读取、群聊、其他 App、自动切换/滚动微信或消息发送，也不改变用户自装 CLI 和外部模型单独授权的要求。

## 与既有决定的关系

- ADR-001、ADR-003、ADR-016 的历史前台正文采集限制已由 ADR-023 的双通道和 ADR-025 的补齐规则修订；视觉采集的前台与最小区域约束继续有效。
- ADR-023 的后台范围和每联系人 cursor 保留；只替换首次默认全选。
- ADR-025 的关闭期间停读、重新开启后有界补齐保留。本次不修改同步引擎、已存在的绑定或用户当前开关。

## 验证

首次列表及后续异步刷新均不自动增加选择；主动全选只选择当时显示的未绑定会话；零选择不能提交。已确认集合以外不写消息、关闭停读、前台定位失败不阻塞后台同步等行为继续由现有同步契约测试约束；真实微信体验仍需用户授权后的人工验证。
