# ADR-026：语用解释先于关系记忆采纳

> 状态：已采纳
> 决策日期：2026-09-09
>
> 本 ADR 补充 ADR-024 的风险门槛，不替换其来源、`pending`、版本化采纳和
> fail-closed 约束。

## 背景

仅要求模型输出一条“事实文本”无法区分事实、计划、假设、转述、玩笑、讽刺和夸张。
例如“我准备贷款 30 万加仓”可能是真实计划，也可能是吹牛；模型可以理解语境，但
不能凭置信度证明现实世界已经发生。若直接写入 `confirmed_memory`，一次玩笑或假设
就会被后续回复当作联系人事实。

## 决策

1. 在现有记忆提取模型调用中加入结构化语用字段：说话行为、断言状态、修辞状态、
   多个备选解释和简短用户可见依据。模型仍由调用方注入，不在模块内硬编码供应商。
2. 第一版继续使用当前结构化输出模型，供应商构造入口的温度固定为 `0`；不额外
   下载或部署分类模型、embedding 模型或规则包。
3. 模型只解释有限的单联系人窗口：每次最多 20 条目标消息，并补充目标前后各最多
   20 条同联系人消息。候选必须至少引用一条目标消息，不能用上下文消息单独制造事实。
4. 由代码计算记忆分流：确定、字面、非歧义陈述才进入既有自动采纳门；计划、假设、
   条件、转述、纠正和未知状态只能 `pending`；问题、玩笑、讽刺和夸张默认不产生
   长期候选。
5. 不判断现实世界真伪。来源、字段、联系人范围和模型失败由确定性外壳校验；模型
   调用失败时整批安全停止、不推进水位、不写入记忆；单条非法候选只被拒绝，合法
   候选可以继续处理。
6. 最小实现不新增关系记忆表字段：提取阶段的结构化标签保留在 `ExtractedFact`；
   写入 pending 时将 `pragmatic:*` 阻塞原因复制到已有 `risk_flags`，保持现有数据库、
   删除和 API 契约可用。完整解释、备选项的记忆管理展示另行设计。

## 取舍

- **单独训练/下载分类模型**：拒绝。当前数据量不足以支持稳定的中文关系语用分类器，
  且会增加部署、隐私和版本维护成本。
- **只靠关键词规则**：拒绝。关键词能识别“如果”“开玩笑”等显式线索，但无法稳定
  处理上下文、省略、反讽和引用；规则保留在模型之后，专门做安全闸门。
- **让模型直接返回 `confirmed`**：拒绝。模型负责解释，代码负责分流和写入；置信度
  不是事实证明。

## 后果

- 记忆提取结果不再只有“事实/不事实”两种隐含状态，用户可以看到待确认原因和来源。
- 计划或未知解释可能增加 `pending` 数量；纯玩笑等结果会被计入不生成长期记忆的统计，
  便于评估漏记与误记的取舍。
- 解释标签当前属于提取运行结果，不能声称已经有完整持久化解释审计；若 UI 需要长期
  展示备选解释和消息正文范围，应新增独立的解释投影和删除路径，而不是把完整 prompt
  或模型内部推理写进关系记忆。

## 验证

合成单元测试覆盖结构化字段解析、联系人窗口和目标证据边界、确定事实自动采纳、计划
和歧义进入 pending、玩笑/讽刺/夸张不生成候选、来源越界拒绝以及模型失败安全停止。
真实模型效果不由这些测试代替，需使用后续匿名标注集单独评测错误确认率、证据精度和
选择性拒答率。
