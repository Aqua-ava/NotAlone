# ADR-132：按会话名称关联已有联系人

> 实现收敛：[ADR-192](superseded/192-retire-foreground-observation-compatibility.md)删除没有正式调用者的前台再次确认／写证明接口及空建议联系人；本文自动关联、顶栏手选与授权边界保持。

> 状态：已采纳（2026-10-31）。按用户在看到低分和缺名阻断后明确要求恢复所有已建联联系人的直接使用，修订 ADR-105／110／130 在 SQLite 接入后叠加的读取授权、逐人新桌面确认及无关群名缺失全局门；ADR-076／077 的名称匹配算法与 0.30 下限保持。

> 后续局部修订：[ADR-158](superseded/158-contact-selection-keeps-foreground-follow.md)移除顶栏手选后的独立锁定模式。显式选人仅确认本次归属，不停止前台跟随，也不提供恢复开关；用户明确确认与读取授权仍分开。

用户已多次实测名称正确，明确要求低至 30% 的正确识别也能通过。分数是原始 OCR 分数，并非最终匹配概率。决定恢复名称与既有稳定绑定的启发式关联，不再把后置条件显示成名称识别失败。

- 每轮仍验证前台与唯一窗口、完整标题、五秒新鲜度、当前配置账号及来源一致，枚举有界全类型会话元数据。按既有算法唯一匹配到 private，且稳定 locator 对应同账号 active 联系人的 verified 既有绑定、保存名称一致时，直接选中该联系人并开放用户主动生成。
- 前台身份投影独立于正文 read grant；未重新授权后台读取的联系人仍可使用已合法保存的资料。自动关联不恢复授权、不建立联系人、不按名称合并，也不写人工确认或新的桌面证明。用户点击生成的既有受理与来源核验流程保持。
- 0.30／0.50 不单独阻塞；已知同名群、重名或规范化碰撞、未知候选类型、非法或截断名单、不完整标题、过期帧、来源变化及删除屏障仍按当前规则拒绝。无关群显示名缺失不再全局否决已匹配的既有私聊；不拼造缺失名称。
- 界面准确显示“按会话名称匹配到配置账号的已有联系人”，不宣称前台账号已独立认证或把匹配标成人工确认。无法匹配时，顶栏显式手选确认本次表达对象，不依赖旧桌面回执，也不授予读取；按 ADR-158 继续自动跟随，返回微信后的新鲜有效匹配可切换对象，失败撤销当轮资格。

这项选择接受名称关联的剩余风险：配置账号元数据不能独立证明前台微信登录同一账号；缺名群也无法严格排除同名冲突。因此这里的“匹配成功”是既有名单与稳定绑定下的启发式结果，不能宣称身份强保证。当前对象必须在界面可见，最终候选可编辑、消息仍由用户亲自发送。没有匹配或关系资料不足时不虚构语境。
