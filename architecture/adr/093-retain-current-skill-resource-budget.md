# ADR-093：沿用现有 Skill 导入限制与整轮输入预算

> 后续局部替代：[ADR-096](096-directory-backed-reply-skills.md)采用目录文件保存已发布正文与资源，自动发现新增和修改；数据库只管理业务元数据。本文旧存储及仅手动导入表述保留历史，范围、审核、预算、删除和权限约束继续有效。

> 状态：已采纳（2026-10-21）。用户在逐项复审 Q08、了解当前限制及独立资源额度缺口后选择“按现在的设计”。

此次沿用现有实现，不增加独立的辅助资源单次读取或整轮累计额度。原规格把单次加载预算作为必备要求，现行文档又声称相关测试已完成，与代码和历史记录不一致；本决定取消该独立额度的强制要求，并分别记录导入限制、运行读取和模型总输入预算，不能把不存在的额度写成已实现或已验证。

- 导入仍完整校验路径、类型、范围和不可变版本。现有实现限制 SKILL.md 最多 500 行、估算 5000 tokens，辅助资源最多 100 个、单个 1 MiB、合计 4 MiB；这些是导入限制，不代表每次模型调用可容纳整个包。
- 运行时仍最多使用一个 Skill 版本，辅助资源须属于已加载版本与本次范围。当前资源读取返回完整正文，记录已读路径，不单独计费单次／累计资源额度；不新增自动裁剪。SKILL.md 沿用现有受控 offset／limit 读取语义。
- 保留每次模型调用前的完整输入预算及输出预留检查。导入成功不保证某次生成能容纳全部资源；大资源可能导致后续输入预算拒绝，沿现有错误路径处理，不绕过总输入上限、不静默压缩讨论。
- 当前不把新增独立资源额度列为必做整改。以后若需要减少大资源造成的生成失败，再凭实际场景单独复审额度或读取方式。
- 设计选择不等于验证通过。原规格关于导入边界测试、桌面回滚或服务端接口的历史记录须按相应代码与实际执行证据单独核对；本轮不补签，不据现行接口存在宣称所有功能或预算均已验收。

本决定修订[Skill Library 现行设计](../current/skill-library.md)第 3.3 节及[原规格](../../.scratch/skill-library/spec.md)的“辅助资源必须有单次加载预算”要求，细化 ADR-019 的受控资源边界；其路径、隔离、版本、隐私、删除与禁止脚本执行规则保持。历史缺口记录保留，并明确独立资源额度已不属于当前必备能力。

依据为[包校验](../../backend/src/notalone/skills/package.py)、[资源读取与 SkillLoadBudget](../../backend/src/notalone/reply/adapters/langchain_runtime.py)及[模型输入预算](../../backend/src/notalone/reply/adapters/input_budget_middleware.py)。本次只改文档，不修改限制数值、程序、模型配置或业务数据，未新跑程序测试或真实模型验收。
