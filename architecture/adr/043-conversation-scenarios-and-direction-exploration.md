# ADR-043：聊天场景与有界方向探索

> 状态：已采纳；本轮合成实现及固定源公开策略38场自动组合已完成，标签通过与同次命令后续失败的区分以逐票实录为准；真实App／原生与真人质量未验。
> 决策日期：2026-10-11。
> 局部修订：ADR-010 的回复策略粒度、ADR-012 第 3 项的输入模式范围，以及核心流程/隐私文档的方向建议阶段约束。

用户已确认聊天策略草图 Q1–Q32，并确认第一版包含回应消息、主动聊聊、候选消息组和活跃任务中的方向更新。主动联系不一定有目标消息，因此扩展既有回复应用入口的输入契约，以明确目的表达该场景；不伪造对方消息，不另建绕过联系人校验、上下文、存储与删除的生成链路。既有草稿改写仍保留。

Q16–Q20 的场景 Skill 可以包含多种处理方向和方法，这与把 ADR-010 的“一种策略”解读成“一种回应方向”冲突。一个 Skill 按沟通场景组织，内部可有接受、拒绝等方法；按当前主要任务至多使用一个已启用的不可变版本，关系类型和语气不各拆成 Skill。具体邀约 Skill 创作继续暂停。

Q19 允许 Skill 在方向确认前辅助理解，与现行方向建议阶段禁止 Skill 冲突；现在允许通过既有受控 Skill 边界读取一个有效版本的有限策略资料。该阶段仍禁止业务 Tool 补查循环、风格样本、日历/网络查询、脚本和外部发送；加载不代表确认用户立场，也不能改变权限。沿用目录 revision、范围检查、版本及来源删除失效，不采用完整自治 Agent。

用户主动打开方向探索后，仅在任务活跃、范围有效且尚未确认方向时，新消息可触发有预算的建议更新；关闭或离开该任务即停止。方向确认或开始生成/编辑后，只提示，由用户决定是否更新。此处的探索停止不改变 ADR-042 中已经发起的候选生成生命周期，不创建应用外后台任务。

代价是需扩展输入、建议版本和消息组契约，并验证探索阶段的 Skill 加载及删除。好处是用户可以主动联系、选择真实意愿，而不被原先单消息输入或策略分类限制。实现范围、验收和排除项见[聊天策略规格](../../.scratch/conversation-reply-strategy/spec.md)；本 ADR 不是功能已实现或外部模型调用的证明。

本轮实施注记：回应与主动目的、独立探索及澄清、Skill版本延续、消息组编辑／选择、typed连续修改和新消息显式采用已接既有联系人与唯一会话／生成链，有逐票合成HTTP和具名Page证据。未确认方向的有界更新与已发起候选仍按各自门禁运行，未增加后台自治或发送能力；最新跨票组合、真实App／原生及真人语义质量未由本注记验收。运行结果和真实State见正式01–11任务Answer，原决定与排除项保持。
