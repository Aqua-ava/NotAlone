# ADR-029：提取失败的分类计数与批次跳过恢复

> 状态：已采纳
> 决策日期：2026-09-17
>
> 本 ADR 落实 ADR-002 第 4 节"失败可见性"和 ADR-014 的水位续跑语义：模型调用失败与输出不可用分开处理，只有输出不可用才计数并在连续失败后跳过。ADR-027 的评测门槛、ADR-024 的采纳规则不变。

## 背景

提取按联系人水位分批执行；一个批次失败就停止本次运行且水位不推进（`command.py`）。这带来两个问题：

1. 确定性坏批次会让水位永久停在同一条消息：CLI 每次手动重跑都停在同一处；后台任务重试到上限后任务失败，同样越不过去，后面的消息永远得不到提取。
2. 失败只有一个来源 `ExtractionRuntimeError`，把"模型调用失败"（网络或服务不可用，修好即恢复）和"输出不可用"（模型有返回但不可解析，同一输入会持续重现）混在一起；如果统一按次数跳过，一次网络中断重跑三次就会把整段积压当坏批次跳过。
3. 写入裁决的模型调用失败直接抛出，绕过批次统计，整轮运行无记录中断。

参照 WeKnora 的提取实现：模型调用错误中止任务、只有输出无效才按区间计数，连续三次后记录失败区间并越过，其余工作继续；失败区间保留供人工查看。

## 决策

1. **失败分类**：`ExtractionRuntimeError` 表示模型或环境不可用，可重试、不计数；新增子类 `ExtractionInvalidOutputError` 表示输出不可用，参与计数。适配器在"无结构化结果、动作或 ID 非法"处抛后者，调用失败处抛前者。
2. **计数口径**：只有 `invalid_output` 计数；只有本次失败区间起点与已记录起点相同才累加，区间变化重新从 1 计数，避免两个坏批次互相累加。阈值 3 为模块常量（`DEFAULT_FAILURE_SKIP_THRESHOLD`），与 ADR-028 一致不做运行时配置，修改需附验证。
3. **跳过语义**：达到阈值时跳过该区间——写入最近跳过记录、把水位推进到区间末尾、清除计数——并在同一次运行里继续处理后续批次。未达阈值或 `unavailable` 失败仍停止本次运行且不推进水位。
4. **状态存放**：`memory_extraction_watermark` 单行扩展两组字段，语义分开：
   - 计数中：`failure_count / failure_code / failed_from_id / failed_to_id`，成功推进水位或跳过时清除；
   - 最近跳过：`last_skipped_from_id / last_skipped_to_id / last_skipped_code / last_skipped_at`，只被下一次跳过覆盖，供 CLI 输出与后续人工重试使用。
   `last_message_id` 改为可空，表示首次运行尚未成功推进。
5. **统计与调用方**：`failed_batches` 表示本次运行提前停止的批次数（两类失败都可能），`skipped_batches` 与 `skipped_ranges` 表示已跳过的批次与区间。后台 Worker 只在 `failed_batches>0` 时记 retryable 失败，纯跳过的运行视为步骤成功；CLI 退出码只看 `failed_batches`，跳过打印警告但退出 0。未跳过的 `invalid_output` 必须仍算失败——否则 Worker 会把"消息尚未提取完"当成功，任务带着缺口进入后续步骤。
6. **覆盖范围**：提取与写入裁决两类批次级模型调用失败套用同一策略；提取循环只捕获 `ExtractionRuntimeError`，非模型异常不转为失败分类、不写入跳过状态。
7. **边界**：没有水位端口（如纯统计调用）时不做计数与跳过，维持停止语义；人工重试入口（重置水位或重试跳过区间）留后续票。

## 取舍

- **分类 vs 统一计数**：选择分类。统一计数会把环境故障的积压按"坏批次"跳过，属于静默数据丢失；分类的代价是适配器要维护两个错误类别。
- **跳过 vs 永不跳过**：选择跳过（有上限的重试）。永不跳过在确定性坏输出面前会让水位永久停滞；跳过把"提取缺口"显式记录下来而不是假装成功。
- **水位表扩展 vs 独立失败表**：选择扩展单行。失败计数与水位同生共死，单行足够；多段历史与人工重试属于后续票，届时再评估独立表。
- **常量阈值 vs 可配置**：选择常量。避免环境差异让跳过行为不可复现。

## 后果

- 新增迁移 `034_extraction_failure_recovery.sql` 并纳入 `install.sh` 的可重复增量迁移列表。
- `run_extraction` 的统计增加 `skipped_batches` 与 `skipped_ranges`，CLI 打印跳过区间；Worker 代码不变。
- 被跳过的消息区间在库中可见（最近一次）并可被后续重试票读取；跳过的批次不计入退出码。
- 输出不可用的失败不再让后台任务失败重试到上限；环境不可用时行为与之前一致（停止、水位不动、可重试）。

## 验证

- 纯函数测试覆盖：首次计数、同区间累加到阈值、区间变化重置、阈值可配置、非法阈值与状态拒绝。
- 命令级合成测试覆盖：未达阈值停止且水位不动、达阈值跳过并继续后续批次、`unavailable` 永不计数或跳过、新区间重新计数；全部离线运行，不调用模型。
- 外壳测试覆盖两类失败的分类标记。
- 迁移在本地数据库重复执行通过。
