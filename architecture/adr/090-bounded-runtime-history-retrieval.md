# ADR-090：回复运行时按需补查受控历史

> 状态：已采纳（2026-10-21）。用户在逐项复审 Q05 时选择沿用当前受控补查设计。

ADR-012 的“Runtime 初期不直接调用动态检索 Tool”与后续上下文规格、现行流程和生产装配不一致。此次明确结束该初期限制：应用层先确认本次回复范围并组装初始上下文，Runtime 在该范围与预算内按需调用只读工具补查相关历史，不必把全量聊天预先放入模型输入。

## 允许的能力与边界

- 保留当前 `conversation_search` 相关历史搜索及 `conversation_query` 邻近消息查询。它们查询已保存且当前可用的资料，不直接读取微信、开启同步、建立联系人或调用任意数据库查询。
- 应用层固定注入 `owner_id + contact_id` 和本次已验证的会话范围；模型只能提交查询意图，不能通过工具参数切换联系人或扩大权限。引用和来源仍经 RetrievalPort 复验，已删除或失效资料不能因补查恢复可用。
- 当前表达工作区只有允许关系语境时装配历史工具；关闭关系语境不提供这些工具。存在排除消息时，沿用 `workspace_recent_only` 的保守策略，停用可能携回原文的补查及相关派生资料，不借查询绕过排除。
- 查询次数、结果数、邻近窗口、文字量及耗时均有上限。当前历史工具调用总预算最多三次并计入前置已用预算，不为每次补查重新分配完整预算；保留本轮证据与调用轨迹。未命中、失败或耗尽不触发无限重试；可以基于仍合法的已有上下文返回，不能绕过范围、来源或输入预算检查。
- Context 仍负责初始资料选择，Retrieval 仍负责查询边界与来源检查，Store 仍负责保存请求、候选及证据快照。Runtime 不成为联系人识别器，也不自行写记忆、修改资料、授权新范围或发送外部消息。

## 替代范围与验证限制

局部替代 ADR-012 第 4 条的初期动态检索禁令及[旧模块草案](../drafts/archive/reply-module-structure.md)的笼统“不直接查询”要求；保留模块职责和应用层范围控制。允许范围仅为已有受控只读能力，不因此批准时间、日历、网络、Shell、任意文件或写入工具；这些能力各自的设计状态不由本决定改变。既有 Skill 与分层资料读取继续遵循其独立规则。

实现依据为[生产装配](../../backend/src/notalone/reply/adapters/langchain_runtime.py)、[历史工具边界](../../backend/src/notalone/reply/tools.py)和[上下文资格](../../backend/src/notalone/reply/context.py)，原功能规格见[记忆与 Skill 上下文](../../.scratch/memory-skill-context/spec.md)。本次仅统一文档，未改代码、同步授权、运行配置或业务数据，不据此宣称本轮已做真实模型或端到端验收。
