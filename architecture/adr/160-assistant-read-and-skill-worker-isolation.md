# ADR-160：助手回看与 Skill 核验分离执行队列

> 状态：已采纳（2026-11-03）。用户确认实施；实际测量与验收见[验证记录](../../docs/verification/assistant-read-isolation-20261103.md)。局部补充 ADR-109、ADR-106 与 ADR-159。

助手打开讨论时，删除状态、会话目录与正文串行进入后台写者队列；单独优化正文接口仍会等待队首长查询。Skill 的原生目录核验使用同步子进程，又会阻塞 HTTP 宿主。决定分别隔离这两条执行路径，同时保留唯一业务写者和全部来源、删除与提交校验。

- 助手复用一个独立于前台识别的只读 SQLite 附属 Worker，沿用同一受控数据库、运行身份和租约；不再次打开业务存储，不复制数据库。仅白名单开放讨论目录／正文／轨迹、候选查看／状态／版本、近期消息和删除状态；不按 HTTP GET 一概分流。
- 每个正文读取使用短快照，前后比较 owner、contact、来源、讨论及相关资料版本，并登记现有删除持有者。范围撤销、来源连续性变化、删除 fence 或租约失效时废弃在途结果并退休连接；普通会话不存在不关闭通道。候选生成、编辑、采纳与最终保存仍在唯一写者上重新核验。
- 删除或宿主退出必须确认只读连接实际关闭；失败保留持有者和退休连接，允许重试，不能把取消请求等同于关闭完成。共享读者退休可能同时取消其他联系人的在途回看；这些请求可重新读取。正常切换联系人复用读者，不为每位联系人创建线程。
- Skill 库拥有独立只读文件 Worker，复用原生受控目录与字节核验规则。主线程在启动前固定根目录身份；Worker 不持有模型凭据，不执行数据库写入。管理刷新和生成准备异步等待结果，提交前仍执行现有版本及来源校验。并发刷新共享核验，一位调用者取消不取消其他等待者；最后一位取消才终止该轮。关闭后不得产生迟到写入。
- Skill 文件任务最多投递 32 项；取消立即结束调用者等待，但直到 Worker 确认完成或跳过才释放额度。原生读取时长、资源和字节上限保持。
- 历史覆盖状态按每批至多 4 位联系人顺序提交，在批次之间允许其他动作执行；不扩大同步范围。存储只记录有界的动作名称、排队与执行毫秒摘要，不记录输入、身份、正文、SQL 或凭据。优化背景任务与隔离助手读取同时保留，计时不充当读取授权或缓存资格。

代价是每个宿主多一个助手数据库 Worker、每个 Skill 库多一个按需文件 Worker，以及需要确认关闭的生命周期。测量将首次连接、已知会话、解析后读取、切换和背景繁忙分开；合成对照证明队列隔离，实际接口样本不替代界面绘制或模型质量验收。
