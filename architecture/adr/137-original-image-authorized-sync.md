# ADR-137：授权会话同步中的原图保存

> 图文输入修订（2026-11-02）：[ADR-153](153-joint-text-image-memory-input.md)。本文的图片保存范围不限制记忆任务使用图片；记忆输入采用实际图片与聊天文字共同处理。

> 后续修订：[ADR-140](140-source-verified-viewable-chat-images.md)已按用户要求取消原图证明门槛；来源已核验且完整可解码的本机图片（包括已绑定缩略图）可以保存和显示。下文原图限制保留为历史决定，其他来源、停读和删除规则继续适用。

> 后续修订：[ADR-138](138-chat-image-original-extraction-and-placeholder.md)将用户明确要求的当前账号图片密钥准备及 WXGF 解码接回聊天图片提取，并规定占位替换；下文“不自动探测密钥”按其限定范围修订。此前独立开发取图已有成功记录，本页旧实机失败仅描述当时的同步入口。

> 状态：已采纳（2026-10-31）。真实复查发现压缩元数据、缓存标识及封装长度处理缺陷，已修复并升级开发组件；285 个既有授权会话身份保持一致。当前账户的真实图片在解密处返回 `needs_image_key`，尚无真实原图成功保存的证据。最新范围见[解码修复验收](../../docs/verification/original-image-decoding-fix-20261031.md)，早期记录见[实施记录](../../docs/verification/original-image-authorized-sync-20261031.md)。
> 局部替代：[ADR-125](125-image-video-byte-decoding-and-validation.md)中授权会话同步图片仍须逐条手动触发、允许保存缩略图并主动补提原图的条款。ADR-125关于唯一消息—资源关联、读取授权、应用受管文件、删除及迟到结果拒绝的边界继续适用；视频及语音的单条媒体操作不变。

## 背景

图片消息需要随用户已授权的会话范围同步，便于离开微信后仍可使用；图片文件保存是消息同步的一部分，与记忆生成相互独立。反复依赖微信缓存会让后续查看受缓存生命周期影响，因此只在本机确实能读取且能证明是原图时保存应用自有副本。

## 决定

- 图片消息跟随现有已授权会话同步范围处理，受应用运行状态、同步总开关、联系人范围、账号与来源有效性约束；不另行扩大读取范围，也不要求为每张图片启动独立的逐条提取操作。
- 仅当本机资源可读，且有独立证据证明其为原图时，才将原图保存到应用受管目录；图片文件字节不以 BLOB 写入数据库。数据库只保存图片消息与资源的唯一关联、来源、引用、质量证明和处理状态。
- 只有缩略图、质量无法证明、资源缺失或缺少所需密钥时，只保留图片消息及相应状态，不保存该图片文件。不得根据文件扩展名、尺寸或可解码性推断其为原图，也不以缩略图替代原图。
- 同一已认证消息—资源关联若已有合法受管副本则复用，不重复保存。用户清除已保存图片后保留消息及清除状态，后续同步不自动重新取回；来源或联系人删除时，按现有删除链清除关联、证明和应用受管副本。
- 只读取同步边界内本机可读资源；不注入或修改微信进程，不自动探测密钥，不驱动微信或远端下载。图片保存不触发 OCR、视觉理解或记忆提取。

## 实施状态

消息页接受后唤醒图片同步，应用启动与合法读取重新开启时补查已保存图片；同一账号串行处理。同一图片的自动尝试使用持久幂等键，原图缺失或失败也保留结果，普通唤醒不反复读取；明确重试仍是新操作。原图副本或清除状态会退出自动目标集合。

原图读取只接收当前固定目标内的消息身份，通过锁定资源表关联及图片消息的 HD 元数据、内容摘要、解密后长度和尺寸逐项核验，分块输出经过证明的完整图片，不返回本机路径。BMP 尺寸预检不替代后续 ImageIO 完整解码。

图片消息的内容先按存储标记有界解压，再解析原图元数据。消息和唯一 `MessageResourceInfo` 的 packed-info 必须各有一个相同的缓存键；缓存键与 XML 的明文内容 MD5 分开，不能混作文件名。只读取该会话、月份及缓存键对应的 `.dat`／`_h.dat`，不读缩略图。detail 集合按实际封装文件长度匹配，完整 Info 与匹配集合进入来源证明；最小 detail ID 只作确定性审计代表，不用 variant 推断原图。解密后的完整字节仍须匹配 HD 长度、XML 明文 MD5 及有效解码尺寸。XML 未提供的 HD 尺寸保留 `null`，实际内容尺寸独立记录；已声明尺寸必须吻合。

v3 质量证明区分封装 `resourceSize`（至多 64 MiB）与明文 `verifiedBytes`／`hdLength`（至多 32 MiB），并记录 Info ID 和完整排序的匹配 detail ID 集合。制品须明确声明 v3 才装配修复版自动同步；旧版误判按新幂等版本重新尝试一次，不删除旧记录、不恢复已清除图片，普通唤醒仍不重复取图。缺少图片密钥、原图声明失证、文件缺失及质量验证失败分别保留状态。

新构建显式声明原图协议；旧构建没有声明时不装配图片适配器与协调器，避免将未知协议误记为每张图片缺失。已有来源别名绑定原制品摘要，新的组件不能直接替换或复制旧别名。受控升级脚本只接受固定、已经审查的源码配对，复验完整源码树、构建链、实际二进制和旧别名绑定后，为新制品生成独立别名与凭证；全部既有授权范围的新旧来源代次、分片、表实例、结构及支持档精确一致才切换。升级不改旧映射、业务身份和读取授权，不解除既有围栏，不复用旧制品游标；未完成这些证明时继续使用旧组件。
