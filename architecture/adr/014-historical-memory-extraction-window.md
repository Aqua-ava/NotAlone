# ADR-014：历史导入的记忆提取窗口与异步任务

> 2026-10-21 设计审查：“水位之后”的增量表述须结合 [ADR-081](081-source-grounded-memory-time-and-conditions.md)对晚导入早日期新消息的要求；不能因消息时间早于水位就永久遗漏新来源。分批、失败恢复、去重和来源隔离保持。

> 状态：已采纳
> 决策日期：2026-08-23

## 背景

ADR-002 原先描述“只取最近 N 轮对话”，而历史导入又需要覆盖早期关系资料。两者如果不区分首次导入和增量导入，就会让实现和用户预期不一致。

## 决策

1. 首次历史导入处理该来源的全部规范消息，但按固定批次和预算分段；任何一次模型调用都不能接收完整历史。
2. 后续增量导入只处理水位之后的新消息，并使用有限的近期对话窗口补充语境。
3. 消息写入成功后创建异步记忆任务；导入成功不等待模型，也不因记忆提取失败回滚消息。任务按 `parse -> normalize -> extract_memory -> index -> verify` 固定步骤执行，失败可重试。
4. `memory_candidate` 通过证据契约后按 ADR-002 自动采纳，标记 `auto`、保留来源并可撤销；`self` 主体事实进入 owner 级记忆，联系人事实进入联系人级记忆。
5. 媒体占位文本只表示媒体存在，不作为关系事实证据；完成 OCR 或转写后，带新来源证据的规范内容才能参与记忆提取。

## 后果

- 首次导入的模型调用数量随历史长度增长，需要任务进度、预算和出站台账。
- 记忆任务与消息导入拥有不同的失败边界；消息可用不代表记忆任务已成功。
- 当前独立 `notalone-extract-memory` 命令可以验证提取规则；导入 CLI 自动创建后台任务仍需后续 Worker 实现。
