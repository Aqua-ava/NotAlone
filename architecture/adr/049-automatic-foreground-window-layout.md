# ADR-049：前台微信窗口自动布局与局部名称 OCR

> 状态：已采纳
> 决策日期：2026-10-14

> 后续局部修订：[ADR-050](050-continuous-single-frame-contact-follow.md)采用持续单帧观察，替代下方第二帧布局/像素复查及每次最多两帧的约束；唯一前台窗口、内存布局、名称局部 OCR 及质量/绑定门槛保留。[任务01](../../.scratch/foreground-contact-follow/issues/01-single-frame-locator.md)已完成单次入口的代码及合成验证，持续流程与实机验收仍待完成；本文保留原双帧决定及原因。

用户明确要求移除手填坐标，微信移动、缩放后仍自动定位；并批准先在本机内存分析当前前台微信窗口画面，再仅对顶部与选中会话名称执行 OCR。此决定修订 ADR-030 的“采集前必须已知最小区域”限制，不改变前台、只读、联系人确认、后台 CLI 独立或手动发送边界。

每次观察选择唯一且受支持的可见微信窗口，在采集前后核对前台进程、窗口及几何；窗口移动或缩放后的下一次观察重新定位，不复用人工 profile。一次观察中发生变化则丢弃，不拼接前后帧。使用限定该窗口的过滤器，原始帧仅端侧内存布局分析，不落盘、不上传；仅将当帧两处名称裁剪送到本机 OCR，不 OCR 聊天正文或其他联系人列表。未知布局、多个高亮候选、截断/不一致/低分名称必须失败关闭。

识别后再取一帧，只复核布局和两处名称像素是否变化，拒绝同一窗口切换会话造成的旧结果；第二帧不做 OCR、不拼接名称，摘要仅用于当前调用的内存比较，不持久化。每次观察最多两帧，无重试循环。

拒绝继续要求用户手填坐标，也不采用全屏扫描、后台截屏、外部视觉模型或“选最大窗口”猜测。版本与主题支持范围由实现和实测决定；自动发现区域不等于联系人确认或已通过原生验收。新观察协议为 `automatic-window-v1`，旧 `--minimal-region` 仅保留参数兼容，不能将整窗分析标成旧最小采集协议。
