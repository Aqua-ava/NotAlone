# ADR-079：统一表达工作区与直接建议候选

> 后续局部替代（2026-10-20）：[ADR-082](082-retire-explicit-style-samples.md)取消主动收藏表达样本及其使用、独立留存和关联生命周期要求；下文涉及样本的内容仅保留为历史。其他决定及原验收范围不因此改变。

> 状态：已采纳（2026-10-19）。实现与验收证据见[任务](../../.scratch/unified-expression-workspace/issues/01-workspace.md)。
> 修订范围：替代 ADR-043 的三个产品入口及方向确认前不得生成候选要求；局部修订 ADR-074 的人工意愿确认描述和 ADR-065 的手动输入入口。联系人隔离、明确场景权限、Skill 单版本边界、资料来源与删除、用户手动发送继续有效。

用户发现回应与主动联系都是“帮我想说什么”，而已有想法与草稿都属于“帮我表达”。按消息来源划分入口并强制选消息、填方向增加了不必要步骤。

同一工作区提供可选输入和两个动作。帮我表达以用户已有想法为约束，保持原意；帮我想想允许空输入，结合近期对话与相关资料直接提供不同方向的候选及理由。模型建议不是已确认意图，不先要求确认方向，也不自动选用或发送。用户选择、编辑和继续调整属于显式操作，不能自动写成长期关系事实或偏好。

默认使用已确认联系人范围内的最近上下文，不要求目标消息。用户可查看、排除本次消息背景及单独补充聊天；补充文字与用户想法分开保存并标记为用户补充。排除消息时保守停用派生关系资料、表达样本与长历史补查，仅使用未排除的近期聊天和本次输入，避免已排除内容回流。上下文选择不扩大同步授权。新消息只提示，生成由点击触发，不能替换正在编辑的文字。

复用现有候选链路，通过明确 workspace action 区别表达与建议，不将空输入补成虚构草稿或 ConfirmedDirection。旧三类输入合同为历史与内部兼容保留，不再是用户必选的页面模式。来源复验、预算、取消、删除和迟到结果拒绝继续适用；来源不足允许指出限制，不编造事实或对方心理。

代价是请求、保存、恢复与继续生成都需区分动作，且生成的不同方向不能冒充用户立场；收益是一次点击获得可用语句与依据，不再经历“建议方向—确认—生成”的固定步骤。
