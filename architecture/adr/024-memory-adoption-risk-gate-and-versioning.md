# ADR-024：关系记忆风险门槛与版本化采纳

> 状态：已采纳
> 决策日期：2026-09-02
>
> 本 ADR 修订 ADR-002 中“风险字段不阻塞自动写入”的局部规则；ADR-002
> 关于来源证据、`auto` 标记、删除和手动发送的其他约束继续有效。

## 背景

关系记忆提取结果同时包含置信度、来源、有效期和风险标签。把健康、关系冲突等
敏感推断直接写入 `confirmed_memory`，即使带有 `auto` 标记，也会让模型推断在
用户没有确认时表现为长期事实。另一方面，用户手动修正已展示的记忆时，原记录
不能被静默覆盖，否则来源和历史审计会断裂。

## 决策

1. 只有达到配置置信度门槛且没有敏感或未知风险标签的候选，才可自动采纳；风险
   标签为空或明确表示低风险时才满足该条件。任何无法识别的标签按有风险处理。
2. 不满足自动采纳条件的候选仍保存为 `pending`，并保留来源、置信度、风险标签
   和有效期，等待用户在应用内查看和确认。它不能进入回复上下文的已确认记忆集合。
3. 自动采纳的 `confirmed_memory` 保留 `auto`、来源候选、来源 UUID、置信度、
   风险标签和有效期；`auto` 不表示用户确认，且仍可撤销或删除。
4. 用户修正创建新的 `confirmed_memory` 版本：旧行变为 `invalidated`，新行使用
   新 ID、`manual` 采纳方式和 `supersedes_memory_id` 指向旧行。旧版本不再检索，
   但保留用于审计。
5. 同一联系人范围、分类、主题、规范化正文和来源集合的 pending 候选只能存在
   一份；重复提取必须返回幂等统计，不产生第二条候选。

## 后果

- `memory_candidate` 和 `confirmed_memory` 必须持久化置信度、风险标签与有效期；
  提取失败可用 `extract_failed + failure_reason` 保留可见性。
- 记忆版本和联系人记忆 revision 都会变化，索引、缓存和正在生成的上下文需要
  在后续读取时重新校验。
- 风险标签的具体枚举仍由独立的提取/规则适配层维护；领域采纳器对未知标签
  采用 fail-closed 策略，不把未知值当作低风险。

## 验证

合成测试覆盖高置信敏感事实留在 pending、低风险事实自动采纳并保留来源、重复
pending 幂等、有效期/删除/联系人范围过滤，以及修正产生新版本并使旧版本失效。
