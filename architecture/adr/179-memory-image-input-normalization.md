# ADR-179：记忆图片在内存规范化并保留原图依据

状态：已采纳（2026-11-11）。用户明确授权向已配置模型发送缩放／重编码的规范化版本；工程及真实验收分别记录在 `.scratch/image-model-input-reliability/`，本决定不替代真实模型验收。

局部修订：[ADR-153](153-joint-text-image-memory-input.md) 的实际图片输入允许使用与原图绑定的规范化版本；[ADR-169](169-memory-uses-confirmed-non-thumbnail-images.md)、[ADR-170](170-no-thumbnail-storage-and-no-original-classification.md) 的当前可查看受管副本资格、不保存缩略图与来源删除合同继续有效。规范化版本不是新保存的缩略图，也不建立图片质量分类。

## 原因

同一图片通过等价 Messages 请求可成功，但现有正式附件适配先强制 PNG，再按官方目标缩放并强制 PNG。实测原图 2,043,188 字节，第一次编码 3,131,712 字节，第二次编码 2,832,863 字节，超过锁定 DSH 默认单图目标 2,097,152 字节。业务代码抛出的本地预算异常被官方适配器映射为 `TRANSPORT`，发生在 fetch 之前。纯合成图片通过正式附件适配与官方适配器复现同类异常，确认 fetch 次数为零。因此不能把该现象直接判定为连接断开，也不能仅改原图字节的批次上限。

## 决定

1. 仅在调用内存中生成模型图片。正常层使用长边不超过 1536、JPEG 质量 85；单张降级层使用长边不超过 1024、JPEG 质量 85，原版本较小时仍实际缩小，不能产生不同更小版本时不发送相同载荷。长边不放大，应用 EXIF 方向，GIF 只使用首帧，透明区域合成白底，并移除原元数据。
2. 每张编码结果不得超过 2 MiB；官方请求目标更小时遵守更小的字节与尺寸限制。固定质量编码仍超限时，有限次缩小尺寸；无法满足时明确失败，不发送超预算版本。附件适配不得再把已规范化 JPEG 强制还原为大 PNG。
3. 共享限制集中在 `backend-ts/src/platform/models/image-normalization.ts`：每请求最多 8 张、规范化字节合计最多 32 MiB。原图资源读取、图像像素／维度上限、完整请求预算继续独立校验；批次按规范化结果的实际字节复核，不据原图大小永久排除合法图片。
4. 来源引用仍指向原始受管副本的 `file_id`、`sha256` 与媒体代次。内存规范化证明绑定原图摘要、原字节、发送摘要、格式、图片标识与层级；它可随结构化复制传递，不能凭任意填写的 `sourceSha256` 跳过来源校验。证明密钥不持久化；重启后重新读取合法原图并生成证明。
5. 运行追踪区分原始字节和实际发送版本的宽高、格式、字节与层级。元数据诊断不存图片、base64、聊天正文或底层错误原文。发送版本不写文件、附件缓存或 Files API；来源删除仍沿现有闭包删除受管副本与关联追踪，不新增磁盘派生图片的清理路径。
6. 单张降级只属于本次请求策略，不成为联系人长期偏好；后续失败隔离、不同请求的有界拆分和每次独立记账按该任务已确认决策实现，未知回执保护不解除。

## 取舍

JPEG 压缩、缩放与首帧可能损失细小文字、透明效果或动画变化。保留原图身份与发送版本元数据，使实际模型输入可解释；不以文字占位冒充模型已观察原图全部细节。1536／1024 与质量 85 来自本次对照范围及明确决策，仍须用正式业务路径做真实模型验收，不能由短提示对照直接宣称提取质量通过。
