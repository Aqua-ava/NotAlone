# ADR-070：默认自动维护记忆并退役旧资料升级

> 2026-10-21 设计审查：取消空维度表、默认自动维护及旧资料升级退役的决定明确有效。关于额外语用、置信度、风险人工门，本文与 [ADR-069](069-direct-scene-memory-and-isolated-publication.md)的用户修订续记相冲突；源码 automatic 路径未将它们用作人工门。本次仅记录差异，待明确适用协议／替代顺序，不擅自恢复旧门或将代码现状提升为已采纳决定。

> 后续修订：[ADR-074](074-tencent-reference-python-memory.md) 规定参考腾讯源码自行实现的算法范围；保留本文来源、删除和人工保护边界。

> 状态：已采纳（2026-10-18）；用户明确要求删除旧资料升级，确认聊天进入后自动记住、更新和整理。

原来默认空维度放行表和外置整理资格配置使正常提取停在待确认、分层整理无法自动启动。
用户此次选择以逐条来源核验作为自动维护依据，减少逐次手动操作；这不是宣称旧质量评测已经通过。

## 替代范围

- 修订 ADR-036／046 中“默认空表、逐类评测批准后才允许生产自动采纳”的运行策略；现行默认流程使用逐条核验，显式历史协议与评测结果保留原含义。
- 修订 ADR-048 中独立旧资料升级产品流程：删除页面、IPC、HTTP 和后台执行入口，不迁入记忆管理。保留历史副本的来源删除能力，不因功能退役删除已保存记忆。
- 细化 ADR-067／069 的正常分层流程：配置可用模型后，L1 变化自动启动联系人／本人 L2、L3 整理，不要求先进入页面启用或准备外置质量评测目录。

## 保留的边界

1. 只处理已导入或已授权同步的消息，按联系人和本人范围隔离；新消息触发提取，不自动重新解释、回填或重新采纳旧历史。
2. 独立核验必须逐项支持当前来源；不足、无支持、来源变化、语用或风险门槛不满足时仍不能自动采纳。自动记录标记为 `auto`，不能冒充用户确认。
3. 更新、合并保留原来源和版本，人工修正、否决、停用与删除优先；新输入不能让已删除的旧证据复活。
   默认逐条核验策略下，明确更正仍保留 `correction` 标签；仅当同次来源回执有效、唯一语用阻塞为更正时允许自动裁决。同类别同主题的更正候选不因词面重合偏低而跳过比较，仍保留八条候选上限、截断保护和模型裁决，不能直接覆盖旧记忆。
4. L2/L3 保留有界输入、有限调用预算、独立核验和发布前版本复验。明确暂停或删除整理结果的范围不会被新消息自动重启；正常新范围默认维护。
5. 已逐项核验的分层记忆可以供用户已开启的关系语境读取；不会自动开启关系语境，也不扩大回复范围或改变最终手动发送。
6. 质量评测继续单独报告，逐项运行核验不等于全局质量达标；显式评测装配仍保留原资格合同。重启恢复与失败重试保持有限，禁止无限重试。

工程、合成验证与实际桌面结果见[本次规格](../../.scratch/automatic-memory-maintenance/spec.md)，不能由本决定推断真实模型质量已通过。

## ADR-081 的有据关系例外（2026-10-20）

新的 UPDATE／MERGE 还须独立核验新旧主张的关系，并在提交事务复验有界原来源和父版本。旧协议没有关系证明时，不把单条事实核验等同于可替代旧事实。关系未知或尚未解决的矛盾保留为待确认（`timeline:relation_unknown`／`timeline:unresolved_conflict`），不进入通常的自动拒绝清理。条件改变与原主张撤销分别核验。关联仍有效的矛盾会成为旧 active 事实的生成不确定性；删除或撤销反证使该依赖失效。历史补充不标成现状冲突。
