# ADR-159：前台联系人识别独立读取通道

> 后续补充：[ADR-160](160-assistant-read-and-skill-worker-isolation.md)为助手回看另建独立读者，不扩大本决定的前台动作白名单。

> 状态：已采纳（2026-11-03）。用户确认前台 OCR、联系人匹配与后台历史、记忆处理分开执行。实现和实际验收分别记录，不以本决定代替运行证据。

## 原因

前台定位读取账号及既有绑定时，与后台记忆统计共享一个串行 SQLite Worker；会话名称元数据又与正文同步共享 CLI 租约。即使 OCR 本身尚未执行，后台长查询也能让前台请求超过既有预算。仅给请求排优先级无法中断正在执行的同步 SQL，后台查询优化也不能保证以后没有新的长任务。

## 决定

- 主存储可以创建受控只读附属读者；每个附属读者拥有独立 Worker 和只读连接，使用同一受控数据库文件及主存储的 `databaseId/runtimeId/epoch`。这局部补充 ADR-109 的连接生命周期，保留一个业务运行身份、具名动作和文件身份校验。附属打开不初始化、不迁移、不推进代次，也不通过第二次 `SqliteStorage.open()` 创建新的业务运行身份。
- 附属读者只接受可信装配声明的只读具名动作集合；前台仅开放 `identity.foregroundSnapshot`，不开放任意 SQL、写动作、维护动作、聊天正文或记忆查询。主存储关闭或失败时撤销所有附属读者，实例、文件身份或租约变化后旧读者拒绝结果。
- 每次快照使用短读事务，读完即结束；事务外再次核验运行租约。不能将 WAL 快照保留至 OCR、CLI 或下一轮。现有前后账号、来源、联系人及删除代次比较保持，名称匹配规则仍按 ADR-132，不恢复正文读取授权。
- 前台读者随联系人元数据生命周期登记到现有删除持有者；关闭名单、删除排空和退出必须真实结束附属读取及连接。关闭失败继续阻止删除完成，不因只读而豁免生命周期。
- 前台会话元数据使用独立、复用的窄协议 CLI 客户端，保留账号前后、来源、候选类型及数量校验；不与后台正文同步共享租约。独立进程不构成前台微信登录账号的独立认证。
- 名单或绑定查询暂时失败不销毁已预热 OCR Worker。取消、权限、账号范围变更及真正的原生故障仍按既有合同停止或回收；每轮取得新画面，不缓存旧名称或身份。

## 代价与验收

额外占用一个只读数据库 Worker 和一个前台元数据 CLI 进程；由对应生命周期复用和关闭。WAL、短读、只读动作白名单及删除排空是必要约束。

后台长 SQL 和正文读取租约仍在途时，分别验证前台快照及元数据读取及时完成；通过生产前台匹配接口验证已有联系人直接关联，并验证识别期间删除、关闭、账号或来源变化拒绝旧结果。正常切换、首次启动、后台繁忙分别测量，既有 3.5／3.2／2.5 秒预算及五秒采集时效保持。后台重复扫描另行优化，不作为前台通道隔离的完成前提。
