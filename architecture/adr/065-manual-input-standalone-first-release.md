# ADR-065：独立 App 首版先交付手动输入路径

> 状态：已采纳的首版范围；尚未完成产品与安装验收。
> 决策日期：2026-10-16
> 局部修订：ADR-061 的首版微信初始化验收门槛，以及核心流程中“手工输入仅为兜底”的首版适用范围。联系人隔离、来源、出站、人工发送和资料更新约束保持。
> 后续局部修订：[ADR-066](066-in-place-schema-updates-and-database-reuse.md)替代下文已有资料更新中的强制备份和恢复校验，沿用原连接、原资料位置补齐结构；手动输入首版范围保持。

微信特权首次初始化的实现子任务被工具安全审查中止，尚无可交付路径。用户随后明确接受先完成“双击启动、本机保存资料、手动粘贴聊天文字或导入文件”的可用版，把微信自动接入保留为未完成项。此决定不授权重复尝试被中止的初始化路线，也不将普通 CLI 编译、合成加密库或既有渠道测试作为真实微信接入证明。

首版通过 App 自带的本机后台完成本人和模型设置。空联系人目录须有无需微信的显式建联系人入口；用户明确选择本次联系人后，粘贴当前聊天文字或确认单联系人文件导入，再使用现有生成、依据查看与候选编辑能力。每次生成仍绑定 `owner_id + contact_id`，不根据正文猜测身份，不自动读取桌面会话、不扩大同步范围，最终消息仍由用户亲自发送。手动输入不能静默成为长期记忆；显式导入继续保留来源与删除路径。

首版不得把安装微信工具、授权系统权限、配置 CLI／探针或填写运行路径作为使用前提。相关未完成能力须有如实的产品说明；不在首版安装包中启用未完成特权初始化。已有资料更新继续遵循 ADR-061：一次明确确认、本机备份、恢复校验、兼容更新、保留资料与失败恢复。

首版新装验收改为：同一实际安装产物在没有开发环境的目标机器完成首启、显式创建／选择联系人、手动输入或单联系人导入、使用用户自己的模型凭据生成带依据的候选并编辑。已有资料更新路径、搬动／重开／退出、来源许可与正式分发检查仍须实际完成。开发机隔离用例和合成模型分别记录，不冒充真实模型或无开发环境验收。

原微信初始化、联系人同步与渠道验收任务继续保留未完成状态，等待新的安全可行方案及独立验收，不作为首版完成的必要依赖。后续重新纳入发布范围时仍需取得相应可验证结果。

规格见[手动输入首版](../../.scratch/standalone-app-delivery/manual-first-release.md)。
