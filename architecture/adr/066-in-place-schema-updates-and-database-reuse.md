# ADR-066：沿用现有数据库并原地补齐结构

> 状态：已采纳的启动与数据位置约束；实现及验证范围以本次任务记录为准。
> 决策日期：2026-10-17
> 局部修订：ADR-061、ADR-065 的已有资料更新要求。取消普通启动中的强制备份、恢复校验、外置库复制和数据库切换；独立新装、本机保存资料、联系人隔离与删除要求继续有效。

与 ADR-061、ADR-065 的强制备份更新要求冲突；重新讨论的原因是，既有本机数据库已经可以继续使用，结构落后只需要执行缺少的版本化 SQL。为了独立新装自带 PostgreSQL，不意味着已有安装也必须复制到另一套数据库。用户已明确要求取消这套搬库与备份流程，沿用原连接和资料位置，并在原库补齐结构。

启动先只读核对已配置的本机目标、可信基线与实际迁移账本。结构已就绪时直接连接；存在缺失版本时，确认本 App 原后台已停读、运行中生成已结算且没有其他目标库连接，再在原库逐版本执行缺少的受信任 SQL，完成后复验并连接。SQL 与本版本账本原子提交，重复启动不重放已成功版本。此路径不创建备份、临时恢复库或数据库副本，不改写数据库连接或资料位置。

首次安装且没有既有配置时，仍由 App 自带的本机 PostgreSQL 初始化空库并创建完整结构。已有配置即使连接失败，也不能据此创建新库替代原库；已有受管库继续使用自己的目录。无可信基线、账本漂移、账本与受信任 SQL 不一致的开发分叉、其他连接或更新并发时停止，显示固定原因；不猜测版本、不补写假账本、不删除业务资料、不静默恢复旧副本。未完成的历史更新现场保留核验，不自动继续搬库。结构核验覆盖版本账本和应用所需的表与字段，不为逐对象比对另建参考数据库；额外自定义对象不获得版本认证。

取消新建备份不等于已有副本可以丢弃。历史 App 管理快照继续受原来源、过程、关系资料和助手会话的删除清理约束；完整归属核验通过后才清理，未知、损坏、未完成或清理失败时不宣告删除成功。外置原库、用户自行导出的副本与模型供应商副本仍遵循各自的归属和删除边界，不能因停用旧流程自动删除。

日常开发默认使用 `cd desktop && npm run dev`，复用现有配置与数据库。保存界面代码只触发热更新；需要安全重启时仍通过同一启动门禁，仅真正缺少版本时补齐结构，不因开发模式或打包方式改变数据库位置。日常开发和原生能力验收均使用 `npm run dev`；只有用户明确提出发布任务时，才按工程工作流构建或运行实际安装包；本决定不认证最终安装版、无开发环境机器或微信集成。
