# ADR-128：微信消息去重保存与撤回状态

状态：已采纳；去重及旧记录清理已实施，集成验收进行中。日期：2026-10-30。

本轮先实现消息去重和旧记录清理；撤回状态的新展示与使用规则暂缓，不作为本轮交付或验收前提。暂缓期间继续执行现有的来源资格保护。

微信历史和增量同步反复扫描时，旧方案为每次出现保存含正文的来源记录，造成大量重复。改为以稳定消息身份保存一条消息和当前状态，仅保留区分来源、核验资格、继续同步与删除所必需的信息。相同来源的重复观察不得再次保存正文或无限累积扫描记录。原始资料、规范化消息、候选和关系记忆仍按各自来源与删除路径分层；此决定只调整微信同步的重复观察，不取消其他输入适配器的原始资料要求。

## 消息和使用资格

- 普通消息保存一份正文；相同身份再次出现时更新必要状态，不新增一条完整副本。消息身份须在 `owner_id + contact_id`、已验证绑定及来源范围内核验；身份冲突或无法核验时不猜测合并。
- 已可靠确认撤回且撤回前已同步的消息，保留之前保存的正文并标记已撤回；撤回前未同步到正文的消息仅保存无正文撤回占位。没有可靠撤回证据时不得把普通系统记录或消息暂时消失猜成撤回。
- 已撤回消息的正文可供用户查看，但不得进入新的回复生成、检索依据或记忆提取。此前仅由该消息支持的记忆失去使用资格；其他仍有有效依据的资料重新核验。已生成的旧回复保持原样，不要求因撤回处理旧回复；新生成仍必须复验输入资格。
- 微信端删除或当前来源暂时不可见，不删除 NotAlone 已保存消息；未撤回且仍符合授权和来源资格的消息可继续用于回复和记忆。不因缺失推断用户已撤回或删除，来源身份变化仍按连续性规则停读或复核。
- 本次不新增普通消息逐条删除功能。按联系人清空聊天的现行删除及排除规则继续有效：已清空旧消息不能被后台自动导回；用户明确重新同步历史时按既有授权和删除边界处理。

## 同步记录和旧数据

- 每个联系人仅保留最近一次同步结果、时间、计数与必要失败原因；这类状态不保存聊天正文，不保留无限增长的逐次同步日志。可靠续读、当前来源核验、必要的身份映射、删除抑制与恢复状态是业务数据，不能因为不属于最近一次结果而丢弃。
- 用户选择采用新方案并清理旧扫描记录，不要求迁就旧逐次捕获设计。已导入的消息及其可用性、联系人归属、撤回状态与必要来源关系须保留；仅存在旧扫描记录而未导入的内容不作为迁移保留目标，后续以微信本机当前可读历史为准，微信中已不可读的内容可能无法恢复。
- 先让消息读取、记忆、回复和删除等消费者使用新身份与来源合同，并验证关联、授权及清空排除，再清理旧扫描记录及其索引。身份冲突、来源无法核验或迁移失败时不得猜测合并或宣称完成；旧正文版本冲突先保留待核验。保留或清理现有备份须遵循各自的数据生命周期，不能把清理扫描记录扩展为删除备份。
- 迁移后核对消息及联系人归属、已撤回内容和使用资格、重扫去重、微信端删除保留、清空后不自动恢复、异常恢复与磁盘占用。普通结构更新不自动创建备份；真实数据迁移与删除按实际范围执行，不由本 ADR 本身执行或证明完成。

## 对既有决定的修订

本决定局部修订 [ADR-113](113-sqlite-private-history-source-contract.md) 中“每次捕获均保存不可改写的原始出现及其正文”和“已保存文字变为系统记录时撤下旧正文”的条款，以及以完整重扫中消失为由阻止保留消息的相关要求。仅可靠确认撤回时才使用撤回状态，原文保留及使用资格以上述规则为准。保留来源身份、联系人隔离、授权、删除抑制和独立系统记录不猜测撤回等边界；[ADR-127](127-sqlite-history-normal-use-restart-rescan.md)的重启同来源核验与原地回滚限制继续有效，不要求保留每次重扫的正文副本。

实施范围以上方状态为准：去重与旧记录清理已有[写入实现](../../backend-ts/src/history/sqlite/ingest.ts)、[正文副本迁移](../../backend-ts/src/history/sqlite/single-text-copy-schema.ts)及[合成迁移测试](../../backend-ts/test/sqlite-single-text-copy.test.mjs)，撤回状态的新展示与使用规则仍暂缓。源码和合成测试不证明所有用户资料已执行迁移，也不构成完整实机验收；旧实现和此前验收继续按对应版本与证据理解。
