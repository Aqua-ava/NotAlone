# ADR-095：首次连接微信与一次账号范围授权

> 决策状态：已采纳（2026-10-21）。用户要求全新用户首次连接微信后，一次授权即可自动关联并同步全部现有及以后新增私聊，无需逐个添加。
> 实现与验证状态：见[本次规格](../../.scratch/wechat-first-connection/spec.md)。本决定仅确立已有可用外置工具的产品接入链，不能证明未配置机器的首次工具准备、真实微信或独立安装验收完成。

此前本人渠道身份主要由历史导入建立，而同步宿主又依赖该身份才能启动。新用户即使已有可用微信读取工具，也无法直接进入同步。决定将首次微信连接独立于同步宿主及历史导入：先检测工具配置账号，再由用户明确确认账号和全部私聊范围，完成会话可读性与账号一致性核验后，在同一事务中保存本人渠道身份、范围授权与同步开启状态，重载受控后端后沿 ADR-089 自动建联。

## 账号与授权

- 运行本人只能来自受控配置；未完成本机本人初始化时先走原初始化入口，不自动选取其他 owner。微信账号只能取固定只读 CLI 探测结果，不能由界面任意填写，也不能从昵称、备注或消息内容推断。
- 工具配置账号与微信前台当前登录账号并非同一证据。页面必须说明实际检测的是已配置工具的账号，不把探测结果冒充前台登录核验。
- 主动检测只执行固定只读 `status`，核对工具配置账号，不读取会话列表或正文、不保存联系人或授权。`ready` 只表示有可供用户核对的候选账号，不证明会话已经实际可读。启动、重连和普通状态刷新只查询本机保存状态，不执行 CLI 检测。
- 确认前展示账号、现有及未来私聊范围、自动建立联系人、开启后台读取与停止入口。明确确认后，服务端先复验候选凭据和配置账号，再执行有界会话可读性检查，随后再次核对账号。候选失效或首次复验发现账号变化时，在读取列表前拒绝；末次核验不一致也不保存身份或授权。
- 上游 `sessions` 可能附带最近消息摘要，因此只能在用户确认范围之后调用；返回的摘要丢弃，不保存或外发。不调用正文历史或监听命令冒充连接检查，系统权限提示仍按真实结果处理。
- 首次成功确认在单事务中建立本人渠道身份、全部私聊授权和开启状态，避免身份、范围与开关只保存一部分。检测、查看页面或刷新不等于授权；模型密钥不作为这次连接的前置条件。
- 响应丢失或受控后端重启失败可以读回并恢复；重复确认不重写原授权起点、不清空排除记录，也不覆盖用户之后关闭的开关或更改的范围。已有账号、已撤销身份、跨 owner 占用或其他身份冲突不得由此入口覆盖。

首次确认明确包含“连接并开启同步”，是新用户的一个完整动作。ADR-089 的已有用户范围设置仍与总开关独立，升级、重连或重新打开页面不会使既有用户从仅所选变为全部私聊，也不会重新打开已关闭的读取。

## 保留边界与未完成目标

后台关联与增量读取复用 ADR-089：仅处理该账号 CLI 可见的私聊，稳定身份相同才复用联系人，同名不合并；撤销／删除排除不自动恢复，不追溯新绑定 baseline 以前历史，关闭总开关或退出即停止读取。前台识别仍遵守重名、改名与低置信度门禁，最终消息由用户亲自发送。

本次不提供外置工具安装或特权初始化，不调用被中止的初始化路线，不接收管理员密码、不修改微信签名、不代用户重启微信。工具不存在、未配置、不可读或不兼容时如实停止；“已连接”的产品状态不能替代工具准备证据。受管新安装仍缺少可交付的工具初始化路径，因此完全未配置机器的一次授权即用目标继续未完成，须另有安全可行方案及真实独立验收。
