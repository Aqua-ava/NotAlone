# ADR-040：Electron 双窗口桌面宿主

> 编号修订：汇总记忆追踪分支时从 ADR-037 调整为 ADR-040，保留已采纳的桌面宿主行为。

> 状态：已采纳
> 决策日期：2026-10-08
> 后续局部修订：[ADR-061](061-standalone-local-app-onboarding-and-updates.md)将独立分发目标改为随包管理本机后台与数据运行环境，替代下文仅外置依赖／只交付宿主的独立版边界；首版范围见 [ADR-065](065-manual-input-standalone-first-release.md)，已有资料更新见 [ADR-066](066-in-place-schema-updates-and-database-reuse.md)。源码开发路径保留，打包与运行打包版仍须用户明确提出发布任务。

用户已确认本机 Mac App 规格，以 Electron 承载 React/TypeScript 界面，分别提供独立管理后台与输入法式小窗。管理后台处理资料与配置，小窗只处理当次表达。主进程统一管理必要桌面能力；渲染层通过隔离、沙箱和具名 preload 桥接调用，不直接启动 Python、访问数据库或操作微信。仅随包的本地资源获得桥接，任意网页不能继承能力。

该选择延续 ADR-039 的共享前端重建方向，替代已退役的 Swift 主窗口宿主。现有 Python 应用层、认证回环 HTTP + SSE、外置 Python/PostgreSQL、联系人隔离、权限和人工发送边界继续保留。本机打包只交付桌面宿主，不内嵌业务数据库或 Python，也不扩展为公共分发、公证或自动更新。

窗口关闭只隐藏，保留本次运行状态；原生“窗口”菜单能恢复两个窗口。未提交草稿和编辑文本不跨重启保存。后端接入后，明确退出必须以同一已验证连接的认证关闭协议确认停读，不能把关窗、网络超时或进程存在与否当成停读证明。

实现状态：当前 `desktop/` 完成双窗口、资源加载、受限桥接、本机打包及认证后端连接/退出停读。主进程以原已验证连接的认证 `stopped` 响应或状态确认停读，失败保留恢复入口，不改持久同步开关，也不按握手 PID 杀复用实例。业务页面仍使用真实未就绪状态，不宣称真实微信读取、候选生成或剪贴板闭环已验收。后续能力按[本机 App 规格](../../.scratch/mac-desktop-app/spec.md)的独立任务推进。
