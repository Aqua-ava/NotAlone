# ADR-089：一次授权同步全部微信私聊

> 决策状态：已采纳（2026-10-21）。用户明确要求开启后自动同步当前账号全部私聊，包括现有未绑定会话及以后新增会话，无需逐个确认。
> 实现与验证状态：见[功能规格](../../.scratch/all-private-sync/spec.md)，本决定不替代工程与实际 App 验收。

逐会话确认让用户误以为打开同步总开关就已覆盖所有私聊，实际上新增会话长期停留在未绑定列表。决定保留默认的“仅所选会话”，新增一次明确授权的“全部微信私聊（包括以后新增的会话）”；用户接受更广的本机读取范围，以换取无需重复添加的连续同步体验。

## 范围与身份

- 范围按用户、渠道和当前已验证微信账号持久保存；升级与无记录时默认仅所选，不从总开关或已有绑定推断全部授权，换账号不继承原授权。
- 全部私聊授权覆盖该账号 CLI 可见的现有及以后新增一对一会话。总开关开启时周期发现，先用稳定外部会话标识核验渠道身份，再建立有效绑定和读取文字；不靠昵称、备注、OCR 或消息内容推断身份。
- 已有唯一有效渠道身份复用原联系人；无对应身份时创建独立联系人。同名不同账号保持独立；身份冲突停止该项自动建联并显示失败，不合并、不改绑、不影响其他有效绑定。
- 撤销绑定及删除联系人保留必要的无正文排除记录，自动发现和重启不能重新授予它们；只有后续明确的单会话确认可以恢复。重复开启全部私聊也不清除排除决定。
- 切回仅所选停止以后自动纳入，已有有效绑定仍可同步。范围设置与总开关独立；关闭总开关或退出停止读取与自动纳入，重新开启后继续有效范围内的发现和恢复。

## 保留边界与取舍

新绑定仍从各自 baseline 开始，已有绑定保留可靠游标与去重；按 ADR-025／083 恢复可检测缺口，不自动导入 baseline 以前历史。来源、消息、关系资料和删除路径仍按 `owner_id + contact_id` 隔离；此范围授权不增加群聊、媒体正文、其他 App、外部模型用途或发送权限。顶部搜索继续只选择本次辅助回复的人，前台识别的重名、改名及低置信度门禁保持。

不采用“把首次列表默认全选”作为替代：它只覆盖当时列表，不能表达未来新增会话的持续授权。不采用“全局开关顺便扩大范围”：已有用户升级不应从仅所选静默变为全部。

## 修订关系

- 修订 ADR-030 的所有新增会话均需逐项确认限制：它继续适用于仅所选模式，全部私聊模式由范围授权建立绑定。
- 修订 ADR-087 中必须逐会话确认才能新建联系人及加入不扩大读取范围的绝对条款；保留真实微信来源建联、独立创建／导入新建退役、历史资料保留和导入仅补充已有联系人。
- 修订 ADR-023 中绑定集合仅能来自当次人工确认的范围限制；保留稳定标识、独立游标、只读事件触发及有界轮询。
- 细化 ADR-025 的“已确认范围”：包括全部私聊授权内已核验建立的有效绑定；baseline、可靠游标、去重与停止／恢复约束不变。
