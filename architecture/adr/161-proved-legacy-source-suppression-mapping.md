# ADR-161：旧读取器来源的有界抑制映射

部分替代（2026-11-07）：[ADR-176](176-in-place-source-recovery.md)。ADR-176 停止由正常恢复建立新绑定；本决定仅继续约束既有历史副本的有界映射、抑制及删除闭包，存量清理完成前保留。

状态：已采纳（2026-11-03）；已实现并完成独立认证、撤回与删除闭包、启动归属验证，见[多联系人同步验收](../../docs/verification/multi-contact-sync-recovery-20261103.md)。

部分旧读取器将相同物理表记录为不同的来源代次，导致 ADR-144 的独立来源重新认证无法延续已有撤回与删除保护。决定只在旧、新正式读取器分别验证同一稳定账号和会话、所选物理表实例及完整结构元数据后，接纳一次有界的来源键映射；不将失证前后的来源认定为连续，不恢复旧资料的使用资格。

- 本机维护证明必须匹配旧读取器保留产物的摘要、旧认证记录、当前读取器支持档及准确目标。两个独立读取器只读取元数据，所选表的分片、物理实例、结构、主键和本地键语义必须一致；当前目标必须明确列出完整检查文件。未选择文件的差异不能据此证明整个账号历史连续。
- 证明只适用于同一 `owner_id + contact_id`、稳定账号和会话以及明确列举的旧、新来源代次。来源键只按已证明表内的规范本地键转换；正文、时间、昵称和服务端别名均不参与。已撤回终态仅迁移证明中逐项列明的终态；未知终态、目标或契约变化继续阻断认证。
- 维护意图保存在数据库目录之外的私有固定路径，启动时验证、原子领取并消耗，不开放 HTTP 证明上传接口。认证仍从空游标完整读取，使用正常 snapshot guard；证明、旧围栏和摘要进入无正文操作审计，最终原子启用前保持停读。取消和关闭必须排空所使用的元数据读取器。
- 窄补充规则（2026-11-06）：核验时，旧来源代次的撤回记录如果当前代次已在同一分片、同一物理表实例、同一规范本地键位置独立记录为撤回（排除的 `capture_record`、原因为 `source_recalled`，且其读取契约与本次核验一致），即视为已被覆盖，映射到当前代次的同一物理位置，不再要求本机维护证明；覆盖不完整时，其余旧键仍须按上述证明规则处理。位置相同但原因不是撤回、或旧键本身不是撤回记录，不构成覆盖；映射不读正文、时间、昵称或服务端别名，也不跨联系人或会话借用。
- 覆盖结论以独立字段（`covered_terminal_mapping`，含摘要）保存在认证操作的无正文审计中；它是不同于双读取器物理证明的窄证据，不冒充完整证明。摘要有效的已完成审计可以延续后续重新认证，并让删除和未来排除同时覆盖两个代次；旧键排除不因映射删除，删除任一代次仍清理两代次的来源、终态与派生结果。
- 只有已经完成认证且审计摘要有效的证明，才能为后续删除和排除扩展同一物理出现。删除任一代次时，冻结跨代次来源及派生结果的清理目标，同时保留全部已证明键的未来排除，即使另一代次尚无捕获也不能重新导入。重试不得依赖原种子仍存在，其他联系人、表和本地键不受影响。
- 后续重新认证可以沿同一有效证明延续这些排除；这只传递抑制，不建立消息别名、读取资格或旧证据复用。没有证明、证明未完成或校验不符时保持原有严格规则。证明随所属联系人或账号的删除路径清理。

本决定仅补充 ADR-144 的独立认证和物理删除闭包，在上述双读取器证据成立时允许所选物理来源的代次标识不同；普通续证、分片增长和读取授权规则不变。直接忽略来源代次、清除围栏、取消撤回保护或通过新身份重新导入旧资料均未采纳。
