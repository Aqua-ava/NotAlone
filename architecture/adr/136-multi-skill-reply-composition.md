## 背景

多个彼此补充的沟通场景可能同时适用于一次回复。只允许选一个会丢掉其他相关方法；让模型无边界地加载资料则会挤占本次上下文，也会使实际使用依据难以核对。

## 决定

正常回复生成由模型根据本次意图和受控目录自动选择零个、一个或多个相关 Skill，并按需读取；没有合适项时可不加载。选择多个不代表必须读完所有包。只有已启用、已核验且来源有效的当前修订进入可选集合；启用方式由目录管理决定；本决定不改变现行目录管理的启停、来源资格和撤销规则。

一次回复在开始时冻结当时符合条件的目录和每个包的当前修订。每个包最多使用其一个当前、不可变修订；读取正文或资源、每次模型发送和候选提交时，都继续复验联系人范围、启停、来源资格及这些修订。对每次选择和实际返回的内容分别记录包身份、修订、准确 Skill 名称、资源路径和正文摘要；列入可选目录或选择工具返回本身都不能算作已加载。界面只显示本次确实读入回复的 Skill 名称与版本。

自动入口可以组合多个相关 Skill。显式 `selectedPackageId` 兼容入口仍只定位用户指定的单个 Skill，并沿同一受控 provider 预加载；此接口不转为多选，也不改变正常自动入口的组合规则。

以下限制维持不变：

- 一次回复最多 5 次物理模型请求，共用原截止时间；不增加自动重试。
- 一次回复最多读取 2 份静态辅助资源，所有 Skill 共用此总数。读取资源时，模型须同时给出准确 Skill 名称和该 Skill 列出的相对路径；业务层还须绑定并复验相应包身份和修订，不能因各包含有同名路径而串读。
- 每次物理发送仍完整检查现有上下文与输出预算。组合 Skill 正文和资源一同计入现有输入；超过预算按既有失败流程处理，不扩大模型上下文预算，也不静默裁剪。
- Skill 仍然只是受控只读策略文字与静态素材；不增加文件系统、脚本、网络、子 Agent 或聊天发送权限。联系人确认、用户亲自发送、来源撤销和删除语义继续有效。

任一 Skill 读取失败时，按既有无 Skill 恢复流程清除本轮已加入的 Skill 正文和资源输入，重新核验其余输入后再生成；不带着部分失效的多 Skill 内容继续回复。联系人身份、授权、资料来源或其他非 Skill 输入失效时仍停止生成。

## 后果与验收边界

候选上下文、运行事件和历史展示须能容纳同一回复内多个包的独立修订及实际输入；静态资源的展示和读取必须保留 Skill 名称与路径的配对。剩余模型调用和资源读取额度按整轮计算。

本决定沿用锁定 DSH provider、Agent、Tool 和 scope 合同，不要求升级 DSH 或改动官方插件。实现需要用合成集成验证：多个 Skill 被选择和实际加载、不同包的同名资源不串读、每包修订及来源失效阻止迟到结果、整体 5 次模型请求／2 份资源／输入预算仍生效，以及任一 Skill 读取失败后完整清除再以无 Skill 流程恢复。真实模型质量和桌面验收另行核实。
