# ADR-015：后台任务与联系人记忆目录生命周期

> 状态：已采纳
> 决策日期：2026-08-23

## 背景

导入后的记忆提取、联系人目录更新和删除清理都可能跨越多个步骤。任务需要可恢复、可重试、可审计，同时不能把聊天正文复制进任务记录，也不能让并发 Worker 同时修改同一联系人的目录。

## 决策

1. `background_task` 是业务工作记录，`background_task_step` 是固定顺序、可独立恢复的步骤；它们不是普通日志，也不是模型 Todo。
2. 同一 `owner_id + contact_id + source_document_id` 的导入任务幂等。重复导入复用原任务和状态，不创建第二个任务；消息写入、来源记录和任务模板在同一事务中创建。
3. 同一联系人同时只允许一个 Worker 执行；不同联系人未来可以并行。Worker 使用租约，租约过期后可接管。用户暂不提供取消入口，来源删除会停止相关未完成步骤。
4. 临时网络或模型错误最多自动重试 3 次；已经成功的步骤跳过，只重试失败步骤。三次失败后任务进入 `failed`，手动重试复用原任务并增加尝试次数。
5. 任务状态展示当前步骤、进度、尝试次数和错误分类。活动任务持续保留，成功/失败等终态保留 90 天后清理。任务只保存对象 ID、数量、时间、模型版本和错误元数据，不保存聊天正文或模型完整输入输出。
6. `contact_memory_index` 是一位联系人的可重建目录，不是新的事实源。它只保存少量主题入口和 `memory_ids`，最多 20 个主题；当前有效记忆变化时优先增量更新，批量变化或版本不一致时合并重建。
7. 目录重建只使用确定性代码，不调用模型。新目录完成验证前保留旧目录；只有 `built_from_memory_revision` 与当前版本一致且状态有效时，目录才能参与回复上下文选择。
8. 外部模型只接收必要的规范化文字和有限窗口。结构化结果必须带消息 ID 和证据范围；无证据、证据越界或格式无效的候选拒绝，不写入记忆。模型调用只在出站台账中记录供应商、模型、时间、用量、耗时和结果状态。

## 后果

- 系统需要任务表、步骤表、租约、幂等键和清理策略，但消息导入不会被模型失败回滚。
- 记忆目录更新可以吸收短时间内的多次变化，避免每条记忆都触发完整重建。
- 失败恢复依赖确定性 Worker 和数据库状态，不依赖模型自己记住进度。
