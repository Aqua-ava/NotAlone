# ADR-105：以当前有效绑定观察恢复前台确认

> 后续修订：[ADR-132](132-existing-contact-name-matching.md)按用户明确选择恢复名称与已有稳定绑定的直接关联；不再以读取 grant、逐人新桌面证明或无关群名缺失全局阻塞，已有名称算法与实际拒绝条件保持。

> 后续局部修订：[ADR-158](158-contact-selection-keeps-foreground-follow.md)按用户 2026-11-03 的明确要求移除独立手动锁定模式；显式选人不停止观察，返回微信后继续自动跟随，不提供恢复开关。逐请求用户确认来历及授权边界保持。

> 状态：已采纳；自动检查与真实桌面验证分别记录。
> 决策日期：2026-10-26
> 局部替代：ADR-050／052／053／054／055／056／073／075／076／077 中失败留下历史人工门、仅允许特定原因解除的条款。当前帧质量、名称匹配、已有绑定、授权与时效规则保持；原主动手动模式条款已由 ADR-158 替代。

真实排查发现，名称识别、完整名单匹配和已有绑定核验均已成功，桌面仍因更早的失败返回 `manual_confirmation_required`。合成回归可稳定重现：先返回探针超时，再返回有效的低分名单匹配，生成仍被阻止。用户要求匹配成功后自动确认，修复范围为确认恢复，不改 OCR 引擎、预处理或分数阈值。

与上述旧 ADR 保留历史人工门的条款冲突；重新讨论的原因是旧失败不再代表当前会话的核验结果。现在以每轮新鲜有效观察独立授予资格：当前质量不足、未绑定、歧义、群聊或技术失败继续拒绝当轮自动确认并撤销旧生成资格；后续正式观察重新通过前台与窗口、标题完整性、现有名称匹配规则、唯一私聊及同 owner／渠道账号的 active 绑定核验后，桌面自动确认对应联系人，不再根据历史失败原因二次拦截。

高分完整名称、通用名单匹配与兼容尾部文字核验三种既有成功结果采用相同恢复规则。OCR 原始分数仍如实保留，不自行抬分；低分原样名称仍须满足 ADR-076／077 的既有门槛。没有新的成功证据时，不复用旧身份、不恢复生成；联系人不在当前可用目录时仍拒绝。

历史决定（已由 ADR-158 替代）：用户主动选择的手动输入模式停止自动观察，只有明确恢复微信会话识别后才重新接收观察。单轮在途、失败退避、执行预算、五秒新鲜度、请求取消、连接代际、范围变更和晚结果丢弃规则保持。恢复只选择联系人及其既有内容，不生成或发送消息，不修改授权、绑定、数据库或私人资料；视觉输入仍只在本机内存按原范围处理。

原验收范围（手动模式相关用例已由 ADR-158 的新验收要求替代）：以桌面公开观察入口与确认状态为测试接缝：失败后成功恢复、失败当轮撤销资格、混合历史、未绑定／群聊、主动手动模式及取消后的迟到成功。真实 App 使用热更新开发实例核对已绑定私聊自动确认；合成失败注入不等于真实故障场次。

2026-10-26 验证：低分有效绑定恢复回归先失败后通过；`desktop` 的 `pnpm run typecheck` 与 `pnpm test` 通过，1012 项通过、1 项条件跳过。原生变化通知子进程测试首次并行运行有时序失败，单例复验及随后全量均通过；仍应关注该测试的并行稳定性。独立规范与需求审查无阻断项，旧注释已更新，现有桥接结构保留兼容。

Computer Use 实测复用热更新开发实例：由用户将真实已绑定私聊置于前台并唤出小窗，Agent 读取界面并核对联系人已自动切换、显示绑定确认及生成入口可用，未点击人工确认、未生成或发送消息。真实界面通过不代表已覆盖所有故障场次；超时与混合失败后的恢复由合成公开入口回归验证。未保存真实截图或姓名；未新增测试 App、修改授权或业务资料。
