# ADR-133：按变化页持续同步与持久检查点

状态：已采纳，实施与验收进行中。日期：2026-10-31。用户明确要求改为真正增量读取，并同时修复状态页超时与消息提醒。

## 修订范围

本决定修订 [ADR-127](127-sqlite-history-normal-use-restart-rescan.md) 中“正常重启必须完整重扫”及每轮 tail 完整快照重扫的实现选择。首次授权仍按 ADR-100 读取本机可读历史；来源实例、授权、删除／排除及未知状态隔离等既有边界保留，不用名称匹配恢复权限，不采用最大消息编号或时间水位假设。

## 读取方式

- 对已确认单个私聊的整数主键表建立页摘要、页内行标识及溢出页归属索引；不解码原始页中的消息正文。普通持续同步读取完整提交的新增 WAL 帧，据变化页定位受影响的行，再经既有只读 SQL 与状态规则定点投影，发现较小编号新增、旧消息修改／撤回及来源行消失。
- WAL 偏移不是持久证据。校验日志版本、页大小、salt、帧校验链和提交边界；日志被回收、截断或出现缺口时，核对所选表可达物理页的摘要，仅重新投影实际变化页所关联的行。不得用损坏、未提交或不连续日志推断已同步；结构或身份无法核验时停读。
- 多分片继续使用已固定的 SQLite 读者与独立观察者，原始页解析前后复验共同无提交窗口，避免把原始文件的新切面与 SQL 旧切面拼接。旧文件或表实例、真实表结构及账号来源身份改变继续停读；新增聊天表按下述受限扩展处理。

## 表身份与新增聊天表

SQLite 的 `schema_version` 是全库结构变更计数，其他会话建表也会改变它，不能单独充当当前联系人的表身份。表实例使用文件分片标识、表名、根页及建表 SQL 摘要；结构比较继续包含列、索引、触发器等实际元数据，仅忽略该全库计数。账号和文件实例核验保持不变。此规则无法独立识别保留这些稳定标识及相同结构的原地删表重建，与 ADR-127 的相同标识原地回滚限制一并记录；消息身份或内容冲突仍隔离。

新目标保存完整、有限的已核验消息文件清单。只有清单和来源相同、每张旧表实例与实际结构不变、变化仅为当前联系人在已核验文件内新增聊天表时，才允许建立新目标。旧目标不跨表续读；先交接到新的历史目标，补读新增表并核对旧表变化，再恢复持续增量。旧目标缺少完整清单或检查点缺少逐表结构证据时，不推断扩展安全。

从旧表身份迁移时，可使用账号、来源目录及读取器制品绑定的一对一不透明别名。必须根据原始无正文元数据逐表核验全部旧文件、根页、SQL、列、索引和触发器，保留消息出现键、来源、删除／排除键及授权决定。只有已备份且严格证明为全库计数变化或上述合法新增表的误报围栏可事务化解除；实际身份或结构不匹配仍停读。

## 持久检查点

检查点仅保留来源作用域摘要、页与行标识、内容摘要及日志位置，不保存正文、密钥、账号明文或私人路径。文件只在本机受管读取器目录保存，目录 0700、文件 0600，核对所有者与普通文件，拒绝链接、超限、重复 JSON 键及绑定失配；内容使用本机来源密钥派生的 HMAC 校验。

检查点绑定账号／会话、来源目录、来源代次、表实例、结构、读取规则和读取器制品，并保存受 MAC 保护的逐表结构摘要。仅业务事务已接受的游标可触发恢复，还须复验当前 owner、联系人、绑定、授权、资料代次和删除屏障。新进程先建立新的受控目标，以变化页交接到新的历史目标，接受完毕再转入持续增量；不直接向旧原生进程游标发送 tail。总体结构摘要不同只允许上述有证据的新增表；旧表摘要变化或证据缺失不恢复旧检查点。

完整检查点在返回新状态令牌前写入并同步文件及目录；保留上一份可恢复状态。空闲轮次只推进内存变化位置并返回同状态令牌下的新不透明游标，不反复重写整个索引；重启可从语义相同的较早页状态补差。检查点缺失时明确重新建立基线，绑定失配或内容损坏不伪造恢复。联系人或相关资料删除需清理其派生检查点，且撤销与删除屏障始终禁止旧检查点复活资料。

## 状态与界面

同步状态须查询当前作用域，允许有界批量并在批次间让出 SQLite 队列，不以延长超时替代实际性能修复。消息事件沿受认证的本机流传递 owner、contact、message 标识，不包含正文；仅事务成功后发布。新增与更新分开处理，旧消息变化只刷新资料，历史补齐不产生新来信提醒洪泛；连接及重连后主动核对当前联系人的最近聊天。

## 验证要求

在锁定 WCDB 与加密合成库中覆盖无变化零历史行投影、单个旧行修改、低编号新增、删除、溢出页、树分裂／合并、WAL 回收、未提交尾、取消与损坏拒绝。比较相同负载下的扫描行数及状态查询耗时，并在 `pnpm run dev` 实测状态页、消息提醒和重启续读。设计采纳不代表上述集成已通过，结果另行记录。
