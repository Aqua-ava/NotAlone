# ADR-098：Skill 数据库只保留业务状态

> 状态：已采纳（2026-10-22）。用户明确要求按目录方案清理不必要的 Skill 表和字段。
> 局部替代 ADR-096 中数据库保存描述、资源清单及旧内容兼容列的安排；目录唯一来源、范围、审核、版本、按需读取和删除要求继续有效。

## 决定

不可变版本根的 `manifest.json` 保存名称、描述、质量警告和资源的相对路径、类型、大小与哈希，不含正文。目录发现读取该清单，选中后才读取 `SKILL.md`、资源或获准方法。数据库以清单哈希校验文件完整性；清单缺失或损坏时拒绝加载，不从旧正文或审核记录回退。

移除 `reply_skill_resource` 整表，以及以下字段：

- `reply_skill.description`、`directory_managed`。
- `reply_skill_version.name`、`description`、`content`、`validation_warnings`。
- `reply_skill_method.title`、`instruction`。

保留 Skill 稳定名称和归属、联系人适用范围、当前版本与启停状态、不可变版本身份/定位/完整性、审核及来源删除依赖、方法身份/顺序/延续映射/停用政策、使用回执、库修订和可重试文件任务。这些记录承载用户决定和业务一致性，不是第二份 Skill 内容。

## 升级与失败

迁移器在删除结构前将所有有效历史与当前版本完整落盘，逐项核验文档、全部资源及方法，补齐无正文清单。已有目录版本保持原文件字节与版本身份。结构删除、业务定位更新和迁移账本在同一事务内提交；任何失败保留原结构与数据，落盘文件可重试复验。旧内容转换只在结构升级执行，正常运行时不再维护数据库正文兼容路径。

删除继续覆盖工作目录、版本根清单、方法、正文、资源和暂存；停用、来源撤销与未完成文件任务不能被扫描恢复。完整性哈希不是授权，运行时仍核验 owner/contact、审核来源和停用政策。

实施与验证见 [规格](../../.scratch/skill-database-cleanup/spec.md)和[验证记录](../../.scratch/skill-database-cleanup/validation.md)。
