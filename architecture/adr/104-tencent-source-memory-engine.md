# ADR-104：记忆生成逻辑按领域模块维护

> 状态：已采纳，2026-10-26 按用户决定修订为本地独立实现。此前独立维护第三方源码的方式不再适用；业务保护约束继续有效。

L1 提取、批量裁决、L2 场景整理和 L3 长期背景生成直接归入相应的记忆模块，使用项目已有的数据字段、模型端口与输出协议。提示词和输入构建由本项目维护，不另设第三方模块、格式转换层或上游版本清单。

[ADR-102](102-dsh-typescript-backend-migration.md) 的 DSH／TypeScript 运行方式继续有效；不引入额外记忆服务、遥测或独立数据库。

## 保留的产品约束

- 原始会话的用户和联系人都是人；分类、主体、来源与时间使用 NotAlone 领域契约。一次性关系要求不升级为助手长期规则。
- PostgreSQL、稳定身份、`owner_id + contact_id` 隔离、原始资料和已有人工修正保持。来源核验、可撤销版本、事务、删除及提交前复验由现有确定性外壳负责，不能以来源编号合法或上游生成成功代替语义支持。
- 模型仍通过现有 DSH、provider、逐物理请求预算及台账；未知请求回执不能盲重放。L2/L3 工具仅操作同范围内存暂存视图，核验后才发布，不获得文件系统、网络或聊天发送能力。
- 生成仅依据同联系人资料；不补造心理动机或代替用户决策。分类、主体、时间、来源版本、场景文件格式和显式完成协议保持约束。
- 真实验收继续限定用户本轮指定且唯一核验的联系人；费用按已确认范围暂豁免。合成检查、模型质量和实际桌面验收分别报告。

提取实现在 `memory/extraction/`，裁决实现在 `memory/management/`，场景与长期背景实现在 `memory/layered/`。实现变化不表示历史失败、未知回执或真实记忆质量已解决。
