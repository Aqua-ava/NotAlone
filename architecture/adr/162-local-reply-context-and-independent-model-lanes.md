# ADR-162：本机回复资料与独立模型并发

> 状态：已实施；专项自动检查与合成开发 App 验收通过，全量检查限制见[验收记录](../../docs/verification/local-reply-and-model-lanes-20261103.md)。决策日期：2026-11-03。
> 局部修订 ADR-038／099 的前后台模型互斥，以及 ADR-113 当前固定目标用于回复资料资格的范围。保留 ADR-106 的出站和保存复核、ADR-063 的实际来源依赖及 ADR-144 的旧失证资料保护。

## 问题

用户已经确认联系人，回复却仍可能因微信读取器暂时不可用而恢复来源、等待或失败。前台模型许可又要求后台调用全部结算，后台提取可使即时回复长时间排队。直接放开并发后，按整个联系人资料集合修订号复核也会把后台新增无关记忆误判为本轮输入失效。

## 决定

### 回复使用持久接纳的本机资料

回复按 `owner_id + contact_id` 读取已接纳的本机消息、正式记忆及正式发布资料；本轮冻结、旧候选继续、讨论恢复、出站和保存使用同一具名本机资格。该资格核验实际捕获的持久接纳范围、版本、可用性、隔离、删除、真实来源冲突及图片／递归事实依赖，不要求当前微信读取进程或运行时代次的活守卫。

回复模块不持有微信 Channel，也不装配 `prepareSource/ensureSourceReady`。生成不启动或等待同步、L1、L2、L3。后台采集、媒体获取和记忆写入继续按原授权、活守卫及来源连续性合同执行；本机使用资格不能恢复读取授权。

本决定不清除既有不明来源围栏，不将新捕获用作旧失证资料的补证，也不恢复删除或清空排除项。可用资料为空时只按本次独立输入生成，并保留真实的覆盖限制。

### 本轮固定精确依赖

新请求只选择当时有效的消息、记忆版本和 current 正式发布集合，持久固定实际来源、解释版本、记忆保护修订、publication、完整成员及递归底层依据。请求不能自行指定任意历史版本。

外发与保存继续在短事务内核验本轮实际依赖，不以整个 owner/contact 的 memory/document revision 变化判失效。新增消息、无关记忆或新发布不自动改写、失效本轮快照；原冻结版本仍可用且实际依据未变时允许完成。实际使用的资料被纠错、删除、隔离、换图、明确撤下或存在真实来源冲突时，旧输入及迟到结果仍拒绝。模型调用期间不持有数据库事务或写锁。

### 模型许可分为独立两类容量

仍使用唯一 DSH 模型宿主、共享 provider 和统一出站记账；不增加第二宿主或供应商配置。`ModelPermitArbiter` 保留原 Interface、socket 和 journal，仅改变集中派发规则：

- foreground 固定 1 路，background 沿用既有 N 路，默认 3、可配置 1–4；互不借槽，总上限为 N＋1。
- 两类分别计数、同类 FIFO。前台不等待后台清空；前台在途不暂停后台。
- 取消等待仅撤销该等待；已授权且未实际结算的调用仍占容量。孤儿仅冻结所属类别，不自动回收未知许可。
- 全局 pause、配置切换、stop、退出和 journal 写失败仍按原保护处理，两类实际调用均参与 drain。重启仍须证明旧宿主及执行者已停止。

## 工程取舍

本机资料资格与外部读取资格分别集中管理，在可信装配处选择读者，不增加来自 UI／HTTP 的跳过校验开关。回复输入模块负责冻结和精确复核，仲裁器负责许可生命周期，调用方不协调微信或后台任务。

独立容量增加默认最高同时在途数至 4，供应商的速率与容量限制仍独立适用。冻结版本可以短暂落后于后台最新资料，但本轮稳定、下轮更新，真实失效仍阻断。

## 验证范围

自动检查与开发 App 实测分开记录。必须证明微信不可读时合法本机资料仍可使用、后台调用悬挂时回复已发送、无关更新不失效而相关删除／纠错仍阻断，以及交错请求的来源、图片、台账和取消归属不混线。使用隔离合成资料及环回供应商，不执行真实微信消息发送；发布包与供应商真实质量不在本轮范围。
