# ADR-027：记忆准确率评测门槛与待确认候选的参考边界

> 状态：已采纳
> 决策日期：2026-09-15
>
> 本 ADR 补充 ADR-024 的采纳门槛与 ADR-026 的语用分流，不替换其
> 来源、`pending`、版本化、fail-closed 和安全规则；待确认候选参与回复
> 只确认方向，实现属后续纵切。

## 背景

语用分流已把"记不记"的决定从模型手里拿回代码，但模型字段判错的代价是：
该记的事实永远进待确认，或不该记的内容被自动采纳。判断维度不止真假一种
（主体、转述、时间、指代、改写保真、媒体占位），目前只有开发期 24 条用例
覆盖了其中一部分。用户目标是逐步走向全自动（无需逐条确认），这要求先有
可信的准确率测量，再按证据逐类放开；同时待确认候选目前永远不参与回复，
大量计划与未定信息等于"记了没法用"。

## 决策

1. 建立合成、分维度的标注评测集，以最终去向（自动采纳 / 待确认 / 不生成）
   判对错；真实聊天只在本机一次性找错，只保留聚合指标，原文不进仓库。
2. 达标签与放行：某维度至少 15 条用例中假事 0、记错人 0、一般错误 ≤1，
   才允许该类事实进入自动采纳；一次只放行一类，并记录证据。
3. 修错手段限定为提示词与示例、字段语义、模型与思考模式配置、生成后的
   确定性降级兜底（只降不升）；禁止写死句子、按用例特判或放宽安全规则。
4. 自动采纳安全规则（语用 CONFIRMABLE、置信度门槛、风险白名单）在评测
   驱动阶段保持不变；修改规则必须单独立项并附评测证据。
5. 待确认候选可以作为回复参考，但必须带明确的未确认标注，不得写成确定
   事实；实现（证据类型、解释理由落库、界面展示）属后续纵切。
6. 生产模型配置由一次性对照实验决定（当前默认、同模型思考模式、官方
   DeepSeek 可选），结果记入 `research/`。

## 取舍

- **严格数字门槛 vs 更快全自动**：选择门槛。先准后自动；否则放开的每一类
  都会把误记带进回复。
- **合成加本机聚合 vs 上传真实数据评测**：选择隐私优先。真实数据只在本机
  产生聚合数字，牺牲一部分真实分布覆盖。
- **待确认可用 vs 只用已确认**：选择可用但强制标注。保住"漏记"方向的质量，
  代价是回复链路将来要新增一种证据类型。
- **一次放行一类 vs 整体放宽**：选择逐类。放行速度慢，但错误可归因。

## 后果

- 自动采纳覆盖率只在有评测证据的维度上增长；短期内待确认仍会积累。
- 回复链路将来需要支持"未确认参考"证据；在此之前待确认对回复不可见。
- 评测集与达标签成为后续放宽门槛的前置条件；记忆巩固、复核员等后续
  能力也要挂在同一套评测上验证。

## 验证

- 评测集与对分工具走正式提取链路；每修好一个维度保留回归用例。
- 放行记录包含：维度、用例数、假事数、记错人数、一般错误数。
- 模型对照实验记录结构化输出稳定性与实际配置。
