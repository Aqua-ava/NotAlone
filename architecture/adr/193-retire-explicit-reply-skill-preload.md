# ADR-193：回复 Skill 统一按需目录并退役显式预加载

状态：已采纳，2026-11-17。用户要求深查并直接重构无用兼容设计。

## 问题与决定

当前回复界面只提交表达或讨论请求，没有显式选包控件或调用者。正常入口已由联系人分组确定可用目录，再由官方 `skill` 工具按需读取正文；`selectedPackageId` 却仍从 IPC、HTTP、业务编排传到 provider，维护另一套主机预加载、工具可见性和追踪分支。仅为旧低层入口保留这条链，增加了配置与验收组合，没有当前用户收益。

- 新候选及助手讨论统一使用受控目录和模型按需读取。IPC、HTTP 与业务受理明确拒绝旧 `selectedPackageId`／`selected_package_id` 字段，包括 `null`，不能静默忽略后换一种策略生成。正常请求信封不发送该字段。
- provider 只冻结联系人分组与合法包修订，不维护显式单包状态。目录发布不算正文载入；模型实际调用官方 `skill` 后才记录选择与正文输入，随后才可读取该包声明的静态资源。
- 联系人分组、启停、来源、包集合及修订复验保持；无可用 Skill 时不提供 Skill 工具。每轮五次物理模型调用、两份静态资源、完整输入容量和原截止时间保持。
- Skill 读取失败仍先排空并清理原运行副本，复验非 Skill 输入后整体回退无 Skill；来源、联系人或授权失效不降级绕过。

本决定局部替代 [ADR-136](136-multi-skill-reply-composition.md) 的显式单包兼容入口与预加载条款；自动目录、按需组合、预算及失败保护继续有效。

## 历史材料与实现边界

不迁移、删除或改写已有资料。历史工作区中的 `selectedPackageId`、原请求指纹、显式选择、预加载回执、实际 Skill 正文与修订继续按原快照只读回看，来源失效及删除仍沿现有闭包执行。保留历史材料协议不意味着继续接受旧生成参数，也不把历史预载改标为模型本轮主动读取。

两种实际产品动作继续保留：助手讨论输出实际发言，候选生成输出带依据的可编辑候选；两者共用现有 DSH 执行壳、模型许可、台账和删除设施，不因本次收敛改变产品会话身份或外部发送边界。

## 源码依据与验证

本轮声明、锁文件及实际安装的 DSH、Agent、Tools、Session、Skill 均为 `0.2.1-rc.2`。官方参考固定为 [`687f282e8625c6b8d11ff58211a90524be2e4317`](https://github.com/deepseek-ai/deepseek-harness/tree/687f282e8625c6b8d11ff58211a90524be2e4317)，不使用相邻仓库的可变 HEAD；未完成整个 npm 制品的可复现构建比对。

官方 [`tool-skill`](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/skill/tool-skill/src/index.ts) 提供可见性一致的名称／简介目录及 `skill` 工具。安装公开类型 `dsh-skill/lib/types/index.d.ts` 的 `registerProvider`、`snapshot`、`get` 与 `dsh-tools/lib/types/index.d.ts` 的 `restrict`、`guard` 已复核；本次删除主机定向预加载，不增加框架接口、不改 DSH 核心或插件树。

合成回归应覆盖旧字段拒绝且零模型调用、首次只有简介、零个或多个正文按需载入、资源读取与分组隔离、来源／修订变化、完整无 Skill 回退，以及既有历史材料读取。正式 profile 与普通业务入口分别验证；合成供应商及类型检查不能代替实际 App 或真实模型效果验收。
