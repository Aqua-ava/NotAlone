# ADR-022：前台同步人工验证的独立控制面

> 状态：已采纳
> 决策日期：2026-09-01

人工验证不能要求用户在微信和 NotAlone 主窗口之间往返：微信前台是同步读取的必要条件，而 NotAlone 主窗口获得焦点会使微信失去前台。因此验证控制面独立于主窗口，用户在主窗口启动验证后保持微信前台，通过菜单栏和全局快捷键记录检查点、处理中断或结束；主窗口只用于查看结果。

## 决策

1. “开始 Follow”允许在 NotAlone 主窗口中先启动，随后进入等待微信前台或读取状态；不要求点击时微信已经在前台。
2. 菜单栏提供验证状态和全部人工控制；全局快捷键可在微信保持前台时执行同样的检查点、恢复和结束动作。
3. 同步状态同时区分“当前微信是否前台”和“最近有效前台观察”。后者只保留不含正文的时间、已绑定联系人标识、水位和计数摘要，用于验证回看，不替代前台门禁或连续性证明。
4. 控制面不获得切换窗口、点击微信、滚动会话、输入或发送消息的能力。
5. 后台发现需要绑定确认的候选时不自动弹出主窗口。后端只在内存中保留最近一次观察产生的待确认绑定证据 60 秒；用户切回主窗口后仍须主动选择联系人，过期或候选变化后重新观察，不能自动绑定。

## 取舍

- **只保留主窗口按钮**：拒绝。它会迫使用户在微信前台和控制入口之间切换，破坏实时观察并让“微信前台”状态与可操作性互相矛盾。
- **可交互浮动窗口作为唯一控制面**：暂不采用。它需要额外处理遮挡、焦点和窗口层级；菜单栏与全局快捷键已经能覆盖验证控制且更小。
- **确认时重新要求微信保持前台**：拒绝。用户为了选择联系人必须回到 NotAlone，重新探测会把这个正常的焦点变化误判为会话失效；短时待确认绑定证据只解决这段确认时序，不放宽读取门禁。
