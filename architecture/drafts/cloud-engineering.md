# 云端工程结构与认证设备（草案）

> 状态：草案。对应改进建议 H4（云端模块划分与客户端形态）、H5（认证与设备绑定）。其中 H4 的模块清单与端云职责、H5 的最小认证方案为云端服务落地前的必须决策；API 契约与设备流程待实现时细化。

## 云端模块化单体内部模块

云端采用模块化单体，以下为内部模块清单与职责边界；模块之间通过明确数据结构交互，不在同一模块混入文件 I/O、模型调用、持久化和 UI 决策。

| 模块 | 职责边界 | 不允许包含 |
| --- | --- | --- |
| `ingest` | 导入文件解析、规范化、OCR/转写产物接入统一文字模型、索引。 | 不持有模型密钥；不写 UI。 |
| `contacts` | 联系人、会话绑定、确认关系与隔离键的权威管理。 | 不做消息正文解析或模型调用。 |
| `memory` | 原始资料、候选资料、已采纳关系资料、风格样本的分层存储与生命周期。 | 不直接调用外部模型；删除走 `jobs`。 |
| `retrieval` | 定义 `RetrievalPort`，实现联系人范围内的 PostgreSQL 结构化/全文检索、排序、预算截断与引用记录；未来可隔离 RAGFlow adapter。 | 不跨联系人检索；不生成回复；外部 Retriever 不成为事实源。 |
| `skills` | 定义 `SkillPort`，管理聊天套路目录、不可变版本和 owner/contact 范围；供 `load_skill` Tool 或用户显式选择复用。 | 不自动创建长期策略；不拥有 Agent Loop；不绕过范围与版本校验。 |
| `reply` | 以确定性外壳包围 LangChain `create_agent` 有界 Tool loop，注册只读 Tool、组装输入、校验并持久化候选。 | 不向领域层暴露框架类型；不检索未隔离上下文；不发送外部消息。 |
| `jobs` | 导入、删除、重建索引等可重试后台任务；维护 `background_task`、固定步骤模板、Worker 租约、幂等执行与最终验证。 | 不做实时同步采集；不让模型控制步骤或状态；不混用 LangGraph checkpoint 作为任务状态。 |
| `gateway` | 对外模型调用的唯一出入口：提供已批准的模型 adapter 与 `ModelPort`，裁剪请求、记录出站台账、校验供应商政策与硬失败。 | 不承载 Agent Loop、业务规则、联系人权限或存储业务资料。 |
| `sync_adapter` | Mac 微信前台会话同步的适配层：变化检测、端侧 OCR 触发、归属校验、增量去重。 | 不作为独立回复管线；原始视觉帧不持久化。 |
| `auth_device` | 认证、设备注册、令牌、解绑清理与设备级数据回收。 | 不参与联系人检索与生成。 |

## 客户端形态与端云职责

v1 客户端形态：macOS 桌面应用（含菜单栏），负责交互与本地采集。

| 职责 | 端侧 | 云端 |
| --- | --- | --- |
| 采集与 OCR | 截图/语音输入、前台会话画面变化检测、本地 OCR、说话人/顺序解析 | 不直接采集 |
| 去重 | 归属校验后与绑定下已有 `message` 去重 | 提供去重所需的联系人消息查询接口 |
| 解析与规范化 | — | 导入文件解析、规范化、索引 |
| 检索与生成 | 展示候选、编辑、确认 | 检索、生成候选回复 |
| 确认持久化 | 用户确认/拒绝、另存为手动资料 | 写入权威库 |
| 删除级联 | 触发删除、展示进度与失败原因 | 执行可重试级联删除 |

跨端流程需要固化 API 契约与数据结构：导入（提交来源 -> 创建 `background_task`（type=import）-> 回调进度）、同步去重（提交新增消息批次 -> 返回去重结果）、确认持久化（提交候选确认/拒绝）、删除级联（提交删除请求 -> 返回幂等任务状态）。契约的具体字段在实现时定义，但必须携带 `owner_id + contact_id` 隔离键。

## 后台 Worker 部署边界

v1 的 API 与 Worker 属于同一个模块化单体代码库，但作为不同进程运行：API 负责鉴权、创建任务和查询状态；Worker 负责领取 `background_task_step`、调用处理器并写回结果。两者只通过 PostgreSQL 中的权威业务记录协调，不在内存中共享任务真相。

- Worker 使用短租约和原子领取避免并发重复执行；租约过期后允许其他 Worker 接管。
- 每个步骤处理器以业务幂等键写入结果；重试不能产生重复数据。
- 解析、规范化、索引和最终校验使用确定性代码；关系提取等语义步骤通过 `ModelPort -> gateway` 调用已批准模型。
- AI 输出必须经过 schema、联系人范围和来源引用校验后才能写入业务表；任务状态只能由 `jobs` 状态机修改。
- 当 PostgreSQL 轮询、并发和可靠性出现可测量瓶颈时，才评估 Celery、Temporal 或独立队列，并保持现有任务契约不变。

## 认证与设备绑定（云端落地前置）

云端服务落地前必须定义最小认证与设备绑定方案：

- **账号与令牌**：用户账号作为 `owner` 的唯一身份；认证令牌最小化为按设备签发的会话令牌，端侧不持有可复用的长期静态密钥。
- **设备注册**：每个客户端首次登录时注册为设备，返回设备 id 与令牌；设备列表可查看、可撤销。
- **绑定会话隔离**：`conversation_binding`、同步开关与设备级采集状态只对注册设备生效，令牌与设备解绑即停止采集。
- **解绑清理**：撤销设备时，回收该设备的令牌与端侧缓存；`session_capture` 临时态与设备本地数据一并清除。
- **删除纳入设备**：账户删除或解绑流程中，必须包含设备级数据回收（令牌、端侧缓存、临时采集批次），并列入删除保证的验证清单。

## 供应商准入与模型代理（云端落地前置）

- **供应商准入表**：按用途（生成/抽取/OCR/转写）为每个候选供应商建立数据处理表：发送字段、数据地域、留存、训练使用、删除 SLA；选定后写入 ADR。满足安全门（地域、留存、删除能力、训练使用）方可生产调用。
- **密钥与代理调用**：端侧不持有供应商 API key；模型调用统一走云端 `gateway` 代理。密钥静态加密存储、可轮换，解绑/删账户时吊销。补齐前不将私密资料写入云端存储（见 H8）。

## 对象存储（云端落地前置）

接入云端对象存储前必须定义：

- 目录结构：按 `owner_id / contact_id / source_id` 分层，便于按联系人或来源级联定位；
- 对象级加密与生命周期策略（过期、版本保留）；
- 对象删除作为 `background_task`（type=delete）的可重试步骤，与权威库记录一致；
- 外部副本声明独立删除路径与留存期限。

## 测试工程组织（云端落地前置）

先建立 Python 包与 `unittest` 配置，再编写跨端流程的合成夹具与本地验证脚本，以 CI 保证可重复验证。夹具只能使用合成或匿名化资料，至少覆盖：正常导入、损坏导出文件、联系人隔离、来源与删除、空或模糊检索、已绑定前台会话的增量去重、未绑定或非前台窗口不会采集、候选回复不会发送外部消息。
