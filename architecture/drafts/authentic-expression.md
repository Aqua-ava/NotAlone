# 真实表达与关系感知挑战（草案）

> 状态：草案。产品北极星与真实性边界已经确认；热梗接入、表达学习、质量评估和具体数据结构仍待验证。本文记录问题空间和设计方向，不代表功能已经实现。

## 1. 产品北极星

> 帮助用户理解关系、探索表达并说出真正想说的话；增强用户的人格，不替用户虚构人格。

这条原则不是功能删减器。热梗、幽默、联系人专属表达、长期上下文、关系记忆、情绪判断和风格学习都可以存在，但必须服务于用户本次真实意图，并由用户选择、编辑和亲自发送。

“真实表达”不等于只能复刻用户过去说过的话。产品可以提供用户尚未想到的表达方式，帮助用户成长；边界是不能为了提高回复率而擅自改变用户立场、冒充不存在的经历，或建立一个与用户脱节的长期代理人格。

## 2. “人味”的可操作拆分

“人味”不是领域术语，也不能被简化为多用热梗或口语。候选是否自然，至少同时受三层语境约束：

| 层级 | 需要理解的内容 | 主要误用风险 |
| --- | --- | --- |
| 用户表达 | 句长、标点、称呼、表情、幽默尺度、直接程度。 | 把少量样本放大成固定人设。 |
| 联系人专属表达 | 双方称呼、内部梗、共同经历、可接受的玩笑边界。 | 跨联系人混用，或编造双方共享的东西。 |
| 当前文化语境 | 热梗的含义、来源社群、新鲜度、适用场景和冒犯风险。 | 梗已过期、用错社群，或在严肃场景强行玩梗。 |

真实聊天还包含停顿、省略、不立即回答、轻微不完整和自然换话题。模型不能把每条消息都写成完整、圆滑、面面俱到的小作文；“更完美”不自动等于“更像用户”。

## 3. 热梗与流行文化

### 3.1 待解决的问题

- **时效**：同一个梗可能在数日或数周内从新鲜变成陈旧、尴尬或反讽对象。
- **社群差异**：同一句话在小红书、抖音、B 站、游戏社区或特定年龄群中的含义可能不同。
- **用户适配**：模型知道一个梗，不代表用户会说，也不代表联系人愿意接。
- **场景适配**：冲突、道歉、悲伤、承诺和边界沟通通常不适合用梗消解。
- **来源与隐私**：公共趋势检索不能携带私人聊天正文、联系人资料或可识别关系信息。

### 3.2 候选设计方向

同一次生成可以提供不同风险等级的表达方向，而不是默认塞入热梗：

```text
A. 最接近用户既有表达的自然版本
B. 稍有幽默但不依赖热梗的版本
C. 使用当前文化表达的实验版本，并说明所用表达及风险
```

如果未来维护趋势资料，每条资料至少需要含义、来源平台或社群、适用场景、风险标签、更新时间、可选失效时间、来源和置信度。是否采用外部趋势 Tool、受控资料包或人工整理仍未决定；无论采用哪种方式，外部查询都不得包含私人聊天原文。

## 4. 已识别的挑战

### 4.1 输入与语境理解

| 挑战 | 典型失败 |
| --- | --- |
| 反话、阴阳和情绪伪装 | 把“你可真厉害”“没事”按字面理解。 |
| 消息归属 | OCR 把用户消息识别成联系人消息，或顺序颠倒。 |
| 多模态缺失 | 忽略表情包、引用、撤回、图片和语音语气。 |
| 上下文缺口 | 把不完整的前台同步历史表述为完整事实。 |
| 话题边界 | 把旧冲突错误带入当前普通聊天，或过早遗忘仍在延续的话题。 |

### 4.2 关系理解

| 挑战 | 典型失败 |
| --- | --- |
| 关系阶段变化 | 已经疏远，仍沿用热恋阶段的表达。 |
| 联系人状态变化 | 对方当前需要严肃回应，系统仍按过去偏好开玩笑。 |
| 权力和角色差异 | 对伴侣、朋友、领导和客户使用同一种策略。 |
| 单方面画像 | 从少量截图断言对方人格、依恋类型或心理状态。 |
| 错误归因 | 把未回复解释为冷淡、生气或关系恶化。 |

系统可以保存带来源的观察事实和用户备注，但不能把模型心理诊断或动机猜测写成联系人事实。

### 4.3 生成与连续性

| 挑战 | 典型失败 |
| --- | --- |
| 过度完美 | 每句都完整体贴，长期使用后明显不像真人。 |
| 风格漂移 | 用户原本简短，候选逐渐变成统一的模型文风。 |
| 事实或经历编造 | 为了自然生成“我上次也遇到过”等不存在的内容。 |
| 越权承诺 | 擅自答应见面、借款、保密、道歉或承担责任。 |
| 跨轮矛盾 | 候选与用户先前表达、当前草稿或已确认事实冲突。 |

当前草稿和用户本次明确意图优先于历史风格、旧记忆、Skill 与热梗。一次选择或临时应急不能静默成为长期偏好；表达样本继续遵守现行的用户主动保存规则。

### 4.4 长期人与产品风险

| 挑战 | 产品需要观测的信号 |
| --- | --- |
| 能力退化和依赖 | 用户是否越来越无法在没有候选时表达。 |
| 身份代理 | 候选是否持续塑造出与用户脱节的人格。 |
| 自动迎合 | 系统是否为了让联系人高兴而改变用户立场。 |
| 反馈污染 | 临时采用、复制或未发送候选是否被误当作偏好。 |
| 错误成功指标 | 采用率上升，但编辑、后悔、撤回或关系误解也上升。 |

产品目标是辅助表达，不是最大化对方回复率、关系推进速度或候选原样采用率。涉及操纵、PUA、制造焦虑、冒充和自动代聊的能力不进入产品范围。

## 5. 市场观察（2026-08-16 快照）

当前相近产品大致沿五条路径发展：

| 路径 | 公开产品例子 | 常见能力 | 暴露出的产品问题 |
| --- | --- | --- | --- |
| 截图即时回复 | RIZZ、YourMove、SayCoding | 读取一到数张截图，生成多条回复。 | 上下文短、重复上传、跨轮连续性弱。 |
| 风格模仿 | Replina、Whoopt | 风格样本、反馈和语气控制。 | 容易把个人风格简化成少量滑杆，并产生“像你”的虚假确定性。 |
| 联系人画像 | HitTheMark | 按聊天对象保存主页、朋友圈和聊天画像。 | 单方面推断、资料过期、第三方隐私和错误心理归因。 |
| 关系顾问 | Meeno | 关系建议、反思和沟通指导。 | 与实时回复链路分离，建议可能建立在不完整的单方叙述上。 |
| 输入法助手 | 智能帮写、AI 键盘 | 低摩擦改写和快捷生成。 | 当前联系人身份、关系资料和可解释上下文通常不足。 |

公开产品页显示，市场已经从一次性话术逐步走向“学习用户风格”和“按联系人理解关系”，但普遍仍需面对以下问题：

- **上下文与真实性**：短截图只能优化当前一句，无法证明候选符合长期关系和用户真实意图。
- **隐私表述**：产品对“不存储”“临时处理”“若干天后删除”的含义可能不一致，用户难以判断真实生命周期。
- **第三方权利**：联系人通常没有主动向回复助手提供资料，却可能出现在截图、画像和外部模型输入中。
- **商业摩擦**：高频生成、图片分析和订阅容易产生额度、隐藏收费或付费后仍需单独购买的问题。
- **真实性惩罚**：研究表明 AI 辅助可能提高效率和积极表达，但当接收者怀疑消息由算法生成时，对发送者的评价可能下降。

## 6. 质量评估方向

只看候选采用率会鼓励迎合和模板化。后续评估至少需要覆盖：

| 维度 | 可观察问题 |
| --- | --- |
| 意图保真 | 候选是否保持用户当前想表达的事实、立场和边界。 |
| 用户相似度 | 用户需要修改多少，是否出现陌生口吻或人格漂移。 |
| 关系适配 | 候选是否尊重该联系人的称呼、玩笑尺度和当前状态。 |
| 事实安全 | 是否编造经历、共享记忆、情绪、承诺或对方动机。 |
| 长期影响 | 用户是否后悔、撤回、发生误解或形成过度依赖。 |

评估数据只能来自用户明确提供的反馈或可验证的应用内行为。复制候选不等于已经发送，对方回复不等于候选正确，沉默也不能被解释为关系结果。

## 7. 尚未决定

- 热梗资料由受控公共趋势 Tool、定期资料包还是用户主动提供，及其更新和失效机制。
- 如何区分稳定表达习惯、联系人专属表达和一次性状态，并避免样本过拟合。
- 是否以及如何让用户表达当前目标、情绪和不愿表达的边界，同时保持交互轻量。
- 如何建立不读取外部发送结果的真实性、后悔和长期依赖评估。
- 未成年人、危机、操纵、骚扰和高风险关系场景的具体拒绝与转介规则。
