**NotAlone 是一个面向真实联系人的中文回复助手。** 有想法时，它帮你组织表达；没有思路时，它结合这位联系人的聊天与关系资料，给出可供选择的说法和建议理由。你可以查看依据、修改候选，再复制到微信中亲自发送。

> **当前提供源码开发版，面向 macOS。** 使用需要自行配置模型服务；首次连接微信还需单独准备受支持的本机读取工具。独立安装包与其他平台的支持状态见[当前进度](#当前进度)。

## 能做什么

| 你遇到的情况 | NotAlone 如何帮忙 |
| --- | --- |
| 知道想说什么，但不知道怎么说 | 输入想法、草稿和语气要求，点击 **「帮我表达」**，整理成可编辑的候选。 |
| 一时不知道该怎么回复 | 点击 **「帮我想想」**，获得几种说法和建议理由；也可以先写下顾虑。 |
| 希望建议考虑你们的关系 | 自动参考同一联系人最近最多 50 条有效聊天，并按需使用相关记忆与关系背景。 |
| 想先和助手讨论，再决定表达 | 围绕当前联系人继续助手讨论，回看已保存的讨论与候选。 |
| 想知道建议从哪里来 | 展开本次依据，核对参考资料，再决定是否采用。 |
| 不想每次都重复交代背景 | 开启记忆处理后，从获准的聊天文字和图片中整理关系资料；资料可以查看、修正和删除。 |

### 一次回复，四个步骤

**确认联系人 → 写下想法或请求建议 → 查看依据并修改 → 复制后亲自发送**

例如，你可以在输入框写：

> 我今天有点累，想把见面改到周末。帮我说得自然一点，也表达一下我还是很想见对方。

点击「帮我表达」后，再从候选中选出符合自己心意的版本。想法、语气和要求都写在同一个输入框里；没有思路时，也可以留空点击「帮我想想」。

生成始终由你点击发起。收到新消息、切换联系人或打开窗口都不会自动生成；一次性的要求和候选修改也不会自动变成长期偏好。

## 快速开始

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| 系统与芯片 | macOS 15 或更高版本，Apple Silicon。 |
| Node.js | **24 或更高版本**。 |
| 包管理器 | **pnpm 11.25.0**，以根 [package.json](package.json) 的锁定版本为准。 |
| 原生工具链 | Xcode Command Line Tools；前台识别探针还需要 Swift 6 和匹配的 SDK，见[原生说明](native/macos/README.md)。 |
| 磁盘空间 | 项目构建所在卷和临时目录所在卷各至少有 **15 GiB** 可用空间。 |
| 模型服务 | 默认使用 DeepSeek，需准备 API Key；其他已适配服务见[配置示例](.env.example)。 |

业务数据库使用本机 SQLite，无需另外安装数据库服务。正常运行也不需要 Python 或 Conda。

### 2. 获取代码并安装依赖

```bash
git clone https://github.com/Aqua-ava/NotAlone.git
cd NotAlone
pnpm install --frozen-lockfile
```

依赖统一在仓库根目录安装，使用根 `pnpm-lock.yaml`，无需在子目录分别安装。

### 3. 启动开发版

先检查是否已有本项目的开发实例：

```bash
pnpm run dev:status
```

已有实例就继续使用；状态为 `stopped` 时启动：

```bash
pnpm run dev
```

启动后，在另一终端再次执行 `pnpm run dev:status`，并在 App 中确认本机服务已连接。React／CSS 保存后热更新，主进程和后台代码变更会触发安全重启。

关闭窗口会保留 App 运行；完全退出请使用 **「NotAlone → 退出 NotAlone」**。更多启动选项、实例检查和排障见[桌面开发说明](desktop/README.md#日常开发热更新)。

### 4. 准备本机语义检索（推荐）

```bash
pnpm run prepare:embedding
```

该命令联网下载约 100 MB 的固定语义模型，让记忆检索能匹配意思相近、用词不同的内容。未安装时按字面匹配；App 启动不会自动下载。准备完成后无需重启，重新生成回复即可使用。

## 首次使用

1. **初始化本人，配置 AI 服务。** 打开「设置 → AI 服务」，按提示填写本人展示名称，再配置 Base URL 和该服务对应的 API Key。保存后等待本机服务重载；保存配置本身不会调用模型。
2. **连接微信，确认联系人。** 准备并配置外置读取工具，在「同步设置」检测和核对账号，再选择要同步的私聊并明确授权。首次授权包含该会话在本机可读的历史，以及后续新消息。
3. **按需开启记忆处理。** 在「记忆」页面开启「记忆自动处理」。它**默认关闭**；开启后会把相应聊天文字和图片发送给已配置的模型服务，用于整理关系资料。保持关闭仍可同步聊天、查看已有记忆并用于回复。
4. **生成第一条候选。** 在输入小窗确认本次联系人，写下想法并点击「帮我表达」，或点击「帮我想想」。核对依据、编辑候选，复制后到微信亲自发送。

> **微信接入需要额外准备。** 完整上游读取器不随本仓库提供，App 也不会自动下载。当前读取器认证的微信版本为 **4.0.6（29387）**；具体准备、配置与版本限制见[外置微信工具](desktop/README.md#外置微信工具)和[读取器构建说明](desktop/wechat-history/README.md)。仅启动 App 还不能完成首次微信连接。

已有联系人可以直接手动选择后生成回复，无需保持微信在前台，也不用等待同步或记忆处理全部完成。自动跟随当前微信联系人则需要相应屏幕录制权限，并且只匹配已经建立的联系人；匹配失败时仍需手选。权限排查见[开发权限指南](docs/guides/macos-app-permissions-and-errors.md)。

## 当前进度

下面按当前正常桌面入口区分能力与限制；架构文档中的目标不等于已开放功能。

| 范围 | 当前状态 |
| --- | --- |
| 回复与助手讨论 | 已有联系人工作区、明确发起生成、候选依据、编辑、复制和讨论记录入口；需要模型配置与本次联系人有效。 |
| 微信同步 | 当前按所选私聊确认授权，支持本机可读历史与后续增量的处理；依赖受支持的读取工具、版本与来源核验。 |
| 图片与关系记忆 | 支持处理可读取的聊天图片，以及图文记忆、资料管理和检索；记忆处理需另行开启，缺失图片保留实际状态。 |
| 前台联系人跟随 | 根据当前微信窗口的会话名称匹配已有联系人；不负责读取聊天正文，也不代替读取授权。 |
| Skill（回复策略包） | 可管理、启停已核验的策略包，生成时按需使用；自动学习与审核发布入口尚未开放。 |
| 全部私聊同步 | 已纳入产品设计，**当前 SQLite 桌面入口尚未开放**。现阶段需选择并确认联系人。 |
| 历史文件导入 | **正常入口尚未开放**，不能通过导入文件创建联系人。 |
| 独立安装包与其他平台 | 当前以 macOS 源码开发版为入口；签名、公证、独立机器首用和其他平台支持仍需各自完成发布与验收。 |

具体运行结果以当前配置与实际操作为准。构建通过、自动测试通过或历史验收记录，都不单独证明当前机器的微信连接与模型调用已经可用。

## 隐私与控制

**资料保存在本机，模型处理会涉及外发。** 联系人、聊天与关系资料使用本机 SQLite 保存；生成回复或处理记忆时，会向你配置的模型服务发送所需资料。本机存储不等于完全离线，目前也不提供数据库和缓存已加密的保证。

- **先确认，再读取。** 当前仅读取明确授权的私聊；不同联系人的资料按稳定身份隔离，昵称或备注相同不会自动合并。
- **可以停止同步。** 关闭同步或完全退出 App 后停止新读取；撤销授权或删除的会话不会因重启而自动恢复授权。
- **屏幕识别范围有限。** 前台定位只分析当前可见的唯一微信窗口，并仅对会话名称区域做 OCR；不对聊天正文或其他联系人列表做 OCR。原始画面默认仅在本机内存处理，不保存或上传。
- **记忆有来源，也能撤销。** 自动采纳的资料标为自动，保留来源；你可以查看、修正和删除，不会被标成你亲自确认的事实。
- **发送由你决定。** 产品不自动发送外部消息。选择或复制候选，也不代表已经发送。

资料删除的范围、关联记录处理及外部原件和供应商副本的边界，见[隐私与删除说明](architecture/current/privacy-deletion.md)。

## 开发与文档

### 技术结构

| 层次 | 技术与职责 |
| --- | --- |
| 桌面界面 | Electron + React + TypeScript，承载输入小窗、联系人、同步、记忆与设置。 |
| 本机后台 | TypeScript + DSH 官方 profile 与薄插件，处理授权、同步、记忆、检索和回复。 |
| 数据存储 | 本机 SQLite，保存业务资料、来源、任务和删除记录。 |
| macOS 集成 | Swift、ScreenCaptureKit、Vision 与外置微信读取器，分别承担前台定位和授权历史读取。 |

```text
NotAlone/
├── desktop/        桌面应用、开发入口与微信读取适配
├── backend-ts/     本机后台、DSH 配置与业务测试
├── native/         macOS 探针及其他原生组件
├── reply-skills/   回复策略包与相关材料
├── architecture/   现行产品规格与架构决策
├── docs/           开发指南与工程工作流
├── scripts/        模型准备、隐私检查等仓库工具
└── website/        项目介绍网站
```

### 命令与验证

以下命令均在仓库根目录执行，优先选择与改动相关的检查：

| 命令 | 用途 |
| --- | --- |
| `pnpm run dev:status` | 查看开发实例状态。 |
| `pnpm run dev` | 启动支持热更新的桌面开发版。 |
| `pnpm run typecheck` | 检查前后端 TypeScript 类型。 |
| `pnpm run test:backend` | 运行当前后台测试。 |
| `pnpm run test:desktop` | 运行桌面端默认自动检查，不启动真实 App。 |
| `pnpm test` | 串行运行两端测试。 |
| `pnpm run build` | 构建开发资源，不制作安装包。 |

日常开发与验收统一使用 `pnpm run dev`；打包或运行打包版仅在明确的发布任务中进行。开发规则、最小验证和实际 App 验收要求见[工程工作流](docs/agents/engineering.md)。其他人改代码时需要继续使用 App，可参考[稳定开发实例](desktop/README.md#他人改码时的稳定实例)。
